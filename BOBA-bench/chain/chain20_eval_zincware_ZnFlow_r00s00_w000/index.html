Background

znflow.DiGraph is a context manager for constructing computational graphs. Inside a with znflow.DiGraph() as graph: block, Node instances are associated with the active graph through _graph_. Once a node has finished construction, reading one of its non-protected public attributes in that context normally returns a znflow.Connection representing that node and attribute instead of returning the concrete value produced by ordinary Python attribute lookup. Outside an active graph context, _graph_ is None and those reads return their ordinary values.

The new APIs must make it possible to suspend that graph-aware behavior temporarily or for one attribute lookup without changing normal graph behavior elsewhere.

Requirements

1. Package version

znflow.__version__ == "0.1.2"
2. disable_graph context manager

Provide a context manager at znflow.base.disable_graph that can be called with no arguments:

with znflow.base.disable_graph():
    ...

  • For the duration of the block, ZnFlow must behave as though there is no active graph. In particular, every node's _graph_ attribute must evaluate to None, even when the block is entered from inside an active DiGraph context.
  • It must also be valid when no graph is active; _graph_ remains None within the block.
  • On leaving the block, the exact graph state that was active immediately before entry must be restored. Thus, a block entered inside a DiGraph restores that graph, while a block entered without one restores None.
  • Restoration must occur for normal and exceptional exits and must compose correctly with nested uses of disable_graph.
  • The surrounding DiGraph context must continue to operate normally after restoration. Once that graph context itself exits, nodes again report _graph_ as None.

For example, a node created in an active graph normally reports that graph through _graph_; the same node reports None inside disable_graph(), reports the graph again after the inner block, and reports None after the outer graph block ends.
