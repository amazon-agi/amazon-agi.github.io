This task concerns the attribute-definition machinery of the attr package. Classes declare attributes using marker objects and are then decorated to collect metadata and generate the usual initializer, representation, comparison, and hashing methods.

The canonical lower-level decorator name for this task is _add_methods. Existing package-level usage through attr.s remains a supported compatibility API.

attr._add_methods is the package-level re-export of the canonical lower-level decorator name. Package-level attr.s is nevertheless required as the compatibility spelling described below. An attr._make.s name is not required.

The existing protocol helpers remain importable from attr._dunders:

  • _add_hash
  • _add_init
  • _add_repr

NOTHING exposed through attr._make and attr._dunders must be the same singleton sentinel. It represents an omitted value where None is a valid explicit value, and repr(NOTHING) is "NOTHING".

Attribute Declarations and Metadata

Attribute

Attribute represents one collected class attribute. Its constructor requires the three fields name, default_value, and default_factory; they can be supplied positionally or by keyword, as in:

Attribute(name="x", default_value=None, default_factory=NOTHING)

Instances expose those three values as attributes. Equality and inequality are value-based across these fields, so independently constructed metadata with equal names and defaults compares equal. Its representation includes the class name and all three named fields, for example:

Attribute(name='x', default_value=None, default_factory=NOTHING)
_make_attr and attr.ib

_make_attr(default_value=NOTHING, default_factory=NOTHING) creates and returns a _CountingAttr declaration marker. attr.ib is the package-level declaration callable with the same behavior and keyword arguments.

Markers record their default value or default factory and enough creation ordering information for declarations to be collected in source order. A marker only becomes part of generated class metadata when its class is processed by the class decorator.

A declaration may have either a default value or a default factory, but not both. Passing both raises ValueError with this message:

Specifying both default_value and default_factory is ambiguous.

None is a valid default_value and must not be treated as an omitted default.

_get_attrs

_get_attrs(cls) returns the declarations defined on cls in declaration order. Its result is a list of (name, marker) pairs, where each marker is a _CountingAttr. For example, declarations named z, y, and x in that source order produce pairs whose names are ['z', 'y', 'x'].

A class with no declarations produces []. This remains true after the class has been processed by _add_methods.

The _add_methods Decorator

_add_methods is a class decorator in attr._make. It must support direct decorator use:

from attr._make import _add_methods, _make_attr

@_add_methods
class Point(object):
    x = _make_attr()
    y = _make_attr(default_value=0)

It returns the processed class.

Metadata collection

For every _CountingAttr declared directly in the class body, _add_methods creates an Attribute carrying:

  • the assigned class attribute name,
  • the marker's default_value, and
  • the marker's default_factory.

It assigns the resulting declaration-ordered list to cls.__attrs_attrs__. Every item in that list is an Attribute. Thus Point.__attrs_attrs__[0].name == "x" in the example above.

Decorating a class with no declarations is valid and sets __attrs_attrs__ to an empty list. The presence of this metadata identifies the class as attrs-decorated even when the list is empty.

Generated initializer and defaults

The generated __init__ accepts declared attributes in declaration order and assigns them to the instance. Values can be supplied positionally or by keyword.

  • An attribute without either kind of default is required.
  • If an argument with default_value is omitted, that value is assigned. This includes an explicit default of None.
  • If an argument with default_factory is omitted, the factory is called with no arguments and its result is assigned. The factory is evaluated when an instance needs the default, not when the class is defined.
  • An explicitly supplied argument takes precedence over either kind of default.
Generated representation

The generated __repr__ uses the runtime class name and displays attributes in declaration order as name=repr(value). For example, a class C with attributes a and b represents C(1, 2) as:

C(a=1, b=2)

A decorated class named C3 with no attributes has the representation C3().

Generated comparisons

The generated equality and ordering methods compare tuples of declared attribute values in declaration order.

  • Instances with equal values compare equal; differing values compare unequal.
  • Equality is class-sensitive. An unrelated object does not compare equal merely because it has attributes with matching names and values.
  • __lt__, __le__, __gt__, and __ge__ perform the corresponding lexicographic tuple comparison for compatible instances.
  • For an object of an unrelated class, the generated direct comparison methods return NotImplemented; normal Python equality therefore resolves such objects as unequal.
  • Two instances of an empty decorated class compare equal.
Generated hash

The generated __hash__ hashes the tuple of declared values in declaration order. Consequently, hash behavior tracks the same values used by comparisons, subject to Python's normal hash requirements and collision semantics.

Package-Level Decorator Compatibility

attr.s must remain available. It supports both established forms:

@attr.s
class A(object):
    x = attr.ib()

@attr.s()
class B(object):
    x = attr.ib(default_value=None)
    y = attr.ib(default_factory=list)

Both forms collect attr.ib declarations into __attrs_attrs__, preserve their defaults, and by default generate the same initializer, representation, comparison, and hash behavior as _add_methods.

The called form continues to accept the boolean options add_repr, add_cmp, add_hash, and add_init, each defaulting to True. Metadata collection always occurs; setting one of these options to False suppresses generation of that corresponding method group.

The lower-level decorator's canonical name remains _add_methods throughout the attr._make API and as the attr._add_methods re-export. Retaining attr.s at package level is an intentional compatibility alias for the same decoration capability, not a requirement to restore the former lower-level attr._make.s name.

Introspection and Conversion Functions

ls

ls(value) accepts either an attrs-decorated class or one of its instances and returns its declaration-ordered list of Attribute metadata. Calling it on a class and on an instance of that class yields the same metadata. It returns an empty list for a decorated class with no declarations.

For a value whose effective class has no attrs metadata, it raises TypeError. The error message is:

{class_repr} is not an attrs-decorated class.

where {class_repr} is repr() of the class being inspected. For example, inspecting the built-in object class uses its class representation in that template.

has

has(value) accepts a class or instance and reports whether ls recognizes it as attrs-decorated:

  • True for decorated classes and their instances;
  • True for decorated classes whose metadata list is empty; and
  • False for ordinary, non-decorated classes or instances.
to_dict

to_dict(instance, recurse=True) returns a dictionary mapping every declared attribute name to its current instance value.

With recurse=False, conversion is shallow. For example, an object with x == 1 and y == 2 converts to {"x": 1, "y": 2}.

With the default recurse=True, a direct attribute value that is itself attrs-decorated is converted recursively. Thus, if both fields of an object hold attrs-decorated objects, both field values become nested dictionaries. Values that are not attrs-decorated are retained unchanged.

attr.ls, attr.has, and attr.to_dict expose these same behaviors at package level.

Protocol Helper Compatibility

The helper decorators in attr._dunders operate on a class whose __attrs_attrs__ contains Attribute metadata. Each returns the modified class.

  • _add_repr(cls, attrs=None) installs the representation behavior described above. When attrs is supplied, it is the ordered sequence of attribute names to display instead of deriving names from __attrs_attrs__.
  • _add_cmp(cls, attrs=None) installs __eq__, __ne__, and all four ordering methods using the comparison behavior described above. An explicit attrs sequence selects and orders the values used.
  • _add_hash(cls, attrs=None) installs tuple-based hashing. An explicit attrs sequence selects and orders the values used.
  • _add_init(cls) installs an initializer from cls.__attrs_attrs__, including required arguments, default values, and default-factory behavior described above.

These helpers must continue to work for classes whose __attrs_attrs__ metadata was assembled directly, as well as for classes processed through the declaration decorator.

Each flag affects only its corresponding generated behavior. Attributes remain declared attrs metadata even when excluded from one or more methods, and the four choices are independent. no_repr

must produce:

If no_cmp=True, omit that attribute from every generated comparison operation: equality, inequality, and ordering (__eq__, __ne__, __lt__, __le__, __gt__, and __ge__). C = make_class("C", {"a": attr(no_cmp=True), "b": attr()})

must evaluate to True because only a differs.

no_hash

C = make_class("C", {"a": attr(no_hash=True), "b": attr()})

C = make_class("C", {"a": attr(no_init=True), "b": attr()})
