from chaosk8s.probes import deployment_is_not_fully_available

Signature: deployment_is_not_fully_available(name, ...) — it must be callable with a single positional argument being the microservice/deployment name.

Purpose: Verify that a deployment is not fully available, i.e. that it never reaches the state where all desired replicas are ready before an observation timeout occurs.

Behavior:

  • Use the Kubernetes watch API (watch.Watch()) to stream events for the deployment identified by name.
  • For each streamed event, obtain the deployment object from the event (each event is a mapping with an "object" key holding the deployment).
  • A deployment is considered "fully available" when deployment.spec.replicas equals deployment.status.ready_replicas.
    • When an observed deployment is fully available, this is the undesired condition and the watch should stop being consumed / considered complete.
  • The function must observe the stream until the watch stops producing events.   • If the stream ends (is exhausted) having observed the deployment in a not fully available state (i.e. spec.replicas != status.ready_replicas), the probe succeeds and the function returns True.
  • If the deployment remained fully available throughout the observation window such that the stream raises urllib3.exceptions.ReadTimeoutError, raise chaoslib.exceptions.FailedActivity with a message containing:
    microservice '<name>' failed to stop running within
    where <name> is the value of the name argument.

Notes

  • All error conditions must raise chaoslib.exceptions.FailedActivity.
  • The functions must respect the existing configuration-loading mechanism gated by chaosk8s.has_local_config_file.
