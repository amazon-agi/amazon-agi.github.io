Task Specification: Black-Scholes Vanilla Option Pricing

Objective

Implement a function that computes the price of a European vanilla option using the Black-Scholes model, built on top of the JAX numerical library.

Module Location & Public API

Create the following module:

src/price_engine/black_scholes/vanilla_options.py

The module must expose a function with exactly this name and signature:

def _vanilla_price(spot, strike, expire, vol, dtype=jnp.float32):
    ...

Where:

  • spot: the current price of the underlying asset (a JAX scalar, e.g. jnp.float32).
  • strike: the strike price of the option (a JAX scalar).
  • expire: the time to expiration in years (a JAX scalar).
  • vol: the volatility of the underlying asset (a JAX scalar).
  • dtype: the floating-point dtype used for the computation; defaults to jnp.float32.

Required Behavior

The function returns the Black-Scholes price of a European vanilla option, computed under the following assumptions:

  • The risk-free interest rate is zero (no discounting term).
  • No dividends.

The standard Black-Scholes formula, with a zero risk-free rate, reduces to:

d1 = (log(spot / strike) + 0.5 * vol^2 * expire) / (vol * sqrt(expire))
d2 = d1 - vol * sqrt(expire)
price = spot * N(d1) - strike * N(d2)

where N(·) is the cumulative distribution function of the standard normal distribution.

Concrete Correctness Requirement

For the inputs:

  • spot = 100
  • strike = 110
  • expire = 1.0
  • vol = 0.3
  • dtype = jnp.float32

the function must return a value equal to 8.141014 (single-precision float).

Implementation Constraints

  • Use jax.numpy (and, as needed, JAX's SciPy-compatible statistics functions) for all numerical operations so that computations are performed with the specified JAX dtype.
  • The returned value must be a single scalar consistent with jnp.float32 precision (matching the concrete result above exactly).

Notes

  • Only the call option pricing path described above is required.
  • No discounting, dividend yield, or non-zero interest rate handling is required.

Parameters

  • strike: a jax.numpy array of strike prices (one per option).
  • expire: a jax.numpy array of times to expiry, expressed in years (one per option).
  • vol: a jax.numpy array of volatilities (one per option).
  • are_calls: an optional jax.numpy boolean array (one per option) indicating, per element, whether the option is a call (True) or a put (False). When omitted (None), every option must be treated as a call.

Return Value

A jax.numpy array (of dtype dtype) of the same length as the inputs, containing the option price for each corresponding set of inputs.

Behavior

For each element, compute the standard Black-Scholes price assuming a zero risk-free interest rate (no discounting, no carry).

Define, per element:

  • d1 = (ln(spot / strike) + (vol² / 2) · expire) / (vol · √expire)
  • d2 = d1 − vol · √expire

Then:

  • Call price = spot · N(d1) − strike · N(d2)
  • Put price = strike · N(−d2) − spot · N(−d1)

where N(·) is the standard normal cumulative distribution function.

The are_calls flag selects, per element, whether the call or put formula is applied. When are_calls is not provided, the call formula is applied to all elements.

Required pricing behavior

The formulas below apply independently to every batch element. Let:

  • S be the corresponding value from spots,
  • K be the strike,
  • T be the time to expiry,
  • σ be the volatility,
  • r be the continuously compounded discount rate,
  • Φ be the standard normal cumulative distribution function.
European Black–Scholes price

For european_price, compute:

[ d_1 = \frac{\ln(S/K) + (r + \sigma^2/2)T}{\sigma\sqrt{T}}, \qquad d_2 = d_1 - \sigma\sqrt{T}, \qquad D = e^{-rT}. ]

The call and put values are:

[ C = S\Phi(d_1) - KD\Phi(d_2), ]

[ P = KD\Phi(-d_2) - S\Phi(-d_1). ]

Futures option price

For future_option_price, first derive the forward value from the supplied spots entry:

[ D = e^{-rT}, \qquad F = \frac{S}{D} = S e^{rT}. ]

Then compute:

[ d_1 = \frac{\ln(F/K) + (r + \sigma^2/2)T}{\sigma\sqrt{T}}, \qquad d_2 = d_1 - \sigma\sqrt{T}. ]

The call and put values are:

[ C = D\left(F\Phi(d_1) - K\Phi(d_2)\right), ]

[ P = D\left(K\Phi(-d_2) - F\Phi(-d_1)\right). ]

Equivalently, the put satisfies P = C - D * (F - K). The rate intentionally affects both the conversion from S to F and the additive rate term in d1; omitting either effect does not satisfy this API’s pricing contract.

Rate and cross-function consistency
  • With r = 0, D = 1 and F = S, so the two functions return the same value for otherwise identical inputs and call/put selections.
  • At nonzero rates, the functions use the distinct rules above and are not generally equal.
  • A nonzero positive rate does not imply that every price is lower than its zero-rate value. The discount factor, normal-distribution arguments, and—for the futures function—the derived forward all contribute to the result.

Task Specification: Multivariate Heston Model

Overview

Implement a multivariate Heston stochastic volatility model class within the existing models module. The module already contains a univariate Heston implementation; add a multivariate counterpart alongside it.

Module Location and Public API

Both of the following class names must be importable from:

jaxfin.models.heston.heston
  • UnivHestonModel (already exists; keep it importable under this name)
  • MultiHestonModel (provide the multivariate class under this exact name)

MultiHestonModel Requirements

Constructor

The class must be constructible with the following positional parameters, in this exact order:

MultiHestonModel(s0, v0, mean, kappa, theta, sigma, corr, dtype=<jax dtype>)

dtype is a keyword-only argument.

Parameters:

  • s0: initial asset prices, one per asset; an array-like value of length d.
  • v0: initial variances, one per asset.
  • mean: drift terms, one per asset.
  • kappa: mean-reversion speeds of the variance processes, one per asset.
  • theta: long-run variance levels, one per asset.
  • sigma: volatility-of-variance parameters, one per asset.
  • corr: a square correlation matrix relating the assets. For a model with d assets, its shape is d x d.
  • dtype: the JAX floating-point dtype, such as jnp.float32, used for the model's stored parameters.

Inputs are supplied as JAX (jax.numpy) arrays.

Public Attributes

After construction, the following readable attributes must be exposed:

  • s0
  • v0
  • mean
  • kappa
  • theta
  • sigma
  • corr
  • dtype

The array-valued attributes s0, v0, mean, kappa, theta, sigma, and corr must compare elementwise equal to the corresponding constructor values. The dtype attribute must compare directly equal to the dtype object supplied to the constructor. These attributes expose initialization state for reading and do not need to support assignment.

Path Simulation

The class must provide a method with this signature:

sample_paths(self, seed, maturity, n, n_sim)

Parameters:

  • seed: an integer used to seed JAX random-number generation, ensuring reproducibility.
  • maturity: a float representing the total simulation horizon.
  • n: the number of time steps in each simulated path.
  • n_sim: the number of independent simulated paths (Monte Carlo samples).

The method must return a JAX array of asset-price paths with shape (n, n_sim, d), where d is the number of assets determined by the constructor inputs and correlation matrix.

For example, for two assets with n=100 and n_sim=100, the returned array must have shape (100, 100, 2).

Notes

  • The correlation matrix dictates the dependency structure across assets in the simulation.
  • Randomness must be driven by JAX random-number generation facilities and seeded by the seed argument.
