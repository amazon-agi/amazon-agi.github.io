01 URL Extraction from Text 475 words · source specification

Task Specification: URL Extraction from Text

Overview

Implement (or modify) a function that extracts indicators of compromise (IOCs) — specifically URLs — from an arbitrary text string. The function must correctly parse URLs that are embedded in HTML attributes, wrapped in brackets/parentheses, and terminated by trailing punctuation.

Public API

Provide a module named ioc_finder exposing a top-level function:

find_iocs(text: str) -> dict
  • Input: a single string of arbitrary text.
  • Output: a dictionary. Among its keys it must contain the key 'urls', whose value is a collection (supporting membership tests via in and length queries via len()) of the distinct URL strings found in the input.

Only the behavior of the 'urls' key is specified here.

Required Behavior

URLs embedded in HTML attributes

When a URL appears inside an HTML attribute value delimited by double quotes, only the URL itself must be extracted — the surrounding quote, tag markup, and other attributes must not be included.

  • Input containing href="http://fonts.googleapis.com/css?family=Lato:400,700" within a <link ...> tag must yield the URL http://fonts.googleapis.com/css?family=Lato:400,700. Query strings, colons, and commas within the query must be preserved.

  • Input containing href="https://bit.ly/12345#abcd" within an <a ...> tag must yield exactly one URL: https://bit.ly/12345#abcd. The fragment (#abcd) must be preserved, and none of the trailing tag content must be captured.

  • Input containing href="https://bit.ly/12345" must yield exactly one URL: https://bit.ly/12345.

  • Input containing href="https://bit.ly" (no path) must yield exactly one URL: https://bit.ly.

  • Input containing href="https://bit.ly/" (bare trailing slash) must yield exactly one URL: https://bit.ly/. The trailing slash must be preserved.

URLs wrapped in parentheses and brackets

When a URL is enclosed in parentheses ( ... ) or square brackets [ ... ], the enclosing bracket characters must not be part of the extracted URL. A trailing ) or ] must be stripped from the end of a URL.

  • Input (https://i.imgur.com/abc.png) must yield exactly one URL: https://i.imgur.com/abc.png (no trailing )).

  • Input (https://i.imgur.com/abc.png#abc) must yield exactly one URL: https://i.imgur.com/abc.png#abc. The fragment must be preserved and the trailing ) stripped.

  • Input [https://i.imgur.com/abc.png](https://i.imgur.com/abc.png) (the same URL appearing twice, in Markdown link form) must yield exactly one distinct URL: https://i.imgur.com/abc.png. Duplicate occurrences collapse to a single entry, and neither ] nor ) is included.

  • Input [https://i.imgur.com/abc.png#abc](https://i.imgur.com/abc.png#abc) must yield exactly one distinct URL: https://i.imgur.com/abc.png#abc, with the fragment preserved.

Edge Cases and Constraints

  • Deduplication: identical URLs appearing multiple times in the input must be represented once in the 'urls' result.
  • Fragment preservation: URL fragments introduced by # are part of the URL and must be retained.
  • Trailing punctuation: a single trailing ) or ] character immediately following a URL is not part of the URL and must be removed.
  • Path/query preservation: paths, query strings (including embedded : and , characters), and bare/present trailing slashes must be preserved exactly as they appear.

Overview

Public API

find_iocs(text: str) -> dict

This function must be importable such that find_iocs is available for direct call (as it currently is in the codebase). It accepts a single string argument and returns a dictionary whose values are collections of extracted indicators. Relevant keys for this task are:

  • Exactly one domain, equal to foo.onion

That is, the full URL is captured under 'urls', and the domain component (foo.onion) is captured under 'domains'.

Notes

Overview

You must modify the IOC (Indicator of Compromise) extraction functionality so that URLs are correctly parsed when they are embedded within quoted strings (single or double quotes) followed by additional characters.

Public API

The function under test is:

find_iocs(text: str) -> dict

It is importable from the package's public interface (i.e., from <package> import find_iocs). It accepts a string and returns a dictionary of extracted indicators. The relevant key for this task is 'urls', whose value is a collection (iterable supporting in membership tests and len()) of extracted URL strings.

Required Behavior

The function must correctly identify URL boundaries when a URL is enclosed in quotes and immediately followed by non-URL content such as closing parentheses, semicolons, and subsequent text.

Specifically, when a URL appears inside single or double quotes, the extracted URL must terminate at the closing quote and must NOT include any characters that follow the quote (such as ');... or ");...).

Additionally, defanged URL notation must be refanged during extraction: the sequence [.] used to obfuscate a dot in a hostname must be normalized back to a literal ..

Concrete Cases

  1. Given the input:

    DownloadString('https://hacks4all[.]net/rdp.ps1');g $I

    The 'urls' result must contain exactly one entry: https://hacks4all.net/rdp.ps1.

  2. Given the input:

    DownloadString("https://hacks4all[.]net/rdp.ps1");g $I

    The 'urls' result must contain exactly one entry: https://hacks4all.net/rdp.ps1.

In both cases:

  • The single URL https://hacks4all.net/rdp.ps1 must be present in the 'urls' collection.
  • The total number of URLs extracted must be exactly one.
  • The trailing characters after the closing quote (');g $I / ");g $I) must not be included in the extracted URL, and must not produce any additional URL entries.

Constraints on Existing Behavior

Existing URL extraction behavior must be preserved. In particular, URLs delimited by boundaries other than quotes (e.g., a URL containing a fragment identifier that stands alone in the text) must continue to be extracted as a single, complete URL including its fragment. This new quote-handling must not break the extraction of otherwise well-formed URLs.

Task Specification: Add File Path Detection to IOC Finder

Overview

Extend the existing IOC (Indicator of Compromise) extraction functionality to detect and extract file paths (both Windows-style and Unix-style) from arbitrary text input.

Public API

The behavior is exercised through the existing function:

from ioc_finder import find_iocs

find_iocs(text: str) -> dict accepts a string and returns a dictionary of extracted indicators.

Required Changes

1. New result key

The dictionary returned by find_iocs must always include a new key:

  • "file_paths" — a list of strings containing every detected file path.

When no file paths are present in the input, this key must still be present and map to an empty list ([]). This applies to all inputs, including inputs that contain other kinds of indicators but no file paths.

2. File path detection behavior

find_iocs must detect the following forms of file paths and include the full matched path string as an element of file_paths.

Windows-style paths
  • A drive-letter prefixed path such as C:\... where the path continues through backslash-separated segments.
  • Segments may contain spaces. For example, the segment Flash Player is part of a single path.
  • Segments may contain spaces adjacent to a backslash. For example, AppData \Local must remain part of the same single path.
  • Paths may include placeholder-style segments containing angle brackets, e.g. <username>.
  • Paths may end in a filename with an extension (e.g. shedaudio.exe, flashplayer.exe).
  • A path may end with a trailing backslash; when it does, the trailing backslash is included in the matched result.

Examples of complete single matches:

  • C:\Users\<username>\AppData\Roaming\Macromedia\Flash Player\macromedia\bin
  • C:\Users\<username>\AppData\Roaming\Macromedia\Flash Player\macromedia\bin\ (trailing backslash retained)
  • C:\Users\<username>\AppData \Local\Microsoft\Windows\shedaudio.exe
  • C:\Windows\11987416.exe
  • C:\Windows\System32\46615275.exe
  • C:\Windows\System32\shedaudio.exe
  • C:\Windows\SysWOW64\f9jwqSbS.exe
Unix-style paths
  • An absolute path beginning with / and continuing through forward-slash-separated segments.
  • Segments may contain spaces (e.g. File System).
  • Paths may end in a filename with an extension (e.g. pivtoken.appex).
  • A path may end with a trailing slash; when it does, the trailing slash is included in the matched result.
  • A home-directory path beginning with ~/ (e.g. ~/Desktop/test.py).
  • Filenames beginning with a dot are supported (e.g. the final segment .rebootime in /etc/init.d/.rebootime).

Examples of complete single matches:

  • /Library/Storage/File System/HFS/25cf5d02-e50b-4288-870a-528d56c3cf6e
  • /Library/Storage/File System/HFS/25cf5d02-e50b-4288-870a-528d56c3cf6e/ (trailing slash retained)
  • /Library/Storage/File System/HFS/25cf5d02-e50b-4288-870a-528d56c3cf6e/pivtoken.appex
  • ~/Desktop/test.py
  • /etc/init.d/.rebootime
3. Extraction from surrounding text

File paths must be extracted even when embedded within a larger sentence. Leading/trailing non-path words separated by whitespace must not be included in the match. For example, given test C:\...\bin is a bad file path, only the path portion (C:\...\bin) is captured; the surrounding words are excluded.

When a path is followed by a space and then additional words, the match must stop at the path boundary and not consume the following words. Likewise, a trailing slash/backslash immediately before a following space is retained as part of the path, but the following space and words are not.

4. Multiple paths

When the input contains multiple distinct file paths (e.g. across multiple lines), each must be extracted as a separate element of file_paths. Non-path content interspersed between paths (e.g. registry keys like HKEY_LOCAL_MACHINE\Software\..., or descriptive headings) must not be captured as file paths.

For the multi-line Windows example, exactly the six drive-letter paths listed in section 2 must appear in file_paths and nothing else.

Constraints

  • Do not remove or alter any existing keys in the returned dictionary; only add the "file_paths" key.
  • All previously supported indicator types must continue to work unchanged.
