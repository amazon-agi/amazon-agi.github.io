Overview

Constructor:

Ability(value=<default>)
  • Accepts an optional initial score value. It must be constructible with no argument (a default is acceptable) and with a single positional integer argument (e.g. Ability(14)).

Instance attributes / behavior:

  • .value: the raw ability score (integer). It must be assignable directly (e.g. stat.value = 15).
  • .modifier: the D&D ability modifier derived from .value, computed as floor((value - 10) / 2). Required mappings across the score range include:
    • 1 → -5
    • 2,3 → -4
    • 4,5 → -3
    • 6,7 → -2
    • 8,9 → -1
    • 10,11 → 0
    • 12,13 → +1
    • 14,15 → +2
    • 16,17 → +3
    • 18,19 → +4
    • 20,21 → +5
    • 30 → +10

Data descriptor behavior:

When Ability is used as a class attribute on some object and assigned an integer, reading the attribute back must yield an object exposing .value and .modifier. For example, setting the attribute to 15 yields an object whose .value is 15 and whose .modifier is 2.

Saving throw:

  • .saving_throw: an integer equal to the ability's .modifier, plus a proficiency bonus only if the owning object grants saving-throw proficiency for this ability.
    • Proficiency applies when the owning object has a saving_throw_proficiencies collection containing the lowercase name under which this Ability is bound as an attribute on that object (e.g. 'strength'), in which case the object's proficiency_bonus is added.
    • Example: an Ability(14) (modifier +2) accessed on a plain instance yields saving_throw == 2. When bound as attribute strength on an object whose saving_throw_proficiencies == ['strength'] and proficiency_bonus == 2, then .strength.saving_throw == 4.
    • A standalone Ability(14) (not attached to an owner with proficiencies) must yield saving_throw == 2.
Class: Skill

Provide a class named Skill that functions as a data descriptor representing a skill derived from a specified ability.

Constructor:

Skill(ability=<ability_name>)
  • ability: the lowercase name (string) of the Ability attribute on the owning object that this skill derives from (e.g. 'dexterity').

Descriptor behavior:

When accessed as an attribute on an owning object, Skill returns an integer value equal to:

  • the .modifier of the referenced ability on the owning object, plus
  • the owning object's proficiency_bonus only if the owning object grants proficiency for this skill.

Proficiency applies when the owning object has a skill_proficiencies collection containing the lowercase name under which this Skill is bound as an attribute on the object (e.g. 'acrobatics').

Example: Given an object with:

  • dexterity = Ability(14) (modifier +2)
  • acrobatics = Skill(ability='dexterity')
  • skill_proficiencies = []
  • proficiency_bonus = 2

then obj.acrobatics == 2. After setting obj.skill_proficiencies = ['acrobatics'], obj.acrobatics == 4.

Compatibility Note

The dungeonsheets.character module must remain importable (from dungeonsheets import character), and dungeonsheets.character.Character must remain importable and usable as before.

Descriptor Naming Requirement

Both Ability.saving_throw and Skill proficiency lookups depend on knowing the attribute name under which the descriptor is bound on the owning class. Ensure each descriptor can determine its own bound attribute name so it can look that name up in the owner's saving_throw_proficiencies / skill_proficiencies collections.

  • For a finesse weapon, use whichever of Strength or Dexterity yields the higher modifier.

  • Additionally proficiencies_extra = ("it's", "me") → "Hello, world, it's, me."

Note: only the first character of the entire combined string is capitalized; the remaining phrases keep their original casing.

A valid reStructuredText heading consists of a title line followed by its underline line. The existing underline-to-command mapping is:

  • = underline: \section*
  • - underline: \subsection*
  • ^ underline: \subsubsection*

These are unnumbered LaTeX heading commands. top_heading_level shifts the selected command deeper by the requested number of levels, with the deepest supported result capped at \subparagraph*.

The following exact behavior must be preserved:

# "\\section*{Hello, world}\n"

# "\\section*{Hello, world}\n"

# "\\subparagraph*{Hello, world}\n"

# "\\section*{Hello, world}\n\nThis is some text"

# "This is a paragraph\n\n\\section*{Hello, world}\n"
