01 You are implementing behavior for a mock Firestore library. 319 words · source specification

Overview

You are implementing behavior for a mock Firestore library. Specifically, you need to ensure that retrieving documents from a collection returns them in a well-defined default order.

Public API Surface

The library exposes a MockFirestore class (importable as MockFirestore from the library's package root, e.g. from mockfirestore import MockFirestore).

A MockFirestore instance:

  • Has a writable attribute _data, which is a dictionary mapping collection names to dictionaries. Each such inner dictionary maps document IDs (strings) to document contents (dictionaries).
  • Has a method collection(collection_name: str) that returns a collection reference object.

The collection reference object has a method:

  • get() — returns a list of document objects representing all documents currently in that collection.

Each document object returned has a method:

  • to_dict() — returns the document's contents as a dictionary.

Required Behavior

When get() is called on a collection reference, the returned list of document objects MUST be ordered by their document IDs in ascending order, regardless of the order in which the documents appear in the underlying _data structure.

Concrete Example

Given a MockFirestore instance whose _data is:

{
    'foo': {
        'beta': {'id': 1},
        'alpha': {'id': 2}
    }
}

Calling collection('foo').get() must return a list whose first element is the document with ID 'alpha'. That is, the first element's to_dict() must return {'id': 2}, because 'alpha' sorts before 'beta' in ascending order.

Compatibility Constraint

All code you write must be compatible with Python 3.5. In particular:

  • Do not rely on dictionary insertion-ordering guarantees (which are not present in Python 3.5); the ascending-by-document-ID ordering above must be produced explicitly.
  • Do not use type-hinting syntax or features that are unavailable in Python 3.5.

Notes

  • An empty collection (a collection name not present in _data, or one mapping to an empty dictionary) must yield an empty list from get(). This existing behavior must be preserved.

Overview

  • limit(count) — Returns a query object that, when executed, yields at most count documents.

  • get() — Executes the accumulated query and returns a list of document snapshot objects.

Each returned document snapshot must expose a to_dict() method returning the document's data as a dictionary.

Composition Requirement (the core of this task)

The order_by and limit operations must be order-independent with respect to how they are chained. Specifically:

  • When order_by(field) is applied before limit(n), the result must be: the full set of documents sorted ascending by field, then truncated to the first n documents.

The correct semantics are that ordering is applied to the complete result set first, and the limit selects the first n documents from that ordered set. Constraints

Overview

This task concerns a mock implementation of a Firestore-like document database. You must ensure that data stored inside the mock is fully isolated from the objects supplied by or returned to callers, so that mutating an external object never affects the internally stored data (and vice versa).

Public API Surface

The following must be importable and usable:

from mockfirestore import MockFirestore

  • MockFirestore.collection(collection_name: str) — returns a collection reference object.

  • The collection reference exposes .document(document_id: str) — returns a document reference object.

  • The document reference exposes:

    • .set(data: dict) — stores data as the document's contents under the given id.
    • .update(data: dict) — merges data into the document's existing contents at the top level (top-level keys in data replace the corresponding stored keys).

  • The document snapshot exposes:

    • .to_dict() — returns the document's field data as a dict.

Required Behavior

1. Isolation on set()

When set(data) is called, the mock must store a copy of data rather than retaining a reference to the caller's object. After calling set(), any subsequent mutation the caller performs on the original data object (e.g., changing one of its top-level values) must have no effect on what is later retrieved via get().to_dict().

Example of required outcome: seed _data with an empty collection foo, call set({'id': 'bar'}) on document bar, then mutate the passed dict's id to 'new value'. Retrieving the document yields {'id': 'bar'}.

When update(data) is called, the mock must store a copy of the incoming data (deeply enough that nested structures are also isolated) rather than retaining references into the caller's object. After calling update(), mutating a nested value inside the original data object must have no effect on what is later retrieved via get().to_dict().

to_dict() must return a copy of the stored document data, not a reference into the backing store. After obtaining a dict from to_dict(), subsequent mutations to the underlying _data store must not alter the previously returned dict.
