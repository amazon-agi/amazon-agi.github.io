    • 'http_url': when set to False, the HTTP (urlopen) back-end is disabled for that protocol.

  3. Absent / default — both back-ends are enabled and attempted (DNS first, then HTTP fallback).

For a given protocol version with retrieval enabled:

  1. DNS back-end first. Attempt to resolve the address via check_output (the dig tool).

    • If check_output raises TimeoutExpired or FileNotFoundError, treat this as a hard failure of the DNS back-end: the exception must be caught and the HTTP fallback must then be attempted.
    • If check_output returns a non-empty string (after stripping whitespace), that stripped string is the result and is returned. The HTTP back-end must NOT be called.

Overview

Modify the LanIP entry class in archey.entries.lan_ip, importable as:

from archey.entries.lan_ip import LanIP

The entry gathers local IPv4 and, optionally, IPv6 addresses from the existing network-interface enumeration facility. It must expose retained addresses in a normalized, human-readable form, exclude loopback addresses, honor address-count and IPv6 options, and produce the correct text for populated, empty, and unavailable states.

Public API

The class must remain constructible as:

LanIP(options={
    'max_count': <non-negative int or False>,
    'ipv6_support': <bool>
})

Both options are optional:

  • max_count defaults to 2.
  • ipv6_support defaults to True.

After construction:

  • lan_ip.value is a list of retained address strings when the network-interface facility is available, including when that list is empty.
  • lan_ip.value is None when the optional network-interface facility is unavailable.
  • lan_ip.output(output) must add one entry through output.append(...), using the entry's name as the first positional argument and the display text described below as the second positional argument.

Address Selection

Address families

IPv4 (AF_INET) addresses are always eligible for collection. IPv6 (AF_INET6) addresses are eligible only when ipv6_support is True. When ipv6_support is False, IPv6 records must not appear in value, while eligible IPv4 records remain.

Records belonging to other families, including link-layer or MAC-address records, must not be included. Link-local and private IP addresses are otherwise valid; only the loopback exclusions below are required.

Per-address normalization

Each eligible raw 'addr' string must be normalized before it is retained or checked for IPv6 loopback equivalence:

  1. Remove a CIDR or netmask suffix. If the string contains /, remove the / and everything after it. For example, 2a02::45:6789:abcd:0123/64 becomes 2a02::45:6789:abcd:0123.
  2. Remove an IPv6 zone or scope suffix. If the string contains %, remove the % and everything after it. For example, fe80::abcd:ef0:abef:dead%en0 becomes fe80::abcd:ef0:abef:dead. The % is a literal character in the raw address.
  3. Compress IPv6 text canonically. For AF_INET6 records, remove leading zeroes from groups and replace the longest eligible run of all-zero groups with :: according to standard IPv6 textual compression rules. Canonical hexadecimal casing and tie-breaking rules must be used. Examples:
    • 2001:0000:0000:0000:0045:6789:abcd:6817 becomes 2001::45:6789:abcd:6817.
    • 0000:0000:0000:0000:0000:0000:0000:0001 becomes ::1.

IPv4 text is not otherwise reformatted; after suffix removal, an address such as 192.168.1.55 remains 192.168.1.55.

Loopback exclusion

Loopback addresses must not be retained:

  • Exclude IPv4 addresses beginning with 127..
  • Exclude the IPv6 loopback address semantically equivalent to ::1.

The exclusion must be representation-independent and occur after, or as part of, semantic normalization. Consequently, both ::1 and 0000:0000:0000:0000:0000:0000:0000:0001 are excluded, including equivalent inputs carrying removable CIDR or zone suffixes. A fully expanded IPv6 loopback must never survive merely because its raw spelling was not already ::1.

Excluded loopback records do not consume the max_count allowance.

Ordering and Limiting

The resulting order is deterministic:

  1. Retained IPv4 addresses come first, in interface/address discovery order.
  2. Retained IPv6 addresses follow, in interface/address discovery order.

Normalization must not reorder the addresses. Each retained discovery contributes its normalized address; no sorting by textual or numeric value is performed.

Apply max_count to the final stream of eligible, normalized, non-loopback addresses while preserving that order:

  • A positive integer retains at most that many addresses.
  • Integer 0 retains no addresses and therefore produces an empty list.
  • Boolean False is the explicit unlimited sentinel and retains all eligible addresses. It must not be conflated with integer 0, even though both are falsy in Python.
  • If omitted, the default limit is 2.

Output Behavior

output() must choose its second append argument according to the entry state:

  1. Non-empty list: Join all strings in value with exactly ", " (comma followed by one space).
  2. Empty list with enumeration available: Use the configured default_strings.no_address value, rather than an empty string. With the default configuration, this is exactly DEFAULT_CONFIG['default_strings']['no_address']. This case includes no interfaces, interfaces with no IP records, hosts exposing only excluded loopbacks, IPv6-only results when IPv6 is disabled, and max_count=0.
  3. Enumeration facility unavailable: Leave value as None, fail softly rather than attempting discovery, and use the configured default_strings.not_detected value. With the default configuration, this is exactly DEFAULT_CONFIG['default_strings']['not_detected'].

Configuration overrides for these default strings must continue to be honored.

Worked Example

Suppose discovery yields the following eligible candidates:

  • IPv4: 192.168.1.55
  • IPv6, in order:
    • 2001:0000:0000:0000:0045:6789:abcd:6817
    • fe80::abcd:ef0:abef:dead%en0
    • 2a02::45:6789:abcd:0123/64

With:

LanIP(options={
    'max_count': 3,
    'ipv6_support': True
})

the resulting value must be:

[
    '192.168.1.55',
    '2001::45:6789:abcd:6817',
    'fe80::abcd:ef0:abef:dead'
]

and the display text passed as the second positional argument to output.append must be:

192.168.1.55, 2001::45:6789:abcd:6817, fe80::abcd:ef0:abef:dead

The fourth candidate, 2a02::45:6789:abcd:0123, is normalized but omitted by the limit. If discovery also supplied 127.0.0.1 or an expanded spelling of IPv6 loopback, those records would be excluded before applying the limit.
