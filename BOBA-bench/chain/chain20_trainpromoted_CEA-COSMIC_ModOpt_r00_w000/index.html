Task Description

Goal

Move the convolution functionality into the modopt.math package so that it can be imported via that package's public namespace, and take it out of the modopt.image package's public namespace.

Required Module Layout

Provide a module convolve inside the modopt.math package such that:

  • Importing with from modopt.math import * exposes a convolve submodule.
  • After that import, the convolution functions described below are accessible as convolve.convolve(...) and convolve.convolve_stack(...).

The convolution functions must no longer be reachable through from modopt.image import * (in other words, convolve must not be part of the modopt.image public namespace).

Public API and Behavior Requirements

convolve.convolve(data, kernel, method='astropy')

Carries out a 2D convolution of a single image array data with a kernel array having the same shape.

Parameters:

  • data: a 2D NumPy array.
  • kernel: a 2D NumPy array with the same shape as data.
  • method: a string that selects the convolution backend; it is either 'astropy' or 'scipy'. The default is 'astropy'.

Return value: a 2D NumPy array with the same shape as data.

How the two methods behave (verified using the following inputs):

Take

data   = [[0, 1, 2], [3, 4, 5], [6, 7, 8]]
kernel = [[1, 2, 3], [4, 5, 6], [7, 8, 9]]

  • When method='astropy', the result must be:

    [[210., 201., 210.],
 [129., 120., 129.],
 [210., 201., 210.]]

    (that is, a centered convolution with wrap-around/periodic boundary handling, normalization off, producing an output of the same size.)

  • When method='scipy', the result must be:

    [[ 14.,  35.,  38.],
 [ 57., 120., 111.],
 [110., 197., 158.]]

    (that is, a 2D convolution of the same size with zero-padded boundaries.)

convolve.convolve_stack(data, kernel, rot_kernel=False)

Runs a convolution across a stack (first axis) of 2D images, where each 2D slice of data is convolved with the corresponding 2D slice of kernel.

Parameters:

  • data: a 3D NumPy array (2D images stacked along axis 0).
  • kernel: a 3D NumPy array with the same shape as data.
  • rot_kernel: a boolean flag. When it is True, each kernel slice is rotated by 180 degrees before it is convolved with the corresponding data slice. The default is False.

Return value: a 3D NumPy array with the same shape as data, in which slice i is the convolution of data[i] with kernel[i] (or the rotated kernel[i]).

Each individual convolution must employ the 'astropy' backend behavior described above.

Behavior (verified against the following inputs):

Start from

data   = arange(18).reshape(2, 3, 3)
kernel = data + 1

  • When rot_kernel=False, the result must be:

    [[[ 210.,  201.,  210.],
  [ 129.,  120.,  129.],
  [ 210.,  201.,  210.]],
 [[1668., 1659., 1668.],
  [1587., 1578., 1587.],
  [1668., 1659., 1668.]]]

  • When rot_kernel=True, the result must be:

    [[[ 150.,  159.,  150.],
  [ 231.,  240.,  231.],
  [ 150.,  159.,  150.]],
 [[1608., 1617., 1608.],
  [1689., 1698., 1689.],
  [1608., 1617., 1608.]]]

Constraints

  • The outputs of the functions must be floating-point NumPy arrays matching the values above.
  • The input's spatial dimensions must be preserved by the convolution results (same-size output).
  • Through modopt.image's public interface, no convolution-related functionality should remain accessible.

1.2 modopt.base.transform

Define a collection of reshaping transformations that connect three representations of the same underlying data:

  • a cube: a 3D array whose shape is (n_images, img_rows, img_cols),
  • a map: a 2D array in which the cube's images are tiled across a grid according to a layout (n_rows, n_cols),
  • a matrix: a 2D array where every column is one flattened image.

The tiling convention is pinned down exactly by the following reference values (applied consistently across every function):

cube = arange(16).reshape((4, 2, 2))
layout = (2, 2)
map = [[ 0,  1,  4,  5],
       [ 2,  3,  6,  7],
       [ 8,  9, 12, 13],
       [10, 11, 14, 15]]
matrix = [[ 0,  4,  8, 12],
          [ 1,  5,  9, 13],
          [ 2,  6, 10, 14],
          [ 3,  7, 11, 15]]

That is: image 0 goes in the top-left tile of the map, image 1 in the top-right tile, image 2 in the bottom-left tile, image 3 in the bottom-right tile, and each tile holds its image in that image's natural 2D layout. The matrix has one column per image, each column being that image's row-major (C-order) flattening.

Implement the following:

  • cube2map(data_cube, layout)

    • Input: a cube plus a layout (n_rows, n_cols).
    • Output: the 2D map that results from tiling the cube's images into a grid following the convention above.
    • With the reference cube and layout → the reference map.

  • map2cube(data_map, layout)

    • Input: a 2D map together with its layout (n_rows, n_cols).
    • Output: the cube reconstructed from the map (the inverse of cube2map).
    • With the reference map and layout → the reference cube.

  • map2matrix(data_map, layout)

    • Input: a 2D map and its layout (n_rows, n_cols).
    • Output: the matrix representation (one flattened image per column) following the convention above.
    • With the reference map and layout → the reference matrix.

  • matrix2map(data_matrix, map_shape)

    • Input: a matrix together with the target shape (rows, cols) of the map.
    • Output: the 2D map (the inverse of map2matrix).
    • With the reference matrix and map_shape = (4, 4) → the reference map.

  • cube2matrix(data_cube)

    • Input: a cube.
    • Output: the matrix representation, with one flattened image (row-major) per column.
    • With the reference cube → the reference matrix.

  • matrix2cube(data_matrix, im_shape)

    • Input: a matrix plus the shape (img_rows, img_cols) of a single image.
    • Output: the cube (the inverse of cube2matrix), built by stacking the reshaped columns along the first axis.
    • With the reference matrix and im_shape = (2, 2) → the reference cube.

The PowerMethod class

The constructor has the signature PowerMethod(operator, data_shape).

  • operator: a callable taking an array and returning an array (e.g., lambda x: x.dot(x.T)).
  • data_shape: the shape (a tuple) of the arrays on which the operator acts.
  • The power method is executed as part of construction to estimate the spectral radius of the operator.
  • Randomness: the method's starting point is a random array. The estimation takes its initial guess from numpy.random, so that seeding via numpy.random.seed produces reproducible results.

Once construction has finished, the following attributes are available:

  • spec_rad: the estimate of the spectral radius (a float).
  • inv_spec_rad: the reciprocal of the spectral radius, that is, 1 / spec_rad.

Reference behavior: using numpy.random.seed(1), the operator lambda x: x.dot(x.T), and data_shape = (3, 3), the outcome is spec_rad ≈ 0.90429242629600837 and inv_spec_rad ≈ 1.1058369736612865.

Build the modopt.signal Package

Build an importable Python subpackage modopt.signal that contains the noise and positivity modules together with the public functions described below. It must support from modopt.signal import * and expose at least the module names noise and positivity.

The modopt.signal.noise Module

add_noise(data, sigma=1.0, noise_type='gaussian')

The function adds noise to array-like data and returns a new NumPy array.

  • With noise_type='gaussian' (the default), independent Gaussian noise is added to every element. This is done by generating a standard-normal array with the same shape as data, scaling it by sigma, and adding it to data.
    • sigma may be a scalar that is applied uniformly, or an array-like collection of per-element scale factors that is broadcastable against data.
    • An array-like sigma made up of ones must produce the same result as the scalar default 1.0 when starting from the same random state.
  • With noise_type='poisson', an independent Poisson draw is added to each original element. For an element x, the result is x + P, with P drawn from a Poisson distribution whose expected value is x. In this mode, sigma is ignored.
  • For any other value of noise_type, the function must raise ValueError.
  • If the shape of sigma cannot be broadcast against the shape of data, the function must raise ValueError. This holds no matter whether sigma is supplied by keyword or positionally; for example, passing a tuple such as (1, 1) is invalid when that tuple is incompatible with the input shape.

Random values must come from NumPy's global random state (numpy.random); seeding that state therefore makes the results reproducible.

thresh(data, threshold, threshold_type='hard')

The function applies thresholding to array-like data and returns a new NumPy array that has the same shape.

  • With threshold_type='hard' (the default), an element is set to zero only when its absolute magnitude is strictly less than threshold. Elements whose magnitude is greater than or equal to threshold are preserved, including values that lie exactly on the threshold boundary.
  • With threshold_type='soft', each element is shrunk toward zero by threshold, and its magnitude is clamped at zero. For each element x, the result is sign(x) * max(|x| - threshold, 0).
  • For any other value of threshold_type, the function must raise ValueError.

Given the input [[0,1,2],[3,4,5],[6,7,8]] with threshold 5, the expected results are:

  • Hard mode: [[0,0,0],[0,0,5],[6,7,8]]
  • Soft mode: [[0,0,0],[0,0,0],[1,2,3]]

The modopt.signal.positivity Module

positive(data)

Return data with every negative value replaced by zero, while non-negative values are kept unchanged.

  • For a scalar int, return 0 when the value is negative and return the value unchanged otherwise; the result is an integer.
  • For a scalar float, return -0.0 when the value is negative and return the value unchanged otherwise; the result is a float.
  • For a NumPy array, the operation is applied element-wise and the array's dtype is preserved. As an example, an integer array must produce an integer array.
  • For a ragged list of arrays whose lengths differ, process each contained array independently and return a NumPy array with object dtype. Each element of that object array must be a plain Python list containing the clipped values for the corresponding input array, not a NumPy ndarray; each element must compare equal, as a single object, to the corresponding Python list. For example, when positive is applied to the two integer arrays [-3, -2, -1, 0, 1] and [-2, -1, 0, 1], it must return an object-dtype array whose two elements are the lists [0, 0, 0, 0, 1] and [0, 0, 0, 1].

  • W0 as the construction-time original_weights, left unchanged,

  2. Compute the reduced SVD X = U @ diag(s) @ Vh, in which the number of singular components is k = min(r*c, n).
  3. Build the coefficient matrix A = diag(s) @ Vh, whose shape is (k, n).
  4. Turn the columns of U into a stack of component images of shape (k, r, c), and apply operator to that stack. When the layers are square, reshaping an individual component amounts to a sqrt(r*c) by sqrt(r*c) reshape.

Condat–Vũ Behavior Within a Single Iteration

Suppose the current iterates are x_n and y_n, and the current parameters are tau_n, sigma_n, and rho_n; one update must then display the observable mathematical behavior described here.

First of all, the gradient is evaluated at the current primal iterate:

grad.get_grad(x_n)
g_n = grad.grad

Next, the unrelaxed primal update is computed:

x_prox = prox.op(
    x_n - tau_n * g_n - tau_n * linear.adj_op(y_n)
)

Extrapolation of that result then takes place through the linear operator:

y_temp = y_n + sigma_n * linear.op(2 * x_prox - x_n)

The prox_dual handed to the algorithm is the proximity of the dual/composite term itself; it is not a proximity of its convex conjugate that was computed ahead of time. Moreau decomposition must therefore be applied in the dual update:

y_prox = y_temp - sigma_n * prox_dual.op(y_temp / sigma_n,
                                           extra_factor=1 / sigma_n)

A call convention other than this one is acceptable only when it produces the same scaling and the same mathematical result. In particular, assigning prox_dual.op(y_temp) directly as the new dual value is not an equivalent choice. With IdentityProx, y_prox is brought to zero by the Moreau expression.

Finally, the same rho_n relaxes both variables:

x_(n+1) = rho_n * x_prox + (1 - rho_n) * x_n
y_(n+1) = rho_n * y_prox + (1 - rho_n) * y_n

  1. Each parameter-update callable that was supplied is applied, so that the value used by the next iteration is prepared.
  2. Convergence is evaluated through cost.get_cost(x_(n+1), y_(n+1)).
  3. The run stops either when the cost monitor reports convergence or when the requested iteration limit has been reached.

The iteration interface that already exists stays available: one update is what update() performs, and iterate(max_iter=150) works with a default limit of 150 updates.

Overview

A Generalized Forward-Backward optimization class named GenForwardBackward is to be provided in modopt.opt.algorithms. It must be available alongside the existing optimization classes via from modopt.opt import algorithms.

Public API

The constructor takes the form:

algorithms.GenForwardBackward(
    x,
    grad,
    prox_list,
    cost=None,
    gamma_update=None,
    lambda_update=None,
    weights=None,

)

Parameters:

  • x: the starting primal value, given as a NumPy array.
  • grad: the gradient operator.
  • prox_list: a list of proximity operators, with one weight and one auxiliary state associated with each operator.
  • cost: an optional convergence/cost object.
  • gamma_update: an optional callable that updates the forward step-size parameter.
  • lambda_update: an optional callable that updates the relaxation parameter.
  • weights: an optional sequence or NumPy array giving the proximity-operator weights.
  • auto_iterate: whether iterate() is to be called during construction, with True as the default.

The class must expose:

  • update(), which performs a single generalized forward-backward update;
  • iterate(max_iter=150), which performs updates repeatedly until convergence or until the iteration limit is reached; and
  • x_final, holding the latest primal result once iteration has completed.

Operator protocols

Gradient operator

To be compatible, a grad object must:

  1. provide a callable get_grad(current_x) method; and
  2. expose the computed gradient as grad.grad after that method has been called.

The current forward step-size gamma is owned by GenForwardBackward. This is the inverse-spectral-radius/forward-step factor that the recurrence uses. Its initial value is 1.0; callers using the built-in GradParent must not have to add an inv_spec_rad attribute by hand. In particular, construction and iteration with an ordinary GradParent must not fail as a result of that metadata being absent.

Proximity operators

Every entry in prox_list must expose a callable op. An absent op attribute is invalid and must cause a ValueError during construction. During an update, the operation is invoked with the intermediate array and an extra_factor keyword, as detailed below. Operators supplied through the framework's standard proximity wrappers may ignore an extra keyword that they do not support, so identity-style operators remain compatible.

Cost object

If cost is supplied, it must provide get_cost(new_x). After each completed update, this method is called with the primal value that was just computed. A truthy return value reports convergence and stops any further iteration.

Initialization and parameter updates

Let x_0 denote x, let N be the number of proximity operators, and let w_i denote their weights. Initialize one auxiliary value for each proximity operator, as

z_(i,0) = x_0.

The scalar parameters owned by the algorithm start at:

  • gamma_0 = 1.0 for the forward/gradient step size; and
  • lambda_0 = 1.0 for relaxation.

After each completed update:

  • if gamma_update is given, it is called with the current gamma_n, and the value it returns is used as gamma_(n+1);
  • otherwise, gamma is left unchanged;
  • if lambda_update is given, it is called with the current lambda_n, and the value it returns is used as lambda_(n+1);
  • otherwise, lambda is left unchanged.

Parameter values that have been updated apply from the next iteration onward; they do not apply retroactively to the update that produced them. Identity callbacks such as lambda value: value therefore preserve the corresponding initial value of 1.0.

Generalized forward-backward update

At iteration n, the following externally observable computation is carried out:

  1. Call grad.get_grad(x_n) and read off g_n = grad.grad.

  2. For each proximity operator i, using the same current primal value together with that operator's current auxiliary value, calculate:

    • t_(i,n) = 2 * x_n - z_(i,n) - gamma_n * g_n
    • p_(i,n) = prox_list[i].op(t_(i,n), extra_factor=gamma_n / w_i)
    • z_(i,n+1) = z_(i,n) + lambda_n * (p_(i,n) - x_n)

  3. Build the next primal value as the weighted sum:

    x_(n+1) = sum(w_i * z_(i,n+1) for i in range(N)).

  4. Carry out the callback updates described above.

  5. If a cost object was supplied, call cost.get_cost(x_(n+1)) and record the convergence result from it.

The current gamma is the sole step-size factor, both in the gradient term and in the proximity extra_factor; no inverse-spectral-radius field from the caller is required in addition to it.

Weight defaults and validation

If weights is left out, use equal floating-point weights, each of them equal to 1.0 / N.

If weights are given explicitly, all of the following rules apply during construction:

  1. weights must be a collection, such as a list, tuple, or NumPy array. A scalar or any other non-collection value raises TypeError.
  2. Every weight must be a floating-point value. Collections whose entries are integer-valued are not converted and raise ValueError, even if their length and sum would otherwise be valid.
  3. The count of weights must equal len(prox_list); a mismatch raises ValueError.
  4. The weights must sum exactly to 1.0; approximate equality does not suffice. Any other sum raises ValueError.

For a prox_list with a single entry, the representative outcomes are:

  • weights=1 raises TypeError because the value is a scalar;
  • weights=[1] raises ValueError because the element it contains is integer-valued;
  • weights=[0.5, 0.5] raises ValueError because the count does not match; and
  • weights=[0.5] raises ValueError because the sum is not exactly one.

All checks on explicit weights must be completed before the gradient or any proximity operator is invoked or otherwise exercised. Consequently, malformed operators cannot mask an error caused by invalid weights. Once the weights have been validated, prox_list is separately checked for the required op attribute, likewise without invoking an operator. These checks made at construction time apply even when auto_iterate=False.

Iteration and result behavior

When auto_iterate=True, construction calls iterate() with its default limit of 150 updates. Iteration comes to an early stop when the get_cost method of a supplied cost object reports convergence; otherwise it performs at most the requested number of updates. When no cost object is supplied, the callback updates on their own do not report convergence, so iterate() runs until its requested limit is reached.

Once iterate() has ended, x_final must be the primal array that was computed most recently. With auto_iterate=False, construction performs initialization and validation but does not automatically execute the gradient, proximity, callbacks, or cost method. The caller can afterwards invoke update() or iterate(), and iterate() must then populate x_final.

Required identity behavior

The fixed-point scenario that is supported consists of:

  • a floating-point NumPy input x;
  • GradParent(x, identity, identity), for which the gradient at x is zero;
  • input values that are nonnegative; and
  • a proximity list that contains Positivity() and IdentityProx(), with the default equal weights.

In this scenario, x_final must be exactly equal to x element-for-element, rather than merely numerically close. This requirement applies in both of the following configurations:

  1. gamma_update and lambda_update are identity callables, and no cost object is required; and
  2. a cost object is supplied while the callbacks that update the parameters are omitted.

Compatibility and scope

GenForwardBackward must coexist with Condat in modopt.opt.algorithms. Nothing in the behavior or the public API of Condat is to change. In particular, the existing use of its constructor with x, y, grad, prox, prox_dual, linear, cost, and auto_iterate must remain accepted and operational.
