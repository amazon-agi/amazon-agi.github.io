Objective

Required Module Structure

Create a module convolve inside the modopt.math package such that:

  • from modopt.math import * exposes a convolve submodule.
  • The convolution functions described below are accessible as convolve.convolve(...) and convolve.convolve_stack(...) after that import.

The convolution functions must no longer be reachable through from modopt.image import * (i.e. convolve must not be part of the modopt.image public namespace).

Required Public API and Behavior

convolve.convolve(data, kernel, method='astropy')

Performs a 2D convolution of a single image array data with a kernel array of the same shape.

Parameters:

  • data: a 2D NumPy array.
  • kernel: a 2D NumPy array of the same shape as data.
  • method: string selecting the convolution backend, either 'astropy' or 'scipy'. Default is 'astropy'.

Return value: a 2D NumPy array of the same shape as data.

Behavior for the two methods (verified with the following inputs):

Given

data   = [[0, 1, 2], [3, 4, 5], [6, 7, 8]]
kernel = [[1, 2, 3], [4, 5, 6], [7, 8, 9]]

  • With method='astropy', the result must be:

    [[210., 201., 210.],
 [129., 120., 129.],
 [210., 201., 210.]]

    (i.e. a centered convolution with wrap-around/periodic boundary handling, normalized-off, producing a same-size output.)

  • With method='scipy', the result must be:

    [[ 14.,  35.,  38.],
 [ 57., 120., 111.],
 [110., 197., 158.]]

    (i.e. a same-size 2D convolution with zero-padded boundaries.)

convolve.convolve_stack(data, kernel, rot_kernel=False)

Performs convolution over a stack (first axis) of 2D images, convolving each 2D slice of data with the corresponding 2D slice of kernel.

Parameters:

  • data: a 3D NumPy array (a stack of 2D images along axis 0).
  • kernel: a 3D NumPy array of the same shape as data.
  • rot_kernel: boolean flag. When True, each kernel slice is rotated by 180 degrees before being convolved with the corresponding data slice. Default is False.

Return value: a 3D NumPy array of the same shape as data, where slice i is the convolution of data[i] with kernel[i] (or the rotated kernel[i]).

Each individual convolution must use the 'astropy' backend behavior described above.

Behavior (verified with the following inputs):

Given

data   = arange(18).reshape(2, 3, 3)
kernel = data + 1

  • With rot_kernel=False, the result must be:

    [[[ 210.,  201.,  210.],
  [ 129.,  120.,  129.],
  [ 210.,  201.,  210.]],
 [[1668., 1659., 1668.],
  [1587., 1578., 1587.],
  [1668., 1659., 1668.]]]

  • With rot_kernel=True, the result must be:

    [[[ 150.,  159.,  150.],
  [ 231.,  240.,  231.],
  [ 150.,  159.,  150.]],
 [[1608., 1617., 1608.],
  [1689., 1698., 1689.],
  [1608., 1617., 1608.]]]

Constraints

  • The functions must produce floating-point NumPy array outputs matching the values above.
  • Convolution results must preserve the input's spatial dimensions (same-size output).
  • No convolution-related functionality should remain accessible through modopt.image's public interface.

Define a set of reshaping transformations relating three representations of the same underlying data:

cube = arange(16).reshape((4, 2, 2))
layout = (2, 2)

          [ 1,  5,  9, 13],
          [ 2,  6, 10, 14],
          [ 3,  7, 11, 15]]

That is: the map places image 0 in the top-left tile, image 1 in the top-right tile, image 2 in the bottom-left tile, image 3 in the bottom-right tile, with each tile holding that image in its natural 2D layout. Module: modopt.signal.noise

add_noise(data, sigma=1.0, noise_type='gaussian')

Add noise to array-like data and return a new NumPy array.

  • With noise_type='gaussian' (the default), add independent Gaussian noise to every element. Generate a standard-normal array with the same shape as data, scale it by sigma, and add it to data.
    • sigma may be a scalar applied uniformly or an array-like collection of per-element scale factors that is broadcastable against data.
    • An array-like sigma consisting of ones must produce the same result as the scalar default 1.0 when starting from the same random state.
  • With noise_type='poisson', add an independent Poisson draw to each original element. For an element x, the result is x + P, where P is drawn from a Poisson distribution whose expected value is x. sigma is ignored in this mode.
  • Any other noise_type value must raise ValueError.
  • A sigma shape that cannot be broadcast against the shape of data must raise ValueError. This applies whether sigma is supplied by keyword or positionally; for example, a tuple such as (1, 1) is invalid when it is incompatible with the input shape.

Random values must come from NumPy's global random state (numpy.random), so seeding that state makes results reproducible.

thresh(data, threshold, threshold_type='hard')

Apply thresholding to array-like data and return a new NumPy array with the same shape.

  • With threshold_type='hard' (the default), set an element to zero only when its absolute magnitude is strictly less than threshold. Preserve elements whose magnitude is greater than or equal to threshold, including values exactly on the threshold boundary.
  • With threshold_type='soft', shrink each element toward zero by threshold, clamping its magnitude at zero. For each element x, the result is sign(x) * max(|x| - threshold, 0).
  • Any other threshold_type value must raise ValueError.

For input [[0,1,2],[3,4,5],[6,7,8]] with threshold 5, the expected results are:

  • Hard: [[0,0,0],[0,0,5],[6,7,8]]
  • Soft: [[0,0,0],[0,0,0],[1,2,3]]

    x_(n+1) = sum(w_i * z_(i,n+1) for i in range(N)).

  4. Complete the callback updates described above.

  5. If a cost object was supplied, call cost.get_cost(x_(n+1)) and record its convergence result.

The current gamma is the sole step-size factor in both the gradient term and the proximity extra_factor; no caller-supplied inverse-spectral-radius field is required in addition to it.

Weight defaults and validation

If weights is omitted, use equal floating-point weights, each equal to 1.0 / N.

If explicit weights are supplied, all of the following rules apply during construction:

  1. weights must be a collection such as a list, tuple, or NumPy array. A scalar or other non-collection value raises TypeError.
  2. Every weight must be a floating-point value. Integer-valued collections are not converted and raise ValueError, even if their length and sum would otherwise be valid.
  3. The number of weights must equal len(prox_list); a mismatch raises ValueError.
  4. The weights must sum exactly to 1.0; approximate equality is not sufficient. Any other sum raises ValueError.

For a one-item prox_list, representative outcomes are:

  • weights=1 raises TypeError because it is scalar;
  • weights=[1] raises ValueError because the explicit element is integer-valued;
  • weights=[0.5, 0.5] raises ValueError because the count does not match; and
  • weights=[0.5] raises ValueError because the sum is not exactly one.

All explicit-weight checks must be completed before invoking, or otherwise exercising, the gradient or any proximity operator. Thus malformed operators cannot mask an invalid-weight error. After weight validation, prox_list is separately checked for the required op attribute, also without invoking an operator. These construction-time checks apply even when auto_iterate=False.

Iteration and result behavior

With auto_iterate=True, construction calls iterate() with its default limit of 150 updates. Iteration stops early when a supplied cost object's get_cost method reports convergence; otherwise it performs at most the requested number of updates. If no cost object is supplied, callback updates alone do not report convergence, so iterate() runs to its requested limit.

At the end of iterate(), x_final must be the most recently computed primal array. With auto_iterate=False, construction performs initialization and validation but does not execute the gradient, proximity, callbacks, or cost method automatically. The caller can subsequently invoke update() or iterate(), and iterate() must then populate x_final.

Required identity behavior

The supported fixed-point scenario consists of:

  • a floating-point NumPy input x;
  • GradParent(x, identity, identity), whose gradient at x is zero;
  • nonnegative input values; and
  • a proximity list containing Positivity() and IdentityProx(), with default equal weights.

For this scenario, x_final must be exactly equal to x element-for-element, not merely numerically close. This requirement applies in both configurations:

  1. gamma_update and lambda_update are identity callables and no cost object is required; and
  2. a cost object is supplied while the parameter-update callbacks are omitted.

Compatibility and scope

GenForwardBackward must coexist with Condat in modopt.opt.algorithms. No behavior or public API of Condat is to change. In particular, its existing constructor use with x, y, grad, prox, prox_dual, linear, cost, and auto_iterate must remain accepted and operational.

Operator contracts

Parameter defaults and update semantics

p_n       = prox.op(x_n - beta_n * g_n)
