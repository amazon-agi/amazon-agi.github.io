Snapshot operations for the current volume

Snapshot operations are scoped to the volume that self.data['uri'] identifies. The snapshot collection endpoint is derived from that volume URI internally; callers do not supply a volume ID or URI. The endpoint matches <self.data['uri']>/snapshots/, but the helper calls specified below do not receive it as a uri keyword.

get_snapshots(self, start=0, count=-1, filter='', sort='')

Return the current volume's snapshots. Delegate to the snapshot collection helper's get_all, supplying all four arguments by keyword:

helper.get_all(start=start, count=count, filter=filter, sort=sort)

Examples:

get_snapshots(2, 500, 'name=TestName', 'name:ascending')
# helper.get_all(count=500, filter='name=TestName',
#                sort='name:ascending', start=2)

get_snapshots()
# helper.get_all(count=-1, filter='', sort='', start=0)
create_snapshot(self, resource, timeout=-1)

Create a snapshot for the current volume. Delegate to the snapshot collection helper's create, passing all arguments positionally in this order:

helper.create(resource, None, timeout, None, False)

For example:

create_snapshot({'name': 'Snapshot'}, 20)
# helper.create({'name': 'Snapshot'}, None, 20, None, False)
get_snapshot_by(self, field, value)

Find the current volume's snapshots by a field/value pair. Delegate directly to the base Resource.get_by, with the two arguments positional and unchanged:

Resource.get_by(field, value)

For example, get_snapshot_by('name', 'test name') delegates as get_by('name', 'test name'). Do not supply a volume URI or a uri keyword to this lookup.

Operations for repair

get_extra_managed_storage_volume_paths(self, start=0, count=-1, filter='', sort='')

Return the collection of extra managed storage volume paths. Delegate to ResourceHelper.get_all, with start and count as its first two positional arguments. Supply the fixed endpoint, filter, and sort by keyword:

helper.get_all(
    start,
    count,
    uri='/rest/storage-volumes/repair?alertFixType=ExtraManagedStorageVolumePaths',
    filter=filter,
    sort=sort
)

The default values are start=0, count=-1, filter='', and sort=''. In contrast to get_all and get_snapshots, this delegation passes start and count positionally.

repair(self, timeout=-1)

Repair the current volume, removing extra managed storage-volume paths. Construct this request body from the current instance:

{
    'resourceUri': self.data['uri'],
    'type': 'ExtraManagedStorageVolumePaths'
}

Then delegate, using the fixed endpoint and the language header:

helper.create(
    data,
    uri='/rest/storage-volumes/repair',
    timeout=timeout,
    custom_headers={'Accept-Language': 'en_US'}
)

The timeout defaults to -1, and a value supplied by the caller must be forwarded. repair does not accept a volume ID or URI.

Collection of attachable volumes

get_attachable_volumes(self, start=0, count=-1, filter='', query='', sort='', scope_uris='', connections='')

Return the volumes that are attachable for the requested connectivity constraints. A volume is attachable when it is shareable, or when it is non-shareable and is not attached.

The order of the parameters and their defaults form part of the public signature:

  1. start=0
  2. count=-1
  3. filter=''
  4. query=''
  5. sort=''
  6. scope_uris=''
  7. connections=''

Build the request URI as follows:

  • Begin with /rest/storage-volumes/attachable-volumes.
  • If connections is non-empty, append ?connections= with str(connections) directly following it. Apart from this, the query component is not added.

Delegate to ResourceHelper.get_all; start and count are passed positionally. The constructed URI and the remaining collection controls are passed by keyword; connections itself appears only in the URI and is not forwarded as a separate helper argument:

helper.get_all(
    start,
    count,
    uri=uri,
    filter=filter,
    query=query,
    sort=sort,
    scope_uris=scope_uris
)

With all defaults in place, the call is equivalent to:

helper.get_all(
    0,
    -1,
    uri='/rest/storage-volumes/attachable-volumes',
    filter='',
    query='',
    sort='',
    scope_uris=''
)

Legacy API that is removed and incompatible

The following legacy surface is removed intentionally by the refactor:

  • The name INVALID_VOLUME_URI at module level.
  • get(id_or_uri), used for fetching a volume by ID or URI.
  • get_snapshot(...), used for fetching a single snapshot by ID or URI.
  • The method delete_snapshot(...).
  • Explicit volume ID/URI parameters on the snapshot operations and on repair.
  • The resource/ID/URI argument that delete formerly accepted; deletion now always targets self.data['uri'].
  • Selecting the update target from an ID or URI supplied in the update payload; update targets self.data['uri'].

Callers must first work with a Volumes instance whose data identifies the current volume and then invoke the instance-scoped operation. The overloads that were removed, together with the module constant, must not be retained as compatibility aliases.
