Task: Add a params keyword argument and deprecate opts in the URL classes

Overview

Two public classes must accept image transformation parameters through a keyword argument named params. In the past, these parameters were passed via a keyword argument named opts. The opts argument must keep working but must be flagged as deprecated.

Public API Surface

UrlHelper

The constructor:

UrlHelper(domain, path, scheme="https", sign_key=None,
          sign_with_library_version=True, include_library_param=True,
          params=None, opts=None)

(Aside from domain and path being the first two positional arguments, this task places no constraint on the exact set and order of the other constructor arguments; the essential point is that both params and opts are accepted as keyword arguments.)

It must be possible to import the class such that UrlHelper('my-social-network.imgix.net', '/users/1.png', ...) works, and str(helper) produces the full URL string.

The existing methods set_parameter(key, value) and delete_parameter(key) must continue to operate on the parameters provided at construction time.

UrlBuilder

The method:

create_url(path, params=None, opts=None)

The parameters dictionary must also continue to be accepted by create_url as a positional second argument (i.e. create_url(path, {"or": 0})), which is treated as params.

Required Behavior

params keyword argument

Both UrlHelper.__init__ and UrlBuilder.create_url must accept a params keyword argument holding a dictionary of image transformation parameters. Whenever it is supplied, the resulting URL must include those parameters exactly as it previously did when they were passed via opts.

Examples of the expected URL output (for a builder/helper whose domain is my-social-network.imgix.net and with library-version signing disabled):

  • params={"w": 400, "h": 300} with path /users/1.png → https://my-social-network.imgix.net/users/1.png?h=300&w=400
  • params={"or": 0} with path /users/1.png → https://my-social-network.imgix.net/users/1.png?or=0
  • params={"hello world": "interesting"} with path demo.png → the parameter keys must be URL-escaped in the output.
  • params={"hello_world": "/foo\"> <script>alert(\"hacked\")</script><"} with path demo.png → the parameter values must be URL-escaped in the output.
  • params={"txt64": u"I cannøt belîév∑ it wors! 😱"} with path ~text → base64-variant parameters (keys ending in 64) must be base64-encoded, producing: https://my-social-network.imgix.net/~text?txt64=SSBjYW5uw7h0IGJlbMOuw6l24oiRIGl0IHdvcu-jv3MhIPCfmLE

When a signing key such as sign_key="FOO123bar" is provided together with params={"w": 400, "h": 300} on /users/1.png:

  • https://my-social-network.imgix.net/users/1.png?h=300&w=400&s=1a4e48641614d1109c6a7af51be23d18

Parameters passed via params at UrlHelper construction time must remain mutable through set_parameter and delete_parameter.

opts keyword argument (deprecated)

Both UrlHelper.__init__ and UrlBuilder.create_url must continue to accept an opts keyword argument. When opts is supplied, its dictionary must be used to produce the same URL output that would result if that same dictionary were supplied via params.

Whenever opts is supplied (whether or not params is also supplied), exactly one DeprecationWarning must be emitted. The text of the warning must contain the substring deprecated. When only params (or the positional parameters dictionary) is used, no warning may be emitted.

Precedence when both are supplied

When params and opts are both supplied, params takes precedence — the resulting URL must reflect the params values, and the values from opts must be ignored. Since opts was supplied, a single DeprecationWarning (as described above) must still be emitted.

Example: params={"w": 400, "h": 300} together with opts={"w": 500, "h": 400} on /users/1.png → https://my-social-network.imgix.net/users/1.png?h=300&w=400

No parameters

If none of params, opts, or a positional parameters dictionary is supplied, no DeprecationWarning is emitted, and the URL is generated without transformation parameters (the existing default behavior).

Task Description

Summary

Modify the imgix Python package so that, on both UrlBuilder and UrlHelper, the option that controls the ixlib library-identification query parameter is named include_library_param. The previous keyword, sign_with_library_version, remains a deprecated compatibility alias and must continue to control the same behavior while emitting a deprecation warning.

Apart from this rename, its warning behavior, and the explicit removal of sign_mode, the existing URL construction behavior must remain compatible.

Public API and Import Compatibility

The public objects listed here must be available:

  • the class imgix.UrlBuilder
  • the class imgix.UrlHelper
  • UrlHelper reachable via the established module import from imgix.urlhelper import UrlHelper
  • imgix._version.__version__, a string that contains the library version

At the package level, imgix.UrlHelper and imgix.urlhelper.UrlHelper must be the same class object. The established imgix.urlhelper module location must remain usable; as part of this change, it must not be renamed or moved.

The existing sharding constants imgix.SHARD_STRATEGY_CRC and imgix.SHARD_STRATEGY_CYCLE stay usable with UrlBuilder.

Renaming the Library Parameter

The new keyword: include_library_param

include_library_param is accepted by both constructors and defaults to True.

  • When include_library_param=True is passed, every URL that is generated includes an ixlib query parameter whose value is python- followed by the exact string in imgix._version.__version__.
  • With include_library_param=False, the generated URLs do not include an automatically added ixlib parameter.
  • Explicitly passing either value via include_library_param must not emit a warning attributable to that keyword.

For example, letting <version> stand for imgix._version.__version__:

imgix.UrlBuilder("assets.imgix.net", include_library_param=True).create_url("image.jpg")
# https://assets.imgix.net/image.jpg?ixlib=python-<version>

imgix.UrlBuilder("assets.imgix.net", include_library_param=False).create_url("image.jpg")
# https://assets.imgix.net/image.jpg

For both classes, leaving the option out is equivalent to include_library_param=True.

The deprecated keyword: sign_with_library_version

sign_with_library_version must continue to be accepted by both constructors as a deprecated compatibility keyword for this setting.

  • Supplying either True or False for the deprecated keyword emits one DeprecationWarning attributable to that keyword.
  • The lowercase substring deprecated is contained in the warning message.
  • Presence must be detected independently of truthiness, so passing False explicitly still emits the warning.
  • sign_with_library_version=True affects URLs the same way as include_library_param=True.
  • sign_with_library_version=False affects URLs the same way as include_library_param=False.
  • After the warning, construction and subsequent URL generation continue normally.
  • A UrlBuilder must not produce a duplicate warning just because it delegates URL serialization to UrlHelper.

UrlBuilder

Constructor

The first positional argument is either one domain string or a list or tuple of domain strings. Positional compatibility as it already exists is retained:

  1. The HTTPS flag is the second positional argument; it is equivalent to use_https and defaults to True.
  2. The signing key is the third positional argument; it is equivalent to sign_key and defaults to None.

The existing shard_strategy option stays supported. The renamed library option is accepted as a keyword. The following forms must work:

imgix.UrlBuilder("my-social-network.imgix.net", include_library_param=False)
imgix.UrlBuilder("my-social-network.imgix.net", True, "FOO123bar",
                 include_library_param=False)
imgix.UrlBuilder("assets.imgix.net", include_library_param=True)
imgix.UrlBuilder("assets.imgix.net", sign_with_library_version=True)   # warns
imgix.UrlBuilder("assets.imgix.net", sign_with_library_version=False)  # warns
imgix.UrlBuilder(["one.imgix.net", "two.imgix.net"])
imgix.UrlBuilder(("one.imgix.net", "two.imgix.net"))

By default, HTTPS is used. An http URL is generated by use_https=False; an https URL is generated by use_https=True, whether passed positionally or by keyword.

Creating URLs

The fully formed URL string is what create_url(path, params=..., opts=...) returns.

  • A parameter dictionary may be supplied as the second positional argument or via params.
  • The legacy opts keyword stays as an alternative input for parameters. A non-empty opts value emits one DeprecationWarning whose message contains deprecated.
  • When both non-empty params and opts are supplied, params takes precedence, and the supplied non-empty opts still causes its deprecation warning.
  • Falsy parameter values — numeric 0, for instance — are retained rather than discarded.
Sharding of Domains

Handling of domains remains unchanged:

  • A single string is treated as a single domain, not as a sequence of characters.
  • SHARD_STRATEGY_CRC selects a domain deterministically from the original image path, so using the same path repeatedly selects the same domain.
  • SHARD_STRATEGY_CYCLE selects domains in sequence, wrapping around to the first domain after the last.
  • With a single domain, either strategy always uses that domain.
  • An unrecognized strategy does not block URL creation and falls back to the first domain.

UrlHelper

Construction and Conversion to a String

UrlHelper takes a domain as its first positional argument and an image path as its second. In addition to include_library_param and its deprecated alias, it continues to accept scheme (default "https"), sign_key, params, and the legacy opts parameter input.

Examples:

from imgix.urlhelper import UrlHelper

helper = UrlHelper("assets.imgix.net", "image.jpg",
                   include_library_param=False)
str(helper)
# https://assets.imgix.net/image.jpg

helper = UrlHelper("assets.imgix.net", "image.jpg",
                   sign_with_library_version=True)
# construction emits one DeprecationWarning
str(helper)
# https://assets.imgix.net/image.jpg?ixlib=python-<version>

The fully formed URL is what str(helper) returns. scheme="http" generates an HTTP URL, whereas the default generates HTTPS.

params and opts follow the same precedence and legacy-warning behavior described for UrlBuilder.create_url: a non-empty opts emits one DeprecationWarning containing deprecated, and when both are supplied, non-empty params wins.

Mutating Parameters

The mutation methods that already exist stay available:

  • set_parameter(key, value) adds a parameter or replaces an existing one, affecting later calls to str(helper).
  • Numeric values, booleans, and None are retained and serialized using their string forms. Specifically, 0, False, and None serialize as 0, False, and None rather than the parameter being deleted.
  • delete_parameter(key) removes the parameter with that key. Removing a key that is not present is a no-op.
  • When automatic ixlib inclusion is disabled and no signing key is configured, removing all user parameters produces a URL with no query string.

URL-Generation Behavior That Stays Preserved

Beyond the rename, how either class serializes URLs must not change.

Path Handling
  • When an ordinary image path is missing its leading slash, the slash is added.
  • Non-ASCII characters in ordinary paths are UTF-8 percent-encoded, with path separators remaining intact. For example, /ǝ becomes /%C7%9D.
  • When a fully qualified source URL is supplied as the image path, it is treated as a web-proxy path and percent-encoded into the generated imgix URL rather than replacing the configured imgix domain.
  • For example, http://avatars.com/john-smith.png ends up as /http%3A%2F%2Favatars.com%2Fjohn-smith.png beneath the imgix domain.
  • Characters that are already preserved for web-proxy compatibility, ~ among them, remain preserved. Hence http://avatars.com/john~smith.png contains john~smith.png after encoding.
Query Parameter Handling
  • Percent-encoding is applied to query keys and values, including spaces, slashes, quotes, angle brackets, and script-like text.
  • Parameters are emitted in a deterministic lexicographic ordering of keys.
  • For a parameter whose key ends in 64, the UTF-8 value is automatically encoded as unpadded URL-safe Base64 before URL escaping. For example, txt64 with the value I cannøt belîév∑ it wors! 😱 serializes as SSBjYW5uw7h0IGJlbMOuw6l24oiRIGl0IHdvcu-jv3MhIPCfmLE.
  • The automatic ixlib value takes part in normal query construction and, when signing is enabled, in the signed content.

For example:

builder = imgix.UrlBuilder("my-social-network.imgix.net",
                           include_library_param=False)
builder.create_url("/users/1.png", {"w": 400, "h": 300})
# https://my-social-network.imgix.net/users/1.png?h=300&w=400
Signing

When sign_key is provided, the existing query-signing behavior stays unchanged:

  • The signature covers the escaped path and the complete, sorted query string, including ixlib when it is enabled.
  • Appended as the final s parameter is the resulting lowercase hexadecimal signature.
  • Signing works both with and without other query parameters, and for fully qualified web-proxy paths.

With automatic library-parameter inclusion disabled, the compatibility examples are:

sign_key="FOO123bar", path="/users/1.png"
https://my-social-network.imgix.net/users/1.png?s=6797c24146142d5b40bde3141fd3600c

sign_key="FOO123bar", path="/users/1.png", params={"w": 400, "h": 300}
https://my-social-network.imgix.net/users/1.png?h=300&w=400&s=1a4e48641614d1109c6a7af51be23d18

Removal of sign_mode Behavior

sign_mode is no longer a constructor keyword for either UrlBuilder or UrlHelper. Neither class should accept or interpret it, and no special deprecation-warning handling for sign_mode should be added. Normal query signing through sign_key is not altered by this removal.

Constraints and Non-Goals

  • Except for selecting the renamed library-parameter option and supporting its deprecated alias as specified, do not change URL generation.
  • Do not alter path escaping, parameter escaping and ordering, Base64 handling, signing, schemes, domain sharding, or parameter mutation behavior.
  • Successful construction or URL generation must not be interrupted by deprecation warnings.

UrlBuilder.create_url(path)

Behavior Requirements

Deprecation warning when multiple domains are supplied

  • The category of the warning must be DeprecationWarning (or a subclass thereof).

CRC strategy (SHARD_STRATEGY_CRC): The domain chosen is deterministic per path — the same path always maps to the same domain in the collection. Different paths may map to different domains. Calling repeatedly with the same path always yields the same domain. Concretely, for a collection of two domains [d0, d1]:

  • /users/1.png and /users/2.png map to d0.
  • /users/a.png and /users/b.png map to d1.

For a collection of three domains [d0, d1, d2], successive calls select d0, d1, d2, d0, d1, d2, … in that order regardless of the path passed.

Notes

The URL structure, signing, path handling, and single-domain behavior stay the same. The only new behavior is the emission of the deprecation warning when multiple domains are given; all existing sharding results must remain identical.

Task Specification: Adding srcset Generation to imgix.UrlBuilder

Overview

Add a new public method create_srcset to the UrlBuilder class in the imgix package. The method generates a srcset string that is suitable for use in the srcset attribute of an HTML <img> element. In addition, several deprecated features of the existing API must be removed.

Part 1: The create_srcset Method

Method Signature
class UrlBuilder:
    def create_srcset(self, path, params={}):
        ...
  • path: the image path, given as a string (e.g. 'image.jpg').
  • params: a dictionary holding imgix URL parameters (its default is an empty dict).
  • Returns: a single String.
Overall Output Format

The returned string is a list of entries delimited by commas (,). Splitting that string on , yields the individual entries. Each entry takes the form:

<URL> <descriptor>

A single space separates <URL> from <descriptor>. Taking index 1 after splitting an entry on a space yields the descriptor.

Each <URL> is built exactly the way create_url(path, params_for_this_entry) would build it, with the same builder configuration (domain, sign key, include_library_param, etc.). As a result, when a sign_key is configured, each URL includes a signature parameter s=<md5hex>, computed as the MD5 hex digest of the string created by concatenating the sign key, the path (including a leading /), and the query string portion of the URL (?... up to but not including the signature). The signature is the last query parameter.

Two output formats exist, and the choice between them is made automatically based on params.

Rules for Format Selection
  • When the params dictionary contains a w (width) key, OR when it contains both an h (height) key and an ar (aspect ratio) key, the DPR format is produced.
  • The width-pairs format is produced in all other cases — including when params is empty, when only h is provided, or when only ar is provided.
The Width-Pairs Format

This format produces exactly 31 entries.

The URL of each entry is built by inserting a w=<value> parameter (alongside any parameters passed in params), and the descriptor of each entry is <value>w (the width value followed by the letter w).

In order, the 31 width values are exactly:

100, 116, 134, 156, 182, 210, 244, 282, 328, 380, 442, 512,
594, 688, 798, 926, 1074, 1246, 1446, 1678, 1946, 2258, 2618,
3038, 3524, 4088, 4742, 5500, 6380, 7400, 8192

Properties that these values must satisfy (all of them satisfied by the list above):

  • The smallest width is 100, the largest is 8192, and every width lies within the inclusive range [100, 8192].
  • The widths are strictly increasing, and every successive width is less than 1.18× the one preceding it (i.e. each step increases by strictly less than 18%).

All parameters supplied in params (e.g. h, ar) are included in every URL in addition to the generated w parameter.

The DPR Format

This format produces exactly 5 entries.

  • Each entry's URL is built from the same params (no per-entry width is generated). The URL is identical for all 5 entries (apart from being built once per entry with the same params).
  • The descriptors, in order, are: 1x, 2x, 3x, 4x, 5x (device pixel ratio 1 through 5, each followed by the letter x).

Part 2: Removal of Deprecated Behavior

The previously supported features listed below must be removed entirely from the public API. After this change, the corresponding parameters/behaviors no longer exist:

  1. opts keyword argument — Remove support for the opts keyword argument from UrlBuilder.create_url and from the UrlHelper constructor (imgix.urlhelper.UrlHelper). These callables must no longer accept an opts parameter. The params keyword argument remains supported.

  2. Domain sharding — Remove the shard_strategy constructor argument as well as the SHARD_STRATEGY_CRC and SHARD_STRATEGY_CYCLE module-level constants, and also remove support for passing multiple domains (domains as a list/tuple) to UrlBuilder.

  3. sign_with_library_version keyword argument — Remove this constructor argument from UrlBuilder. Only include_library_param controls library-version inclusion.

Retained and Confirmed Existing Behavior

The following must continue to work (left unchanged by this task):

  • imgix.UrlBuilder(domain, sign_key=..., include_library_param=...), where domain is a string.
  • builder.create_url(path), builder.create_url(path, params), and builder.create_url(path, params={...}).
  • When include_library_param=True (the default), URLs include an ixlib=python-<version> parameter; when it is False, they do not.
  • URLs are signed via sign_key, as described above.
  • The imgix.urlhelper.UrlHelper constructor accepting a domain, path, include_library_param, and params.

In the generated URLs, query parameters are ordered such that the signature parameter s= (when present) appears last, and the other parameters appear in a consistent (sorted) order before it.

Handling of boundaries

stop acts as an inclusive boundary against the actual integer widths. A width equal to stop is included; a width greater than the raw stop does not get included just because it is nearby. The boundary must not be rounded up and must not be passed through an “ensure even” adjustment. As a result:

  • stop=7401 includes the canonical width 7401 while 8192 is excluded.
  • stop=4087 includes the canonical width 4087; that width must not be changed to 4088.
  • The list that is produced is no longer restricted to even integers.

With a custom progression, widths grow according to 1 + 2 * (tol / 100), are emitted as nearest integers with no even-number normalization, and include the requested terminal width when a further progression step would pass it. The generation of widths must not exceed IMAGE_MAX_WIDTH.

  • Bounds that are equal are valid. target_widths(start=328, stop=328) returns [328].
  • When the tolerance is large enough to jump directly beyond the supported range, both endpoints are still preserved. As an example, target_widths(tol=10000000000) returns [100, 8192].
  • The result is made up of ascending integer widths.

  • The values start and stop must be numeric and greater than zero.
  • The value of stop must be no greater than 8192.
  • start must be less than or equal to stop; equality is permitted.
  • The value of tol must be numeric and at least 1.

Overview

Responsive imgix URL generation is to be implemented through UrlBuilder. The class must remain importable as:

Every example below uses HTTPS and include_library_param=False, so its basic URL form is:

https://<domain>/<path>?<query>

Candidate generation must preserve the established create_url behavior for path and query escaping, Base64-variant parameters, optional signing, scheme selection, and the library parameter. The method returns a single string. Candidate entries are joined with exactly ",\n" (a comma followed by a newline); there is no trailing comma or newline.

params supplies the query parameters that must be kept in every candidate unless a generated candidate parameter intentionally replaces the same key. Generating a srcset must not mutate the caller's dictionary.

Precedence for mode selection

The output mode is determined by the following precedence:

  1. A widths list that is non-empty selects explicit custom-width mode.
  2. Otherwise, fixed-size DPR mode is selected whenever params contains either:
    • a w key, or
    • both an h key and an ar key.
  3. All calls beyond those cases use generated width-descriptor mode.

The trigger is a matter of key presence. Consequently, h by itself and ar by itself use width-descriptor mode, whereas h and ar together use DPR mode. A w key also selects DPR mode, whether or not h is present.

Mode 1: Custom widths given explicitly

If widths is given a non-empty list of integer widths, produce one candidate for each width, in the list's original order:

<URL with w=<width>> <width>w

For each candidate, the generated w value replaces any w value found in the copied parameters. Explicit widths take precedence over widths generated from start/stop/tol and over automatic DPR-mode inference.

builder = UrlBuilder("testing.imgix.net", include_library_param=False)

https://testing.imgix.net/image.jpg?w=320 320w,
https://testing.imgix.net/image.jpg?w=446 446w,
https://testing.imgix.net/image.jpg?w=640 640w
Mode 2: Generated width descriptors

When no explicit widths are given and the fixed-size conditions are not met, target widths are generated from start through stop.

  • start is the first width, inclusive, and defaults to 100.
  • stop is the final width, inclusive, and defaults to 8192.
  • tol is a fractional relative tolerance whose default is 0.08, meaning 8 percent.

The target widths are produced according to these rules:

  1. Emit start as the first value.
  2. For every subsequent step, multiply the unrounded current value by 1 + 2 * tol.
  3. Each value emitted by the geometric sequence is rounded to the nearest integer.
  4. If the final generated value is below stop, append stop exactly, so that the upper bound is inclusive.
  5. If start == stop, only that one width is returned.

Each width then takes the form:

<URL with w=<width>> <width>w

A tolerance is given as a fraction, not as an integer percentage:

  • Numeric values of both integer and floating-point kind are accepted.
  • The minimum valid tolerance is 0.01 (1 percent), represented by SRCSET_MIN_WIDTH_TOLERANCE.

  • When tol is applied there is no percentage conversion and no division by 100; the growth factor is 1 + 2 * tol directly.
