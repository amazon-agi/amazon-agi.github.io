Aim

Introduce non-negative integer exponentiation into the existing mutable, single-variable polynomial types of the polynomial package. The ** and **= operations being added must integrate with the package's existing construction, normalization, arithmetic, equality, calculus, containment, and formatting behavior as described below.

Public package and class names

The names below must remain directly importable from polynomial:

from polynomial import (
    Polynomial,
    ZeroPolynomial,
    Constant,
    Monomial,
    LinearBinomial,
    QuadraticTrinomial,
)

The exponentiation requirements apply directly to four types: Polynomial, Monomial, Constant, and ZeroPolynomial. LinearBinomial(a, b) stands for a*x + b, and QuadraticTrinomial(a, b, c) stands for a*x^2 + b*x + c; the public construction and representations these already have must stay compatible.

Current polynomial representation and construction

Construction from coefficients

Polynomial models a polynomial in the single variable x. Coefficients are accepted in descending degree order, given either as positional arguments or as a single iterable:

Polynomial(1, 2, 3)
Polynomial([1, 2, 3])
Polynomial(range(1, 4))

Each of these stands for x^2 + 2x + 3. When construction happens from another polynomial, as in Polynomial(existing_polynomial), the corresponding polynomial value is created. Strings are accepted as coefficient iterables: Polynomial("abc") and Polynomial(*"abc") both stand for the coefficients a, b, and c in descending degree order.

Given from_monomials=True, construction accepts monomial objects or (coefficient, degree) pairs, supplied either inside an iterable or as the terms passed in directly. For example:

Polynomial([(1, 2), (2, 1), (3, 0)], from_monomials=True)

gives a value equal to Polynomial(1, 2, 3). Terms that share a degree are combined additively.

Canonicalization removes leading zero coefficients without changing the value represented. Therefore:

Polynomial(0, 0, 1, 2, 3, 0) == Polynomial(1, 2, 3, 0)

and both values share the same degree, terms, string form, and representation. Zero coefficients at lower degrees still take up their degree positions.

Defaults and the specialized constructors
  • Polynomial() produces a zero polynomial value.
  • Monomial(coefficient, degree) stands for coefficient*x^degree.
  • Monomial() has the same meaning as Monomial(1, 1), i.e. x.
  • Constant(value) stands for a degree-zero value.
  • Constant() has the same meaning as Constant(1).
  • ZeroPolynomial() is the specialized value for a zero polynomial.
Observable structure

For a polynomial p:

  • p.degree gives its highest nonzero degree. Every zero form — Polynomial(), Constant(0), and ZeroPolynomial() included — has degree -math.inf.
  • p.terms is a list of the nonzero (coefficient, degree) pairs in descending-degree order.
  • p.monomials presents that same descending sequence as Monomial objects.
  • p[k] accesses the coefficient of degree k, where p[0] denotes the constant coefficient. This degree-based indexing makes the coefficients mutable. Assigning zero to the current leading coefficient must normalize the value and reduce its degree. For instance, performing p[p.degree] = 0 on Polynomial(1, 2, 3) gives the same observable polynomial as Polynomial(2, 3).

Current calculus behavior

p.derivative returns the standard power-rule derivative as a new polynomial. Example:

Polynomial(1, 2, 3).derivative == Polynomial(2, 2)

Differentiating a constant, or any zero polynomial, gives a ZeroPolynomial value.

p.nth_derivative(n) is defined for every non-negative integer n and returns a new polynomial equal to derivative applied exactly n times:

  • nth_derivative(0) is a copy of p with nothing changed, and it does not mutate p.
  • nth_derivative(1) is equal to p.derivative.
  • After the degree has been exhausted, the result is zero and stays zero for higher derivative orders.
  • Invoking it must not mutate p.

Current equality and scalar conversion behavior

Equality between polynomials compares normalized polynomial values: once leading zeros have been removed canonically, coefficients must match at the same degrees. For the equality and zero comparisons described here, the corresponding inequality result is the logical opposite.

Every representation of the zero polynomial compares equal to numeric zero of the built-in integer, floating-point, and complex forms:

Constant(0) == Polynomial() == ZeroPolynomial() == 0
Constant(0) == Polynomial() == ZeroPolynomial() == 0.0
Constant(0) == Polynomial() == ZeroPolynomial() == 0j

A polynomial that is nonzero does not compare equal to numeric zero.

A Constant compares equal to the scalar value it holds, exposes that value through .const, and supports the corresponding built-in conversions:

int(Constant(69)) == 69
float(Constant(4.2)) == 4.2
complex(Constant(4.2 - 69j)) == 4.2 - 69j

Equality in general is value-oriented: differently specialized polynomial classes can compare equal when they represent the same terms. However, wherever this specification requires an operation to return a particular effective type such as Constant, Monomial, or ZeroPolynomial, it is not sufficient to return only an algebraically equal value whose specialized representation is different.

Current arithmetic behavior

The operators already present accept polynomial operands and numeric constants (int, float, and complex) wherever applicable. Direct, reflected, and augmented forms must keep agreeing in value.

Addition and subtraction

+, -, +=, and -= carry out ordinary coefficient-wise polynomial arithmetic, aligning equal degrees and normalizing leading zeros. Reflected forms with scalars are supported. Some examples include:

Polynomial(1, 1, 1) + Polynomial(2, 2) == Polynomial(1, 3, 3)
Polynomial(1, 1, 1) + 2 == 2 + Polynomial(1, 1, 1) == Polynomial(1, 1, 3)
Polynomial(3, 3, 3) - 2 == Polynomial(3, 3, 1)
2 - Polynomial(3, 3, 3) == Polynomial(-3, -3, -1)

The augmented forms give the same normalized result. Adding any zero, whether numeric or polynomial, leaves the value unchanged. Subtracting a polynomial from itself gives a normalized general zero value equal to both Polynomial() and ZeroPolynomial().

Multiplication

*, reflected *, and *= carry out ordinary polynomial multiplication via coefficient convolution. Example:

Polynomial(1, 2, 3) * Polynomial(1, 2, 3) == Polynomial(1, 4, 10, 12, 9)
Polynomial(1, 1, 1) * 10 == 10 * Polynomial(1, 1, 1) == Polynomial(10, 10, 10)

When a multiplication that is not in place involves a zero operand, it returns a ZeroPolynomial. By contrast, multiplying a general Polynomial in place by ZeroPolynomial(), 0, 0.0, or 0j sets its value to zero but keeps it a general Polynomial, represented as Polynomial() instead of downcasting it to ZeroPolynomial.

Ordinary multiplication between two Constant objects keeps its existing monomial-typed result. Exponentiation is an explicit exception to this behavior, as described below.

Polynomial division quotient and remainder

divmod(dividend, divisor) carries out polynomial long division and returns a (quotient, remainder) pair. It must support exact division, a nonzero remainder, divisors that are constants or monomials, and a divisor with a degree exceeding the dividend's degree. In particular, the values returned are mathematically equal to the following:

divmod(Polynomial(1, 4, 4), Polynomial(1, 4, 4))
# (Polynomial(1), Polynomial())

divmod(Polynomial(1, 4, 4), Polynomial(1, 2))
# (Polynomial(1, 2), Polynomial())

divmod(Polynomial(1, 2, 3), Polynomial(1, 2))
# (Polynomial(1, 0), Polynomial(3))

divmod(Polynomial(1, 2, 3), Constant(5))
# (Polynomial(1/5, 2/5, 3/5), Polynomial())

divmod(Polynomial(1, 2, 3), Monomial(1, 10))
# (Polynomial(), Polynomial(1, 2, 3))

The quotient comes from // and //=, the remainder from % and %=, and the augmented forms update the left operand consistently.

Current containment behavior

candidate in p operates on polynomial terms, not on evaluated values or a contiguous coefficient slice. The forms accepted as candidates are:

  • a single (coefficient, degree) tuple;
  • a list or set made up of such tuples; or
  • another polynomial, whose nonzero terms are used.

Containment is true exactly when each candidate term occurs in p with both its coefficient and its absolute degree matching. Proper subsets and non-contiguous subsets are permitted. Containment is therefore directional, and moving otherwise identical coefficients to different degrees changes the outcome. For instance, all of the following are contained in Polynomial(1, 2, 3):

(1, 2)
[(1, 2), (3, 0)]
{(2, 1), (3, 0)}
Polynomial([(1, 2), (2, 1)], from_monomials=True)

A candidate is not contained when even one of its terms is missing from p or mismatched.

Current representations

repr

repr is built from normalized constructor syntax plus each coefficient's repr. A general nonzero polynomial shows its coefficients in descending order:

repr(Polynomial(0, 0, -2, 0, 4.6666666666, -(69 + 420j), -1, 1337))
# "Polynomial(-2, 0, 4.6666666666, (-69-420j), -1, 1337)"

repr(Polynomial("abcdef"))
# "Polynomial('a', 'b', 'c', 'd', 'e', 'f')"

For the general zero value and the specialized values, the exact constructor-style forms are:

Polynomial()
ZeroPolynomial()
Monomial(1, 2)
Constant(5)
LinearBinomial(5, 2)
QuadraticTrinomial(1, -4, 4)

Those forms are what repr(Polynomial()), repr(ZeroPolynomial()), repr(Monomial(1, 2)), repr(Constant(5)), repr(LinearBinomial(5, 2)), and repr(QuadraticTrinomial(1, -4, 4)) produce, respectively.

str

str outputs the conventional polynomial notation in descending order, written with x:

  • Terms with a zero coefficient are left out.
  • On nonconstant terms the coefficient 1 is omitted, whereas a constant 1 is displayed.
  • A nonconstant term whose coefficient is -1 is rendered as a short minus sign, with the 1 left off.
  • Degree one is written as x, not x^1; other positive degrees are written as x^n; constant terms have no variable suffix.
  • Between terms, negative real coefficients use - rather than + -.
  • Character coefficients are shown without quotes.
  • Complex coefficients keep their normal parenthesized string form.
  • Each zero-polynomial form is rendered as 0.

The required examples include:

str(Polynomial(3, -2, 0, 0)) == "3x^3 - 2x^2"
str(Polynomial(2, 0)) == "2x"
str(Polynomial(1, 2)) == "x + 2"
str(Polynomial(1, 0, 1)) == "x^2 + 1"
str(Polynomial(-1, 0, 2)) == "-x^2 + 2"
str(Monomial(5, 10)) == "5x^10"
str(Polynomial("abcdef")) == "ax^5 + bx^4 + cx^3 + dx^2 + ex + f"
str(ZeroPolynomial()) == "0"

For the example that mixes numeric and complex coefficients:

str(Polynomial(0, 0, -2, 0, 4.6666666666, -(69 + 420j), -1, 1337))

the result must be exactly:

-2x^5 + 4.6666666666x^3 + (-69-420j)x^2 - x + 1337

Exponentiation behavior required

Operators supported and the exponent domain

Exponentiation must be provided for Polynomial, Monomial, Constant, and ZeroPolynomial through both:

p ** n
p **= n

The right-hand operand n is required to be a non-negative integer. For every supported value, p ** n must return a fresh polynomial object; it must not mutate p, and its result must never be the same object as p.

p **= n must give the same observable result as assigning p = p ** n, including all of the value, normalization, and effective-type rules below.

Exponent zero

With exponent zero, every polynomial type returns the multiplicative identity in the form of a Constant(1), which includes the conventional zero-to-zero-power case in this API:

Constant(5) ** 0       # Constant(1)
Monomial(5, 10) ** 0   # Constant(1)
ZeroPolynomial() ** 0  # Constant(1)
Polynomial(1, 2, 3) ** 0  # Constant(1)

These results must match Constant(1) in value, degree, terms, monomials, str, and specialized repr.

Exponent one

With exponent one, every polynomial type returns a fresh copy that is equal to the operand and preserves its effective type and representation:

  • a Constant comes back as the corresponding Constant;
  • a Monomial comes back as the corresponding Monomial;
  • a ZeroPolynomial comes back as a ZeroPolynomial;
  • a general Polynomial comes back as a general Polynomial.

The object that is returned must not alias the operand.

Exponents of two and greater

When n >= 2, p ** n has the value of the product of n copies of p. Equivalently, stepping through successive positive powers, the expected value begins as a copy of p and is multiplied by p one additional time for each increment of the exponent. General polynomial results must match the corresponding repeated product in normalized coefficients, degree, terms, monomials, string form, and effective representation. Example:

Polynomial(1, 2) ** 2 == Polynomial(1, 4, 4)
Polynomial(1, 2, 3) ** 2 == Polynomial(1, 2, 3) * Polynomial(1, 2, 3)

Fresh-object behavior applies at every exponent — exponent one included, as well as all larger powers.

Result rules for specialized types

Exponentiation of Constant is deliberately constant-preserving. For every non-negative n, the result is a Constant, not the monomial-typed value that ordinary constant multiplication produces:

Constant(5) ** 2  # exactly the effective form Constant(25)

For a Monomial(coefficient, degree) with a positive n, the coefficient is raised to n, the degree is multiplied by n, and the result is a Monomial:

Monomial(5, 10) ** 2  # Monomial(25, 20)

At exponent two, this must match m * m in both value and effective type.

For a ZeroPolynomial:

ZeroPolynomial() ** 0  # Constant(1)
ZeroPolynomial() ** 1  # a fresh ZeroPolynomial()
ZeroPolynomial() ** 2  # ZeroPolynomial(), matching z * z

Every positive power of a ZeroPolynomial is a zero-polynomial value with the specialized ZeroPolynomial() representation.

Scope

What is required is only non-negative integer powers, in the forms p ** n and p **= n. Exponentiation that is negative, fractional, complex, multivariate, reflected, or modular lies outside this task. The existing multiplication semantics—including the monomial-typed result of ordinary Constant * Constant and the in-place/non-in-place zero distinction—must not be changed in order to deliver the exponentiation behavior.

All of the existing construction, normalization, inspection, arithmetic, calculus, comparison, conversion, and formatting behavior described below must remain compatible.

Public API

The name of the public package is polynomial. The imports below must work at package level:

from polynomial import (
    Polynomial,
    ZeroPolynomial,
    Constant,
    Monomial,
    LinearBinomial,
    QuadraticTrinomial,
)

ZeroPolynomial must remain instantiable with no arguments:

z = ZeroPolynomial()

Construction and Canonical Form

Polynomial

Coefficients are provided in descending degree order. Polynomial must accept either positional coefficients or a single iterable of coefficients, and these forms must be equivalent:

Polynomial(1, 2, 3) == Polynomial([1, 2, 3])
Polynomial(1.0, 2.0, 3.0) == Polynomial([1.0, 2.0, 3.0])
Polynomial(1j, 2j, 3j) == Polynomial([1j, 2j, 3j])
Polynomial(*"abc") == Polynomial("abc")

A string is handled as an iterable of character coefficients. Constructing from another polynomial must produce an equal polynomial value, and Polynomial() must construct the general zero polynomial.

When from_monomials=True is passed, construction must accept positional terms or a single iterable of terms in (coefficient, degree) form:

Polynomial([(1, 2), (2, 1), (3, 0)], from_monomials=True)
Polynomial((1, 2), (2, 1), (3, 0), from_monomials=True)

Both of these examples represent x^2 + 2x + 3.

Leading zero coefficients are removed canonically, and the degrees represented by the remaining coefficients stay unchanged. Therefore:

Polynomial(0, 0, 0, 1, 2, 3, 0) == Polynomial(1, 2, 3, 0)

The two values must also produce identical repr and str output.

Specialized Constructors
  • Monomial(coefficient=1, degree=1) represents coefficient * x^degree; as a result, Monomial() is equivalent to Monomial(1, 1) and renders as x.
  • Constant(const=1) represents a degree-zero constant; as a result, Constant() is equivalent to Constant(1).
  • LinearBinomial(a, b) represents ax + b.
  • QuadraticTrinomial(a, b, c) represents ax^2 + bx + c.
  • ZeroPolynomial() represents the zero polynomial.

Polynomial State and Introspection

Every polynomial exposes:

  • degree: the greatest degree that has a nonzero coefficient;
  • terms: a list of the nonzero (coefficient, degree) tuples, in descending-degree order;
  • monomials: those same nonzero terms as Monomial values, again in descending degree order;
  • degree-based coefficient indexing, in which p[d] reads and p[d] = value updates the coefficient of x^d.

Assigning zero to a leading coefficient must renormalize the polynomial and lower its degree. For example:

p = Polynomial(1, 2, 3)
p[p.degree] = 0
# p is now Polynomial(2, 3), representing 2x + 3

All forms of the zero polynomial, including Polynomial(), Constant(0), and ZeroPolynomial(), have a degree of negative infinity (-math.inf). A specialized zero polynomial has:

ZeroPolynomial().terms      # []
ZeroPolynomial().monomials  # []
ZeroPolynomial().degree     # -math.inf

Constants and Zero Polynomials

Reading const

A Constant exposes its scalar value via const. For a nonzero constant, this value compares equal to the scalar it represents.

On every ZeroPolynomial instance, const must always return the integer 0:

ZeroPolynomial().const  # 0
Assigning const

ZeroPolynomial.const is read-only. Any attempt to assign a value to it must raise AttributeError, including assignment of None, zero, or a nonzero value:

z = ZeroPolynomial()
z.const = None  # raises AttributeError

When an assignment fails, the value represented by the instance must not change.

Scalar Conversion

The corresponding built-in numeric conversions must be supported by a Constant:

int(Constant(69)) == 69
float(Constant(4.2)) == 4.2
complex(Constant(4.2 - 69j)) == 4.2 - 69j

The specialized zero value converts into 0, 0.0, and 0j, respectively.

Equality and Inequality

Polynomial equality is determined by normalized polynomial value rather than by construction form. For the corresponding equality cases, inequality must be the logical opposite.

In particular:

  • Normalized coefficient/degree pairs that are equal compare equal.
  • A nonzero polynomial is not equal to numeric zero.
  • The values Polynomial(), Constant(0), and ZeroPolynomial() compare equal to one another.
  • Every zero-polynomial form compares equal to the integer 0, the float 0.0, and the complex 0j.
  • A nonzero Constant(value) compares equal to the scalar value it represents.

Differentiation

derivative returns a new polynomial computed with the ordinary power rule. Example:

Polynomial(1, 2, 3).derivative == Polynomial(2, 2)

The derivative of a constant or of any zero polynomial is a zero polynomial.

nth_derivative(n) is defined for every non-negative integer n, and it must:

  • return a new, equal polynomial when n == 0;
  • apply derivative exactly n times;
  • return zero as soon as the polynomial's degree has been exhausted; and
  • leave the source polynomial unchanged.

Addition, Subtraction, and Multiplication

Addition, subtraction, and multiplication must carry out ordinary polynomial coefficient arithmetic. Each operation must support another polynomial or an int, float, or complex scalar in its direct, reflected, and in-place forms where applicable (+, -, *, +=, -=, and *=).

Representative results include the following:

Polynomial(1, 1, 1) + Polynomial(2, 2) == Polynomial(1, 3, 3)
Polynomial(3, 3, 3) - 2 == Polynomial(3, 3, 1)
2 - Polynomial(3, 3, 3) == Polynomial(-3, -3, -1)
Polynomial(1, 2, 3) * Polynomial(1, 2, 3) == Polynomial(1, 4, 10, 12, 9)

The direct, reflected, and in-place forms must agree in polynomial value. The in-place forms mutate their left operand. Results must come out normalized: cancellation or subtraction may lower the degree or produce zero, and adding zero must preserve the original value.

Multiplication by Zero

Multiplication by zero that is not in place must return a ZeroPolynomial-typed result. This holds regardless of operand order and covers numeric zero, a general zero polynomial, ZeroPolynomial, and zero-valued Monomial/Constant operands.

In particular, multiplying two specialized zero polynomials must succeed without raising an exception:

z = ZeroPolynomial()
product = z * z

product must be a new ZeroPolynomial having all of the following observable properties:

repr(product) == "ZeroPolynomial()"
str(product) == "0"
product.terms == []
product.monomials == []
product.degree == -math.inf
product == z ** 2

In contrast, in-place multiplication must not downcast a general Polynomial instance. When a general polynomial is multiplied in place by zero, it remains a general Polynomial object whose normalized value is zero (and whose general representation is Polynomial()).

Polynomial Division

divmod(dividend, divisor) must perform polynomial long division and return (quotient, remainder), such that the dividend is equal in value to divisor * quotient + remainder and any nonzero remainder has lower degree than the divisor.

The required cases include:

divmod(Polynomial(1, 4, 4), Polynomial(1, 4, 4))
# (Polynomial(1.0), Polynomial())

divmod(Polynomial(1, 4, 4), Polynomial(1, 2))
# (Polynomial(1.0, 2.0), Polynomial())

divmod(Polynomial(1, 2, 3), Polynomial(1, 2))
# (Polynomial(1.0, 0), Polynomial(3))

divmod(Polynomial(1, 2, 3), Constant(5))
# (Polynomial(0.2, 0.4, 0.6), Polynomial())

divmod(Polynomial(1, 2, 3), Monomial(1, 10))
# (Polynomial(), Polynomial(1, 2, 3))

Dividing by a zero polynomial must raise ZeroDivisionError.

The operators relate to one another as follows:

  • a // b returns the quotient that divmod(a, b) returns;
  • a % b returns the remainder;
  • a //= b mutates a into the quotient; and
  • a %= b mutates a into the remainder.

Membership

candidate in polynomial performs a check for term containment. A candidate may be:

  • a single (coefficient, degree) tuple;
  • a list or set of tuples of that form; or
  • another polynomial, in which case the nonzero terms it contains are used.

Containment holds exactly when every candidate term occurs in the target with both coefficient and degree matching. The candidate terms may form a proper subset and need not be contiguous. For example, each of the following is contained in Polynomial(1, 2, 3):

(1, 2)
[(1, 2), (2, 1)]
[(1, 2), (3, 0)]
{(1, 2), (2, 1), (3, 0)}
Polynomial([(1, 2), (3, 0)], from_monomials=True)

Containment is directional. The terms of a smaller polynomial can be contained in a larger polynomial while the reverse does not hold. Degree takes part in each match, so coefficient sequences shifted to different degrees do not contain one another. If even one candidate term fails to match, containment is false.

Exponentiation

The ** operator must support non-negative integer exponents for Polynomial, Constant, Monomial, and ZeroPolynomial values.

  • For every supported value, an exponent of zero returns Constant(1), including ZeroPolynomial() ** 0.
  • An exponent of one returns a new object, distinct from the source, with the same effective polynomial type and all the same observable polynomial properties.
  • Positive powers neither mutate nor alias the source.
  • Higher powers hold the same mathematical value as repeated multiplication.

Power results with specialized types must be preserved:

Constant(5) ** 2 == Constant(25)
Monomial(5, 10) ** 2 == Monomial(25, 20)
ZeroPolynomial() ** 2 == ZeroPolynomial()

The constant result must remain a Constant, the monomial result a Monomial, and the zero result a ZeroPolynomial. Squaring a general polynomial must agree with its self-product in normalized value, representation, terms, monomials, and degree. Squaring zero must likewise agree with the valid ZeroPolynomial() * ZeroPolynomial() result.

For a general polynomial, the result for every positive exponent must be a distinct polynomial object equal to the corresponding repeated product. Non-integer and negative exponents stay unsupported and raise ValueError.

Representations

repr

repr must emit normalized constructor-style syntax and apply repr to each coefficient:

  • For general nonzero values: Polynomial(c_n, ..., c_0).
  • For the general zero value: Polynomial().
  • For specialized values: exactly ZeroPolynomial(), Monomial(coefficient, degree), Constant(value), LinearBinomial(a, b), and QuadraticTrinomial(a, b, c).

Examples:

repr(Polynomial("abcdef"))
# "Polynomial('a', 'b', 'c', 'd', 'e', 'f')"

repr(Polynomial([0, 0, -2, 0, 4.6666666666, -(69 + 420j), -1, 1337]))

repr(ZeroPolynomial())                 # "ZeroPolynomial()"

repr(Constant(5))                     # "Constant(5)"
repr(LinearBinomial(5, 2))            # "LinearBinomial(5, 2)"
repr(QuadraticTrinomial(1, -4, 4))    # "QuadraticTrinomial(1, -4, 4)"
str

str must render the conventional descending polynomial notation:

  • leave out zero-coefficient terms;
  • separate ordinary positive terms using + and negative numeric terms using -;
  • write a leading - with no extra space for a negative first term;
  • suppress coefficients 1 and -1 on nonconstant terms while keeping unit constant terms;
  • render degree one as x, other positive degrees as x^n, and degree zero with no variable;
  • render character coefficients with no quotes;
  • keep the normal parenthesized string form of complex coefficients; and
  • render every zero polynomial as 0.

Examples:

str(Polynomial(1, 2))                    # "x + 2"

Adding, subtracting, multiplying

Ordinary coefficient arithmetic is something polynomials support, both with other polynomials and with integer, floating-point, and complex constants. The direct form, the reflected form, and the in-place form must agree in value:

  • p + q, q + p, and p += q
  • p + c, c + p, and p += c
  • p - q and p -= q
  • p - c, c - p, and p -= c
  • p * q, q * p, and p *= q

The last zero in this example is a meaningful degree-zero slot; only leading high-degree zeroes are removed. Construction and subsequent operations must keep the value normalized in this way.

Value model and introspection for polynomials

A polynomial is a sum of terms coefficient * x**degree, where degrees are non-negative integers. Its normalized value is described by the following public interfaces:

  • degree is the largest degree with a nonzero coefficient. Every zero value (Polynomial(), ZeroPolynomial(), and Constant(0)) has degree negative infinity (-math.inf).
  • terms is a list of the nonzero (coefficient, degree) pairs, ordered by descending degree.
  • monomials is the corresponding list of Monomial objects, also in descending degree order.
  • Accessing p[k] gets the coefficient at degree k, not the coefficient at positional index k. Assignment via p[k] = value updates that degree. Zeroing the leading coefficient lowers the degree, and degree, terms, monomials, repr, and str immediately reflect the change; zeroing every term produces a normalized zero value.

Derivative behavior

derivative returns a new polynomial computed with the ordinary power rule. For example:

nth_derivative(n) is defined for every non-negative integer n and returns a new polynomial created by applying derivative exactly n times. In particular:

  • nth_derivative(0) produces a new value equal to the original.
  • The outcome of nth_derivative(1) equals derivative.
  • After the degree is exhausted, this method returns ZeroPolynomial(), including for still higher derivative orders.
  • The source polynomial is not mutated by calling it.

Operators that shift degree

Implement the following operators on the polynomial types:

  • __lshift__(self, n) implements p << n and returns a new object;
  • __rshift__(self, n) implements p >> n and returns a new object;
  • __ilshift__(self, n) implements p <<= n;
  • __irshift__(self, n) implements p >>= n.

The shift amount n is an integer; it may be positive, negative, or zero. For every term coefficient * x**degree:

  • under p << n, its degree maps to degree + n;
  • under p >> n, its degree maps to degree - n;
  • a negative amount reverses the direction: p << -n has the value of p >> n, and p >> -n has the value of p << n;
  • shifting by zero produces a new value equal to the original; augmented assignment by zero likewise preserves the value.

The only effect of these operations is to shift degrees. They must not apply a bit shift to any coefficient.

Dropping terms that would fall below degree zero

When a shifted term would have a negative degree, that term is dropped completely; it is not retained as a negative-degree or fractional term. When every term is dropped, the result is zero. The rule applies both to a positive right shift and to a negative left shift.

Behavior of a general Polynomial

For a general Polynomial, raising degrees appends zero coefficient slots at lower degrees, while lowering degrees removes slots that pass below degree zero:

Polynomial(1, 3, 5) << 3   == Polynomial(1, 3, 5, 0, 0, 0)
Polynomial(1, 3, 5) << 1   == Polynomial(1, 3, 5, 0)
Polynomial(1, 3, 5) << -1  == Polynomial(1, 3)

Polynomial(1, 3, 5) >> 1   == Polynomial(1, 3)
Polynomial(1, 3, 5) >> 3   == Polynomial()
Polynomial(1, 3, 5) >> -1  == Polynomial(1, 3, 5, 0)

A shift that goes past the entire polynomial returns the general zero Polynomial():

Polynomial(*range(1, 11)) >> 15   == Polynomial()
Polynomial(*range(1, 11)) << -15  == Polynomial()

The augmented-assignment counterparts must produce the same resulting values. For augmented assignment on an ordinary Polynomial, there is no object-identity requirement.

Behavior of Monomial, Constant, and the zero value

A nonzero Monomial that stays at a non-negative degree returns a Monomial with the same coefficient and adjusted degree, including when the adjusted degree is zero:

Monomial(1, 5) << 10    == Monomial(1, 15)
Monomial(1, 15) << -10  == Monomial(1, 5)
Monomial(1, 5) >> -10   == Monomial(1, 15)
Monomial(1, 15) >> 10   == Monomial(1, 5)
Constant(5) << 10       == Monomial(5, 10)

When a monomial or constant is shifted below degree zero, the result is ZeroPolynomial():

Monomial(1, 10) >> 15   == ZeroPolynomial()
Monomial(1, 10) << -15  == ZeroPolynomial()

Shifting a ZeroPolynomial in either direction still leaves a ZeroPolynomial value.

Augmented assignment and immutability of specialized instances

A shift carried out with <<= or >>= must never mutate an existing Constant or ZeroPolynomial instance. Augmented assignment must rebind the target to a new, distinct result object, leaving every alias to the original unchanged. The requirement covers both directions and every shift amount. For example:

c1 = c
c1 <<= 5

assert c == Constant(5)
assert c1 == Monomial(5, 5)
assert c1 is not c

z = ZeroPolynomial()
z1 = z
z1 <<= 5

assert z == ZeroPolynomial()
assert z1 == ZeroPolynomial()
assert z1 is not z

>>= falls under the same distinctness rule. Non-augmented << and >> always return new objects as specified above.

  • terms: a list containing all nonzero (coefficient, degree) pairs, ordered from the highest degree to the lowest degree.
  • monomials: a matching list of Monomial objects, in that same descending-degree order.

Coefficient indexing follows degree rather than descending display position: degree 0 addresses the constant coefficient. Assignment by degree is supported and must renormalize all dependent views. In particular:

p = Polynomial(1, 2, 3)
p[p.degree] = 0
# p is now equal to Polynomial(2, 3)

The resulting degree, terms, monomials, string form, and representation must all reflect that normalization. When arithmetic cancels leading terms or the entire polynomial, these views must be updated in the same way.

Operators for shifting degree

On the appropriate polynomial classes, implement the following methods:

  • __lshift__(self, other) for obj << n
  • __rshift__(self, other) for obj >> n
  • __ilshift__(self, other) for obj <<= n
  • __irshift__(self, other) for obj >>= n

n here is an integer, and it may be positive, negative, or zero. All four operators return the shifted object described below.

Semantics in general

A shift alters term degrees without changing term coefficients:

  • A left shift by n turns every degree d into d + n.
  • A right shift by n turns every degree d into d - n.
  • value << n and value >> -n are equivalent, as are value >> n and value << -n.
  • Shifting by zero produces a value equal to the original.
  • Any term whose resulting degree would be negative is dropped instead of a negative-degree term being created.

So a downward shift truncates terms below degree zero; it neither performs numeric bit shifting on coefficients nor creates Laurent-polynomial terms.

Behavior of the general Polynomial

Since the coefficients of a general polynomial run from highest degree to lowest degree:

  • A left shift with positive n appends n zero coefficients at the low-degree end.
  • A left shift with negative n drops the matching number of low-degree coefficient positions.
  • A right shift with positive n drops low-degree coefficient positions.
  • A right shift with negative n appends zero coefficients.

The following examples are required:

Polynomial(1, 3, 5) << 3   == Polynomial(1, 3, 5, 0, 0, 0)
Polynomial(1, 3, 5) << 1   == Polynomial(1, 3, 5, 0)
Polynomial(1, 3, 5) << -1  == Polynomial(1, 3)

Polynomial(1, 3, 5) >> 1   == Polynomial(1, 3)
Polynomial(1, 3, 5) >> 3   == Polynomial()
Polynomial(1, 3, 5) >> -1  == Polynomial(1, 3, 5, 0)

If a downward shift equals or exceeds the number of represented degree positions, every term is removed and the outcome is a general empty Polynomial, not a negative-degree value:

Polynomial(*range(1, 11)) >> 15   == Polynomial()
Polynomial(*range(1, 11)) << -15  == Polynomial()
Behavior of Monomial

For a monomial, a valid shift keeps the coefficient and returns a Monomial at the adjusted degree:

Monomial(c, d) << n  == Monomial(c, d + n)
Monomial(c, d) >> n  == Monomial(c, d - n)

These formulas hold only when the resulting degree is non-negative. Examples include the following:

Monomial(1, 5) << 10    == Monomial(1, 15)
Monomial(1, 15) << -10  == Monomial(1, 5)
Monomial(1, 5) >> -10   == Monomial(1, 15)
Monomial(1, 15) >> 10   == Monomial(1, 5)

When the resulting degree would be negative, the result is a ZeroPolynomial:

Monomial(1, 10) >> 15   == ZeroPolynomial()
Monomial(1, 10) << -15  == ZeroPolynomial()

A shift down to exactly degree zero remains a Monomial at degree zero.

Behavior of Constant and the zero value

A constant acts like a monomial at degree zero. Shifting it upward therefore produces a Monomial:

Constant(5) << 10  == Monomial(5, 10)

The corresponding negative right shift behaves the same way. Shifting downward past degree zero produces ZeroPolynomial(). A shift by zero stays equal to the original constant. Any amount of shifting applied to a ZeroPolynomial leaves a ZeroPolynomial value.

Categories of results and augmented assignment

The constructor categories shown above are required; mathematical equivalence alone does not suffice:

  • A shifted general Polynomial stays a general Polynomial, including when all terms are removed.
  • A shifted Monomial that survives is a Monomial.
  • A monomial shifted below degree zero is a ZeroPolynomial.
  • Shifting a constant upward gives a result that is a Monomial.

The result's normalized coefficients, degree, terms, monomials, str, and repr must be the same as those of the indicated target object.

<<= and >>= must produce the same resulting values as << and >>. For augmented shifts, Constant and ZeroPolynomial are immutable-valued: augmented assignment must return a new object instead of modifying an aliased original. For example:

c = Constant(5)
c1 = c
c1 <<= 5
assert c1 is not c

z = ZeroPolynomial()
z1 = z
z1 <<= 5
assert z1 is not z

Both augmented shift directions follow this same non-mutating rebinding rule.

Calculus operations

Applying the ordinary power rule to every term is what the derivative property does. For example:

Polynomial(1, 2, 3).derivative == Polynomial(2, 2)

The derivative of a constant, or of any zero representation, is ZeroPolynomial().

nth_derivative(n) returns the value that results from differentiating n times:

  • An equal, unchanged copy is returned for n=0.
  • Positive orders apply the power rule repeatedly.
  • After n exceeds the polynomial's degree, the result is ZeroPolynomial().
  • n is required to be a non-negative integer; invalid orders raise ValueError.

Equality, conversion to numbers, and membership

Equality

Equality and inequality are comparisons of normalized polynomial values, and != must be the logical opposite of ==. Differences in construction involving leading zeros have no effect on equality. All zero forms compare equal:

Polynomial() == ZeroPolynomial() == Constant(0) == 0
Polynomial() == 0.0
Polynomial() == 0j

A polynomial that is nonzero does not compare equal to numeric zero.

A Constant exposes its stored value through const, compares equal to the corresponding numeric value, and supports matching conversions through int(), float(), and complex(). So Constant(69).const == int(Constant(69)) == 69, with analogous float and complex behavior.

ZeroPolynomial.const returns numeric 0 at all times. The attribute is read-only; assigning to it must raise AttributeError.

Membership

item in polynomial tests for exact term containment. These are the accepted item forms:

  • one (coefficient, degree) tuple;
  • a list of such tuples;
  • a set of such tuples; or
  • another polynomial.

A collection or polynomial counts as contained exactly when every one of its complete coefficient-degree pairs occurs in the receiving polynomial. Subsets of terms are permitted, but a coefficient that matches at the wrong degree, a degree that matches with the wrong coefficient, or a pair that is otherwise partial is not a match. As an example, Polynomial(1, 2, 3) is contained in Polynomial(6, 5, 4, 1, 2, 3); adding a trailing zero, which shifts all three degrees, changes the terms and blocks containment in either direction. Membership item types that are unsupported raise ValueError.

Compatibility of arithmetic

Addition, subtraction, and multiplication

Coefficients are aligned by degree in addition and subtraction. Multiplication carries out ordinary coefficient convolution. Each operation supports another polynomial or an int, float, or complex value, where numeric values are treated as constants. The reflected operations and the augmented forms +=, -=, and *= must agree with the corresponding binary operations.

Representative results include the following:

Polynomial(1, 1, 1) + Polynomial(2, 2) == Polynomial(1, 3, 3)
Polynomial(3, 3, 3) - 2 == Polynomial(3, 3, 1)
2 - Polynomial(3, 3, 3) == Polynomial(-3, -3, -1)
Polynomial(1, 2, 3) * Polynomial(1, 2, 3) == Polynomial(1, 4, 10, 12, 9)

The polynomial value is preserved when numeric zero or ZeroPolynomial() is added. Subtracting a general polynomial from itself produces a normalized general Polynomial() value.

The binary multiplication of a polynomial with any zero polynomial or numeric zero returns ZeroPolynomial(). Augmented multiplication of a general Polynomial by zero, in contrast, keeps the receiver in the general-polynomial category while normalizing it to Polynomial(). Multiplying two Constant instances returns a Constant; multiplying compatible monomials preserves monomial behavior.

Quotient and remainder of polynomials

Polynomial long division is exposed via:

  • divmod(dividend, divisor), which returns (quotient, remainder);
  • // and //=, which select the quotient; and
  • % and %=, which select the remainder.

The quotient and remainder obey ordinary polynomial division; when the remainder is nonzero, its degree is lower than the divisor's. Examples:

divmod(Polynomial(1, 4, 4), Polynomial(1, 2))
# (Polynomial(1, 2), Polynomial())

divmod(Polynomial(1, 2, 3), Polynomial(1, 2))
# (Polynomial(1, 0), Polynomial(3))

When the divisor is a Constant or a numeric constant, every coefficient is scaled and the remainder is left zero:

divmod(Polynomial(1, 2, 3), Constant(5))
# (Polynomial(1/5, 2/5, 3/5), Polynomial())

If the divisor is a monomial whose degree is greater than the dividend's degree, the quotient returned is Polynomial() and the dividend value is left as the remainder. Division by a zero polynomial raises ZeroDivisionError.

Powers

** and **= are supported on polynomial values for non-negative integer powers. Powers that are non-integer or negative raise ValueError. Augmented exponentiation must be value-consistent with ordinary exponentiation.

  • An exponent of zero yields the multiplicative one: Constant(1) for a general polynomial, a constant, or a zero polynomial, while a plain Monomial yields Monomial(1, 0).
  • An exponent of one returns a fresh, equal result and preserves the operand's concrete category.
  • Higher powers are equal to repeated polynomial multiplication.
  • Constants stay Constant values.
  • For Monomial(c, d) ** n, the coefficient is c ** n and the degree is d * n.
  • ZeroPolynomial() ** n stays ZeroPolynomial() when n is positive.
  • For a general polynomial, higher powers are general polynomial products.

As examples, Constant(5) ** 2 == Constant(25) and Monomial(5, 10) ** 2 == Monomial(25, 20). A non-augmented power result must not be an alias of the original operand.

Representations

repr

Representations are built from reconstructable constructor syntax together with each coefficient's repr. For a general polynomial, coefficients appear in normalized descending-degree order, including zero positions at internal and low degrees:

repr(Polynomial(1, 2, 3)) == "Polynomial(1, 2, 3)"
repr(Polynomial("abcdef")) == "Polynomial('a', 'b', 'c', 'd', 'e', 'f')"
repr(Polynomial()) == "Polynomial()"
repr(ZeroPolynomial()) == "ZeroPolynomial()"

Specialized values keep their concrete constructor names:

repr(Monomial(1, 2)) == "Monomial(1, 2)"
repr(Constant(5)) == "Constant(5)"
repr(LinearBinomial(5, 2)) == "LinearBinomial(5, 2)"
repr(QuadraticTrinomial(1, -4, 4)) == "QuadraticTrinomial(1, -4, 4)"

In repr, character coefficients stay quoted, and complex coefficients use their normal Python repr, including parentheses where Python supplies them.

str

str renders polynomials in conventional descending notation:

  • Terms with zero coefficients are omitted.
  • x is used for degree one and x^n for other positive degrees.
  • A variable is not appended to the degree-zero term.
  • On nonconstant terms, a coefficient of 1 is suppressed, including rendering a leading -1 as a short -.
  • For a constant term, coefficient 1 is retained.
  • For a negative numeric term, - is rendered rather than + -, with spaces between terms.
  • Arbitrary character coefficients are prefixed directly to their variable terms.
  • The normal text and parentheses of complex coefficients are preserved.
  • Every zero polynomial value is rendered as 0.

Required examples:

str(Polynomial(-1, 0, 2)) == "-x^2 + 2"
str(Polynomial(1, 0, 1)) == "x^2 + 1"
str(Monomial(5, 10)) == "5x^10"
str(Polynomial("abcdef")) == "ax^5 + bx^4 + cx^3 + dx^2 + ex + f"

Constructing and normalizing polynomials

Building from coefficients

Coefficients are supplied in descending degree order. Polynomial accepts both of the following equivalent forms:

Polynomial(a, b, c, ...)
Polynomial([a, b, c, ...])

The one-argument form may be any iterable of coefficients; this includes a string, a generator, or another polynomial. As an example:

Polynomial([1, 2, 3]) == Polynomial(1, 2, 3)
Polynomial("abc") == Polynomial("a", "b", "c")
Polynomial(Polynomial(1, 2, 3)) == Polynomial(1, 2, 3)

Polynomial() produces the zero polynomial. In the normalized value, leading zero coefficients are stripped, whereas zero coefficients sitting between terms or at lower degrees keep their positional meaning. Hence:

Polynomial(0, 0, 1, 2, 3, 0) == Polynomial(1, 2, 3, 0)
Constructing from terms

A polynomial is built by Polynomial(terms, from_monomials=True) from an iterable of terms. Every term may be either a Monomial or a 2-tuple (coefficient, degree). Terms that share a degree contribute to the same coefficient. Within a tuple, the coefficient comes first and the exponent second.

Existing defaults of the specialized classes
  • Monomial(coefficient, degree) stands for coefficient * x^degree.
  • Monomial() is equivalent to Monomial(1, 1), and represents x.
  • Constant(value) stands for a degree-zero value.
  • Constant() on its own is equivalent to Constant(1).
  • ZeroPolynomial() stands for zero, and its value is equal to that of Polynomial() and Constant(0).

Normalized views and mutating coefficients

The following normalized public views are exposed by polynomial values:

  • degree: the greatest exponent that has a nonzero coefficient. Every representation of zero carries degree -math.inf.
  • terms: a list of the nonzero (coefficient, degree) pairs, in order from greatest degree to least degree.
  • monomials: a list of the corresponding Monomial objects, in that same descending-degree order.

As an example, Polynomial(1, 0, 3) has degree 2, terms [(1, 2), (3, 0)], and monomials equal to [Monomial(1, 2), Monomial(3, 0)].

For item access by degree, the exponent serves as the index. When a coefficient is assigned by degree, all normalized views must be updated. In particular, assigning zero as the leading coefficient lowers the degree and removes that leading term:

p = Polynomial(1, 2, 3)
p[p.degree] = 0
p == Polynomial(2, 3)

Arithmetic that cancels a leading term, or the entire polynomial, must normalize in the same way.

Equality, constant values, and zero

After normalization, polynomial equality is value-based, no matter whether the value is represented by Polynomial or by a specialized subclass. Inequality must always form the logical opposite of equality.

All forms of zero compare equal:

Polynomial() == ZeroPolynomial() == Constant(0) == 0

They compare equal as well to numeric zero written as an int, float, or complex. A polynomial that is nonzero does not compare equal to numeric zero.

Constant(value) exposes value via its const property, compares equal to the corresponding numeric value, and supports conversion through int(), float(), and complex() using that value. ZeroPolynomial.const always returns numeric 0; it is read-only, and assignment to it raises AttributeError.

Taking derivatives

derivative is a property that holds the first derivative as computed by the usual power rule. For example:

Polynomial(1, 2, 3).derivative == Polynomial(2, 2)

nth_derivative(n) carries out differentiation n times:

  • For n == 0, an equal but independent copy is returned.
  • Orders that are positive apply the power rule repeatedly.
  • Once all terms have vanished, ZeroPolynomial() is the result.
  • For a constant or any zero polynomial, the derivative is ZeroPolynomial().

The differentiation order must be a non-negative integer; orders that are invalid raise ValueError.

Compatible arithmetic

For addition, subtraction, and multiplication, an operand may be a polynomial (including any specialized subclass) or a numeric int, float, or complex scalar. A scalar is treated as a constant. The ordinary, reflected, and augmented forms must agree in value: +, -, *, +=, -=, and *= are supported as applicable.

  • Coefficients are aligned by degree for addition and subtraction.
  • Multiplication carries out polynomial convolution.
  • Leading zeroes that arise from cancellation are removed.
  • Adding any representation of zero preserves the polynomial value.
  • In binary form, multiplication by zero returns ZeroPolynomial().
  • For a general Polynomial, augmented multiplication by zero leaves a normalized zero Polynomial instead of changing it into the dedicated ZeroPolynomial class.
  • When two Constant objects are multiplied, the operation returns a Constant.

Some examples:

Polynomial(1, 1, 1) + Polynomial(2, 2) == Polynomial(1, 3, 3)
Polynomial(3, 3, 3) - 2 == Polynomial(3, 3, 1)
2 - Polynomial(3, 3, 3) == Polynomial(-3, -3, -1)
Polynomial(1, 2, 3) * Polynomial(1, 2, 3) == Polynomial(1, 4, 10, 12, 9)
Constant(5) * Constant(5) == Constant(25)

When two equal general polynomials are subtracted, the outcome is a normalized general zero value, equal to Polynomial() and ZeroPolynomial().

Dividing polynomials

The following provide polynomial long division:

  • divmod(dividend, divisor), which returns (quotient, remainder);
  • dividend // divisor and dividend //= divisor, which select the quotient;
  • dividend % divisor and dividend %= divisor, which select the remainder.

These are polynomial quotient/remainder computations; // does not imply that quotient coefficients are numerically rounded down. Divisors that are numeric scalars are treated as constants. Dividing by a zero polynomial raises ZeroDivisionError.

Examples and edge cases that must be handled include:

divmod(Polynomial(1, 4, 4), Polynomial(1, 2))
# (Polynomial(1, 2), Polynomial())

divmod(Polynomial(1, 2, 3), Polynomial(1, 2))
# (Polynomial(1, 0), Polynomial(3))

divmod(Polynomial(1, 2, 3), Constant(5))
# (Polynomial(1/5, 2/5, 3/5), Polynomial())

Division by a constant scales every coefficient and leaves a zero remainder. When the divisor is a monomial whose degree is greater than that of the dividend, the quotient is zero and the remainder equals the original dividend.

Raising to a power

** and **= support powers that are non-negative integers, and the two operators must agree in polynomial value. Powers that are non-integer or negative raise ValueError.

  • Exponent zero yields the multiplicative identity: Constant(1) for a general polynomial, a Constant, or ZeroPolynomial; a Monomial yields Monomial(1, 0).
  • Exponent one returns an equal, fresh value and keeps the concrete category. In particular, p ** 1 must not alias p.
  • Powers greater than one equal repeated polynomial multiplication.
  • A Constant taken to a power remains a Constant.
  • For positive n, Monomial(c, d) ** n has coefficient c ** n and degree d * n.
  • For every positive power, ZeroPolynomial() remains ZeroPolynomial().
  • Raising a general multi-term polynomial to a power produces the corresponding general polynomial product.

For instance, Polynomial(1, 2) ** 2 == Polynomial(1, 4, 4).

Shifting degrees

With the shift operators, every term is moved by a signed integer number of degrees:

  • Under p << n, every exponent is raised by n.
  • Under p >> n, every exponent is lowered by n, and terms that move below degree zero are discarded.
  • A negative shift reverses the direction: in value, p << -n is equivalent to p >> n, and vice versa.
  • A shift of zero keeps the value unchanged.
  • The forms <<=, >>=, <<, and >> have the corresponding values.

Some examples:

Polynomial(1, 3, 5) << 3 == Polynomial(1, 3, 5, 0, 0, 0)
Polynomial(1, 3, 5) >> 1 == Polynomial(1, 3)
Constant(5) << 10 == Monomial(5, 10)

If a general polynomial is shifted entirely below degree zero, the result is Polynomial(). Doing the same to a monomial gives ZeroPolynomial(). For Constant and ZeroPolynomial, augmented shifts return a distinct result object instead of mutating another reference to the original fixed-category object.

Membership testing for terms

Exact coefficient-and-degree terms are what the in operator checks. Its left operand may be:

  • a single (coefficient, degree) tuple;
  • a list or set of tuples of that kind; or
  • another polynomial.

Membership is true exactly when every supplied tuple appears in the target polynomial's nonzero terms, with both the coefficient and the degree matching. When the supplied operand is another polynomial, that polynomial's nonzero terms are the supplied terms. It is allowed to supply only a subset, but every term in that supplied subset must match. A supplied collection whose match is partial is false, and coefficient patterns that are equal but sit at shifted degrees do not match. Membership operand forms that are unsupported raise ValueError.

As an example, [(1, 2), (2, 1)], (3, 0), and Polynomial(1, 2, 3) are all members of Polynomial(1, 2, 3), whereas Polynomial(1, 2, 3) is not a member of Polynomial(1, 2, 3, 0), since its terms occur at different degrees.

Task Specification: Correcting the __repr__ of Binomial and Trinomial

Background

You are working within a polynomial package that offers a hierarchy of polynomial classes. The classes enumerated below are publicly importable from the top-level polynomial module, and they must stay that way:

  • Constant
  • LinearBinomial
  • Monomial
  • Polynomial
  • QuadraticTrinomial
  • ZeroPolynomial
  • FrozenPolynomial
  • Trinomial
  • Binomial

Each of them is a subclass of Polynomial, whether directly or indirectly.

Goal

Fix the __repr__ implementation of the Binomial and Trinomial classes, and ensure that __repr__ behaves consistently across the whole Polynomial class hierarchy.

Constructing Instances

  • A Binomial is built from two terms; each term is supplied as a 2-tuple (coefficient, degree). For instance, Binomial((4, 3), (2, 1)).
  • A Trinomial is built from three terms; each term is supplied as a 2-tuple (coefficient, degree). For instance, Trinomial((5, 5), (2, 3), (1, 1)).
  • At the conceptual level, each (coefficient, degree) term corresponds to a Monomial(coefficient, degree).
  • It must be possible to construct every class in the Polynomial hierarchy with no arguments (that is, SomeClass() must succeed for each such class).

__repr__ Behavior Requirements

Binomial

When repr() is called on a Binomial, it must produce a string of this form:

Binomial(Monomial(<c1>, <d1>), Monomial(<c2>, <d2>))

Here (c1, d1) and (c2, d2) are the two terms supplied at construction. As a concrete example, repr(Binomial((4, 3), (2, 1))) must equal:

Binomial(Monomial(4, 3), Monomial(2, 1))
Trinomial

When repr() is called on a Trinomial, it must produce a string of this form:

Trinomial(Monomial(<c1>, <d1>), Monomial(<c2>, <d2>), Monomial(<c3>, <d3>))

Here the three terms are the ones supplied at construction. As a concrete example, repr(Trinomial((5, 5), (2, 3), (1, 1))) must equal:

Trinomial(Monomial(5, 5), Monomial(2, 3), Monomial(1, 1))
Rule that applies across the hierarchy

Take any class C that is a subclass of Polynomial (this includes Polynomial itself and all the classes listed above). For a default-constructed instance C() of such a class, repr() must begin with the exact class name string "C". Put differently, repr(C()) must start with the class's own name.

The repr() outputs that already exist for the other classes must continue to satisfy the following exact results:

  • repr(LinearBinomial(5, 2)) equals LinearBinomial(5, 2)
  • repr(QuadraticTrinomial(1, -4, 4)) equals QuadraticTrinomial(1, -4, 4)
  • repr(FrozenPolynomial(1, 2, 3)) equals FrozenPolynomial(1, 2, 3)

Scope of the Changes

The only change that is required is to make the __repr__ output of Binomial and Trinomial correct (that is, to use the Monomial(...)-based format above and to begin with the correct class name), while the __repr__ behavior of the other classes, which is already correct, must be preserved and all listed classes must remain importable and constructible with no arguments.
