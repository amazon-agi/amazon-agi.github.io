Goal

Add non-negative integer exponentiation to the existing mutable, single-variable polynomial types in the polynomial package. The new ** and **= operations must integrate with the package's existing construction, normalization, arithmetic, equality, calculus, containment, and formatting behavior described below.

Public package and classes

The following names must remain importable directly from polynomial:

from polynomial import (
    Polynomial,
    ZeroPolynomial,
    Constant,
    Monomial,
    LinearBinomial,
    QuadraticTrinomial,
)

The four types to which the exponentiation requirements directly apply are Polynomial, Monomial, Constant, and ZeroPolynomial. LinearBinomial(a, b) represents a*x + b, and QuadraticTrinomial(a, b, c) represents a*x^2 + b*x + c; their existing public construction and representations must remain compatible.

Existing polynomial representation and construction

Coefficient construction

Polynomial represents a polynomial in the single variable x. It accepts coefficients in descending degree order either as positional arguments or as one iterable:

Polynomial(1, 2, 3)
Polynomial([1, 2, 3])
Polynomial(range(1, 4))

Each of these represents x^2 + 2x + 3. Constructing from another polynomial, as in Polynomial(existing_polynomial), creates the corresponding polynomial value. Strings are accepted as coefficient iterables, so Polynomial("abc") and Polynomial(*"abc") both represent coefficients a, b, and c in descending degree order.

With from_monomials=True, construction accepts monomial objects or (coefficient, degree) pairs, either in an iterable or as the supplied terms. For example:

Polynomial([(1, 2), (2, 1), (3, 0)], from_monomials=True)

is equal to Polynomial(1, 2, 3). Terms of the same degree contribute additively.

Leading zero coefficients are removed canonically without changing the represented value. Thus:

Polynomial(0, 0, 1, 2, 3, 0) == Polynomial(1, 2, 3, 0)

and the two values have the same degree, terms, string form, and representation. Zero coefficients at lower degrees still occupy their degree positions.

Defaults and specialized constructors
  • Polynomial() is a zero polynomial value.
  • Monomial(coefficient, degree) represents coefficient*x^degree.
  • Monomial() is equivalent to Monomial(1, 1), i.e. x.
  • Constant(value) represents a degree-zero value.
  • Constant() is equivalent to Constant(1).
  • ZeroPolynomial() is the specialized zero-polynomial value.
Observable structure

For a polynomial p:

  • p.degree is its highest nonzero degree. Every zero form, including Polynomial(), Constant(0), and ZeroPolynomial(), has degree -math.inf.
  • p.terms is a descending-degree list of the nonzero (coefficient, degree) pairs.
  • p.monomials is the same descending sequence represented as Monomial objects.
  • p[k] addresses the coefficient of degree k, with p[0] denoting the constant coefficient. Coefficients are mutable through this degree-based indexing. Setting the current leading coefficient to zero must normalize the value and lower its degree. For example, setting p[p.degree] = 0 on Polynomial(1, 2, 3) produces the same observable polynomial as Polynomial(2, 3).

Existing calculus behavior

p.derivative returns the ordinary power-rule derivative as a new polynomial. For example:

Polynomial(1, 2, 3).derivative == Polynomial(2, 2)

The derivative of a constant or any zero polynomial is a ZeroPolynomial value.

p.nth_derivative(n) is defined for every non-negative integer n and returns a new polynomial equal to applying derivative exactly n times:

  • nth_derivative(0) is an unchanged copy of p, not a mutation of it.
  • nth_derivative(1) equals p.derivative.
  • Once the degree is exhausted, the result is zero and remains zero for higher derivative orders.
  • Calling it must not mutate p.

Existing equality and scalar conversion behavior

Polynomial equality compares normalized polynomial values: coefficients must match at the same degrees after canonical removal of leading zeros. The corresponding inequality result is the logical opposite for the equality and zero comparisons described here.

All representations of the zero polynomial compare equal to numeric zero of the built-in integer, floating-point, and complex forms:

Constant(0) == Polynomial() == ZeroPolynomial() == 0
Constant(0) == Polynomial() == ZeroPolynomial() == 0.0
Constant(0) == Polynomial() == ZeroPolynomial() == 0j

A nonzero polynomial does not compare equal to numeric zero.

A Constant compares equal to its scalar value, exposes that value through .const, and supports the matching built-in conversions:

int(Constant(69)) == 69
float(Constant(4.2)) == 4.2
complex(Constant(4.2 - 69j)) == 4.2 - 69j

General equality is value-oriented, so differently specialized polynomial classes can compare equal when they represent the same terms. However, whenever this specification requires an operation to return a particular effective type such as Constant, Monomial, or ZeroPolynomial, returning only an algebraically equal value with a different specialized representation is not sufficient.

Existing arithmetic behavior

The existing operators accept polynomial operands and numeric constants (int, float, and complex) where applicable. Direct, reflected, and augmented forms must continue to agree in value.

Addition and subtraction

+, -, +=, and -= perform ordinary coefficient-wise polynomial arithmetic, aligning equal degrees and normalizing leading zeros. Reflected scalar forms are supported. Examples include:

Polynomial(1, 1, 1) + Polynomial(2, 2) == Polynomial(1, 3, 3)
Polynomial(1, 1, 1) + 2 == 2 + Polynomial(1, 1, 1) == Polynomial(1, 1, 3)
Polynomial(3, 3, 3) - 2 == Polynomial(3, 3, 1)
2 - Polynomial(3, 3, 3) == Polynomial(-3, -3, -1)

Augmented forms produce the same normalized result. Adding any numeric or polynomial zero leaves the value unchanged. Subtracting a polynomial from itself produces a normalized general zero value equal to both Polynomial() and ZeroPolynomial().

Multiplication

*, reflected *, and *= perform ordinary polynomial multiplication by coefficient convolution. For example:

Polynomial(1, 2, 3) * Polynomial(1, 2, 3) == Polynomial(1, 4, 10, 12, 9)
Polynomial(1, 1, 1) * 10 == 10 * Polynomial(1, 1, 1) == Polynomial(10, 10, 10)

A non-in-place multiplication involving a zero operand returns a ZeroPolynomial. In contrast, multiplying a general Polynomial in place by ZeroPolynomial(), 0, 0.0, or 0j sets its value to zero while retaining it as a general Polynomial, represented as Polynomial() rather than downcasting it to ZeroPolynomial.

Ordinary multiplication of two Constant objects retains its existing monomial-typed result. Exponentiation has an explicit exception to this behavior, described below.

Polynomial quotient and remainder

divmod(dividend, divisor) performs polynomial long division and returns a (quotient, remainder) pair. It must support exact division, a nonzero remainder, constant or monomial divisors, and a divisor whose degree exceeds the dividend's degree. In particular, the returned values are mathematically equal to the following:

divmod(Polynomial(1, 4, 4), Polynomial(1, 4, 4))
# (Polynomial(1), Polynomial())

divmod(Polynomial(1, 4, 4), Polynomial(1, 2))
# (Polynomial(1, 2), Polynomial())

divmod(Polynomial(1, 2, 3), Polynomial(1, 2))
# (Polynomial(1, 0), Polynomial(3))

divmod(Polynomial(1, 2, 3), Constant(5))
# (Polynomial(1/5, 2/5, 3/5), Polynomial())

divmod(Polynomial(1, 2, 3), Monomial(1, 10))
# (Polynomial(), Polynomial(1, 2, 3))

// and //= produce the quotient, while % and %= produce the remainder, with augmented forms updating the left operand consistently.

Existing containment behavior

candidate in p checks polynomial terms, not evaluated values or a contiguous coefficient slice. The accepted candidate forms are:

  • one (coefficient, degree) tuple;
  • a list or set of such tuples; or
  • another polynomial, whose nonzero terms are used.

Containment is true exactly when every candidate term occurs in p with both its coefficient and absolute degree matching. Proper subsets and non-contiguous subsets are allowed. Consequently, containment is directional, and shifting otherwise identical coefficients to different degrees changes the result. For example, all of the following are contained in Polynomial(1, 2, 3):

(1, 2)
[(1, 2), (3, 0)]
{(2, 1), (3, 0)}
Polynomial([(1, 2), (2, 1)], from_monomials=True)

A candidate with even one missing or mismatched term is not contained.

Existing representations

repr

repr uses normalized constructor syntax and the repr of each coefficient. A general nonzero polynomial uses descending coefficients:

repr(Polynomial(0, 0, -2, 0, 4.6666666666, -(69 + 420j), -1, 1337))
# "Polynomial(-2, 0, 4.6666666666, (-69-420j), -1, 1337)"

repr(Polynomial("abcdef"))
# "Polynomial('a', 'b', 'c', 'd', 'e', 'f')"

The exact constructor-style forms for general zero and specialized values are:

Polynomial()
ZeroPolynomial()
Monomial(1, 2)
Constant(5)
LinearBinomial(5, 2)
QuadraticTrinomial(1, -4, 4)

The corresponding forms are produced by repr(Polynomial()), repr(ZeroPolynomial()), repr(Monomial(1, 2)), repr(Constant(5)), repr(LinearBinomial(5, 2)), and repr(QuadraticTrinomial(1, -4, 4)), respectively.

str

str renders conventional descending polynomial notation using x:

  • Zero-coefficient terms are omitted.
  • Coefficient 1 is omitted on nonconstant terms, while a constant 1 is displayed.
  • Coefficient -1 on a nonconstant term is rendered as a short minus sign without the 1.
  • Degree one uses x, not x^1; other positive degrees use x^n; constants have no variable suffix.
  • Negative real coefficients use - between terms rather than + -.
  • Character coefficients are displayed without quotes.
  • Complex coefficients retain their normal parenthesized string form.
  • Every zero-polynomial form renders as 0.

Required examples include:

str(Polynomial(3, -2, 0, 0)) == "3x^3 - 2x^2"
str(Polynomial(2, 0)) == "2x"
str(Polynomial(1, 2)) == "x + 2"
str(Polynomial(1, 0, 1)) == "x^2 + 1"
str(Polynomial(-1, 0, 2)) == "-x^2 + 2"
str(Monomial(5, 10)) == "5x^10"
str(Polynomial("abcdef")) == "ax^5 + bx^4 + cx^3 + dx^2 + ex + f"
str(ZeroPolynomial()) == "0"

The mixed numeric/complex example:

str(Polynomial(0, 0, -2, 0, 4.6666666666, -(69 + 420j), -1, 1337))

must be exactly:

-2x^5 + 4.6666666666x^3 + (-69-420j)x^2 - x + 1337

Required exponentiation behavior

Supported operators and exponent domain

Provide exponentiation for Polynomial, Monomial, Constant, and ZeroPolynomial through both:

p ** n
p **= n

The required right-hand operand n is a non-negative integer. For every supported value, p ** n must return a fresh polynomial object and must not mutate p; the result must never be the same object as p.

p **= n must produce the same observable result as assigning p = p ** n, including all value, normalization, and effective-type rules below.

Exponent zero

For every polynomial type, exponent zero returns the multiplicative identity as a Constant(1), including the conventional zero-to-zero-power case in this API:

Constant(5) ** 0       # Constant(1)
Monomial(5, 10) ** 0   # Constant(1)
ZeroPolynomial() ** 0  # Constant(1)
Polynomial(1, 2, 3) ** 0  # Constant(1)

These results must have the same value, degree, terms, monomials, str, and specialized repr as Constant(1).

Exponent one

For every polynomial type, exponent one returns a fresh copy equal to the operand and preserves its effective type and representation:

  • a Constant produces the corresponding Constant;
  • a Monomial produces the corresponding Monomial;
  • a ZeroPolynomial produces a ZeroPolynomial;
  • a general Polynomial produces a general Polynomial.

The returned object must not alias the operand.

Exponents two and greater

For n >= 2, the value of p ** n is the product of n copies of p. Equivalently, for successive positive powers, the expected value starts as a copy of p and is multiplied by p once more for each increment of the exponent. General polynomial results must have the same normalized coefficients, degree, terms, monomials, string form, and effective representation as the corresponding repeated product. For example:

Polynomial(1, 2) ** 2 == Polynomial(1, 4, 4)
Polynomial(1, 2, 3) ** 2 == Polynomial(1, 2, 3) * Polynomial(1, 2, 3)

Fresh-object behavior applies to every exponent, including one and all larger powers.

Specialized result rules

Constant exponentiation is deliberately constant-preserving. For every non-negative n, its result is a Constant rather than the monomial-typed value produced by ordinary constant multiplication:

Constant(5) ** 2  # exactly the effective form Constant(25)

For a Monomial(coefficient, degree) and positive n, coefficients are raised to n and degrees are multiplied by n, with a Monomial result:

Monomial(5, 10) ** 2  # Monomial(25, 20)

For exponent two this must match m * m in both value and effective type.

For a ZeroPolynomial:

ZeroPolynomial() ** 0  # Constant(1)
ZeroPolynomial() ** 1  # a fresh ZeroPolynomial()
ZeroPolynomial() ** 2  # ZeroPolynomial(), matching z * z

All positive powers of a ZeroPolynomial are zero-polynomial values with the specialized ZeroPolynomial() representation.

Scope

Only non-negative integer powers in the forms p ** n and p **= n are required. Negative, fractional, complex, multivariate, reflected, and modular exponentiation are outside this task. Existing multiplication semantics—including the monomial-typed result of ordinary Constant * Constant and the in-place/non-in-place zero distinction—must not be changed to obtain the exponentiation behavior.

  • monomials: the same nonzero terms as Monomial values, also in descending degree order;
  • degree-based coefficient indexing, where p[d] reads and p[d] = value updates the coefficient of x^d.

Setting a leading coefficient to zero must renormalize the polynomial and lower its degree. For example:

ZeroPolynomial().const  # 0

int(Constant(69)) == 69
float(Constant(4.2)) == 4.2
complex(Constant(4.2 - 69j)) == 4.2 - 69j

Equality and Inequality

Polynomial equality is based on normalized polynomial value rather than construction form. Inequality must be the logical opposite in the corresponding equality cases.

In particular:

  • Equal normalized coefficient/degree pairs compare equal.
  • A nonzero polynomial does not equal numeric zero.
  • Polynomial(), Constant(0), and ZeroPolynomial() compare equal to one another.
  • Every zero-polynomial form compares equal to integer 0, float 0.0, and complex 0j.
  • A nonzero Constant(value) compares equal to its represented scalar value.

Differentiation

derivative returns a new polynomial computed with the ordinary power rule. For example:

Polynomial(1, 2, 3).derivative == Polynomial(2, 2)

The derivative of a constant or any zero polynomial is a zero polynomial.

nth_derivative(n) is defined for every non-negative integer n and must:

  • return a new, equal polynomial for n == 0;
  • apply derivative exactly n times;
  • return zero once the polynomial's degree has been exhausted; and

Polynomial(3, 3, 3) - 2 == Polynomial(3, 3, 1)
2 - Polynomial(3, 3, 3) == Polynomial(-3, -3, -1)
Polynomial(1, 2, 3) * Polynomial(1, 2, 3) == Polynomial(1, 4, 10, 12, 9)

Direct, reflected, and in-place forms must agree in polynomial value. In-place forms mutate the left operand. Results must be normalized: cancellation or subtraction may lower the degree or produce zero, and adding zero must preserve the original value.

Objective

Make ZeroPolynomial instances immutable: after a zero polynomial has been constructed, every attempt to assign instance state through an attribute or polynomial item must raise AttributeError. Construction and all existing read-only polynomial behavior must continue to work.

This is a focused compatibility change. The behavior of the other polynomial classes, and all non-mutation behavior described below, must remain unchanged.

Public API

The public package is polynomial. It must expose these classes directly at package level:

from polynomial import (
    Polynomial,
    ZeroPolynomial,
    Constant,
    Monomial,
    LinearBinomial,
    QuadraticTrinomial,
)

The relevant public constructors are:

  • Polynomial(...)
  • ZeroPolynomial()
  • Constant(value=1)
  • Monomial(coefficient=1, degree=1)
  • LinearBinomial(a=1, b=0), representing ax + b
  • QuadraticTrinomial(a=1, b=0, c=0), representing ax^2 + bx + c

ZeroPolynomial Immutability

ZeroPolynomial() must remain constructible with no arguments and return a usable zero-polynomial instance. Once constructed, the instance must reject both of the following public mutation paths.

Attribute assignment

Assigning any attribute, whether existing or arbitrary, must raise AttributeError. This applies both to normal assignment and to direct or indirect calls to __setattr__:

z = ZeroPolynomial()
z.x = 5                         # raises AttributeError
setattr(z, "anything", 5)       # raises AttributeError
z.__setattr__("x", 5)           # raises AttributeError

The required exception is AttributeError; an attempted coefficient-style attribute assignment must not leak another exception type.

Item assignment

Assigning a coefficient by item must likewise raise AttributeError, including when __setitem__ is invoked directly:

z = ZeroPolynomial()
z[0] = 5                         # raises AttributeError
z.__setitem__(0, 5)             # raises AttributeError

This applies to every attempted key/value assignment on a ZeroPolynomial.

Polynomial Construction and Normalization

Coefficient construction

Polynomial coefficients are supplied from highest degree to the constant term. For example, Polynomial(1, 2, 3) represents x^2 + 2x + 3. The constructor must accept either positional coefficients or one iterable of coefficients, with equivalent results:

Polynomial(1, 2, 3) == Polynomial([1, 2, 3])

This applies to integer, floating-point, complex, and character coefficients. A string is treated as an iterable of character coefficients, so these are equivalent:

Polynomial("abcdef")
Polynomial(*"abcdef")

With from_monomials=True, construction instead accepts terms in (coefficient, degree) form, either as an iterable or as term arguments. For example:

Polynomial([(1, 2), (2, 1), (3, 0)], from_monomials=True)

is the same polynomial value as Polynomial(1, 2, 3).

Calling Polynomial() with no coefficients creates a general zero polynomial. Calling ZeroPolynomial() creates the specialized immutable zero polynomial. These values compare equal, although their specialized representations remain distinct.

Canonical normalization

Leading zero coefficients—zeros on the highest-degree side—must be discarded. Normalization governs degree, equality, terms, arithmetic results, and display. For example:

Polynomial(0, 0, 0, 1, 2, 3, 0) == Polynomial(1, 2, 3, 0)

Their repr and str values must also agree. A zero constant at the low-degree end is retained when it determines the degrees of preceding nonzero terms.

The specialized defaults are:

Monomial() == Monomial(1, 1)  # x
Constant() == Constant(1)     # 1

Polynomial Value Interface

Degree, terms, and monomials

Every polynomial exposes:

  • degree: the greatest degree having a nonzero coefficient. Every zero-polynomial value has degree -math.inf.
  • terms: a list of nonzero (coefficient, degree) pairs ordered from greatest degree to least.
  • monomials: the same nonzero terms represented as Monomial objects, also in descending degree order.

For example:

p = Polynomial(1, 2, 0, 3)
p.degree     # 3
p.terms      # [(1, 3), (2, 2), (3, 0)]

A zero polynomial has no nonzero terms or monomials.

Degree-based coefficient indexing

Mutable polynomial types support reading and writing coefficients by degree: p[k] is the coefficient of x^k. Assignment must re-normalize the value. In particular, setting a general polynomial's leading coefficient to zero lowers its degree as appropriate:

p = Polynomial(1, 2, 3)
p[p.degree] = 0
p == Polynomial(2, 3)

This mutability does not apply to ZeroPolynomial, whose item assignment always raises AttributeError as specified above.

Derivatives

derivative is a property returning the ordinary power-rule derivative as a new polynomial value. For example:

Polynomial(1, 2, 3).derivative == Polynomial(2, 2)

The derivative of a constant is a zero polynomial, and the derivative of a zero polynomial is zero.

nth_derivative(n) returns a new polynomial obtained by applying derivative exactly n times, for every non-negative integer n. The zeroth derivative has the same value as the source but is a new polynomial object; once the degree is exhausted, further derivatives remain zero. Neither derivative nor nth_derivative may mutate the source.

Equality and Numeric Constants

Polynomial equality compares normalized coefficient-by-degree values. In the comparison cases defined here, != is the logical opposite of ==. Equal normalized polynomials compare equal even when created through different supported constructors. A nonzero polynomial does not equal numeric zero.

All public zero forms compare equal to integer, floating-point, and complex zero:

ZeroPolynomial() == Polynomial() == Constant(0) == 0
ZeroPolynomial() == 0.0
ZeroPolynomial() == 0j

A Constant compares equal to its scalar value, exposes that value through its const property, and supports the corresponding built-in numeric conversions:

int(Constant(69)) == 69
float(Constant(4.20)) == 4.20
complex(Constant(4.20 - 69j)) == 4.20 - 69j

Arithmetic

Addition, subtraction, and multiplication

Polynomials support ordinary coefficient arithmetic with other polynomials and with integer, floating-point, and complex constants. Direct, reflected, and in-place forms must agree in value:

  • p + q, q + p, and p += q
  • p + c, c + p, and p += c
  • p - q and p -= q
  • p - c, c - p, and p -= c
  • p * q, q * p, and p *= q
  • p * c, c * p, and p *= c

Coefficients are aligned by degree, products use ordinary polynomial convolution, and every result is normalized. For example:

Polynomial(1, 1, 1) + Polynomial(2, 2) == Polynomial(1, 3, 3)
Polynomial(3, 3, 3) - 2 == Polynomial(3, 3, 1)
2 - Polynomial(3, 3, 3) == Polynomial(-3, -3, -1)
Polynomial(1, 2, 3) * Polynomial(1, 2, 3) == Polynomial(1, 4, 10, 12, 9)

Adding any numeric or polynomial zero leaves the value unchanged. Subtraction may normalize a result to zero or remove canceled leading terms.

Non-in-place multiplication by zero returns a ZeroPolynomial value:

Polynomial(1, 1, 1) * ZeroPolynomial()
# ZeroPolynomial()

In contrast, in-place multiplication must not downcast a general Polynomial. After p *= 0 or p *= ZeroPolynomial(), a general Polynomial remains a general Polynomial whose value is zero (and whose general representation is Polynomial()).

Division and remainder

divmod(dividend, divisor) performs polynomial long division and returns (quotient, remainder). It must handle exact division, a nonzero remainder, division by a constant polynomial, and a divisor whose degree is greater than the dividend's. Coefficients use ordinary division, so integral inputs can produce floating-point quotient coefficients. The remainder is zero or has lower degree than the divisor.

Required examples include the following value equalities:

divmod(Polynomial(1, 4, 4), Polynomial(1, 4, 4))
# (Polynomial(1), Polynomial())

divmod(Polynomial(1, 4, 4), Polynomial(1, 2))
# (Polynomial(1, 2), Polynomial())

divmod(Polynomial(1, 2, 3), Polynomial(1, 2))
# (Polynomial(1, 0), Polynomial(3))

divmod(Polynomial(1, 2, 3), Constant(5))
# (Polynomial(1/5, 2/5, 3/5), Polynomial())

divmod(Polynomial(1, 2, 3), Monomial(1, 10))
# (Polynomial(), Polynomial(1, 2, 3))

// returns the quotient and % returns the remainder. Their in-place forms, //= and %=, replace a mutable left operand with the corresponding normalized quotient or remainder.

Membership by Terms

The expression candidate in polynomial accepts any of these candidate forms:

  • one (coefficient, degree) tuple;
  • a list of such tuples;
  • a set of such tuples; or
  • another polynomial.

Containment is term-based and directional. It is true exactly when every candidate nonzero term occurs in the target with both coefficient and degree matching. The candidate may be a proper subset, and its terms need not be contiguous in degree. Thus all of the following are contained in Polynomial(1, 2, 3):

(1, 2)
[(1, 2), (2, 1)]
[(1, 2), (3, 0)]
{(1, 2), (2, 1), (3, 0)}
Polynomial([(1, 2), (3, 0)], from_monomials=True)

Coefficient matches without degree matches are insufficient. For example, Polynomial(1, 2, 3) is not contained in Polynomial(1, 2, 3, 0), because the same coefficient sequence occupies different degrees. A smaller polynomial can be contained in a larger one without the reverse being true.

Representations

repr

repr uses normalized constructor syntax and applies repr to each coefficient. General Polynomial values list descending coefficients, including internal zeros needed to preserve degrees; a general zero is Polynomial(). For example:

repr(Polynomial(0, 0, -2, 0, 4.6666666666, -(69 + 420j), -1, 1337))
# "Polynomial(-2, 0, 4.6666666666, (-69-420j), -1, 1337)"

repr(Polynomial("abcdef"))
# "Polynomial('a', 'b', 'c', 'd', 'e', 'f')"

Specialized values use these exact forms:

ZeroPolynomial()
Monomial(coefficient, degree)
Constant(value)
LinearBinomial(a, b)
QuadraticTrinomial(a, b, c)

For example, the exact results include Monomial(1, 2), Constant(5), LinearBinomial(5, 2), and QuadraticTrinomial(1, -4, 4).

str

str renders conventional single-variable notation in descending degree order:

  • zero-coefficient terms are omitted;
  • coefficients 1 and -1 are suppressed on nonconstant terms, while their sign is retained;
  • degree one uses x, never x^1;
  • other positive degrees use x^n;
  • constants have no variable suffix;
  • terms use spaced + and - separators, while a leading negative term starts with a short -;
  • character coefficients are displayed without quotes; and
  • every zero-polynomial value renders as 0.

Examples:

str(Polynomial(3, -2, 0, 0)) == "3x^3 - 2x^2"
str(Polynomial(-1, 0, 2)) == "-x^2 + 2"
str(Polynomial(1, 0, 1)) == "x^2 + 1"
str(Monomial(5, 10)) == "5x^10"
str(Polynomial("abcdef")) == "ax^5 + bx^4 + cx^3 + dx^2 + ex + f"
str(ZeroPolynomial()) == "0"

Complex coefficients retain their standard parenthesized string form. The complete mixed example is:

str(Polynomial(0, 0, -2, 0, 4.6666666666, -(69 + 420j), -1, 1337))
# "-2x^5 + 4.6666666666x^3 + (-69-420j)x^2 - x + 1337"

Compatibility and Non-goals

  • The only intended behavior change is that every ZeroPolynomial attribute or item assignment now raises AttributeError.
  • General Polynomial instances and the other mutable polynomial types must remain mutable.
  • Do not redesign constructors, normalization, arithmetic, comparison, division, membership, derivative behavior, result types, or textual representations.
  • Do not add or otherwise change unrelated behavior.

Objective

Extend the polynomial package with exponentiation while preserving its existing single-variable polynomial behavior. Public results must remain normalized, and all explicitly type-sensitive operations must return the concrete class described below.

Public package and class hierarchy

The following names must be importable directly from polynomial:

  • Polynomial
  • ZeroPolynomial
  • Constant
  • Monomial
  • LinearBinomial
  • QuadraticTrinomial

The core specialization hierarchy is Polynomial → Monomial → Constant → ZeroPolynomial: a constant is a degree-zero monomial, and the zero polynomial is a specialized constant.

Ordinary polynomial equality is value-based and may hold across concrete classes. In this specification, two results are exactly the same only when they have equal normalized polynomial values and the same concrete class (type(left) is type(right)). Type-sensitive requirements below use this stronger meaning.

Construction and normalization

Polynomial

Polynomial accepts coefficients in descending degree order, either as positional arguments or as one iterable. Thus:

  • Polynomial(1, 2, 3) and Polynomial([1, 2, 3]) both represent x^2 + 2x + 3.
  • Numeric coefficient types such as integers, floats, and complex values are supported.
  • Iterable and positional character coefficients are supported. For example, Polynomial("abcdef") is equal to Polynomial(*"abcdef") and represents ax^5 + bx^4 + cx^3 + dx^2 + ex + f.
  • Polynomial(p) constructs an equivalent copy from another polynomial-like iterable such as a Polynomial.

With from_monomials=True, construction accepts (coefficient, degree) terms, supplied positionally or through one iterable. For example, Polynomial([(1, 2), (2, 1), (3, 0)], from_monomials=True) is equal to Polynomial(1, 2, 3). Monomial values may likewise be used as terms.

Calling Polynomial() with no coefficients constructs the zero polynomial value. Leading zero coefficients—zeros attached to degrees above the first nonzero term—must be removed. For example, Polynomial(0, 0, 1, 2, 3, 0) normalizes to the same value, degree, text, and general constructor representation as Polynomial(1, 2, 3, 0). An all-zero coefficient sequence normalizes to zero.

Specialized constructors
  • Monomial(coefficient, degree) represents coefficient * x^degree.
  • Monomial() is equivalent to Monomial(1, 1), namely x.
  • Constant(value) represents a degree-zero value.
  • Constant() is equivalent to Constant(1).
  • ZeroPolynomial() represents zero.
  • LinearBinomial(a, b) represents ax + b.
  • QuadraticTrinomial(a, b, c) represents ax^2 + bx + c.

Polynomial inspection and mutation

Every polynomial exposes the following public polynomial information:

  • degree is the highest nonzero degree. The degree of every zero value, including Polynomial(), Constant(0), and ZeroPolynomial(), is negative infinity (-math.inf).
  • terms is a list of all nonzero (coefficient, degree) pairs, ordered from highest degree to lowest. Zero terms are omitted.
  • monomials is the corresponding list of Monomial objects in descending degree order.
  • Coefficient indexing is degree-based: p[0] addresses the constant coefficient and p[p.degree] addresses the leading coefficient. Existing coefficients of mutable polynomial instances are assignable through this interface. Normalization must be recomputed after assignment, so assigning zero to the leading coefficient lowers the degree to the next nonzero term (or to negative infinity if none remains).

Derivatives

p.derivative returns the power-rule derivative as a new polynomial. For example, Polynomial(1, 2, 3).derivative is exactly the same as Polynomial(2, 2). A constant differentiates to a ZeroPolynomial, and the derivative of zero is also a ZeroPolynomial.

p.nth_derivative(n) must:

  • accept every non-negative integer n;
  • apply derivative exactly n times;
  • return an independent result with the source's unchanged value and concrete class for n == 0;
  • return zero once the original degree has been exhausted; and
  • leave p unmodified.

A negative or non-integer derivative count is invalid and raises ValueError.

Membership

candidate in p supports each of these candidate forms:

  • one (coefficient, degree) tuple;
  • a list of such tuples;
  • a set of such tuples; or
  • another polynomial.

Membership is true exactly when every candidate nonzero term occurs in p with both its coefficient and its absolute degree matching. The candidate may be a proper subset, and its terms need not be contiguous. For example, (1, 2), [(1, 2), (3, 0)], and Polynomial(1, 2, 3) are all contained in Polynomial(1, 2, 3). Degree shifts do not match: Polynomial(1, 2, 3) is not contained in Polynomial(1, 2, 3, 0). Containment is directional; a smaller term set may be contained in a larger one without the reverse being true. Unsupported candidate forms raise ValueError.

Equality, zero, and scalar conversion

Polynomial equality compares normalized values rather than concrete classes. In particular:

  • Equal normalized polynomials satisfy == and not !=.
  • A nonzero polynomial satisfies p != 0 and not p == 0.
  • ZeroPolynomial(), Polynomial(), and Constant(0) compare equal to one another and to numeric zero written as an int, float, or complex; for these values != 0 is false.
  • A nonzero Constant(value) compares equal to its numeric scalar value.

Constant.const exposes the scalar constant value. Numeric constants support int(c), float(c), and complex(c), with the corresponding normal scalar conversion.

ZeroPolynomial.const is read-only: its getter always returns 0, and assigning any value to it must raise AttributeError.

Addition, subtraction, and multiplication

Addition and subtraction perform ordinary coefficient-wise polynomial arithmetic. They support polynomial operands and numeric int, float, and complex constants in direct, reflected, and in-place forms (+, -, +=, and -=). Reflected subtraction has the normal operand order. Operations must normalize cancelled leading terms and zero results. For example:

  • Polynomial(1, 1, 1) + 2 is Polynomial(1, 1, 3).
  • 2 - Polynomial(3, 3, 3) is Polynomial(-3, -3, -1).
  • Subtracting two equal general Polynomial values produces the general zero representation Polynomial().

Multiplication performs ordinary polynomial convolution and supports polynomial and numeric operands in direct, reflected, and in-place forms (* and *=). For example, Polynomial(1, 2, 3) * Polynomial(1, 2, 3) is Polynomial(1, 4, 10, 12, 9), while multiplication by scalar 10 scales every coefficient.

The following concrete-result rules are required:

  • Two nonzero operands whose concrete type is Monomial multiply to a Monomial with coefficient a*b and degree d+e.
  • Two concrete Constant operands multiply to a Constant, never a general Monomial: Constant(a) * Constant(b) is exactly the same as Constant(a*b). In particular, Constant(5) * Constant(5) is exactly the same as Constant(25).
  • Any non-in-place multiplication involving a ZeroPolynomial returns a ZeroPolynomial; in particular, ZeroPolynomial() * ZeroPolynomial() is a ZeroPolynomial.
  • For a general Polynomial, non-in-place multiplication by zero returns a ZeroPolynomial.
  • In-place multiplication does not downcast an existing general Polynomial: after p *= 0, p has zero value and the concrete general representation Polynomial(), rather than becoming a ZeroPolynomial.

Polynomial division

divmod(dividend, divisor) performs polynomial long division and returns (quotient, remainder). It must support exact division, a nonzero remainder, constant divisors, monomial divisors, and a divisor whose degree is greater than the dividend's. The remainder is zero or has degree below the divisor. Representative results are:

  • divmod(Polynomial(1, 4, 4), Polynomial(1, 2)) gives quotient Polynomial(1, 2) and Polynomial() as remainder.
  • divmod(Polynomial(1, 2, 3), Polynomial(1, 2)) gives quotient Polynomial(1, 0) and remainder Polynomial(3).
  • Division of Polynomial(1, 2, 3) by Constant(5) gives quotient Polynomial(1/5, 2/5, 3/5) and a zero remainder.
  • If the divisor has larger degree, the quotient is zero and the remainder equals the original dividend.
  • Dividing a polynomial by itself gives quotient one and remainder zero.

// and //= produce the quotient component. % and %= produce the remainder component. Division by the zero polynomial raises ZeroDivisionError.

Exponentiation

All four core classes—Polynomial, Monomial, Constant, and ZeroPolynomial—must support ** through __pow__. The supported exponent is a non-negative integer.

For any supported polynomial p and exponent n:

  1. Zeroth power: p ** 0 is exactly the same as Constant(1), including for ZeroPolynomial(); thus zero to the zeroth power follows this library identity rule.
  2. First power: p ** 1 has the same normalized value and concrete class as p, but is a distinct object.
  3. Higher powers: for n >= 2, p ** n is exactly the result of multiplying p by itself n times, with the specialized result type described below.
  4. Direct exponentiation must not mutate p. Every direct p ** n result must be a distinct object from p, including the zeroth and first powers.

Concrete power results include:

  • Constant(a) ** n is a Constant with value a ** n when n >= 1; for example, Constant(5) ** 2 is exactly the same as Constant(25). The universal zeroth-power rule above takes precedence.
  • For n >= 1, a nonzero operand whose concrete type is Monomial produces a Monomial with coefficient a ** n and degree d*n; for example, Monomial(5, 10) ** 2 is exactly the same as Monomial(25, 20) and as the corresponding monomial multiplication.
  • For n >= 1, a positive power of ZeroPolynomial() is a ZeroPolynomial.
  • For a general nonzero Polynomial, the result agrees in value and concrete type with repeated general polynomial multiplication. For example, Polynomial(1, 2) ** 2 is exactly the same as Polynomial(1, 4, 4).

The same rules apply for arbitrary supported positive powers, not only squares.

All four core classes must also support **= through __ipow__. If the left operand's pre-operation value is p, then after p **= n the bound result must have the same value and concrete type that direct p ** n would produce. This includes preserving a Monomial result for positive monomial powers and producing Constant(1) for exponent zero.

Negative and non-integer exponents are outside the supported exponentiation contract.

repr uses normalized constructor syntax and applies repr to each coefficient. Exact forms are:

  • General nonzero values: Polynomial(c_n, ..., c_0) with ", " separators and leading zeros removed.
  • A general zero value: Polynomial().

  • Constant(value).

  • Omit zero terms.
  • Use x for degree one, x^n for other positive degrees, and no variable for degree zero.

  • Use a leading - without surrounding spaces for an initial negative real coefficient, and + or - between subsequent terms.
  • Render character coefficients without quotes.
  • Render every zero polynomial value as 0.

Required examples include:

  • str(Polynomial(1, 2, 3)) == "x^2 + 2x + 3"
  • str(Polynomial(3, -2, 0, 0)) == "3x^3 - 2x^2"
  • str(Polynomial(-1, 0, 2)) == "-x^2 + 2"

Add degree-shifting operators to the polynomial types while preserving the package's established construction, value, arithmetic, containment, derivative, and formatting behavior. The operators are <<, >>, <<=, and >>=. They shift polynomial degrees; they do not perform bitwise operations on coefficients.

Public package and classes

The public package is polynomial (singular). The following names must be importable directly from it:

from polynomial import (
    Polynomial,
    ZeroPolynomial,
    Constant,
    Monomial,
    LinearBinomial,
    QuadraticTrinomial,
)

The principal constructors are:

  • Polynomial(a, b, c, ...): coefficients are ordered from highest degree to degree zero.
  • Polynomial(coefficients): accepts one iterable with the same highest-to-lowest ordering.
  • Polynomial(): constructs the zero polynomial.
  • Polynomial(terms, from_monomials=True): accepts (coefficient, degree) terms and constructs their sum.
  • Monomial(coefficient=1, degree=1): constructs coefficient * x**degree; therefore Monomial() is Monomial(1, 1), or x.
  • Constant(value=1): constructs a degree-zero value; therefore Constant() is Constant(1).
  • ZeroPolynomial(): constructs the specialized zero value.
  • LinearBinomial(a, b): represents a*x + b.
  • QuadraticTrinomial(a, b, c): represents a*x**2 + b*x + c.

Polynomial accepts numeric coefficients, including integers, floats, and complex values, and also accepts character coefficients. For example, Polynomial("abcdef") and Polynomial(*"abcdef") are equal.

Leading zero coefficients on the highest-degree side are removed canonically. Thus:

Polynomial(0, 0, 0, 1, 2, 3, 0) == Polynomial(1, 2, 3, 0)

The final zero in this example is a meaningful degree-zero slot; only leading high-degree zeroes are removed. Construction and later operations must keep the value normalized in this way.

Polynomial value model and introspection

A polynomial is a sum of terms coefficient * x**degree, with non-negative integer degrees. The following public interfaces describe its normalized value:

  • degree is the largest degree having a nonzero coefficient. Every zero value—Polynomial(), ZeroPolynomial(), and Constant(0)—has degree negative infinity (-math.inf).
  • terms is a list of nonzero (coefficient, degree) pairs in descending degree order.
  • monomials is the corresponding list of Monomial objects, also in descending degree order.
  • p[k] gets the coefficient at degree k, not the coefficient at positional index k. Assignment through p[k] = value updates that degree. Zeroing the leading coefficient lowers the degree and immediately updates degree, terms, monomials, repr, and str; zeroing every term produces a normalized zero value.

For example:

p = Polynomial(1, 0, 3)
p.degree == 2
p.terms == [(1, 2), (3, 0)]
p.monomials == [Monomial(1, 2), Monomial(3, 0)]
p[0] == 3
p[2] == 1

Derivatives

derivative returns a new polynomial obtained with the ordinary power rule. For example:

Polynomial(1, 2, 3).derivative == Polynomial(2, 2)

The derivative of a constant or any zero polynomial is ZeroPolynomial().

nth_derivative(n) is defined for every non-negative integer n and returns a new polynomial obtained by applying derivative exactly n times. In particular:

  • nth_derivative(0) is a new value equal to the original.
  • nth_derivative(1) equals derivative.
  • Once the degree is exhausted, this method returns ZeroPolynomial(), including for still higher derivative orders.
  • Calling it does not mutate the source polynomial.

ZeroPolynomial() == Polynomial() == Constant(0) == 0
ZeroPolynomial() == 0.0
ZeroPolynomial() == 0j

  • QuadraticTrinomial(a, b, c=0)

The relevant public attributes and operators are:

  • LinearBinomial.root
  • Monomial.coefficient
  • unary +
  • __floordiv__, __ifloordiv__, __mod__, __imod__, and __divmod__
  • __pow__ and __ipow__
  • == and !=
Constructor behavior and validation
  • Calling QuadraticTrinomial() with no arguments must remain valid. It must produce a polynomial equivalent to Polynomial(1, 1, 1), representing x^2 + x + 1.
  • The coefficient-taking form remains QuadraticTrinomial(a, b, c=0).
  • LinearBinomial(0, 1) must raise ValueError; a linear binomial cannot have a zero leading coefficient.
  • QuadraticTrinomial(0, 1) must raise ValueError, not TypeError. The two-argument form must reach leading-coefficient validation.
  • A monomial degree must be a non-negative integer for the covered inputs:
    • Monomial(1, -1) raises ValueError.
    • Monomial(1, 1.2) raises ValueError.
    • Degree 0 remains valid, including Monomial(1, 0) and Monomial(0, 0).
Linear-binomial root

For LinearBinomial(a, b), the .root property must equal -b / a, using normal Python numeric arithmetic. This must work for integer, floating-point, and complex coefficients. In particular:

  • LinearBinomial(10, 0).root == 0
  • LinearBinomial(-10, 0).root == 0
  • LinearBinomial(11, 5).root == -5 / 11
  • LinearBinomial(12.1, 3).root == -3 / 12.1
  • LinearBinomial(13.2, 3.6).root == -3.6 / 13.2
  • LinearBinomial(5 + 10j, 2 + 1j).root == -(2 + 1j) / (5 + 10j)
Unary positive

Unary + must be supported and produce the same polynomial value, with the same terms and degree, for:

  • Polynomial(1, 2, 3)
  • Monomial(1, 2)
  • Constant(5)
  • ZeroPolynomial()
  • QuadraticTrinomial(1, 3, 7)
  • LinearBinomial(9, 2)

No object-identity requirement is imposed.

Zero division

For every polynomial form listed above, passing integer 0 directly to any of these methods must raise ZeroDivisionError:

  • value.__floordiv__(0)
  • value.__ifloordiv__(0)
  • value.__mod__(0)
  • value.__imod__(0)
  • value.__divmod__(0)

This requirement also applies to ZeroPolynomial().

Exponent validation

For all six polynomial forms:

  • Negative integer exponents must raise ValueError for both ordinary and in-place power operations, including value.__pow__(-1) and value.__ipow__(-2).
  • Non-integral floating-point exponents must raise ValueError, including value.__pow__(1.2) and value.__ipow__(1.5).
Mutable monomial coefficient

Monomial.coefficient must be assignable:

  • Setting Monomial(1, 2).coefficient = 2 produces the polynomial value represented by Monomial(2, 2).
  • Setting Monomial(1, 2).coefficient = 0 canonicalizes the value to the zero monomial represented by Monomial(0, 0).
Equality and inequality

Equivalent constant representations must compare equal:

  • Constant(1) == Polynomial(1)
  • Constant(1) == Monomial(1, 0)
  • Two separately created Constant(1) instances compare equal.

Equality must compare polynomial values rather than degree alone. Consider these distinct values:

  1. Polynomial(1, 2, 3)
  2. Monomial(1, 2)
  3. Constant(5)
  4. ZeroPolynomial()
  5. QuadraticTrinomial(1, 3, 7)
  6. LinearBinomial(9, 2)
  7. Integer 7

Each value must equal itself and must not be unequal to itself. Every pair at different positions must compare unequal in both operand orders:

  • lhs == rhs is False.
  • lhs != rhs is True.

This includes pairs of polynomials having the same degree but different coefficients.
