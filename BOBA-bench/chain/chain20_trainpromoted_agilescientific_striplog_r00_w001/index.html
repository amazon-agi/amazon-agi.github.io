Task Specification for the striplog Package

Your task is to implement a Python package named striplog that provides models for geological rock descriptions, intervals, and striplogs. It must be possible to import the classes listed below directly from the top-level package:

from striplog import Component
from striplog import Lexicon
from striplog import Decor
from striplog import Legend
from striplog import Interval
from striplog import Striplog

1. Component

This class stands for a rock or material whose description consists of a set of named attributes.

Constructor

Build an instance as Component(properties); properties is a dict whose keys are attribute names (strings) and whose values are strings, e.g. {'colour': 'grey', 'grainsize': 'vf-f', 'lithology': 'sand'}.

Accessing attributes

An attribute, reachable through dot notation, exists for each key of the input dict. When an attribute is accessed, its name is lowercased; its value, however, is stored and returned exactly as passed:

rock = Component({'colour': 'grey', 'grainsize': 'vf-f', 'lithology': 'sand'})
rock.colour      # 'grey'
Equality semantics

Two Component instances count as equal when their attributes match case-insensitively on both keys and values. Concretely:

Component({'colour': 'grey', 'grainsize': 'vf-f', 'lithology': 'sand'})
== Component({'grainsize': 'VF-F', 'colour': 'Grey', 'lithology': 'Sand'})   # True

whereas semantically different values make the components unequal:

Component({...'sand'...}) != Component({...'sandstone', grainsize 'Coarse'...})   # True

!= must amount to the logical negation of ==.

summary(fmt=...)

A formatted string is what this method returns. The fmt argument is a Python format string; component attributes are what its replacement fields name. Field names are handled case-insensitively, and:

  • Given a lowercase field name, the value is yielded as stored.
  • Given an uppercase field name, the value is yielded uppercased.

Example:

rock = Component({'colour': 'grey', 'grainsize': 'vf-f', 'lithology': 'sand'})
rock.summary(fmt="My rock: {lithology} ({colour}, {GRAINSIZE})")
# 'My rock: sand (grey, VF-F)'

If summary() is called with no arguments, it must return a non-empty string that describes the component (this string is used elsewhere; e.g. a component whose only attribute is lithology='volcanic' summarizes to 'Volcanic').

Component.from_text(text, lexicon)

Classmethod. A free-text rock description is taken in and parsed with a Lexicon; the Component returned is equal to the one that would be built from the parsed attributes. To illustrate: 'Grey coarse sandstone.', parsed with the default lexicon, must yield a component equal to Component({'grainsize': 'Coarse', 'colour': 'Grey', 'lithology': 'Sandstone'}).

You must be able to use a Component as a membership target: component in striplog (see Striplog).

2. Lexicon

The vocabularies used in parsing geological text are held by this class (synonyms, abbreviations, and category word lists such as colours, grainsizes, lithologies).

Lexicon.default()

Classmethod. The lexicon it returns is ready to use, stocked with sensible built-in vocabularies sufficient to satisfy the behaviors below.

find_synonym(word)

For a word that has a synonym mapping, the canonical term is what gets returned; e.g. find_synonym('Halite') returns 'salt'. A word that has no synonym should return the word itself.

expand_abbreviations(s)

Whitespace-separated abbreviations found in a string are expanded to their full words; the order is preserved, and spacing comes out as single spaces. For example:

lexicon.expand_abbreviations("lt gn ss w/ sp gy sh")
# 'lighter green sandstone with spotty gray shale'

At least the following abbreviations must be present in the set: lt→lighter, gn→green, ss→sandstone, w/→with, sp→spotty, gy→gray, sh→shale.

Strings such as 'Grey coarse sandstone.' must be parseable by the default lexicon into colour/grainsize/lithology attributes.

3. Decor

A display style tied to a Component.

Constructor

Build one as Decor(d), with d a dict that includes:

  • 'component': an instance of Component
  • 'color' (or 'colour'): a colour — for instance a hex string like '#86F0B6'
  • 'width': a width given numerically
Exposed attributes
  • decor.component — the Component as stored.
  • decor.colour — the colour after normalization to a lowercase hex string (e.g. '#86f0b6'); the input key can equally be color or colour, and both map to this attribute.
  • decor.rgb — the colour expressed as an (r, g, b) tuple of integers, e.g. (134, 240, 182).

4. Legend

An ordered collection of Decor entries; colours/widths get mapped to components through it.

Legend.from_csv(csv_text)

Classmethod. A CSV string is what the legend gets built from. Its first line serves as a header that names the columns. To mark a Component attribute, a column name may carry the prefix component . The header below is the supported one (whitespace around commas must be tolerated):

colour, width, component lithology, component colour, component grainsize

Each row after the header supplies a colour, a numeric width, and component attribute values (lithology, colour, grainsize). Empty fields are permitted. Each row turns into a single Decor.

The example input contains 19 data rows (one of them an all-blank component with colour #FFFFFF and width 0).

Legend.default()

Classmethod. A built-in default legend is what it returns.

Indexing and iterating
  • legend[i] returns the i-th Decor, while the normalized lowercase hex ('#f7e9a6') is what legend[1].colour returns.
  • Iteration over a legend yields its Decor objects in order (hence [d.colour for d in legend] gives all the colours; the example legend has length 19).
get_colour(component)

This method returns the lowercase hex colour of whichever Decor has a component that matches the given component. Matching here amounts to component equality, restricted to the attributes the legend entry contains — a queried component is matched by a legend Decor when all of the legend component's specified attributes agree (case-insensitively) with that component. Examples based on the CSV above:

  • With {'colour':'grey','grainsize':'vf-f','lithology':'sand'} as the component, the mapping is to '#eeeeee' (the match is the blank/whitespace-only component entry, which normalizes to that default colour when no lithology is specified).
  • With {'colour':'red','grainsize':'vf-f','lithology':'sandstone'} as the component, the mapping is to '#ffdbba'.
get_width(component)

The numeric width of the Decor that matches is returned, as a float. In the red vf-f sandstone case above, the value is 3.0.

get_component(colour)

The argument is a hex colour string; the Component of the Decor that matches is returned. With '#f7e9a6', the component returned has lithology == 'sandstone'.

5. Interval

A depth/elevation interval holding one or more components.

Constructor

Create one via Interval(a, b, components=[...]); a and b are numeric boundaries, while components is a list of Component objects. You may supply the two boundaries in either order (top-first or base-first).

Exposed attributes
  • interval.components — the components, as a list.
  • interval.primary — the component occupying the first position in the list.

6. Striplog

A sequence of Interval objects, kept in order.

Constructor

Striplog([iv1, iv2, ...]) builds one.

order

The intervals a Striplog contains determine its ordering:

  • 'elevation' if they run bottom-up (in each interval the first boundary is greater than the second, with depth decreasing as the list goes down).
  • 'depth' if they run top-down (with depth increasing).
Length, start and stop
  • len(striplog) — the number of intervals it holds.
  • striplog.start — the shallowest boundary value to be found across all intervals.
  • striplog.stop — the deepest boundary value to be found across all intervals.

Take a set of elevation-ordered intervals spanning 100–200: here order == 'elevation', start == 100, stop == 200. Take depth-ordered intervals spanning 80–250: here order == 'depth', start == 80, stop == 250.

Access by index

striplog[i] returns the i-th Interval — negative indexing is supported. .primary and .components are exposed by each interval.

Striplog.from_img(imgfile, start, stop, legend=...)

Classmethod. An image file is the input: a striplog gets built from it, with its colour bands interpreted against the given legend and depths running from start to stop. The value returned is a Striplog.

Striplog.from_csv(csv_string, lexicon=...)

Classmethod. The CSV string it takes has lines of the form top, base, description (whitespace tolerated); via the lexicon, each description is parsed into components, and from these the striplog is assembled.

find(term)

Components are matched against the search term (e.g. a lithology name like 'sandstone'); the method returns a Striplog (a subset) made up of the intervals whose components match. This result:

  • can be indexed, and each interval it returns exposes .components;
  • has a .cum attribute that gives the cumulative thickness of the matched intervals.
depth(d)

The Interval covering the depth d is returned; .primary.lithology provides its primary lithology.

to_las3()

What the method returns is a string representation of the striplog, and this string is non-empty.

Membership testing

component in striplog returns True in the case where the Component being tested is equal to one contained in any interval.

top

An attribute; it yields a grouped/summarized view of the striplog, and it must support len(...).

7. Utilities for colour conversion

From striplog.utils, the package must provide these public functions:

Accepts a list or tuple of exactly three integer RGB channels in the range 0–255; the corresponding six-digit hex colour string is returned. The string starts with #, and its hexadecimal digits are uppercase.

rgb_to_hex((255, 128, 128))    # '#FF8080'

Accepts a six-digit hex colour string case-insensitively; what it returns is an (r, g, b) tuple of three integers in the range 0–255.

hex_to_rgb('#ff8080')    # (255, 128, 128)

Accepts a colour name case-insensitively; the return value is that name's six-digit hex colour string, written with uppercase hexadecimal digits.

name_to_hex('red')    # '#FF0000'
name_to_hex('Red')    # '#FF0000'
hex_to_name(hex_string)

Accepts a hex colour string case-insensitively; the corresponding lowercase colour name is the return value.

hex_to_name('#FF0000')    # 'red'
hex_to_name('#ff0000')    # 'red'

The target is CPython 3.6+ (Python 3.5 and PyPy are not targets). numpy is available for use as a dependency.

Equality

  • Comparing a Component with an object that is not a Component, such as a string, returns False rather than raising an exception.
summary(fmt=..., default=...)

Returns a formatted string that describes the component.

striplog.interval.Interval

Models a single lithologic or stratigraphic interval bounded by a top and a base, holding one or more Components.

Constructing an Interval

Interval(top, base, description, lexicon=..., components=...)

  • The numeric bounds top and base are exposed as the float attributes .top and .base.
  • When a free-text description and a lexicon are supplied, the description is parsed through the lexicon into the interval's .components, a list of Components. For example, Interval(20, 40, "Grey sandstone.", lexicon=lexicon) yields a component with colour == 'grey' and lithology == 'sandstone'.
  • Alternatively, an explicit list may be supplied through the components keyword, e.g. Interval(120, 100, components=[r1]), and is stored as .components.
Properties
  • The first component in .components is exposed as .primary.
  • .thickness is the absolute difference between the bounds, abs(base - top), expressed as a float.
summary(fmt=...)

Returns the string "{thickness:.2f} m of {formatted components}"; the thickness is rendered with two decimal places, and each component is rendered with the component-style template fmt (multiple components are joined into a single phrase).

  • For Interval(20, 40, "Grey sandstone.", lexicon=lexicon) together with fmt="{colour} {lithology}", the result is "20.00 m of grey sandstone".
  • For Interval(40, 65, "Red sandstone.", lexicon=lexicon) and the same template, the result is "25.00 m of red sandstone".
Comparing intervals

Intervals are compared by thickness:

  • Two intervals with different thickness are unequal.
  • > compares thicknesses, the thicker interval being the greater. So max(interval_a, interval_b) returns the thicker interval.
Adding intervals
  • interval + other_interval returns a new Interval whose .components is the concatenation of the two intervals' components and whose bounds cover both intervals. For the adjacent intervals 20–40 and 40–65, the merged interval has two components and satisfies base - top == 45.0.
  • interval + number extends the interval by that numeric amount, returning a new interval with increased thickness. For an interval 20 units thick, interval + 5 has .thickness == 25.0.
  • Adding a type that is not supported, such as a string, raises IntervalError.

striplog.striplog.Striplog

A collection of Intervals that is kept in order.

Constructing a Striplog

Striplog(list_of_intervals)

  • Construction from an empty list raises StriplogError.
  • The intervals are sorted automatically, and the ordering that is detected is exposed as the .order attribute:
    • If every interval's base lies above its top (base < top)—that is, the intervals are defined bottom-up in elevation—then .order == 'elevation'.
    • If every interval's base lies below its top (base > top)—that is, the intervals are defined top-down in depth—then .order == 'depth', and the intervals are ordered by increasing top.

For example, given:

iv1 = Interval(120, 100, components=[r1])
iv2 = Interval(150, 120, components=[r2])
iv3 = Interval(180, 160, components=[r1, r2])
iv4 = Interval(200, 180, components=[r3, r2])

a Striplog holding all four has length 4, .order == 'elevation', .start == 100, and .stop == 200.

Conversely, a Striplog built from top-down intervals like 80–120, 120–150, 180–200, and 200–250 has length 4, .order == 'depth', .start == 80, and .stop == 250.

.start, .stop, and .order
  • .start is the smallest bound across all intervals.
  • .stop is the largest bound across all intervals.
  • After the striplog's contents are modified, .start and .stop reflect the new extents.
Length, iteration, indexing, replacement, and deletion
  • len(striplog) equals the number of intervals.
  • Iteration yields the intervals in order; for example, [iv.thickness for iv in striplog] has one value per interval.
  • Indexing with striplog[i] gets the i-th interval.
  • The assignment striplog[i] = interval replaces the i-th interval.
  • del striplog[list_of_indices] deletes several intervals at the supplied integer indices in a single operation.
Adding striplogs

striplog_a + striplog_b returns a new, ordered Striplog holding all intervals from both operands. Two two-interval striplogs therefore produce a four-interval striplog with the combined extents of the two operands.

find_gaps()

Returns a collection that identifies gaps between intervals, and an empty or otherwise falsy result when there are no gaps. Introducing discontinuities by replacing or deleting intervals makes the number of gaps grow accordingly; deleting N intervals from a contiguous log produces N gaps.

prune(limit=...)

Removes intervals that are thinner than limit, using the same units as interval thickness, and modifies the striplog in place.

anneal()

Closes the gaps in place. After annealing, find_gaps() is empty or falsy.

find(term)

Looks for intervals whose primary component, components, or description match term, such as a lithology name. It returns a striplog-like result that:

  • supports indexing, so .find('sandstone')[1] returns an interval;
  • has a .cum property that gives the cumulative thickness of the matching intervals.
depth(d)

Returns the interval that is present at depth d; its primary lithology is available as .primary.lithology.

thickest(n=...) and thinnest(n=...)

Return the n thickest or thinnest intervals in an indexable, striplog-like result. For example, thickest(n=7)[1] and thinnest(n=7)[1] return intervals whose .primary.lithology can be inspected.

.cum

The cumulative thickness of all the intervals in the striplog.

.top

A summary of the striplog's contents: it holds one entry for each distinct primary component, with the intervals' primary components grouped according to component equality. Each entry pairs a component with the cumulative thickness of the intervals whose primary equals that component, and the entries themselves are ordered by decreasing cumulative thickness. As a result, len(striplog.top) equals the number of distinct primary components in the striplog.

to_las3()

Returns a non-empty string representation in LAS3 format.

to_log()

Returns a numeric log representation that supports two-dimensional indexing; for example, to_log()[1][5] returns a floating-point value.

Membership testing

component in striplog returns True when that component appears in any interval's components.

Striplog.from_csv(text, lexicon=...) (classmethod)

Parses CSV text that contains one top, base, description interval per line, tolerating surrounding whitespace and using the lexicon to parse each description. On the resulting striplog, the .top property behaves as defined above; its length equals the number of distinct primary components parsed from the descriptions. Striplog.from_image(...) and Striplog.from_img(...) (classmethods)

A module for Markov-chain analysis is to be added at striplog/markov.py, together with the plotting adjustments described further down. The Markov class must be importable in this way:

from striplog.markov import Markov_chain

The functionality may draw on NumPy, on SciPy for the chi-squared distribution functions, and on matplotlib. Other required third-party dependencies must not be introduced.

Markov_chain

Instantiation
Markov_chain(observed_counts, states=None, step=1)
  • observed_counts is a square, 2D array-like matrix of transition counts; the entry [i, j] records how many transitions from state i to state j were observed.
  • states is optional: an ordered sequence supplying one label for each row and column of the matrix. Both axes use this single ordering.
  • step is an integer, the transition lag, and 1 is its default.
  • The states and the step must be retained by the instance, which must also expose observed_counts as a float-valued array compatible with NumPy.
String form

Both str(m) and the object representation must look like this:

Markov_chain(<N> transitions, states=<states_list>, step=<step>)

N is the total over all observed counts, shown as an integer, and states_list is formatted with normal Python list formatting. As an example:

data = [[0, 37, 3, 2],
        [21, 0, 41, 14],
        [20, 25, 0, 0],
        [1, 14, 1, 0]]

m = Markov_chain(data, states=['A', 'B', 'C', 'D'])
str(m)

the exact output must be:

Markov_chain(179 transitions, states=['A', 'B', 'C', 'D'], step=1)

Building from observations

Markov_chain.from_sequence(sequence, include_self=False, ...)

sequence is an ordered iterable of state observations. A string counts as a sequence of single-character state labels. The method is required to:

  1. Work out the distinct labels present in the observations.
  2. If labels are inferred, sort them into ascending label order. This sorted sequence is the states order and the row/column order for every matrix; it is not the first-appearance order.
  3. Treat every adjacent ordered pair as a transition and count it.
  4. Retain diagonal transitions when include_self=True; when include_self=False, transitions whose two labels are equal are excluded.
  5. Return a Markov_chain that carries the resulting floating-point counts and has the default step, 1.

The label-to-index mapping must stay consistent across states, all the numerical arrays, and the plots. Specifically:

sequence = (
    'sssmmmlllmlmlsslsllsmmllllmssssllllssmmlllll'
    'ssssssmmmmsmllllssslmslmsmmmslsllll'
)
m = Markov_chain.from_sequence(sequence, include_self=True)

this has ['l', 'm', 's'] as its state order, and the resulting counts are:

[[19., 5.,  7.],
 [ 6., 9.,  5.],
 [ 7., 6., 14.]]

The sum is 78 because every adjacent pair, repeated labels included, is counted.

Expected transitions

expected_counts

A NumPy array called expected_counts must be exposed. It holds the finite-tolerance quasi-independence fit defined in this section; a different marginal fit driven to full convergence does not give an equivalent result.

Let the observed matrix be O, with n states; define:

r[i] = sum_j O[i, j]       # observed row totals
c[i] = sum_j O[j, i]       # observed column totals

Two floating-point factor vectors, a and b, are used, and both begin as all ones. One complete round of updates refreshes a first, and the freshly refreshed a is then what refreshes b:

a_new[i] = r[i] / (sum(b_old) - b_old[i])
b_new[i] = c[i] / (sum(a_new) - a_new[i])

Once a complete round is finished, convergence counts as reached only when both of the conditions below hold for every element:

abs(a_new - a_old) < 0.001 * a_new
abs(b_new - b_old) < 0.001 * b_new

Take the factors from the first round in which both conditions are met; do not carry on to a tighter limit. Build the unfollowed fitted matrix like this:

E[i, j] = b[i] * a[j]

So the matrix columns receive the factors fitted from the observed row totals, while the matrix rows receive the factors fitted from the observed column totals. Each factor denominator leaves the diagonal out, even when self-transitions were observed. Any observed diagonal counts are themselves part of the observed row totals and column totals.

What happens to the diagonal follows the observed matrix:

  • If the observed diagonal is structurally zero as a whole, the fitted diagonal is set to zero once E has been formed.
  • If any observed diagonal entry is nonzero, the diagonal of the outer product is retained; the fitted matrix must not be hollowed.

With this stopping rule, 11 update rounds are reached for the four-state example, and 9 rounds for the three-state sequence example. These finite-tolerance results are deliberate.

Take the matrix:

[[ 0, 37,  3,  2],
 [21,  0, 41, 14],
 [20, 25,  0,  0],
 [ 1, 14,  1,  0]]

together with states ['A', 'B', 'C', 'D']; here expected_counts must be numerically equal to:

[[ 0.        , 31.27069125,  8.17143874,  2.55787001],
 [31.28238248,  0.        , 34.05692583, 10.66069169],
 [ 8.17137105, 34.04391563,  0.        ,  2.78471333],
 [ 2.55797970, 10.65716447,  2.78485582,  0.        ]]
expected_freqs

A NumPy array named expected_freqs must be exposed too. Its derivation is based on the fitted expected-count matrix, not on the observed column marginals. The transition probabilities for each fitted row are what that row contains:

expected_freqs[i, j] = expected_counts[i, j] / sum_k expected_counts[i, k]

If the fitted diagonal is retained, the fitted matrix is an outer product, and therefore every row is identical. Put another way, dividing the fitted column totals by the fitted grand total yields each row. In the case of the three-state sequence above, the result must be:

[[0.49712747, 0.19796476, 0.30490777],
 [0.49712747, 0.19796476, 0.30490777],
 [0.49712747, 0.19796476, 0.30490777]]

Normalized differences

normalized_difference must be exposed as a NumPy array whose entries are element-wise Pearson residuals:

(observed_counts - expected_counts) / sqrt(expected_counts)

A structural cell whose observed and expected values are both zero must contribute zero rather than NaN; for that purpose, a negligible guard on the denominator, such as 1e-12, may be applied.

On the three-state sequence, normalized_difference must be numerically equal to:

[[-2.24633883, -2.14054029, -2.81568096],
 [-1.81677174,  1.82886491, -0.94412655],
 [-2.68890472, -0.51627836,  0.76836845]]

Chi-squared result

m.chi_squared()

The tuple returned contains three values:

(chi2, critical_value, cumulative_probability)

in which:

  • chi2 is obtained by summing (O - E)^2 / E over the transition matrix, and structural zero/zero cells contribute zero to the sum.
  • With n states, the degrees of freedom come to (n - 1)^2 - n.
  • critical_value is the chi-squared quantile at the 95th percentile, for those degrees of freedom.
  • cumulative_probability comes from evaluating the chi-squared CDF at chi2 for the same degrees of freedom. This is the cumulative probability rather than the upper-tail survival probability.

In the four-state example there are 5 degrees of freedom, and the returned values must be approximately:

(35.73687369691601, 11.070497693516351, 0.9999989278539752)

Plot of the normalized differences

ax = m.plot_norm_diff(ax=ax)

If an axes object is supplied, the drawing goes onto that object, and that same object is what gets returned. With default settings, the plot must:

  • present normalized_difference as a heat map built from square cells, with the matrix's first row at the top;
  • apply the RdBu colormap;
  • give the colors symmetric limits, -L and +L, where L = ceil(max(normalized_difference)) (this is not the ceiling of the maximum absolute value);
  • add a colorbar;
  • put string forms of the ordered state labels on both axes;
  • have the column labels at the top and the row labels at the left; and
  • suppress the tick marks together with the bottom and right labels.

For an inferred sequence, the labels must come from the same sorted state mapping as the matrix.

Alignment support for Striplog.bar

Besides the arguments it already takes, such as height, sort, reverse, legend, ax, and figsize, Striplog.bar must accept an align keyword argument. align must be forwarded unchanged to the underlying matplotlib bar operation, which is what makes calls such as the following work:

ax = striplog.bar(sort=True, legend=legend, ax=ax, align='center')

Every part of the existing sorting, coloring, legend, axis, and return behavior must stay unchanged.

Labels for Striplog.hist / Striplog.histogram

Whenever a histogram is drawn, its x-axis labels must match, one-to-one, the aggregated entities that the bars represent, and in the same order as those bars. After lumping and sorting, exactly one label must exist for each distinct plotted entity, instead of one label for every original interval. The alias behavior of histogram with hist must be retained.

Because of this, plotting onto supplied axes must work in the case where a striplog holds more source intervals than distinct components. The histogram's values, ordering options, coloring behavior, return values, and y-axis labeling are left as they are.

Numerical compatibility

Every array and every scalar result must match the reference values given earlier within normal NumPy floating-point comparison tolerance.

Call form for the constructor:

Markov_chain(observations, states=None, step=1, include_self=False)

If an instance is constructed from four states and 179 transitions, with step=1 left as the default and include_self omitted, str(instance) must return exactly:

Markov_chain(179 transitions, states=['A', 'B', 'C', 'D'], step=1, include_self=False)

So the default value represented for include_self is False.

striplog.Striplog.from_dict

The following class method must be provided:

Striplog.from_dict(tops)

It must accept a dictionary that maps interval names to numeric top positions and return a Striplog.

For the following input:

{
    'Ardmore': 2510.03,
    'Cody': 2521.61,
    'Sussex Upper Top': 2521.61,
    'Sussex Lower Top': 2527.71,
    'Sussex Lower Base': 2528.62,
    'Sussex Upper Base': 2529.54,
    'Niobrara': 2530.75,
}

the object that is returned must:

  • Hold seven intervals, one for each dictionary entry.
  • Preserve entries whose numeric positions are equal instead of deduplicating them.
  • Keep a zero-thickness interval associated with Cody.
  • striplog.thinnest() must return that interval such that:
striplog.thinnest().summary()

returns exactly:

0.00 m of Cody

No dictionary validation or error behavior beyond this is required.

striplog.Striplog.extract

The required form of the call is:

Striplog.extract(self, log, basis=basis, name=name, function=function)

The method must return a Striplog holding the extraction result; callers must be able to use the return value directly:

result = striplog.extract(
    log,
    basis=basis,
    name="Log",
    function=np.mean,
)

The extracted values must be stored under the supplied name in the data mapping belonging to each applicable interval.

For the existing numerical extraction scenario, the first returned interval must satisfy:

result[0].data["Log"] == 2.0

It is not constrained whether the original receiver is also mutated; the behavior that is required is that the returned Striplog contains the extracted data.
