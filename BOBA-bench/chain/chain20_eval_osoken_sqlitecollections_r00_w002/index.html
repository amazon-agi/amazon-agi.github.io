Part 1: sanitize_table_name function

Implement a function in the base module:

def sanitize_table_name(table_name: str, prefix: str = ...) -> str
Behavior

Given an arbitrary input string, produce a "sanitized" table name by removing all characters that are not valid in a table name identifier. The set of valid characters consists of:

  • ASCII letters (a–z, A–Z)
  • ASCII digits (0–9)
  • the underscore character (_)

All other characters (including but not limited to ~ ! @ # $ % ^ & * ( ) + - = { } | [ ] \ ; : ' " < > ? , . / and whitespace) must be stripped out entirely, preserving the order of the remaining valid characters.

Examples of the transformation:

  • Input "~!@#$%^&*()_+-=qwerty{}|[]\\;:'\"<>?,./01234abc" → output "_qwerty01234abc"
  • Input "abc" → output "abc"
The prefix parameter

The function accepts an optional second parameter, prefix. Its purpose is to be used only when the sanitized result would otherwise be invalid as a table name. When the input, after sanitization, already yields a valid (non-empty) table name, the prefix argument must be ignored and have no effect on the returned value.

  • sanitize_table_name("abc", prefix="list") must return "abc" (the prefix is ignored because "abc" is already a valid table name).

The exact behavior of prefix in the case where sanitization produces an invalid/empty result is not otherwise constrained by this task, but the parameter must exist and be accepted without error.

Part 2: Default connection setup when constructing a collection with no arguments

The base module contains a base class SqliteCollectionBase. When an instance of a concrete subclass is created with no constructor arguments (no connection provided), the object must establish its own database connection using a temporary file.

Required behavior

When constructing such an object with no arguments:

  1. A temporary file must be created by calling NamedTemporaryFile (referenced within the base module as sqlitecollections.base.NamedTemporaryFile). This call must be made with the keyword arguments suffix=".db" and prefix="sc_".
  2. The .name attribute of the object returned by NamedTemporaryFile provides the filesystem path of the temporary file.
  3. A SQLite connection must be established by calling sqlite3.connect (referenced within the base module as sqlitecollections.base.sqlite3.connect) exactly once, passing that temporary file name as its single positional argument.
  4. The resulting connection object must become the object's connection attribute (accessible via the instance's connection property).

In other words, the temporary-file creation and the sqlite3.connect call must happen directly (via NamedTemporaryFile and sqlite3.connect at module scope), rather than being delegated to any intermediate helper functions.

Removal of prior helpers

The previously existing helper functions create_temporary_db_file and create_tempfile_connection in the base module must no longer be present/used. Their logic is folded directly into the connection-setup path described above.

Other constructor behavior (unchanged, must still hold)

When constructed with no arguments, the resulting instance must also expose:

  • a serializer attribute equal to the module/class default serializer,
  • a deserializer attribute equal to the module/class default deserializer.

(These are the existing defaults; do not alter them.)

Summary of the public API surface

  • sqlitecollections.base.sanitize_table_name(table_name: str, prefix: str = ...) -> str

      returning the dictionary’s keys-view object.

  • The keys-view object must support:

    KeysView.__rsub__(self, other: Iterable[Any]) -> sqlitecollections.Set

  • sqlitecollections.Set

    • The returned object must expose its backing SQLite table name through:
      result.table_name

  • sqlitecollections.base.SqliteCollectionBase._default_serializer(value) remains the serializer used for values stored in the result set.

Behavior

For an expression of the form:

left_iterator - dictionary.keys()

the keys view’s reflected subtraction must return a sqlitecollections.Set containing the elements from the left iterator that are not keys in the dictionary.

Given a dictionary backed by an existing SQLite table containing the keys "a", "b", and "c":

result = iter((1, 2, 3)) - dictionary.keys()

must:

  • return an instance of sqlitecollections.Set;
  • contain 1, 2, and 3;
  • store those values in the result’s backing table as serialized_value values produced by SqliteCollectionBase._default_serializer;
  • create the result’s backing table in the same SQLite connection as the dictionary.

Similarly:

result = iter(("a", "b")) - dictionary.keys()

must return an empty sqlitecollections.Set, because both left-side values are dictionary keys. The empty result must still have a queryable backing table identified by result.table_name.

Creating either result must not modify the original dictionary table.

Result lifecycle

The returned set’s backing table is temporary to that result object. Once the result object is deleted, its backing table must be removed from the shared SQLite connection, leaving the original dictionary table intact and no result table behind.
