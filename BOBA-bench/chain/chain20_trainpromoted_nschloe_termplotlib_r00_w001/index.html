Task Specification: Subplot Grid Rendering

Overview

Implement subplot-grid rendering in the package used as apl (for example, import asciiplotlib as apl). A subplot grid arranges independent text cells into a rectangular grid and renders the complete grid as one bordered ASCII string.

Public API

apl.subplot_grid(shape, width, border_style=..., padding=...)

Create and return a subplot-grid object.

  • shape is a 2-tuple (rows, cols) giving the number of grid rows and columns.
  • width is an integer giving the total character width of the rendered output, including all outer borders and column separators.
  • border_style is an optional compatibility keyword. It must be accepted, but its value does not change rendering: all borders and separators are always drawn with x. For example, border_style="|" still produces x borders.
  • padding controls padding inside every cell. When omitted, the default is 1 blank row at the top and bottom and 2 spaces at the left and right. When supplied as an integer p, it applies p units to all four sides in top, right, bottom, left order: p blank rows above and below the content and p spaces to its left and right.

The returned grid object must support:

  1. Two-dimensional item access: grid[r, c] returns the cell at zero-based row r and column c. Every grid position has an independent cell object.
  2. grid.get_string(): returns the fully rendered grid as one string, with newline characters between display rows and no trailing newline.
Cell objects

Each cell obtained through grid[r, c] must support:

  • cell.aprint(text): records text for display in that cell. Newline characters split the text into separate display lines, retained in order. Only the behavior of a single aprint call per cell is required.

Rendering Behavior

The renderer uses x for every outer border, vertical separator, and horizontal separator. Padding and otherwise empty areas contain spaces.

Width and column allocation

For total width W and C columns, there are exactly C + 1 one-character vertical borders: the two outer borders and C - 1 separators. The remaining width is allocated to the cell fields. Define:

available = W - (C + 1)
base, remainder = divmod(available, C)

Every column has field width base, and the first remainder columns from the left each receive one additional character. Equivalently, column j has width base + 1 when j < remainder, and base otherwise. Thus leftover width is distributed left to right rather than placed in the last column or discarded.

For example, with width=20 and two columns, the cell-field widths are [9, 8]: 17 characters remain after the three vertical borders, so the first field receives the extra character. With width=40 and three columns, all three field widths are 12.

Every rendered display row is exactly width characters wide. A content row has this structure:

x<column 0 field>x<column 1 field>x...x<last column field>x
Horizontal borders and grid rows

A horizontal line consisting entirely of width x characters is rendered:

  • at the top of the grid,
  • between every pair of adjacent grid rows, and
  • at the bottom of the grid.

Each grid row is rendered independently between its surrounding horizontal lines. All cells in one grid row use the same displayed height, large enough for the cell with the most text lines in that row together with the required top and bottom padding. Cells with fewer lines are filled with spaces for the remaining display rows.

With default padding, text starts after one blank content row and is followed by at least one blank content row. Consequently, a grid row whose tallest cell has N text lines has N + 2 content rows under the default padding. With an integer padding value p, there are p blank rows before the text and p blank rows after it; a row whose tallest cell has N lines therefore has N + 2p content rows.

Text placement, padding, and truncation

Within each cell field:

  • Text lines appear in input order, one line per display row, after the top padding.
  • A line is left-aligned after the cell's left padding.
  • The usable text width is the column's field width minus its left and right padding. A line longer than that usable width is truncated to fit.
  • Shorter lines and empty areas are right-padded with spaces so that the complete field always occupies its assigned width.

Under the default padding, a 12-character field has 2 leading spaces, room for at most 8 text characters, and 2 trailing spaces. Thus Some more text renders as Some mor, Some text as Some tex, and even more as even mor in such a field.

  • border_style: controls how the grid's border/separator lines are drawn (see "Border Styles" below). Default is the light box-drawing style described below.
  • width: the total display width (in characters) of the rendered grid, including all border characters.
  • padding: an integer number of blank content lines to add above and below each cell's text within the cell. Default is 0.
Return value

subplot_grid returns a grid object that:

  • Supports item access by (row, col) index: grid[r, c] returns the subplot cell at that position (0-based).
  • Each cell exposes a method aprint(text) that sets/adds the cell's text content. The text may contain embedded newlines (\n) to produce multiple lines within the cell.
  • Exposes a method get_string() that returns the fully rendered grid as a single string (no trailing newline).

Rendering Behavior

Layout and sizing
  • The total rendered width equals width. This width includes the left border, the vertical separators between columns, and the right border. The interior area is divided among the columns.
  • Each column's interior content area has equal width; when the interior does not divide evenly, columns are sized so the total (including all border/separator columns) exactly matches width. Earlier columns may be one character wider than later columns.
  • Each cell's text is placed within its interior area. Each line of text is truncated to fit the cell's interior content width if necessary, and is horizontally centered within that area.
  • Within a cell, content lines consist of: padding blank lines, followed by the cell's text lines, followed by padding blank lines. All cells in the same grid row share the same number of content lines, equal to the maximum needed across cells in that row; shorter cells are padded with additional blank lines at the bottom so all cells in a row have equal height.
  • There is a blank content line (one space of vertical margin) at the top and bottom of every cell's content region, in addition to any padding lines.
Border drawing

Borders are drawn around the entire grid, between adjacent rows, and between adjacent columns. The rendering uses the following components depending on the selected style:

  • Top-left, top-right, bottom-left, bottom-right corners.
  • Horizontal line segments (top, bottom, and interior horizontal separators between rows).
  • Vertical line segments (left, right, and interior vertical separators between columns).
  • Junction characters where interior separators meet the outer border (top edge, bottom edge, left edge, right edge) and where interior separators cross each other.

Horizontal border segments fill the full width of each column's interior. Junctions appear at each point where a vertical separator meets a horizontal line.

layout is a two-item (rows, columns) shape. Indexing with grid[row, column] returns that cell's Figure, on which aprint and the other figure content methods are available.

width and column_widths are alternatives and must not both be supplied:

  • With total width=W and n columns, border positions count toward the total. Compute q, r = divmod(W - (n + 1), n); the first r interior columns have width q + 1 and the remaining columns have width q.
  • column_widths must contain exactly one value per column, and each value is that column's exact interior width.
  • If neither is supplied, each column is as wide as the widest rendered cell in that column across all grid rows, including cell padding.

The total-width formula continues to reserve the n + 1 border positions when borders are suppressed.

The default per-cell padding is (1, 2): one blank line above and below and two spaces on both sides. Embedded newlines create explicit cell lines. Text is clipped to the available interior width after horizontal padding and is never automatically wrapped. Within each grid row, shorter cells are extended with blank lines to the tallest cell and content lines are space-filled to the column width.

Border styles

border_style accepts:

  • "thin", "thick", or "double";
  • "thin rounded", which is the thin set with outer corners ╭, ╮, ╰, ╯;
  • "ascii";
  • any single-character string, which is repeated for every border and junction position;
  • a list of exactly 11 custom characters; or
  • None to suppress all borders.

The ordered 11 positions for a custom list are:

  1. horizontal,
  2. vertical,
  3. top-left,
  4. top-right,
  5. bottom-left,
  6. bottom-right,
  7. left junction between grid rows,
  8. right junction between grid rows,
  9. top junction between columns,
  10. bottom junction between columns,
  11. interior cross.

The built-in sets are:

  • thin: ─ │ ┌ ┐ └ ┘ ├ ┤ ┬ ┴ ┼;
  • thin rounded: ─ │ ╭ ╮ ╰ ╯ ├ ┤ ┬ ┴ ┼;
  • thick: ━ ┃ ┏ ┓ ┗ ┛ ┣ ┫ ┳ ┻ ╋;
  • double: ═ ║ ╔ ╗ ╚ ╝ ╠ ╣ ╦ ╩ ╬;
  • ASCII: - | - - - - | | - - +.

With border_style=None, fixed-width cell rows are concatenated without delimiter characters, no outer or inter-row border is drawn, and line-ending spaces are removed. Under default padding, the blank top padding of the first grid row therefore produces a leading \n in the returned string. Padding rows on either side of adjacent grid rows remain visible as blank lines.

Grid rendering methods
  • get_string() returns the complete layout with lines joined by \n. Lines are right-stripped; the completed grid has no trailing whitespace or trailing newline.
  • show() prints get_string() to standard output using normal print semantics and returns None.

General rendering requirements

  • Rendering must be deterministic for identical inputs in the same terminal environment.
  • Unicode box-drawing and block glyphs are used when the selected feature permits them and the output encoding is UTF-8. force_ascii=True uses ASCII for generated histogram or table glyphs; subplot grids use border_style="ascii" for an ASCII border.
  • Whitespace is part of the public output contract. In particular, figure-level bottom padding may leave terminal newline separators even though each line has been right-stripped; this is distinct from subplot-grid final trimming.
  • Existing plotting, histogram, table, figure, and subplot behavior must remain equivalent when accessed through asciiplotlib.

Dependencies and environment

Numeric sequences and NumPy arrays are supported inputs, and the package may use NumPy for numeric handling. Line plotting requires gnuplot. The package must otherwise import and operate under standard CPython on non-Windows platforms.

Overview

You are working on asciiplotlib, a Python package (importable as asciiplotlib, conventionally aliased apl) that renders text-based plots and tables. Public API

The rendered plot is a bordered chart with axis tick labels. The exact character-level layout is defined by the following requirements.

General structure
  1. The returned string begins with a single newline character (\n) before the first content row.
  2. Rows are separated by newline characters. There is no trailing newline at the very end of the string.
  3. The chart consists of:
    • A top border row.
    • A sequence of interior rows (the plotting canvas).
    • A bottom border row.
    • An x-axis tick-label row beneath the bottom border.
  4. Data points are plotted using the * character. A continuous curve is drawn by placing * marks approximating the data across the canvas.
Left margin and y-axis labels
  • Each chart row is preceded by a left margin used for y-axis tick labels.
  • Y-axis tick labels are right-aligned within a fixed-width margin. Labels appear on a subset of interior rows; other interior rows have blank label margins.
  • The label margin width accommodates the widest label (including a leading minus sign for negatives). Given the label set 1, 0.8, 0.6, 0.4, 0.2, 0, -0.2, -0.4, -0.6, -0.8, -1, the labels are formatted with a fixed field so that, e.g., 1 renders as 1 and -0.2 renders as -0.2 at the row start (a trailing space separates the label from the border/canvas).
Borders and gridlines

  • Interior rows that align with a labeled y-tick begin and end with +; all other interior rows begin and end with |.

Task: Add horizontal bar chart support to asciiplotlib

Overview

Implement a horizontal bar chart method on the figure object of the asciiplotlib package. The package is importable as apl (import asciiplotlib as apl).

Public API

apl.figure()

A factory function returning a figure object. The figure object must support the following methods used in this task:

  • fig.barh(values, labels, force_ascii=False) — add a horizontal bar chart to the figure.
  • fig.get_string() — return the rendered figure as a single string (no trailing newline).

barh behavior

fig.barh(values, labels, force_ascii=False) renders a horizontal bar chart, one row per data point.

Parameters:

  • values: a list of non-negative numeric values, one per bar.
  • labels: a list of strings, one per bar, aligned with values by index.
  • force_ascii: a boolean keyword argument (default False). When False, bars are drawn using the full-block character █ (U+2588). When True, bars are drawn using the asterisk character *.
Row layout

Each row consists of three sections separated by fixed spacing, in this order:

  1. Label section: the label string, left-aligned and padded on the right with spaces so that all labels occupy the same width equal to the length of the longest label. This section is followed by two spaces.

  2. Value section: the numeric value formatted as an integer, right-aligned within brackets. The number is right-justified to the width of the widest value's digit-count, and wrapped in [ and ]. For example, with values 3, 10, 5, 2 the widest value has 2 digits, producing [ 3], [10], [ 5], [ 2]. This section is followed by two spaces.

  3. Bar section: a run of the bar character whose length is proportional to the value. The maximum value maps to a bar length of 40 characters; every other bar length is round(value / max_value * 40). Using values 3, 10, 5, 2 (max = 10) this yields bar lengths of 12, 40, 20, and 8 respectively.

Output format

get_string() returns all rows joined by newline characters, with no trailing newline after the final row.
