Specification of the Task

Build a Python API client for talking to a Podman service over an HTTP-style connection to a Unix socket. The implementation must provide an ApiConnection class, helper modules for images and system operations, and a set of error classes.

Layout of the Package

It must be possible to import the following public API surface:

  • from podman import ApiConnection
  • podman.errors — a module that contains the error classes
  • podman.system — a module that contains the system functions
  • podman.images — a module that contains the image functions
Exposure of the submodule at package level

When the top-level podman package is loaded, the images submodule must be loaded as well and bound as the package attribute podman.images. This holds even when the loading of the package happens through an import of another submodule, such as import podman.errors or import podman.system. Once such an import has happened, callers must be able to use podman.images.<function> without a separate import podman.images statement.

Error Classes in podman.errors

The following exception classes must be defined:

  • NotFoundError
  • InternalServerError
  • ImageNotFound

Each one must be constructable with a single message argument, e.g. NotFoundError('nope').

The ApiConnection class (importable as podman.ApiConnection)

Constructor

ApiConnection(url, base='/v1.24/libpod') — the signature must accept url as a positional argument and base as a keyword argument. Apart from the signature shown, no further behavior around reliance on the default is required below.

Behavior:

  • If url is None, ValueError must be raised.
  • The scheme must be parsed out of the url. Only the unix scheme (and ssh scheme, see connect) are recognized as valid for construction. A URL whose scheme is tcp (e.g. "tcp://localhost//") must raise ValueError.
  • A unix:/// URL paired with an explicit base (e.g. base='/test') must construct successfully.
  • An ssh:/// URL must construct successfully.
  • The base value must be retained by the instance; it serves as a path prefix (see join).

The class should be usable as a context manager (support with ApiConnection(...) as api:), but no specific behavior on entry/exit is required beyond that.

connect(self)
  • When the connection was created from a unix:// URL, calling connect() must create a socket via socket.socket(socket.AF_UNIX, socket.SOCK_STREAM).
  • When the connection was created from an ssh:// URL, calling connect() must raise NotImplementedError.
join(self, path, params=None)

Return a string that combines the connection's base with the supplied path, and that appends URL-encoded query parameters when params is provided.

  • With base='/test', join('/foo') returns '/test/foo'.
  • With base='/test', join('/foo', {'a': '"b"'}) returns '/test/foo?a=%22b%22' (query values must be URL-encoded).
  • Multiple params are joined with & in the order given, e.g. producing '/test/bar?a=b&c=d'.
quote(self, value)

Return the URL-quoted form of value, following urllib.parse.quote semantics. To give an example, quote('"') returns '%22'.

request(self, method, path, body=None, headers=None)

Carry out an HTTP request over the underlying http.client.HTTPConnection:

  • The underlying connection's request(method, path, <body>, <headers>, encode_chunked=False) must be called. If the call passes only method and path, the body passed through must be None and the headers must be {}.
  • The underlying connection's getresponse() must be called (with no arguments) to obtain the response.
  • If the response status is 200, the response object must be returned.
  • If the response status is 404, NotFoundError must be raised.
  • If the response status is 500, InternalServerError must be raised.
get(self, path, params=None)

A wrapper that issues a GET request. self.request('GET', <joined-path>) must be called, where the joined path is produced by join(path, params):

  • get('/baz') → request('GET', '/test/baz')
  • get('/foo', params={'a': 'b'}) → request('GET', '/test/foo?a=b')
  • get('/bar', params={'a': 'b', 'c': 'd'}) → request('GET', '/test/bar?a=b&c=d')
delete(self, path, params=None)

A wrapper that issues a DELETE request, behaving like get except that the method is 'DELETE':

  • delete('/baz') → request('DELETE', '/test/baz')
  • delete('/foo', params={'a': 'b'}) → request('DELETE', '/test/foo?a=b')
  • delete('/bar', params={'a': 'b', 'c': 'd'}) → request('DELETE', '/test/bar?a=b&c=d')
post(self, path, params=None, headers=None)

A wrapper that issues a POST request in which params are sent as a URL-encoded form body rather than in the URL:

  • The path handed to request must be the joined path without query params (i.e. join(path)).
  • When params is None/empty and no headers are given: request('POST', <joined-path>, body=None, headers={}) must be called.
  • When params are provided: the body must be the URL-encoded form of the params (e.g. 'a=b', or 'a=b&c=d' for multiple params in the order given), and the headers must include 'content-type': 'application/x-www-form-urlencoded'.
  • When headers are provided as well, they must be merged with the content-type header. Example: post('/bar', params={'a': 'b', 'c': 'd'}, headers={'x': 'y'}) → request('POST', '/test/bar', body='a=b&c=d', headers={'x': 'y', 'content-type': 'application/x-www-form-urlencoded'}).

The request calls coming from post must be made using the keyword arguments body= and headers=.

raise_image_not_found(self, exc, response)

Taking an original exception exc together with a response object, parse the response body as JSON (it contains keys such as cause and message) and raise ImageNotFound. The response body must be read/decoded and run through json.loads exactly once.

Task Specification: Implementing the podman.pods Module

Summary

Add a new public module, podman.pods, offering module-level functions for managing pods via a Podman API connection. It must be importable as podman.pods.

In addition, ensure that podman.errors exposes a pod-specific PodNotFound exception.

API Connection and Response Handling

Every function takes an API connection object as its first argument. That connection provides:

  • GET requests are made with api.get(path, params=...);
  • POST requests are made with api.post(path, ...);
  • DELETE requests are made with api.delete(path, params=...); and
  • api.raise_not_found(exc, response), which translates a low-level not-found condition into a domain-specific exception.

A response that comes back from these request methods provides read(), which returns a JSON payload as bytes. Unless a function's contract states otherwise, the function must read the successful response, decode and parse that JSON, and return the resulting Python value without reshaping it. What the function must use is the client's post helper; for this operation, the function must not require or substitute a generic request method.

Behavior Requirements

When prune(api) is called, it must:

  1. Invoke api.post exactly once, passing:
    • '/networks/prune' as the sole positional argument.
    • headers={'content-type': 'application/json'} as the sole keyword argument.
    • no query parameters, no request body, and no other arguments.
  2. Use the response object that the api.post call returned, and read its body by calling .read().
  3. Parse the JSON bytes that were returned and return the Python object that results, without wrapping it or otherwise transforming it.

The endpoint path, the lowercase header name, the header value, and the argument placement are exact elements of the API contract.

Example

If the response body is:

b'[{"Name": "net1"}, {"Name": "net2"}]'

then prune(api) returns:

[{'Name': 'net1'}, {'Name': 'net2'}]

Scope and Compatibility

  • This addition applies to the legacy podman.networks module, which is function-based.
  • The behavior that all other network functions currently exhibit must remain unchanged.
  • Modules and functionality related to volumes lie outside the scope of this task; no volume changes are required.

Task: Implement Bindings for Podman Volumes

Build Python bindings for Podman volumes; these bindings supply a Volume model together with a VolumesManager that is accessible from the client. In addition, apply a small adjustment to the existing network model.

Module and API Surface

podman.domain.volumes

Add a new module podman/domain/volumes.py that exposes two public classes: Volume and VolumesManager.

Volume

A model class that represents a single volume and follows the model conventions used elsewhere in this codebase (it is constructed with attrs=<dict> and, optionally, a client/collection reference).

  • The constructor must accept an attrs keyword argument that holds the volume's attributes dictionary, e.g. Volume(attrs={"Name": "dbase"}).
  • Property attrs: returns the dictionary of attributes.
  • Property id: returns the volume's identifier; this is the value of the "Name" key in attrs.
  • Property name: returns the value found under the "Name" key in attrs.
  • In the case of a volume, id and name refer to the same underlying value.
  • Method remove(force=<bool>): removes this volume. The method must issue an HTTP DELETE to the libpod endpoint /libpod/volumes/{name}, with the force value passed as a query parameter named force. As an example, calling remove(force=True) targets .../libpod/volumes/dbase?force=True. HTTP status 204 indicates that the removal was successful.
VolumesManager

A manager/collection class whose model is Volume (it follows the same manager conventions used elsewhere in this codebase). A VolumesManager must be reachable as the volumes attribute of a PodmanClient instance (client.volumes returns a VolumesManager).

Methods:

  • create(name, labels=<dict>): Creates a volume.

    • It issues an HTTP POST to /libpod/volumes/create.
    • The JSON body of the request must contain "Name" set to the given name and "Labels" set to the labels dict that was provided. Only the fields that were provided should appear; e.g. calling create("dbase", labels={"BackupRequired": True}) sends exactly {"Name": "dbase", "Labels": {"BackupRequired": True}}.
    • Success corresponds to HTTP status 201; the JSON of the response is the volume's attributes.
    • It returns a Volume built from the response, so that the id and attrs of the returned object reflect the response body.

  • get(name): Retrieves a single volume, identified by name.

    • It issues an HTTP GET to /libpod/volumes/{name}.
    • It returns a Volume whose attrs equals the full JSON body of the response and whose id/name reflect the "Name" field.
    • When the volume is not found (HTTP 404), raise podman.errors.NotFound.

  • list(filters=<dict>): Lists the volumes.

    • It issues an HTTP GET to /libpod/volumes.
    • The method accepts an optional filters argument (a dict).
    • The JSON of the response is a list of dicts of volume attributes; the return value is a list of Volume objects, one per entry, with the order preserved.
    • If the endpoint responds with HTTP 404, return an empty list (do not raise).

  • prune(): Prunes volumes that are unused.

    • It issues an HTTP POST to /libpod/volumes/prune.
    • The JSON of the response is a list of objects, each of which contains an "Id" and a "Size".
    • The method returns a dict with two keys:
      • "VolumesDeleted": a list of the "Id" values, in order.
      • "SpaceReclaimed": the sum of all "Size" values.
    • Example: with a response of [{"Id": "dbase", "Size": 1024}, {"Id": "source", "Size": 1024}], this yields {"VolumesDeleted": ["dbase", "source"], "SpaceReclaimed": 2048}.

Integration with the Client

PodmanClient (which can be imported as from podman import PodmanClient) must expose a volumes attribute/property that returns a VolumesManager bound to the client. The client is constructed with a base_url (for example PodmanClient(base_url="http+unix://localhost:9999")) and supports a close() method. All of the libpod endpoints described above are relative to the client's versioned libpod base path (e.g. .../v3.0.0/libpod/...).

Error Handling

podman.errors.NotFound must be importable, and it must be raised as described for get.

Adjustment to the Network Model

For the domain Network model, the network remove behavior must remain functional: calling remove(force=True) on a network obtained via client.networks.get(<name>) must issue exactly one request to remove that network.

Note: for this task, the low-level podman.networks module has no prune operation.
