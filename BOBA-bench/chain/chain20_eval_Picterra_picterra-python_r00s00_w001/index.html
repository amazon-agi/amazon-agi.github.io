Task Specification: Introduce Page-Based Pagination for List Operations

Overview

Change the affected client list operations to return exactly one API page at a time. Each response must be wrapped in a sequence-like paginated result object from which callers can explicitly request the next page. This replaces the previous behavior of automatically requesting and flattening every available page into one list.

The affected methods are:

  • list_rasters
  • list_detectors
  • list_raster_markers
  • list_folder_detectors

Existing endpoint selection, filtering, item dictionaries, authentication, and HTTP error behavior must otherwise remain compatible. In particular, an unsuccessful page request must continue to raise APIError rather than return a page result.

Paginated Result Contract

Each affected method returns a paginated result representing only the response page that was explicitly requested. The object must provide the following public behavior:

  1. Indexing — result[i] returns the item at index i in the current page's results array. Items remain the raw dictionaries supplied by the API.
  2. Length — len(result) is the number of items in the current page's results array, not the API's total result count.
  3. Iteration — iterating over the object, including list(result), yields the current page's items in order and does not continue onto later pages.
  4. Next-page navigation — result.next() returns a new paginated result for the next page, or None when the current page has no successor.

No particular public class name is required; the observable sequence and navigation behavior above is the contract.

Response shape

A list response is a JSON object containing at least the following relevant fields:

  • results: the list of raw item dictionaries for the current page.
  • next: a URL string identifying the next page, or null/None if the current page is the final page.

Pagination behavior must be derived from results and next. The response's count and previous metadata are not used to determine the current page's length or navigation behavior.

Request and .next() behavior
  • Calling an affected list method performs exactly one HTTP request for its initial or explicitly selected page.
  • Returning or constructing a paginated result must not prefetch any later page. Indexing, measuring, and iterating over an already returned page must not issue further requests.
  • If next is a non-null URL, each call to .next() performs exactly one HTTP request to that URL and returns a new paginated result wrapping that response. It must not fetch any page beyond that next page.
  • If next is None, .next() returns None without issuing an HTTP request.
  • Navigation follows the URL supplied in the current response, including its query parameters.

The service uses the page_number query parameter with 1-based numbering: page 1 is the first page, and successive pages use increasing page numbers. Directly requesting a page must return the same page items, in the same order, as reaching that page through repeated .next() calls.
