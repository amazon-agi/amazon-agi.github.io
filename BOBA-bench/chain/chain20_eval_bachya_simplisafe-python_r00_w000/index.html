Task Specification: Async SimpliSafe Python Library

Overview

Implement an asyncio-based Python library named simplipy for interacting with the SimpliSafe™ home security REST API (https://api.simplisafe.com). The library authenticates a user, discovers their security systems, exposes system and sensor state, allows changing the armed state, and retrieves event history. It must support both "v2" and "v3" generations of SimpliSafe hardware, which use different API endpoints and payload shapes.

All network calls are made via an aiohttp.ClientSession supplied by the caller.

Public API Surface

simplipy package (simplipy/__init__.py)
async def get_systems(email: str, password: str, websession) -> list
  • Authenticates the user with the given email and password using the provided aiohttp client session.
  • Discovers all security systems attached to the account and returns them as a list of System objects (see below).
  • Authentication flow performs, in order:
    1. POST /v1/api/token — obtains an access token, refresh token, and expiration.
    2. GET /v1/api/authCheck — obtains the authenticated user's userId.
    3. GET /v1/users/{userId}/subscriptions — obtains the list of subscriptions/systems.
  • For each returned system, the library must then load full system data (settings/sensors) as described under System discovery & update below.

Data Model Details

System discovery & update

The subscriptions response (GET /v1/users/{userId}/subscriptions) contains a subscriptions list. Each subscription includes:

  • sid → the system id / subscription id.
  • location.system → the system info block containing serial, alarmState, isAlarming, version, etc. alarmState may be uppercase and must be interpreted case-insensitively as described above.

The value of location.system.version selects the generation:

v2 systems (version == 2):

  • Sensor/settings data is fetched from GET /v1/subscriptions/{subscription_id}/settings.
  • The response contains settings.sensors, a list of sensor objects. Some entries in this list are empty objects ({}) and must be ignored (not counted, not turned into Sensor objects). For the reference v2 data, the resulting sensors mapping contains exactly 34 sensors.
  • Each v2 sensor object has keys: type, serial, setting, sensorStatus, sensorData, name, error, and optionally battery, entryStatus.
  • v2 sensor property derivation:
    • settings = setting (int).
    • data = sensorData (int).
    • error = error (bool).
    • low_battery, triggered derived from the sensor's status fields; for the sensor with serial '195' all of error, low_battery, triggered are False, and settings == 1, data == 0.

v3 systems (version == 3):

  • Sensor data is fetched from GET /v1/ss3/subscriptions/{subscription_id}/sensors.
  • The response contains a sensors list. For the reference v3 data, the resulting sensors mapping contains exactly 21 sensors.
  • Each v3 sensor object has keys: type, serial, name, setting (a dict), status (a dict), flags (a dict with swingerShutdown, lowBattery, offline).
  • v3 sensor property derivation:
    • settings = the setting dict.
    • error derived from status/flags; for the entry sensor serial '825' it is False.
    • low_battery = flags.lowBattery.
    • offline = flags.offline.
    • triggered = status.triggered when present. For serial '825' (status.triggered == False) → False. For the siren serial '236' (empty status) → False.
    • temperature = status.temperature for temperature sensors (e.g. serial '320' → 67). Non-temperature sensors raise ValueError on access.
Setting state — endpoints and response handling

v2 (set_away/set_home/set_off):

  • Issues POST /v1/subscriptions/{subscription_id}/state (the target state is conveyed as a request parameter, not part of the path).
  • The response contains success: true and requestedState: <away|home|off>; the system's state is updated to the corresponding SystemStates member.

v3 (set_away/set_home/set_off):

  • Issues POST /v1/ss3/subscriptions/{subscription_id}/state/{state_name}, where {state_name} is the target SystemStates member's .name (away, home, or off).
  • The response contains success: true and state: <AWAY|HOME|OFF>; the system's state is updated to the corresponding SystemStates member.
Events
