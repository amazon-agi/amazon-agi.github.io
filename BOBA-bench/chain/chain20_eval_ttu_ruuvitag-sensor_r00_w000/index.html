Conversion of Raw Advertisements

The following public static method must be exposed by RuuviTagSensor, and it can be called without creating a sensor instance:

encoded = RuuviTagSensor.convert_data(raw)

raw is a hexadecimal Bluetooth advertisement string. The method interprets the octets of this string as character data and recognizes a RuuviTag URL when that data contains either of these markers:

  • ruu.vi/#
  • r/

When either marker is found, the method returns the encoded payload text that immediately follows that marker. The advertisement shown above therefore produces AjwYAMFc. Both the long and the short marker forms are valid.

The absence of a marker and malformed input are normal invalid-data outcomes: they must not cause an exception to escape. The lookup of markers must have non-raising, find-style semantics, and convert_data must return None when no supported marker can be found or when the raw value cannot be converted. In particular:

RuuviTagSensor.convert_data('not_valid') is None

Decoding the URL Payload

The existing decoder continues to be public at:

from ruuvitag_sensor.url_decoder import UrlDecoder

An instance of it exposes:

data = UrlDecoder().decode_data(encoded)

decode_data base64-decodes the RuuviTag URL payload and returns a dictionary containing temperature, humidity, and pressure values. For the URL data format that is handled here:

  • humidity is byte 1 multiplied by 0.5, expressed in percent;
  • temperature uses bytes 2 and 3 as signed 8.8 fixed-point data, where the high bit of byte 2 serves as the sign, and it is rounded to one decimal place in degrees Celsius;
  • pressure is the big-endian value in bytes 4 and 5 plus 50000 Pa, converted to hPa through division by 100.

When the payload cannot be base64-decoded, or when it does not contain the bytes required for these fields, decode_data returns None rather than propagating the decoding error.

The decoding results below are required:

UrlDecoder().decode_data('AjwYAMFc')
# {'temperature': 24.0, 'humidity': 30.0, 'pressure': 995.0}

UrlDecoder().decode_data('AjgbAMFc')
# {'temperature': 27.0, 'humidity': 28.0, 'pressure': 995.0}

The acquisition of raw advertisements remains delegated to the package's Bluetooth communication component. RuuviTagSensor is responsible for passing the appropriate MAC address to that component and for converting and decoding the data that comes back from it; callers of update() do not provide raw data themselves.

Humidity

  • The byte 00 decodes to 0.0.

  1. Apply the mask 0x7F to the first byte to obtain the integer magnitude.
  2. To that, add the second byte divided by 100.
  3. If the original first byte had its most significant bit set, negate the magnitude in its entirety, including the fractional part.
  4. Return the result rounded to two decimal places.

  • 7F63 decodes as 127 + 99/100, which is 127.99.
  • For FF63, the sign bit is set; after masking, its magnitude is likewise 127 + 99/100, so it decodes to -127.99.

Rules for Decoding Each Field

  • Temperature: Read the two bytes as a signed 16-bit big-endian number and multiply it by 0.005 degrees Celsius; the outcome is rounded to 2 decimal places. For example, 12FC decodes to 24.30.
  • Humidity: Read the two bytes as an unsigned 16-bit big-endian number and multiply it by 0.0025 percent; the outcome is rounded to 2 decimal places. For example, 5394 decodes to 53.49.
  • Pressure: Read the two bytes as an unsigned 16-bit big-endian number, add 50000, and divide the sum by 100 to obtain hPa; the outcome is rounded to 2 decimal places. For example, C37C decodes to 1000.44.
  • Acceleration: Each axis is a signed 16-bit big-endian integer, with its value given in mG. The byte strings 0004, FFFC, and 040C decode to 4, -4, and 1036, respectively.

    • The upper 11 bits encode the battery voltage in millivolts, with a 1600 mV offset applied. Put differently, the voltage in volts is given by ((power_info >> 5) + 1600) / 1000.
    • The lower 5 bits encode the transmit power, computed as (power_info & 0x1F) * 2 - 40 dBm.
    • Decoding AC36 therefore gives a battery voltage of 2.977 V and a transmit power of 4 dBm.
  • Movement counter: Read the byte as an unsigned integer; 42, for example, decodes to 66.
  • Measurement sequence number: Here the two bytes form an unsigned 16-bit big-endian integer; 00CD decodes to 205.
  • MAC address: The six bytes are written out as lowercase hexadecimal, and no delimiters are used. CBB8334C884F decodes to cbb8334c884f.

The following static method is exposed by the class:

DataFormats.convert_data(data: str) -> tuple

The data parameter is a hexadecimal representation of a BLE advertisement; by convention it is uppercase and contains no separators. The return value is a two-tuple (data_format, encoded):

  • data_format is the number of the recognized Ruuvi data format.
  • encoded is the encoded sensor payload that the decoder for that format expects.
  • When the input contains no recognizable, complete Ruuvi measurement, the result is (None, None).

Malformed input, non-hexadecimal text, and unsupported input such as a binary byte string must not be treated as measurements; they must be rejected by returning (None, None).

Framing of BLE advertisements

AD structures make up BLE advertising data. Each structure consists of:

  1. a one-byte length L, which counts all bytes after the length byte within that structure;
  2. a one-byte AD type; and
  3. L - 1 bytes of AD data.

The strings that scanners provide may include a leading byte that describes the total length of the advertising-data area, may contain one or more AD structures before the relevant structure, and may have bytes such as RSSI after that area. Conversion must also work when the caller supplies the AD structures without a larger HCI envelope, including when the manufacturer-specific structure comes first. If the advertising data is preceded by normal HCI report framing, the framed manufacturer structure must still be locatable and no HCI bytes may become part of encoded. A fixed absolute offset for the Ruuvi payload may not be assumed.

A Ruuvi manufacturer measurement is found in an AD structure with:

  • AD type 0xFF (Manufacturer Specific Data);
  • Ruuvi Innovations manufacturer ID 0x0499, represented little-endian as 99 04 immediately after the type; and
  • a supported format byte immediately after the manufacturer ID.

Recognition must be based on a correctly framed AD structure. It is not sufficient to merely find byte text such as FF990403 or FF990405 at an arbitrary location.

For a manufacturer structure whose declared length is L, the value returned as encoded starts at its format byte and contains exactly L - 3 bytes: the type byte and the two manufacturer-ID bytes are omitted. The value must never include bytes outside the declared end of that structure. Conversely, every byte that the length declares must actually be present in the structure; bytes outside the advertising-data boundary cannot be used to make an incomplete structure appear complete.

Behavior requirements

Data format 3 (0x03)

A complete Ruuvi manufacturer structure with format byte 03 must return data format 3. The encoded value begins with 03 and ends exactly at the declared boundary of that manufacturer structure.

A format-3 payload must have enough bytes for a valid format-3 measurement. The normal format-3 payload is 14 bytes; advertisements that carry additional declared padding bytes nevertheless remain valid, and all bytes genuinely within the manufacturer structure are returned. A declared structure that is cut short, or that does not contain a complete measurement, is invalid.

Examples:

  • '1502010611FF990403651652CAE900080018041C0C8BC6' must return (3, '03651652CAE900080018041C0C8B').
  • '1502010611FF990403411540C84AFC72FE2FFFC50B89C6' must return (3, '03411540C84AFC72FE2FFFC50B89').

In each case, 11 is the length of the manufacturer structure, the final C6 lies outside that structure, and C6 is therefore not part of encoded.

Data format 5 (0x05)

A complete Ruuvi manufacturer structure with format byte 05 must return data format 5, not format 3. Its encoded value begins with 05 and ends exactly at the declared boundary of the manufacturer structure. A normal format-5 measurement payload is 24 bytes, and it must be complete enough for the format-5 decoder.

  • a manufacturer structure whose declared length extends beyond the advertising-data bytes that are available;
  • a Ruuvi payload that is too short for its indicated measurement format;
  • a Ruuvi measurement format that is unknown or absent;
