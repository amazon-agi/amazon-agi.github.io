01 Implement a PubSubManager class in a new module socketio/pubsub_manager.py. 745 words · source specification

Task: Implement a PubSub-based Socket.IO Manager

Overview

Implement a PubSubManager class in a new module socketio/pubsub_manager.py. This class extends the existing socketio.base_manager.BaseManager to distribute Socket.IO events across multiple servers via a publish/subscribe message backend. This class is a base for concrete backends; it defines the message routing logic while delegating the actual transport (_publish and _listen) to subclasses.

Public API

socketio.pubsub_manager.PubSubManager

A subclass of socketio.base_manager.BaseManager.

__init__(self, channel='socketio')
  • Stores the channel argument on self.channel.
  • Generates a random host identifier stored on self.host_id, which must be a string of exactly 32 characters. Each instance gets its own value.
initialize(self, server)
  • Performs the base-class initialization for the given server (must remain compatible with BaseManager.initialize, so self.server is set as usual).
  • Starts a background task by calling self.server.start_background_task(self._thread) exactly once.

Methods to Publish (outgoing)

emit(self, event, data, namespace=None, room=None, skip_sid=None, callback=None)

Instead of emitting locally, publish a message describing the emit. Behavior:

  • namespace defaults to '/' when not provided (i.e. when None).
  • room defaults to None.
  • skip_sid defaults to None.
  • When callback is None, publish a single message (via self._publish(message)):
    {'method': 'emit', 'event': event, 'data': data,
 'namespace': namespace, 'room': room, 'skip_sid': skip_sid,
 'callback': None}
  • When callback is provided:
    • A room must be provided; if room is None, raise ValueError and do not publish.
    • Generate an acknowledgement id by calling self._generate_ack_id(room, namespace, callback) and use its return value as ack_id.
    • The published 'callback' field must be the tuple (room, namespace, ack_id). All other fields are as above.
close_room(self, room, namespace=None)

Publish a message rather than closing locally:

{'method': 'close_room', 'room': room, 'namespace': namespace}
  • namespace defaults to '/' when not provided.

Methods to Handle Incoming Messages

_handle_emit(self, message)
  • Reads 'event' and 'data' from the message (required).
  • Reads 'namespace', 'room', 'skip_sid', 'callback' from the message, each defaulting to None if absent.
  • When the message has no 'callback', invoke the base-class emit:
    BaseManager.emit(event, data, namespace=namespace, room=room,
                 skip_sid=skip_sid, callback=None)
  • When the message contains a 'callback' value, it is a 3-tuple (sid, callback_namespace, callback_id). Build a callable and pass it as the callback keyword to the base-class emit. This callable must be a functools.partial object. The base-class emit is called with positional args (event, data) and keyword args namespace, room, skip_sid, and this callback.
  • When the constructed callback is later invoked with arbitrary positional arguments, it must publish a callback message:
    {'method': 'callback', 'host_id': self.host_id, 'sid': sid,
 'namespace': callback_namespace, 'id': callback_id, 'args': <the args tuple>}
    where <the args tuple> is the tuple of positional arguments passed to the callback.
_handle_callback(self, message)
  • Reads 'host_id' from the message.
  • If host_id does not equal this instance's self.host_id, do nothing.
  • Otherwise, read 'sid', 'namespace', 'id', and 'args' from the message. Only if all four are present, call self.trigger_callback(sid, namespace, id, args). If any of these keys is missing, do nothing (do not call trigger_callback).
_handle_close_room(self, message)
  • Reads 'room' (required) and 'namespace' (defaulting to None) from the message.
  • Invokes BaseManager.close_room(room=room, namespace=namespace).

Background Thread and Transport Hooks

_thread(self)

Continuously consume messages by iterating over self._listen() (a generator). For each yielded item:

  1. If the item is bytes, attempt to deserialize it as a pickled object. If unpickling fails, skip the item.
  2. Else if the item is a string (str), attempt to parse it as JSON. If parsing fails, skip the item.
  3. Else the item is used as-is (e.g. a dict).

After obtaining a data object:

  • If it is a mapping containing a 'method' key:
    • 'emit' → call self._handle_emit(data)
    • 'callback' → call self._handle_callback(data)
    • 'close_room' → call self._handle_close_room(data)
    • any other/unknown method → ignore
  • If it has no 'method' key, ignore it.

The loop terminates naturally when the _listen() generator raises (e.g. KeyboardInterrupt); such an exception should propagate out of _thread (it need not be swallowed).

_publish(self, data) and _listen(self)

These are abstract transport hooks intended to be overridden by concrete subclasses. In this base class they may raise NotImplementedError. They are the only two methods a backend must override; all message routing is implemented here.

Notes

  • _generate_ack_id and trigger_callback are provided by the base class / infrastructure and are called as described above; you do not implement them here.
  • The message dictionaries published must contain exactly the keys described, with the exact string values shown.

05 Room Membership Cleanup in BaseManager 1053 words · rewritten by GPT-5.6-sol

Task Specification: Room Membership Cleanup in BaseManager

Overview

Update the in-memory room-management behavior of BaseManager so that leaving a room or disconnecting from a namespace produces a fully reconciled rooms structure immediately and synchronously. Removed memberships must be deleted, not retained as inactive tombstones that require a later cleanup pass.

This is a focused cleanup change. Existing connection, room, emission, callback, and integration behavior must remain compatible except for the timing and representation of room-membership removal described here.

Public API and State Model

BaseManager remains instantiable without arguments:

bm = BaseManager()

It maintains the public nested mapping:

rooms[namespace][room_name][sid] = <truthy value>
  • namespace is a namespace string such as '/' or '/foo'.
  • room_name is a room identifier or None.
  • sid is a client session identifier.
  • The None room contains all clients connected to that namespace.
  • Connecting a client also implicitly creates membership in a room whose name is that client's sid.
  • Membership values for entries that remain present are truthy; examples below use True.

The relevant methods retain their existing signatures:

  • connect(sid, namespace) registers the client in the namespace and adds it to both the None room and its sid-named room.
  • enter_room(sid, namespace, room) adds the client to a room.
  • leave_room(sid, namespace, room) removes that one membership.
  • disconnect(sid, namespace) disconnects the client from that namespace.
  • is_connected(sid, namespace) reports whether the client is connected to that namespace.
  • get_participants(namespace, room) returns an iterable of the room's current participants.
  • close_room(room, namespace) removes all participants from the room.

Required Behavior

1. Eliminate deferred reconciliation

BaseManager must no longer expose or use _clean_rooms, and callers must not need any equivalent externally triggered cleanup operation. Participant enumeration must not be required to make pending removals take effect. No pending-removal queue or inactive membership tombstones may be used as the externally observable room state.

At the return of leave_room, disconnect, or close_room, rooms must already represent the completed operation.

2. Remove memberships outright and prune empty containers

For a membership that exists, leave_room(sid, namespace, room) must immediately delete the sid key from that room. It must not assign False, None, or any other inactive marker to the key.

After a membership is removed:

  1. If the room has no remaining members, remove the room key from its namespace.
  2. If the namespace then has no remaining rooms, remove the namespace key from rooms.

Leaving a room, namespace, or membership that does not exist remains a no-op and must not raise an error.

3. Disconnect all memberships in the selected namespace

disconnect(sid, namespace) must synchronously remove the client from every room in the selected namespace, including:

  • the namespace's None room;
  • the client's sid-named room; and
  • every custom room joined by that client.

Empty rooms and namespaces must be pruned under the same rules as leave_room. Once the call returns:

  • the disconnected sid is not a key in any room of that namespace;
  • is_connected(sid, namespace) reports False while that namespace still exists; and
  • participant enumeration cannot return the disconnected sid.

Repeating a disconnect for a client already removed from a namespace must not fail or alter the remaining state. Existing acknowledgement-callback cleanup remains namespace-scoped: callback registrations for the disconnected namespace are removed, while registrations associated with other namespaces remain until those namespaces are disconnected.

4. Preserve every other namespace

A disconnect is strictly scoped to the namespace argument. Disconnecting a session from one namespace must leave all of that session's memberships in every other namespace unchanged, including its None membership, its sid-named room, and any custom-room memberships. Those memberships remain until the session separately leaves or disconnects from those namespaces.

Consequently, a client can be disconnected from '/foo' and remain connected to '/', or vice versa.

5. Preserve room-operation compatibility

Immediate deletion must not break operations that enumerate participants. close_room must still remove every participant from a valid room and remove the resulting empty room synchronously; closing a missing room remains a no-op. Emission and participant queries must operate only on memberships that are present at the time of the operation and must not expose stale, falsy entries.

Concrete Expected States

Dictionary membership values are shown as True.

Sequence A: Disconnect one client with custom rooms

Clients 123 and 456 are connected to both '/' and '/foo'. Client 123 joins room 'bar' in '/foo', client 456 joins room 'baz', and then 123 disconnects from '/foo':

rooms['/foo'] == {
    None: {'456': True},
    '456': {'456': True},
    'baz': {'456': True},
}

The 123 membership, its sid-named room, and the now-empty 'bar' room are entirely absent from '/foo'. Its memberships in '/' remain unchanged.

Sequence B: Disconnect from only one namespace

Clients 123 and 456 connect to both '/' and '/foo'. Disconnecting 123 only from '/foo' gives:

rooms['/'] == {
    None: {'123': True, '456': True},
    '123': {'123': True},
    '456': {'456': True},
}

rooms['/foo'] == {
    None: {'456': True},
    '456': {'456': True},
}

Immediately afterward:

is_connected('123', '/foo') is False
is_connected('123', '/') is True

Thus all traces of 123 are gone from '/foo', while all of its memberships in '/' are unchanged. The same isolation rule applies to custom rooms in an unaffected namespace.

Sequence C: Repeat a disconnect

With 456 still connected in '/foo', disconnecting 123 from '/foo' again after it has already been removed is a no-op and leaves:

rooms['/foo'] == {
    None: {'456': True},
    '456': {'456': True},
}
Sequence D: Remove the last clients

If the only active namespace is '/foo' and every client connected to it disconnects, all of their custom, implicit, and None memberships are removed, followed by the empty rooms and namespace:

rooms == {}
Sequence E: Participant visibility is immediate

After clients 123, 456, and 789 connect to '/' and 789 disconnects:

  • '789' is immediately absent as a key from rooms['/'][None];
  • get_participants('/', None) yields exactly 123 and 456, with ordering unspecified; and
  • no additional operation is needed to reconcile rooms.

Constraint and Non-Goals

Do not redesign unrelated manager or server behavior. The required change is the immediate, synchronous deletion and pruning of room memberships during leave, close, and disconnect operations, while preserving existing APIs, callback behavior, broadcasts, and namespace isolation.

Namespace event dispatch

A Namespace instance represents its configured namespace, such as '/foo'.

set_server(server) associates the instance with a server and makes that server available as ns.server.

trigger_event(event, *args) dispatches to a method named on_<event> on the namespace instance:

  • trigger_event('connect', sid, environ) calls on_connect(sid, environ).
  • trigger_event('disconnect', sid) calls on_disconnect(sid).
  • trigger_event('custom_message', sid, data) calls on_custom_message(sid, data).

Arguments must be passed through unchanged. If the corresponding on_<event> method does not exist, the call must have no effect and must not raise an error.

Server-operation convenience methods

Each convenience method invokes the corresponding method on the associated server. If the call does not supply namespace, use the namespace configured on the Namespace instance. An explicitly supplied namespace overrides it.

For an instance configured with '/foo', required forwarding is:

  • emit(...) calls:

    server.emit(
    event,
    data=data,
    room=room,
    skip_sid=skip_sid,
    namespace='/foo',
    callback=callback
)

  • send(...) calls:

    server.send(
    data,
    room=room,
    skip_sid=skip_sid,
    namespace='/foo',
    callback=callback
)

  • enter_room(sid, room) calls:

    server.enter_room(sid, room, namespace='/foo')

  • leave_room(sid, room) calls:

    server.leave_room(sid, room, namespace='/foo')

  • close_room(room) calls:

    server.close_room(room, namespace='/foo')

  • rooms(sid) calls:

    server.rooms(sid, namespace='/foo')

  • disconnect(sid) calls:

    server.disconnect(sid, namespace='/foo')

For each method, passing namespace='/bar' must result in '/bar' being forwarded instead of the instance’s configured namespace.

Registering namespaces with Server

Server.register_namespace(namespace_handler) accepts instances of socketio.namespace.Namespace, including subclass instances, and registers them for their configured namespace.

Passing a value that is not a Namespace instance must raise ValueError. This includes numeric values, unrelated class objects, and instances of unrelated classes.

Registered namespace dispatch

A registered namespace must participate in normal Socket.IO message handling.

Given a namespace subclass registered for '/foo':

  • After an Engine.IO connection for a SID and a namespace-connect message such as:

    0/foo

    the namespace’s on_connect(sid, environ) method is called with the SID and the environment previously supplied to Server._handle_eio_connect.

  • An event packet:

    2/foo,["foo","a"]

    calls on_foo(sid, "a").

  • An event packet with no event arguments:

    2/foo,["bar"]

    calls on_bar(sid).

  • An event packet with multiple arguments:

    2/foo,["baz","a","b"]

    calls on_baz(sid, "a", "b").

  • Calling:

Low-level emit (coroutine)
  • _emit_internal(sid, event, data, namespace=None, id=None) — coroutine. Encode an EVENT Socket.IO packet and send it via self.eio.send.
    • The packet is a text frame '2' + [namespace prefix] + [id] + JSON, where JSON is [event, ...data]:
      • data that is a tuple or list is spread into the JSON array as multiple elements after the event name (a tuple → each element becomes a top-level array element; a list → the list is nested as a single element). A scalar data becomes a single element.
      • Default namespace '/' adds no namespace prefix; other namespaces add <namespace>, after the packet type.
      • When id is provided it is inserted between the namespace prefix and the JSON array.
    • Examples (default binary=False):
      • _emit_internal('123', 'my event', 'my data', namespace='/foo') → eio.send('123', '2/foo,["my event","my data"]', binary=False).
      • with tuple ('foo','bar') → '2/foo,["my event","foo","bar"]'.
      • with list ['foo','bar'] → '2/foo,["my event",["foo","bar"]]'.
      • default namespace → '2["my event","my data"]'.
      • with id set → '2/foo,1["my event","my data"]'.
    • When the encoded packet requires binary attachments (e.g. binary=True with bytes payload), multiple eio.send calls are issued (one text frame plus one per binary attachment).
Engine event handlers (all coroutines)
  • _handle_eio_connect(sid, environ) — store environ[sid] = environ, call manager.connect(sid, '/'), and (once, on the first ever connection) call manager.initialize(). Then dispatch the connect event for namespace '/' (see dispatch rules) with args (sid, environ). On the first-ever eio connect, manager.initialize is called exactly once and not again on later connects.
    • If the connect handler returns False, reject: call manager.disconnect(sid, '/') and send an error/disconnect packet ('4'); otherwise send the connect-accepted packet ('0').
  • _handle_eio_message(sid, data) — parse incoming Socket.IO packets and act by packet type:
    • CONNECT ('0' optionally with a namespace, e.g. '0/foo'): call manager.connect(sid, namespace), dispatch the connect event for that namespace with (sid, environ). If accepted, send '0<namespace>' (e.g. '0/foo'); if the handler returns False, call manager.disconnect and send '4<namespace>' (e.g. '4/foo').
    • DISCONNECT ('1' optionally with namespace): dispatch the disconnect event for that namespace with (sid,) and update manager state for that namespace only, without touching other namespaces or clearing environ.
    • EVENT ('2' optionally with namespace, id, and a JSON array [event, ...args]): dispatch the named event with (sid, *args). If the packet carries an ack id, take the handler's return value and send an ACK packet back:
      • The ack packet is '3' + [namespace prefix] + id + JSON, where JSON encodes the return value: a tuple is spread into multiple array elements, a list is nested as a single element, a scalar becomes a single element, and None becomes []. Example: return 'foo', id 1000, default ns → '31000["foo"]'; return None → '31000[]'; return tuple (1,'2',True) → '31000[1,"2",true]'; return list [1,'2',True] → '31000[[1,"2",true]]'; with namespace /foo, id 1 → '3/foo,1[...]'.
    • ACK ('3' optionally with namespace and id, plus a JSON array of arguments): await manager.trigger_callback(sid, namespace, id, args).
    • BINARY_EVENT / BINARY_ACK ('5' / '6' with attachment count): buffer the first frame and the subsequent raw binary frames (passed as separate _handle_eio_message calls with bytes data) until all attachments arrive, then reconstruct and process as EVENT/ACK respectively. Reconstructed binary placeholders map to the received byte frames by their declared index.
    • ERROR ('4') and any unrecognized/invalid packet type must raise ValueError.
  • _handle_eio_disconnect(sid) — for every namespace the sid is in (as reported by manager.get_namespaces()), dispatch the disconnect event with (sid,) and call manager.disconnect(sid, namespace); then remove the sid from environ (so after a full disconnect environ == {}). Disconnecting an unknown client must be a harmless no-op.
Event dispatch rules (used by the handlers above)

For a given (namespace, event, *args):

  • If a class-based namespace handler is registered for namespace (via register_namespace), await/call its trigger_event(event, *args).
  • Otherwise, if a function handler is registered under handlers[namespace][event], call it with *args. The handler may be a plain function or a coroutine function; both must be supported (coroutines awaited).
  • The return value of the handler (needed for connect acceptance and ack replies) must be obtained regardless of whether the handler is sync or async.

Part 4: Changes to existing synchronous socketio code

socketio.namespace.Namespace

Add a method is_asyncio_based(self) returning False by default, so that subclasses can override it to declare themselves asyncio-based (returning True).

socketio.server.Server
  • register_namespace must additionally raise ValueError when given a namespace instance whose is_asyncio_based() returns True (i.e. reject async namespaces from the sync server), in addition to its existing rejections (non-namespace values, classes rather than instances, and the base Namespace class object).
  • In _handle_eio_connect, manager.initialize() must be invoked exactly once across the lifetime of the server — on the first connection only — and not again on subsequent connections.

Notes on coroutine support in mocks / callbacks

Throughout the async components, wherever a user-supplied callback or event handler is invoked (ack callbacks, event handlers, connect/disconnect handlers), the code must accept both ordinary functions and coroutine functions, calling the former directly and awaiting the latter, and obtaining any return value in both cases.

The synchronous packet format, packet types, and JSON encoding used by the async server are identical to the existing synchronous server's; reuse the existing socketio.packet machinery.
