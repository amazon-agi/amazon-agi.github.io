01 Create a PubSubManager class inside a new module socketio/pubsub_manager.py. 815 words · source specification, reworded by GLM-5.3-Flash

Task: Implement a Socket.IO Manager Based on PubSub

Overview

Create a PubSubManager class inside a new module socketio/pubsub_manager.py. It extends the existing socketio.base_manager.BaseManager in order to distribute Socket.IO events across multiple servers by way of a publish/subscribe message backend. Concrete backends are built on top of this class: the message routing logic is defined here, while the actual transport (_publish and _listen) is delegated to subclasses.

Public API

socketio.pubsub_manager.PubSubManager

It subclasses socketio.base_manager.BaseManager.

__init__(self, channel='socketio')
  • The channel argument is stored on self.channel.
  • A random host identifier is generated and stored on self.host_id; it must be a string of exactly 32 characters. Every instance is given its own value.
initialize(self, server)
  • Carries out the base-class initialization for the given server (this must remain compatible with BaseManager.initialize, so self.server is set in the usual way).
  • A background task is started by calling self.server.start_background_task(self._thread) exactly once.

Publishing Methods (outgoing)

emit(self, event, data, namespace=None, room=None, skip_sid=None, callback=None)

The method does not emit locally; instead, it publishes a message describing the emit. Behavior:

  • If namespace is not provided (i.e. when it is None), it defaults to '/'.
  • The default for room is None.
  • The default for skip_sid is None.
  • If callback is None, a single message is published (via self._publish(message)):
    {'method': 'emit', 'event': event, 'data': data,
 'namespace': namespace, 'room': room, 'skip_sid': skip_sid,
 'callback': None}
  • If a callback is provided:
    • A room must be supplied; if room is None, raise ValueError and do not publish.
    • An acknowledgement id is generated by calling self._generate_ack_id(room, namespace, callback), and its return value is used as ack_id.
    • The 'callback' field of the published message must be the tuple (room, namespace, ack_id). All other fields are as above.
close_room(self, room, namespace=None)

Publish a message instead of closing locally:

{'method': 'close_room', 'room': room, 'namespace': namespace}
  • If namespace is not provided, it defaults to '/'.

Methods for Handling Incoming Messages

_handle_emit(self, message)
  • Read 'event' and 'data' from the message (required).
  • Read 'namespace', 'room', 'skip_sid', 'callback' from the message, each of them defaulting to None when absent.
  • If the message has no 'callback', invoke the base-class emit:
    BaseManager.emit(event, data, namespace=namespace, room=room,
                 skip_sid=skip_sid, callback=None)
  • If the message does contain a 'callback' value, that value is a 3-tuple (sid, callback_namespace, callback_id). Construct a callable and pass it to the base-class emit as the callback keyword. This callable must be a functools.partial object. The base-class emit is called with positional args (event, data) together with the keyword args namespace, room, skip_sid, and this callback.
  • If the constructed callback is later invoked with arbitrary positional arguments, it must publish a callback message:
    {'method': 'callback', 'host_id': self.host_id, 'sid': sid,
 'namespace': callback_namespace, 'id': callback_id, 'args': <the args tuple>}
    where <the args tuple> is the tuple of positional arguments that were passed to the callback.
_handle_callback(self, message)
  • Read 'host_id' from the message.
  • If host_id is not equal to this instance's self.host_id, do nothing.
  • Otherwise, read 'sid', 'namespace', 'id', and 'args' from the message. Call self.trigger_callback(sid, namespace, id, args) only when all four are present. If any of these keys is missing, do nothing (do not call trigger_callback).
_handle_close_room(self, message)
  • Read 'room' (required) and 'namespace' (defaulting to None) from the message.
  • Then invoke BaseManager.close_room(room=room, namespace=namespace).

Background Thread and Transport Hooks

_thread(self)

Consume messages in a continuous loop by iterating over self._listen() (a generator). For each item the generator yields:

  1. Should the item be bytes, attempt to deserialize it as a pickled object; if unpickling fails, skip the item.
  2. Else, if the item is a string (str), attempt to parse it as JSON; if parsing fails, skip the item.
  3. In every remaining case, the item is used as-is (e.g. a dict).

After a data object has been obtained:

  • If it is a mapping that contains a 'method' key:
    • 'emit' → call self._handle_emit(data)
    • 'callback' → call self._handle_callback(data)
    • 'close_room' → call self._handle_close_room(data)
    • any other/unknown method → ignore
  • If there is no 'method' key, the item is ignored.

The loop comes to a natural end when the _listen() generator raises (e.g. KeyboardInterrupt); an exception of that kind should propagate out of _thread (it need not be swallowed).

_publish(self, data) and _listen(self)

These act as abstract transport hooks, meant to be overridden by concrete subclasses. Within this base class they may raise NotImplementedError. These are the only two methods that a backend must override; all message routing is implemented in this class.

Notes

  • _generate_ack_id and trigger_callback come from the base class / infrastructure and are called as described above; you do not implement them yourself here.
  • The message dictionaries that get published must contain exactly the keys described, with the exact string values shown.

05 Cleaning Up Room Memberships in BaseManager 1148 words · rewritten by GPT-5.6-sol, reworded by GLM-5.3-Flash

Task Specification: Cleaning Up Room Memberships in BaseManager

Overview

Change the in-memory room-management behavior of BaseManager so that leaving a room or disconnecting from a namespace results in a fully reconciled rooms structure immediately and synchronously. Memberships that have been removed must be deleted, not retained as inactive tombstones that require a later cleanup pass.

This is a cleanup change with a narrow scope. Connection, room, emission, callback, and integration behavior that already exists must remain compatible except for the timing and representation of room-membership removal described here.

Public API and State Model

BaseManager remains instantiable with no arguments:

bm = BaseManager()

It maintains the following public nested mapping:

rooms[namespace][room_name][sid] = <truthy value>
  • namespace is a string naming a namespace, such as '/' or '/foo'.
  • room_name is a room identifier or None.
  • sid is an identifier for a client session.
  • All clients connected to that namespace are contained in the None room.
  • When a client connects, membership in a room whose name is that client's sid is also implicitly created.
  • Entries that stay present hold truthy membership values; the examples below use True.

The relevant methods keep their existing signatures:

  • connect(sid, namespace) registers the client in the namespace and adds it to both the None room and the room named after its sid.
  • enter_room(sid, namespace, room) adds the client as a member of a room.
  • leave_room(sid, namespace, room) removes just that one membership.
  • disconnect(sid, namespace) disconnects the client from the given namespace.
  • is_connected(sid, namespace) reports whether the client is connected to the given namespace.
  • get_participants(namespace, room) returns an iterable of the participants currently in the room.
  • close_room(room, namespace) removes all of the room's participants.

Required Behavior

1. Eliminate deferred reconciliation

_clean_rooms must no longer be exposed or used by BaseManager, and callers must not need any equivalent cleanup operation triggered externally. Making pending removals take effect must not require participant enumeration. Neither a pending-removal queue nor inactive membership tombstones may be used as the externally observable room state.

By the time leave_room, disconnect, or close_room returns, rooms must already represent the completed operation.

2. Delete memberships outright and prune empty containers

For an existing membership, leave_room(sid, namespace, room) must immediately delete the sid key from that room. The key must not be assigned False, None, or any other inactive marker.

After a membership has been removed:

  1. If no members remain in the room, remove the room key from its namespace.
  2. If no rooms then remain in the namespace, remove the namespace key from rooms.

Leaving a room, namespace, or membership that does not exist is a no-op and must not raise an error.

3. Disconnect all memberships in the given namespace

disconnect(sid, namespace) must synchronously remove the client from every room in the namespace passed to the call, including:

  • the None room of that namespace;
  • the room named after the client's sid; and
  • every custom room that the client has joined.

Empty rooms and namespaces must be pruned following the same rules as leave_room. Once the call has returned:

  • the disconnected sid does not appear as a key in any room of that namespace;
  • is_connected(sid, namespace) reports False as long as that namespace still exists; and
  • the disconnected sid cannot be returned by participant enumeration.

Repeating a disconnect for a client already removed from a namespace must not fail or change the state that remains. The existing cleanup of acknowledgement callbacks remains scoped to the namespace: callback registrations for the disconnected namespace are removed, while registrations belonging to other namespaces stay in place until those namespaces are disconnected.

4. Keep every other namespace intact

The effect of a disconnect is strictly limited to the namespace argument. When a session is disconnected from one namespace, all of that session's memberships in every other namespace must be left unchanged, including its None membership, its sid-named room, and any custom-room memberships. Those memberships stay in place until the session separately leaves or disconnects from those namespaces.

As a result, a client can be disconnected from '/foo' while remaining connected to '/', or the other way around.

5. Keep room-operation compatibility

The immediate deletion must not break operations that enumerate participants. close_room must still remove every participant from a valid room and remove the resulting empty room synchronously; closing a room that does not exist remains a no-op. Emission and participant queries must operate only on the memberships present at the moment of the operation and must not expose stale, falsy entries.

Expected States in Concrete Terms

In the dictionaries, membership values are shown as True.

Sequence A: Disconnect one client that has custom rooms

Clients 123 and 456 are connected to both '/' and '/foo'. Client 123 joins room 'bar' in '/foo', and client 456 joins room 'baz'. Then 123 disconnects from '/foo':

rooms['/foo'] == {
    None: {'456': True},
    '456': {'456': True},
    'baz': {'456': True},
}

The 123 membership, the room named after its sid, and the 'bar' room, which is now empty, are entirely absent from '/foo'. Its memberships in '/' are unchanged.

Sequence B: Disconnecting from only one namespace

Clients 123 and 456 connect to both '/' and '/foo'. Disconnecting 123 only from '/foo' produces:

rooms['/'] == {
    None: {'123': True, '456': True},
    '123': {'123': True},
    '456': {'456': True},
}

rooms['/foo'] == {
    None: {'456': True},
    '456': {'456': True},
}

Immediately afterwards:

is_connected('123', '/foo') is False
is_connected('123', '/') is True

Hence all traces of 123 are gone from '/foo', while all of its memberships in '/' are unchanged. Custom rooms in an unaffected namespace are covered by the same isolation rule.

Sequence C: Repeating a disconnect

With 456 still connected in '/foo', disconnecting 123 again from '/foo' after it has already been removed is a no-op and leaves:

rooms['/foo'] == {
    None: {'456': True},
    '456': {'456': True},
}
Sequence D: Removing the last clients

If '/foo' is the only active namespace and every client connected to it disconnects, all of their custom, implicit, and None memberships are removed, followed by the empty rooms and namespace:

rooms == {}
Sequence E: Participants are visible immediately

After clients 123, 456, and 789 have connected to '/' and 789 has disconnected:

  • '789' is immediately no longer present as a key in rooms['/'][None];
  • get_participants('/', None) yields exactly 123 and 456, with the ordering left unspecified; and
  • there is no need for any additional operation to reconcile rooms.

Constraints and Non-Goals

Unrelated manager or server behavior must not be redesigned. The required change is the immediate, synchronous deletion and pruning of room memberships during leave, close, and disconnect operations, while existing APIs, callback behavior, broadcasts, and namespace isolation are preserved.

  • leave_room(sid, room, namespace=None) — the call performed is server.leave_room(sid, room, namespace=<resolved>). (Not a coroutine.)
  • close_room(room, namespace=None) — the call performed is server.close_room(room, namespace=<resolved>). (Not a coroutine.)
  • rooms(sid, namespace=None) — the call performed is server.rooms(sid, namespace=<resolved>). (Not a coroutine.)
  • disconnect(sid, namespace=None) — coroutine. Awaits server.disconnect(sid, namespace=<resolved>).

For each of the methods above: with no namespace supplied, the namespace given at construction time is used; with one supplied, that supplied value is used.

Part 3: Module socketio.asyncio_server

Define a class AsyncServer matching the synchronous server in behavior, except that its network/dispatch operations are coroutine-based. The engine underneath it is engineio.AsyncServer (referenced as socketio.server.engineio.AsyncServer).

Constructing the server

AsyncServer(client_manager=None, logger=False, binary=False, json=None, engineio_logger=..., **kwargs):

  • A client_manager that is supplied becomes self.manager; with none supplied, a default async manager is created.
  • engineio.AsyncServer is instantiated with the relevant kwargs passed through. On top of that, async_handlers=False is always among the arguments given to it. Leftover kwargs (e.g. foo='bar') are forwarded. A supplied engineio_logger goes to the engine as its logger kwarg; a supplied json goes to the engine as its json kwarg (and then serves as the JSON module for packet encoding/decoding).
  • Three handlers (connect, message, disconnect) are registered on the engine — put differently, eio.on is called 3 times.
  • The attributes are: manager, eio, binary (default False), async_handlers (default False), environ (dict), handlers (dict), logger.
  • What logger does:
    • logger=False → the resulting logger has ERROR as its effective level.
    • logger=True → the effective level becomes INFO when it was previously unset; otherwise the level it already has is left as-is.
    • logger=<object> → that very object is taken as self.logger, verbatim.
Registering events
  • on(event, handler=None, namespace=None) — makes handler the registered handler for event under namespace (default '/'). It can serve as a decorator (@s.on('connect')) or be invoked directly (s.on('disconnect', bar, namespace='/foo')). The handlers that were registered can be read back from s.handlers['<namespace>']['<event>'].
  • register_namespace(namespace_handler) — takes an AsyncNamespace instance and registers it. ValueError must be raised whenever the argument is not an AsyncNamespace instance — namely for a value that is not a namespace (e.g. an int), an arbitrary class or instance, the AsyncNamespace/base namespace class itself (not an instance), or a synchronous Namespace instance.
Emit and send (all coroutines)
  • emit(event, data=None, room=None, skip_sid=None, namespace=None, callback=None) — what is awaited is manager.emit(event, data, namespace_or_default_'/', room, skip_sid, callback); the manager receives positional args, in that order.
  • send(data, room=None, skip_sid=None, namespace=None, callback=None) — same behavior as emit but with 'message' as the event name; what is awaited is manager.emit('message', data, namespace_or_'/', room, skip_sid, callback).
Room and connection operations (delegated to the manager; not coroutines)
  • enter_room(sid, room, namespace=None) → forwards to manager.enter_room(sid, namespace_or_'/', room).
  • leave_room(sid, room, namespace=None) → forwards to manager.leave_room(sid, namespace_or_'/', room).
  • close_room(room, namespace=None) → forwards to manager.close_room(room, namespace_or_'/').
  • rooms(sid, namespace=None) → forwards to manager.get_rooms(sid, namespace_or_'/').
  • transport(sid) → return self.eio.transport(sid).
Methods passed straight through to the engine
  • attach(app, socketio_path) — a direct call of self.eio.attach(app, socketio_path).
  • handle_request(environ) — coroutine. Awaits self.eio.handle_request(environ).
  • start_background_task(target, *args, **kwargs) — coroutine. Awaits self.eio.start_background_task(target, *args, **kwargs).
  • sleep(seconds) — coroutine. Awaits self.eio.sleep(seconds).
  • disconnect(sid, namespace=None) — coroutine. Takes a client off a namespace (default '/'): the fitting Socket.IO disconnect packet is sent and manager state is brought up to date (the packet format is given below). For a sid/namespace disconnected already, another packet must not be sent (subsequent calls trigger no additional eio.send calls).
Emit at packet level (a coroutine)
  • _emit_internal(sid, event, data, namespace=None, id=None) — coroutine. An EVENT Socket.IO packet is encoded and sent by way of self.eio.send.
    • The packet's shape is the text frame '2' + [namespace prefix] + [id] + JSON, JSON standing for [event, ...data]:
      • data in the form of a tuple or list is spread over the JSON array as multiple elements following the event name (a tuple → each element lands as a top-level array element; a list → the list is nested as a single element). A scalar data ends up as a single element.
      • The default namespace '/' contributes no namespace prefix; any namespace other than that appends <namespace>, after the packet type.
      • A provided id is placed between the namespace prefix and the JSON array.
    • Examples (with the default binary=False):
      • _emit_internal('123', 'my event', 'my data', namespace='/foo') → eio.send('123', '2/foo,["my event","my data"]', binary=False).
      • with tuple ('foo','bar') → '2/foo,["my event","foo","bar"]'.
      • with list ['foo','bar'] → '2/foo,["my event",["foo","bar"]]'.
      • default namespace → '2["my event","my data"]'.
      • with id set → '2/foo,1["my event","my data"]'.
    • Whenever the encoded packet calls for binary attachments (e.g. binary=True with bytes payload), eio.send fires multiple times (one text frame plus one call for each binary attachment).
Handlers wired to engine events (all coroutines)
  • _handle_eio_connect(sid, environ) — environ[sid] = environ is stored, manager.connect(sid, '/') is called, and manager.initialize() is called once — on the first ever connection. Next, the connect event is dispatched for namespace '/' with args (sid, environ) (see the dispatch rules). On a first-ever eio connect, manager.initialize is called exactly once; later connects do not call it again.
    • A connect handler returning False means rejection: manager.disconnect(sid, '/') is called and an error/disconnect packet ('4') is sent; otherwise the connect-accepted packet ('0') is what goes out.
  • _handle_eio_message(sid, data) — the Socket.IO packets that come in are parsed, and what happens next follows the packet type:
    • CONNECT ('0', possibly followed by a namespace, e.g. '0/foo'): manager.connect(sid, namespace) is called, then the connect event is dispatched for that namespace with (sid, environ). Acceptance means '0<namespace>' is sent (e.g. '0/foo'); a handler returning False means manager.disconnect is called and '4<namespace>' is sent (e.g. '4/foo').
    • DISCONNECT ('1', possibly with a namespace): the disconnect event is dispatched for that namespace with (sid,), and manager state is updated for that namespace alone — other namespaces are not touched, and environ is not cleared.
    • EVENT ('2', possibly with namespace, id, and a JSON array [event, ...args]): the event named in the packet is dispatched with (sid, *args). An ack id carried by the packet means the handler's return value is taken and an ACK packet is sent back:
      • The ACK packet reads '3' + [namespace prefix] + id + JSON, and the JSON encodes the return value as follows: a tuple is spread into multiple array elements, a list is nested as a single element, a scalar takes a single element, and None becomes []. Examples: return 'foo' with id 1000 in the default ns → '31000["foo"]'; return None → '31000[]'; return tuple (1,'2',True) → '31000[1,"2",true]'; return list [1,'2',True] → '31000[[1,"2",true]]'; namespace /foo with id 1 → '3/foo,1[...]'.
    • ACK ('3', possibly with namespace and id, plus a JSON array of arguments): await manager.trigger_callback(sid, namespace, id, args).
    • BINARY_EVENT / BINARY_ACK ('5' / '6', carrying an attachment count): the first frame together with the raw binary frames after it (delivered as separate _handle_eio_message calls with bytes data) is buffered until all attachments are in; at that point the packet is reconstructed and handled as an EVENT/ACK respectively. For the reconstructed binary placeholders, the declared index is what decides which received byte frame each one maps to.
    • ERROR ('4'), along with any packet type that is unrecognized/invalid, must raise ValueError.
  • _handle_eio_disconnect(sid) — for every namespace the sid belongs to (per what manager.get_namespaces() reports), the disconnect event is dispatched with (sid,) and manager.disconnect(sid, namespace) is called; afterwards the sid is removed from environ (so that environ == {} holds after a full disconnect). A disconnect of an unknown client must be a harmless no-op.
Dispatch rules for events (what the handlers above rely on)

For a particular (namespace, event, *args):

  • When a class-based namespace handler is registered for namespace (via register_namespace), its trigger_event(event, *args) is what gets awaited/called.
  • When there is no such handler, a function handler registered under handlers[namespace][event] is called with *args. That handler may be a plain function or a coroutine function; both must be supported (coroutines awaited).
  • The handler's return value (connect acceptance and ack replies depend on it) must be obtained no matter whether the handler is sync or async.

Part 4: Adjustments to the existing synchronous socketio code

socketio.namespace.Namespace

Introduce a method is_asyncio_based(self) whose return value is False by default; subclasses can override it to declare themselves asyncio-based (returning True).

socketio.server.Server
  • register_namespace must, in addition, raise ValueError when handed a namespace instance whose is_asyncio_based() returns True — that is, async namespaces are rejected by the sync server — on top of the rejections it already performs (non-namespace values, classes rather than instances, and the base Namespace class object).
  • Within _handle_eio_connect, manager.initialize() must be invoked exactly once over the whole lifetime of the server — the first connection only — and no invocation happens again on subsequent connections.

A note on coroutine support in mocks / callbacks

Everywhere in the async components where a user-supplied callback or event handler ends up invoked (ack callbacks, event handlers, connect/disconnect handlers), the code must accept both ordinary functions and coroutine functions — the plain kind is called directly, the coroutine kind is awaited — and any return value must be captured in both cases.

The synchronous packet format, packet types, and JSON encoding that the async server uses are identical to the existing synchronous server's; the existing socketio.packet machinery is what gets reused.
