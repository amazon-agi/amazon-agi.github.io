from fusiondls import run_dls

run_dls(constants, radios, d, s_parallel, control_variable="density")

CfInt is the analytic control-parameter calculation and supports the public call form below:

CfInt(S, Btot, Sx, maximum_parallel_coordinate, front_position)

This matches the callable signature CfInt(spar, B_field, sx, L, sh=0, kappa1=2500).

  • Btot/B_field is the total magnetic-field sequence that corresponds to it.
  • Sx/sx is the parallel coordinate of the X-point.
  • maximum_parallel_coordinate/L is the connection-length endpoint and is normally numpy.max(S).
  • front_position/sh is the parallel front position that has been requested.
  • kappa1 stays optional, with a default of 2500.
  • The value returned is a numeric scalar compatible with NumPy. For a sequence of front positions, the values returned must be usable as numerical array data and support normalization by the first value.

Required form of the call

run_dls(constants, radios, d, s_parallel, control_variable="density")

  • "upstreamGrid"

Using the following supported setup:

    "ionisation": False,
    "upstreamGrid": True,
}

constants = {
    "gamma_sheath": 7,
    "Tt": 1,
    "qpllu0": 4e8,
    "nu": 1e20,
    "nu0": 1e20,
    "cz0": 0.02,
    "Lfunc": LfuncN,

s_parallel = numpy.linspace(0, d["S"][d["Xpoint"] - 1], 30)

numerical_i = result["cvar"][i] / result["cvar"][0]

    d["S"],
    d["Btot"],
    d["Sx"],

    d["S"],
    d["Btot"],
    d["Sx"],
    numpy.max(d["S"]),

Task: Add a MagneticGeometry dataclass

Overview

Add a new MagneticGeometry dataclass to the fusiondls package. It represents the magnetic geometry of a divertor leg. It must be possible to import it directly from the top-level package:

from fusiondls import MagneticGeometry

The existing run_dls function must accept a MagneticGeometry instance in place of the plain dictionary of geometry data it previously accepted (see "Compatibility with run_dls" below).

Data source format

Pickle files store the geometry data. When a pickle file is loaded, it yields a nested dictionary with this structure:

data[design][leg] -> dict of geometry arrays/values

where:

  • design is a top-level key (for example "V10").
  • leg is one of the four divertor legs: "iu", "ou", "il", "ol".
  • At least the following entries are contained in the innermost dict:
    • "S": a 1D array of parallel distances along the leg.
    • "Btot": a 1D array of total magnetic field magnitude along the leg (the same length as "S").
    • "Xpoint": an integer index into the arrays that marks the X-point.
    • "Sx": the parallel distance at the X-point as a scalar.

Required public API

MagneticGeometry (dataclass in fusiondls)

A dataclass whose fields hold the geometry quantities loaded from the innermost dict. It must expose at least the following attributes (they match the source dict keys, with the same values/types):

  • S
  • Btot
  • Xpoint
  • Sx
  • Bx — the total magnetic field magnitude at the X-point, that is, the value of Btot at index Xpoint.
MagneticGeometry.from_pickle(filename, design, leg) -> MagneticGeometry

Class method. It loads the pickle file at filename (a path-like object), selects data[design][leg], and returns a single MagneticGeometry instance populated from that innermost dict.

MagneticGeometry.read_design(filename, design) -> dict[str, MagneticGeometry]

Class method. It loads the pickle file at filename, selects data[design], and returns a dict that maps each leg key ("iu", "ou", "il", "ol") to a corresponding MagneticGeometry instance built from that leg's innermost dict. The keys of the returned dict are exactly those four leg names.

MagneticGeometry.scale_flux_expansion(self, scale_factor=None, expansion=None) -> MagneticGeometry

An instance method that returns a new MagneticGeometry in which Bx is modified so that the flux expansion at the X-point is scaled. Flux expansion is defined in this context as:

expansion = Bx / Btot[0]

There are two mutually exclusive modes:

  • When called with scale_factor (for example scale_factor=2): the flux expansion of the new geometry equals the flux expansion of the original geometry multiplied by scale_factor. In concrete terms, multiplying the original Bx by scale_factor gives the new Bx, so that new_Bx / new_Btot[0] == scale_factor * (old_Bx / old_Btot[0]).

  • When called with expansion (a target flux-expansion value): the flux expansion of the new geometry equals exactly the supplied expansion value, i.e. new_Bx / new_Btot[0] == expansion. In this mode Btot[0] is unchanged, so new_Bx = expansion * Btot[0].

The original instance must not be mutated; a new MagneticGeometry is returned instead. Between the original and the returned geometry, the Btot[0] reference value used for the flux-expansion calculation is unchanged.

Compatibility with run_dls

run_dls(constants, geometry, s_parallel, control_variable=...) must accept a MagneticGeometry instance as its geometry argument (previously a plain dict), and produce the same results it would have produced from the equivalent dict data. Access to whatever geometry quantities run_dls consumes must therefore be provided by MagneticGeometry, consistent with the source dict contents (in particular S, Btot, Xpoint, Sx).

The result run_dls returns supports result["cvar"] (an indexable/array-like sequence of control-variable values).

Aim

The MagneticGeometry class that fusiondls already exports must be extended with live, read-only convenience properties for the X-point, together with a refine operation that is non-mutating. Behavior that is unrelated must not be changed.

Geometry contract already in place

A MagneticGeometry stands for a magnetic field line; at least the following are exposed on it:

  • S: a coordinate along the magnetic field line (the parallel distance); it is one-dimensional and monotonically increasing, and it has enough entries for point-to-point spacing to be defined.
  • Spol: a one-dimensional profile that runs parallel to S.
  • Btot: a one-dimensional profile of the total magnetic field, parallel to S.
  • zl: a one-dimensional profile, likewise parallel to S.
  • Xpoint: an integer index giving the X-point's position within those arrays.

Consistent indexing is shared by all of the parallel profile arrays: any given index refers to the same physical point in each of them. This consistency rule applies just as much to the other field-line profiles the class already carries — its magnetic-field and spatial-coordinate profiles, for instance.

1. Convenience properties for the X-point

The read-only properties below must be exposed on MagneticGeometry:

Property Value required
Sx S[Xpoint]
Spolx Spol[Xpoint]
Bx Btot[Xpoint]
zx zl[Xpoint]

Whenever one of them is accessed, exactly the value currently stored at Xpoint in the corresponding array must be returned; an independent or stale value must not be maintained. Therefore, if an existing supported operation changes the relevant array or Xpoint, the properties must keep reflecting the geometry. They function as convenience views rather than as independently assignable state.

2. Method refine

The public method shown below must be added to MagneticGeometry:

def refine(self, location, width=...):
    ...
Parameters
  • location: a scalar, given in the same coordinate and units as S. It pinpoints where the refined grid must have its finest spacing.
  • width: an optional numeric parameter that governs the extent or scale of the refinement region. The method must accept it as a keyword argument, for instance geometry.refine(location, width=2).
Value returned and mutation behavior

A new MagneticGeometry is what refine must return. Mutation of the receiver, or of any of the receiver's profile values, must not occur as a side effect.

The object that comes back is the same physical field line, resampled onto a new S grid. It must remain a MagneticGeometry that is fully usable and internally consistent, with the X-point properties above included.

Invariants on grid size and range

Starting from refined = geometry.refine(location, width=...), all of the following must hold for the refined grid:

  • The number of grid points is preserved exactly: len(refined.S) == len(geometry.S).
  • The overall coordinate range must be the same as the original grid's; specifically, the first and final coordinates match the original endpoints, and refined.S[-1] == geometry.S[-1].
  • refined.S must still be one-dimensional and monotonically increasing.
Distribution of the refinement

Around location, grid points must be packed more densely — consecutive-point spacing there is smaller — while away from the refinement region they must be packed more sparsely. Taking a numerical gradient of refined.S as the spacing measure, the minimum spacing must occur at the grid position closest to the requested location.

Consider this concrete midpoint case:

location = geometry.S[-1] / 2
refined = geometry.refine(location, width=2)
spacing = numerical_gradient(refined.S)
i_min = index_of_minimum(spacing)

the outcome must satisfy:

  • abs(i_min - (len(geometry.S) // 2)) <= 2; and
  • abs(refined.S[i_min] - location) <= 1.

The midpoint index is intentionally derived from the receiver's grid length; since refinement preserves the point count, this index is also the midpoint of the refined array.

Consistency of the resampling

Every one-dimensional profile parallel to S must be resampled consistently onto the new grid and must remain aligned with refined.S afterward; Spol, Btot, and zl fall under this, as does any other per-grid-point profile carried by the class. The length that such arrays must have is the refined grid's preserved length.

Within the resampled arrays, it must be refined.Xpoint that identifies the X-point, so that refined.Sx, refined.Spolx, refined.Bx, and refined.zx all refer to one consistent resampled physical location. Non-profile geometry data that already exists, along with public behavior, must remain valid. As long as all observable requirements above are met, no particular grid-generation or interpolation algorithm is required.

Scope and compatibility

The change is an additive one. Construction and loading routes that already exist, geometry transformations, and downstream uses of MagneticGeometry must all continue to work. Outside of the new properties and the refine behavior, unrelated APIs and behavior must not be changed.

SimulationInputs is a dataclass that holds the physical and control parameters for a simulation. It must support construction both positionally and by keyword.

  2. nu — upstream density.

  4. qpllu0 — upstream parallel heat flux.

  6. cz0 — impurity concentration.

  • cooling_curve — selection of cooling function, with a default.

cooling_curve accepts either a callable or a string.
