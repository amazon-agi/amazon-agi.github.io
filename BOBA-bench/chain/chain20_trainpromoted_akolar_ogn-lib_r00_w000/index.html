They may derive directly from Exception or from a shared exception base. No additional behavior is required.

Module: ogn_lib.client

Class: ogn_lib.client.OgnClient

Class-level constants

OgnClient must define:

  • APRS_SERVER — the default APRS server hostname, as a string.
  • APRS_PORT_FULL — the integer port for a full, unfiltered feed.
  • APRS_PORT_FILTER — the integer port for a filtered feed.

APRS_PORT_FULL and APRS_PORT_FILTER must have different values.

Constructor
OgnClient(username, passcode='-1', server=None, port=None, filter_=None)

The constructor must support positional and keyword arguments as shown and retain the supplied connection and authentication values.

  • username is required. It is stored on the instance and used in the authentication message.
  • passcode defaults to the string '-1'. It is stored on the instance and used in the authentication message.
  • server selects the hostname:
    • When a non-None value is supplied, instance.server must equal that value.
    • Otherwise, instance.server must equal APRS_SERVER.
  • port selects the connection port, with an explicitly supplied value taking precedence over filter-based defaults:
    • When port is not None, instance.port must equal the supplied value exactly, whether or not filter_ is set. For example, port=-1 must produce instance.port == -1.
    • When port is None and no filter is set, instance.port must equal APRS_PORT_FULL.
    • When port is None and a filter is set, instance.port must equal APRS_PORT_FILTER.
  • filter_ is an optional APRS filter string. It is retained on the instance, influences default-port selection, and, when set, is included in the authentication message.
connect(self)

connect() establishes a TCP connection and performs the APRS login exchange.

Connection setup
  • Open the connection through the standard socket.create_connection entry point, using the instance's selected server and port.
  • Store the returned socket as self._socket.
  • Obtain a line-readable socket stream using the socket's makefile() method and store it as self._sock_file.
Banner and login-response handling

The APRS exchange contains an initial server greeting before the actual login response:

  1. Read the initial server banner/comment from _sock_file. A normal example is # aprsc 2.1.4-g408ed49; it begins with # but is not a # logresp message.
  2. Pass the banner to _validate_login. Direct validation of such a non-login line raises exceptions.LoginError, as specified below. During connect(), that particular LoginError is expected: it must be suppressed for the initial non-login banner, and the connection flow must continue rather than treating the banner as an authentication failure. The banner does not complete authentication.
  3. Generate and send the APRS authentication message, then continue reading the response stream to obtain the subsequent login-response line.
  4. Validate the login response with _validate_login and use its result as the authentication state. A verified login response must leave self._authenticated truthy; an unverified response leaves it falsy.

The special suppression applies only to the LoginError caused by the ordinary initial non-login banner. It does not change the standalone behavior of _validate_login, and it does not suppress errors from the actual login response.

Resource and error behavior
  • After a successful connection/login exchange, _sock_file and the underlying socket must remain open; in particular, _sock_file.close() must not be called.
  • If login validation otherwise raises exceptions.ParseError or exceptions.LoginError, the exception must propagate from connect(). Before it propagates, call _sock_file.close() exactly once and _socket.close() exactly once.
  • A ParseError while validating the initial response is not the expected banner case and must likewise propagate after both resources are closed.
  • Suppressing the initial banner-related LoginError must not close either resource; processing must continue to the login response.
send(self, message)

Send a textual message through self._socket:

  • Strip leading and trailing whitespace/newlines from message.
  • Append exactly one trailing newline (\n).
  • Encode the resulting string to bytes.
  • Pass those bytes to self._socket.sendall() in one call.

Examples:

send('test message')
# sends b'test message\n'

send('\n\ntest\nmessage\n\n\n')
# sends b'test\nmessage\n'

Only outer whitespace is removed; interior newlines are preserved.

_gen_auth_message(self)

Return the APRS authentication message as one space-delimited string.

Without a filter, splitting the result on single spaces must yield exactly these leading fields and software-identification fields:

  1. 'user'
  2. the configured username
  3. 'pass'
  4. the configured passcode
  5. exactly three additional tokens containing the software identification/version information

Thus, with the default passcode and no filter, indexes 0 through 3 are respectively 'user', the username, 'pass', and '-1', followed by exactly three more tokens.

When filter_ is set, append filter <filter_value> to the base authentication message. The complete result must end with the literal text filter followed by the configured filter value. This filter suffix is additional to the three software-identification/version tokens.

_validate_login(self, response)

Validate one textual server-response line.

A structurally valid login response has this form:

# logresp <user> <status>, server <servername>

Its behavior depends on <status>:

  • verified — return a truthy value. In particular, a verified response for a client using a real passcode (anything other than the default '-1') is successful. A verified response used by connect() must set the client's authentication state to truthy.
  • unverified — return a falsy value in both cases:
    • the client uses the default '-1' passcode and did not attempt authenticated access; or
    • the client uses a real passcode but authentication failed.
  • Any other status, such as blocked, is a login protocol failure and must raise exceptions.LoginError.

Response classification also has these requirements:

  • A comment/banner that is not a login response, such as # aprsc 2.1.4-g408ed49, must raise exceptions.LoginError when _validate_login is called directly. connect() handles only the initial occurrence of this banner-related error specially, as described above.
  • A line that starts as a login response but cannot be parsed into the expected user/status and server structure, such as # logresp 2.1.4-g408ed49, must raise exceptions.ParseError.

Compatibility Notes

  • Socket creation must go through the standard library's socket.create_connection symbol.
  • No local APRS passcode verification is required. The passcode is sent to the server; locally, the distinguished default '-1' means no authenticated access was requested, while any other value means authentication was attempted.

  • ogn_lib.exceptions — the custom exception classes.

OgnClient must be defined in ogn_lib.client and must also be importable directly from the package root:

from ogn_lib import OgnClient

Define these exception classes in ogn_lib.exceptions:

  • LoginError — raised for login-related failures.

OgnClient

Define OgnClient in ogn_lib.client.

  • APRS_PORT_FULL — the integer port used when no filter is provided.
  • APRS_PORT_FILTER — the integer port used when a filter is provided.

APRS_PORT_FULL and APRS_PORT_FILTER must have distinct values.

Constructor
OgnClient(username, passcode=None, server=None, port=None, filter_=None)

Parameters and resolution rules:

  • username is the required positional login username.
  • passcode is the login passcode. It defaults to -1, represented by the string '-1' in generated messages. A real passcode string such as '123456' is used when evaluating authentication results.
  • server is an optional server hostname. If omitted, use APRS_SERVER; if supplied, use and expose that exact value as server.
  • port is resolved as follows:
    • An explicitly supplied value is used exactly, whether or not a filter is set.
    • If omitted and filter_ is omitted, use APRS_PORT_FULL.
    • If omitted and filter_ is supplied, use APRS_PORT_FILTER.
  • filter_ is an optional APRS filter string.

The instance attributes server and port must expose the resolved values.

The client must also maintain these attributes:

  • _kill — the receive-loop termination flag, initially falsy.
  • _authenticated — whether authentication succeeded, initially falsy.
  • _socket — the underlying socket, populated while connecting.
  • _sock_file — the file-like view returned by the socket, populated while connecting.
  • _last_send — the timestamp of the most recent send, used for keepalive decisions.
connect(self)

Establish and authenticate a connection:

  1. Open a socket by calling socket.create_connection((server, port)) with the resolved endpoint and retain it as _socket.
  2. Call the socket's makefile() method and retain the result as _sock_file.
  3. Reset _kill to a falsy value so that a newly established connection can receive data.
  4. Read the initial server banner from _sock_file.readline(). A typical banner is '# aprsc 2.1.4-g408ed49'.
  5. Generate the authentication message with _gen_auth_message() and send it over the connection.
  6. Read the subsequent login-response line, such as '# logresp user verified, server GLIDERN3', and validate that response with _validate_login(...). Store the resulting authentication state in _authenticated; a successfully verified response leaves it truthy.

On a successful connection, _sock_file must remain open.

If login validation raises an authentication or parsing exception, that exception must propagate from connect(). Before propagating it, close both _sock_file and _socket.

disconnect(self)

Terminate the connection by:

  • Setting _kill to a truthy value.
  • Closing _socket.
  • Closing _sock_file.

The truthy kill flag must cause active or subsequent receive processing to stop.

receive(self, callback, parser=None)

Run receive processing by delegating per-line work to _receive_loop(callback, parser).

Every entry into _receive_loop, including the first entry and every entry after reconnection, is conditional on _kill being falsy. If _kill is already truthy, receive() must return without invoking _receive_loop.

If _receive_loop raises BrokenPipeError, receive() must call connect() to attempt reconnection. Once that reconnect call returns, it must check _kill again before attempting another receive-loop entry:

  • If _kill is falsy, resume receiving by invoking _receive_loop(callback, parser) again.
  • If _kill is truthy, return immediately without invoking the receive loop again.

This reconnect-and-retry behavior may repeat for successive broken pipes. In particular, even if every attempted receive-loop run raises BrokenPipeError, receive() must terminate once a reconnect attempt leaves the client in the disconnected/killed state. If the receive loop returns normally, receive() also returns normally.

_receive_loop(self, callback, parser)

Process records from _sock_file until killed:

  • Check _kill before or at the start of every iteration. If it is truthy, return immediately without reading or processing another line.
  • Otherwise, read one line using _sock_file.readline().
  • Invoke _keepalive() on each iteration.
  • If parser is None, pass the raw line unchanged to callback as callback(raw_line).
  • If a parser callable is supplied, enter the parsing path. Parsing is intentionally not implemented, so this path must raise NotImplementedError rather than invoking the callback with parsed data.

The callback is user supplied and receives one record at a time. It may call disconnect(); doing so sets _kill and prevents another loop iteration.

send(self, message)

Send a message through the connected socket:

  • Remove surrounding newline characters/whitespace so that blank lines around the message are removed while interior newlines are preserved.
  • Append exactly one trailing newline (\n).
  • Encode the resulting string to bytes and pass it to _socket.sendall(...).
  • After sending, update _last_send to the current value of time.time().

Examples:

  • '\n\ntest\nmessage\n\n\n' is sent as b'test\nmessage\n'.
_keepalive(self)

Use _last_send to determine whether the connection needs a keepalive:

  • If the most recent send was sufficiently recent, do nothing and do not call send().
  • If sufficient time has elapsed, including when _last_send is far in the past such as 0, call send(...) with a keepalive message.
_gen_auth_message(self)

Return the APRS authentication message as a space-separated string. Without a filter, its tokens must be, in order:

  1. The literal user.
  2. The configured username.
  3. The literal pass.
  4. The configured passcode as a string, using -1 by default.
  5. Exactly three additional space-separated client-identification/version tokens.

Thus the unfiltered base message contains the required first four tokens followed by exactly three more tokens.

If a filter was supplied, append filter <filter_value> after the base message. For example, the filter 'special_filter' makes the message end with filter special_filter.

Validate a server login response. Representative inputs include:

  • '# logresp user unverified, server GLIDERN3'
  • '# logresp user blocked, server GLIDERN3'
  • '# aprsc 2.1.4-g408ed49'

Required behavior:

  • A well-formed login response with status verified is successful: return a truthy value and mark the client authenticated. In particular, this is the successful authentication result when a real passcode rather than the default -1 was configured.
  • A well-formed login response with status unverified returns a falsy value and does not authenticate the client. This applies both to guest/default-passcode connections and to connections for which a real passcode was supplied but not verified by the server.
