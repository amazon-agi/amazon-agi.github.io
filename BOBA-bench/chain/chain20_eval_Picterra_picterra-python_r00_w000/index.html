01 You are working on the picterra Python package, which provides a client for interacting with the Picterra REST API. 586 words · source specification

Overview

You are working on the picterra Python package, which provides a client for interacting with the Picterra REST API. This task requires you to add a new method to the API client and remove an existing method and its associated command-line interface.

Public API Surface

The client class is exposed as APIClient and is importable directly from the package:

from picterra import APIClient

The client is configured via environment variables. In particular, the base API URL is read from the environment variable PICTERRA_BASE_URL, and requests are authenticated by sending an X-Api-Key HTTP header. All API endpoints are formed by joining paths onto the base URL.

Required Change 1: Add run_advanced_tool

Add a new public method to APIClient:

def run_advanced_tool(self, tool_id, inputs, outputs):
    ...
Behavior

Calling run_advanced_tool must:

  1. Issue an HTTP POST request to the API endpoint at the relative path:

    advanced_tools/{tool_id}/run/

    where {tool_id} is the first argument. The request must include the standard X-Api-Key authentication header.

  2. The JSON body of the POST request must be exactly:

    {
  "inputs": <inputs>,
  "outputs": <outputs>
}

    where <inputs> is the inputs argument and <outputs> is the outputs argument, passed through verbatim. These arguments are arbitrary JSON-serializable structures (dicts containing nested dicts, lists, strings, integers, and null/None values) and must be forwarded without modification.

    The endpoint responds (HTTP 201) with a JSON object of the form:

    {
  "operation_id": <int>,
  "poll_interval": <float>
}

  3. After starting the operation, the method must poll the operation to completion. Polling is performed by issuing GET requests to:

    operations/{operation_id}/

    using the operation_id from the run response. Each poll response is a JSON object that includes at least a status field and a type field. Polling repeats (respecting the returned poll_interval as the interval between checks) until the operation reaches a successful terminal state (status equal to "success").

  4. On successful completion, the method must return the final operation object (the parsed JSON body of the final polling response). This returned object is a dictionary that includes the operation's type field, and callers rely on being able to read that field from the return value.

Notes on the operation object

The final operation response used to determine success contains a status of "success" and additional metadata fields. The full JSON body of that operation response is what must be returned to the caller.

Required Change 2: Remove upload_remote_raster

Remove the upload_remote_raster method from APIClient entirely. This method (which previously uploaded a raster from a remote source such as an xyz or wms tile service) is no longer part of the client and should not exist.

Required Change 3: Remove the command-line interface

The package previously shipped a command-line interface built on top of the client. Remove it entirely. Specifically:

  • Remove the picterra.__main__ module (including its parse_args entry point).
  • Remove the picterra.command_parsers package/module and its submodules (e.g. detect, create).
  • Remove the picterra.helpers module if it exists solely to re-export the client for the CLI.

The client itself (from picterra import APIClient) must continue to import and function correctly after these removals. No CLI-related modules should remain importable.

Constraints

  • The APIClient public API surface used elsewhere (raster upload from local file, listing rasters/detectors, creating/editing/deleting detectors and rasters, training detectors, running detectors, managing annotations and detection areas, downloading results and rasters, etc.) must remain unchanged in behavior.
