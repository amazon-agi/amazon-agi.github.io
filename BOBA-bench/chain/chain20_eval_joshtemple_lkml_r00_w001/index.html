Task Specification: Implement Serializer in the lkml Package

Overview

You must implement a Serializer class in the lkml package that converts Python dictionaries into LookML-formatted string output. The class must be importable as lkml.Serializer.

Public API

  • Module/package: lkml (importable via import lkml)
  • Class: Serializer
    • Must be instantiable with no arguments: lkml.Serializer()
    • Method: serialize_dict(self, data)
      • data: a Python dict.
      • Returns an iterable/generator of string fragments. When the fragments are concatenated (joined with the empty string), they produce the complete LookML output described below.

Serialization Behavior

The dictionary is serialized into a LookML block. The dict is expected to contain a "name" key plus one or more additional key/value pairs. Output is produced according to these rules.

Block structure
  • The value of the "name" key becomes the block's key/label, and it is not emitted as a normal field line. Instead it opens the block.
  • The first output fragment is the block opener: the "name" value, followed by ": {", followed by a newline. For example, if data["name"] == "dimension", the opening fragment is:
    dimension: {\n
  • Each remaining key/value pair (every key other than "name") is emitted, in the order the keys appear in the dict, as an indented line.
  • The final output fragment is the closing brace } (a single } character with no trailing newline).
Field lines

Each non-name key/value pair is rendered as its own fragment with:

  • Two leading spaces of indentation.
  • The key name, followed by ": ".
  • The value, rendered per the quoting rules below.
  • A trailing newline \n.
Value quoting rules

Whether a value is wrapped in double quotes depends on the key:

  • Unquoted values — the value is emitted verbatim (no surrounding quotes). This applies to keys including:

    • from_field
    • to_field

  • Quoted values — the value is wrapped in double quotes ("..."). This applies to keys including:

    • label
    • group_label
    • description

Worked Examples

Example 1 — unquoted literals

Input:

{"name": "bind_filters", "from_field": "field_name", "to_field": "field_name"}

Concatenated output:

bind_filters: {
  from_field: field_name
  to_field: field_name
}

As ordered fragments:

"bind_filters: {\n"
"  from_field: field_name\n"
"  to_field: field_name\n"
"}"
Example 2 — quoted literals

Input:

{
    "name": "dimension",
    "label": "Dimension Name",
    "group_label": "Group Name",
    "description": "A dimension description.",
}

Concatenated output:

dimension: {
  label: "Dimension Name"
  group_label: "Group Name"
  description: "A dimension description."
}

As ordered fragments:

"dimension: {\n"
'  label: "Dimension Name"\n'
'  group_label: "Group Name"\n'
'  description: "A dimension description."\n'
"}"

Notes

  • Insertion order of the dict keys must be preserved in the output field lines.
  • The serialize_dict return value must be iterable such that joining its fragments yields the exact strings shown above.

Task Specification: Dictionary Serializer

Objective

Implement a serialize_dict method on a serializer object that converts a Python dictionary into a formatted string representation, yielded as a sequence of string fragments.

API Surface

The serializer is instantiated via a class provided by your serializer module. The relevant method is:

def serialize_dict(self, data: dict) -> Iterator[str]
  • Input: a dictionary whose keys are strings and whose values are strings.
  • Output: a generator (or any iterator) yielding string fragments. Concatenating all yielded fragments (e.g. via "".join(...)) produces the complete serialized output.

Serialization Behavior

Overall structure

The output consists of an optional name prefix, followed by a brace-enclosed body containing one line per key/value entry.

The optional name key

The key "name" is treated specially and is optional:

  • When "name" is present in the dictionary, its value becomes a prefix to the opening brace. The output begins with the value of "name", followed by a space, then {, then a newline. The name entry itself is NOT emitted as one of the body lines.

    Example prefix form:

    dimension_name {

  • When "name" is absent, the output begins directly with { followed by a newline (no prefix, no leading space):

    {
The body

Every key/value pair other than "name" is emitted as a line inside the braces. Each such line:

  • Begins with two spaces of indentation.
  • Contains the key, followed by : (colon and single space), followed by the serialized value.
  • Ends with a newline.

Entries appear in the dictionary's iteration order.

Value formatting (quoted vs. unquoted)

Each value is rendered either as a bare (unquoted) literal or as a double-quoted string, based on the value's content:

  • Unquoted: values that consist solely of characters valid for an unquoted identifier-style literal (letters, digits, and underscores) are emitted verbatim, with no surrounding quotes.

    Example: the value field_name is emitted as field_name.

  • Quoted: values containing any other characters (such as spaces or periods) are wrapped in double quotes (").

    Examples:

    • Dimension Name → "Dimension Name"
    • Group Name → "Group Name"
    • A dimension description. → "A dimension description."
Closing

After all body lines, the output ends with a closing } character. There is no trailing newline after the closing brace.

Complete Examples

No name, unquoted values:

Input: {"from_field": "field_name", "to_field": "field_name"}

Output:

{
  from_field: field_name
  to_field: field_name
}

No name, quoted values:

Input:

{
    "label": "Dimension Name",
    "group_label": "Group Name",
    "description": "A dimension description.",
}

Output:

{
  label: "Dimension Name"
  group_label: "Group Name"
  description: "A dimension description."
}

With name:

Input: {"name": "dimension_name", "label": "Dimension Name"}

Output:

dimension_name {
  label: "Dimension Name"
}

Public API

serialize_dict(data: dict) -> generator/iterable of str

The method returns an iterable of string fragments. Callers join these fragments with "" to obtain the full serialized output. The fragments must include their own newline characters and leading whitespace so that concatenation yields the exact formatted text described below.

Serialization Rules

Given a dictionary, produce block-structured text using 2 spaces per indentation level.

Block structure
  • A top-level dictionary without a name key is wrapped in a block delimited by { and }.
  • The opening brace is followed by a newline.
  • The closing } appears on its own line at the indentation level of the block it closes.
  • Each key/value pair inside a block appears on its own line, indented one level deeper than its enclosing block's braces.
  • Indentation must decrease to the correct parent level when a nested block closes.
  • The final top-level closing } has no trailing newline.
Dictionary values and name hoisting

A dictionary value is rendered as a nested block. Without a name key, it has this form:

key: {
  ...
}

If any dictionary contains a key named name, that key is not rendered as an ordinary line in the block body. Instead, its value is hoisted onto the block's opening line. All remaining keys are rendered inside the block in their normal order.

  • For a nested dictionary, use key: <name_value> {.
  • For the top-level dictionary, use <name_value> {, with no key or colon before the name value. This named opening replaces the otherwise bare top-level {.

For example, serializing:

{
    "name": "dimension_name",
    "label": "Dimension Name",
}

produces:

dimension_name {
  label: "Dimension Name"
}
Scalar values

A scalar, non-dictionary value is rendered on one line as:

key: value

The value is rendered using its string form without surrounding quotes, except for the quoted fields and booleans described below.

Quoted string fields

String values for keys named exactly label, group_label, or description must be surrounded by double quotes. This rule applies wherever those fields occur, including inside nested dictionaries. For example:

label: "Dimension Name"
group_label: "Group Name"
description: "A dimension description."

Other plain string scalar fields remain unquoted.

Boolean values

Boolean scalar values must be serialized as yes for True and no for False.

Ordering

Key/value pairs are emitted in the dictionary's iteration order (insertion order). A hoisted name key is omitted from the body; the relative order of the remaining entries is preserved.

Nested Formatting Example

Serializing:

{
    "derived_table": {
        "explore_source": {
            "bind_filters": {
                "from_field": "field_name",
                "to_field": "field_name",
            },
            "name": "explore_name",
        }
    }
}

produces, after joining the returned fragments:

{
  derived_table: {
    explore_source: explore_name {
      bind_filters: {
        from_field: field_name
        to_field: field_name
      }
    }
  }
}

In this example, the explore_source dictionary's name value is hoisted onto its opening line, its other key remains in the block body, indentation increases by 2 spaces at each nested level, and each closing brace returns to the indentation of the block it closes.

A complete scan must no longer discard ordinary whitespace between tokens. For example, scanning:

must produce, in order:

Expression-block trailing-whitespace exception

Whitespace that forms part of the trailing end of an expression block, immediately before its terminating ;;, is an exception to the general whitespace-emission rule. Expression scanning must consume and strip that trailing whitespace from the ExpressionBlockToken value. It must not emit a WhitespaceToken for that run. The ;; must still be represented by an ExpressionBlockEndToken.

Thus, scanning:

sql_distinct_key: concat(${orders.order_id}, '|', ${orders__items.primary_key}) ;;

must produce exactly this order:

(
    StreamStartToken(1),
    LiteralToken("sql_distinct_key", 1),
    ValueToken(1),
    WhitespaceToken(" ", 1),
    ExpressionBlockToken(
        "concat(${orders.order_id}, '|', ${orders__items.primary_key})",
        1,
    ),
    ExpressionBlockEndToken(1),
    StreamEndToken(1),
)

The space after : is emitted because it separates tokens. The space immediately before ;; is consumed as trailing expression-block whitespace, removed from the expression value, and does not become a separate token. Outside this expression-ending exception, whitespace runs between tokens continue to be emitted normally.

Module: lkml.tree

This module defines the node and token types used to build the syntax tree. Every type must support equality comparison by value (two instances with equal fields compare equal) and must render to a string via str(...).

Syntax Tokens

These represent leaf tokens carrying a string value plus optional surrounding whitespace ("trivia").

SyntaxToken
  • Constructor signature: SyntaxToken(value, prefix="", suffix="")
    • value: the token's string content.
    • prefix: whitespace/text rendered immediately before the value.
    • suffix: whitespace/text rendered immediately after the value.
  • str(SyntaxToken("foo")) → "foo"
  • str(SyntaxToken("foo", prefix="# Skip this\n ")) → "# Skip this\n foo"
  • str(SyntaxToken("foo", prefix="\n\t", suffix="\t\n")) → "\n\tfoo\t\n"
  • General rendering: prefix + value + suffix.
QuotedSyntaxToken
  • Same constructor signature as SyntaxToken (value, prefix="", suffix="") and same trivia behavior.
  • Rendering wraps the value in double quotes: prefix + '"' + value + '"' + suffix.
  • str(QuotedSyntaxToken("foo")) → '"foo"'
ExpressionSyntaxToken
  • Same constructor signature (value, prefix="", suffix="").
  • Represents a LookML expression block value. It must be constructible and comparable by value. (No specific string-rendering format is exercised.)
Punctuation Tokens

These are fixed-symbol tokens that also carry optional prefix/suffix trivia. Constructor signature for each: Cls(prefix="", suffix=""). Each renders as its symbol wrapped by its trivia (prefix + symbol + suffix).

  • Colon — symbol ":"
  • LeftCurlyBrace — symbol "{"
  • RightCurlyBrace — symbol "}"
  • LeftBracket — symbol "["
  • RightBracket — symbol "]"

    • str(PairNode(SyntaxToken("foo"), SyntaxToken("bar"))) → "foo: bar"
