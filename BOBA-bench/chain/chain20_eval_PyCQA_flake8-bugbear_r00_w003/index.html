Required change: how B008 handles lambdas

Public interface

Keep the top-level bugbear checker API in place:

  • bugbear.BugBearChecker
    • It is constructed by passing the source AST and an optional filename to its existing constructor.
    • run() returns the checker’s usual Flake8-style diagnostics.
  • bugbear.B008(lineno, col) continues to be the diagnostic type used for B008 findings.

For diagnostics, line numbers are one-based while columns are zero-based.

Behavior of B008

B008 detects function calls that are evaluated within function argument defaults. Calls located inside a lambda body must not be reported, because the lambda body is not evaluated when the default value is defined.

The following cases are required:

  1. When a lambda is used directly as a default value, it must not trigger B008 for a call in its body:

    def foo(f=lambda x: print(x)):
    f(1)

    In this case, no B008 diagnostic is produced.

  2. If a lambda occurs inside another call used as a default, the enclosing call is still reported, whereas calls within the lambda body are not:

    def no_nested_b006(a=map(lambda s: s.upper(), ["a", "b", "c"])):
    pass

    The result is one B008 diagnostic for map(...) at line 1, column 21. B008 must not be produced for s.upper() at column 35.

  3. This suppression applies specifically to lambda bodies. Nested calls located elsewhere in a default expression are still reported independently:

    def nested_b008(a=random.randint(0, dt.datetime.now().year)):
    pass

    This example produces B008 diagnostics at line 1, column 18 for random.randint(...) and at line 1, column 36 for dt.datetime.now().

A diagnostic is identified by its class and its source position; line numbers are one-based and columns are zero-based, and diagnostics are returned in source-location order.

Behavior of getattr / B009

A call to getattr must produce B009 when its constant attribute name can be written as normal attribute access.

The valid attribute names that are exercised are:

  • "bar"
  • "_123abc"
  • "abc123"
  • "some_attr"

B009 must not be produced for the exercised invalid names "123abc" and "except".

Inside lambda bodies, this behavior remains active. For instance, this call:

c = lambda x: getattr(x, "some_attr")

must produce B009 at the start of getattr. If this code is on line 45 as shown, the diagnostic is:

B009(45, 14)

A setattr call that appears in a lambda body must not produce B010. This covers both of the exercised forms that follow:

c = lambda x: setattr(x, "some_attr", 1)

and:

    def __init__(self, has_setter):
        self.cookie_filter = None
        if has_setter:
            self.setCookieFilter = lambda func: setattr(

04 Update the BugBearChecker class (in the bugbear module) so that it does not crash when the flake8 options object supplies select and/or extend_select… 343 words · source specification, reworded by GLM-5.3-Flash

Goal

Update the BugBearChecker class (in the bugbear module) so that it does not crash when the flake8 options object supplies select and/or extend_select attributes set to None.

Background

BugBearChecker is a plugin checker for flake8. It is instantiated with a filename (string path to a Python source file) together with an options object (a namespace-like object that carries flake8 configuration attributes). When it is run, the checker yields lint errors for the given file.

In newer versions of flake8, the options object's select and extend_select attributes may be None (instead of a list or tuple); this signifies that the user has not explicitly set them and that default values should apply.

Behavior Requirements

When its options object has both select and extend_select attributes equal to None, the BugBearChecker class must be constructable and runnable.

In particular:

  • For a BugBearChecker constructed with:

    • filename — a string path to a valid Python source file, and
    • options — an object exposing select = None and extend_select = None,

    calling its run() method must not raise any exception. It must return/yield an iterable of results (the call is wrapped in list(...) to consume the results).

  • Any checker logic that inspects select or extend_select (for example, to determine whether certain opt-in checks are enabled) must treat a None value as equivalent to "no selection provided" — i.e., it must not attempt operations (such as membership tests or iteration) that would fail on None. When both are None, default behavior is used to process the file, and no opt-in-only errors are produced for a clean file.

Public API Surface

  • Module: bugbear
  • Class: BugBearChecker
    • The constructor accepts the keyword arguments filename (str) and options (an options namespace object).
    • Instance method run() — returns an iterable of error results.

Edge Cases

  • options.select is None and options.extend_select is None: the checker must run successfully without error, yielding an empty result list for an input file that is otherwise clean and triggers no default errors.
05 Expose the following at the top level of the bugbear module 793 words · source specification, reworded by GLM-5.3-Flash

Add B023 diagnostics for late-binding loops

Public interface

Expose the following at the top level of the bugbear module:

B023(lineno: int, col: int, vars: tuple[str, ...] = ())

B023 must behave in the same manner as the existing bugbear diagnostic classes. As an example:

B023(12, 29, vars=("x",))

stands for a diagnostic whose message is:

B023 Function definition does not bind loop variable 'x'.

BugBearChecker must keep supporting:

checker = BugBearChecker(filename="path/to/file.py")
errors = list(checker.run())

The B023 diagnostics yielded by run() must be in the normal bugbear/flake8 diagnostic tuple format, which is equivalent to the corresponding B023(...).args.

For locations, line numbers are one-based and columns are zero-based.

Behavior that is required

Emit B023 when a lambda or def that is defined within a loop reads a name rebound by an enclosing loop, thereby creating a late-bound closure.

The following loop forms are the relevant ones:

  • for
  • async for
  • while
  • list comprehensions
  • set comprehensions
  • dict comprehensions
  • generator expressions, including async comprehensions

Loops must be checked regardless of whether they occur at module level or inside regular or async functions.

Names regarded as rebound by a loop

The rebinding forms that are exercised are:

  • for/async for/comprehension targets, including unpacked targets
  • ordinary name assignment
  • chained assignment
  • augmented assignment
  • annotated name assignment

Assignments count anywhere in the loop body, even if they appear textually after the function that reads the name.

In the example below, each marked read produces B023:

for x in range(3):
    y = x + 1
    lambda: x  # B023 for x
    lambda: y  # B023 for y

    def f():
        return x  # B023 for x

Similarly:

while True:
    a = a_ = a - 1
    b += 1
    lambda: a   # B023 for a
    lambda: a_  # B023 for a_
    lambda: b   # B023 for b
    lambda: c   # B023 for c
    c: bool = a > 3

Rebinding is relevant only when it is associated with an enclosing loop. A name assigned outside that loop does not qualify just because a function inside the loop reads it.

Placement and multiplicity of diagnostics
  • Place the diagnostic on the offending name read rather than on the lambda or def.
  • Set vars to a one-element tuple that contains that name.
  • Emit a separate diagnostic for each occurrence of an offending name.
  • Return the diagnostics in source order.
  • Nested loops must not result in duplicate diagnostics for the same occurrence.

As an example:

for j in range(2):
    for k in range(3):
        lambda: j * k

results in exactly two diagnostics, on the j and k name reads.

Comprehensions

A function created inside a comprehension may late-bind the comprehension target:

[lambda: x for x in range(2)]
{lambda: x for x in range(2)}
(lambda: x for x in range(2))
{x: lambda: x for x in range(2)}

Each of these examples produces one B023 on the x inside the lambda. The ordinary x that serves as the dict key does not produce B023.

The same holds for async comprehensions and for lambdas inside async for bodies.

Even when its read occurs inside a nested comprehension expression, a function body must still be checked:

for j, k, l in [(1, 2, 3)]:
    def f():
        j = None
        [l for k in range(2)]

This results in one B023 on the read of l. The assignment target j and the comprehension target k produce no diagnostics.

Mandatory exclusions

In the following cases, do not emit B023:

Function parameters

A parameter binding prevents its reference in the body from being treated as a late-bound loop reference:

for x in range(3):
    lambda x: x

    def f(x):
        return x
Expressions in default arguments

Reads that occur in the default values of a function or lambda are explicit captures and must not produce B023:

for x in range(3):
    lambda x=x: x

for var in range(2):
    def f(captured=var):
        return captured
Names that the enclosing loop does not rebind
z = 0

for x in range(3):
    lambda: z

Here, no B023 is produced for z.

Name occurrences that are not reads

The only diagnostic candidates are name reads. B023 must not be produced by assignment targets themselves.

An assignment made through an attribute or an item does not rebind the base name:

for j, k, l in [(1, 2, 3)]:
    def f():
        assert a and functions

    a.attribute = 1
    functions[0] = lambda: None

Neither a.attribute = ... nor functions[0] = ... turns a or functions into loop-rebound names, so the reads inside f produce no B023.

Add B024: abstract base class lacking abstract methods

Extend the bugbear module with a new default checker diagnostic that applies to abstract base classes containing no recognized abstract methods.

Public interface

The following import must execute successfully:

from bugbear import B024

B024 must follow the existing bugbear diagnostic API and must be callable in the following form:

B024(lineno, col, vars=(class_name,))

The text of the diagnostic is:

B024 {} is an abstract base class, but it has no abstract methods

bugbear.BugBearChecker(filename=...), together with its run() method, must emit this diagnostic in the existing checker result format.

Abstract base class declaration forms

A class is subject to B024 when declared in one of the following declaration forms:

  • class Name(ABC):
  • class Name(metaclass=ABCMeta):
  • class Name(abc.ABC):
  • class Name(metaclass=abc.ABCMeta):
  • A multiple-inheritance declaration that contains abc.ABCMeta, for example:
    class Name(other.Base, abc.ABCMeta):
  • A declaration that has another base together with abc.ABCMeta as its metaclass:
    class Name(other.Base, metaclass=abc.ABCMeta):

The spelling matters. If abc was imported under a different module alias, then a base like notabc.ABC does not, on its own, make the class subject to B024.

Abstract methods that are recognized

B024 must not be emitted when the class has a method that uses any of these decorator forms:

@abstractmethod
@abc.abstractmethod
@notabc.abstractmethod
@abstract
@abstractaoeuaoeuaoeu

Therefore, qualified abstractmethod is recognized no matter whether the qualifier is literally abc, and unqualified decorator names starting with abstract are recognized.

A decorator called notabstract is not recognized as an abstract-method decorator, even when it was imported as an alias of abc.abstractmethod.

Location and variables of the diagnostic

Whenever B024 is emitted, it must:

  • Point at the line of the class definition.
  • Use the column of the class definition, which is 0 for top-level classes.
  • Provide the class name via vars=(class_name,).
  • Be emitted in the same order as the source.

When a source file contains the declarations below at the indicated lines, the diagnostics emitted are exactly:

B024(17, 0, vars=("Base_1",))
B024(52, 0, vars=("Base_7",))
B024(58, 0, vars=("MetaBase_1",))
B024(69, 0, vars=("abc_Base_1",))
B024(74, 0, vars=("abc_Base_2",))
B024(84, 0, vars=("multi_super_1",))
B024(89, 0, vars=("multi_super_2",))

No B024 diagnostic is emitted in the following cases:

  • An ABC class that has a method decorated by any of the recognized abstract decorators listed above.
  • A class for which the only abstract-base spelling is notabc.ABC.

  • Dotted names, for example pickle.PickleError

B026(lineno: int, col: int)

  • col
  • message

B026 Star-arg unpacking after a keyword argument is strongly discouraged
bugbear.BugBearChecker

The interface that already exists must continue to support:

BugBearChecker(filename: str)
BugBearChecker.run()

Behavior that is required

Handling B023 false positives

Revise the B023 late-bound loop-variable analysis while keeping the existing public linting API intact.

Public API

The behavior is exposed via the top-level bugbear module:

  • bugbear.BugBearVisitor(filename=..., lines=...)
    • Analyze an AST by calling .visit(tree).
    • Report diagnostics via .errors.
  • bugbear.BugBearChecker(tree=..., filename=..., lines=...).run()
    • Continue to expose the same diagnostics through the checker interface.
  • bugbear.B023(lineno, col, vars=(variable_name,))
    • B023 diagnostics keep the message: B023 Function definition does not bind loop variable {!r}.

A B023 diagnostic must be located at the Name expression of the captured variable, using its one-based source line and zero-based AST column offset.

Behavior requirements

Names bound locally within a nested function

A name that a nested function assigns locally must not be treated as a captured loop variable, even when the same name is assigned elsewhere in the enclosing loop. The order of assignments in the enclosing loop must not affect this.

No B023 diagnostics are produced by this construct:

for name in ["a", "b"]:
    query = name

    def myfunc(x):
        query = x
        query_post = x
        _ = query
        _ = query_post

    query_post = name
Comprehensions with independent scopes

Targets from separate or nested comprehensions must not be conflated. Specifically, the repeated name targets below are local to their respective comprehensions and must not be treated as loop variables captured by the reduce callback:

_ = {
    k: v
    for k, v in reduce(
        lambda data, event: merge_mappings(
            [data, {name: f(caches, data, event) for name, f in xx}]
        ),
        events,
        {name: getattr(group, name) for name in yy},
    ).items()
    if k in backfill_fields
}

This construct as a whole produces no B023 diagnostics.
