01 The attr package offers declarative class definitions. 986 words · rewritten by GPT-5.6-sol, reworded by GLM-5.3-Flash

Summary

The attr package offers declarative class definitions. In a class body, attributes are declared with attr.ib, and attr.s turns the class into an attrs-decorated class carrying attribute metadata and the usual generated object protocols. In addition, the public helpers must expose that metadata and convert decorated instances to dictionaries.

Required Public API

The following names must be available directly from the top-level attr package and must support direct imports such as from attr import ib, s, ls, to_dict:

  • attr.s: the decorator for classes.
  • attr.ib: the callable for declaring attributes.
  • attr.ls: introspection of attribute metadata.
  • attr.to_dict: conversion of a decorated instance into a dictionary.

Beyond these, Attribute and NOTHING must be importable from attr._make.

Class Declaration and Decoration

attr.ib

The public call form of attr.ib is:

attr.ib(default_value=NOTHING, default_factory=NOTHING)

Callers are not required to import or pass NOTHING; it represents the omitted-argument state. These are the supported forms:

  • Calling attr.ib() declares a required attribute with no default.
  • Calling attr.ib(default_value=value) declares an attribute whose fallback is exactly value. None is a valid explicit default and is distinct from having no default.
  • Calling attr.ib(default_factory=factory) declares an attribute whose fallback is produced by calling the zero-argument factory when a value is omitted.

Providing both an actual default_value and an actual default_factory is ambiguous and must raise ValueError with this message:

Specifying both default_value and default_factory is ambiguous.

A declaration becomes effective when attr.s processes the class containing it.

attr.s

Both spellings of the decorator must work and must have equivalent default behavior:

@attr.s
class C(object):
    ...

@attr.s()
class D(object):
    ...

The decorator gathers attr.ib declarations in class-body declaration order, supports classes that have no declarations, and returns a decorated class that is usable. It stores on the class, as __attrs_attrs__, an ordered list of the corresponding Attribute objects.

For each declaration collected, the metadata must record:

  • the name of the class member in Attribute.name;
  • the explicit value in Attribute.default_value, or NOTHING when no value default was supplied; and
  • the factory in Attribute.default_factory, or NOTHING when no factory was supplied.
How Decorated Classes Behave

With the default behavior of attr.s, decorated classes provide the following observable protocols over their declared attributes, in declaration order:

  • Required values are accepted by the initializer positionally or by keyword and are assigned to the instance. Value defaults that are omitted are assigned as-is. Factory defaults that are omitted cause the factory to be called and its result to be assigned; a supplied value bypasses the factory.
  • repr(instance) takes the form <ClassName(name=value_repr, ...)>. For an empty decorated class, the representation is <ClassName()>.
  • For equality, inequality, and ordering, tuples of declared attribute values are compared. When the other operand is not an instance of self.__class__, the generated comparison method returns NotImplemented; as a consequence, ordinary equality with an unrelated class is false and inequality is true.
  • Hashing is derived from the tuple of declared attribute values.

Classes that have no declared attributes remain valid: they can be constructed without arguments, they have an empty metadata list, and their instances compare equal to other instances of the same class.

Metadata for Attributes

Attribute

It must be possible to construct attr._make.Attribute with the signature:

Attribute(name, default_value, default_factory)

Keyword use must be supported by all three arguments, including the fully keyword-based form. Through readable attributes of the same names, instances expose the three values.

Equality for Attribute is value-based: two Attribute instances compare equal when their name, default_value, and default_factory values compare equal. This makes it possible for lists returned by attr.ls to be compared directly with independently constructed metadata lists.

NOTHING

The sentinel for an absent value or factory is attr._make.NOTHING. It must be possible to distinguish it by identity from every valid explicit default, None in particular, and its representation is NOTHING.

Introspection Using attr.ls

The function attr.ls(class_or_instance) accepts either an attrs-decorated class or one of its instances. What it returns is a concrete list of that class's Attribute metadata in declaration order. Calling it on the class and calling it on an instance of that class must yield equivalent metadata.

When the argument does not identify an attrs-decorated class, attr.ls raises TypeError. The message takes this form:

<repr-of-class> is not an attrs-decorated class.

When the argument is an instance, the class used in this message is the instance's class.

Dictionary Conversion Using attr.to_dict

A new dictionary is what attr.to_dict(instance, recurse=True) returns: the declared attribute names serve as its keys, and its values are the current values of those attributes on the decorated instance. Instance attributes that are undeclared are not included.

  • Recursive conversion is switched on by default. When a declared attribute's value is itself an attrs-decorated instance, that value is converted recursively.
  • When recurse=False, values are retained without change, nested decorated instances included.
  • Recursion comes into play when the attribute value itself is decorated; values that are merely contained inside other container objects are not required to be traversed.
  • Supplying a value that is not an instance of an attrs-decorated class results in the same TypeError contract as attr.ls.

Worked Example

import attr
from attr._make import Attribute, NOTHING

@attr.s
class Child(object):
    value = attr.ib()

@attr.s()
class Parent(object):
    child = attr.ib()
    label = attr.ib(default_value=None)
    items = attr.ib(default_factory=list)

p = Parent(Child(1))

assert attr.ls(Parent) == [
    Attribute(name="child", default_value=NOTHING,
              default_factory=NOTHING),
    Attribute(name="label", default_value=None,
              default_factory=NOTHING),
    Attribute(name="items", default_value=NOTHING,
              default_factory=list),
]
assert attr.ls(p) == attr.ls(Parent)
assert attr.to_dict(p) == {
    "child": {"value": 1},
    "label": None,
    "items": [],
}
assert attr.to_dict(p, recurse=False)["child"] is p.child

Names and Scope

For the declaration callable, the required public name is attr.ib. Historical names such as attr.a fall outside the required surface; consumers must not need them.

The API and the behavior described here are the only requirements. There is no need to add unrelated functionality.

Overview

This task deals with the machinery that defines attributes in the attr package. Classes declare attributes by means of marker objects and are then decorated, which collects metadata and generates the usual initializer, representation, comparison, and hashing methods.

For this task, the canonical lower-level decorator name is _add_methods. Existing package-level use via attr.s remains a supported compatibility API.

Required Public API Surface

The following names must be importable from attr._make:

  • Attribute
  • NOTHING
  • _CountingAttr
  • _make_attr
  • _get_attrs
  • _add_methods

The following names must be importable from attr._funcs:

  • ls
  • has
  • to_dict

The package-level attr namespace must expose:

  • attr._add_methods
  • attr.s
  • attr.ib
  • attr.ls
  • attr.has
  • attr.to_dict

attr._add_methods is the re-export, at package level, of the canonical lower-level decorator name. Even so, package-level attr.s is required as the compatibility spelling described below. A name attr._make.s is not required.

The existing protocol helpers remain importable from attr._dunders:

  • NOTHING
  • _add_cmp
  • _add_hash
  • _add_init
  • _add_repr

The NOTHING exposed through attr._make and the one exposed through attr._dunders must be the same singleton sentinel. It represents an omitted value in situations where None is a valid explicit value, and repr(NOTHING) is "NOTHING".

Attribute Declarations and Metadata

Attribute

An Attribute represents one collected class attribute. Its constructor requires the three fields name, default_value, and default_factory; these fields can be supplied positionally or by keyword, as in:

Attribute(name="x", default_value=None, default_factory=NOTHING)

Instances expose those three values as attributes. Equality and inequality are value-based across these fields, so metadata constructed independently, with equal names and defaults, compares equal. Its representation includes the class name and all three named fields, for example:

Attribute(name='x', default_value=None, default_factory=NOTHING)
_make_attr and attr.ib

_make_attr(default_value=NOTHING, default_factory=NOTHING) creates a _CountingAttr declaration marker and returns it. attr.ib is the package-level callable for declaring attributes; it behaves the same and takes the same keyword arguments.

Markers record their default value or default factory, plus enough information about creation order for declarations to be collected in source order. A marker becomes part of generated class metadata only when its class is processed by the class decorator.

A declaration may have either a default value or a default factory, but not both. Supplying both raises ValueError with this message:

Specifying both default_value and default_factory is ambiguous.

None is a valid default_value and must not be treated as an omitted default.

_get_attrs

_get_attrs(cls) returns the declarations that are defined on cls, in declaration order. The result is a list of (name, marker) pairs, where each marker is a _CountingAttr. For example, declarations named z, y, and x in that source order produce pairs whose names are ['z', 'y', 'x'].

A class that has no declarations produces []. This is still true after _add_methods has processed the class.

The _add_methods Decorator

_add_methods is a class decorator that lives in attr._make. It must support being applied directly as a decorator:

from attr._make import _add_methods, _make_attr

@_add_methods
class Point(object):
    x = _make_attr()
    y = _make_attr(default_value=0)

It returns the class after processing it.

Collection of metadata

For each _CountingAttr declared directly in the class body, _add_methods creates an Attribute that carries:

  • the name of the class attribute to which the marker was assigned,
  • the marker's default_value, and
  • the marker's default_factory.

The resulting list, in declaration order, is assigned to cls.__attrs_attrs__. Each item in that list is an Attribute. So in the example above, Point.__attrs_attrs__[0].name == "x".

It is valid to decorate a class that has no declarations; doing so sets __attrs_attrs__ to an empty list. The presence of this metadata is what identifies the class as attrs-decorated, even when the list is empty.

Generated initializer and defaults

The generated __init__ accepts the declared attributes in declaration order and assigns them to the instance. Values can be given positionally or by keyword.

  • An attribute that has neither kind of default is required.
  • When an argument with default_value is omitted, that value is assigned. This covers an explicit default of None as well.
  • When an argument with default_factory is omitted, the factory is called with no arguments and its result is assigned. The factory is evaluated at the point where an instance needs the default, not at the time the class is defined.
  • An argument that is supplied explicitly takes precedence over either kind of default.
Generated representation

The generated __repr__ uses the class name at runtime and displays the attributes in declaration order as name=repr(value). For example, for a class C with attributes a and b, the representation of C(1, 2) is:

C(a=1, b=2)

A decorated class named C3 with no attributes has the representation C3().

Generated comparisons

The generated equality and ordering methods compare tuples of the declared attribute values in declaration order.

  • Instances whose values are equal compare equal; instances whose values differ compare unequal.
  • Equality is class-sensitive. An unrelated object does not compare equal merely because it has attributes with matching names and values.
  • __lt__, __le__, __gt__, and __ge__ perform the corresponding lexicographic tuple comparison for compatible instances.
  • For an object of an unrelated class, the generated direct comparison methods return NotImplemented; normal Python equality therefore resolves such objects as unequal.
  • Two instances of an empty decorated class compare equal.
Generated hash

The generated __hash__ hashes the tuple of the declared values in declaration order. Hash behavior therefore tracks the same values that comparisons use, subject to Python's normal hash requirements and collision semantics.

Package-Level Decorator Compatibility

attr.s must remain available. It supports both of the established forms:

@attr.s
class A(object):
    x = attr.ib()

@attr.s()
class B(object):
    x = attr.ib(default_value=None)
    y = attr.ib(default_factory=list)

In both forms, attr.ib declarations are collected into __attrs_attrs__, their defaults are preserved, and by default the same initializer, representation, comparison, and hash behavior as _add_methods is generated.

The called form continues to accept the boolean options add_repr, add_cmp, add_hash, and add_init, each of which defaults to True. Metadata collection always takes place; setting one of these options to False suppresses generation of the corresponding method group.

Throughout the attr._make API, and as the attr._add_methods re-export, the canonical name of the lower-level decorator remains _add_methods. Keeping attr.s at package level is an intentional compatibility alias for the same decoration capability, not a requirement to bring back the former lower-level attr._make.s name.

Introspection and Conversion Functions

ls

ls(value) accepts either an attrs-decorated class or one of its instances, and it returns the declaration-ordered list of Attribute metadata for that value. The metadata is the same whether it is called on the class or on an instance of that class. For a decorated class with no declarations, it returns an empty list.

For a value whose effective class has no attrs metadata, it raises TypeError. The message is:

{class_repr} is not an attrs-decorated class.

Here {class_repr} is repr() of the class being inspected. For example, when the built-in object class is inspected, its class representation is what appears in that template.

has

has(value) accepts a class or an instance and reports whether ls recognizes it as attrs-decorated:

  • True for decorated classes and for their instances;
  • True for decorated classes that have an empty metadata list; and
  • False for classes or instances that are ordinary and non-decorated.
to_dict

to_dict(instance, recurse=True) returns a dictionary that maps every declared attribute name to its current value on the instance.

With recurse=False, the conversion is shallow. For example, an object with x == 1 and y == 2 converts to {"x": 1, "y": 2}.

With the default recurse=True, a direct attribute value that is itself attrs-decorated is converted recursively. Consequently, if both fields of an object hold attrs-decorated objects, both field values become nested dictionaries. Values that are not attrs-decorated are kept unchanged.

attr.ls, attr.has, and attr.to_dict expose these same behaviors at package level.

Protocol Helper Compatibility

The helper decorators in attr._dunders operate on a class whose __attrs_attrs__ contains Attribute metadata. Each of them returns the modified class.

  • _add_repr(cls, attrs=None) installs the representation behavior described above. If attrs is supplied, it is the ordered sequence of attribute names to display, in place of deriving names from __attrs_attrs__.
  • _add_cmp(cls, attrs=None) installs __eq__, __ne__, and all four ordering methods, using the comparison behavior described above. An explicit attrs sequence selects and orders the values used.
  • _add_hash(cls, attrs=None) installs tuple-based hashing. An explicit attrs sequence selects and orders the values used.
  • _add_init(cls) installs an initializer built from cls.__attrs_attrs__, including required arguments, default values, and the default-factory behavior described above.

These helpers must keep working for classes whose __attrs_attrs__ metadata was assembled directly, as well as for classes processed through the declaration decorator.
