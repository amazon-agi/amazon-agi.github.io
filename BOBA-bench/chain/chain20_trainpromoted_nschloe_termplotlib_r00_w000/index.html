Task Specification: Adding subplot_grid to asciiplotlib

Overview

A subplot grid feature is to be added to the asciiplotlib package. The package is imported under the name apl:

import asciiplotlib as apl

Your implementation must provide the public factory function apl.subplot_grid(...), which returns a grid object that supports cell indexing, per-cell text printing, and rendering to a string.

Public API

apl.subplot_grid(layout, border_style="x", width=None)
  • layout: a 2-tuple (nrows, ncols) specifying the grid dimensions.
  • border_style: a string that serves as the single character drawing every border line (both horizontal and vertical borders, and corners/intersections). The default is "x".
  • width: the total width (in characters) of the fully rendered grid, with all border characters included. This value governs the entire output, and the interior column widths are divided evenly among the columns.

Returns a grid object (described below).

Indexing the grid object

2-D indexing using a (row, col) tuple is supported on the grid object:

cell = grid[0, 0]

Each indexing operation returns a cell object corresponding to that position in the grid.

Cell object: cell.aprint(text)

The supplied text string is stored in that cell for rendering later. The text may contain embedded newlines (\n), which produce multiple text lines within the cell.

The grid object: grid.get_string()

Returns the fully rendered grid as a single string (no trailing newline); the rows are separated by \n.

How the Grid Is Rendered

The grid is drawn as a box with borders, with the border_style character used at every border position (outer frame, inner column separators, and all intersections/corners).

Layout and dimensions
  • The total rendered width, in characters, is equal to width.
  • Border characters and separators surround each row of text content. A vertical border character occurs at the far left, between each pair of adjacent columns, and at the far right.
  • Padding of exactly one space sits immediately inside each vertical border, on both sides of the cell text.
  • The interior area lying between the borders is split evenly across the columns.
Vertical structure

The output is made up of:

  1. A top border line consisting of width copies of the border character.
  2. For each grid row:
    • One blank content line (interior filled with spaces, borders in place) above the text.
    • One content line for each text line of the tallest cell in that grid row.
    • One blank content line (interior filled with spaces, borders in place) below the text — this bottom blank line is produced only when at least one cell in that grid row has more than one line of text.
  3. A bottom border line made up of width copies of the border character.

Cells that have fewer text lines than the tallest cell in their row are padded with blank (space-filled) content lines, so that all cells in a grid row occupy the same number of content lines.

Text placement inside a cell
  • Within the cell's interior, text is left-aligned.
  • The interior text region begins after the left vertical border plus one space of padding.
  • Text longer than the available interior width is truncated so that it fits the interior width.

Worked Examples

Example 1
grid = apl.subplot_grid((1, 2), border_style="|", width=20)
grid[0, 0].aprint("Some text")
grid[0, 1].aprint("Some more text")
string = grid.get_string()

string must equal the following (rows joined by \n, no trailing newline):

xxxxxxxxxxxxxxxxxxxx
x         x        x
x Some te x Some m x
x         x        x
xxxxxxxxxxxxxxxxxxxx

Note: in this example, even with border_style="|", the rendered output still uses x characters for all border positions, as shown above.

Example 2
grid = apl.subplot_grid((1, 2), width=20)
grid[0, 0].aprint("Some text")
grid[0, 1].aprint("Some more text\nand more")
string = grid.get_string()

The value of string must equal:

xxxxxxxxxxxxxxxxxxxx
x         x        x
x Some te x Some m x
x         x and mo x
x         x        x
xxxxxxxxxxxxxxxxxxxx

In this case the second cell has two text lines, so the first cell is padded with a blank content line to match it, and a trailing blank content line is added for the grid row.

Notes on the Examples (deriving the exact dimensions)

For a total width of 20 and 2 columns:

  • The border/separator characters take up 3 positions (left, middle, right): columns 0, 9, and 19.
  • The interior of each column spans 8 characters, formatted as one leading space, then up to 6 characters of text, then one trailing space.
  • "Some text" truncates to "Some te" — the interior text region displays "Some te" in the available space (" Some te ").
  • "Some more text" is rendered as "Some m" (" Some m ").
  • "and more" is rendered as "and mo" (" and mo ").

A blank content line consists of the border character at each border position and spaces everywhere in the interior.

Miscellaneous

  • Behavior that already exists in the package (e.g. histogram functionality) must remain intact.

Behavior of the Horizontal Histogram

fig.hist(counts, bin_edges, orientation="horizontal") draws one text line per histogram bin. Each line follows this exact format:

<lower> - <upper>  [<count>]  <bar>

Where:

  1. Label for the bin range (<lower> - <upper>):

    • lower and upper are the values of consecutive bin edges.
    • Each edge is formatted using scientific notation with 2 digits after the decimal point and an explicit sign on both the mantissa and the exponent, that is, the format %+.2e (e.g. -3.23e+00, +1.70e-01, +2.89e+00).
    • Joining the two edge strings is - (space, hyphen, space).
    • All bin-range labels are right-aligned to a shared width (left-padded with spaces) so that the - separators and the columns around them line up across all rows. Since the sign is always explicit, all edge strings are equal in length; the label column width is uniform.

  2. Count field ([<count>]):

    • Square brackets enclose the integer count.
    • The count number is right-aligned inside a fixed width equal to the width of the largest count, which makes all counts line up. As an example, when the maximum count is 286 (3 digits), a count of 7 renders as [ 7] and 286 renders as [286].

  3. Separators: the range label and the count field are separated by exactly two spaces, and exactly two spaces also separate the count field from the bar.

  4. Bar (<bar>):

    • A horizontal bar is drawn with block-fill characters that represent the count magnitude, scaled so that the largest count fills a maximum bar width of 40 characters.
    • Bars use Unicode block elements to represent fractional widths in eighths. The full block is █ (U+2588). Any fractional remainder is rendered with the appropriate partial block from the eighth-block set:
      • ▏ (1/8, U+258F)
      • ▎ (2/8, U+258E)
      • ▍ (3/8, U+258D)
      • ▌ (4/8, U+258C)
      • ▋ (5/8, U+258B)
      • ▊ (6/8, U+258A)
      • ▉ (7/8, U+2589)
      • █ (8/8 / full, U+2588)
    • A bin's bar length is proportional to its count relative to the maximum count: bar_units = count / max_count * 40, expressed in eighths. For each whole unit a full block is drawn, and any fractional remainder gets a single partial block appended.
    • Trailing empty portions must not result in trailing characters or whitespace. A bar is made up only of its filled blocks (whole plus an optional partial); no padding is added after the bar. Counts that are very small round down to a single small partial block (e.g. a count of 2 against a max of 286 renders as just ▎).

Overall rendering behavior

  • Each value is converted to its normal string representation.

Public API

fig.table must keep accepting ordinary, ungrouped table data together with all existing table options. Grouped input is an additional form that is accepted. fig.get_string() returns the rendered table as a string that has no trailing newline. Other figure rendering and layout features must keep their existing behavior.

Structure of grouped table input

Grouped input consists of an outer sequence of row groups. Each group is made up of one or more rows, and each row is made up of the table's cells. For example:

data = [
    [["a", "bb", "ccc"]],
    [
        [1, 2, 3],
        [613.23236243236, 613.23236243236, 613.23236243236],
    ],
]

This stands for two consecutive groups:

  1. A heading group containing one row.
  2. A body group containing two rows.

The additional nesting is structural and must never be rendered as list syntax inside cells. The number of columns is the same for every row in every group. Cell values are rendered by means of their normal string representation.

Flat row data that was supported previously, such as [[1, 2], [3, 4]] or an equivalent two-dimensional array, is still valid and behaves as a single row group; it must not gain a special group separator.

Column widths are computed across all rows in all groups. Likewise, alignment and padding are applied consistently across group boundaries. A one-character alignment value applies to every column; a per-column value such as "lcr" chooses left, center, and right alignment respectively. Left is the default alignment.

How separators behave

With borders enabled:

  • The outer border, the vertical column boundaries, and ordinary row separators all use the table's normal border style.
  • Between every pair of adjacent rows within the same group, an ordinary horizontal separator is emitted. Under default thin Unicode borders this uses ├, ─, ┼, and ┤; under thin borders in ASCII mode it uses + junctions and - runs.
  • Between the last row of one group and the first row of the next, a single group separator is emitted. It takes the place of the ordinary separator at that boundary.
  • Group separators use the double style unless a different group style is selected. Under default Unicode borders this uses ╞, ═, ╪, and ╡; in ASCII mode it uses + junctions and = runs.
  • At a group boundary, no blank line is inserted.

border_style may be given as a two-item tuple (table_style, group_separator_style). The outer border, vertical borders, and ordinary separators are controlled by the first item, while separators between groups are controlled by the second. For instance, ("thin", "thick") keeps thin borders and thin within-group separators but uses a heavy horizontal group separator. Single-style border values that already exist keep their existing behavior for the ordinary table borders.

When border_style=None, all border output is switched off: there is no outer border, no vertical divider, no ordinary row separator, and no group separator. Group boundaries, in addition, do not introduce blank lines.
