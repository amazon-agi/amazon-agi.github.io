Task Specification: Implement subplot_grid in asciiplotlib

Overview

Add a subplot grid feature to the asciiplotlib package. The package is imported as apl:

import asciiplotlib as apl

You must implement a public factory function apl.subplot_grid(...) that returns a grid object supporting cell indexing, per-cell text printing, and rendering to a string.

Public API

apl.subplot_grid(layout, border_style="x", width=None)
  • layout: a 2-tuple (nrows, ncols) describing the grid dimensions.
  • border_style: a string used as the single character that draws every border line (both horizontal and vertical borders, and corners/intersections). Defaults to "x".
  • width: the total width (in characters) of the fully rendered grid, including all border characters. This value applies to the entire output, and the interior column widths are divided evenly among the columns.

Returns a grid object (described below).

Grid object indexing

The grid object supports 2-D indexing with a (row, col) tuple:

cell = grid[0, 0]

Each indexing returns a cell object corresponding to that position in the grid.

Cell object: cell.aprint(text)

Stores the given text string in that cell for later rendering. The text may contain embedded newlines (\n), producing multiple text lines within the cell.

Grid object: grid.get_string()

Returns the full rendered grid as a single string (no trailing newline), with rows separated by \n.

Rendering Behavior

The grid is drawn as a bordered box using the border_style character for every border position (outer frame, inner column separators, and all intersections/corners).

Layout and dimensions
  • The total rendered width in characters equals width.
  • Each row of text content is surrounded by border characters and separators. A vertical border character appears at the far left, between each pair of adjacent columns, and at the far right.
  • There is exactly one space of padding immediately inside each vertical border on both sides of the cell text.
  • The interior area between borders is split evenly across the columns.
Vertical structure

The output consists of:

  1. A top border line: width copies of the border character.
  2. For each grid row:
    • One blank content line (interior filled with spaces, borders in place) above the text.
    • One content line per text line of the tallest cell in that grid row.
    • One blank content line (interior filled with spaces, borders in place) below the text — this bottom blank line is produced only when at least one cell in that grid row has more than one line of text.
  3. A bottom border line: width copies of the border character.

Cells with fewer text lines than the tallest cell in their row are padded with blank (space-filled) content lines so all cells in a grid row occupy the same number of content lines.

Text placement within a cell
  • Text is left-aligned within the cell's interior.
  • The interior text region begins after the left vertical border and one space of padding.
  • Text that is longer than the available interior width is truncated to fit the interior width.

grid[0, 1].aprint("Some more text")

x Some te x Some m x
x         x        x
xxxxxxxxxxxxxxxxxxxx

Note: with border_style="|" in this example, the rendered output still uses x characters for all border positions as shown above.

Example 2

string = grid.get_string()

x Some te x Some m x
x         x and mo x
x         x        x
xxxxxxxxxxxxxxxxxxxx

Horizontal Histogram Behavior

fig.hist(counts, bin_edges, orientation="horizontal") renders one text line per histogram bin. Each line has this exact format:

<lower> - <upper>  [<count>]  <bar>

Where:

  1. Bin range label (<lower> - <upper>):

    • lower and upper are the consecutive bin edge values.
    • Each edge is formatted in scientific notation with 2 digits after the decimal point and an explicit sign on both the mantissa and exponent, i.e. the format %+.2e (e.g. -3.23e+00, +1.70e-01, +2.89e+00).
    • The two edge strings are joined by - (space, hyphen, space).
    • All bin-range labels are right-aligned to a common width (padded on the left with spaces) so that the - separators and the surrounding columns line up across all rows. Because the sign is always explicit, all edge strings have equal length; the label column width is uniform.

  2. Count field ([<count>]):

    • The integer count enclosed in square brackets.
    • The count number is right-aligned within a fixed width equal to the width of the largest count, so all counts line up. For example, with a maximum count of 286 (3 digits), a count of 7 renders as [ 7] and 286 renders as [286].

  3. Separators: exactly two spaces separate the range label from the count field, and exactly two spaces separate the count field from the bar.

  4. Bar (<bar>):

    • A horizontal bar drawn with block-fill characters representing the count magnitude, scaled so the largest count fills a maximum bar width of 40 characters.
    • Bars use Unicode block elements to represent fractional widths using eighths. The full block is █ (U+2588). Fractional remainders are rendered with the appropriate partial block from the eighth-block set:
      • ▏ (1/8, U+258F)
      • ▎ (2/8, U+258E)
      • ▍ (3/8, U+258D)
      • ▌ (4/8, U+258C)
      • ▋ (5/8, U+258B)
      • ▊ (6/8, U+258A)
      • ▉ (7/8, U+2589)
      • █ (8/8 / full, U+2588)
    • The bar length for a bin is proportional to its count relative to the maximum count: bar_units = count / max_count * 40, expressed in eighths. Full blocks are drawn for each whole unit, and a single partial block is appended for any fractional remainder.
    • Trailing empty portions must not produce trailing characters or whitespace. A bar consists only of its filled blocks (whole plus optional partial); no padding is added after the bar. Very small counts round down to a single small partial block (e.g. a count of 2 against a max of 286 renders as just ▎).

Required subplot-grid behavior

Grid creation and access

Text may be added directly to those figures. For example, grid[0, 1].aprint("first line\nsecond line") creates two successive content lines in the cell at row 0, column 1.

Borders and overall width

All visible grid borders must use the literal lowercase character x:

  • the full top and bottom borders consist of x characters;
  • the left and right edge of each body line uses x; and
  • adjacent columns are separated by x.

For C = layout[1] columns, column widths must be calculated from the requested overall width as follows:

base_width = (width - 3) // C
remainder = (width - 3) % C

Start every column at base_width, then add one character to each of the first remainder columns. Cell padding, truncation, and alignment

The default padding=(1, 2) gives every cell one blank line above and below its content and two spaces of padding to the left and right. A scalar padding applies to all four sides; for example, padding=2 gives two blank lines above and below the content as well as two spaces on each horizontal side.

Each cell must obey all of the following rules:

  1. Top and bottom padding are rendered as blank, space-filled lines inside the cell, before and after its content lines.
  2. A content line begins with the configured left padding.
  3. Text is truncated to the available content width: column_width - left_padding - right_padding.

The remaining width is divided as evenly as possible among the columns. Any remainder is assigned one character at a time from the leftmost column.

Consequently:

  • width=40 with three columns gives three 12-character cell slots; and
  • width=20 with two columns gives cell slots of 9 and 8 characters.

For bordered output, the slots plus the n + 1 visible border characters occupy exactly width characters. Borderless output removes the visible border positions and right-trims its lines, so its physical lines need not occupy the full width budget.

Padding

Padding follows CSS-like top/right/bottom/left expansion:

  • an integer applies to all four sides;
  • (a,) means (a, a, a, a);
  • (v, h) means (v, h, v, h);
  • (top, h, bottom) means (top, h, bottom, h); and
  • (top, right, bottom, left) is used directly.

With the default padding=(1, 2), every cell has one blank row above and below its content and two spaces at both the left and right. Content is left-aligned after the left padding. Its maximum displayed length is the cell-slot width minus the left and right padding; excess characters are dropped rather than wrapped.

Thus a 12-character slot under the default padding displays at most eight content characters:

  • Some text becomes Some tex;
  • Some more text becomes Some mor; and
  • even more becomes even mor.
Row heights

Every cell in one grid row is rendered to the height of the tallest cell in that row. Cells with fewer lines are blank-padded below their own rendered lines. Different grid rows may have different heights.

For the standard two-by-three example used below, the cells in the first grid row contain 1, 2, and 3 content lines, and those in the second contain 3, 2, and 1. Each row therefore has three content-line positions. With default padding, each bordered row occupies five lines: a blank top line, three aligned content positions, and a blank bottom line.

Support grouped table data for header/body sections

Public API

The top-level package must continue to expose the figure API:

import asciiplotlib as apl

fig.table(

    border_style=...,

fig.table must continue to accept ordinary, ungrouped table data and all existing table options. Grouped input is an additional accepted form. fig.get_string() returns the rendered table as a string without a trailing newline. Other figure rendering and layout features must retain their existing behavior.

Grouped table input

Grouped input is an outer sequence of row groups. Each group contains one or more rows, and each row contains the table's cells. For example:

data = [
    [["a", "bb", "ccc"]],
    [
        [1, 2, 3],
        [613.23236243236, 613.23236243236, 613.23236243236],
    ],
]

This represents two consecutive groups:

  1. A one-row heading group.
  2. A two-row body group.

The extra nesting is structural and must never be rendered as list syntax inside cells. Every row in every group has the same number of columns. Cell values are rendered using their normal string representation.

Previously supported flat row data, such as [[1, 2], [3, 4]] or an equivalent two-dimensional array, remains valid and behaves as one row group; it must not acquire a special group separator.

Column widths are calculated across all rows in all groups. Alignment and padding are likewise applied consistently across group boundaries. A one-character alignment value applies to every column; a per-column value such as "lcr" selects left, center, and right alignment respectively. The default alignment is left.

Separator behavior

When borders are enabled:

  • The table's normal border style is used for the outer border, vertical column boundaries, and ordinary row separators.
  • An ordinary horizontal separator is emitted between every pair of adjacent rows within the same group. With default thin Unicode borders this uses ├, ─, ┼, and ┤; with thin borders in ASCII mode it uses + junctions and - runs.
  • A single group separator is emitted between the last row of one group and the first row of the next. This replaces the ordinary separator at that boundary.
  • Unless a different group style is selected, group separators use the double style. With default Unicode borders this uses ╞, ═, ╪, and ╡. In ASCII mode it uses + junctions and = runs.
  • No blank line is inserted at a group boundary.

border_style may be a two-item tuple (table_style, group_separator_style). The first item controls the outer border, vertical borders, and ordinary separators, while the second controls separators between groups. For example, ("thin", "thick") retains thin borders and thin within-group separators but uses a heavy horizontal group separator. Existing single-style border values retain their existing behavior for the ordinary table borders.

With border_style=None, all border output is disabled: there is no outer border, no vertical divider, no ordinary row separator, and no group separator. Group boundaries also do not introduce blank lines.
