Task Description

Goal

The imgix URL-builder package is to be updated so that it works correctly on Python 3 and exposes the public API and URL-generation behavior laid out below. The package must be importable as follows:

import imgix

Public API of the Package

Module-Level Constants

These module-level constants must be exported by the package:

  • imgix.SIGNATURE_MODE_PATH
  • imgix.SHARD_STRATEGY_CYCLE

Their exact literal values are not prescribed. They must be stable, distinct, comparable values that are suitable for passing to UrlBuilder.

imgix.UrlBuilder

A class named UrlBuilder must be exported by the package. Constructing it must conceptually support the following argument order:

UrlBuilder(
    domain,
    use_https=False,
    sign_key=None,
    sign_mode=...,
    shard_strategy=...,
)

The following requirements apply:

  • domain is the first positional argument and is a domain string such as "my-social-network.imgix.net". It serves as the network location of generated URLs.

  • use_https is the second positional argument, may also be passed as a keyword argument, and defaults to False.

  • sign_key is the third positional argument, may also be supplied by keyword, and its default is no signing key.

  • The constructor must accept sign_mode and shard_strategy as keyword arguments.

  • Mode and strategy values supplied to the constructor must be retained exactly. In particular:

    builder = imgix.UrlBuilder(
    "my-social-network.imgix.net",
    sign_mode=imgix.SIGNATURE_MODE_PATH,
    shard_strategy=imgix.SHARD_STRATEGY_CYCLE,
)
assert builder._sign_mode == imgix.SIGNATURE_MODE_PATH
assert builder._shard_strategy == imgix.SHARD_STRATEGY_CYCLE

  • Calling imgix.UrlBuilder(domain) must return an object whose type is exactly imgix.UrlBuilder.

Generation of URLs

Signature of the Method
builder.create_url(path, **parameters)

path is a string. Any additional keyword arguments stand for URL query parameters, such as w=400 and h=300. The method returns a URL string.

URL Scheme and Host
  • When use_https is omitted or is False, the scheme is http.
  • When use_https is True, the scheme is https, whether the value is supplied positionally or by keyword.
  • The network location of the URL is the configured domain.
  • The string that results must be a valid, parseable URL.
Normalizing the Path

The path is normalized before the URL is rendered or a signature is computed:

  1. If the input starts with the case-sensitive prefix http (including ordinary http://... and https://... source URLs), the entire input is percent-encoded with no additional safe characters. Observably, this is equivalent to urllib.parse.quote(path, safe=""): characters such as : and / are encoded, while RFC-unreserved characters stay unescaped. That encoded text then serves as the imgix path.
  2. Otherwise, an ordinary path is preserved unchanged, apart from the leading-slash rule below. In particular, an existing leading-slash ASCII path remains unchanged.
  3. Ensure the resulting path starts with /; when it does not, prepend one.

As an illustration, take the source URL:

http://avatars.com/john-smith.png

It becomes the following normalized path on the configured domain:

/http%3A%2F%2Favatars.com%2Fjohn-smith.png
Serialization of Query Parameters
  • Transformation parameters are serialized as key=value query components. For numeric values, their textual representation must be used, so h=300 renders as h=300.
  • The components are sorted lexicographically by key, regardless of the order in which the keyword arguments were supplied.
  • The components are joined with &.
  • A non-empty query is prefixed with ?.
  • When there are neither transformation parameters nor a signature, no query delimiter is added.

As an example:

builder = imgix.UrlBuilder("my-social-network.imgix.net")
builder.create_url("/users/1.png", w=400, h=300)

must return:

http://my-social-network.imgix.net/users/1.png?h=300&w=400
URL Signing

If a signing key is configured, an s query parameter that holds a lowercase 32-character MD5 hexadecimal digest is appended. It is computed as follows:

  • Let P denote the normalized path, its leading / included.
  • Let Q be the sorted transformation query, without a leading ? and without the signature.
  • When Q is non-empty, the signing input is sign_key + P + "?" + Q.
  • When Q is empty, the signing input is sign_key + P, and no delimiter follows the path.
  • Neither the scheme nor the domain is part of the signing input.
  • When Q is non-empty, the signature is appended after all transformation parameters, as &s=<digest>.
  • When Q is empty, the query of the URL is ?s=<digest>.

Path normalization and fully-qualified-source-URL encoding take place before signing, so the value included in P is an encoded proxy path.

By way of example:

signed = imgix.UrlBuilder(
    "my-social-network.imgix.net", False, "FOO123bar"
)
signed.create_url("/users/1.png")

must return:

http://my-social-network.imgix.net/users/1.png?s=6797c24146142d5b40bde3141fd3600c

Given w=400, h=300, the signing input is:

FOO123bar/users/1.png?h=300&w=400

and the final signature is still the last query component.

Exact Shape of the Returned URL

The URL that is returned has the following shape:

<scheme>://<domain><normalized-path>[?<sorted-query>][&s=<signature>]

In the signature-only case, ?s=<signature> is used. No path-parameter section or fragment is added. As a result, a plain unsigned path produces exactly:

http://my-social-network.imgix.net/users/1.png

Compatibility with Python 3

All code in the imgix package must run under Python 3 and must not depend on Python 2-only modules or syntax. Specifically, URL parsing, quoting, query serialization, and URL assembly must use Python 3-compatible facilities such as those in urllib.parse, instead of the Python 2-only urlparse module or the Python 2-only urllib APIs. Other Python 2-only idioms must, likewise, be replaced with Python 3-compatible equivalents.

Scope and Non-Goals

  • The query-signing behavior driven by sign_key is required exactly as described above. For SIGNATURE_MODE_PATH, no separate path-signature generation semantics are required; the public requirement for sign_mode is that it be accepted and retained.
  • Beyond accepting and retaining the supplied shard_strategy, no domain-sharding selection behavior is required.
  • For ordinary paths, no general UTF-8 encoding behavior is prescribed. Full encoding of input strings that begin with http is required, as described above.
  • The exact literal values of the exported constants are intentionally left unspecified.

Task Specification: URL Builder Supporting UTF-8 Paths

Goal

Supply an imgix package in which UrlBuilder builds imgix image URLs out of one or more domains plus an image path. URL generation must preserve the existing behavior for query parameters, signing, scheme selection, proxy sources, and domain sharding, while correctly accepting Unicode paths and percent-encoding their UTF-8 bytes.

Python 2.7 and Python 3 are both required to deliver the same public behavior and URL strings.

Public API

The package must be importable with:

import imgix

It must expose the following constants at module level:

imgix.SHARD_STRATEGY_CRC     == "crc"
imgix.SHARD_STRATEGY_CYCLE   == "cycle"
imgix.SIGNATURE_MODE_QUERY   == "query"
imgix.SIGNATURE_MODE_PATH    == "path"

It must also expose imgix.UrlBuilder with this constructor-compatible interface:

UrlBuilder(
    domains,
    use_https=False,
    sign_key=None,
    sign_mode=imgix.SIGNATURE_MODE_QUERY,
    shard_strategy=imgix.SHARD_STRATEGY_CRC,
)
  • domains is either a domain string, such as "my-social-network.imgix.net", or an ordered list of domain strings for domain sharding. A single string is handled as a one-domain configuration. Domains serve as the URL hosts and are not prefixed with a scheme by the caller.
  • use_https determines the scheme that is generated. It appears as the second positional argument and may also be supplied by keyword.
  • sign_key is a signing key that is optional. It appears as the third positional argument and may also be supplied by keyword.
  • sign_mode accepts the signature-mode constants that the module exports.
  • shard_strategy accepts the sharding-strategy constants that the module exports.

For compatibility, the constructor must accept sign_mode and shard_strategy by keyword, and it must retain the values supplied for them on the builder as _sign_mode and _shard_strategy, respectively. In particular, constructing with sign_mode=imgix.SIGNATURE_MODE_PATH and shard_strategy=imgix.SHARD_STRATEGY_CYCLE must succeed, with both values preserved.

The builder must provide:

create_url(path, **parameters)
  • path is a string or a Unicode string, and it may contain arbitrary Unicode characters.
  • Each keyword in parameters stands for a URL query parameter.
  • The method returns the fully assembled URL as a string.

Behavior Requirements

Choosing the scheme
  • With use_https=False, including when it is omitted, an http URL is produced.
  • use_https=True produces an https URL.
  • Both values must work whether they are passed positionally or by keyword.

For example:

imgix.UrlBuilder("my-social-network.imgix.net").create_url("/users/1.png")
# http://my-social-network.imgix.net/users/1.png

imgix.UrlBuilder("my-social-network.imgix.net", True).create_url("/users/1.png")
# https://my-social-network.imgix.net/users/1.png
Domain choice and sharding

Whenever a single domain is supplied, that domain is always the one used. Whenever an ordered list is supplied:

  • SHARD_STRATEGY_CRC, the default, picks the domain deterministically: it computes the unsigned CRC-32 of the original path's bytes and takes the result modulo the number of domains. Unicode paths must be converted to UTF-8 bytes for this calculation; domain selection must not fail merely because a path is non-ASCII. The same path therefore resolves to the same domain.
  • SHARD_STRATEGY_CYCLE picks the first domain for the first generated URL, then steps through the list on each call, wrapping back to the first domain.
Normalizing paths

Every generated URL must have a path that begins with /:

  • When an ordinary input path already begins with /, preserve that leading separator.
  • Otherwise, prepend one.

So both "users/1.png" and "/users/1.png" result in a URL path of /users/1.png:

http://my-social-network.imgix.net/users/1.png

The normalized encoded path goes immediately after <scheme>://<domain>.

Encoding of ordinary paths and Unicode

For an ordinary image path:

  • / path separators and URL-path-safe ASCII characters are preserved, including ASCII letters, digits, and ..
  • Each non-ASCII character is encoded as UTF-8, and each resulting byte is then percent-escaped.
  • The hexadecimal digits in percent escapes must be uppercase.
  • Callers must be able to pass Unicode text directly; they must not have to pre-encode it to bytes.

With the domain my-social-network.imgix.net and the default scheme, the required examples are:

builder.create_url(u"/ǝ")
# http://my-social-network.imgix.net/%C7%9D

and:

builder.create_url(u"/üsers/1/米国でのパーティーします。.png")
# http://my-social-network.imgix.net/%C3%BCsers/1/%E7%B1%B3%E5%9B%BD%E3%81%A7%E3%81%AE%E3%83%91%E3%83%BC%E3%83%86%E3%82%A3%E3%83%BC%E3%81%97%E3%81%BE%E3%81%99%E3%80%82.png

In the second example, /, sers, 1, and .png stay literal, whereas ü, the Japanese characters, and 。 are represented by percent-escaped UTF-8 bytes.

Source URLs that are fully qualified

A path that starts with the literal prefix http is treated as a fully qualified proxy-source URL. Its source URL must be percent-encoded as a single path component:

  • In the source URL, reserved characters — including : and every / — are percent-escaped.
  • URL-unreserved characters, such as letters, digits, -, and ., stay literal.
  • A leading / is then added, so that the encoded source sits below the configured imgix domain.
  • Only after this path conversion are query parameters and signing applied. The signing payload uses the encoded, leading-slash-prefixed path.

As an example, this source:

http://avatars.com/john-smith.png

becomes this imgix path:

/http%3A%2F%2Favatars.com%2Fjohn-smith.png
Query-string parameters

create_url must serialize its keyword parameters into the query string of the URL:

  • The parameters are sorted lexicographically by key, independently of the order in which they were supplied.
  • Keys and values are converted to their string forms and URL-encoded as query components.
  • Each pair is emitted as key=value, the pairs are joined with &, and a non-empty query is prefixed with ?.
  • A parameter is omitted if its value is falsey.
  • When there are no retained parameters and no signature, do not add a query delimiter.

For example:

builder.create_url("/users/1.png", w=400, h=300)
# http://my-social-network.imgix.net/users/1.png?h=300&w=400
URL signing in query mode

When a sign_key that is non-empty has been configured, an s query parameter containing a lowercase MD5 hexadecimal digest is appended.

Let:

  • encoded_path be the final normalized path, with its leading / included;
  • query be the sorted, encoded transformation query, with no leading ? and with no signature.

The input for the signature is:

sign_key + encoded_path                         # when query is empty
sign_key + encoded_path + "?" + query           # when query is non-empty

MD5 is computed over the UTF-8 bytes of that concatenated value. If transformation parameters exist, &s=<digest> is appended after all of them; otherwise ?s=<digest> is used. The s parameter therefore always comes last and is not included in its own digest.

Using sign_key="FOO123bar", the required results include:

builder.create_url("/users/1.png")
# http://my-social-network.imgix.net/users/1.png?s=6797c24146142d5b40bde3141fd3600c

builder.create_url("/users/1.png", w=400, h=300)
# http://my-social-network.imgix.net/users/1.png?h=300&w=400&s=1a4e48641614d1109c6a7af51be23d18

builder.create_url("http://avatars.com/john-smith.png")
# http://my-social-network.imgix.net/http%3A%2F%2Favatars.com%2Fjohn-smith.png?s=493a52f008c91416351f8b33d4883135

builder.create_url("http://avatars.com/john-smith.png", w=400, h=300)
# http://my-social-network.imgix.net/http%3A%2F%2Favatars.com%2Fjohn-smith.png?h=300&w=400&s=a201fe1a3caef4944dcb40f6ce99e746

These examples assume the following:

builder = imgix.UrlBuilder(
    "my-social-network.imgix.net", False, "FOO123bar"
)

SIGNATURE_MODE_QUERY is the URL-generation mode that is supported, and it is the default. SIGNATURE_MODE_PATH must remain exported, must be accepted by the builder, and must be retained for API compatibility. URL generation with path signatures is unsupported: trying to generate a URL in that mode must raise an exception rather than silently applying query-mode signing.

Shape of the final URL

The output has exactly this shape:

<scheme>://<selected-domain><encoded-path>[?<sorted-query>[&s=<signature>]]

or, for a signed URL with no transformation parameters:

<scheme>://<selected-domain><encoded-path>?s=<signature>

Neither a path-parameter section nor a fragment is added. Query ordering, path normalization, and percent encoding all take place before signing, so that the URL text and the signing payload agree.

Compatibility

  • The package must support Python 2.7 as well as Python 3.
  • In both environments, direct Unicode path input must work.
  • In both environments, equivalent text input must produce identical percent-encoded URL output.
  • With the default CRC sharding strategy, non-ASCII paths must also remain usable rather than raising an ASCII encoding error.

Summary

A Python package called imgix is to be implemented. What it delivers is the functionality for building imgix image URLs; support for signed URLs is part of this, and so is URL-safe encoding of paths. The package must function under both Python 2 and Python 3.

Package Layout and Public API

Package imgix

The names listed below must be exposed directly by the top-level imgix package (importable as imgix.<name>):

  • UrlBuilder — a class (its description appears further down).
  • SIGNATURE_MODE_PATH — a constant value.
  • SHARD_STRATEGY_CYCLE — a constant value.
The imgix.compat submodule

There must be a submodule, imgix.compat, whose purpose is to abstract away the standard-library differences between Python 2 / Python 3. From it, the following must be exposed:

  • urlparse — a name that refers to the standard-library module doing URL parsing (that is, the module called urllib.parse in Python 3 and urlparse in Python 2.7). Calling imgix.compat.urlparse.urlparse(url) must return a parse result on which the .scheme attribute is available.

Resolution of the Python 2/3 URL-handling differences happens in this module and nowhere else; everything else in the package must rely on it instead of carrying out version checks of its own.

Class UrlBuilder

The Constructor
UrlBuilder(domain, use_https=False, sign_key=None,
           sign_mode=SIGNATURE_MODE_PATH, shard_strategy=SHARD_STRATEGY_CYCLE)
  • domain (str, required) — the imgix domain; 'my-social-network.imgix.net' serves as an example.
  • HTTPS usage is controlled by the second positional parameter. When it is omitted, the default is a value that produces http URLs.
  • The signing key — the input from which signed URLs get produced — is the third positional parameter. When it is omitted, or when None is passed, the URLs are not signed.
  • sign_mode (keyword) — the default here is SIGNATURE_MODE_PATH.
  • shard_strategy (keyword) — its default is SHARD_STRATEGY_CYCLE.

The constructor must record the values supplied for sign_mode and shard_strategy in a way that leaves them accessible as the instance attributes _sign_mode and _shard_strategy. Construction with sign_mode=SIGNATURE_MODE_PATH and shard_strategy=SHARD_STRATEGY_CYCLE must leave those attributes equal to the corresponding module constants.

For an instance, it must be true that type(builder) is imgix.UrlBuilder.

Switching on HTTPS

Even after construction has taken place, the builder must support a switch over to HTTPS. For this, provide the method:

UrlBuilder.set_use_https(use_https)

Once it has been called with a truthy value, URLs created from then on use the https scheme. Prior to any call (default construction), created URLs use the http scheme.

Method create_url
UrlBuilder.create_url(path, **parameters)

The method builds a full URL string and returns it.

Scheme and host. By default the scheme of the URL is http; enabling HTTPS changes it to https. The host is taken from the domain given to the constructor.

Handling of the path.

  • With a plain path — "/users/1.png" is one such — the path simply gets appended to the host, which produces, for example, http://my-social-network.imgix.net/users/1.png.

  • When the path handed in is a fully-qualified URL (one example being "http://avatars.com/john-smith.png"), percent-encoding must cover it in its entirety, after which it serves as a single path segment. Escaping must be applied to every reserved character — : and / included — with the result that http://avatars.com/john-smith.png turns into http%3A%2F%2Favatars.com%2Fjohn-smith.png.

  • Should the path contain non-ASCII / UTF-8 characters, those characters must be UTF-8 encoded and percent-encoded; the ordinary path separators (/), which give a non-URL path its structure, are preserved on the other hand. Some examples:

    • u'/ǝ' → path portion /%C7%9D
    • u'/üsers/1/米国でのパーティーします。.png' → path portion /%C3%BCsers/1/%E7%B1%B3%E5%9B%BD%E3%81%A7%E3%81%AE%E3%83%91%E3%83%BC%E3%83%86%E3%82%A3%E3%83%BC%E3%81%97%E3%81%BE%E3%81%99%E3%80%82.png

    (Note: with an ordinary path, the / separators stay unescaped; with a path that is a fully-qualified URL, the / characters get escaped, since that URL in its entirety is handled as one segment.)

Query-string parameters. Any keyword arguments handed to create_url turn into query-string parameters. Their emission must follow an ascending alphabetical order by key. To illustrate: w=400, h=300 results in the query string h=300&w=400.

Signing. If the builder was given a signing key at construction, a signature parameter s must be appended as the final query parameter (following any user-supplied parameters). The signature itself is the MD5 hex digest of the signing key concatenated with the request path together with its query string — in other words, everything running from the path's leading / through the parameter query string, if any. To make this concrete, let the signing key be "FOO123bar":

  • create_url("/users/1.png") → http://my-social-network.imgix.net/users/1.png?s=6797c24146142d5b40bde3141fd3600c
  • create_url("/users/1.png", w=400, h=300) → http://my-social-network.imgix.net/users/1.png?h=300&w=400&s=1a4e48641614d1109c6a7af51be23d18
  • create_url("http://avatars.com/john-smith.png") → http://my-social-network.imgix.net/http%3A%2F%2Favatars.com%2Fjohn-smith.png?s=493a52f008c91416351f8b33d4883135
  • create_url("http://avatars.com/john-smith.png", w=400, h=300) → http://my-social-network.imgix.net/http%3A%2F%2Favatars.com%2Fjohn-smith.png?h=300&w=400&s=a201fe1a3caef4944dcb40f6ce99e746

Absent a signing key, no s parameter is added:

  • create_url("/users/1.png") → http://my-social-network.imgix.net/users/1.png
  • create_url("/users/1.png", w=400, h=300) → http://my-social-network.imgix.net/users/1.png?h=300&w=400

Compatibility Constraints

The implementation must function correctly on both Python 2.7 and Python 3; what is more, imgix.compat is where all URL-parsing/encoding version differences must be isolated.

Overall Output Format

The returned string is a list of entries delimited by commas (,). Splitting that string on , yields the individual entries. Each entry takes the form:

<URL> <descriptor>

A single space separates <URL> from <descriptor>. Taking index 1 after splitting an entry on a space yields the descriptor.

Each <URL> is built exactly the way create_url(path, params_for_this_entry) would build it, with the same builder configuration (domain, sign key, include_library_param, etc.). As a result, when a sign_key is configured, each URL includes a signature parameter s=<md5hex>, computed as the MD5 hex digest of the string created by concatenating the sign key, the path (including a leading /), and the query string portion of the URL (?... up to but not including the signature). The signature is the last query parameter.

Two output formats exist, and the choice between them is made automatically based on params.

Rules for Format Selection
  • When the params dictionary contains a w (width) key, OR when it contains both an h (height) key and an ar (aspect ratio) key, the DPR format is produced.
  • The width-pairs format is produced in all other cases — including when params is empty, when only h is provided, or when only ar is provided.
The Width-Pairs Format

This format produces exactly 31 entries.

The URL of each entry is built by inserting a w=<value> parameter (alongside any parameters passed in params), and the descriptor of each entry is <value>w (the width value followed by the letter w).

In order, the 31 width values are exactly:

100, 116, 134, 156, 182, 210, 244, 282, 328, 380, 442, 512,
594, 688, 798, 926, 1074, 1246, 1446, 1678, 1946, 2258, 2618,
3038, 3524, 4088, 4742, 5500, 6380, 7400, 8192

Properties that these values must satisfy (all of them satisfied by the list above):

  • The smallest width is 100, the largest is 8192, and every width lies within the inclusive range [100, 8192].
  • The widths are strictly increasing, and every successive width is less than 1.18× the one preceding it (i.e. each step increases by strictly less than 18%).

All parameters supplied in params (e.g. h, ar) are included in every URL in addition to the generated w parameter.

The DPR Format

This format produces exactly 5 entries.

  • Each entry's URL is built from the same params (no per-entry width is generated). The URL is identical for all 5 entries (apart from being built once per entry with the same params).
  • The descriptors, in order, are: 1x, 2x, 3x, 4x, 5x (device pixel ratio 1 through 5, each followed by the letter x).
