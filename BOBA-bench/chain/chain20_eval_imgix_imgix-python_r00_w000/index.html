Objective

Update the imgix URL-builder package so that it runs correctly on Python 3 and exposes the public API and URL-generation behavior defined below. The package must be importable as:

import imgix

Public package API

Constants

The package must export these module-level constants:

  • imgix.SIGNATURE_MODE_PATH
  • imgix.SHARD_STRATEGY_CYCLE

Their exact literal values are not prescribed. They must be stable, distinct, comparable values suitable for passing to UrlBuilder.

imgix.UrlBuilder

The package must export a class named UrlBuilder. Constructing it must conceptually support this argument order:

UrlBuilder(
    domain,
    use_https=False,
    sign_key=None,
    sign_mode=...,
    shard_strategy=...,
)

Requirements:

  • domain is the first positional argument and is a domain string such as "my-social-network.imgix.net". It is used as the network location of generated URLs.

  • use_https is the second positional argument, may also be passed by keyword, and defaults to False.

  • sign_key is the third positional argument, may also be passed by keyword, and defaults to no signing key.

  • sign_mode and shard_strategy must be accepted as keyword arguments.

  • Constructor-provided mode and strategy values must be retained exactly. In particular:

    builder = imgix.UrlBuilder(
    "my-social-network.imgix.net",
    sign_mode=imgix.SIGNATURE_MODE_PATH,
    shard_strategy=imgix.SHARD_STRATEGY_CYCLE,
)
assert builder._sign_mode == imgix.SIGNATURE_MODE_PATH
assert builder._shard_strategy == imgix.SHARD_STRATEGY_CYCLE

  • imgix.UrlBuilder(domain) must return an object whose type is exactly imgix.UrlBuilder.

URL generation

Method signature
builder.create_url(path, **parameters)

path is a string. Any additional keyword arguments represent URL query parameters, such as w=400 and h=300. The method returns a URL string.

Scheme and host
  • The scheme is http when use_https is omitted or is False.
  • The scheme is https when use_https is True, whether supplied positionally or by keyword.
  • The configured domain is the URL's network location.
  • The resulting string must be a valid, parseable URL.
Path normalization

Normalize the path before rendering the URL or computing a signature:

  1. If the input begins with the case-sensitive prefix http (including ordinary http://... and https://... source URLs), percent-encode the entire input with no additional safe characters. This is observably equivalent to urllib.parse.quote(path, safe=""): characters such as : and / are encoded, while RFC-unreserved characters remain unescaped. Use that encoded text as the imgix path.
  2. Otherwise, preserve an ordinary path unchanged, apart from the leading-slash rule below. In particular, an existing leading-slash ASCII path remains unchanged.
  3. Ensure the resulting path starts with /; prepend one when it does not.

For example, the source URL:

http://avatars.com/john-smith.png

becomes this normalized path on the configured domain:

/http%3A%2F%2Favatars.com%2Fjohn-smith.png
Query parameters
  • Serialize transformation parameters as key=value query components. Numeric values must have their textual representation, so h=300 renders as h=300.
  • Sort components lexicographically by key, regardless of the order in which keyword arguments were supplied.
  • Join components with &.
  • Prefix a non-empty query with ?.
  • Do not add a query delimiter when there are neither transformation parameters nor a signature.

For example:

builder = imgix.UrlBuilder("my-social-network.imgix.net")
builder.create_url("/users/1.png", w=400, h=300)

must return:

http://my-social-network.imgix.net/users/1.png?h=300&w=400
Signing

When a signing key is configured, append an s query parameter containing a lowercase 32-character MD5 hexadecimal digest. Compute it as follows:

  • Let P be the normalized path, including its leading /.
  • Let Q be the sorted transformation query without a leading ? and without the signature.
  • If Q is non-empty, the signing input is sign_key + P + "?" + Q.
  • If Q is empty, the signing input is sign_key + P; no delimiter follows the path.
  • The scheme and domain are not part of the signing input.
  • If Q is non-empty, append the signature after all transformation parameters as &s=<digest>.
  • If Q is empty, the URL query is ?s=<digest>.

Path normalization and fully-qualified-source-URL encoding occur before signing, so an encoded proxy path is the value included in P.

For example:

signed = imgix.UrlBuilder(
    "my-social-network.imgix.net", False, "FOO123bar"
)
signed.create_url("/users/1.png")

must return:

http://my-social-network.imgix.net/users/1.png?s=6797c24146142d5b40bde3141fd3600c

With w=400, h=300, the signing input is:

FOO123bar/users/1.png?h=300&w=400

and the final signature remains the last query component.

Exact URL shape

The returned URL has this shape:

<scheme>://<domain><normalized-path>[?<sorted-query>][&s=<signature>]

The signature-only case uses ?s=<signature>. No path-parameter section or fragment is introduced. Thus a plain unsigned path produces exactly:

http://my-social-network.imgix.net/users/1.png

Python 3 compatibility

All code in the imgix package must run under Python 3. It must not depend on Python 2-only modules or syntax. In particular, URL parsing, quoting, query serialization, and URL assembly must use Python 3-compatible facilities such as those in urllib.parse, rather than the Python 2-only urlparse module or Python 2-only urllib APIs. Other Python 2-only idioms must likewise be replaced with Python 3-compatible equivalents.

Scope and non-goals

  • The query-signing behavior driven by sign_key is required exactly as described above. No separate path-signature generation semantics are required for SIGNATURE_MODE_PATH; the public requirement for sign_mode is that it is accepted and retained.
  • No domain-sharding selection behavior is required beyond accepting and retaining the supplied shard_strategy.
  • No general UTF-8 encoding behavior for ordinary paths is prescribed. The full encoding of input strings beginning with http is required as described above.
  • The exact literal values of the exported constants are intentionally unspecified.

Task Specification: URL Builder with UTF-8 Path Support

Objective

Provide an imgix package whose UrlBuilder constructs imgix image URLs from one or more domains and an image path. URL generation must preserve the existing query-parameter, signing, scheme-selection, proxy-source, and domain-sharding behavior while correctly accepting Unicode paths and percent-encoding their UTF-8 bytes.

The same public behavior and URL strings are required on Python 2.7 and Python 3.

Public API

The package must be importable as:

import imgix

It must expose the following constants at module level:

imgix.SHARD_STRATEGY_CRC     == "crc"
imgix.SHARD_STRATEGY_CYCLE   == "cycle"
imgix.SIGNATURE_MODE_QUERY   == "query"
imgix.SIGNATURE_MODE_PATH    == "path"

It must expose imgix.UrlBuilder with this constructor-compatible interface:

UrlBuilder(
    domains,
    use_https=False,
    sign_key=None,
    sign_mode=imgix.SIGNATURE_MODE_QUERY,
    shard_strategy=imgix.SHARD_STRATEGY_CRC,
)
  • domains is either a domain string, such as "my-social-network.imgix.net", or an ordered list of domain strings for domain sharding. A single string is treated as a one-domain configuration. Domains are used as URL hosts and are not prefixed with a scheme by the caller.
  • use_https controls the generated scheme. It is the second positional argument and may also be supplied by keyword.
  • sign_key is an optional signing key. It is the third positional argument and may also be supplied by keyword.
  • sign_mode accepts the exported signature-mode constants.
  • shard_strategy accepts the exported sharding-strategy constants.

For compatibility, the constructor must accept sign_mode and shard_strategy by keyword and retain their supplied values on the builder as _sign_mode and _shard_strategy, respectively. In particular, construction with sign_mode=imgix.SIGNATURE_MODE_PATH and shard_strategy=imgix.SHARD_STRATEGY_CYCLE must succeed and preserve both values.

The builder must provide:

create_url(path, **parameters)
  • path is a string or Unicode string and may contain arbitrary Unicode characters.
  • Each keyword in parameters represents a URL query parameter.
  • The return value is the fully assembled URL as a string.

Required Behavior

Scheme selection
  • use_https=False, including when omitted, produces an http URL.
  • use_https=True produces an https URL.
  • Both values must work when passed positionally or by keyword.

For example:

imgix.UrlBuilder("my-social-network.imgix.net").create_url("/users/1.png")
# http://my-social-network.imgix.net/users/1.png

imgix.UrlBuilder("my-social-network.imgix.net", True).create_url("/users/1.png")
# https://my-social-network.imgix.net/users/1.png
Domain selection and sharding

When one domain is supplied, that domain is always used. When an ordered list is supplied:

  • SHARD_STRATEGY_CRC, the default, deterministically selects the domain by computing the unsigned CRC-32 of the original path's bytes and taking the result modulo the number of domains. Unicode paths must be converted to UTF-8 bytes for this calculation; domain selection must not fail merely because a path is non-ASCII. The same path therefore resolves to the same domain.
  • SHARD_STRATEGY_CYCLE selects the first domain for the first generated URL, then advances through the list on each call and wraps back to the first domain.
Path normalization

Every generated URL must have a path beginning with /:

  • If an ordinary input path already starts with /, preserve that leading separator.
  • If it does not, prepend one.

Thus both "users/1.png" and "/users/1.png" produce a URL path of /users/1.png:

http://my-social-network.imgix.net/users/1.png

The normalized encoded path is placed immediately after <scheme>://<domain>.

Ordinary path encoding and Unicode

For an ordinary image path:

  • Preserve / path separators and URL-path-safe ASCII characters, including ASCII letters, digits, and ..
  • Encode each non-ASCII character as UTF-8, then percent-escape each resulting byte.
  • Percent escapes must use uppercase hexadecimal digits.
  • Callers must be able to pass Unicode text directly; they must not need to pre-encode it to bytes.

Required examples for the domain my-social-network.imgix.net with the default scheme are:

builder.create_url(u"/ǝ")
# http://my-social-network.imgix.net/%C7%9D

and:

builder.create_url(u"/üsers/1/米国でのパーティーします。.png")
# http://my-social-network.imgix.net/%C3%BCsers/1/%E7%B1%B3%E5%9B%BD%E3%81%A7%E3%81%AE%E3%83%91%E3%83%BC%E3%83%86%E3%82%A3%E3%83%BC%E3%81%97%E3%81%BE%E3%81%99%E3%80%82.png

In the second example, /, sers, 1, and .png remain literal, while ü, the Japanese characters, and 。 are represented by percent-escaped UTF-8 bytes.

Fully qualified source URLs

A path beginning with the literal prefix http is treated as a fully qualified proxy-source URL. Its source URL must be percent-encoded as one path component:

  • Reserved characters in the source URL, including : and every /, are percent-escaped.
  • URL-unreserved characters such as letters, digits, -, and . remain literal.
  • A leading / is then added so the encoded source sits below the configured imgix domain.
  • Query parameters and signing are applied only after this path conversion. The encoded, leading-slash-prefixed path is the path used in the signing payload.

For example, the source:

http://avatars.com/john-smith.png

becomes this imgix path:

/http%3A%2F%2Favatars.com%2Fjohn-smith.png
Query parameters

create_url must serialize its keyword parameters into the URL query string:

  • Sort parameters lexicographically by key, independently of the order in which they were supplied.
  • Convert keys and values to their string forms and URL-encode them as query components.
  • Emit each pair as key=value, join pairs with &, and prefix a non-empty query with ?.
  • A parameter whose value is falsey is omitted.
  • Do not add a query delimiter when there are no retained parameters and no signature.

For example:

builder.create_url("/users/1.png", w=400, h=300)
# http://my-social-network.imgix.net/users/1.png?h=300&w=400
Query-mode URL signing

When a non-empty sign_key is configured, append an s query parameter containing a lowercase MD5 hexadecimal digest.

Let:

  • encoded_path be the final normalized path, including its leading /;
  • query be the sorted, encoded transformation query without a leading ? and without the signature.

The signature input is:

sign_key + encoded_path                         # when query is empty
sign_key + encoded_path + "?" + query           # when query is non-empty

Compute MD5 over the UTF-8 bytes of that concatenated value. If transformation parameters exist, append &s=<digest> after all of them. Otherwise use ?s=<digest>. The s parameter is therefore always last and is not included in its own digest.

With sign_key="FOO123bar", the required results include:

builder.create_url("/users/1.png")
# http://my-social-network.imgix.net/users/1.png?s=6797c24146142d5b40bde3141fd3600c

builder.create_url("/users/1.png", w=400, h=300)
# http://my-social-network.imgix.net/users/1.png?h=300&w=400&s=1a4e48641614d1109c6a7af51be23d18

builder.create_url("http://avatars.com/john-smith.png")
# http://my-social-network.imgix.net/http%3A%2F%2Favatars.com%2Fjohn-smith.png?s=493a52f008c91416351f8b33d4883135

builder.create_url("http://avatars.com/john-smith.png", w=400, h=300)
# http://my-social-network.imgix.net/http%3A%2F%2Favatars.com%2Fjohn-smith.png?h=300&w=400&s=a201fe1a3caef4944dcb40f6ce99e746

These examples assume:

builder = imgix.UrlBuilder(
    "my-social-network.imgix.net", False, "FOO123bar"
)

SIGNATURE_MODE_QUERY is the supported URL-generation mode and is the default. SIGNATURE_MODE_PATH must remain exported, accepted by the builder, and retained for API compatibility. Path-signature URL generation is unsupported: attempting to generate a URL in that mode must raise an exception rather than silently applying query-mode signing.

Final URL shape

The exact output shape is:

<scheme>://<selected-domain><encoded-path>[?<sorted-query>[&s=<signature>]]

or, for a signed URL without transformation parameters:

<scheme>://<selected-domain><encoded-path>?s=<signature>

No path-parameter section or fragment is added. Query ordering, path normalization, and percent encoding all occur before signing so that the URL text and signing payload agree.

Compatibility

  • The package must support Python 2.7 and Python 3.
  • Direct Unicode path input must work in both environments.
  • Equivalent text input must produce identical percent-encoded URL output in both environments.
  • Non-ASCII paths must also remain usable with the default CRC sharding strategy rather than raising an ASCII encoding error.

  • params: a dictionary of imgix URL parameters (defaults to an empty dict).
  • Returns: a single String.
General Output Format

The returned string is a comma-delimited (,) list of entries. Splitting the returned string on , yields the individual entries. Each entry has the form:

<URL> <descriptor>

where <URL> and <descriptor> are separated by a single space. Splitting an entry on a space and taking index 1 yields the descriptor.

Each <URL> is built exactly as create_url(path, params_for_this_entry) would build it, using the same builder configuration (domain, sign key, include_library_param, etc.). This means when a sign_key is configured, each URL includes a signature parameter s=<md5hex>, computed as the MD5 hex digest of the string formed by concatenating the sign key, the path (including a leading /), and the query string portion of the URL (?... up to but not including the signature). The signature is the last query parameter.

There are two output formats, selected automatically based on params.

Format Selection Rules
  • DPR format is produced when the params dictionary contains a w (width) key, OR when it contains both an h (height) key and an ar (aspect ratio) key.
  • Width-pairs format is produced in all other cases — including when params is empty, when only h is provided, or when only ar is provided.
Width-Pairs Format

Produces exactly 31 entries.

Each entry's URL is built by inserting a w=<value> parameter (in addition to any parameters passed in params), and each entry's descriptor is <value>w (the width value followed by the letter w).

The 31 width values, in order, are exactly:

100, 116, 134, 156, 182, 210, 244, 282, 328, 380, 442, 512,
594, 688, 798, 926, 1074, 1246, 1446, 1678, 1946, 2258, 2618,
3038, 3524, 4088, 4742, 5500, 6380, 7400, 8192

Properties these values must satisfy (all satisfied by the list above):

  • The smallest width is 100 and the largest is 8192; every width lies within the inclusive range [100, 8192].
  • The widths are strictly increasing, and each successive width is less than 1.18× the previous width (i.e. each step increases by strictly less than 18%).

Any parameters supplied in params (e.g. h, ar) are included in each URL in addition to the generated w parameter.

DPR Format

Produces exactly 5 entries.

  • Each entry's URL is built from the same params (no per-entry width is generated). The URL is identical across all 5 entries (aside from being built once per entry with the same params).
  • The descriptors are, in order: 1x, 2x, 3x, 4x, 5x (the device pixel ratio 1 through 5, each followed by the letter x).
