  • instances: a list made up of service instance objects (e.g., StaticServiceInstance) that the supplier is to provide.

A load balancer whose selection of service instances follows a round-robin strategy.

Signature of the constructor:

RoundRobinLoadBalancer(service_instance_list_supplier, service_id)
  • service_instance_list_supplier: a supplier object (such as FixedServiceInstanceListSupplier) from which the list of available service instances can be obtained.
  • service_id: identifies the service served by this load balancer (string).

Method:

choose()

Each call to this method returns a single service instance taken from the supplier's list of instances, with round-robin ordering applied. The supplied instances must be cycled through by consecutive calls, following the order in which they appear in the supplier's list:

  • The instance returned by the first call is the one that comes first in the list.
  • On the second call, it is the second instance that gets returned.
  • Each call after that moves ahead to the next instance in the list.

When the supplier's list contains N instances, N consecutive calls made to choose() return those N instances, one per call, in their original list order.

It must be possible to import RoundRobinLoadBalancer directly from the spring_cloud.commons.client.loadbalancer package.

Summary of the Behavioral Requirements

  • If a FixedServiceInstanceListSupplier is created from a service id together with a list of StaticServiceInstance objects, and a RoundRobinLoadBalancer is then built on top of that supplier, the resulting setup must make it possible for repeated choose() calls to yield the instances in the order in which they were supplied (first instance on the first call, second on the second call, and so on).
  • For StaticServiceInstance objects, equality must be value-based over (uri, service_id, instance_id), so that an instance that choose() returns compares equal to the corresponding instance originally put into the supplier's list.

Requirements for Packaging

All of the modules and packages named above must be importable at exactly the paths given:

  • spring_cloud.commons.client (with StaticServiceInstance exposed)
  • spring_cloud.commons.client.loadbalancer (with RoundRobinLoadBalancer exposed)
  • spring_cloud.commons.client.loadbalancer.supplier (with FixedServiceInstanceListSupplier exposed)

  • lease_duration_in_secs: the duration of the lease, expressed in seconds.

    • A lease that is constructed with lease_duration_in_secs = 0 is not expired immediately after construction.
    • A lease that is constructed with lease_duration_in_secs = 1 (one second):
      • is not expired immediately after construction,
      • is not expired after ~0.7 seconds have passed,
      • is expired after ~1.4 seconds have passed.

The timestamps captured at construction (registration_timestamp, last_update_timestamp), together with those captured by method calls, must be within a small measurement tolerance of the actual moment at which they were taken (on the order of tens of milliseconds). An internal position counter, working together with the load balancer's server data, is what drives selection.

  • The candidates are taken from the load balancer's full server list (get_all_servers); among them, only a server that is alive/reachable is eligible to be returned.

  1. The server on port 200 (the position moves on from starting position 0 to index 1).
  2. The server on port 100 (index 2 is reached, but it is not alive, so the position wraps around to index 0, which is alive).

Create a new module that exposes a DiscoveryEnabledServer class, importable as:

from ribbon.eureka.discovery_enabled_server import DiscoveryEnabledServer
Constructor
DiscoveryEnabledServer(instance_info, use_secure_port=False, use_ip_address=False)
  • instance_info — a Eureka InstanceInfo object (a keyword argument; tests always pass it by keyword).
  • use_secure_port — boolean, with False as the default.
  • use_ip_address — boolean, with False as the default.

Using the flags below, the constructor builds the server's host and port from the supplied instance_info.

Selecting the host
  • If use_ip_address is False (the default), the server's host comes from the instance's hostname.
  • If use_ip_address is True, the server's host comes from the instance's IP address.

For the instance data this task uses:

  • the hostname resolves to "localhost".
  • the IP address resolves to "127.0.0.1".
Selecting the port
  • If use_secure_port is False (the default), the server's port is the instance's non-secure port.
  • If use_secure_port is True, the server's port is the instance's secure port.

The port values are taken from the InstanceInfo object. The defaults used here are defined by two class-level constants on InstanceInfo:

  • InstanceInfo.DEFAULT_PORT — serves as the non-secure port for the instance data in this task.
  • InstanceInfo.DEFAULT_SECURE_PORT — serves as the secure port for the instance data in this task.
Attributes required on the instance

Once constructed, an instance of DiscoveryEnabledServer must expose:

  • server.host — the selected host string (as determined by the host-selection rules).
  • server.port — the selected port (as determined by the port-selection rules).
  • server.meta_info — a MetaInfo instance (from ribbon.loadbalancer.server) that describes the server's metadata.

Behavior Summary (for the standard test instance data)

For an InstanceInfo whose hostname is "localhost", whose IP address is "127.0.0.1", whose non-secure port equals InstanceInfo.DEFAULT_PORT, and whose secure port equals InstanceInfo.DEFAULT_SECURE_PORT:

  • DiscoveryEnabledServer(instance_info=info) → host == "localhost", port == InstanceInfo.DEFAULT_PORT, and meta_info is an instance of MetaInfo.
  • DiscoveryEnabledServer(instance_info=info, use_secure_port=True) → port == InstanceInfo.DEFAULT_SECURE_PORT.
  • DiscoveryEnabledServer(instance_info=info, use_ip_address=True) → host == "127.0.0.1".

Remarks

  • DiscoveryEnabledServer is expected to be (or behave as) a specialization of the existing Server, with the host and port derived from the InstanceInfo.
  • Do not modify the existing InstanceInfo API; rely on its existing hostname, IP address, secure/non-secure port accessors and its DEFAULT_PORT / DEFAULT_SECURE_PORT constants.
