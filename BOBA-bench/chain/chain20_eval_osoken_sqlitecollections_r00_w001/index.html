Task: Implement Mutable Sequence Operations for List

Context

The sqlitecollections package provides a List class that stores its elements in a SQLite table, persisting each element as a pickled blob. The class is imported as:

from sqlitecollections import List

A List is constructed with a keyword argument connection (a sqlite3.Connection) and a keyword argument table_name (a str), e.g. List[str](connection=conn, table_name="items"). The backing table stores one row per element, with a pickled serialized_value column and an integer item_index column that reflects the element's 0-based position (contiguous, starting at 0, in order).

You must implement/extend the following behaviors. Elements are serialized using pickle when written and the resulting stored order/indices must always stay contiguous starting at 0.

1. __getitem__ with a slice: zero step

When __getitem__ is called with a slice whose step is 0, raise ValueError with the message slice step cannot be zero.

Slices with a non-zero step (including negative steps and out-of-range start/stop values) must continue to behave like standard Python list slicing, returning a new List-like object whose backing table contains the sliced elements re-indexed contiguously from 0.

2. __setitem__

Integer index: sut[i] = value
  • A valid index (supporting negative indexing) replaces the element at that position with the pickled value; all other elements and their indices are unchanged.
  • An index outside the valid range (in either direction) raises IndexError with the message list assignment index out of range, leaving the stored data unchanged.
Slice index: sut[s] = iterable

Assigning an iterable to a slice must reproduce exactly the semantics of Python's built-in list.__setitem__ for slices, for all combinations of start, stop, step (including None, negative, zero, and out-of-range values) and iterables of varying lengths:

  • For an extended slice (step is not None and not 1), if the number of assigned values does not match the number of selected positions, raise ValueError matching Python's message, e.g. attempt to assign sequence of size N to extended slice of size M.
  • For an extended slice with step == 0, raise ValueError with the message slice step cannot be zero.
  • Otherwise, the selected positions are removed and the iterable's values inserted in their place (for a simple contiguous slice), or replaced element-by-element (for a valid extended slice), matching built-in list behavior.
  • The assigned value is an arbitrary iterable (it may be a one-shot iterator) and must be consumed correctly.

After the operation, the stored elements (pickled) and their item_index values must match exactly what a native Python list would contain after the same slice assignment, re-indexed contiguously from 0.

3. __delitem__

Integer index: del sut[i]
  • A valid index (supporting negative indexing) removes the element at that position; remaining elements are re-indexed contiguously from 0.
Slice index: del sut[s]

Deleting a slice must reproduce exactly the semantics of Python's built-in list.__delitem__ for slices, for all combinations of start, stop, step (including None, negative, zero, and out-of-range values):

  • For a slice with step == 0, raise ValueError with the message slice step cannot be zero.
  • Otherwise remove exactly the elements a native Python list would remove for the same slice.

After the operation, the stored elements (pickled) and their item_index values must match exactly what a native Python list would contain after the same deletion, re-indexed contiguously from 0.

4. insert

Provide a method:

def insert(self, index: int, value) -> None

It must behave exactly like Python's built-in list.insert:

  • Insert the pickled value so it ends up at position index, shifting subsequent elements one position later.
  • Negative indices count from the end.
  • Indices beyond the end (e.g. very large positive values) clamp to appending at the end.
  • Negative indices beyond the beginning (e.g. very large negative values) clamp to inserting at the front (position 0).

After insertion, all elements' item_index values must remain contiguous starting at 0, in the correct order.

General Requirements

  • All values written to the backing store are pickle-serialized.
  • After every mutating operation, the backing table must contain exactly the resulting elements with item_index values 0, 1, 2, … in order, with no gaps.
  • No auxiliary/temporary tables may remain after operations complete.

Public API

Method: append
def append(self, value: T) -> None

Appends value to the end of the list. The value is serialized with pickle.dumps and stored with an index equal to the current length of the list (i.e., the next available contiguous index starting from 0 for an empty list).

  • Appending to an empty list stores the value at index 0.
  • Each subsequent append stores the value at the next consecutive index.

Error condition:

Notes

  • After any mutating operation, the stored index column must remain a contiguous sequence starting at 0, matching the list's element order.

  • All items from values, in iteration order.

When a collection is constructed with a table_name that already has stored records (for example, from a previous instance built against the same connection and table name), and data is provided, the resulting backing table must contain only the newly supplied initial data. You are working on sqlitecollections, a Python library that provides dict, list, and set-like collections backed by SQLite. Values (and dictionary keys) are serialized to bytes before being stored in the database and deserialized when read back.

You must introduce an explicit, centralized default serializer and deserializer on the base collection class, and make it the default (de)serialization mechanism for all collections. The serialized byte representation produced by these defaults must be a specific, deterministic format (see below).

Public API to Implement

In the module sqlitecollections.base, the base class SqliteCollectionBase must expose two static methods (callable both on the class and via the class object without instantiating):

class SqliteCollectionBase(...):

    def _default_serializer(value) -> bytes: ...

    def _default_deserializer(data: bytes) -> Any: ...

These must be reachable as:

  • sqlitecollections.base.SqliteCollectionBase._default_serializer
  • sqlitecollections.base.SqliteCollectionBase._default_deserializer

The module sqlitecollections.base must continue to expose the names dumps and loads (the pickle serialization functions), such that sqlitecollections.base.dumps and sqlitecollections.base.loads are patchable/importable symbols in that module namespace.

Required Behavior

_default_serializer(value)

Serializes an arbitrary Python object to bytes using pickle, explicitly specifying pickle protocol version 3.

  • It must delegate to the module-level dumps symbol (sqlitecollections.base.dumps), calling it with the object as the single positional argument and the protocol passed as a keyword argument protocol=3. It must return exactly what dumps returns.
  • Concretely, _default_serializer("123") must return the bytes: b'\x80\x03X\x03\x00\x00\x00123q\x00.'
  • _default_serializer("x") calling behavior: dumps is invoked exactly once as dumps("x", protocol=3).
_default_deserializer(data)

Deserializes bytes produced by _default_serializer back into the original Python object (pickle load).

  • _default_deserializer(b'\x80\x03X\x03\x00\x00\x00123q\x00.') must return "123".
Default (de)serialization used by all collections

When a collection (Dict, List, Set, or a subclass of SqliteCollectionBase) is constructed without an explicitly supplied serializer/deserializer:

  • Its serializer attribute must be SqliteCollectionBase._default_serializer.
  • Its deserializer attribute must be SqliteCollectionBase._default_deserializer.

Specifically, for a freshly constructed instance with no serializer/deserializer arguments:

  • instance.serializer is SqliteCollectionBase._default_serializer
  • instance.deserializer is SqliteCollectionBase._default_deserializer

(The remaining initialization behavior — creating/connecting to the database, persist, table_name, etc. — is unchanged.)

Consequence: on-disk serialized format

Because the default serializer now uses pickle protocol 3, every value stored by any collection using the defaults must match the bytes that SqliteCollectionBase._default_serializer produces for that value. In particular:

  • List stores each element's serialized bytes in the serialized_value column (with its item_index); the stored bytes for element x must equal _default_serializer(x).
  • Dict stores serialized key and serialized value in the serialized_key / serialized_value columns (with item_order); the stored bytes must equal _default_serializer(key) and _default_serializer(value) respectively.
  • Set stores each element's serialized bytes in the serialized_value column; the stored bytes must equal _default_serializer(element).

For reference, protocol‑3 pickle produces byte sequences like:

  • "a" → 800358010000006171002e
  • "z" → 80035801000000 7a 71002e
  • 0 (int) → 80034b002e
  • None → 80034e2e

These are the values written to and read from the database for all collection operations (initialization with initial data, item assignment, insertion, appending, extending, popping, sorting, set operations, etc.). All such operations must round-trip correctly through the new default (de)serializer.

Notes / Constraints

  • The change is purely about the default serialization mechanism and its byte format. Do not alter the public method signatures or semantics of the collection operations themselves beyond what is needed to route (de)serialization through the new defaults.
  • Explicitly-supplied serializer/deserializer arguments must still be honored (only the default changes).
  • list.append must persist the change so that the appended element is immediately reflected in the database.
