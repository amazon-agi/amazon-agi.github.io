Task Specification: Parallel Composition Codec

Objective

Implement a new codec constructor function named parallel in the craystack core module. This function combines multiple independent codecs so they operate on disjoint views (slices) of a single message head.

API Surface

The function must be accessible as craystack.parallel (i.e., importable from the top-level craystack package, conventionally aliased as cs).

Signature
parallel(codecs, view_funs)
  • codecs: a list of codec objects. Each codec is a (push, pop) pair following the existing craystack codec convention.
  • view_funs: a list of the same length as codecs. Each element is a function that, given a message head, returns the sub-view of that head which the corresponding codec should operate on.

The two lists are aligned positionally: codecs[i] operates on the view produced by view_funs[i].

Codec Convention (context)

A codec is a pair (push, pop):

  • push(message, data) encodes data into message, returning the updated message.
  • pop(message) decodes from message, returning a (message, data) pair.

A message's "head" is the structured array-like object codecs read from and write to. A view_fun extracts a portion of the head (e.g., via slicing) so that a given codec only sees and modifies its assigned region.

Required Behavior

parallel(codecs, view_funs) must return a single codec (push, pop) that:

  1. Applies each constituent codec to its own view of the head. When pushing or popping, codecs[i] must interact only with the portion of the head selected by view_funs[i]. The views are disjoint slices that together partition the head.

  2. Operates on lists of data. The combined codec encodes/decodes a list of data items, one per constituent codec, in positional correspondence: item i is handled by codecs[i] on view i.

  3. Is a correct codec (round-trip property). For any valid list of data items, pushing the data and then popping must recover:

    • the original message state, and
    • the exact original list of data items (element-wise equal).

    Symmetrically, the resulting pop followed by push must be consistent, as required for any well-formed craystack codec.

Concrete Usage Scenario (for grounding)

The combined codec must work when:

  • Each constituent codec is a uniform-distribution codec over a fixed precision (encoding integers uniformly in the range [0, 2**precision)).
  • Each view_fun selects a contiguous slice of a flat head of total size equal to the sum of the individual segment sizes.
  • The data is a list where item i is an array of unsigned 64-bit integers of length equal to segment i's size, with values in [0, 2**precision_i).

Under these conditions, encoding the full list of arrays into an initialized message and then decoding must return the original message and the original list of arrays unchanged.

Notes

  • Do not impose constraints beyond those above; the number of codecs, the segment sizes, and the precisions are arbitrary and provided by the caller.
  • The function only composes the given codecs and views; it does not itself define distributions or precisions.

Background Concepts

A message is a pair (head, tail):

  • head is a NumPy array of dtype uint64; its shape is called the head shape.
  • tail is an immutable linked-list-like stack structure. It is falsy when empty; otherwise it can be unpacked as element, rest = tail.

A message is created with vrans.x_init(shape), producing a message whose head has the given shape.

A codec is a pair (append, pop):

  • append(message, symbol) -> message encodes symbol onto the message.
  • pop(message) -> (message, symbol) decodes a symbol from the message.

Message and codec model

A message is the abstract state manipulated by ANS-style codecs. A message has a head and a tail and can be created empty, populated by pushing data, and consumed by popping data.

A codec provides a pair of functions:

  • push(message, data) encodes data and returns the resulting message.
  • pop(message) decodes one item and returns (new_message, data).

Codec values must be usable as (push, pop) pairs, including by unpacking them. Codec objects exposed by this package also support the corresponding .push and .pop attributes.

For every codec described below, the fundamental round-trip invariant is:
