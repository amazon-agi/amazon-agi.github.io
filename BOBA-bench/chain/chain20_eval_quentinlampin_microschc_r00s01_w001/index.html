Overview

Simplify packet parsing so that parsing is performed by one parse call. No separate matching step is exposed, and packet-level parsing does not take a direction argument. In addition, a SCHC Context must identify the protocol-stack parser associated with that context and preserve that identifier through JSON serialization and deserialization.

1. Remove the parser match API

Parser objects must no longer expose a match method. This applies to:

  • HeaderParser and PacketParser from microschc.parser / microschc.parser.parser;
  • CoAPParser from microschc.parser.protocol.coap;
  • IPv4Parser from microschc.parser.protocol.ipv4;
  • IPv6Parser from microschc.parser.protocol.ipv6; and
  • UDPParser from microschc.parser.protocol.udp.

A match method must not remain available through inheritance. Parsing valid input must not require a preliminary validation or matching call, and no replacement matching entry point is required.

2. Protocol parser API

Each protocol parser must expose the following public method:

def parse(self, buffer: Buffer) -> HeaderDescriptor

The method must be callable with the single keyword argument buffer, whose value is a microschc.binary.buffer.Buffer. It must return a HeaderDescriptor for the parsed protocol header.

For valid buffers, existing parsing results must remain unchanged, including:

  • the header identifier and parsed header length;
  • the number and order of fields; and
  • every field's identifier, Buffer value and bit length, and position.

No protocol parser's public parse method may require a direction argument.

3. Packet parser API

PacketParser must expose:

def parse(self, buffer: Buffer) -> PacketDescriptor

It must be callable as:

packet_descriptor = packet_parser.parse(buffer=packet_buffer)

buffer is the only parse argument after self; callers must neither provide a direction nor perform a separate match operation. This change concerns the parser call chain only and does not otherwise remove the existing direction-related data types or APIs used elsewhere in the package.

The returned PacketDescriptor must preserve the existing packet parsing behavior:

  • Protocol headers are parsed in the order configured for the packet parser.
  • fields is the flattened concatenation of the protocol headers' fields, in protocol and field order.
  • Each flattened field preserves the id, value, and position produced by its protocol parser.
  • Field values remain Buffer instances with the same contents and bit lengths as before.
  • payload is the unconsumed remainder after all configured protocol headers have been parsed.
  • length remains the bit length of the original packet buffer.
  • The returned object remains a PacketDescriptor.

The parser must successfully handle complete IPv6/UDP/CoAP packets, including both of these edge cases without raising an exception:

  1. a CoAP message containing zero options; and
  2. a CoAP message containing options but no payload and therefore ending without a payload marker or payload bytes.

An absent payload is represented consistently with the existing Buffer-based packet output.

The protocol-stack registry API remains available from microschc.parser.protocol.registry. In particular, the existing Stack members and the factory call must continue to work, including:

The factory must continue to return a PacketParser configured with the protocol parsers for the requested stack. Existing registered stacks, including IPv6/UDP/CoAP and IPv4/UDP/CoAP, must retain their identifiers and parser ordering.

  • be exposed unchanged as the public context.parser_id attribute.

    id="example",
    description="Example context",
    interface_id="eth0",
    parser_id=Stack.IPV6_UDP_COAP,
    ruleset=[],

All existing Context attributes and ruleset behavior remain available. Adding parser_id must not alter the representation or round-trip behavior of the rules in ruleset.

Overview

The return-type change must not alter which rules match. Buffer concatenation must also preserve the destination bit orientation when the destination is empty, so compressed and reconstructed packets have the correct bit placement.

Affected Public API

The affected interfaces are:

  • Ruler(rules_descriptors=[...])
  • Ruler.match_packet_descriptor(self, packet_descriptor)
  • Buffer(content=..., length=..., padding=...) and Buffer.__add__ (also used by +=)
  • compress(packet_descriptor=..., rule_descriptor=...) -> Buffer
  • decompress(schc_packet=..., rule_descriptor=...) -> Buffer

Relevant existing types include RuleDescriptor, RuleFieldDescriptor, FieldDescriptor, PacketDescriptor, MatchMapping, Padding, MatchingOperator, and CompressionDecompressionAction.

Buffer Bit-Sequence Semantics

A Buffer represents exactly length significant bits. Bits in content outside that logical sequence are padding and are not part of the value:

  • With Padding.LEFT, unused bits precede the significant bits. A two-bit value 11 can therefore be represented by content=b'\x03'.
  • With Padding.RIGHT, unused bits follow the significant bits. The same two-bit value is represented by content=b'\xc0'.

Operations that combine buffers must combine their logical significant-bit sequences, not their raw padded byte strings.

Concatenation

For left + right:

  1. The result's logical bits are all significant bits of left, followed immediately by all significant bits of right.
  2. The result length is left.length + right.length.
  3. No operand padding and no byte-alignment gap may be inserted between the two sequences.
  4. If the operands use different padding orientations, their significant bits must be realigned as needed.
  5. The result uses the left operand's padding mode.
  6. Neither operand is modified by concatenation.

The left-padding-mode rule also applies when left.length == 0. An empty left operand must not simply pass through the right operand with its original padding mode. For example:

left = Buffer(content=b'', length=0, padding=Padding.RIGHT)
right = Buffer(content=b'\x03', length=2, padding=Padding.LEFT)
combined = left + right

combined must have length == 2, padding == Padding.RIGHT, content == b'\xc0', and logical bits 11. This behavior is required for accumulators initialized as empty right-padded buffers.

Ruler.match_packet_descriptor

Return Value

Advancing the iterator yields matching RuleDescriptor objects. Matching rules must be yielded in the order in which they were supplied through rules_descriptors. Thus, code that previously used the directly returned first match must now use:

If no rule matches, preserve the existing RuleDescriptorMatchError behavior when the iterator is advanced. Existing higher-level operations that require one rule must consume the first item from the returned iterator so that their externally visible behavior remains compatible.

  • Paired field IDs must match.
  • Existing matching-operator behavior remains unchanged: IGNORE accepts the field, EQUAL compares the complete buffer value including logical length, MSB compares the target prefix, and MATCH_MAPPING requires the field value to occur in the mapping.

Compression

compress(packet_descriptor=..., rule_descriptor=...) must return a Buffer containing the SCHC packet as one contiguous bit sequence.

Logical Output Order

The output consists, in this exact order, of:

  1. Exactly rule_descriptor.id.length significant rule-ID bits.
  2. For each corresponding packet field and rule field, in descriptor order: any required variable-length prefix followed immediately by that field's compression residue.
  3. packet_descriptor.payload immediately after the final field residue.

Existing compression-action semantics are preserved:

  • NOT_SENT contributes zero residue bits.
  • LSB contributes the least-significant bits not covered by its target prefix.
  • MAPPING_SENT contributes the mapped index.
  • VALUE_SENT contributes the packet field's complete logical value.

For an LSB or VALUE_SENT residue whose rule field has length == 0, the residue's bit length is encoded immediately before that residue using the existing format:

  • lengths below 15: the length in 4 bits;
  • lengths from 15 through 254: 1111 followed by the length in 8 bits, for 12 bits total;
  • lengths from 255 through 65535: 1111, then 11111111, then the length in 16 bits, for 28 bits total.

Lengths in this format are bit lengths.

Packing and Return Buffer

The returned buffer must:

  • use Padding.RIGHT;
  • have a logical length equal to the sum of the rule-ID, length-prefix, residue, and payload bit lengths actually emitted;
  • place the first logical bit in the most-significant bit of the first output byte;
  • place every subsequent component immediately after the previous component, even when either component is not byte-aligned;
  • contain only final right-padding after the last logical bit, with no padding between components;
  • use compact byte storage of ceil(length / 8) bytes, with any unused low-order bits of the final byte set to zero.

Input fragments may be left-padded or right-padded. Their padding orientation must not leak into the wire format; only their significant bits are emitted. For example, a two-bit rule ID with logical value 11 occupies the two most-significant bits of the first SCHC byte. If it were the only output component, the result would be Buffer(content=b'\xc0', length=2, padding=Padding.RIGHT), not a buffer beginning with raw byte b'\x03'.

Decompression

  • Consume exactly rule_descriptor.id.length bits from the beginning as the rule ID; those bits are not copied to the reconstructed packet.
  • Reconstruct rule fields in descriptor order and append each reconstructed field directly after the previous field at bit granularity.
  • Preserve the existing decompression-action semantics:
    • NOT_SENT reconstructs the field from its target value.
    • LSB reconstructs the field from the target prefix followed by the consumed least-significant residue bits.

    • Fixed-length VALUE_SENT consumes the declared number of residue bits.

  • Preserve existing compression/decompression action behavior and the existing variable-length encoding scheme; the required change is exact cross-buffer bit placement and packing.
  • Preserve existing Buffer behavior outside the concatenation contract above, including its public padding, slicing, equality, iteration, and serialization behavior.
  • Do not introduce per-field or per-residue byte alignment.
  • No new compression actions, matching operators, parser behavior, or rule-selection policy are required.
  • These requirements specify observable values, lengths, padding modes, ordering, and iterator behavior without prescribing a particular internal algorithm.

Task Specification: Compute Functions for Compression Field Descriptors

Overview

You must ensure that a SCHC-style compression rule can be applied to a parsed packet where certain rule field descriptors describe values that are computed from the packet contents rather than matched or sent literally. This task centers on making the compressor correctly handle a rule descriptor built for a CoAP packet.

Context

The codebase models compression rules using rule field descriptors. The relevant public types (already existing, used as given) include:

  • RuleFieldDescriptor(id, length, position, direction, target_value, matching_operator, compression_decompression_action)
  • RuleDescriptor(id, field_descriptors)
  • Buffer(content, length) — a bit-oriented buffer whose content is bytes and length is a length in bits.
  • Enumerations: CoAPFields, ParserDefinitions, DirectionIndicator, MO (matching operators), CDA (compression/decompression actions).

The compressor consumes a RuleDescriptor (a list of RuleFieldDescriptors) plus a parsed packet, and produces the compressed residue.

Required Behavior

1. Field descriptor target-value lengths must be self-consistent

When a RuleFieldDescriptor carries a target_value Buffer intended to be matched against or substituted for a field of a declared bit length, the Buffer.length (in bits) of that target value must equal the field's declared length.

Concretely, for a CoAP OPTION_DELTA field declared with length=4 and target content b'\x0c', the target value Buffer must have length=4 (not 0). The compressor must operate correctly given target values whose buffer bit-length matches the declared field length.

2. Rule descriptors need not contain a trailing generic payload descriptor

A rule descriptor for a CoAP packet may terminate after the last CoAP-specific field descriptor (e.g. after the PAYLOAD_MARKER field). There must be no requirement for a final RuleFieldDescriptor with id=ParserDefinitions.PAYLOAD. The compressor must correctly process a rule descriptor whose field descriptors end at the last protocol field, treating any remaining packet content as the payload without needing an explicit payload field descriptor in the rule.

3. Compression of a CoAP packet with the given rule must succeed and produce the correct residue

The compressor must correctly apply a rule whose field descriptors include:

  • Fields matched and elided via MO.EQUAL / CDA.NOT_SENT (their target value buffers must match the parsed field values, using bit-lengths consistent with declared field lengths).
  • Fields sent as residue via MO.IGNORE / CDA.VALUE_SENT.
  • Fields of declared length=0 whose value is variable and carried in the residue.

Given such a rule and a matching parsed CoAP packet, the compressor must produce the expected compressed output: the rule id followed by the residue built from the value-sent fields and the trailing payload bytes.

Deliverables

Implement/fix the compression path so that:

  • Target-value buffers are interpreted using their declared bit lengths, and a field descriptor with a declared length of N bits is matched against exactly N bits of the corresponding parsed field.
  • The compressor does not depend on the presence of a trailing ParserDefinitions.PAYLOAD field descriptor; remaining packet bytes after the described fields are handled as payload.
  • Chunk padding when assembling residue bytes uses integer division that rounds up to whole bytes (a residue of B bits occupies ceil(B/8) bytes).

Notes

The public API names and signatures listed above must remain importable and callable exactly as given; the compressor entry point must accept a RuleDescriptor and a parsed packet and return the compressed Buffer.

Required Behavior

Round-trip correctness with COMPUTE fields

Given an IPv6/UDP/CoAP packet:

  1. Parse the raw packet bytes into a PacketDescriptor via a parser obtained from factory(stack_id=Stack.IPV6_UDP_COAP).
  2. Compress the PacketDescriptor with a RuleDescriptor using compress(...).
  3. Decompress the resulting SCHC packet with the same RuleDescriptor using decompress(...).

The decompressed result must be a Buffer whose content and length are byte-for-byte identical to the original packet buffer (a Buffer built from the original raw bytes with length = 8 * len(raw_bytes)).

COMPUTE action semantics

For any rule field whose compression_decompression_action is CDA.COMPUTE:

  • On compression: the field value carries no bits into the SCHC packet (it is neither stored via VALUE_SENT nor otherwise transmitted); it is treated as derivable at decompression.
  • On decompression: the field value must be recomputed from the reconstructed packet rather than read from the SCHC residue. The following fields must be correctly recomputed so the reconstructed bytes match the original:
    • IPv6 payload length (IPv6Fields.PAYLOAD_LENGTH, 16 bits): the length in bytes of everything following the IPv6 header (i.e., the UDP header plus its payload).
    • UDP length (UDPFields.LENGTH, 16 bits): the length in bytes of the UDP header plus the UDP payload.
    • UDP checksum (UDPFields.CHECKSUM, 16 bits): the standard UDP checksum computed over the IPv6 pseudo-header, the UDP header (with checksum field zeroed during computation), and the UDP payload.

The recomputed values must be inserted at the correct bit positions so the fully reconstructed packet equals the original.

Other actions (context)

The rule under test also exercises, and these must continue to work so the round-trip succeeds:

  • CDA.NOT_SENT with MO.EQUAL: field omitted from residue; restored from the rule's target_value.
  • CDA.VALUE_SENT with MO.IGNORE: field value carried verbatim in the SCHC residue and restored from it.
  • CDA.MAPPING_SENT with MO.MATCH_MAPPING: index carried in the residue and restored via the mapping.

Rules may contain repeated field ids (e.g., multiple CoAP option delta/length/value triplets), each matched positionally in order.

Acceptance Criterion

For an IPv6/UDP/CoAP packet parsed via the IPV6_UDP_COAP stack and compressed then decompressed with a rule where the IPv6 payload length, UDP length, and UDP checksum fields use the COMPUTE action, the decompressed Buffer must equal the original packet Buffer exactly (same content bytes, same bit length).

The following classes must exist and be importable (module paths as currently used in the codebase):

  • PacketDescriptor
  • FieldDescriptor
  • Buffer

Buffer

Constructed as Buffer(content=<bytes>, length=<int>), and optionally with a padding attribute. A Buffer supports equality comparison by value.

Its JSON object representation has these keys:

  • "content": the hex-string encoding of the bytes (lowercase, no separators, each byte as two hex digits).
  • "length": the integer length in bits.
  • "padding": either "left" or "right".
FieldDescriptor

Constructed as FieldDescriptor(id=<str>, value=<Buffer>, position=<int>). Supports equality by value.

Its JSON object representation has keys "id", "value" (a Buffer object), and "position".

PacketDescriptor

Constructed as:

PacketDescriptor(direction=<DirectionIndicator>, fields=<list[FieldDescriptor]>, payload=<Buffer>)

Note: length is no longer a constructor parameter. It must not be required or accepted as an input.

Attributes accessible after construction:

  • direction
  • fields (list of FieldDescriptor)
  • payload (a Buffer)
  • length (an int, computed — see below)

Required Behavior

Computed raw content

The PacketDescriptor must compute a raw buffer by concatenating, in order:

  1. The content bytes of each field's value buffer, in the order the fields appear in the fields list.
  2. The content bytes of the payload buffer.

The raw buffer's:

  • content is the concatenation of the above byte sequences.
  • length (in bits) equals the sum of the length values of all field value buffers plus the payload buffer's length.
  • padding is "right".

Example: given field values with contents 0x0001 (16 bits) and 0x0002 (16 bits), and a payload of 0x000102 (24 bits), the raw content is bytes 00 01 00 02 00 01 02 with length 56 bits.

length attribute

The length attribute of a PacketDescriptor is the total bit-length of the raw buffer (sum of all field value lengths plus payload length). In the example above, length == 56.

JSON serialization: PacketDescriptor.json()

Returns a JSON string with keys emitted in exactly this order:

  1. "direction" — the direction value as a string (e.g. "Up" for DirectionIndicator.UP).
  2. "fields" — a JSON array of field descriptor objects.
  3. "payload" — the payload buffer object.
  4. "raw" — the computed raw buffer object (content, length, padding "right").
  5. "length" — the integer total bit-length (equal to the raw buffer's length).

The output must be compact (a single space after each : and , separator, matching standard JSON formatting).

Example output for the sample above:

{"direction": "Up", "fields": [{"id": "fd1", "value": {"content": "0001", "length": 16, "padding": "left"}, "position": 0}, {"id": "fd2", "value": {"content": "0002", "length": 16, "padding": "left"}, "position": 0}], "payload": {"content": "000102", "length": 24, "padding": "left"}, "raw": {"content": "00010002000102", "length": 56, "padding": "right"}, "length": 56}
JSON deserialization: PacketDescriptor.from_json(json_str=<str>)

A class method that accepts a JSON string in the format produced by json() above (including the "raw" and "length" keys) and returns a PacketDescriptor instance.

After deserialization:

  • direction reflects the serialized direction (e.g. "Up" → DirectionIndicator.UP).
  • fields reconstructs the list of FieldDescriptor objects with their id, value buffer (content decoded from hex, length in bits), and position.
  • payload reconstructs the payload Buffer.
  • length equals the total bit-length derived from fields and payload (matching the length/raw computation described above).

The "raw" key present in the input must be accepted without error, but the resulting length and raw content must be consistent with the field/payload data (i.e. the same computed value described above).

Constraints

  • The length value is always the computed total bit-length; it cannot be set independently to an arbitrary number.
