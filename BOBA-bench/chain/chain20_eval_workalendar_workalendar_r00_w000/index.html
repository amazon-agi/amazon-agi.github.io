01 You must implement a Calendar base class in the workalendar.core module that provides date/calendar utilities. 533 words · source specification

Overview

You must implement a Calendar base class in the workalendar.core module that provides date/calendar utilities. The class is designed to be subclassed: subclasses define their own holidays and weekend days, and the base class provides workday logic on top of those definitions.

Public API

Module

All code lives in workalendar/core.py, importable as workalendar.core.

Class: Calendar

The base class must support the following methods, which subclasses may override:

holidays(self, year=None)

Returns the set of holiday dates for the given year. In the base class this may return an empty collection; subclasses override it to return a set of datetime.date objects. When called by other methods, it will be passed a specific year (integer).

get_weekend_days(self)

Returns the collection of weekday numbers considered weekend days (using Python's date.weekday() convention where Monday is 0 and Sunday is 6). Subclasses override this; it may return an empty list to indicate no weekend days.

is_workday(self, day, extra_workdays=None, extra_holidays=None)

Determines whether a given datetime.date is a working day.

A day is not a workday if:

  • Its weekday number is among the values returned by get_weekend_days(), OR
  • It appears in the set of holidays returned by holidays() for that day's year.

The two optional parameters override the default determination:

  • extra_workdays: an iterable of datetime.date objects. If the given day is contained in this collection, it must be treated as a workday, even if it would otherwise be a holiday or weekend day.
  • extra_holidays: an iterable of datetime.date objects. If the given day is contained in this collection, it must be treated as not a workday, even if it would otherwise be a normal working day.

extra_workdays takes precedence when deciding a day is a workday: a day listed in extra_workdays is a workday regardless of holidays/weekends. A day listed in extra_holidays is not a workday.

Returns a boolean-compatible value.

add_workdays(self, day, delta)

Given a starting datetime.date (day) and a positive integer count (delta), returns the datetime.date reached by advancing delta working days forward from day.

Counting begins the day after the start date. Each subsequent calendar day that qualifies as a workday (per is_workday, using no extra overrides) increments the count by one; non-workdays are skipped. The result is the date on which the delta-th workday is reached.

For example, in a calendar with no weekend days and only two holidays in a year (December 25 and January 1): starting from December 20 and advancing 20 workdays lands on January 11 of the following year (December 25 and January 1 are skipped, so the plain 20-day arithmetic is shifted by 2 days).

get_last_weekday_in_month(year, month, weekday)

(Already assumed present / must be available.) A method returning the datetime.date of the last occurrence of the given weekday in the specified month and year. For instance, the last Thursday of January 2013 is January 31, 2013.

Constants

The module must expose weekday constants usable as date.weekday() values, including at least THU (Thursday = 3).

Notes

  • All date objects are datetime.date instances.
  • holidays() and get_weekend_days() are the extension points: a subclass supplies fixed definitions by overriding these, and all workday logic derives from them.
