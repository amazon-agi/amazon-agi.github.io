Objective

Create an icon function that produces a Fomantic/Semantic UI icon HTML element: an empty <i> element with the appropriate icon CSS classes. The result must compose with Shiny/htmltools UI objects and with page_semantic(...).

Public API

The function must be publicly importable as:

from shiny_semantic.elements import icon
Signature
def icon(name, modifiers=""):
    ...
  • name (str, required): The icon name, such as "users", "home", or "asterisk".
  • modifiers (str, optional): Additional space-separated CSS modifier classes, such as "loading", "large", or "bordered teal". It defaults to the empty string.

Icon Rendering Requirements

icon(...) must return a Shiny/htmltools-compatible HTML tag object representing an <i> element.

The element's class value must be exactly the modifiers value, one literal space, the name value, one literal space, and the literal word icon, in that order:

f"{modifiers} {name} icon"

Consequently, the rendered opening tags for the required examples are:

Call Rendered opening tag
icon("users") <i class=" users icon">
icon("asterisk", "loading") <i class="loading asterisk icon">
icon("home", "large") <i class="large home icon">
icon("home", "bordered teal") <i class="bordered teal home icon">

The class order and spacing are part of the public output contract. In particular:

  • If modifiers is omitted, its empty value is still followed by the separator space, so the class value begins with a leading space (for example, " users icon").
  • A multi-class modifier string remains before the icon name and preserves its internal spaces.
  • The <i> element has no children or text content.

page_semantic Integration

The page helper remains publicly importable as:

from shiny_semantic import page_semantic

An object returned by icon(...) must be accepted as a child of page_semantic(...), and serialization of the resulting Shiny page must contain the corresponding <i> markup.

Every page produced by page_semantic(...), including a page created with no child content, must include references to all of the following front-end dependencies in its rendered HTML:

  • The Fomantic UI stylesheet named fomantic.min.css.
  • The Fomantic UI script named fomantic.min.js.
  • The Shiny Semantic bindings script named shiny-semantic-bindings.js.

The rendered page HTML must therefore contain each of those exact filename literals. Callers must not need to add these dependencies separately in order to use an icon within a semantic page.

Compatibility Requirements

  • The return value of icon(...) must participate in normal Shiny/htmltools tag composition rather than being merely a raw, non-composable value.
  • Existing use of page_semantic(...) as the semantic page wrapper must continue to work while supplying the required stylesheet and scripts.

  • value (bool, default False): whether the checkbox is pre-checked.
  • type (str or None, default None): a modifier that adjusts the input type and CSS classes.
Return Value

The function must return an htmltools-compatible tag object (such that it can be placed inside htmltools.TagList and rendered via get_html_string()).

Rendered HTML Structure

The component renders as an outer <div> containing an <input> and a <label>:

<div id="{id}" class="{classes}">
  <input id="{id}" type="{input_type}" name="{id}"{checked_attr}/>
  <label for="{id}">{label}</label>
</div>

Details:

  • The outer <div> has id equal to the id argument, and a class attribute (see class rules below).
  • The <input> has id equal to id, a type attribute (see type rules below), and name equal to id.
  • The <label> has for equal to id and contains the label text as its content.
Class Rules for the Outer <div>

The class string always begins with ui and always ends with checkbox. Additional class tokens are inserted between them based on value and type:

  • Base (no value, no type): ui checkbox
  • When value is True: insert the token checked immediately after ui.
  • When type is provided: insert the type value as a token before checkbox.

The token ordering, when multiple apply, is: ui, then checked (if checked), then {type} (if provided), then checkbox.

Examples:

  • value=True, type="radio" → ui checked radio checkbox
  • type="slider" → ui slider checkbox
  • type="toggle" → ui toggle checkbox
Type Rules for the <input>
  • If type is None, the input type attribute is checkbox.
  • If type is "radio", the input type attribute is radio.
  • If type is "slider" or "toggle", the input type attribute remains checkbox (the type value only affects the outer <div> class, not the input's type attribute).
Checked Attribute Rules for the <input>
  • When value is True, the <input> includes a checked attribute rendered as checked="".
  • When value is False, no checked attribute is present on the <input>.

from shiny_semantic.checkbox import checkbox_group

  • type (str, optional): Input type, either "checkbox" or "radio". The default is "checkbox".

Return value

Return an HTML element object with a get_html_string() method. Calling that method must produce the group's rendered markup as a string.

Required HTML structure

For example:

element = checkbox_group(
    id="group",
    label="group",
    choices=["one", "two"],
    selected="one",
)
html = element.get_html_string()

The rendered string must contain all of the following exact fragments.

Group container
<div id="group" class="grouped fields ss-checkbox-group">

The container's id is the supplied group id, and its class attribute is exactly grouped fields ss-checkbox-group.

Choice wrapper

Each choice must have its own wrapper. For the selected choice "one", the fragment is:

<div id="group__one" class="ui checked checkbox" data-shiny-value="one">

For every choice:

  • Form its option id as <group id>__<choice>, using exactly two underscores as the separator.
  • Use that id on the choice wrapper.
  • Set data-shiny-value to the choice value.
  • A selected option's wrapper has the checked class token, yielding class="ui checked checkbox" in this case. An unselected option must use the corresponding unchecked form and must not have the checked class token.
Choice input

The selected choice above must contain this input fragment:

<input id="group__one" type="checkbox" name="group" checked=""/>

For every choice input:

  • Use the same <group id>__<choice> id as its wrapper.
  • Set type to the function's type argument; it is checkbox by default and radio when requested.
  • Set name to the overall group id, so all inputs belong to the same group.
  • Include checked="" only when that choice is selected. Do not emit the checked attribute for an unselected choice.

  • If selected is a single string, the matching choice is initially checked.
  • If selected is a list of strings, every matching choice in that list is initially checked for a checkbox group.
  • Every selected choice must have both representations of checked state: the wrapper's checked class token and the input's checked="" attribute.
  • Choices not selected must have neither representation of checked state.

A radio group may have at most one initially selected value. When type="radio" and selected is a list containing more than one value, raise an exception. Its message must contain:

Radio buttons may have a maximum of 1 active value
