Task: Update AvroAttrsBridge to bridge complete signal event data

Implement support for building Avro schemas and converting event data based on an OpenEdxPublicSignal and its declared data fields.

Public API

openedx_events.bridge.avro_attrs_bridge.AvroAttrsBridge

The class must support:

AvroAttrsBridge(signal, extensions=None)
  • signal is an openedx_events.tooling.OpenEdxPublicSignal instance.
  • extensions is an optional mapping from Python classes to AvroAttrsBridgeExtention instances.

Expose:

bridge.schema_dict
bridge.to_dict(event_data)
bridge.from_dict(data)
  • schema_dict is the generated Avro schema dictionary.
  • to_dict(event_data: dict) -> dict converts signal event values into Avro-compatible values.
  • from_dict(data: dict) -> dict reconstructs the signal event values and their declared Python types.

The signal may be created using:

OpenEdxPublicSignal(
    event_type="simple.signal",
    data={"field_name": FieldType},
)

Multiple entries in data represent multiple top-level event fields.

openedx_events.bridge.avro_attrs_bridge_extensions.AvroAttrsBridgeExtention

Keep this exact class name and spelling available for subclassing. An extension used by the bridge has this contract:

class SomeExtension(AvroAttrsBridgeExtention):
    cls = SomePythonClass

    def serialize(self, obj):
        ...

    def deserialize(self, data):
        ...

    def record_fields(self):
        ...

The value returned by record_fields() is used as that class’s Avro field type.

Schema generation

Constructing a bridge must generate schema_dict immediately.

Every schema has this exact top-level structure:

{
    "type": "record",
    "name": "CloudEvent",
    "doc": "Avro Event Format for CloudEvents created with openedx_events/avro_attrs_bridge",
    "fields": [...],
}

Each declared signal data item becomes one top-level field, preserving declaration order:

{
    "name": "<signal data key>",
    "type": <schema for its declared type>,
}
Attrs classes

Classes defined with attr.s, including auto_attribs=True, become Avro records:

{
    "name": "<Python class name>",
    "type": "record",
    "fields": [...],
}

Attrs fields must retain their declaration order. Nested attrs classes must recursively become nested records.

Support these annotated primitive attrs field types:

Python type Avro type
bool "boolean"
int "long"
float "double"
bytes "bytes"
str "string"

For example, an attrs class named SimpleAttrs with fields declared as bool, int, float, bytes, and str must produce:

{
    "name": "SimpleAttrs",
    "type": "record",
    "fields": [
        {"name": "boolean_field", "type": "boolean"},
        {"name": "int_field", "type": "long"},
        {"name": "float_field", "type": "double"},
        {"name": "bytes_field", "type": "bytes"},
        {"name": "string_field", "type": "string"},
    ],
}

Distinct nested attrs classes must retain their own class names in their record schemas, even when they have identical fields.

Event-data conversion

to_dict

to_dict accepts the complete event keyword-data dictionary for the signal.

Attrs instances must be recursively converted to dictionaries. For example, nested attrs values must produce nested dictionaries containing their declared field names and values.

Primitive values remain in their Avro-compatible form.

from_dict

from_dict accepts a dictionary shaped according to schema_dict and returns a top-level event-data dictionary.

Attrs fields must be recursively reconstructed as instances of their declared attrs classes. Distinct nested declared classes must be reconstructed as the correct respective types.

If a dictionary lacks a required attrs constructor field, from_dict must raise TypeError.

The resulting dictionary must be suitable for use as:

signal.send_event(**bridge.from_dict(data))

Built-in custom-type support

The bridge must support these types without requiring callers to provide extensions.

datetime.datetime

For a signal field declared as datetime:

  • to_dict converts the value using datetime.isoformat().
  • from_dict converts that ISO-formatted string back into a datetime instance.

For example, datetime(year=1989, month=9, day=6) serializes as:

"1989-09-06T00:00:00"
opaque_keys.edx.keys.CourseKey

For a signal field declared as CourseKey:

  • to_dict converts the key using str(course_key).
  • from_dict reconstructs an equal CourseKey instance from that string.

Caller-provided extensions

A non-attrs class can be supported by passing an extension:

bridge = AvroAttrsBridge(
    signal,
    extensions={SomeExtension.cls: SomeExtension()},
)

For such a field:

  • Schema generation uses extension.record_fields().
  • to_dict uses extension.serialize(value).
  • from_dict uses extension.deserialize(value).

The generated schema and converted dictionaries must work with fastavro.schemaless_writer and fastavro.schemaless_reader. A nested attrs event and a custom extension whose record_fields() returns "string" must survive a write/read plus to_dict/from_dict round trip with equivalent values.

Errors

  • Constructing a bridge for an arbitrary non-attrs class with no matching built-in or caller-provided extension must raise TypeError.
  • Constructing a bridge when a top-level signal data type is list or dict must raise an exception during construction.

Task Specification: Support Optional/Nullable Fields in AvroAttrsBridge

Overview

You must extend the existing AvroAttrsBridge so that it correctly handles attrs class fields that have a default value of None. Such fields must be treated as optional/nullable throughout Avro schema generation, serialization, and deserialization.

Public API Surface

Existing (must continue to work)
  • Module: openedx_events.bridge.avro_attrs_bridge
    • Class: AvroAttrsBridge
      • Constructor accepts a signal object (as produced by the project's signal-creation utility) whose event-data configuration maps top-level key names to attrs-decorated classes.
      • Must provide the serialization/deserialization behavior already relied upon by existing bridge functionality (roundtrip of event data dictionaries to/from Avro-encoded bytes).
Test Support Classes (must be created)

Add the following attrs-decorated classes to the module openedx_events.bridge.tests.test_utilities:

  • SimpleAttrsWithDefaults — a frozen attrs class with the following fields, each declared with a default value of None:

    • boolean_field (type bool)
    • int_field (type int)
    • float_field (type float)
    • bytes_field (type bytes)
    • string_field (type str)

  • NestedAttrsWithDefaults — a frozen attrs class with a single field:

    • field_0 (type SimpleAttrsWithDefaults, default value None)

Both classes must be constructible with no arguments, in which case every field takes the value None.

Required Behavior

An attrs field declared with a default value of None must be treated as an optional/nullable field.

  1. Schema generation. When building the Avro schema for an attrs class, any field whose default is None must be represented as a nullable Avro type (i.e., the field may hold either its declared type or null).

  2. Serialization. Constructing an AvroAttrsBridge from a signal whose event data contains such classes, and serializing an event-data dictionary in which those fields are None, must succeed and produce Avro-encoded bytes.

  3. Deserialization. Deserializing those bytes back into event data must reproduce an instance of the original attrs class whose optional fields are None.

  4. Nested classes. The rule applies to fields whose type is itself an attrs class. A field typed as a nested attrs class with default None must be serializable and deserializable, and when its value is None it must roundtrip back to None.

Concrete roundtrip requirements

  • Given a signal configured with a single top-level key mapping to SimpleAttrsWithDefaults, and event data {"<key>": SimpleAttrsWithDefaults()}:

    • Serialization to bytes then deserialization must yield, under the same top-level key, an object whose boolean_field, int_field, float_field, bytes_field, and string_field are all None.

  • Given a signal configured with a single top-level key mapping to NestedAttrsWithDefaults, and event data {"<key>": NestedAttrsWithDefaults()}:

    • Serialization to bytes then deserialization must yield, under the same top-level key, an object whose field_0 is None.

Constraints

  • All previously supported bridge behavior (schema generation, serialization, and deserialization for non-defaulted fields, nested attrs data, bridge extensions for non-attrs types, and rejection of unsupported signal configurations) must remain intact.
  • No change in behavior is required for fields that do not have a None default.

Task: Implement an Avro schema/serialization module for OpenEdx signals

Overview

You will implement a set of modules under the Python package path openedx_events/event_bus/avro/ that convert OpenEdxPublicSignal instances and their event data to and from Avro-compatible schemas and dictionaries. The functionality is split across four separately importable concerns: schema generation, serialization (Python objects → dict), deserialization (dict → Python objects), and a base class for custom-type serializers.

There is an existing signal class, openedx_events.tooling.OpenEdxPublicSignal, which is constructed with an event type string and an init_data mapping of field-name → Python type. A helper used throughout the tests constructs signals like this:

OpenEdxPublicSignal(event_type="simple.signal", data=data_dict)

where data_dict maps top-level field names to Python types (which may be attrs-decorated classes, plain classes, datetime, opaque_keys.edx.keys.CourseKey, or primitives).

Required public API

Module openedx_events/event_bus/avro/types.py

Must expose a dict named PYTHON_TYPE_TO_AVRO_MAPPING mapping Python primitive types to their Avro type-name strings. It must at minimum contain the following entries (Python type → Avro string):

  • bool → "boolean"
  • int → "long"
  • float → "double"
  • bytes → "bytes"
  • str → "string"

PYTHON_TYPE_TO_AVRO_MAPPING[str] must equal "string" and is used as a field type value by custom serializers.

Module openedx_events/event_bus/avro/custom_serializers.py

Must expose a base class BaseCustomTypeAvroSerializer intended to be subclassed to teach the system how to handle a non-attrs, non-primitive Python type. A subclass declares:

  • cls: the Python class this serializer handles.
  • field_type: the Avro field type used to represent instances of cls in a schema (e.g. "string").
  • serialize(obj) -> str (a static method): converts an instance of cls into its Avro-representable value.
  • deserialize(data) -> object (a static method): reconstructs an instance of cls from the Avro-representable value.
Module openedx_events/event_bus/avro/schema.py

Must expose a function:

def schema_from_signal(signal, custom_type_to_avro_type=None):
  • signal: an OpenEdxPublicSignal.
  • custom_type_to_avro_type: optional mapping of Python type → Avro type string, used to represent otherwise-unsupported types.

Returns a dict representing the Avro schema (see "Schema format" below).

Module openedx_events/event_bus/avro/serializer.py

Must expose a class:

class AvroSignalSerializer:
    def __init__(self, signal): ...
    @property
    def schema(self): ...        # the Avro schema dict for the signal
    def to_dict(self, event_data): ...
    def custom_type_serializers(self): ...   # returns a list; default empty
  • Constructed from an OpenEdxPublicSignal.
  • .schema yields the Avro schema dict, consistent with schema_from_signal applied to the same signal (accounting for any custom type serializers this instance provides).
  • .to_dict(event_data) converts a dict of {field_name: python_value} into a dict of Avro-representable values.
  • custom_type_serializers() returns a list of BaseCustomTypeAvroSerializer subclasses. The default returns an empty list; subclasses override it to register custom serializers.
Module openedx_events/event_bus/avro/deserializer.py

Must expose a class:

class AvroSignalDeserializer:
    def __init__(self, signal): ...
    @property
    def schema(self): ...        # the Avro schema dict for the signal
    def from_dict(self, data): ...
    def custom_type_serializers(self): ...   # returns a list; default empty
  • Constructed from an OpenEdxPublicSignal.
  • .schema yields the Avro schema dict, consistent with the signal (and any custom serializers).
  • .from_dict(data) converts a dict of Avro-representable values into a dict of {field_name: python_value}, reconstructing attrs objects and custom types.
  • custom_type_serializers() behaves as on the serializer.

The serializer and deserializer schemas must be mutually compatible: a value produced by AvroSignalSerializer.to_dict, written with the serializer's schema via fastavro.schemaless_writer and read back with the deserializer's schema via fastavro.schemaless_reader, must reconstruct the original event data via AvroSignalDeserializer.from_dict.

Schema format

schema_from_signal (and the .schema properties) produce a top-level dict of this shape:

{
    "type": "record",
    "name": "CloudEvent",
    "doc": "Avro Event Format for CloudEvents created with openedx_events/schema",
    "fields": [ <one entry per top-level signal field> ],
}

The doc string must be exactly "Avro Event Format for CloudEvents created with openedx_events/schema".

Each top-level field appears in fields in the same order as declared in the signal's data mapping, as {"name": <field_name>, "type": <avro_type>}.

Primitive fields

A field whose Python type is a primitive uses the mapped Avro string directly as its "type". Example — a signal field of Python type str produces {"name": <field_name>, "type": "string"}.

attrs record fields

A field whose Python type is an attrs-decorated class becomes a nested Avro record:

{
    "name": <ClassName>,
    "type": "record",
    "fields": [ <one entry per attrs attribute, in declaration order> ],
}

The record's "name" is the class's name. Each attribute is rendered by the same rules recursively (primitive attributes use their mapped string, nested attrs attributes become nested records, etc.). A given nested record definition is emitted with its full definition each place it is first needed (see examples below).

Custom / extension types

When a field's Python type is not a primitive and not an attrs class, it must be representable either through custom_type_to_avro_type (for schema_from_signal) or through a registered BaseCustomTypeAvroSerializer subclass (for the serializer/deserializer classes). Such a type is represented in the schema by its declared Avro field type (e.g. "string"). This applies both at the top level and when the custom type appears as an attribute nested inside an attrs record.

Two custom types are supported by default (no registration needed) by the serializer and deserializer classes:

  • datetime.datetime: serialized to its ISO-8601 string via .isoformat(), and deserialized back to an equal datetime.
  • opaque_keys.edx.keys.CourseKey: serialized to str(course_key), and deserialized back to an equal CourseKey.

Both are represented in the schema as "string"-typed fields.

Fields with defaults (optional fields)

An attrs attribute that has a default value must be rendered as a nullable Avro union with a null default:

{"name": <attr_name>, "type": ["null", <avro_type>], "default": "null"}

where <avro_type> is the same representation the attribute's type would otherwise have (a mapped primitive string, or a nested record dict). The "default" value must be the string "null", and the union list must be exactly ["null", <avro_type>] with "null" first.

This applies recursively: an attrs attribute whose type is itself an attrs class with defaults produces a nested record whose own fields follow the same nullable-union rules.

Serialization behavior (to_dict)

  • Top-level output is a dict keyed by the signal's field names.
  • attrs instances are converted to plain dicts of their attributes (recursively), with attribute names as keys.
  • For an attrs instance with default/optional fields left unset (i.e. None), each such field appears in the output dict with value None. For example, an instance of a class with fields boolean_field, int_field, float_field, bytes_field, string_field, attrs_field all unset serializes to {'boolean_field': None, 'int_field': None, 'float_field': None, 'bytes_field': None, 'string_field': None, 'attrs_field': None}.
  • Nested attrs values are recursively converted to nested dicts.
  • datetime values become their .isoformat() string.
  • CourseKey values become their str(...) representation.
  • A value whose type is handled by a registered custom serializer is replaced by that serializer's serialize(obj) output. This applies to top-level fields and to custom-typed attributes nested inside attrs records.

Deserialization behavior (from_dict)

  • Top-level output is a dict keyed by the signal's field names.
  • Dicts corresponding to attrs record types are reconstructed into instances of the appropriate attrs class (recursively for nested records). The reconstructed instances must be of the correct class and compare equal to the original objects.
  • For optional/default attrs fields: an empty dict {} for such a record must reconstruct to an instance equal to the class constructed with all defaults. A nested optional field given as {"field_0": {}} reconstructs the nested record with defaults.
  • ISO-8601 strings for datetime-typed fields reconstruct to equal datetime objects.
  • String representations for CourseKey-typed fields reconstruct to equal CourseKey objects.
  • Values for custom-typed fields (registered via a custom serializer) are reconstructed with that serializer's deserialize(data). This applies to top-level fields and to custom-typed attributes nested inside attrs records.
  • If a dict is missing a required (non-default) field of an attrs class it is being converted into, a TypeError must be raised.

Error conditions

  • schema_from_signal (and constructing the serializer/deserializer such that a schema is built) must raise TypeError when a signal field's Python type is a plain class that is neither a primitive, an attrs class, a default-supported custom type (datetime, CourseKey), nor covered by a provided custom_type_to_avro_type mapping / registered custom serializer.
  • A signal field whose Python type is list or dict must cause an exception to be raised during schema generation.

Concrete schema examples

  "name": "CloudEvent",
  "doc": "Avro Event Format for CloudEvents created with openedx_events/schema",
  "fields": [
    {"name": "event_data", "type": {
      "name": "SimpleAttrs", "type": "record", "fields": [
        {"name": "boolean_field", "type": "boolean"},
        {"name": "int_field", "type": "long"},
        {"name": "float_field", "type": "double"},
        {"name": "bytes_field", "type": "bytes"},
        {"name": "string_field", "type": "string"},
      ]

  ],
}
