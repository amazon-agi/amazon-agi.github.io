SqliteCollectionBase

SqliteCollectionBase[T] is a generic abstract base class and must support runtime generic subscription, such as SqliteCollectionBase[Any]. A concrete subclass must provide a string-valued schema_version property and _do_create_table(self, commit: bool = False) -> None.

    • For None, create a temporary-file-backed connection by obtaining NamedTemporaryFile().name and passing that name to sqlite3.connect.
    • For a string, pass the string to sqlite3.connect.
    • For an existing sqlite3.Connection, reuse that exact object.

  • serializer is a callable from values to bytes. When omitted or None, use the module-level dumps.
  • deserializer is a callable from bytes to values. When omitted or None, use the module-level loads.

The resolved values must be exposed through these properties/attributes:

  • table_name: str

  • deserializer

  • If table_name is omitted, the exact format is:

    <container_type_name>_<str(uuid4()) with every hyphen removed>

Metadata and initialization

Each connection used by a container must have a metadata table with at least these columns:

  • table_name
  • schema_version
  • container_type

(table_name, schema_version, container_type_name)

The table name must uniquely identify its metadata record. Observable initialization behavior is:

  • Constructing the same concrete container twice with the same connection and table_name reuses the initialized backing table and produces exactly one metadata row. Existing rows in that backing table are not cleared.
  • Distinct table names on one connection produce one metadata row per name.
  • The result of SELECT table_name, schema_version, container_type FROM metadata reflects the insertion order of distinct table names.
  • An initialized table is reusable when its metadata identifies the same container type and schema version and the physical table exists.

_do_create_table(self, commit: bool = False) -> None is the subclass hook used to create the concrete table.

Destructive lifecycle option

  1. remove the metadata row matching the container's table name and container type,
  2. drop the backing table, and
  3. finalize those database changes on the connection.

Construction and codecs

The constructor accepts:

Dict(

    table_name=None,

    **kwargs,

serializer and deserializer encode and decode values. key_serializer and key_deserializer independently encode and decode keys and are exposed through properties of those names. If a key codec is omitted, it defaults to the corresponding configured value codec. With no custom codecs, both keys and values use the module-level pickle dumps/loads bindings. serialize_key(key) and deserialize_key(blob) must use the configured key codecs; key serialization also performs the hashability validation described below.

data, when provided, is an initial mapping. Populate in this order:

  1. entries from data, in that mapping's iteration order;
  2. entries from kwargs, in keyword order.

Keyword entries take precedence over duplicate keys from data, but replacing a duplicate must retain that key's original insertion position. Initial data updates an already initialized table rather than clearing it first.

Backing-table schema and persisted representation

A Dict backing table has exactly these three columns in this order and with these names:

  1. serialized_key — a non-null, unique BLOB
  2. serialized_value — a non-null BLOB
  3. item_order — an integer ordering key

A compatible schema is equivalent to:

CREATE TABLE <table_name> (
    serialized_key BLOB NOT NULL UNIQUE,
    serialized_value BLOB NOT NULL,
    item_order INTEGER PRIMARY KEY
)

The first inserted key receives item_order 0. A newly inserted key receives one greater than the current maximum item_order; replacing an existing key preserves its order. Deletions do not renumber remaining rows, so gaps are permitted. Ordering is always determined by ascending item_order, on every supported Python version.

Key identity in storage is determined by the serialized key bytes. Values returned to callers are deserialized. Consequently, mutating a deserialized mutable value does not itself persist that mutation; the changed value must be assigned back to the mapping.

When an existing compatible table contains data encoded in a non-canonical form for the active codecs, opening it must decode and re-encode its keys and values with the active key and value codecs while preserving every item_order. This includes reading rows written with an older pickle protocol and normalizing them to the current default pickle.dumps representation. Opening an existing dictionary otherwise preserves all entries.

Hashability and missing keys

Every operation that accepts a key—including lookup, assignment, deletion, membership, get, pop, and setdefault—must reject an unhashable key with TypeError in the standard form containing:

unhashable type: '<type-name>'

A missing key in indexed lookup, deletion, or pop without a default raises KeyError(key), so the original key is the exception argument.

Core mapping behavior
  • len(d) returns the number of rows in the backing table, regardless of gaps in item_order.
  • d[key] returns the deserialized value for the matching serialized key.
  • d[key] = value is an upsert. It replaces only the value for an existing key without moving it; a new key is appended at the next order index.
  • del d[key] removes the matching row without changing other rows' order indices.
  • key in d and key not in d report membership by serialized key.
  • iter(d) returns a collections.abc.Iterator of deserialized keys in ascending insertion order. Each call creates a fresh iterator; an individual iterator has normal one-shot exhaustion behavior.
  • clear() removes all entries and leaves the backing table empty. It also works when already empty.
Dictionary methods and views
  • get(key, default=None) returns the existing value or default without inserting anything.
  • keys() returns a collections.abc.KeysView enumerating keys in insertion order.
  • items() returns a collections.abc.ItemsView enumerating deserialized (key, value) pairs in insertion order.
  • values() returns a collections.abc.ValuesView enumerating values in insertion order.
  • pop(key[, default]) removes and returns an existing value. If absent, it returns a supplied default without changing the mapping; if no default was supplied, it raises KeyError(key).
  • setdefault(key, default=None) returns an existing value without changing it. For a missing key, it appends key with default, returns that default, and uses None when no default was supplied.
  • update([other], **kwargs) follows normal mutable-dictionary semantics. It accepts a mapping or iterable of key/value pairs, then keyword entries. Existing values are replaced in place, while new keys are appended in source order.
popitem()

popitem() removes and returns the most recently inserted (key, value) pair, using the greatest item_order (LIFO). The returned key and value are deserialized, and the corresponding row is removed. On an empty mapping it raises:

KeyError("popitem(): dictionary is empty")

The exception message is exactly 'popitem(): dictionary is empty'.

Reversed iteration
  • On Python 3.8 and later, reversed(d) returns a collections.abc.Iterator of deserialized keys in descending insertion order.
  • Before Python 3.8, Dict is not reversible; reversed(d) raises TypeError with the standard message 'Dict' object is not reversible.
Mapping union operators

On Python 3.9 and later:

  • d | other, where other is a mapping, returns a new SQLite-backed Dict on the same SQLite connection. It uses a fresh automatically generated table and does not mutate d. Left-hand entries retain their relative order; right-hand values replace duplicate left-hand values without moving those keys; keys unique to the right operand are appended in right-hand iteration order. Because the result is a fresh table, its item_order values are consecutive starting at 0.
  • d |= other performs the same right-precedence merge in place. It keeps the original object and backing table, preserves positions of existing keys, and appends new right-hand keys at the end.

Before Python 3.9, neither operator is supported. They raise the normal TypeError forms identifying Dict and the right operand type:

unsupported operand type(s) for |: 'Dict' and '<right-type>'
unsupported operand type(s) for |=: 'Dict' and '<right-type>'

Compatibility Requirements

  • Runtime behavior must work across supported Python versions before and after 3.8 and 3.9.
  • Typing and collections.abc import differences between those versions must not cause import-time or runtime failures.
  • Insertion ordering is guaranteed on all supported Python versions, even where the built-in dict did not yet guarantee it.

Scope

Only SqliteCollectionBase, Dict, and the explicitly listed behaviors are required. Additional standard mapping methods may be provided, but no other collection type is required.
