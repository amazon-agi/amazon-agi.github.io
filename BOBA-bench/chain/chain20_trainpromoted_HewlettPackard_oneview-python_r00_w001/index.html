Task: Refactor the DeploymentPlans Resource to the New Resource Base Classes

Overview

The DeploymentPlans resource in the Image Streamer client must be migrated from the legacy ResourceClient-based implementation to the newer resource base classes (Resource, ResourceHelper). This changes how the class is constructed, how its methods delegate to helper methods, and the signatures of several public methods.

Module and Class

  • Module: hpOneView.image_streamer.resources.deployment_plans
  • Class: DeploymentPlans

The class must be constructed as DeploymentPlans(connection) where connection is an hpOneView.connection.connection instance.

DeploymentPlans must derive from the refactored Resource base class (from hpOneView.resources.resource). As a consequence:

  • The instance must hold its resource state in a data attribute (a dict). External code may assign self._client.data = {'uri': ...} and the instance methods must use the uri stored in data when performing per-instance operations.
  • Delegated operations must be routed through a ResourceHelper instance and through Resource methods, rather than through ResourceClient.

Client Integration

In the Image Streamer client, the deployment_plans property must return a new DeploymentPlans instance on each access (no caching/lazy-loading of a single shared instance). Two consecutive accesses of the property must yield distinct (non-equal) objects, each being an instance of DeploymentPlans.

Returns all deployment plans. Delegates to the resource helper's get_all, passing the arguments as keyword arguments:

  • start → start
  • count → count

  • sort → sort

delete(resource, timeout=-1)

resource may be a plain scope ID/URI or a scope data dictionary. Delegate to Resource.delete, passing resource as the first positional argument, timeout=timeout, and the appropriate custom_headers dictionary:

  • For a plain ID or URI, pass:

    {'If-Match': '*'}

  • For a dictionary containing an eTag, use its exact value:

    {'If-Match': resource['eTag']}

  • For a dictionary without an eTag, use the wildcard:

    {'If-Match': '*'}

Return the result of Resource.delete.

update_resource_assignments

Expose:

update_resource_assignments(uri, information, timeout=-1)

This method adds and removes resource assignments for a scope. It must delegate to ResourcePatchMixin.patch_request with:

  1. the supplied scope URI with /resource-assignments appended;
  2. a shallow copy of the information dictionary as the second positional argument; and
  3. timeout=timeout.

The required call shape is:

patch_request(
    uri + '/resource-assignments',
    information.copy(),
    timeout=timeout
)

Do not pass a custom_headers argument from update_resource_assignments. Any standard content-type handling performed internally by ResourcePatchMixin remains the mixin's responsibility.

Removed legacy Scopes-specific APIs

Remove the former Scopes-specific implementations and behaviors for:

  • get_by_name;
  • create;
  • patch; and
  • the standalone get(id_or_uri) lookup wrapper.

These legacy wrappers must not continue to dispatch through ResourceClient. Generic behavior inherited from a shared base class is outside this removal; in particular, a generic inherited get may still exist, but no Scopes-specific get wrapper is required.

3. Shared Resource Classes (hpOneView/resources/resource.py)

Public classes

The module must expose all of the following as importable public names:

  • Resource;
  • ResourceHelper;
  • ResourcePatchMixin; and
  • the existing ResourceClient.

The Scopes refactor must not remove or replace ResourceClient; Tasks and other compatible legacy resources continue to use it.

Remove Resource.get_by_id

Remove get_by_id from the newer resource base class that provides get_by_uri. That base class must no longer provide behavior that accepts a bare ID, constructs <resource collection URI>/<id>, and returns a resource object or None when the response is empty.

This removal applies only to that shared base-class method. It must not remove independently defined resource-specific methods or the ID/URI retrieval supported by ResourceClient.get.

ResourceClient.create and payload fields named force

ResourceClient.create must not apply special handling to a force field contained in the request payload. Such a field is ordinary payload data: do not remove it, interpret it as a control argument, or modify the target URI because it is present.

For example:

payload = {'resource_name': 'a name', 'force': 'yes'}
ResourceClient.create(payload, timeout=-1)

must post a dictionary with those contents unchanged to the client's collection URI, using custom_headers=None. All other existing ResourceClient.create behavior, including its normal default-value handling, remains unchanged.

5. OneView Client — scopes Property (hpOneView/oneview_client.py)

The OneView client's scopes property must return a Scopes object configured with the client's connection, but it must not cache or memoize that object.

Each property access must construct and return a fresh Scopes instance. Consequently:

first = oneview_client.scopes
second = oneview_client.scopes

must yield distinct, non-equal objects. This lifecycle change applies only to scopes; do not alter the existing lifecycle behavior of unrelated OneView-client properties.

Compatibility and Non-Goals

  • This is a focused Scopes refactor, not a migration of every legacy resource to the newer architecture.
  • Tasks.get_all and Tasks.get specifically remain ResourceClient integrations.
  • Do not change unrelated resource APIs, return types, request headers, URI construction, or OneView-client property behavior.
