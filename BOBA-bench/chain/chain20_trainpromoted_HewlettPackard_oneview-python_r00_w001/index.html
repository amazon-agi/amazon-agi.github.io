Task: Migrate the DeploymentPlans Resource over to the New Resource Base Classes

Overview

Within the Image Streamer client, the DeploymentPlans resource must be migrated off the legacy ResourceClient-based implementation and onto the newer resource base classes (Resource, ResourceHelper). As a result, the construction of the class, the delegation of its methods to helper methods, and the signatures of several public methods all change.

Module and Class

  • Module: hpOneView.image_streamer.resources.deployment_plans
  • Class: DeploymentPlans

The class must be constructed as DeploymentPlans(connection), with connection being an hpOneView.connection.connection instance.

DeploymentPlans must derive from the refactored Resource base class (found in hpOneView.resources.resource). This has the following consequences:

  • The instance must keep its resource state in a data attribute (a dict). External code may assign self._client.data = {'uri': ...}, and when performing per-instance operations the instance methods must use the uri stored in data.
  • Delegated operations must be routed through a ResourceHelper instance and through Resource methods instead of through ResourceClient.

Integration with the Client

In the Image Streamer client, the deployment_plans property must return a new DeploymentPlans instance each time it is accessed (no caching/lazy-loading of a single shared instance). Two consecutive accesses of the property must yield distinct (non-equal) objects, each of them an instance of DeploymentPlans.

Required Public Methods and Their Behavior

get_all(start=0, count=-1, filter='', sort='')

Returns all deployment plans. The delegation target is the resource helper's get_all, with the arguments passed as keyword arguments:

  • start → start
  • count → count
  • filter → filter
  • sort → sort

Examples of the call that gets delegated:

  • get_all(2, 500, 'name=TestName', 'name:ascending') → helper get_all(start=2, count=500, filter='name=TestName', sort='name:ascending')
  • get_all() → helper get_all(start=0, count=-1, filter='', sort='')
get_by(field, value)

The delegation target is the Resource.get_by method, which receives the same two positional arguments unchanged; e.g. get_by('name', 'Deployment Plan Name') → get_by('name', 'Deployment Plan Name').

create(data, ...)

Creates a deployment plan. A default type of "OEDeploymentPlan" must be set before creation if the provided data dict does not contain a type key. If type is already there, it must be preserved.

The delegation target is the resource helper's create. In the delegated call, the resulting data dict must be passed as the first positional argument, with these positional arguments after it, in this order: None, -1, None, False.

Examples:

  • create({"name": "Deployment Plan Name"}) → helper create({"type": "OEDeploymentPlan", "name": "Deployment Plan Name"}, None, -1, None, False)
  • create({"type": "OEDeploymentPlan", "name": "Deployment Plan Name"}) → helper create({"type": "OEDeploymentPlan", "name": "Deployment Plan Name"}, None, -1, None, False)
update(data, ...)

Updates the deployment plan. The delegation target is the resource helper's update. In the delegated call, the (unchanged) data dict must be passed as the first positional argument, with these positional arguments after it, in this order: the resource's uri (from data['uri']), False, -1, None.

Example: with self.data = {'uri': '/rest/deployment-plans/<id>'} set and update({...,"uri":"/rest/deployment-plans/<id>"}) called → helper update({...}, '/rest/deployment-plans/<id>', False, -1, None).

get_osdp()

Fetches the OS Deployment Plan details for the current resource. It takes no arguments. The delegation target is the resource helper's do_get; the single URI argument passed in is built by appending /osdp to the resource's uri.

Example: given uri = '/rest/deployment-plans/<id>' → helper do_get('/rest/deployment-plans/<id>/osdp').

get_usedby()

Fetches what uses the current resource. It takes no arguments. The delegation target is the resource helper's do_get; the single URI argument passed in is built by appending /usedby to the resource's uri.

Example: given uri = '/rest/deployment-plans/<id>' → helper do_get('/rest/deployment-plans/<id>/usedby').

delete(force=False)

Deletes the current resource. It takes only a force keyword argument (default False). The delegation target is the resource helper's delete: the resource's uri goes in as the first positional argument, and the following are passed as keyword arguments: custom_headers=None, force=<force>, timeout=-1.

Examples:

  • delete(force=False) → helper delete('/rest/deployment-plans/<id>', custom_headers=None, force=False, timeout=-1)
  • delete(force=True) → helper delete('/rest/deployment-plans/<id>', custom_headers=None, force=True, timeout=-1)

Additional Notes

  • The standalone get method (which accepts an id or uri) that existed on the legacy implementation must no longer belong to the public surface exercised here; operations on a per-resource basis now rely on the uri stored in data.
  • The helper methods referenced above (get_all, create, update, delete, do_get) are defined on ResourceHelper; get_by is defined on Resource.

1. Default API Version

1.1 connection

When api_version is omitted, the connection constructor must default to API version 800:

The API version that gets selected is exposed via _apiVersion and via the X-API-Version request header.

For a connection that uses the default API version, the base headers must be equivalent to:

{
    'X-API-Version': 800,
    'Accept': 'application/json',
    'Content-Type': 'application/json'
}

The header behavior listed below is required:

  • X-API-Version must contain the integer 800 rather than the string '800'.
  • A call to disable_etag_validation() must retain the API-version header and add 'If-Match': '*'.
  • A call to enable_etag_validation() must remove the If-Match override and restore the base header set. Enabling and disabling ETag validation in either order must still preserve X-API-Version: 800.
  • Custom headers must be merged with the base headers. For example, adding 'Accept-Language': 'en_US' must not remove or alter the API-version, accept, or content-type headers.
  • The headers that result, X-API-Version: 800 among them, must be used by normal HTTP operations such as POST, PUT, PATCH, and DELETE, including any follow-up request used for an accepted asynchronous operation.
  • Multipart/form-data POST uploads must emit X-API-Version with the integer value 800 via their putheader calls.

The default API version for OneViewClient must be 800.

  • When the JSON configuration omits api_version, OneViewClient.from_json_file(path) must use API version 800. client.connection._apiVersion and client.api_version must both then equal 800.

  • _apiVersion is less than minimumVersion.
  • _apiVersion is greater than currentVersion.

A version equal to either supported boundary is valid.

  • Credentials that have no usable sessionID, including username/password credentials, must use POST for login.

helper.get_all(0, -1,
               uri='/rest/storage-volumes/attachable-volumes',
               filter='',
               query='',
               sort='',
               scope_uris='')

5. Compatibility and Extent of the Changes

  • Keep unrelated resource APIs and all existing generic resource behavior that is not explicitly changed above.
  • Keep API-version default merging, synchronous response handling, task completion waiting, and delegated return values intact.
  • Every supplied timeout value must be forwarded. The existing timeout semantics stay unchanged: a timeout stops the waiting for completion but does not cancel the operation on the appliance.
  • Header names, header values, endpoint paths, where positional arguments are placed, and the demonstrated connection-query formatting are exact public contracts.
  • No broader redesign of the resource hierarchy or of other resource classes is required.

Task Specification: Rework of the Scopes Resource

Summary

The Scopes resource is to be refactored so that it sits on the newer resource base-class architecture (Resource, ResourceHelper, and ResourcePatchMixin) rather than the legacy ResourceClient. For Tasks, the required integration with the legacy ResourceClient stays in place, and the associated shared-resource, storage-volume, and OneView-client behaviors covered below are adjusted.

Existing public APIs and compatibility behavior must remain unchanged wherever this specification does not explicitly change a behavior.

1. The Scopes Resource (hpOneView/resources/settings/scopes.py)

Construction of the resource and its metadata

  • The /rest/scopes endpoint continues to be represented by Scopes, which is available for API version 300 and later.

  • Construction must take a single connection argument:

    Scopes(connection)

    This API does not have a second constructor argument for resource data.

  • Move Scopes off its legacy implementation backed by ResourceClient. For its operations, the newer architecture of Resource, ResourceHelper, and ResourcePatchMixin must be used, as set out below.

  • The public class attribute DEFAULT_VALUES is kept, its existing values included:

    {
    '300': {'type': 'Scope'},
    '500': {'type': 'ScopeV2'}
}

    For scope updates, DEFAULT_VALUES is what gets supplied as the default-values mapping.

get_all

Expose:

get_all(start=0, count=-1, sort='', query='', view='')

A list of scopes is what this method retrieves and returns. The delegation must go to ResourceHelper.get_all; start and count are passed positionally, while sort, query, and view are passed as keyword arguments:

get_all(start, count, sort=sort, query=query, view=view)

Each argument keeps its existing meaning:

  • start: the index of the first item, counting from zero; its default is 0.
  • count: how many items are being requested; -1 asks for all items.
  • sort: the sort expression being requested; its default is an empty string.
  • query: a general-purpose query expression; its default is an empty string.
  • view: a predefined view for the response; its default is an empty string.
update

Expose the API for updating a scope, with the existing data, timeout, and force parameters:

update(data, timeout=-1, force=False)

Resource.update must be what this method delegates to. Within the delegated call, these elements must be present:

  1. data, placed in the first positional slot;
  2. timeout=timeout;
  3. default_values=DEFAULT_VALUES; and
  4. a custom_headers argument that contains an If-Match value.

The header is selected this way:

  • When data contains no eTag, pass:

    {'If-Match': '*'}

  • When an eTag is present in data, that value must be passed unchanged. For instance:

    {'If-Match': '2016-11-03T18:41:10.751Z/2016-11-03T18:41:10.751Z'}

Other arguments must not be added to this call by the delegation. The result of Resource.update must be returned.

Timeout semantics are untouched: with -1, the existing wait-for-completion behavior applies, and the operation on the appliance is not aborted when a wait is stopped.

delete

Expose:

delete(resource, timeout=-1)

The resource argument may be a scope data dictionary or a plain scope ID/URI. The delegation goes to Resource.delete, with resource in the first positional slot, along with timeout=timeout and the custom_headers dictionary appropriate to the case:

  • With a plain ID or URI, pass:

    {'If-Match': '*'}

  • With a dictionary that includes an eTag, its exact value is used:

    {'If-Match': resource['eTag']}

  • With a dictionary that has no eTag, the wildcard is used:

    {'If-Match': '*'}

The result of Resource.delete must be returned.

update_resource_assignments

Expose:

update_resource_assignments(uri, information, timeout=-1)

Addition and removal of a scope's resource assignments is what this method performs. ResourcePatchMixin.patch_request must be the delegation target, receiving:

  1. the scope URI that was supplied, with /resource-assignments appended to it;
  2. a shallow copy of the information dictionary, which takes the second positional slot; and
  3. timeout=timeout.

The call is required to have this shape:

patch_request(
    uri + '/resource-assignments',
    information.copy(),
    timeout=timeout
)

From update_resource_assignments, no custom_headers argument is to be passed. Whatever standard content-type handling ResourcePatchMixin performs internally remains the responsibility of the mixin.

Legacy Scopes-specific APIs to be removed

These former Scopes-specific implementations and behaviors are to be removed:

  • get_by_name;
  • create;
  • patch; and
  • the standalone get(id_or_uri) lookup wrapper.

These legacy wrappers must not go on dispatching through ResourceClient. This removal does not extend to generic behavior inherited from a shared base class; in particular, a generic inherited get may still exist, but a Scopes-specific get wrapper is not required.

2. The Tasks Resource (hpOneView/resources/activity/tasks.py)

Construction of the resource and its legacy-client integration

  • /rest/tasks is the endpoint that Tasks continues to represent.

  • A single connection argument must be used at construction:

    Tasks(connection)

  • The data-retrieval operations below must route their delegation through a legacy ResourceClient instance that is configured with the supplied connection and the Tasks URI. Dispatch through ResourceHelper must not be used for them.

get_all

The public signature and its defaults stay as they are:

get_all(start=0, count=-1, fields='', filter='', query='', sort='', view='')

The delegation must go to ResourceClient.get_all, with all seven parameters passed as keyword arguments:

ResourceClient.get_all(
    count=count,
    fields=fields,
    filter=filter,
    query=query,
    sort=sort,
    start=start,
    view=view
)

Every supplied value must be passed on unchanged. To illustrate: when the caller provides only fields, filter, sort, and view, the defaults count=-1, query='', and start=0 must also be forwarded by the call. The result of ResourceClient.get_all is to be returned unchanged.

get

Expose:

get(id_or_uri)

ResourceClient.get is the delegation target; the task identifier or URI that was supplied goes in unchanged, as the only positional argument:

ResourceClient.get(id_or_uri)

The delegated result must be returned unchanged.

3. Shared Classes for Resources (hpOneView/resources/resource.py)

Publicly importable names

As importable public names, all of the following must be exposed by the module:

  • Resource;
  • ResourceHelper;
  • ResourcePatchMixin; and
  • the existing ResourceClient.

ResourceClient must not be removed or replaced by the Scopes refactor; Tasks and the other compatible legacy resources go on using it.

Resource.get_by_id removal

get_by_id is to be removed from the newer resource base class, the one that provides get_by_uri. After the removal, that base class must no longer provide behavior which accepts a bare ID and, from it, constructs <resource collection URI>/<id>, returning a resource object or None when the response is empty.

That shared base-class method is the only thing this removal affects. Independently defined resource-specific methods, together with the ID/URI retrieval that ResourceClient.get supports, must not be removed by it.

ResourceClient.create and payload fields called force

A force field contained in the request payload must not receive special handling from ResourceClient.create. A field of this kind is nothing beyond ordinary payload data: it must not be removed, it must not be treated as a control argument, and the target URI must not be modified on account of its presence.

As an example:

payload = {'resource_name': 'a name', 'force': 'yes'}
ResourceClient.create(payload, timeout=-1)

a dictionary carrying those contents unchanged must be posted to the client's collection URI, with custom_headers=None used. Every other part of the existing ResourceClient.create behavior, its normal default-value handling included, remains unchanged.

4. Storage Volumes — URI for the Attachable-Volumes Endpoint (hpOneView/resources/storage/volumes.py)

The existing API is kept as is:

get_attachable_volumes(
    start=0,
    count=-1,
    filter='',
    query='',
    sort='',
    scope_uris='',
    connections=''
)

When connections is not empty, it is appended onto /rest/storage-volumes/attachable-volumes as the connections query parameter. The supplied list is serialized with standard Python list/dictionary string formatting. Notably, the normal spaces after dictionary colons and after the commas separating list elements must be preserved; stripping spaces to compact the representation must not happen.

Take these connections as an example:

[
    {'networkUri': '/rest/fc-networks/90bd0f63-3aab-49e2-a45f-a52500b46616'},
    {'networkUri': '/rest/fc-networks/8acd0f62-1aab-49e2-a45a-d22500b4acdb'}
]

the URI that must be produced is:

/rest/storage-volumes/attachable-volumes?connections=[{'networkUri': '/rest/fc-networks/90bd0f63-3aab-49e2-a45f-a52500b46616'}, {'networkUri': '/rest/fc-networks/8acd0f62-1aab-49e2-a45a-d22500b4acdb'}]

The delegation target is ResourceHelper.get_all, which is called with:

  • start and count passed positionally; and
  • uri, filter, query, sort, and scope_uris passed as keyword arguments.

Aside from constructing the required URI, all collection arguments are forwarded unchanged. When connections is empty, /rest/storage-volumes/attachable-volumes is used with no connections query parameter, and the delegation keeps the same shape and defaults.

5. OneView Client — the scopes Property (hpOneView/oneview_client.py)

A Scopes object configured with the client's connection is what the OneView client's scopes property must return, but that object must not be cached or memoized.

A fresh Scopes instance must be constructed and returned by each property access. As a consequence:

first = oneview_client.scopes
second = oneview_client.scopes

the two accesses above must yield distinct, non-equal objects. Only scopes is affected by this lifecycle change; the existing lifecycle behavior of the OneView client's unrelated properties must not be altered.

Non-Goals and Compatibility

  • What is happening here is a refactor focused on Scopes; it is not a migration of every legacy resource to the newer architecture.
  • It is Tasks.get_all and Tasks.get specifically that remain ResourceClient integrations.
  • Unrelated resource APIs, return types, request headers, URI construction, and OneView-client property behavior must not be changed.
