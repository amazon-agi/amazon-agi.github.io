Overview

In the infoblox_client.objects module, IP address objects (represented by the IP class and its concrete subclasses such as IPv4 for IPv4 addresses) carry a host field. This host field must be treated as a shadow field: it may be stored on the object in memory (e.g., populated when the object is constructed from data returned by NIOS), but it must not be included in the payload sent to the backend when a parent object is updated via the API.

Required Behavior

The host field on IP objects
  • The IP object type must continue to accept and store a host value (settable/gettable on the instance in memory).
  • The host field must not appear in the dictionary representation of the IP object that is serialized and sent on update operations to the connector/backend.
Effect on HostRecord updates

When a HostRecord object contains one or more IP addresses (in its ip / ipv4addrs collection) and update() is called on that record, the update payload sent to the connector's update_object method must contain the serialized IP entries without the host key — regardless of whether a given IP object has a host value set internally.

Each serialized IP entry in the update payload must still include its other writable fields, such as:

  • ipv4addr — the IP address string
  • mac — the MAC address string (when set)
  • configure_for_dhcp — the DHCP configuration boolean (when set, including False)

Other fields on the HostRecord that are set (e.g., extattrs) must continue to be included in the update payload as before.

Interaction points required by the tests
  • objects.IP.create(ip=..., mac=..., configure_for_dhcp=...) — creates a new IP object. This classmethod must accept at least the keyword arguments ip, mac, and configure_for_dhcp, and must produce an object whose serialized form omits host.
  • A HostRecord instance must expose an ip attribute (a list) to which new IP objects can be appended, and an extattrs attribute that can be assigned.
  • Calling host_record.update() must invoke the connector's update_object with:
    1. the record's ref,
    2. a payload dictionary containing ipv4addrs (a list of the serialized IP entries, each excluding host) and any other set fields such as extattrs,
    3. a third positional argument (return-fields / additional argument as previously passed).

Constraints

  • Do not otherwise change the set of fields serialized for IP objects; only ensure host is excluded from update payloads while still being retained on the in-memory object.
