Task Specification: Air Purifier Property Enhancements

Overview

Extend the AirPurifier device class located in the miio package (importable as from miio import AirPurifier) and its associated status object. Two new properties (illuminance and volume) must be exposed, one new setter method (set_volume) added, and the handling of certain optional properties must be made robust against missing/None values.

Public API Surface

AirPurifier class

Must provide the following methods (in addition to the existing ones):

  • set_volume(self, volume: int) — sets the device volume. Sends the command set_volume with the given value.
AirPurifier.status() return object

The object returned by status() must expose the following read-only properties. Each property derives its value from the device's raw state dictionary (the keys are given in parentheses):

  • illuminance — reads the raw state key bright.
  • volume — reads the raw state key volume.
  • led_brightness — reads the raw state key led_b.
  • buzzer — reads the raw state key buzzer.
  • temperature — reads the raw state key temp_dec.
  • child_lock — reads the raw state key child_lock.

Property Behavior

illuminance
  • When the raw state key bright holds an integer value, illuminance returns that integer unchanged.
  • When the raw state key bright is None, illuminance returns None.
volume
  • When the raw state key volume holds an integer value, volume returns that integer unchanged.
  • When the raw state key volume is None, volume returns None.
led_brightness
  • When the raw state key led_b holds a value, led_brightness returns a LedBrightness enum instance constructed from that value.
  • When the raw state key led_b is None, led_brightness returns None.
buzzer
  • When the raw state key buzzer equals the string 'on', buzzer returns True; when it equals 'off' it returns False.
  • When the raw state key buzzer is None, buzzer returns None.
temperature
  • When the raw state key temp_dec is None, temperature returns None. (Otherwise it derives a temperature value from that key, per existing behavior.)
child_lock
  • When the raw state key child_lock equals 'on', child_lock returns True; when it equals 'off' it returns False.

Setter Behavior

set_volume(volume)
  • Accepts integer values in the inclusive range 0 to 100.
  • Values 0, 35, and 100 (and any other value within range) are valid and cause the command set_volume to be sent with the given value.
  • If volume is less than 0 or greater than 100, raise AirPurifierException (importable from the same module as AirPurifier, e.g. from miio.airpurifier import AirPurifierException). No command is sent in this case.
set_favorite_level(level)
  • A favorite level of 10 is a valid value and must be accepted.
  • A favorite level of -1 (and any negative value) must raise AirPurifierException.

Dependency Requirement

The appdirs package must be declared as a project dependency.

Notes

  • The LedBrightness enum is already available (importable from the same module as AirPurifier).
  • The raw state dictionary is the mapping of property names to values returned by the device's get_prop command; the property values above read directly from that mapping.

03 Xiaomi Air Conditioning Companion Support 675 words · source specification

Task Specification: Xiaomi Air Conditioning Companion Support

Overview

Extend the AirConditioningCompanion device implementation in the miio package. The device is controlled by sending commands to a Xiaomi miIO device and interpreting its state responses.

Public API Surface

Module: miio.airconditioningcompanion

The following must be importable from this module:

  • Class AirConditioningCompanion (also importable from the top-level miio package).
  • Enums: OperationMode, FanSpeed, Power, SwingMode.
  • Constant: STORAGE_SLOT_ID.
Enums
  • OperationMode — must include at least the member Auto.
  • FanSpeed — must include at least the member Low.
  • Power — must include the members On and Off.
  • SwingMode — must include the member On.

The enum member values must be usable by the configuration-building logic described below (i.e. they must map to meaningful values used to construct a device command string).

Constant
  • STORAGE_SLOT_ID — a default storage-slot identifier used by the learn-related methods. Its concrete value is not directly asserted, but it must be a valid argument for the methods that accept a slot id and must be the value used when those methods are called without an explicit slot argument.

Device State Parsing

The device's raw state is a list of values obtained via the get_model_and_state command. The list contains three elements; element index 0 is the model/identifier string, element index 1 is a data string that encodes temperature, operation mode, and fan speed, and element index 2 is another value.

A status object is produced from this raw state and must expose (at minimum) the following read-only properties:

  • temperature
  • mode — value from OperationMode or None.
  • fan_speed — value from FanSpeed or None.
  • swing_mode — boolean.
Parsing rules exercised

Given a raw state where index 1 is the string '010201190280222221':

  • swing_mode is False.
  • fan_speed equals FanSpeed.Low.
  • mode equals OperationMode.Auto.
Missing-data handling

When the state element at index 1 is None:

  • temperature must be None.
  • mode must be None.
  • fan_speed must be None.

The status object must not raise when this element is None; it must gracefully return None for the affected properties.

Methods

learn(self, slot_id=STORAGE_SLOT_ID)

Starts IR learning for the given storage slot. Issues the start_ir_learn command. Callable with an explicit slot id or with no arguments (defaulting to STORAGE_SLOT_ID). Returns the device response.

learn_result(self)

Reads the IR learning result. Issues the get_ir_learn_result command. Returns the device response.

learn_stop(self, slot_id=STORAGE_SLOT_ID)

Stops IR learning for the given storage slot. Issues the end_ir_learn command. Callable with an explicit slot id or with no arguments (defaulting to STORAGE_SLOT_ID). Returns the device response.

send_ir_code(self, command)

Sends a raw IR code. Issues the send_ir_code command. Accepts a code string. Returns the device response.

send_command(self, command)

Sends a command to the device. Issues the send_cmd command with the given command string. Returns the device response.

send_configuration(self, model, power, operation_mode, target_temperature, fan_speed, swing_mode)

Builds a hexadecimal command string from the supplied air-conditioner configuration and sends it via the send_cmd command. Parameters:

  • model — a model identifier string (e.g. '0100010727' or '01000fffff').
  • power — a Power enum member (Power.On / Power.Off).
  • operation_mode — an OperationMode enum member.
  • target_temperature — a numeric temperature (e.g. 22.5).
  • fan_speed — a FanSpeed enum member.
  • swing_mode — a SwingMode enum member.

The method must construct a command consisting only of hexadecimal characters (digits 0-9 and letters a-f/A-F) and pass it as the command argument to send_cmd. This must succeed for both a "known" air-conditioner model (e.g. '0100010727') with power on and with power off, and for an "unknown" model (e.g. '01000fffff'). The value returned by the underlying command is returned to the caller.

Command Dispatch Notes

Methods call the device via named commands with the following argument shapes:

  • start_ir_learn, end_ir_learn: single-argument (slot id).
  • get_ir_learn_result: single argument.
  • send_ir_code: single argument.
  • send_cmd: argument list whose first element is the constructed/passed command string; that first element must be an all-hexadecimal string.

Each method returns whatever the corresponding device command returns.

Task Specification: Chuangmi IR Command Handling

Overview

You must implement IR command handling in the ChuangmiIr device class located at miio/chuangmi_ir.py. This class must support playing IR commands in two formats — raw (base64-encoded device-native commands) and pronto (hex-encoded Pronto codes) — including automatic format detection and an explicit typed-command format.

Public API

The module miio.chuangmi_ir must expose:

  • Class ChuangmiIr (a device class; it is used via multiple inheritance with a dummy device base in tests).
  • Exception class ChuangmiIrException.
Methods

All methods below are on ChuangmiIr.

The class relies on an internal method _ir_play_input_validation(self, payload) where payload is a dict. The methods that actually send a command must call this validation/send mechanism with a dict containing the keys 'code' (a base64-encoded string) and 'freq' (an integer frequency, or absent/None). This is the single point through which all playback ultimately dispatches. Concretely, the playback methods must build such a payload and pass it to the send mechanism.

pronto_to_raw(pronto, repeats=1) — static/class method

Callable as ChuangmiIr.pronto_to_raw(...) without an instance.

  • Input:

    • pronto: a string containing a Pronto hex code. The string may contain hex byte-words separated by spaces or be a continuous string of hex digits with no separators. Both forms represent the same data and must produce identical results.
    • repeats (optional, default 1): a non-negative integer specifying the number of repeat frames to include beyond the mandatory frame content.

  • Output: a 2-tuple (code, frequency) where:

    • code is a base64-encoded string of the raw Chuangmi IR command.
    • frequency is an integer carrier frequency (in Hz) derived from the Pronto code.

  • Behavior details:

    • The Pronto code encodes a carrier frequency, a "once" (lead-in) burst sequence, and a "repeat" burst sequence. The produced raw command must always contain at least one repeat frame regardless of the repeats argument — that is, the command always emits the burst content at least once even when repeats is 0, and appends repeats additional repeat frames on top of the guaranteed content. (See the concrete input/output pairs below to fix exact encoding.)
    • If repeats is negative, raise ChuangmiIrException.

play_raw(self, command, frequency=38400)

  • Input:

    • command: a base64-encoded raw IR command string.
    • frequency (optional, default 38400): integer carrier frequency.

  • Behavior: Sends the command by dispatching a payload whose 'code' is command and whose 'freq' is frequency. Returns the truthy result of the send.

  • Examples: playing raw command Z6VP...UA with default frequency dispatches code=Z6VP...UA, freq=38400; with explicit frequency 19200 it dispatches code=Z6VP...UA, freq=19200.

play_pronto(self, pronto, repeats=1)
  • Input: same as pronto_to_raw.
  • Behavior: Converts the pronto code to (code, frequency) via pronto_to_raw and dispatches that raw command with its derived frequency. Returns the truthy result of the send.
  • If repeats is negative, raise ChuangmiIrException.
play(self, command, frequency=None)

A single entry point that supports three modes based on the command string:

  1. Typed command form: If command contains type/argument fields separated by :, of the form:

    • raw:<base64code> or raw:<base64code>:<frequency>
    • pronto:<prontohex> or pronto:<prontohex>:<repeats>

    The prefix (raw or pronto) selects the handler. Remaining colon-separated fields are passed as arguments to the corresponding method (play_raw or play_pronto), with numeric arguments (frequency / repeats) interpreted as integers. When no extra argument is present, the method's default is used.

  2. Auto-detection form: If command is a plain string with no type prefix (and no explicit frequency argument that would apply), automatically determine whether it is a raw (base64) command or a pronto (hex) command and dispatch to the appropriate handler using default parameters.   • Message.parse(data: bytes, **context) -> parsed Parses a serialized binary message. The parse call receives keyword context including token (a 16-byte bytes value): e.g. Message.parse(serialized, token=token).

    The returned object must expose the decrypted, decoded payload at parsed.data.value.

Message Binary Format

A serialized message consists of a 32-byte header followed by the encrypted payload:

Field Size (bytes) Description
magic 2 Constant 0x2131
length 2 Big-endian total message length = 32 + length of encrypted payload
unknown 4 0x00000000
did 4 Device id
epoch 4 Timestamp field
checksum 16 MD5 of magic + length + unknown + did + epoch + token + encrypted_payload
payload variable The encrypted payload (encrypted with token via Utils.encrypt)

The encrypted payload, once decrypted with the provided token, yields UTF‑8 bytes representing a JSON object.

Payload Decoding Behavior

After decrypting the payload, the decoded value exposed at parsed.data.value must be a Python dict produced by parsing the payload as JSON. The parser must correctly handle the following cases:

  1. Valid JSON. A well-formed JSON object decodes into the corresponding dict. Example: payload {"id": 123456} → {"id": 123456} (so parsed.data.value['id'] == 123456).

  2. Trailing bytes after a null terminator. Some payloads contain a \x00 byte followed by one or more extra bytes, making the raw payload invalid JSON. The parser must strip the \x00 byte and everything after it (i.e., keep only the content up to but not including the last \x00) and then parse the remaining content as JSON. Example: payload {"id": 123456}\x00k → {"id": 123456}.

  3. Malformed JSON containing a doubled comma. Some payloads contain an invalid ,, sequence where a single comma was intended. When the payload fails to parse as JSON as-is, doubled commas (,,) must be corrected to single commas (,) so the content parses correctly. Example: payload {"id": 123456,,"otu_stat":0} → {"id": 123456, "otu_stat": 0} (so parsed.data.value['id'] == 123456 and parsed.data.value['otu_stat'] == 0).

In all three cases, parsed.data.value must be a non-empty dict.
