Task Specification: Block Slicing for Java Code

Overview

Build functionality that analyzes Java source code (given as a string) and finds the code "blocks" in it, along with the contiguous statement slicing "opportunities" it contains.

Public API

Create a module at program_slicing/decomposition/block_slicing.py that exposes two functions:

def determine_unique_blocks(source_code: str) -> <collection>
def get_opportunities_list(source_code: str) -> list

Each function accepts one string argument holding a fragment of Java source code.

determine_unique_blocks(source_code)

Given a fragment of Java code, identify the distinct code blocks present in it and return a collection whose length equals the number of unique blocks. Only the number of blocks (the len(...) of the return value) is observed.

Rules for counting blocks (derived from the required behavior)

Treat the whole fragment as a single enclosing (outer) block. Beyond that, each of the following language constructs introduces exactly one additional nested block, no matter whether the construct's body uses braces:

  • An if statement.
  • A for loop — both the classic for (init; cond; update) form and the enhanced for (T x : collection) form.
  • A while loop.
  • A synchronized block.
  • A construct body that has no surrounding braces (e.g., a single-statement for body) still counts as one nested block.

For each of the following single constructs, the length of the returned collection is 2 (one outer + one nested):

  • a lone if statement,
  • an enhanced for-each loop,
  • a while loop,
  • a synchronized block,
  • a classic for loop,
  • a loop that has no braces around its body.
Compound and multi-part constructs

  • A try / catch / finally statement yields 4 blocks in total: the outer enclosing block together with the try body, the catch body, and the finally body (one nested block for each clause body).

  • Code that contains an anonymous class instantiation yields 4 blocks in total. When an object is created with an anonymous class body (new Type() { ... }) that contains method definitions, the outer enclosing block is counted, plus one block for each method body defined inside that anonymous class body. (For a fragment consisting of a plain object creation followed by an anonymous class with two method bodies, the total is 4.)

  • A lambda expression that has a braced body ((s) -> { ... }) yields 2 blocks in total: the outer enclosing block plus the lambda body block.

get_opportunities_list(source_code)

Given a Java code fragment, compute the set of statement-range "slicing opportunities" and return them.

Structure of the returned value

Return a list that contains exactly one element. That single element is a list of 2-tuples (start_line, end_line), in which start_line and end_line are 1-based line numbers relative to the input string.

Line numbering: line 1 is the first physical line of the string. Note that the input strings start with a newline immediately after the opening triple-quote, so the first line of actual code is line 2.

What an opportunity means

Each (start_line, end_line) tuple denotes a contiguous, extractable span of statements — a candidate slice — with start_line being the first source line of the span and end_line being the last source line of the span. The complete result enumerates every valid contiguous statement range of this kind found in the code.

Ordering of results

Within the inner list, opportunities are ordered primarily by ascending start_line; among entries that share a start_line, the order is by ascending end_line.

Behavior of get_ranges

get_ranges() returns a sorted list of ((start_row, start_col), (end_row, end_col)) ranges that represent exactly which portions of the source belong to the slice. The rules below apply:

  • The set of source rows the slice covers is the union of all rows spanned by every added statement and every added range, except that a statement of type StatementType.statements contributes only its opening and closing boundary rows, and not the interior rows it merely encloses.
  • A statements block spanning start_point through end_point contributes:
    • its first row, from the block's start_point through the column immediately after the opening brace, so that only { is selected; and
    • its last row, as a range selecting the closing brace.
  • On every other covered row, the produced range starts at the column of that source line's first non-whitespace character and ends at the end column implied by the statement or explicit range covering that row. In the worked example below, the interior rows that are selected begin at column 12.
  • Coverage on the same row that overlaps or duplicates is merged or deduplicated.
  • The final ranges are sorted by start point in ascending order.

For example, take this source, in which the prefixes show the zero-based row indices:

0: (empty)
1:         class A {
2:             void main() {
3:                 int a = 0;
4:                 int b = 10;
5:                 a = b;
6:                 b += a;
7:             }
8:         }
9:         (empty)

and with these items registered:

  • a statements block that spans (2, 24) to (7, 13);
  • a variable statement that spans (3, 16) to (3, 26);
  • a variable statement that spans (4, 16) to (4, 27); and
  • a full range from (5, 16) to (5, 22);

This result has no trailing newline.

3.3 __is_slicing_criterion(a, b)

This predicate is sensitive to role and to statement type. It is True exactly when all of the following hold:

  1. b.statement_type is StatementType.variable;
  2. a.name == b.name; and
  3. either:
    • a.statement_type is StatementType.assignment, or
    • a is b, meaning the variable-declaration statement is being compared with itself.

As a result:

  • pairing a variable-declaration statement with itself is a valid criterion;
  • pairing an assignment statement with itself is not a valid criterion;
  • an assignment of the same name as the first argument together with a variable declaration as the second argument is valid;
  • that assignment/declaration pair, reversed, is not valid;
  • two distinct variable-declaration objects do not qualify merely because their names match; and
  • statements whose names differ are never criteria for one another.

  • Definitions of functions or methods, together with function entry statements: StatementType.FUNCTION.
  • Scopes and blocks of statements: StatementType.SCOPE.
  • Variable declarations, including declarations tied to enhanced loops and exception parameters: StatementType.VARIABLE.

  • Exit points, returns being one example: StatementType.EXIT.
  • Goto-like control transfers, break and continue being examples: StatementType.GOTO.
  • Any statement that is otherwise unclassified/default: StatementType.UNKNOWN.

The rename must be applied consistently in Java parsing — nested scopes, loop bodies, try-with-resources and multiple-catch structures included — as well as in every graph derived from parsed statements.

Every comparison, branch, default, and collection filter that consumes StatementType must use the matching uppercase member while keeping its previous logic. Specifically:

  • Discovery of variable statements continues to select statements of type StatementType.VARIABLE.

  • Backward slicing continues to retain enclosing/default statements represented by StatementType.SCOPE and StatementType.UNKNOWN under the same conditions as before.
  • Graph conversion, basic-block construction, decomposition, and complete-computation slicing must continue to produce the same externally observable results apart from the renamed enum identifiers.
Semantics of the Slicing Criterion

is_slicing_criterion(source, target) must return True exactly when all of the following conditions hold:

  1. the value of source.statement_type is either StatementType.VARIABLE or StatementType.ASSIGNMENT;
  2. the value of target.statement_type is StatementType.VARIABLE; and
  3. source.name == target.name.

Object identity does not constitute an independent reason to reject a criterion. As a result:

  • An assignment compared against itself is not a criterion, since the target is an assignment rather than a variable declaration.
  • An assignment and a distinct variable statement having the same name form a criterion.
  • A variable statement compared against itself is a criterion.
  • Distinct variable statements likewise form a criterion when their names match.
  • Names that differ, a non-variable target, or a source of any other statement type produce False.

Compatibility of CodeLinesSlicer

CodeLinesSlicer must keep accepting a list of source-code lines via its constructor and must keep supporting add_statement(statement). The type-dependent handling of ranges must retain its existing behavior under the renamed members:

  • Boundary-only range handling applies to StatementType.SCOPE.
  • Full-range handling applies to StatementType.UNKNOWN.
  • Beginning-range handling applies to every other statement type.

Range aggregation and the resulting ranges, lines, and slice text must keep their existing behavior.

Compatibility of BasicBlock

  • BasicBlock() constructs an empty block.

check_slice checks a supplied slice against line-count constraints:

  • The slice's own number of lines is read by the function.
  • If min_amount_of_lines is provided, the function returns True only if the slice's number of lines is greater than or equal to min_amount_of_lines; in any other case the constraint fails.
  • If max_amount_of_lines is provided, the function returns True only if the slice's number of lines is less than or equal to max_amount_of_lines; in any other case the constraint fails.
  • If all of the provided constraints are satisfied, the function returns True; if any provided constraint is violated, it returns False.
Concrete Requirement in Practice

For a slice that spans exactly 6 lines:

  • The call check_slice(slice, min_amount_of_lines=6, max_amount_of_lines=6) returns True.
  • The call check_slice(slice, min_amount_of_lines=7, max_amount_of_lines=7) returns False (the slice has fewer lines than the minimum).
  • The call check_slice(slice, min_amount_of_lines=5, max_amount_of_lines=5) returns False (the slice has more lines than the maximum).

Main Change

The line-count calculation must be carried out by the slice object itself and exposed through it, instead of being computed inside check_slice from a passed-in statement collection. In order to evaluate the bounds, check_slice consumes the slice's reported line count.
