01 Build a Python package named grafana_api that offers a client interface for interacting with a Grafana API server. 353 words · source specification, reworded by GLM-5.3-Flash

Task Description

Goal

Build a Python package named grafana_api that offers a client interface for interacting with a Grafana API server.

Public API

Module grafana_api.grafana_face

This module must expose a class named GrafanaFace.

Constructor of GrafanaFace:

GrafanaFace(auth, host='localhost', url_path_prefix='', protocol='https', ...)
  • auth: authentication credentials. Must accept a 2-tuple such as ('admin', 'admin') that represents username/password basic-auth credentials.
  • host: the server's hostname (a string).
  • url_path_prefix: a string used as a path prefix that is prepended to API endpoints (it may be an empty string).
  • protocol: the connection protocol as a string (e.g. 'https').

The constructor must accept these as keyword arguments, and it must construct successfully without contacting any server.

Method on GrafanaFace:

  • find_user(login_or_email): Performs a lookup of a user by their login name or email address. It accepts a single string argument (for example an email address such as 'test@test.com'). The method must be callable on a GrafanaFace instance and must issue the corresponding lookup call through the underlying API layer.
Module grafana_api.grafana_api

This module must expose a class named GrafanaAPI.

GrafanaAPI.__getattr__:

GrafanaAPI must implement dynamic attribute access by means of __getattr__. Reading an attribute on a GrafanaAPI instance resolves to a callable that performs the corresponding HTTP request. This mechanism constitutes the pathway through which GrafanaFace methods (such as find_user) delegate their work — calling a GrafanaFace method must ultimately trigger attribute resolution on the underlying GrafanaAPI object and invoke the resulting callable.

Required Behavior

  • Creation of a GrafanaFace using the tuple credentials and the listed keyword arguments must not raise.
  • Calling find_user with a string argument must complete successfully when the underlying GrafanaAPI attribute-access/request layer is available, with the actual request delegated through GrafanaAPI.__getattr__.

Packaging

The grafana_api package must be importable in such a way that:

  • an import of the form from grafana_api.grafana_face import GrafanaFace works.
  • grafana_api.grafana_api.GrafanaAPI.__getattr__ is a patchable attribute — in other words, GrafanaAPI defines __getattr__.

Remarks

For the behavior under test, no live network interaction is required; higher-level methods rely on the request-dispatch layer (GrafanaAPI.__getattr__) as their integration point.

02 Implement a client library for the Grafana API that offers a dynamic, attribute-based interface for making HTTP requests to a Grafana server. 276 words · source specification, reworded by GLM-5.3-Flash

Task Description

Goal

Implement a client library for the Grafana API that offers a dynamic, attribute-based interface for making HTTP requests to a Grafana server.

Public API

Create a module located at grafana_api/grafana_api.py that contains a class called GrafanaAPI.

The GrafanaAPI Class

The class must expose dynamic attribute access through a __getattr__ method. Accessing an attribute on an instance of GrafanaAPI invokes __getattr__, which returns a callable.

Expected Behavior

The key behavioral contract being exercised is the following:

  1. Accessing an arbitrary attribute on a GrafanaAPI instance triggers __getattr__; the method then returns a callable object.
  2. Invoking that returned callable performs the underlying request operation and returns the response payload directly — meaning the value returned by calling the object that __getattr__ produced is the response body itself.

Concretely, the value obtained from calling the callable that __getattr__ returns is the raw response content (e.g., a JSON string / decoded body), not an intermediate response wrapper object. Put differently:

instance.<some_attr>(...)  ->  returns the response body

The code that consumes the library depends on the invocation result being the body payload directly, without having to access a .content (or similar) attribute on it.

Constraints

  • The implementation must be importable as from grafana_api.grafana_api import GrafanaAPI, and it must support patching of GrafanaAPI.__getattr__.
  • When a callable produced by __getattr__ is invoked, the result must be the response body value itself.

Compatibility

  • The library must work under both Python 2 and Python 3.

Out of Scope

Beyond what is described above, do not add any behavior. The only contract required is the attribute-access-returns-callable and callable-returns-body one.

Update the Grafana API client library so that it supports disabling SSL certificate verification on HTTP requests. A verify option must be exposed by the client and propagated to the underlying HTTP request calls.

Public API

grafana_api.grafana_face.GrafanaFace

The GrafanaFace class, importable from grafana_api.grafana_face, must accept a keyword argument verify in its constructor in addition to its existing parameters. The invocation form observed for the constructor is:

GrafanaFace(auth, host='localhost', url_path_prefix='', protocol='https', verify=False)
  • auth: the first positional argument. Its value may be a (username, password) tuple (basic-auth style) or a token string.
  • host, url_path_prefix, protocol: connection parameters that already exist.
  • verify: a new parameter that controls SSL certificate verification. When it is not supplied, it defaults to True. When it is passed explicitly (e.g. verify=False), the value given must be stored and used for all outgoing HTTP requests.

Once constructed, the GrafanaFace instance must expose an attribute api. The api object must:

  • expose an attribute auth that holds the authentication value derived from the auth argument (for a (username, password) tuple, this is the tuple itself),
  • expose an attribute s that represents the HTTP session object whose get method is used to perform GET requests.
Behaviour of Requests

When a GET request over HTTP is issued by an API operation via api.s.get, the call must be made with exactly the following keyword arguments in addition to the URL:

api.s.get(url, auth=<auth>, headers=<headers>, json=<json>, verify=<verify>)

where:

  • url is the fully composed URL of the request, e.g. https://localhost/api/users/lookup?loginOrEmail=test@test.com.
  • auth is the authentication value (the (username, password) tuple in the case where tuple auth was supplied).
  • headers is None when the request needs no headers.
  • json is None when no body is sent.
  • verify is the value provided to the verify parameter of the GrafanaFace constructor (e.g. False).

The verify value that is passed at construction time must flow unchanged into every GET request of this kind.

https://localhost/api/users/lookup?loginOrEmail=test@test.com

The request must be issued exactly once, by means of api.s.get, with the keyword arguments described above (auth, headers=None, json=None, and the constructor's verify value).

The return value of the method is the parsed JSON body of the response.

Constraints

  • The URL query parameter for the email/login lookup must not be URL-escaped in a manner that alters test@test.com; the value occurs literally in the query string.
  • No behavior beyond propagating verify and carrying out the described GET request is required.
07 Authentication Handling for the Grafana API 453 words · source specification, reworded by GLM-5.3-Flash

Task Specification: Authentication Handling for the Grafana API

Overview

You must implement the handling of authentication credentials for a Grafana API client library. The client accepts an authentication credential, and the appropriate authentication mechanism must be selected according to the type of credential provided.

Public API Surface

Module: grafana_api.grafana_api

A class named TokenAuth must be defined. The class represents token-based authentication. It must be possible to import it as:

from grafana_api.grafana_api import TokenAuth

TokenAuth should be an authentication handler that is callable and compatible with the requests library authentication interface (i.e., it can be used as the auth argument to a requests request). The token credential is accepted by its constructor.

Module: grafana_api.grafana_face

A class named GrafanaFace must be defined. It must be possible to import it as:

from grafana_api.grafana_face import GrafanaFace
Constructor Signature
GrafanaFace(auth, host='localhost', url_path_prefix='', protocol='https', ...)

auth, the first positional parameter, is the authentication credential. The parameters host, url_path_prefix, and protocol are parameters that are supported as keyword arguments.

Attributes

An instance of GrafanaFace must expose an attribute api that is the underlying API client object. This API client object must expose:

  • An attribute auth that holds the resolved authentication handler (see the behavior below).
  • An attribute s that holds a requests-style session object used to perform HTTP requests.

Behavior Requirements

The type of the auth credential passed to GrafanaFace determines which authentication mechanism is selected:

  1. Basic authentication — If auth is a tuple (for example, a (username, password) pair), the auth attribute resolved on the API client must be an instance of requests.auth.HTTPBasicAuth, constructed using the tuple's elements.

  2. Token authentication — If auth is not a tuple (for example, a plain string token), the auth attribute resolved on the API client must be an instance of TokenAuth, constructed from the credential that was given.

The resolved authentication handler must be stored on the API client's own auth attribute (not on the session object), so that it is available for use when requests are issued.

Request Behavior

When the API client performs an HTTP request through its session object (s), the resolved authentication handler must be passed as the auth argument to the session's request methods.

As an example: a lookup that issues a GET request, when called, must invoke the session's get method with the target URL and the keyword arguments auth (the resolved authentication handler), headers, json, and verify.

When a client is constructed with a (username, password) tuple, the auth passed to the session's requests is the corresponding HTTPBasicAuth — equivalently the (username, password) tuple when compared for equality — and verify reflects the configured TLS verification setting.

Task Specification: Client Library for the Grafana API

Your task is to implement the behavior of a Python client library for the Grafana API. The exact behavior required is specified below.

Module Structure and Public API

1. Exception classes — grafana_api/grafana_api.py

The following exception classes must be defined by this module, all of them importable from grafana_api.grafana_api:

  • GrafanaClientError
  • GrafanaServerError
  • GrafanaUnauthorizedError
  • GrafanaBadInputError

These exception types are raised by the HTTP layer depending on the HTTP status code of a Grafana API response:

  • An HTTP status of 500 (server-side errors, i.e. 5xx) → raise GrafanaServerError
  • An HTTP status of 401 → raise GrafanaUnauthorizedError
  • An HTTP status of 400 → raise GrafanaBadInputError

Overview

Your task is to implement methods on a Grafana API client that deal with annotations. Access to the annotations functionality goes through an annotations attribute on the main client object. API Surface

The annotations component is accessible as client.annotations (where client is the main Grafana client instance). The following methods must be exposed.

get_annotation(...)

Signature (all arguments are keyword arguments, and all of them are optional):

get_annotation(time_from=None, time_to=None, alert_id=None, dashboard_id=None, panel_id=None, user_id=None, ann_type=None, tags=None, limit=None)

  • The tags parameter is a list of tag strings; it must be placed as-is in the request body under a tags field (a JSON array of strings).
  • The remaining arguments go into the JSON request body (e.g. time range, region flag, annotation text).
  • Returns the parsed JSON response (a dictionary) containing fields such as endId, id, and message.

update_annotation(annotations_id, time_from=None, time_to=None, is_region=None, tags=None, text=None)

  • The tags parameter is a list of tag strings, placed as-is (a JSON array of strings) in the request body.
