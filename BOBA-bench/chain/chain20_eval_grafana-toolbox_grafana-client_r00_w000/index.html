Objective

Implement a Python package named grafana_api that provides a client interface for interacting with a Grafana API server.

  • url_path_prefix: a path prefix string prepended to API endpoints (may be an empty string).
  • protocol: connection protocol string (e.g. 'https').

The constructor must accept these as keyword arguments and construct successfully without contacting any server.

Must expose a class named GrafanaAPI.

GrafanaAPI.__getattr__:

GrafanaAPI must implement dynamic attribute access via __getattr__. Attribute access on a GrafanaAPI instance resolves to a callable that performs the corresponding HTTP request. This mechanism is the pathway through which GrafanaFace methods (such as find_user) delegate their work — calling a GrafanaFace method must ultimately trigger attribute resolution on the underlying GrafanaAPI object and invoke the resulting callable.

Behavioral Requirements

  • Creating a GrafanaFace with the tuple credentials and the listed keyword arguments must not raise.
  • Calling find_user with a string argument must complete successfully when the underlying GrafanaAPI attribute-access/request layer is available, delegating the actual request through GrafanaAPI.__getattr__.

  • from grafana_api.grafana_face import GrafanaFace works.
  • grafana_api.grafana_api.GrafanaAPI.__getattr__ is a patchable attribute (i.e., GrafanaAPI defines __getattr__).

Notes

No live network interaction is required for the behavior under test; the request-dispatch layer (GrafanaAPI.__getattr__) is the integration point that higher-level methods rely upon.

02 Implement a Grafana API client library that provides a dynamic, attribute-based interface for making HTTP requests to a Grafana server. 261 words · source specification

Objective

Implement a Grafana API client library that provides a dynamic, attribute-based interface for making HTTP requests to a Grafana server.

Public API Surface

Create a module at grafana_api/grafana_api.py containing a class named GrafanaAPI.

Class: GrafanaAPI

The class must expose dynamic attribute access via a __getattr__ method. When an attribute is accessed on an instance of GrafanaAPI, __getattr__ is invoked and returns a callable.

Behavior

The key behavioral contract exercised is:

  1. Accessing an arbitrary attribute on a GrafanaAPI instance triggers __getattr__, which returns a callable object.
  2. Invoking that returned callable performs the underlying request operation and returns the response payload directly — that is, the return value of calling the object produced by __getattr__ is the response body itself.

Specifically, the value obtained from calling the callable returned by __getattr__ is the raw response content (e.g., a JSON string / decoded body), not an intermediate response wrapper object. In other words:

instance.<some_attr>(...)  ->  returns the response body

The consuming code relies on the invocation result being the body payload directly, without needing to access a .content (or similar) attribute on it.

Constraints

  • The implementation must be importable as from grafana_api.grafana_api import GrafanaAPI and support patching of GrafanaAPI.__getattr__.
  • The result of invoking a __getattr__-produced callable must be the response body value itself.

Compatibility

  • The library must function under both Python 2 and Python 3.

Out of Scope

Do not add any behavior beyond what is described above. Only the attribute-access-returns-callable and callable-returns-body contract is required.

Task Specification: Grafana API Authentication Handling

Overview

You must implement authentication credential handling for a Grafana API client library. The client accepts an authentication credential and must select the appropriate authentication mechanism based on the type of credential provided.

Public API Surface

Module: grafana_api.grafana_api

Define a class named TokenAuth. This class represents token-based authentication. It must be importable as:

from grafana_api.grafana_api import TokenAuth

TokenAuth should be a callable authentication handler compatible with the requests library authentication interface (i.e., it can be used as the auth argument to a requests request). Its constructor accepts the token credential.

Module: grafana_api.grafana_face

Define a class named GrafanaFace. It must be importable as:

from grafana_api.grafana_face import GrafanaFace
Constructor signature
GrafanaFace(auth, host='localhost', url_path_prefix='', protocol='https', ...)

The first positional parameter, auth, is the authentication credential. The parameters host, url_path_prefix, and protocol are supported as keyword arguments.

Attributes

A GrafanaFace instance must expose an attribute api which is the underlying API client object. That API client object must expose:

  • An attribute named auth, holding the resolved authentication handler (see behavior below).
  • An attribute named s, holding a requests-style session object used to perform HTTP requests.

Required Behavior

The authentication mechanism is selected based on the type of the auth credential passed to GrafanaFace:

  1. Basic authentication — When auth is a tuple (e.g., a (username, password) pair), the resolved auth attribute on the API client must be an instance of requests.auth.HTTPBasicAuth, constructed from the tuple's elements.

  2. Token authentication — When auth is not a tuple (e.g., a plain string token), the resolved auth attribute on the API client must be an instance of TokenAuth, constructed from the given credential.

The resolved authentication handler must be stored on the API client's own auth attribute (not on the session object), so that it is available for use when issuing requests.

Request Behavior

When the API client performs an HTTP request through its session object (s), it must pass the resolved authentication handler as the auth argument to the session's request methods.

An example: calling a lookup that issues a GET request must invoke the session's get method with the target URL and the keyword arguments auth (the resolved authentication handler), headers, json, and verify.

For a client constructed with a (username, password) tuple, the auth passed to session requests is the corresponding HTTPBasicAuth — equivalently the (username, password) tuple when compared for equality — and verify reflects the configured TLS verification setting.
