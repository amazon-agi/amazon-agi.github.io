Task Specification: Batch Dependent Entities Utility

Objective

Implement a utility function that groups a flat list of Atlas entity JSON dictionaries into batches of a bounded size, while ensuring that entities connected through relationships are kept together in the same batch.

Public API Surface

Add a function named batch_dependent_entities to the module pyapacheatlas.core.util. It must be importable as:

from pyapacheatlas.core.util import batch_dependent_entities

The module pyapacheatlas.core.util must also continue to expose the existing GuidTracker class (importable from the same location).

Signature
def batch_dependent_entities(entities, batch_size=...):
    ...
  • entities: a list of entity dictionaries (each is the JSON/dict representation of an Atlas entity).
  • batch_size: an integer keyword argument specifying the maximum number of entities allowed in any single output batch.
Return Value

Returns a list of batches. Each batch is a list (or collection) of the input entity dictionaries. The concatenation of all batches contains every input entity exactly once.

Input Entity Structure

Each entity dictionary contains at least:

  • A guid field, which uniquely identifies the entity. For entities created within the same upload, guids are typically small integers or numeric-looking strings (e.g., 0, 1, -1, "-1").
  • A relationshipAttributes field: a mapping from relationship names to relationship references. Each referenced value is itself a dictionary that may contain a guid field pointing to another entity.

Dependency Semantics

Two entities are considered dependent (must be placed in the same batch) when one references the other through a relationship guid, where that referenced guid is a numeric guid (an integer, or a string that represents an integer such as "-1").

  • A relationship reference whose guid is numeric is treated as a pointer to another entity within the same upload set. Entities linked by such references form a connected group and must remain together.
  • A relationship reference whose guid is not numeric (e.g., a real persisted guid like "abc-123") is not treated as an in-upload dependency. It creates no grouping obligation between entities and is ignored for the purpose of batching.

Dependency grouping is transitive and undirected: if A relates to B and B relates to C (via numeric guids), then A, B, and C all belong to the same connected group, regardless of the direction of the relationship or the order in which entities appear in the input list. The input order is not guaranteed to place related entities adjacently.

Batching Rules

  1. Compute connected groups of entities based on numeric-guid relationships as described above. Entities with no qualifying numeric-guid relationship form singleton groups.
  2. Each connected group must be kept intact within a single batch (never split across batches).
  3. Pack these groups into batches such that no batch exceeds batch_size entities. Independent (single or small) groups may be combined into the same batch as long as the total count in that batch stays within batch_size.
  4. The goal is to produce a minimal set of batches consistent with the above constraints (i.e., avoid creating more batches than necessary; fill batches with independent groups where they fit).

Behavioral Examples

  • No dependencies: Given 10 fully independent entities and batch_size=2, the result is 5 batches of 2 entities each.

  • With dependencies: Given 16 entities where some form connected groups through numeric-guid relationships (e.g., one connected group of 7 entities, one connected group of 3 entities, and the rest independent) and batch_size=7, the result is 3 batches: the 7-entity group fills one batch, the 3-entity group plus enough independent entities fills another, and remaining independent entities fill the last — with no batch exceeding 7.

  • Non-numeric guid reference: Given 4 entities where one entity has a relationship pointing to a non-numeric guid (e.g., "abc-123", which is a reference to a pre-existing entity not in the upload set), that relationship does not create a dependency. With batch_size=2, entities that would otherwise be grouped only through such a non-numeric reference remain ungrouped; the result is 2 batches (any genuine numeric-guid dependency is still honored).

Notes

  • Only relationships whose referenced guid is numeric (integer or integer-valued string, including negative values) establish grouping between entities.
  • A group's size may exceed batch_size in principle; the tests only exercise groups that fit within the given batch_size, so grouped entities always fit in one batch under the exercised conditions.
