Task Specification: ANSI Color Management Module

Objective

Create a new module archey.colors that centralizes ANSI escape-code color management, and integrate it into the existing entry (Disk, RAM) and Output components so they use this module for coloring.

The Colors Class

Create a class named Colors in archey/colors.py. This class serves both as a set of named color constants and as a small utility for producing/selecting ANSI escape codes.

Named color members

Colors must expose members whose string representation resolves to specific ANSI escape sequences. Each member's __str__ must return a full ANSI escape sequence of the form \x1b[<attrs>m.

The following members are required, with these exact string representations:

Member str(...) value
Colors.CLEAR \x1b[0m
Colors.CYAN_BRIGHT \x1b[1;36m
Colors.GREEN_NORMAL \x1b[0;32m
Colors.YELLOW_NORMAL \x1b[0;33m
Colors.RED_NORMAL \x1b[0;31m

The "attributes" of a member (the part between \x1b[ and m) are:

  • CLEAR → 0
  • CYAN_BRIGHT → 1;36
  • GREEN_NORMAL → 0;32
  • YELLOW_NORMAL → 0;33
  • RED_NORMAL → 0;31

str() applied to any member must wrap that member's attributes as \x1b[<attrs>m.

Static/utility methods

Colors.escape_code_from_attrs(attributes)

  • Accepts a string of semicolon-separated ANSI attributes (e.g. '0;31' or '0;31;45').
  • Returns the full escape sequence string \x1b[<attributes>m.
  • Examples:
    • escape_code_from_attrs('0;31') → '\x1b[0;31m'
    • escape_code_from_attrs('0;31;45') → '\x1b[0;31;45m'

Colors.get_level_color(value, warning_threshold, danger_threshold)

  • Selects a color member based on where value falls relative to two ascending thresholds.
  • Returns:
    • Colors.GREEN_NORMAL when value is below warning_threshold.
    • Colors.YELLOW_NORMAL when value is at/above warning_threshold but below danger_threshold.
    • Colors.RED_NORMAL when value is at/above danger_threshold.
  • Examples:
    • get_level_color(25, 50, 75) → Colors.GREEN_NORMAL
    • get_level_color(34, 33, 66) → Colors.YELLOW_NORMAL
    • get_level_color(90, 33, 66) → Colors.RED_NORMAL

Integration Requirements

Disk entry (archey/entries/disk.py)

The value produced by Disk().value must embed the appropriate level color as a raw ANSI escape sequence, chosen according to disk usage level, such that:

  • Regular/low usage produces a substring equal to str(Colors.GREEN_NORMAL).
  • Warning usage produces a substring equal to str(Colors.YELLOW_NORMAL).
  • (These substrings appear alongside the numeric usage figures already present in the output.)
RAM entry (archey/entries/ram.py)

The value produced by RAM().value must embed the appropriate level color as a raw ANSI escape sequence, chosen according to RAM usage level, such that:

  • Low usage produces a substring equal to str(Colors.GREEN_NORMAL).
  • Warning usage produces a substring equal to str(Colors.YELLOW_NORMAL).
  • Danger usage produces a substring equal to str(Colors.RED_NORMAL).
Output component (archey/output.py)

The Output class assembles displayed result lines. Its behavior with respect to color must be:

  • archey.output must expose a module-level COLOR_DICT mapping distributions (keys of type Distributions, e.g. Distributions.DEBIAN) to a list of color strings. This mapping no longer contains any special 'clear' key — the clearing sequence is obtained from Colors.CLEAR.

  • archey.output must expose a module-level LOGOS_DICT mapping distributions to logo template strings (also without any special 'clear' key).

  • When an entry (key + value) is appended and rendered into Output.results, the resulting line must be formatted as:

    <first color of the distribution's COLOR_DICT entry><KEY>:<Colors.CLEAR> <VALUE>

    Concretely, for a Debian color list ['COLOR_0', 'COLOR_1'], appending key KEY with value VALUE yields the single result string:

    'COLOR_0KEY:' + str(Colors.CLEAR) + ' VALUE'

    (i.e. the key is prefixed with the first color entry, followed by :, then the clear sequence from Colors.CLEAR, a space, and the value.)

  • Output construction must resolve the current distribution via archey.output.distro.id (which returns a plain distribution id string such as 'debian', 'opensuse', or an unrecognized id like 'an-unknown-distro-id') and must handle known distributions, unknown distributions, and Windows Subsystem for Linux cases without error.

Constraints

  • The Colors members' string forms and the utility method outputs must match exactly the escape sequences specified above.
  • Components that previously relied on a 'clear' key inside COLOR_DICT/LOGOS_DICT must instead obtain the clear sequence from Colors.CLEAR.

Task Specification: Distribution Detection in archey.output

Overview

Implement/modify the Output class in the module archey.output so that it determines the current Linux distribution, including detecting Windows Subsystem for Linux (WSL) and matching distributions via the os-release ID_LIKE field.

  • distro — a module exposing at least these callables:

    • distro.os_release_attr(...) — used elsewhere for release attributes.
  • re — the standard regular expression module.

    def __init__(self):
        ...

After construction, the instance must expose:

  • self.distribution — a Distributions enum member (see below).
  • self.colors_palette — a list of color entries corresponding to the detected distribution, taken from COLOR_DICT[<distribution>].
Enum Distributions

An enum accessible as Distributions (imported into the test scope from the project's distributions module). Members referenced include at least:

  • Distributions.WINDOWS
  • Distributions.UBUNTU
  • Distributions.LINUX_MINT
  • Distributions.SLACKWARE
  • Distributions.LINUX (generic fall-back)
Mapping COLOR_DICT

A dictionary mapping each Distributions member to its list of color entries.

Required Behavior of Output.__init__

The constructor determines self.distribution using the following ordered logic:

  1. Kernel release / WSL detection. Obtain the kernel release string via check_output (a single string, e.g. 'X.Y.Z-R-ARCH\n', possibly with a trailing newline). Inspect this string (using re) to determine whether it indicates a Windows Subsystem for Linux environment.

    • If the kernel release string indicates WSL (i.e., it contains a Microsoft marker, as in 'X.Y.Z-R-Microsoft\n'), then self.distribution is Distributions.WINDOWS, regardless of distro.id() / distro.like().

  2. Direct distribution id match. If not WSL, call distro.id(). If the returned identifier corresponds to a known Distributions member, use that member.

  3. ID_LIKE fall-back. If distro.id() returns an empty string or an identifier that does not correspond to any known Distributions member, call distro.like(). This returns a possibly-empty, possibly space-separated list of identifiers (e.g., 'ubuntu' or 'linuxmint debian').

    • Split the value on whitespace and, in order, take the first token that corresponds to a known Distributions member. Use that member.
    • Example: 'ubuntu' → Distributions.UBUNTU.
    • Example: 'linuxmint debian' → Distributions.LINUX_MINT (the first recognized token wins).

  4. Generic fall-back. If neither distro.id() nor distro.like() yields a recognized distribution (both effectively empty / unknown), self.distribution is Distributions.LINUX.

Color Palette

Once self.distribution is determined, self.colors_palette must be set to COLOR_DICT[self.distribution] (a list). Its length must equal the length of that mapping's entry for the detected distribution.

Notes / Edge Cases

  • The kernel release string may include a trailing newline; detection must work whether or not surrounding quoting/whitespace is present.
  • Detection of WSL takes priority over both the direct id match and the ID_LIKE fall-back.
  • An unknown distro.id() (empty string or unrecognized value) must not raise; it must proceed to the ID_LIKE step.
  • An empty distro.like() combined with an unknown distro.id() must resolve to Distributions.LINUX.

The Configuration class currently exposes a public method used to load configuration from a given directory path. This method must be renamed to be a protected method (prefixed with a single underscore).

API Surface

The Configuration class must provide the following instance method:

def _load_configuration(self, directory)
  • Name: _load_configuration (with a leading underscore).
  • Parameter: directory — a path (string) to a directory containing a config.json file to load configuration from.
  • Behavior: Identical to the previously public loading method. It reads and merges configuration values from a config.json file located in the provided directory.

There must no longer be a public load_configuration method; the only way to invoke this behavior (from within the class or externally) is via _load_configuration.

Behavioral Requirements

The _load_configuration(directory) method must:

  1. Load and merge configuration values — Given a directory that contains a config.json file, read that file and merge its key/value settings into the instance's internal configuration state. After loading a config file that sets a given option, querying that option must reflect the loaded value.

  2. Respect the allow_overriding setting — The instance holds a configuration option named allow_overriding (a boolean). When allow_overriding is False, loading a config.json file must not modify the existing configuration state: all configuration values must remain exactly as they were before the call. When allow_overriding is True (or otherwise not disabling overriding), loaded values take effect as normal.

Constraints

  • Do not change any other behavior of the Configuration class beyond the method rename described above.
  • The method remains an instance method callable as configuration._load_configuration(directory).
