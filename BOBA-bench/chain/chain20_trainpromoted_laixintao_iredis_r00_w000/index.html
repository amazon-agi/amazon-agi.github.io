Task Specification: Redis Command Grammar for CLUSTER ADDSLOTS

Objective

Provide a grammar object that can parse Redis command strings and extract named tokens from them. Specifically, the grammar must correctly parse the CLUSTER ADDSLOTS command with one or more integer slot arguments.

Public API Surface

Create a module importable as:

from iredis.redis_grammar import redis_grammar

The redis_grammar object must expose a match(command: str) method with the following behavior:

  • redis_grammar.match(command) returns a match object when command is a valid command, or None when it is not.
  • When a match succeeds, the returned match object must provide a variables() method that returns a mapping (dict-like) from named token strings to their matched string values. Callers access values via .get(token_name).

This means match and variables should behave like the API of the prompt_toolkit compiled-grammar system (prompt_toolkit.contrib.regular_languages.compiler.compile), whose match(...) returns an object with a .variables() method exposing captured named groups. Using that library to build the grammar is the natural approach.

Required Grammar Behavior

The grammar must recognize the CLUSTER ADDSLOTS command followed by a whitespace-separated list of one or more slot values.

Named tokens to capture
  • command_slots: captures the command keyword portion, which for this command is the string cluster addslots.
  • slots: captures the entire remaining argument portion as a single string — i.e. all slot arguments joined exactly as they appear in the input (space-separated), without leading/trailing whitespace.
Matching rules
  • A slot argument is valid only if it is a sequence of decimal digits (an integer). Non-numeric arguments are invalid.
  • The slots portion must consist of one or more integer arguments separated by single spaces.
  • If all slot arguments are integers, the command matches, and:
    • command_slots equals "cluster addslots".
    • slots equals the full space-separated argument string (e.g. "1" or "1 2 3 4").
  • If any slot argument is not a valid integer, the entire command must fail to match (match returns None).
Examples of expected outcomes
Input Result
cluster addslots 1 match; command_slots="cluster addslots", slots="1"
cluster addslots 1 2 3 4 match; command_slots="cluster addslots", slots="1 2 3 4"
cluster addslots 1 a no match (None)
cluster addslots a no match (None)
cluster addslots a 2 no match (None)
cluster addslots abc no match (None)

Notes

  • The grammar must fully match the command string (a partial match that leaves trailing non-integer content must be treated as a non-match).
  • The comparison for captured token values is against the raw substrings as shown above.
