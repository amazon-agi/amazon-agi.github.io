Task Specification: Grammar for the Redis Command CLUSTER ADDSLOTS

Goal

Supply a grammar object that can parse strings containing Redis commands and extract named tokens from them. In particular, the grammar must parse the CLUSTER ADDSLOTS command correctly when it carries one or more integer slot arguments.

Public API

Create a module that can be imported as:

from iredis.redis_grammar import redis_grammar

The redis_grammar object must expose a match(command: str) method whose behavior is as follows:

  • redis_grammar.match(command) returns a match object if command is a valid command, or None if it is not.
  • On a successful match, the match object that gets returned must provide a variables() method; this method returns a mapping (dict-like) of named token strings to their matched string values. Values are accessed by callers via .get(token_name).

In other words, match and variables should behave the same as the API of the prompt_toolkit compiled-grammar system (prompt_toolkit.contrib.regular_languages.compiler.compile), in which match(...) returns an object carrying a .variables() method that exposes the captured named groups. Building the grammar with that library is the natural approach.

Grammar Behavior Requirements

The grammar must recognize the CLUSTER ADDSLOTS command followed by a list of one or more slot values, separated by whitespace.

Named Tokens to Capture
  • command_slots: captures the keyword part of the command; for this command, that part is the string cluster addslots.
  • slots: captures all of the remaining argument portion as one single string — that is, every slot argument joined exactly as it appears in the input (space-separated), with no leading/trailing whitespace.
Rules for Matching
  • A slot argument is valid only when it is a sequence of decimal digits (an integer). Arguments that are non-numeric are invalid.
  • The slots portion must be made up of one or more integer arguments separated by single spaces.
  • If all of the slot arguments are integers, the command matches, and:
    • command_slots is equal to "cluster addslots".
    • slots is equal to the complete space-separated argument string (e.g. "1" or "1 2 3 4").
  • If any slot argument is not a valid integer, the whole command must fail to match (match returns None).
Expected Outcome Examples
Input command Expected result
cluster addslots 1 match; command_slots="cluster addslots", slots="1"
cluster addslots 1 2 3 4 match; command_slots="cluster addslots", slots="1 2 3 4"
cluster addslots 1 a no match (None)
cluster addslots a no match (None)
cluster addslots a 2 no match (None)
cluster addslots abc no match (None)

Additional Notes

  • The grammar must match the command string in its entirety (a partial match that leaves trailing non-integer content must be treated as a non-match).
  • Captured token values are compared against the raw substrings, as shown above.

Overview

  • Valid input: parsing succeeds and produces named tokens whose values are exactly the substrings that were matched (as described for each command).
  • Invalid input: parsing fails / produces no result for the expected tokens (equivalent to a None outcome, meaning the named tokens are not present).

Command keywords must be matched case-insensitively (e.g. cluster addslots and CLUSTER ADDSLOTS are both valid), and the value captured for the command-name token must preserve the input's original casing as it appeared.

  • The portion forming the command name is cluster addslots (keyword matching is case-insensitive).
  • Following it are one or more integer arguments (slots).

On success, the named tokens produced are:

  • command_slots — the text matched for the command name, preserving the original casing from the input (e.g. "cluster addslots" or "CLUSTER ADDSLOTS").
  • slots — the sequence of integer arguments, whitespace-separated, exactly as they appeared (e.g. "1" or "1 2 3 4").

  • All slot arguments must be integers. Parsing fails if any argument is non-numeric.
