Task: Add support for parsing the CLUSTER KEYSLOT command

Context

There is an existing command-parsing facility in this codebase that parses a Redis-style command string into a structured dictionary of named components. Your task is to extend it so that the CLUSTER KEYSLOT command is recognized and parsed correctly.

Behavior of the Parser (existing infrastructure)

The parser is invoked through a function that, given a command string, returns either:

  • a dictionary mapping component names to their parsed string values (on a successful parse), or
  • None (when the input does not match a valid command form).

The command keyword portion is preserved verbatim from the input, including its original letter casing (e.g. lowercase, uppercase, or mixed).

Required New Behavior: CLUSTER KEYSLOT

Add parsing support for the CLUSTER KEYSLOT <key> command.

Syntax

The command consists of the two-word command keyword cluster keyslot followed by exactly one argument, the key.

Successful parse result

When the input matches, the parser must return a dictionary with exactly these two entries:

  • "command_key": the command keyword portion exactly as it appeared in the input (preserving original casing and the original spacing between the two words — a single space).
  • "key": the key argument exactly as it appeared in the input.
Casing

The command keyword is case-insensitive for the purpose of matching, but is echoed back in the result verbatim as given. Examples:

  • Input cluster keyslot mykey → {"command_key": "cluster keyslot", "key": "mykey"}
  • Input CLUSTER KEYSLOT MYKEY → {"command_key": "CLUSTER KEYSLOT", "key": "MYKEY"}

The key argument itself is preserved verbatim (its casing is never altered).

Quoted key arguments

The key argument may be a double-quoted string. When the key is enclosed in (or contains) double quotes, the quote characters are retained as part of the "key" value — the value is captured exactly as it appears in the input, including surrounding quotes, embedded escaped quotes, and any internal whitespace. Examples:

  • Input cluster keyslot "mykey" → {"command_key": "cluster keyslot", "key": "\"mykey\""}
  • Input cluster keyslot "\"mykey" → {"command_key": "cluster keyslot", "key": "\"\\\"mykey\""} (i.e., the raw characters "\"mykey")
  • Input cluster keyslot "mykey " → {"command_key": "cluster keyslot", "key": "\"mykey \""} (a trailing space inside the quotes is preserved)

Scope

Only add the CLUSTER KEYSLOT command handling described above. Do not alter the behavior of any other command already supported by the parser.

Task Specification: Redis Command Grammar

Overview

You must provide a grammar object that parses Redis CLUSTER subcommands and extracts named tokens from a command string. The grammar must recognize the syntax of several CLUSTER subcommands and expose the parsed components as named variables.

Public API

Provide a module importable as:

iredis.redis_grammar

This module must expose a module-level object named redis_grammar.

The object must support:

  • redis_grammar.match(command_string) — returns a match object if the given command string is recognized by the grammar, or None if it is not recognized.
  • The returned match object must support .variables(), returning a mapping (dict-like) from token name (string) to the matched substring (string). Looking up an unmatched token via .get(name) must return a falsy/None value.

Matching Rules

Commands are case-insensitive at the keyword level: the command keyword may appear in any case (e.g. cluster meet, CLUSTER MEET), and the token that captures the command keyword must reflect the exact case as typed in the input.

The full command string must match in its entirety. Extra trailing arguments beyond what a subcommand accepts must cause the match to fail (return None). A leading/prefixing of the keyword (e.g. Acluster info) must not match.

For each supported subcommand below, on a successful match the variables() mapping must contain the listed token names with the described values.

cluster addslots and cluster delslots
  • Accepts one or more integer slot values separated by single spaces.
  • Token command_slots = the command keyword as typed (e.g. cluster addslots).
  • Token slots = the full space-joined string of slot integers (e.g. 1 or 1 2 3 4).
  • Non-integer arguments (e.g. a, abc, or a mix like 1 a) must not match.
cluster count-failure-reports and cluster forget
  • Accepts exactly one integer node argument.
  • Token command_node = the command keyword as typed.
  • Token node = the single integer string.
  • More than one argument, non-integer arguments, or a mix must not match.
cluster countkeysinslot
  • Accepts exactly one integer slot argument.
  • Token command_slot = the command keyword as typed.
  • Token slot = the single integer string.
  • More than one argument or non-integer arguments must not match.
cluster failover
  • Accepts exactly one choice argument whose value (case-insensitive) is force or takeover.
  • Token command_failoverchoice = the command keyword as typed.
  • Token failoverchoice = the choice as typed (preserving case, e.g. force, FORCE, takeover, TAKEOVER).
cluster getkeysinslot
  • Accepts exactly two integer arguments: a slot and a count.
  • Token command_slot_count = the command keyword as typed.
  • Token slot = the first integer string.
  • Token count = the second integer string.
  • Fewer or more than two arguments, or non-integer arguments, must not match.
cluster info
  • Accepts no arguments.
  • Token command = the command keyword as typed.
  • Any trailing argument must not match.
cluster keyslot
  • Accepts exactly one key argument.
  • Token command_key = the command keyword as typed.
  • Token key = the key as typed.
  • The key may be a bare word (e.g. mykey, MYKEY) or a double-quoted string. When double-quoted, the entire quoted literal (including surrounding quotes) is the token value:
    • "mykey" → token value "mykey"
    • A quoted string containing an escaped quote, e.g. "\"mykey" → token value includes the backslash-escaped quote exactly as typed.
    • A quoted string containing spaces, e.g. "mykey " → the space is preserved inside the quotes.
cluster meet
  • Accepts exactly two arguments: an IPv4 address and a port.
  • Token command_ip_port = the command keyword as typed (e.g. cluster meet).
  • Token ip = the IPv4 address string.
  • Token port = the port string.

IPv4 validation: Each of the four dot-separated octets must be a valid integer in the range 0–255. Values with any octet greater than 255 (e.g. 192.168.0.256, 192.256.0.26, 99.999.100.1, 300.168.0.1) must not match. Valid examples include 192.168.0.1, 255.255.255.255, 0.0.0.0.

Port validation: The port must be an integer in the range 1–65535 inclusive. 0 must not match. Values above 65535 (e.g. 65536, 65545, 65635, 66535, 75535, 99999, 99999999) must not match. An IP-like value in the port position (e.g. 192.168.0.256) must not match. Valid examples include 1, 1024, 6553, 65535.

Notes

  • When a command string does not match the grammar, match returns None.
  • Token values always reflect the exact text as it appeared in the input (case and quoting preserved).
