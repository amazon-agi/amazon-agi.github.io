Task Specification: IOC Finder — ssdeep Hash Extraction

Public API

The package must expose a module ioc_finder providing a top-level function:

find_iocs(text: str) -> dict
  • Input: a single string containing arbitrary text.
  • Output: a dictionary of extracted indicators of compromise (IOCs). Values are lists of strings. The keys relevant to this task include at least:
    • 'md5s'
    • 'sha1s'
    • 'sha256s'
    • 'sha512s'
    • 'ssdeeps'
    • 'urls'
    • 'email_addresses'

Required Behavior

File hashes

Given a string containing space-separated hex-like tokens, find_iocs must classify hashes by length:

  • A 32-character token → md5s (matched case-insensitively; both uppercase and lowercase hex tokens qualify).
  • A 40-character token → sha1s.
  • A 64-character token → sha256s.
  • A 128-character token → sha512s.

For a string containing exactly one token of each of the above lengths, each corresponding list must contain exactly one entry.

URLs

find_iocs must extract valid URLs from the input text and place them in urls.

The following inputs, when whitespace-joined into one string, must all be recognized as valid URLs (each contributing to urls):

  • https://a.com
  • https://en.wikipedia.com
  • https:// followed by a 63-character label, then .com
  • https:// followed by two 63-character labels separated by a dot, then .com
  • https://test-ing.com
  • https://2600.com
  • https://example.com
  • https://example.com/test%20page/
  • http://userid@example.com:8080
  • http://"John..Doe"@example.com
  • http://test@a.com
  • http://bingo@en.wikipedia.com
  • http://foo@ followed by a 63-character label, then .com

The following inputs must not be recognized as valid URLs:

  • foo@ + 64-character label + .com
  • !@.com
  • foo@abc
  • @@@@-hi-.com
  • @_hi_.com
  • me@*hi*.com
  • foo + 64-character label + .com
  • .com
  • abc
  • -hi-.com
  • _hi_.com
  • *hi*.com

(Notably, a domain label of 63 characters is valid, but a label of 64 characters is not.)

ssdeep hashes

find_iocs must extract ssdeep hashes from the input text into the ssdeeps list.

An ssdeep hash has the general form:

<blocksize>:<chunk>:<chunk>

where <blocksize> is a sequence of digits, and each <chunk> is a base64-like sequence (letters, digits, and the characters + and /). The two chunk segments are separated by colons.

Requirements:

  • ssdeep hashes must be recognized even when they appear as part of larger lines, including CSV-style lines where the hash is followed by a comma and a quoted field, e.g.:

    <ssdeep-hash>,"000/000/000000001"

    The trailing ,"..." portion must not be included in the extracted ssdeep hash and must not prevent recognition.

  • Multiple ssdeep hashes appearing on separate lines of a single input string must each be extracted individually.

  • Given an input containing 9 distinct ssdeep hashes (one per line, each followed by a comma and a quoted numeric-path field), ssdeeps must contain exactly 9 entries.

  • ssdeep chunks may contain + and / characters; hash lengths vary and blocksizes may be large multi-digit numbers.

Constraints

  • Extraction functions operate purely on the text passed in; no network access or file I/O is involved.
  • Each IOC category is independent; extracting one category must not interfere with the correct counting of others.

Task Specification: Parsing URLs Without a Scheme

Overview

Add support for detecting URLs that do not include a scheme (e.g., http:// or https://) to the IOC (Indicator of Compromise) finder. This behavior must be enabled by default, with an option to disable it, both in the Python API and the command-line interface.

Python API

Function: find_iocs

Location: importable as from ioc_finder import find_iocs.

Add a new keyword parameter to find_iocs:

find_iocs(text, ..., parse_urls_without_scheme=True)
  • parse_urls_without_scheme (bool, default True): controls whether URLs lacking a scheme are detected and included in the results.

The function returns a dictionary of IOC categories. The relevant categories for this task are:

  • iocs['urls'] — a list of detected URLs.
  • iocs['domains'] — a list of detected domains.
Required behavior

When parse_urls_without_scheme=True (default):

  • A schemeless URL consisting of a domain followed by a path must be detected and included in iocs['urls'] exactly as it appears in the text (including the domain and path portions, without any added scheme).

    Examples of strings that must each produce exactly one URL entry equal to the input:

    • github.com/StylishThemes/GitHub-Dark/blob/master/tools/authors.sh → urls contains github.com/StylishThemes/GitHub-Dark/blob/master/tools/authors.sh
    • hightower.space/projects → urls contains hightower.space/projects

  • Multiple schemeless URLs within the same text must all be detected. For example, the text:

    github.com/StylishThemes/GitHub-Dark/blob/master/tools/authors.sh hightower.space/projects

    must yield exactly two entries in iocs['urls']:

    • github.com/StylishThemes/GitHub-Dark/blob/master/tools/authors.sh
    • hightower.space/projects

When parse_urls_without_scheme=False:

  • URLs that include a scheme continue to be detected normally. For example, the text:

    https://github.com/StylishThemes/GitHub-Dark/blob/master/tools/authors.sh hightower.space/projects

    must yield exactly one entry in iocs['urls']:

    • https://github.com/StylishThemes/GitHub-Dark/blob/master/tools/authors.sh

    The schemeless hightower.space/projects must NOT appear in iocs['urls'].

Domain extraction interaction

Domain detection continues to operate independently. Given text containing both a bare domain and a schemeless URL, e.g.:

This is just an example.com example.org/test/bingo.php
  • iocs['domains'] must contain both example.com and example.org.
  • When schemeless URL parsing is enabled, iocs['urls'] must contain example.org/test/bingo.php.

Command-Line Interface

Command: cli_find_iocs

Location: importable as from ioc_finder import ioc_finder and accessible as ioc_finder.cli_find_iocs. It is a Click command that accepts a positional text argument and prints results as pretty-printed JSON (parseable via json.loads) to standard output, exiting with code 0 on success.

Add a new flag:

  • --no_urls_without_schemes: when present, disables detection of URLs that lack a scheme (equivalent to parse_urls_without_scheme=False). When absent, schemeless URL parsing is enabled by default.
Required behavior

  • The JSON output object contains at least the keys domains and urls, each mapping to a list.

  • Without the flag, given the text:

    This is just an example.com example.org/test/bingo.php

    the output must have:

    • domains containing both example.com and example.org
    • urls containing example.org/test/bingo.php

  • With --no_urls_without_schemes, given the same text:

    This is just an example.com example.org/test/bingo.php

    the output must have:

    • domains containing both example.com and example.org
    • the schemeless URL is not detected.

Compatibility Notes

  • The existing --no_url_domain_parsing flag and its behavior must remain intact. With that flag, given the text This is just an example.com https://example.org/test/bingo.php, the JSON output must include all standard IOC categories (as empty lists where nothing matches), including keys such as asns, bitcoin_addresses, complete_email_addresses, and xmpp_addresses, and the urls list must contain the full https://example.org/test/bingo.php.
  • All previously supported IOC categories and parsing behaviors remain unchanged.
