Task Specification: SmartyStreets Python SDK

Implement a Python 3 package named smartystreets_python_sdk that provides HTTP request sending, retry handling, JSON serialization, and typed clients for the US Street address-verification and US ZIP Code lookup APIs.

HTTP sending

Module-level requests_sender.build_request(smarty_request)

The smartystreets_python_sdk.requests_sender module must provide a module-level build_request function. It builds and returns a requests-library request object, or a compatible prepared request object, from a Request. The returned object must carry the request method, body data, URL, and header information needed for sending.

  • The target URL comes from smarty_request.url_prefix.
  • If smarty_request has a non-empty payload, the method must be "POST", and the returned object's data attribute must equal that payload.
  • If the request has no payload, the method must be "GET".
  • Header information supplied through the SmartyStreets Request must remain available on the resulting HTTP request.
RequestsSender
  • Must be constructable with no arguments: RequestsSender().
  • send(smarty_request) must send the corresponding HTTP request through requests.Session.send and return a SmartyStreets Response.
  • The returned Response.payload must equal the underlying HTTP response's .text value.
  • The returned Response.status_code must equal the underlying HTTP response's status code. This includes successful responses such as 200 and error responses such as 400; the sender must preserve the status rather than replacing it.

Retry handling

Module-level retry_sender.backoff(attempt)

The smartystreets_python_sdk.retry_sender module must expose a module-level backoff(attempt) function used for the pause between attempts. RetrySender must resolve and call this module-level function so callers can substitute it. It is called with an integer retry index. The particular delay policy may be supplied by that function; RetrySender is responsible for supplying the correct attempt sequence.

RetrySender
  • Constructor signature: RetrySender(max_retries, inner_sender).
  • send(request) initially calls inner_sender.send(request).
  • A response status code equal to 200 is success. Every other status code is a failure eligible for retry.
  • max_retries is the number of additional attempts after the initial send, so at most max_retries + 1 sends occur.
  • The first response with status 200 must be returned immediately, with no later send or backoff call.
  • If every allowed attempt fails, the last non-None Response received must be returned.
  • Before each retry, and only before a retry that will actually occur, call backoff(attempt) exactly once. The first retry uses attempt == 0, the second uses 1, and so on, yielding 0, 1, 2, 3, .... No backoff occurs before the initial attempt or after the final failed attempt.

Concrete required behavior:

  • With max_retries=5, an initial success causes exactly one send and no backoff.
  • With max_retries=10, if the fourth send is the first success, exactly four sends occur.
  • With max_retries=4 and all failures, exactly five sends occur, backoff receives [0, 1, 2, 3], and the last failed response is returned.
  • With many retries, the attempt values supplied to backoff continue increasing by one. Any capping or transformation of the actual delay belongs to the substitutable backoff function, not to the retry-index sequence.

JSON serialization

StandardSerializer

StandardSerializer must be importable directly from the top-level package and constructable with no arguments.

  • serialize(obj) must JSON-serialize obj and return the serialized representation. For example, when passed a list containing an address dictionary with street equal to 123 fake street, the string form of the result must contain "street": "123 fake street".
  • deserialize(body) must parse a JSON body and return the corresponding Python structure, including lists, dictionaries, strings, numbers, booleans, and omitted fields as represented by the JSON. A JSON array of result objects must therefore become a list of dictionaries.

Overview

You are working on the smartystreets_python_sdk Python package. This task has two goals:

  1. Replace the duplicated US Street and US ZIP Code batch types with one shared, top-level Batch public API.
  2. Ensure that clients propagate errors carried by a Response instead of attempting to process an errored response.

Existing US Street and US ZIP Code lookup, serialization, sending, and result-assignment behavior must remain compatible with the shared batch type.

Requirement 1: Extract Batch to the top-level package

Public location

Batch must be importable directly from the package root:

from smartystreets_python_sdk import Batch

There must be one shared Batch type for both us_street.Lookup and us_zipcode.Lookup objects. Both corresponding client types must accept and operate on instances of this shared type.

Batch is no longer part of either subpackage's public API: it must not be exposed as smartystreets_python_sdk.us_street.Batch or smartystreets_python_sdk.us_zipcode.Batch. Callers must use the top-level import.

Construction and public collections
  • Batch() is constructible without arguments.
  • A new batch is empty.
  • Every batch exposes all_lookups, a list containing every successfully added lookup in insertion order.
  • Every batch exposes named_lookups, a dictionary mapping each non-None lookup input_id to the corresponding lookup object.
  • Batch.MAX_BATCH_SIZE is a class-level integer that defines the maximum number of lookups accepted by a batch. It retains the SDK's existing value of 100.
Adding and capacity

batch.add(lookup) attempts to append lookup to the batch.

  • If the batch is below capacity, the lookup is appended to all_lookups. If its input_id is not None, the named_lookups mapping is updated for that ID. The call returns a truthy success value.
  • Adding the lookup that makes the size exactly MAX_BATCH_SIZE succeeds and returns a truthy value.
  • Once the batch already contains MAX_BATCH_SIZE lookups, another call to add fails, returns a false value, and does not add the lookup.
Access, length, and clearing
  • len(batch) returns the number of lookups currently stored in the batch.
  • Integer indexing is supported: batch[i] returns the lookup at position i in insertion order.
  • batch.get_by_input_id(input_id) returns the lookup stored under that input ID.
  • batch.clear() removes every stored lookup. After it returns, both batch.all_lookups and batch.named_lookups are empty, and len(batch) is 0.

For example:

from smartystreets_python_sdk import Batch, us_street

batch = Batch()
lookup = us_street.Lookup(input_id="address-1")

assert batch.add(lookup)
assert batch[0] is lookup
assert batch.get_by_input_id("address-1") is lookup
assert len(batch) == 1

batch.clear()
assert len(batch.all_lookups) == 0
assert len(batch.named_lookups) == 0

Requirement 2: Preserve client operation with the shared batch

Both client classes remain constructible as:

Client(sender, serializer)

Their single-lookup and batch workflows must use the shared top-level Batch contract. In particular:

  • send_batch accepts a shared Batch.
  • An empty batch is not sent to the underlying sender.
  • For a nonempty batch, the client serializes its lookups, places the serialized value in the outgoing request payload, and passes that request to the sender.
  • The successful response payload is passed to the serializer's deserialization operation. A deserialized value of None is handled as an empty result collection.
  • The US Street client converts returned candidate data to Candidate objects and appends each candidate to the result list of the lookup selected by the candidate's input_index. Multiple candidates for one input remain associated with that lookup.
  • The US ZIP Code client converts returned result data to Result objects and assigns each result to the lookup selected by its input_index.
  • send_lookup(lookup) performs the corresponding operation for one lookup and leaves its result on that lookup.

The existing US Street freeform constructor behavior is preserved: passing a freeform address as the first argument to us_street.Lookup assigns it to the lookup's street field.

Requirement 3: Raise errors carried by responses

Public exception API

The exceptions module must be available from the package root:

from smartystreets_python_sdk import exceptions

It must define the raisable exception class exceptions.BadCredentialsError.

Response error field

The top-level Response remains available and supports an optional third error argument:

from smartystreets_python_sdk import Response

response = Response(payload, status_code, error)
# Equivalently, omitting error defaults it to None.

The supplied values are publicly available as response.payload, response.status_code, and response.error. The error may be an exception instance or a raisable exception class.

Client error propagation

After the sender returns a Response, the client must inspect response.error before deserializing or assigning results. If that field is not None, the client must raise the carried error. This applies to the response-handling path used by batch sends and, consequently, by send_lookup.

In particular, the following call must raise exceptions.BadCredentialsError rather than attempting to deserialize the response:

response = Response(None, None, exceptions.BadCredentialsError)
# A sender returns this response to a US Street Client.
client.send_lookup(us_street.Lookup())

When response.error is None, normal payload deserialization and result assignment continue.

Public API Summary

Top-level package smartystreets_python_sdk:

  • Batch — the sole shared batch class, including MAX_BATCH_SIZE, all_lookups, named_lookups, add, get_by_input_id, clear, indexing, and len() support.
  • Response — constructible as Response(payload, status_code, error=None).
  • exceptions — a module containing BadCredentialsError.

Subpackage smartystreets_python_sdk.us_street:

  • Client, Lookup, and Candidate.
  • No subpackage-level Batch export.
  • Client response handling raises a non-None response error.

Subpackage smartystreets_python_sdk.us_zipcode:

  • Client, Lookup, and Result.
  • No subpackage-level Batch export.

Both client types accept the shared top-level Batch and are constructed as Client(sender, serializer).

An SDK Request must allow direct assignment of at least:

request.url_prefix = "http://localhost"
request.payload = "request body"

Its existing request attributes and defaults must remain available, including parameters, referer, and content type.

Module-level request builder

The smartystreets_python_sdk.requests_sender module must be accessible as smarty.requests_sender and expose this public function:

smarty.requests_sender.build_request(request)

For an ordinary SDK request, the function retains the established behavior:

  • the outgoing URL and query parameters come from the SDK request;
  • a request with a payload uses POST, and the payload becomes the outgoing data;
  • a request without a payload uses GET;
  • Content-Type comes from the SDK request's content_type unless a custom header overrides it;
  • the SDK User-Agent is supplied unless a custom header overrides it; and
  • a configured referer continues to be included.

When the input request already has a headers mapping, build_request must carry every entry into the resulting HTTP request. It may add normal SDK headers, but it must neither discard custom entries nor overwrite colliding custom values. Looking up each supplied header name on the result must return its originally supplied value.

RequestsSender.send must continue to use normal request conversion and return the response payload and status code through the SDK Response object as before.

3. Candidate response classes must not expose input_id

This change applies specifically to these public response classes:

  • smartystreets_python_sdk.international_street.Candidate
  • smartystreets_python_sdk.us_street.Candidate

Each constructor continues to accept one deserialized response dictionary. For both classes:

  • construction must not require an input_id key;
  • construction must not create or expose an input_id attribute; and
  • if an input_id key is present in the response dictionary, it must not be parsed into a candidate attribute.

This removal is limited to candidate response objects. It must not remove request-side lookup identifiers or existing batching behavior that uses lookup identifiers.

International Street candidate compatibility

All other root and nested response fields must continue to be populated exactly as before, including:

  • organization;
  • address1 through address12;
  • components, including fields such as country_iso_3 and super_administrative_area;
  • metadata; and
  • analysis, including its nested changes information.

These fields must populate normally when the input dictionary has no input_id key.

US Street candidate compatibility

All other root and nested response fields must continue to be populated exactly as before, including:

  • input_index;
  • candidate_index;
  • addressee;
  • delivery-line and barcode fields; and
  • nested components, metadata, and analysis objects.

These fields must populate normally when the input dictionary has no input_id key. Candidate-to-lookup association continues to use input_index.

4. International Street request lookup identifier

smartystreets_python_sdk.international_street.Lookup must expose a public snake-case attribute named input_id. This is a request-side lookup field and is distinct from the candidate response field removed above.

  • A newly constructed Lookup initializes input_id to None.
  • Existing constructor forms, including Lookup() and Lookup(freeform, country), remain valid.
  • No caller assignment of input_id is required before building or sending an otherwise valid lookup.
  • With the default value of None, request construction omits the optional input_id parameter rather than raising an attribute error.
  • If a non-empty input_id is assigned, International Street request construction includes that value under the input_id parameter.
  • Other existing lookup attributes and address validation behavior must remain unchanged.

In particular, the client must continue to accept each established valid input shape without requiring an identifier:

  1. country plus a freeform address;
  2. country plus address1 and a postal code; or
  3. country plus address1, locality, and administrative area.

After a valid lookup is sent, normal client processing remains unchanged: the response payload is deserialized, each response entry is converted to an International Street Candidate, the candidate list is assigned to lookup.result, and that list is returned. Invalid or insufficient address combinations retain their existing validation behavior.

5. Compatibility and scope

Except for the explicit removal of input_id from the two candidate response classes and the additions described above, existing SDK behavior must remain unchanged. In particular, custom-header support must not alter request URL construction, query parameters, payloads, method selection, serialization, response handling, retry behavior, batching, or the behavior of existing API clients.

Objective

Add a sender wrapper that attaches configured license identifiers to outgoing requests, while preserving sender chaining and the existing SDK behavior. Also ensure that the public International Street single-lookup operation can build valid requests and assign its results correctly.

Public API

LicenseSender

The following import must work:

from smartystreets_python_sdk import LicenseSender

Constructor:

LicenseSender(licenses, inner_sender)
  • licenses is a list of string license identifiers.
  • inner_sender is any sender object exposing send(request).

Public method:

send(request)

send must modify the supplied request in place as described below, delegate that same request to inner_sender.send(request), and return the inner sender's return value. Delegation is required whether or not any licenses are configured.

Existing top-level APIs

Request and RequestsSender must remain importable directly from smartystreets_python_sdk. A new Request() has an empty dictionary-like parameters collection and permits assignment to url_prefix. LicenseSender must compose with RequestsSender and with any other object following the same sender protocol.

License Parameter Behavior

Non-empty license list

When licenses is non-empty, send(request) must set:

request.parameters['license'] = ','.join(licenses)

The value is one string containing every identifier in its original order, separated by commas with no added spaces. For example:

licenses = ['one', 'two', 'three']
# request.parameters['license'] == 'one,two,three'

Setting the parameter occurs before delegation. If the request already has a license entry, the configured joined value replaces it.

Empty license list

When licenses is empty, send(request) must not add, remove, or change any request parameter. In particular, it must not create a license key; a request whose parameters collection began empty must still have zero entries when it is delegated.

International Street Compatibility

Public operation

smartystreets_python_sdk.international_street.Client must expose the single-lookup operation under the existing public name:

client.send(lookup)

The behavior in this section belongs to send, not to a differently named send_lookup operation.

For a valid lookup, send must build a Request, pass it to the client's configured sender, deserialize the returned response payload with the configured serializer, convert each deserialized item to an international-street Candidate, assign the resulting collection to lookup.result, and return that collection. The serializer must receive response.payload exactly. An empty candidate response must result in an empty collection assigned to lookup.result. If the response carries an error, that error must be raised rather than processing the payload.

International Lookup.input_id

A newly constructed smartystreets_python_sdk.international_street.Lookup must expose the snake-case public attribute:

lookup.input_id

It must initially be None. Sending an otherwise valid lookup without an input identifier must therefore complete without an attribute error. If a non-blank input_id is supplied, it is sent under the exact query-parameter key input_id; when it is unset, that parameter is omitted.

Lookup validation

Blank strings are treated as missing values. Before dispatch, an international lookup must satisfy all of the following:

  1. country is present.
  2. Either freeform is present, or address1 is present.
  3. If freeform is absent, address1 must be accompanied by either postal_code or both locality and administrative_area.

Insufficient lookups must raise UnprocessableEntityError and must not be dispatched. Thus country plus address1 and only one of locality or administrative area remains insufficient, while country plus freeform, country plus address1 and postal code, and country plus address1, locality, and administrative area are valid.

Query parameters

Only populated optional values are added. The lookup's common options use these exact keys:

  • country -> country
  • language -> language
  • geocode -> geocode

When lookup.geocode is truthy, the outgoing value must be the lowercase string "true", not the Boolean value True. When geocode is None, False, or otherwise falsy, the geocode parameter must be omitted.

The freeform value uses the exact key freeform. Structured address values use these exact keys:

  • address1
  • address2
  • address3
  • address4
  • organization
  • locality
  • administrative_area
  • postal_code

Freeform and structured input are not mutually exclusive for request construction. If freeform and structured fields are populated on the same lookup, the outgoing request must contain freeform and every populated structured field. Setting freeform must not suppress any structured-address parameter. When freeform is absent, all populated structured fields are still copied using the keys above.

Scope and Non-goals

  • Do not add license-specific validation, normalization, extra parameters, or side effects beyond joining the configured identifiers, conditionally setting license, and delegating.
