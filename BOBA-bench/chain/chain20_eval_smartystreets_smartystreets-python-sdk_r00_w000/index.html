SmartyStreets Python SDK: Task Specification

Build a Python 3 package named smartystreets_python_sdk that covers HTTP request sending, retry handling, JSON serialization, and typed clients for the US Street address-verification and US ZIP Code lookup APIs.

The package's public import surface

All of the following must be importable directly from smartystreets_python_sdk:

  • Request
  • Response
  • RetrySender
  • RequestsSender
  • StandardSerializer
  • the submodule requests_sender, reachable as smartystreets_python_sdk.requests_sender
  • the submodule retry_sender, reachable as smartystreets_python_sdk.retry_sender
  • the subpackages us_street and us_zipcode

Under Python 3, the package and every one of these imports must work.

Fundamental request and response types

Request
  • Construction without required arguments must be supported: Request().
  • A url_prefix string attribute that can be assigned to must be exposed.
  • An assignable payload attribute must likewise be exposed.
  • A dict-like headers attribute must be exposed, which callers can use for header assignment.
Response
  • The constructor is invoked as Response(payload, status_code).
  • The values supplied at construction must show up as the payload and status_code attributes.

Sending requests over HTTP

Module-level requests_sender.build_request(smarty_request)

Inside smartystreets_python_sdk.requests_sender, a module-level build_request function must be provided. From a Request, it builds and returns a requests-library request object, or else a compatible prepared request object. The request method, body data, URL, and header information needed for sending must all be carried by the object it returns.

  • smarty_request.url_prefix is where the target URL comes from.
  • Should smarty_request carry a non-empty payload, the method must be "POST", and data on the returned object must equal that payload.
  • With no payload on the request, the method must be "GET".
  • Whatever header information was supplied through the SmartyStreets Request must remain available on the HTTP request that results.
RequestsSender
  • RequestsSender() must be constructible without arguments.
  • Through requests.Session.send, send(smarty_request) must send the corresponding HTTP request and return a SmartyStreets Response.
  • Response.payload on the returned object must equal the underlying HTTP response's .text value.
  • The same holds for Response.status_code: it must equal the underlying HTTP response's status code. Successful responses such as 200 and error responses such as 400 are alike covered here; rather than replacing the status, the sender must preserve it.

Retry behavior

Module-level retry_sender.backoff(attempt)

A module-level backoff(attempt) function, used for the pause between attempts, must be exposed by smartystreets_python_sdk.retry_sender. So that callers can substitute it, RetrySender must resolve and call this module-level function. An integer retry index is passed in on each call. That function may be where the particular delay policy comes from; supplying the correct attempt sequence is RetrySender's responsibility.

RetrySender
  • RetrySender(max_retries, inner_sender) is the constructor signature.
  • send(request) begins by calling inner_sender.send(request).
  • A response status code equal to 200 counts as success. Every status code other than that is a failure eligible for retry.
  • max_retries is how many additional attempts come after the initial send, which puts the send count at most max_retries + 1.
  • The first response whose status is 200 must be returned immediately, with no later send or backoff call.
  • Should every allowed attempt fail, the Response that must be returned is the last non-None one received.
  • backoff(attempt) must be called exactly once before each retry, and only before a retry that will actually occur. The first retry is assigned attempt == 0, the second 1, and so on, producing the sequence 0, 1, 2, 3, .... Before the initial attempt there is no backoff, and after the final failed attempt there is none either.

Behavior required in concrete terms:

  • max_retries=5 with success on the initial send: exactly one send occurs, and no backoff happens.
  • max_retries=10 with the fourth send being the first success: exactly four sends occur.
  • max_retries=4 with every send failing: exactly five sends occur, backoff is handed [0, 1, 2, 3], and the response returned is the last failed one.
  • When retries are numerous, the attempt values passed to backoff keep growing by one. Where any capping or transformation of the actual delay belongs is the substitutable backoff function — not the retry-index sequence.

JSON serialization support

StandardSerializer

Direct imports of StandardSerializer from the top-level package must work, and constructing it must be possible without arguments.

  • serialize(obj) must serialize obj as JSON and return the serialized representation. For instance, given a list containing an address dictionary with street equal to 123 fake street, the string form of the result must contain "street": "123 fake street".
  • deserialize(body) must parse a JSON body and return the Python structure corresponding to it, including lists, dictionaries, strings, numbers, booleans, and omitted fields as the JSON represents them. A JSON array of result objects must therefore come out as a list of dictionaries.

Overview

Your work targets the smartystreets_python_sdk Python package. The task has two goals:

  1. Swap the duplicated US Street and US ZIP Code batch types for a single shared, top-level Batch public API.
  2. Make sure that clients propagate errors carried by a Response rather than attempting to process an errored response.

The existing US Street and US ZIP Code lookup, serialization, sending, and result-assignment behavior must stay compatible with the shared batch type.

Requirement 1: Extract Batch to the top-level package

Public location

It must be possible to import Batch directly from the package root:

from smartystreets_python_sdk import Batch

A single shared Batch type must serve both us_street.Lookup and us_zipcode.Lookup objects. Both corresponding client types must accept instances of this shared type and operate on them.

Batch no longer belongs to either subpackage's public API: it must not be exposed as smartystreets_python_sdk.us_street.Batch or smartystreets_python_sdk.us_zipcode.Batch. The top-level import is what callers must use.

Construction and public collections
  • Batch() can be constructed without arguments.
  • A freshly created batch is empty.
  • Every batch exposes all_lookups, a list containing every lookup that was added successfully, in insertion order.
  • Every batch exposes named_lookups, a dictionary that maps each non-None lookup input_id to the corresponding lookup object.
  • Batch.MAX_BATCH_SIZE is a class-level integer defining the maximum number of lookups a batch accepts. It keeps the SDK's existing value of 100.
Adding and capacity

batch.add(lookup) tries to append lookup to the batch.

  • If the batch is below capacity, the lookup is appended to all_lookups. If its input_id is not None, the named_lookups mapping is updated for that ID. The call returns a truthy value to indicate success.
  • The add that brings the size to exactly MAX_BATCH_SIZE succeeds and returns a truthy value.
  • Once the batch already contains MAX_BATCH_SIZE lookups, a further call to add fails, returns a false value, and does not add the lookup.
Access, length, and clearing
  • len(batch) returns how many lookups are currently stored in the batch.
  • Indexing with an integer is supported: batch[i] returns the lookup at position i in insertion order.
  • batch.get_by_input_id(input_id) returns the lookup that is stored under that input ID.
  • batch.clear() removes every lookup stored in the batch. After it returns, both batch.all_lookups and batch.named_lookups are empty, and len(batch) is 0.

For instance:

from smartystreets_python_sdk import Batch, us_street

batch = Batch()
lookup = us_street.Lookup(input_id="address-1")

assert batch.add(lookup)
assert batch[0] is lookup
assert batch.get_by_input_id("address-1") is lookup
assert len(batch) == 1

batch.clear()
assert len(batch.all_lookups) == 0
assert len(batch.named_lookups) == 0

Requirement 2: Preserve client operation with the shared batch

Both client classes can still be constructed as:

Client(sender, serializer)

The single-lookup and batch workflows of both clients must use the shared top-level Batch contract. Specifically:

  • send_batch accepts a shared Batch.
  • No empty batch is sent to the underlying sender.
  • For a batch that is not empty, the client serializes its lookups, puts the serialized value into the outgoing request payload, and passes that request to the sender.
  • The payload of the successful response is passed to the serializer's deserialization operation. A deserialized value of None is treated as an empty result collection.
  • The US Street client converts returned candidate data to Candidate objects and appends each candidate to the result list of the lookup chosen by the candidate's input_index. Multiple candidates for one input all stay associated with that lookup.
  • The US ZIP Code client converts returned result data to Result objects and assigns each result to the lookup chosen by its input_index.
  • send_lookup(lookup) carries out the corresponding operation for a single lookup and leaves its result on that lookup.

The existing US Street freeform constructor behavior stays in place: supplying a freeform address as the first argument to us_street.Lookup assigns it to the lookup's street field.

Requirement 3: Raise errors carried by responses

Public exception API

The exceptions module must be accessible from the package root:

from smartystreets_python_sdk import exceptions

The module must define the raisable exception class exceptions.BadCredentialsError.

Response error field

The top-level Response stays available and supports an optional third argument for the error:

from smartystreets_python_sdk import Response

response = Response(payload, status_code, error)
# Equivalently, omitting error defaults it to None.

The values supplied are publicly available as response.payload, response.status_code, and response.error. The error may be either an exception instance or a raisable exception class.

Client error propagation

After the sender returns a Response, the client must inspect response.error before it deserializes or assigns results. If that field is not None, the client must raise the error carried by the response. This requirement covers the response-handling path used by batch sends and, consequently, by send_lookup.

Specifically, the following call must raise exceptions.BadCredentialsError instead of attempting to deserialize the response:

response = Response(None, None, exceptions.BadCredentialsError)
# A sender returns this response to a US Street Client.
client.send_lookup(us_street.Lookup())

If response.error is None, normal payload deserialization and result assignment proceed as usual.

Public API Summary

Top-level package smartystreets_python_sdk:

  • Batch — the single shared batch class, including MAX_BATCH_SIZE, all_lookups, named_lookups, add, get_by_input_id, clear, indexing, and len() support.
  • Response — can be constructed as Response(payload, status_code, error=None).
  • exceptions — a module that contains BadCredentialsError.

Subpackage smartystreets_python_sdk.us_street:

  • Client, Lookup, and Candidate.
  • There is no subpackage-level Batch export.
  • Client response handling raises a response error that is not None.

Subpackage smartystreets_python_sdk.us_zipcode:

  • Client, Lookup, and Result.
  • There is no subpackage-level Batch export.

Both client types accept the shared top-level Batch, and both are constructed as Client(sender, serializer).

Goal

Add a wrapper around senders that attaches the configured license identifiers to outgoing requests, while sender chaining and the SDK's existing behavior are preserved. In addition, ensure that the public International Street single-lookup operation can build valid requests and correctly assign its results.

Public Interface

LicenseSender

An import of the following form must work:

from smartystreets_python_sdk import LicenseSender

The constructor:

LicenseSender(licenses, inner_sender)
  • licenses is a list made up of string license identifiers.
  • inner_sender is any sender object that exposes send(request).

The public method:

send(request)

send must alter the supplied request in place as described below, delegate that same request to inner_sender.send(request), and return the value the inner sender returns. Delegation is required regardless of whether any licenses are configured.

Existing top-level APIs

Request and RequestsSender must still be importable directly from smartystreets_python_sdk. A newly created Request() starts out with an empty dictionary-like parameters collection and permits assignment to url_prefix. LicenseSender must compose with RequestsSender and also with any other object that follows the same sender protocol.

How the License Parameter Behaves

Non-empty license list

If licenses is non-empty, send(request) must set:

request.parameters['license'] = ','.join(licenses)

That value is a single string containing every identifier in its original order, joined by commas with no added spaces. For example:

licenses = ['one', 'two', 'three']
# request.parameters['license'] == 'one,two,three'

The parameter is set before delegation takes place. When the request already contains a license entry, the configured joined value replaces it.

Empty license list

If licenses is empty, send(request) must not add, remove, or change any request parameter. Specifically, it must not create a license key; a request whose parameters collection started out empty must still have zero entries when delegation happens.

Compatibility with International Street

The public operation

The single-lookup operation must be exposed by smartystreets_python_sdk.international_street.Client under its existing public name:

client.send(lookup)

The behavior described in this section is part of send, not of a send_lookup operation under a different name.

For a valid lookup, send must build a Request, pass it to the client's configured sender, deserialize the returned response payload using the configured serializer, convert each deserialized item to an international-street Candidate, assign the resulting collection to lookup.result, and return that collection. response.payload is exactly what the serializer must receive. An empty candidate response must result in an empty collection being assigned to lookup.result. When the response carries an error, that error must be raised rather than the payload being processed.

The International Lookup.input_id attribute

A smartystreets_python_sdk.international_street.Lookup that has just been constructed must expose the public snake-case attribute:

lookup.input_id

Its initial value must be None. Sending an otherwise valid lookup that has no input identifier must therefore complete without an attribute error. When a non-blank input_id is supplied, it is sent under the exact query-parameter key input_id; if it is unset, that parameter is omitted.

Validating lookups

Blank strings are regarded as missing values. Prior to dispatch, an international lookup must satisfy all of the following:

  1. country is present.
  2. Either freeform is present, or address1 is present.
  3. When freeform is absent, address1 must be accompanied by either postal_code or both locality and administrative_area.

Lookups that are insufficient must raise UnprocessableEntityError and must not be dispatched. So country plus address1 with only one of locality or administrative area remains insufficient, while country plus freeform, country plus address1 and postal code, and country plus address1, locality, and administrative area are valid.

Query parameter usage

Optional values are added only if they are populated. The lookup's common options use the following exact keys:

  • country -> country
  • language -> language
  • geocode -> geocode

If lookup.geocode is truthy, the outgoing value must be the lowercase string "true", not the Boolean value True. If geocode is None, False, or otherwise falsy, the geocode parameter must be omitted.

The freeform value is sent under the exact key freeform. Structured address values use the following exact keys:

  • address1
  • address2
  • address3
  • address4
  • organization
  • locality
  • administrative_area
  • postal_code

For request construction, freeform and structured input are not mutually exclusive. If freeform and structured fields are populated on the same lookup, the outgoing request must contain freeform and every populated structured field. Setting freeform must not suppress any structured-address parameter. If freeform is absent, all populated structured fields are still copied with the keys above.

Scope and Non-Goals

  • License-specific validation, normalization, extra parameters, or side effects must not be added beyond joining the configured identifiers, conditionally setting license, and delegating.
  • No automatic integration of LicenseSender into client construction is required; it is a sender layer that is public and composable.
  • Existing sender, request, serializer, response, and API-client behavior must remain compatible except for the International Street corrections explicitly stated above.
