01 The public mutual information estimation function in the ennemi package is to be renamed from estimate_mi to estimate_single_mi. 409 words · source specification, reworded by GLM-5.3-Flash

Goal

The public mutual information estimation function in the ennemi package is to be renamed from estimate_mi to estimate_single_mi. It must be possible to import the function directly from the ennemi package namespace:

from ennemi import estimate_single_mi

Public API

estimate_single_mi(x, y, k=3)

Estimates the mutual information between two continuous scalar random variables using paired sample data.

Parameters:

  • x: a one-dimensional array-like containing observations.
  • y: a one-dimensional array-like containing observations, paired element-wise with x.
  • k (keyword argument, default 3): the count of nearest neighbors the estimator uses.

Returns:

  • One floating-point number: the estimated mutual information between x and y.

Required Behavior

Validation of inputs
  • Raise ValueError when the lengths of x and y differ.
  • Raise ValueError when the number of observations is less than or equal to k. (for example, 3 observations with k=5, or 3 observations with the default k.)
  • Raise ValueError when k is not strictly positive (for example, negative).
  • Raise TypeError when k is not an integer (for example, a float such as 2.71828).
Accuracy of the estimation

The estimator must produce mutual information estimates in line with the k-nearest-neighbor MI estimation approach:

  1. Bivariate Gaussian data. When samples are drawn from a bivariate Gaussian distribution with correlation coefficient rho, the estimate must approximate the analytical value -0.5 * ln(1 - rho^2) within a small tolerance suited to the sample size and k.

  2. Independent uniform data. Given two independent samples drawn from a uniform distribution on [0, 1] (1024 points each, k=8), the estimate must be approximately 0 (within a delta of 0.02).

  3. Symmetry. The estimate must be symmetric with respect to its arguments: estimate_single_mi(x, y, k) and estimate_single_mi(y, x, k) must produce essentially identical results (agreement within 0.00001).

  4. Invariance under monotonic scaling / non-uniform density. Given two independent samples drawn from a uniform distribution on [0, 10] (1024 points each, k=8), the estimate must still be approximately 0 (within a delta of 0.02), that is, the estimator handles differently-scaled data and non-uniform densities without bias.

Remarks

  • The estimator's own functionality is unchanged; the exported name is the only thing that changes. If an existing estimate_mi function already implements the required behavior, the task effectively amounts to renaming it (and its export) to estimate_single_mi.
  • The helper module ennemi.entropy_estimators, which contains an internal helper _count_within, continues to exist, and its behavior is unaffected.

Task Specification: Implement estimate_mi — an Interface for Mutual Information Estimation

Summary

A high-level mutual-information interface is to be added to the Python package ennemi. The function must estimate mutual information (MI) between one or more explanatory variables and one target variable, optionally at one or more time lags. It must be possible to import it from the package root as:

from ennemi import estimate_mi

The behavior of existing public package APIs, including the existing estimate_single_mi export, must not be removed or changed by this addition.

Public API

def estimate_mi(x, y, time_lag=0):
    ...
Parameter Details

  • x: The explanatory variable or variables. Either of the following is accepted:

    • a one-dimensional Python sequence or NumPy array, understood as a single variable with N observations, or
    • a two-dimensional Python sequence or NumPy array in which each row is a separate variable and each row holds the same N observations. An input with k rows therefore stands for k explanatory variables.

  • y: The target variable, given as a one-dimensional Python sequence or NumPy array of N observations. Its number of observations must match that of every explanatory variable.

  • time_lag: Either:

    • a single integer, with 0 as its default value, or
    • a sequence of integers, such as a Python list or a NumPy array.

    The values are handled in the order in which they are supplied, and both positive and negative lags are meaningful.

Returned Value

The function must return a two-dimensional NumPy array of shape:

(num_variables, num_lags)
  • A one-dimensional x counts as a single variable.
  • A scalar time_lag counts as a single lag.
  • The entry [i, j] holds the MI estimate between row i of x and y at the j-th requested lag.
  • Both dimensions must be retained at all times. In particular, one variable together with one lag produces shape (1, 1).

Every variable/lag cell is estimated separately, after the common alignment described below has been applied.

Lag Semantics and the Shared Observation Window

For a lag L, the alignment semantics are:

x(t) is paired with y(t + L)

As a result:

  • With L = 0, observations at the same time are paired.
  • With L > 0, an earlier explanatory observation is paired with a later target observation. A positive lag L picks up a relationship such as y(t) = x(t - L), in which the target follows the explanatory variable by L steps.
  • With L < 0, a later explanatory observation is paired with an earlier target observation. A negative lag picks up a relationship such as y(t) = x(t + |L|), in which the target leads the explanatory variable.
A single common window for all requested lags

All estimates within one call must use the same target-observation window. A different maximal overlap for each lag must not be used.

Given N observations and requested lags L0, L1, ..., define:

positive_extent = max(0, L0, L1, ...)
negative_extent = min(0, L0, L1, ...)
start = positive_extent
stop = N + negative_extent
window_size = stop - start
            = N - (positive_extent - negative_extent)

Whenever window_size is positive, each estimate uses the shared target slice conceptually equivalent to:

y[start:stop]

For a given lag L, the variable x_i is aligned to that same target slice using the observations conceptually equivalent to:

x_i[start - L : stop - L]

Both aligned inputs consequently contain exactly window_size observations, and each pair still obeys x(t) with y(t + L). The input arrays do not have to be sliced literally in this manner, but the observable alignment and the selected observations must be equivalent.

Among the consequences:

  • With a single lag, the common window has N - |L| observations.
  • With several lags, every lag—lag zero included—uses N - (positive_extent - negative_extent) observations.
  • With lags [0, 1, -1], every estimate uses N - 2 observations: the shared target window is y[1:N-1], and the corresponding explanatory windows are, respectively, x[1:N-1], x[0:N-2], and x[2:N].
  • Adding a more extreme positive or negative lag may shorten the observations used by all the other requested lags.
Directional behavior to expect
  • When y(t) = x(t - 1) holds wherever defined, MI is high at lag +1 and close to zero at lags 0 and -1, provided the other temporal pairings are independent.
  • When y(t) = x(t + 1) holds wherever defined, MI is high at lag -1 and close to zero at lags 0 and +1.
  • When x and y are identical, MI is high at lag 0 and close to zero at lags +1 and -1 for a temporally independent series.

Error Cases

An empty shared lag window

When the shared window defined above is empty—that is, when:

window_size <= 0

a ValueError must be raised with the exact message:

lag is too large, no observations left

This rule covers both positive and negative lags as well as their combined extent. In particular, with four observations, each of the following must raise that error:

  • time_lag=4
  • time_lag=-4
  • time_lag=[2, -2]

The last example is invalid because the common window is empty, even though either lag considered on its own would leave observations.

Non-integer lag values

Every lag value must be an integer. When a scalar lag, or any element of a lag sequence, is non-integral—for instance 1.2—a TypeError must be raised.

Requirements on the Estimation

A nearest-neighbor-based MI estimator suitable for continuous data must be used. The estimates must be accurate enough that all of the following behavior appears:

  • When variables are independent, the estimates are near 0.
  • A variable that is nearly equal to y, differing only by small independent noise, produces an estimate within ±0.1 of exp(1) ≈ 2.718.
  • An exactly identical pairing, evaluated at its matching lag, produces an estimate within ±0.02 of exp(1).
  • In the tightest cases, independent continuous variables remain within ±0.02 of 0; in smaller or noisier cases—including sample sizes of roughly 40–201 observations—they remain within approximately ±0.05 to ±0.1.
  • In a mixed, multi-variable lagged input, the estimate for a strongly dependent pairing is greater than 0.5, the estimate for a weaker genuinely dependent pairing is greater than 0.15, and independent pairings remain within approximately ±0.05 to ±0.07 of 0.
  • Nonlinear dependence must be detectable; specifically, dependence of the target on the absolute value of an explanatory variable must yield positive MI at the correct lag.

Small estimates around zero do not have to be artificially clipped; the required observable behavior is estimation accuracy together with dependence detection.

Compatibility of Inputs

  • Both plain Python lists and NumPy arrays must be accepted for x and y.
  • Likewise, a lag sequence may be supplied as an ordinary Python sequence or a NumPy array.
  • Two-dimensional inputs, whether list-of-lists or NumPy, are interpreted row by row as separate explanatory variables.
  • NumPy arrays that result from loading external tabular data must behave the same as equivalent arrays created directly in memory.

Scope of the Interface

Each explanatory variable is estimated by the interface against a single one-dimensional target. The rows of x are not combined into one multivariate MI estimate. Every requested variable/lag combination is a separate estimate, while its observation selection is governed by the single shared lag window of the call.

Both functions estimate mutual information or conditional mutual information from paired samples with a k-nearest-neighbor-based estimator. Results are reported in nats. The addition of the conditional estimator must not remove or change existing package-level entry points.

Accuracy requirements

For the representative sampled continuous distributions below, the estimator must provide the following accuracy.

Bivariate Gaussian

When the samples are drawn from a two-dimensional Gaussian with unit variances and correlation coefficient rho, the result must approximate

-0.5 * log(1 - rho**2)

This applies across correlations that include zero, positive values, and negative values; observation counts from approximately 40 through 2000; and neighbor counts including k=3 and k=5. The accepted absolute error becomes tighter as the sample size grows, from as much as 0.1 at approximately 40 observations to approximately 0.005 at approximately 2000 observations.

Given two independent uniform variables with approximately 1024 observations and k=8, the estimate must be within 0.04 of zero. This holds both when each variable is uniform on [0, 1] and when each is uniform on [0, 10]; rescaling the variables must not meaningfully change the result.

Sum of independent exponential variables

Suppose X ~ Exp(rate=a) and W ~ Exp(rate=b) are independent, and set Y = X + W. Using 1000 observations and k=5, estimate_single_mi(x, y, k=5) must approximate

euler_gamma + log((b - a) / a) + psi(b / (b - a))

within 0.025, including for (a, b) equal to (1, 2), (0.2, 0.3), and (3, 3.1). Here, euler_gamma denotes the Euler–Mascheroni constant and psi is the digamma function.

    x and y must have same length

    k must be smaller than number of observations

  • The value of k must be positive and integer-valued by type:

    • A k that is a non-positive integer must raise ValueError. There is no constraint on its message.
    • A k that is not an integer, such as 2.71828, must raise TypeError, not ValueError. There is no constraint on its message.

Each of the length-mismatch and too-large-k requirements applies independently on inputs that are otherwise suitable.

Task Specification: Adding Conditional Mutual Information to estimate_mi

Goal

The existing high-level estimate_mi API is to be extended so that it can estimate conditional mutual information for one or more explanatory variables and one or more time lags. Calls made without a conditioning variable must retain the existing ordinary mutual-information behavior.

Public Interface

It must remain possible to import estimate_mi from the package root:

from ennemi import estimate_mi

Its public signature must support the following:

estimate_mi(x, y, time_lag=0, k=3, cond=None, cond_lag=0)
  • x is array-like continuous numeric data. It may be one-dimensional (a single explanatory variable) or two-dimensional, with the variables in rows and the observations in columns.
  • y is a one-dimensional array-like series serving as the target.
  • time_lag is either a single integer or a one-dimensional sequence of integers. Its default is 0.
  • k is the nearest-neighbor parameter, a positive integer. Its default is 3.
  • cond is an optional one-dimensional array-like continuous series used for conditioning. Its default is None.
  • cond_lag is a single integer whose default is 0. It affects the calculation only when cond is supplied.

Plain Python lists as well as NumPy arrays must continue to be accepted. Before lag alignment is applied, every row of x, y, and, when present, cond must have the same observation count N.

Return Value and Shape

The result is always a two-dimensional NumPy array whose entries are floating-point estimates in nats:

(number of x variables, number of requested time lags)

The columns follow the same order as the supplied time_lag values. Specifically:

  • for one-dimensional x and one integer lag, the shape is (1, 1), not a scalar;
  • for V rows of x and one integer or default lag, the shape is (V, 1);
  • for one-dimensional x and L requested lags, the shape is (1, L);
  • for V rows and L lags, the shape is (V, L).

Each entry holds the MI or conditional-MI estimate for one x row and one lag.

Ordinary Mutual Information

When cond is None, the behavior is unchanged: each result entry estimates the ordinary mutual information between the selected row of x and y at the requested lag. In this mode, cond_lag has no effect.

The established lag convention is kept. For a target index r and lag L, the aligned pair is:

x[r - L], y[r]

Equivalently, an explanatory observation from time t is paired with the target at t + L. A positive lag therefore associates an earlier x observation with a later y observation, while a negative lag associates a later x observation with an earlier y observation.

Conditional Mutual Information

When cond is supplied, each entry estimates the mutual information, conditioned on the aligned conditioning observation, between the aligned x and y observations.

For a target index r, a requested time lag L, and C = cond_lag, the required triple is:

x[r - L], y[r], cond[r - L - C]

Equivalently, with the explanatory observation's time t = r - L, align:

x[t], y[t + L], cond[t - C]

This reference point matters: cond_lag is taken relative to the already-lagged explanatory observation, not independently relative to the fixed target. The conditioning observation's displacement into the target's past is therefore L + C. When multiple time_lag values are requested, the conditioning alignment consequently differs by column.

As an example, with time_lag=[0, 1] and cond_lag=1, a common target index r gives:

lag 0: x[r],     y[r], cond[r - 1]
lag 1: x[r - 1], y[r], cond[r - 2]

If the conditioning variable fully explains the dependence between x and y, the conditional estimate should be approximately 0.0. When the conditioning variable is independent, the estimate should be statistically consistent with ordinary MI. Because these are finite-sample estimates, clipping values near zero to exactly zero is not required.

Common Alignment Window

One common valid target window must be used for all requested columns. This keeps the count of aligned samples the same for every requested lag.

Let lags denote the requested time-lag values, and form the set of target-relative backward displacements:

D = {0} union {L for L in lags}

When conditioning is enabled, additionally include the compounded displacements:

D = D union {L + cond_lag for L in lags}

The common target indices form the half-open range:

start = max(D)
stop  = N + min(D)
r in [start, stop)

For each column, index x, y, and cond over this same target range according to the formulas above. The usable number of observations is:

M = stop - start = N - (max(D) - min(D))

Validation and cropping therefore use the full span of all required offsets. They must not rely only on the largest individual magnitude of time_lag and cond_lag. In particular, time_lag and cond_lag with the same direction compound additively. For a nonnegative cond_lag and a nonnegative maximum requested lag, the required trim of leading targets reaches max(time_lag) + cond_lag.

Validation and Error Behavior

  • Each time_lag value must be an integer. A lag that is not an integer raises TypeError.

  • If cond is supplied, cond_lag must be an integer.

  • A requested lag configuration is invalid whenever the common aligned window is empty, i.e. when M <= 0, equivalently max(D) - min(D) >= N.

  • An invalid/empty lag window must raise ValueError with exactly this message:

    lag is too large, no observations left

    This lag-window validation must take place before a neighborhood-size failure can obscure it.

  • The existing failures are retained by this rule for a single lag whose magnitude is at least N and for mixed lags whose total span is at least N.

  • This rule must additionally account for the compounded conditioning displacement. With N=4, time_lag=1, and cond_lag=3, D={0, 1, 4}, so no observations remain and the exact lag error above is required.

  • As another boundary example, with N=4 and time_lag=[2, -2], D={0, 2, -2} and the same error is required.

  • The existing length validation stays in effect: x and y must have equal observation counts, and a supplied cond must have that same count.

  • The existing k validation also remains in force. k must be a positive integer and must be smaller than M, the count of observations left after the common crop. If M is positive but not greater than k, the existing ValueError message k must be smaller than number of observations is retained.

Compatibility and Data Assumptions

The original positional parameters, defaults, handling of multiple rows, lag ordering, and ordinary-MI numerical behavior must stay compatible. This extension leaves the existing lower-level MI and conditional-MI public APIs unchanged.

The estimators are meant for continuous variables. As before, discrete data or many identical observations may produce unreliable results or -inf; where appropriate, callers may add small-amplitude noise.

Summary

Public interface

estimate_mi(x, y, time_lag=..., parallel=None, ...)

  • time_lag: an int or a list of ints specifying the lag(s) at which to evaluate the estimate.

How the parallel parameter behaves

The parallel parameter accepts exactly one of the following values:

  • None (the default value)
  • "always"
  • "disable"

  • With respect to output, the three accepted parallel values must be interchangeable.
  • Do not alter the shape, indexing convention, or estimation accuracy of the returned array.

  • Take three jointly Gaussian series X, Y, Z such that Y at time t+1 depends on both X and Z at time t (in other words, Y leads X and Z by one step).

Task Specification: Implementing pairwise_mi()

Goal

Introduce a new public function pairwise_mi in the ennemi package. The function must be importable directly from the package:

from ennemi import pairwise_mi

Its purpose is to estimate the pairwise mutual information (MI) between every pair of variables (columns) in a dataset.

Signature

def pairwise_mi(data, *, k=..., cond=None, mask=None, normalize=False)
  • data: the dataset given as input (required, positional).
  • k: an integer parameter for the neighbors (keyword).
  • cond: an optional conditioning variable (keyword, default None).
  • mask: an optional boolean mask (keyword, default None).
  • normalize: a boolean flag (keyword, default False).

Formats of the Inputs

data stands for a collection of variables laid out as columns:

  • A 2D NumPy array with shape (N, M): N observations of M variables. Column j corresponds to variable j.
  • A 1D array-like (e.g. list [1, 2, 3, 4]): handled as a single variable (the same as a single column, i.e. shape effectively (N, 1)).
  • A 2D array-like consisting of a single column (e.g. [[1], [2], [3], [4]], shape (N, 1)): a single variable.
  • A pandas DataFrame: each named column counts as a variable.

When cond is provided, it is a 1D variable whose length (number of observations N) matches that of the data columns.

When mask is provided, it is a 1D boolean array of length N.

Result

The function returns a square matrix of shape (M, M), with M the number of variables:

  • Entry [i, j] holds the estimated mutual information between variable i and variable j.
  • The diagonal entries [i, i] are NaN (a variable is not compared with itself).
  • The matrix is symmetric: [i, j] equals [j, i] (both are computed from the same pair and yield the same estimate).

The return type is determined by the input type:

  • When data is a pandas DataFrame, the result is a pandas DataFrame whose row index and column labels are the original column names. Elements are accessed with those labels (e.g. result.loc["X", "Y"]).
  • Otherwise (array-like / NumPy input), the result is a NumPy array that is indexable as result[i, j].

When there is only a single variable (M == 1), the result has shape (1, 1) and its sole element is NaN.

Semantics of the Estimation

For each unordered pair of distinct variables, the mutual information between the two columns is estimated with the same MI estimator that already underlies the existing estimate_mi functionality of this package (the same k-nearest-neighbor based estimator, honoring the same k, cond, mask, and normalize semantics described below).

The k parameter
  • k determines how many nearest neighbors the estimator uses.
  • The effective number of usable observations after the mask is applied (see below) must be strictly greater than k. Whenever k is greater than or equal to the number of usable observations, raise ValueError with the message: "k must be smaller than number of observations"
  • If k is less than 1 (e.g. 0), raise ValueError with the message: "k must be greater than zero"
The cond parameter
  • When cond is provided, the MI for each pair is estimated conditionally on it (conditional mutual information). Conditioning on a variable that fully explains the dependence between two variables pushes the estimate toward 0.
  • cond must have the same length as the data columns (number of observations). If it does not, raise ValueError with the message: "x and cond must have same length"
The mask parameter
  • When provided, only the observations where the mask is True take part in the estimation; observations where the mask is False are excluded.
  • This makes it possible for datasets that contain NaN values in the excluded rows to be estimated successfully by masking those rows out.
Handling of NaN values
  • If, after the mask is applied (or with no mask), the data used for estimation still contains NaN values, raise ValueError with the message: "input contains NaNs (after applying the mask)"
The normalize parameter
  • When False (the default), the matrix entries are the raw MI estimates.
  • When True, the matrix entries are the normalized MI values (the same normalization as applied by the package's existing normalized-MI functionality, giving values on a correlation-like scale). The diagonal entries remain NaN.
