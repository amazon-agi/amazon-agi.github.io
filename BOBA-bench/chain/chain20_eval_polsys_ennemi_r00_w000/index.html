estimate_single_mi(x, y, k=3)

Estimates the mutual information between two continuous scalar random variables from paired sample data.

Parameters:

  • x: a one-dimensional array-like of observations.
  • y: a one-dimensional array-like of observations, paired element-wise with x.
  • k (keyword argument, default 3): the number of nearest neighbors used by the estimator.

Returns:

  • A single floating-point number: the estimated mutual information between x and y.

Behavioral Requirements

Input validation
  • If x and y have different lengths, raise ValueError.
  • If the number of observations is less than or equal to k, raise ValueError. (e.g. 3 observations with k=5, or 3 observations with the default k.)
  • If k is not strictly positive (e.g. negative), raise ValueError.
  • If k is not an integer (e.g. a float such as 2.71828), raise TypeError.
Estimation accuracy

The estimator must produce mutual information estimates consistent with the k-nearest-neighbor MI estimation approach:

  1. Bivariate Gaussian data. For samples drawn from a bivariate Gaussian distribution with correlation coefficient rho, the estimate must approximate the analytical value -0.5 * ln(1 - rho^2) within a small tolerance appropriate to the sample size and k.

  2. Independent uniform data. For two independent samples drawn from a uniform distribution on [0, 1] (1024 points each, k=8), the estimate must be approximately 0 (within a delta of 0.02).

  4. Invariance under monotonic scaling / non-uniform density. Task Specification: Implement estimate_mi — a Mutual Information Estimation Interface

Overview

Add a high-level mutual-information interface to the Python package ennemi. The function must estimate the mutual information (MI) between one or more explanatory variables and one target variable, optionally at one or more time lags. It must be importable from the package root as:

from ennemi import estimate_mi

This addition must not remove or change the behavior of existing public package APIs, including the existing estimate_single_mi export.

Public API

def estimate_mi(x, y, time_lag=0):
    ...
Parameters

  • x: The explanatory variable or variables. It accepts either:

    • A one-dimensional Python sequence or NumPy array, interpreted as one variable with N observations, or
    • A two-dimensional Python sequence or NumPy array in which each row is a separate variable and each row contains the same N observations. Thus, an input with k rows represents k explanatory variables.

  • y: The target variable, supplied as a one-dimensional Python sequence or NumPy array of N observations. Its observation count must match that of every explanatory variable.

  • time_lag: Either:

    • A single integer, with default value 0, or
    • A sequence of integers, such as a Python list or NumPy array.

    Values are processed in the order supplied, and both positive and negative lags are meaningful.

Return Value

Return a two-dimensional NumPy array with shape:

(num_variables, num_lags)
  • A one-dimensional x counts as one variable.
  • A scalar time_lag counts as one lag.
  • Entry [i, j] is the MI estimate between row i of x and y at the j-th requested lag.
  • Both dimensions must always be retained. In particular, one variable and one lag produce shape (1, 1).

Each variable/lag cell is estimated separately after applying the common alignment described below.

Lag Semantics and Shared Observation Window

A lag L has the alignment semantics:

x(t) is paired with y(t + L)

Therefore:

  • L = 0 pairs observations at the same time.
  • L > 0 pairs an earlier explanatory observation with a later target observation. A positive lag L detects a relationship such as y(t) = x(t - L), where the target follows the explanatory variable by L steps.
  • L < 0 pairs a later explanatory observation with an earlier target observation. A negative lag detects a relationship such as y(t) = x(t + |L|), where the target leads the explanatory variable.
One common window for all requested lags

All estimates in one call must use the same target-observation window. They must not use a different maximal overlap for each lag.

For N observations and requested lags L0, L1, ..., define:

positive_extent = max(0, L0, L1, ...)
negative_extent = min(0, L0, L1, ...)
start = positive_extent
stop = N + negative_extent
window_size = stop - start
            = N - (positive_extent - negative_extent)

When window_size is positive, every estimate uses the shared target slice conceptually equivalent to:

y[start:stop]

For a particular lag L, variable x_i is aligned to that same target slice using the observations conceptually equivalent to:

x_i[start - L : stop - L]

Both aligned inputs therefore contain exactly window_size observations, and each pair still obeys x(t) with y(t + L). The input arrays need not literally be sliced in this manner, but the observable alignment and selected observations must be equivalent.

Consequences include:

  • With one lag, the common window has N - |L| observations.
  • With several lags, every lag—including lag zero—uses N - (positive_extent - negative_extent) observations.
  • For lags [0, 1, -1], every estimate uses N - 2 observations: the shared target window is y[1:N-1]; the corresponding explanatory windows are x[1:N-1], x[0:N-2], and x[2:N], respectively.
  • Adding a more extreme positive or negative lag may shorten the observations used for all other requested lags.
Expected directional behavior
  • If y(t) = x(t - 1) wherever defined, MI is high at lag +1 and near zero at lags 0 and -1 when the other temporal pairings are independent.
  • If y(t) = x(t + 1) wherever defined, MI is high at lag -1 and near zero at lags 0 and +1.
  • If x and y are identical, MI is high at lag 0 and near zero at lags +1 and -1 for a temporally independent series.

Error Conditions

Empty shared lag window

If the shared window defined above is empty—that is, if:

window_size <= 0

raise ValueError with the exact message:

lag is too large, no observations left

This rule applies to both positive and negative lags and to their combined extent. In particular, for four observations, each of the following must raise that error:

  • time_lag=4
  • time_lag=-4
  • time_lag=[2, -2]

The final example is invalid because the common window is empty even though either lag considered alone would leave observations.

Non-integer lag

Every lag value must be an integer. If a scalar lag or any element of a lag sequence is non-integral—for example, 1.2—raise TypeError.

Estimation Requirements

Use a nearest-neighbor-based MI estimator suitable for continuous data. The estimates must be accurate enough to exhibit all of the following behavior:

  • Independent variables produce estimates near 0.
  • A variable that is nearly equal to y, differing only by small independent noise, produces an estimate within ±0.1 of exp(1) ≈ 2.718.
  • An exactly identical pairing at its matching lag produces an estimate within ±0.02 of exp(1).
  • Independent continuous variables remain within ±0.02 of 0 in the tightest cases and within approximately ±0.05 to ±0.1 in smaller or noisier cases, including sample sizes of roughly 40–201 observations.
  • In a mixed, multi-variable lagged input, a strongly dependent pairing produces an estimate greater than 0.5, a weaker genuinely dependent pairing produces an estimate greater than 0.15, and independent pairings remain within approximately ±0.05 to ±0.07 of 0.
  • Nonlinear dependence must be detectable; in particular, dependence of the target on the absolute value of an explanatory variable must yield positive MI at the correct lag.

Small estimates around zero need not be artificially clipped; estimation accuracy and dependence detection are the required observable behavior.

Input Compatibility

  • Plain Python lists and NumPy arrays must both be accepted for x and y.
  • A lag sequence may likewise be supplied as an ordinary Python sequence or a NumPy array.
  • Two-dimensional list-of-lists and NumPy inputs are interpreted row by row as separate explanatory variables.
  • NumPy arrays produced by loading external tabular data must behave the same as equivalent arrays created directly in memory.

Scope

The interface estimates each explanatory variable against a single one-dimensional target. It does not combine the rows of x into one multivariate MI estimate. Requested variable/lag combinations are separate estimates, while their observation selection is governed by the single shared lag window for the call.

The result is always a two-dimensional NumPy array of floating-point estimates in nats:

(number of x variables, number of requested time lags)

The columns appear in the same order as the supplied time_lag values. In particular:

  • one-dimensional x and one integer lag produce shape (1, 1), not a scalar;
  • V rows of x and one integer/default lag produce shape (V, 1);
  • one-dimensional x and L requested lags produce shape (1, L);
  • V rows and L lags produce shape (V, L).

Each entry is the MI or conditional-MI estimate for one x row and one lag.

Ordinary mutual information

When cond is None, behavior is unchanged: each result entry estimates ordinary mutual information between the selected row of x and y at the requested lag. cond_lag has no effect in this mode.

The established lag convention is retained. For a target index r and lag L, the aligned pair is:

x[r - L], y[r]

Equivalently, an explanatory observation at time t is paired with the target at t + L. Thus a positive lag associates an earlier x observation with a later y observation, while a negative lag associates a later x observation with an earlier y observation.

Conditional mutual information

When cond is supplied, each entry estimates the mutual information between the aligned x and y observations conditioned on the aligned conditioning observation.

For target index r, requested time lag L, and C = cond_lag, the required triple is:

x[r - L], y[r], cond[r - L - C]

Equivalently, using the explanatory observation's time t = r - L, align:

x[t], y[t + L], cond[t - C]

This reference point is important: cond_lag is relative to the already-lagged explanatory observation, not independently relative to the fixed target. Therefore the conditioning observation's displacement into the target's past is L + C. With multiple time_lag values, the conditioning alignment consequently differs by column.

For example, with time_lag=[0, 1] and cond_lag=1, a common target index r gives:

lag 0: x[r],     y[r], cond[r - 1]
lag 1: x[r - 1], y[r], cond[r - 2]

If the conditioning variable fully explains the dependence between x and y, the conditional estimate should be approximately 0.0. An independent conditioning variable should leave the estimate statistically consistent with ordinary MI. These are finite-sample estimates, so values near zero need not be clipped to exactly zero.

Common alignment window

All requested columns must use one common valid target window. This keeps the aligned sample count the same for every requested lag.

Let lags be the requested time-lag values and form the set of target-relative backward displacements:

D = {0} union {L for L in lags}

When conditioning is enabled, also include the compounded displacements:

D = D union {L + cond_lag for L in lags}

The common target indices are the half-open range:

start = max(D)
stop  = N + min(D)
r in [start, stop)

For each column, index x, y, and cond according to the formulas above over this same target range. The usable observation count is:

M = stop - start = N - (max(D) - min(D))

Thus validation and cropping use the full span of all required offsets. They must not use only the largest individual magnitude of time_lag and cond_lag. In particular, same-direction time_lag and cond_lag compound additively. For nonnegative cond_lag and a nonnegative maximum requested lag, the required leading target trim reaches max(time_lag) + cond_lag.

  • Every time_lag value must be an integer. A non-integer lag raises TypeError.

  • When cond is supplied, cond_lag must be an integer.

  • A requested lag configuration is invalid when the common aligned window is empty, i.e. when M <= 0, equivalently max(D) - min(D) >= N.

  • An invalid/empty lag window must raise ValueError with exactly this message:

    lag is too large, no observations left

    This lag-window validation must occur before a neighborhood-size failure can obscure it.

  • This rule retains the existing failures for a single lag whose magnitude is at least N and for mixed lags whose total span is at least N.

  • It must also account for the compounded conditioning displacement. For N=4, time_lag=1, and cond_lag=3, D={0, 1, 4}, so no observations remain and the exact lag error above is required.

  • For another boundary example, with N=4 and time_lag=[2, -2], D={0, 2, -2} and the same error is required.

  • Existing length validation remains in force: x and y must have equal observation counts, and a supplied cond must have that same count.

  • Existing k validation remains in force. k must be a positive integer and must be smaller than M, the number of observations remaining after the common crop. If M is positive but not greater than k, the existing ValueError message k must be smaller than number of observations is retained.

The original positional parameters, defaults, multi-row handling, lag ordering, and ordinary-MI numerical behavior must remain compatible. Existing lower-level MI and conditional-MI public APIs are not changed by this extension.

The estimators are for continuous variables. As before, discrete data or many identical observations may produce unreliable results or -inf; callers may add small-amplitude noise where appropriate.

Numerical behavior

The existing estimator behavior must not change:

  • Independent continuous variables estimate near zero, while dependent variables produce positive MI. Finite-sample estimates may be slightly negative near zero.
  • For correlated unit-variance Gaussian variables with correlation rho, the estimate approximates -0.5 * log(1 - rho**2).
  • A fully dependent uniform relationship exhibits the package's established estimate near exp(1), while an independent uniform covariate remains near zero.
  • Time-shifted dependence appears at the correct lag and remains near zero at unrelated lags.
  • Conditional MI agrees approximately with known analytic continuous-distribution values. Conditioning on an independent variable leaves ordinary MI essentially unchanged, while conditioning on y drives conditional MI to zero. One- and multi-dimensional conditioning data remain supported.
  • Applying a mask estimates MI from the selected aligned subset. Combining a mask with lag, cond, and cond_lag must retain the corresponding lag-adjusted observations and preserve the expected conditional or unconditional result.
  • Valid parallel modes must preserve these numerical results.

normalize_mi Behavior to Preserve

normalize_mi converts non-negative MI values to the corresponding non-negative Gaussian correlation magnitude using

sqrt(1 - exp(-2 * mi))

This is the inverse of mi = -0.5 * log(1 - rho**2) for non-negative rho.

  • Zero maps to zero.
  • Negative values, including negative infinity, pass through unchanged rather than being normalized.
  • Scalars, Python lists, and NumPy arrays are processed element by element while retaining the applicable array shape.
  • For pandas structures, the returned pandas structure preserves the input shape, index, and column labels.

The behavior of the lower-level estimator functions must remain unchanged:

It is symmetric to numerical precision, approximates -0.5 * log(1 - rho**2) for correlated Gaussians, and is near zero for independent variables, including transformed non-uniform marginals.
  • _estimate_conditional_mi(x, y, cond, k) estimates conditional MI for one- or multi-dimensional continuous conditions. It agrees with ordinary MI when the condition is independent, is zero when the condition equals y, and approximates known multivariate-Gaussian conditional MI values.
  • _psi(x) computes the package's digamma function for its supported non-negative integer inputs. _psi(0) returns positive infinity, and positive inputs agree with the standard digamma function to the established numerical precision.

Task Specification: Implement pairwise_mi()

Objective

Add a new public function pairwise_mi to the ennemi package. It must be importable directly from the package:

from ennemi import pairwise_mi

This function estimates the pairwise mutual information (MI) between every pair of variables (columns) in a dataset.

Function Signature

def pairwise_mi(data, *, k=..., cond=None, mask=None, normalize=False)
  • data: the input dataset (required, positional).
  • k: integer neighbor parameter (keyword).
  • cond: optional conditioning variable (keyword, default None).
  • mask: optional boolean mask (keyword, default None).
  • normalize: boolean flag (keyword, default False).

Input Formats

data represents a collection of variables arranged as columns:

  • A 2D NumPy array of shape (N, M): N observations of M variables. Column j is variable j.
  • A 1D array-like (e.g. list [1, 2, 3, 4]): treated as a single variable (equivalent to a single column, i.e. shape effectively (N, 1)).
  • A 2D array-like with a single column (e.g. [[1], [2], [3], [4]], shape (N, 1)): a single variable.
  • A pandas DataFrame: each named column is a variable.

cond, when provided, is a 1D variable of the same length (number of observations N) as the data columns.

mask, when provided, is a 1D boolean array of length N.

Output

The function returns a square matrix of shape (M, M), where M is the number of variables:

  • Element [i, j] is the estimated mutual information between variable i and variable j.
  • Diagonal elements [i, i] are NaN (a variable is not compared with itself).
  • The matrix is symmetric: [i, j] equals [j, i] (both are computed from the same pair and yield the same estimate).

Return type depends on input type:

  • If data is a pandas DataFrame, the result is a pandas DataFrame whose row index and column labels are the original column names. Element access uses those labels (e.g. result.loc["X", "Y"]).
  • Otherwise (array-like / NumPy input), the result is a NumPy array indexable as result[i, j].

When there is only a single variable (M == 1), the result has shape (1, 1) and its single element is NaN.

Estimation Semantics

For each unordered pair of distinct variables, estimate the mutual information between the two columns using the same MI estimator that already underlies the existing estimate_mi functionality in this package (same k-nearest-neighbor based estimator, honoring the same k, cond, mask, and normalize semantics described below).

k parameter
  • k controls the number of nearest neighbors used by the estimator.
  • The effective number of usable observations after applying the mask (see below) must be strictly greater than k. If k is greater than or equal to the number of usable observations, raise ValueError with the message: "k must be smaller than number of observations"
  • If k is less than 1 (e.g. 0), raise ValueError with the message: "k must be greater than zero"
cond parameter
  • When provided, the MI between each pair is estimated conditionally on cond (conditional mutual information). Conditioning on a variable that fully explains the dependence between two variables drives the estimate toward 0.
  • cond must have the same length as the data columns (number of observations). If not, raise ValueError with the message: "x and cond must have same length"
mask parameter
  • When provided, only observations where the mask is True are used in the estimation; observations where the mask is False are excluded.
  • This allows datasets that contain NaN values in the excluded rows to be estimated successfully by masking those rows out.
NaN handling
  • If, after applying the mask (or with no mask), the data used for estimation still contains NaN values, raise ValueError with the message: "input contains NaNs (after applying the mask)"
normalize parameter
  • When False (default), matrix entries are the raw MI estimates.
  • When True, matrix entries are the normalized MI values (the same normalization applied by the package's existing normalized-MI functionality, producing values on a correlation-like scale). Diagonal entries remain NaN.
