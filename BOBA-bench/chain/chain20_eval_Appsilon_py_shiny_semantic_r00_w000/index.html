01 Provide the implementation of the public page and button APIs for the shiny_semantic package. 654 words · rewritten by GPT-5.6-sol, reworded by GLM-5.3-Flash

Task Description

Goal

Provide the implementation of the public page and button APIs for the shiny_semantic package. The page must render Shiny UI content alongside the required browser assets from Fomantic UI and Shiny Semantic, and the button must produce HTML compatible with Semantic UI.

Public API Requirements

shiny_semantic.page_semantic

The function must be importable in the following way:

from shiny_semantic import page_semantic

When called, it takes the public form:

page_semantic(*args)

It accepts any number of positional UI child elements — zero included — and returns a page UI object that is suitable for use as the UI argument of shiny.App. For example, after an application has been constructed with:

app = App(page_semantic(...), None)
html = app.ui.get("html")

html must be a rendered HTML string in which all child elements passed to page_semantic appear.

Dependencies required for the page

Every page that page_semantic renders, including a page created with no children, must include references to all of the following browser assets:

  • The Fomantic UI stylesheet named fomantic.min.css.
  • The Fomantic UI script named fomantic.min.js.
  • The Shiny Semantic bindings script named shiny-semantic-bindings.js.

Therefore, the exact filename literals fomantic.min.css, fomantic.min.js, and shiny-semantic-bindings.js must appear in the HTML that app.ui.get("html") returns.

shiny_semantic.elements.button

It must be possible to import the function as follows:

from shiny_semantic.elements import button

The function's signature is:

button(id, label, class_name="", icon_name=None)

Parameters:

  • id (str): the DOM element ID that is assigned to the rendered button.
  • label (str): the visible text of the button.
  • class_name (str, optional): extra Semantic UI CSS classes. The default is the empty string.
  • icon_name (str, optional): the name of a Semantic UI icon to be placed inside the button. The default is None.

The function returns a UI element that can be passed to page_semantic as a child.

Contract for Button Rendering

HTML element and ID

Rendering must produce an HTML <button> element. The opening tag must carry an id attribute whose value is equal to the id that was supplied. The label that was supplied must be rendered as the visible text content of the button.

CSS class attribute

A class attribute must always be present on the button. Its value is put together, with no normalization, from the following three segments, in this order:

  1. The literal prefix ui.
  2. The class_name as supplied.
  3. The literal suffix button.

The segments are joined so that one space sits between each pair. As a result, the opening tag must be exactly:

<button id="{id}" class="ui {class_name} button">

class_name is substituted literally. Specifically:

  • With the default empty class_name, the class value is exactly ui button — that is, two consecutive spaces appear between ui and button.
  • With class_name="red basic", the class value comes out as exactly ui red basic button.
The optional icon

When icon_name is not None, the button must contain an <i> element, and the class value of this element is made up of the supplied icon name followed by the literal class icon. The opening tag of this element must be:

<i class="{icon_name} icon">

For instance, icon_name="plane" must produce <i class="plane icon"> within the button. When icon_name is None, no icon element gets added.

Mandatory Rendering Examples

If the elements below are rendered inside a page_semantic page, the resulting page HTML must contain the exact fragments shown here:

button("test1", "Test1")

<button id="test1" class="ui  button">

button("test2", "Test2", class_name="red basic")

<button id="test2" class="ui red basic button">

button("test3", "Test3", icon_name="plane")

<i class="plane icon">

Compatibility of the Package

The package must expose page_semantic from its top-level namespace and button from its elements submodule, exactly in the way shown above. The returned page and element objects must interoperate with the Shiny App and UI rendering APIs that are available.

Summary

For the shiny_semantic package, an icon component is to be implemented. This component's output is the HTML for an icon element in the Semantic UI style — an element that can be embedded into a Shiny UI page.

Public API

The icon function

Its home is shiny_semantic/elements/icon.py; it must be importable in the following way:

from shiny_semantic.elements import icon

Its signature:

def icon(name, modifiers=""):
    ...

Parameters:

  • name (str): the icon's name (for instance, "users", "home", "asterisk").
  • modifiers (str, optional): extra CSS class tokens, packed into one string, that qualify the icon (for instance, "loading", "large", "bordered teal"); the default value is an empty string.

Behavior Requirements

What icon must return is a UI element which renders as an HTML <i> tag; on that tag, the class attribute is assembled from the modifiers first, then the icon name, then the literal token icon, with the pieces separated by single spaces:

<i class="{modifiers} {name} icon">

Behind the scenes, the class attribute is a join of the modifiers string, the name string, and the word icon, using single spaces. In practice:

  • icon("users") must render an element that contains <i class=" users icon"> (notice the leading space, which the empty default modifiers produce).
  • icon("asterisk", "loading") must render <i class="loading asterisk icon">.
  • icon("home", "large") must render <i class="large home icon">.
  • icon("home", "bordered teal") must render <i class="bordered teal home icon">.

The returned object must be compatible with Shiny's UI composition: handed to a page layout as a child, it can produce the expected HTML fragment once the page gets rendered.

Requirements for Integration

These imports must work, and they must do so in combination:

from shiny import App
from shiny_semantic import page_semantic
from shiny_semantic.elements import icon
  • As for page_semantic(...): it must be a page-layout function exported from the shiny_semantic package, one that accepts one or more UI children (icon(...) results included) and produces a Shiny UI page from them.
  • Once a page of that kind has gone into a Shiny App, the HTML that gets rendered — the app's UI provides it as an "html" value — must contain the <i ...> fragments spelled out above, one for each icon the page includes.

Notes

  • Several icons may be included on one page; each must independently produce its corresponding <i class="..."> fragment within the final HTML.
  • The only things required are the composition of the class attribute ("{modifiers} {name} icon") and the use of the <i> tag.

Build a text_input function that generates a text input component styled according to Semantic UI, for use inside a Shiny for Python application.

Public API

The function must be importable in the following way:

from shiny_semantic.elements import text_input
Function signature
def text_input(
    input_id,
    placeholder="",
    input_type="text",
    class_name="",
    icon_name=None,
    label=None,
):
    ...

The input's identifier is taken by the first positional parameter. It must also be possible to pass it using the keyword name input_id.

What the function returns must be a UI element that works with shiny's page composition (that is, it can be handed to page_semantic(...) as a child and render into the resulting HTML).

Rendering Behavior Requirements

The component renders as an outer wrapper <div> that contains an <input> element and, optionally, an icon and a label.

The outer wrapper <div>

The wrapper must be a <div> whose class attribute is put together as follows, with exactly this order and spacing:

ui <class_name> <icon-token> <label-token> input

Where:

  • The prefix is the literal ui, and the suffix is the literal input.
  • <class_name> stands for the value of the class_name argument (an empty string when it is not provided).
  • <icon-token> is the literal string icon if icon_name is provided (i.e., not None); otherwise it adds nothing.
  • <label-token> is the literal string labeled if label is provided (i.e., not None); otherwise it adds nothing.

The spacing must correspond exactly to the following observed outputs:

  • When there is no class_name, no icon_name, and no label:

    <div class="ui  input">

    (Note: two spaces separate ui and input here, which corresponds to the empty class_name.)

  • When class_name="error", icon_name="react", and label="Password" are supplied:

    <div class="ui error icon labeled input">
The <input> element

The inner element must have this form:

<input type="<input_type>" placeholder="<placeholder>" id="<input_id>"/>

with the attributes appearing in exactly this order: type, then placeholder, then id. Examples:

  • Calling text_input("users") produces:
    <input type="text" placeholder="" id="users"/>
  • Calling text_input(input_id="complex", placeholder="Complex", input_type="password", ...) produces:
    <input type="password" placeholder="Complex" id="complex"/>
The label

If label is provided (not None), the component must render a label <div> as part of it:

<div class="ui label"><label-text></div>

For instance, label="Password" gives:

<div class="ui label">Password</div>

When label is None, no label <div> of that kind gets rendered.

The icon

If icon_name is provided (not None), an icon element must be rendered as an <i> tag with a class attribute consisting of a leading space, then the icon name, then icon:

<i class=" <icon_name> icon">

For instance, icon_name="react" gives:

<i class=" react icon">

When icon_name is None, no icon element gets rendered.

Notes

  • Because the rendered HTML is matched by substring, the exact literal attribute ordering, spacing, and class-token ordering displayed above must be reproduced precisely.
  • The "basic" rendering demonstrated for text_input("users") is what the default argument values must yield.

Goal

In the module shiny_semantic.elements, implement a text_input function, importable as:

from shiny_semantic.elements import text_input

This function generates the HTML markup for a text input field styled according to Semantic UI, suitable for embedding within a Shiny UI page.

Function Signature

def text_input(
    input_id,
    placeholder="",
    input_type="text",
    class_name="",
    icon_name=None,
    label=None,
):
    ...
  • input_id (str, required, first positional argument): the value applied to the id attribute of the <input> element.
  • placeholder (str, default ""): the value applied to the placeholder attribute of the <input> element.
  • input_type (str, default "text"): the value applied to the type attribute of the <input> element.
  • class_name (str, default ""): extra CSS class name(s) added to the class list of the wrapping <div>.
  • icon_name (str or None, default None): when supplied, an icon element is added and the wrapper is marked as an icon input.
  • label (str or None, default None): when supplied, a label element is added and the wrapper is marked as a labeled input.

When calling the function, the arguments above are passed as keyword arguments in any combination.

Required Output Behavior

The component is rendered as a wrapping <div> that contains an <input> element (and, optionally, an icon element and/or a label element).

The <input> element

The <input> element must be rendered such that its attributes appear in exactly this order:

<input id="{input_id}" type="{input_type}" value="" placeholder="{placeholder}"/>
  • The value of the id attribute always equals input_id.
  • The value of the type attribute always equals input_type (default "text").
  • A value attribute is always present, set to an empty string: value="".
  • The value of the placeholder attribute always equals placeholder (default "", resulting in placeholder="").

Example with text_input("users"):

<input id="users" type="text" value="" placeholder=""/>

Example with text_input(input_id="complex", placeholder="Complex", input_type="password", ...):

<input id="complex" type="password" value="" placeholder="Complex"/>

The wrapper is a <div> whose class attribute is made up of the following tokens, joined by single spaces and placed in this order:

  1. ui
  2. the value of class_name (only when it is non-empty)
  3. icon (only when icon_name is supplied)
  4. labeled (only when label is supplied)
  5. input

Tokens that do not apply are omitted, and no extra internal or trailing whitespace should appear between the tokens.

  • Base case (without class_name, without an icon, without a label):

    <div class="ui input">

  • With class_name="error" together with an icon and a label (in that combination):

    <div class="ui error icon labeled input">

When icon_name is supplied, an icon element must be rendered inside the wrapper as:

<i class=" react icon">

That is, an <i> element whose class attribute consists of a leading space, followed by the icon_name, followed by icon. (With icon_name="react", the class value is " react icon".)

When label is supplied, a label element must be rendered inside the wrapper as a <div> with class ui label that contains the label text:

<div class="ui label">Password</div>

(With label="Password", the content is Password.)

Task Description

Goal

Expose the low-level Semantic/Fomantic text-input component from the shiny_semantic package publicly under the name semantic_input. Once renamed, the component must retain the former component's complete input, value, label, icon, styling, and HTML-attribute behavior.

Public Interface

The component must be publicly importable as follows:

from shiny_semantic.elements import semantic_input

The old public name text_input is not required any longer. Continuity of behavior means carrying its feature set forward under semantic_input; it does not require text_input to be kept as a public alias.

Signature of the Function

semantic_input(
    input_id: str,
    placeholder: str | None = "",
    value: str = "",
    label: str | None = None,
    icon_name: str | None = None,
    input_type: str = "text",
    class_name: str | None = None,
    **kwargs,
)

The function must accept input_id either by position or via the input_id keyword. Every optional named argument listed above must be accepted as a keyword.

Parameter Descriptions
  • input_id: Identifier for the inner HTML input. Outside a Shiny module namespace it is rendered as-is; within a namespace it must receive the active namespace the same way other Shiny input controls do.
  • placeholder: The placeholder text. Its default is the empty string, so the default input includes placeholder="". Passing None may result in the attribute being omitted, in line with normal Shiny/htmltools attribute handling.
  • value: The initial input value. Its default is the empty string, and it must still be emitted as a value attribute.
  • label: Optional content for a label. None means no label. Any value other than None, an empty string included, requests the labeled form.
  • icon_name: Optional name of a Semantic icon. None means no icon. Any value other than None requests the icon form.
  • input_type: The value used for the HTML type attribute, with "text" as the default; values like "password", "date", and "email" are passed through.
  • class_name: An optional Semantic modifier class, or several classes separated by spaces, for the outer wrapper — for instance "error", "fluid", or "large". None and the empty string add no modifier.
  • **kwargs: Extra valid tag attributes meant for the inner <input>, following the usual Shiny/htmltools keyword conventions. These attributes apply to the input element, not to the wrapper.

Required Rendered Structure

semantic_input returns a Shiny-compatible UI tag that always has a <div> as its root. When present, the root contains the following, in this order:

  1. the optional label;
  2. the <input> element;
  3. the optional icon.

Whitespace used for formatting between these elements carries no significance, while the element hierarchy, attributes, class values, and child order do.

Classes on the Wrapper

The wrapper's class value is put together in the following order:

  1. ui;
  2. the nonempty token or tokens that class_name supplies;
  3. icon if icon_name is not None;
  4. labeled if label is not None;
  5. input.

The assembled wrapper class is normalized with respect to whitespace: whitespace at the start and the end, as well as repeated whitespace, is removed, and the resulting tokens are separated by single spaces. Consequently, the default wrapper opening tag is exactly:

<div class="ui input">

Given class_name="error", an icon, and a label, it is exactly:

<div class="ui error icon labeled input">
Inner Input Element

The inner <input> must contain the resolved id, type, value, and placeholder values. With the defaults plus input_id="users", its rendered form is exactly:

<input id="users" type="text" value="" placeholder=""/>

Extra attributes supplied via **kwargs are rendered on this element by standard Shiny/htmltools attribute conversion. As an example, input-specific attributes like autocomplete, disabled, aria_*, or data_* must not be attached to the wrapper.

Label Element

Whenever label is not None, a label <div> is rendered before the input, with the exact class ui label and the supplied label as its content:

<div class="ui label">Password</div>

The labeled class token must also be applied to the wrapper. When label is None, both the label element and that generated token are left out.

Icon Element

When icon_name is not None, an <i> element is rendered after the input, and the icon token is added to the wrapper. The icon element adheres to the package's existing icon-class format: its class value is made up of a leading space, the supplied icon name, and icon. With icon_name="react", the element is:

<i class=" react icon"></i>

When icon_name is None, both the icon element and that generated wrapper token are left out.

<div class="ui input">
  <input id="users" type="text" value="" placeholder=""/>
</div>

The Modal Component

The import required for compatibility is:

from shiny_semantic.modules import modal

modal must return an element that supports direct serialization via .get_html_string(). For:

modal(id="modal", header="Header", content="Content", actions=None)

the rendered structure must include, in order:

  • an outer opening tag <div id="modal" class="ui modal">;
  • a header section <div class="header">Header</div>;
  • a content section <div class="content">Content</div>; and
  • an actions container that begins with <div class="actions">.

When actions=None, the actions container must include the default buttons whose DOM IDs are cancel and ok, so the output contains <button id="cancel" and <button id="ok".

Task Specification for the Container Element Component

Goal

Within the module shiny_semantic.elements, implement a function named container (importable via from shiny_semantic.elements import container).

Public API

container(*args, **kwargs)

The function accepts the child content as positional arguments (for example, a string such as "Hello").

Behavior Requirements

The container function must generate an HTML element that renders as a <div> whose CSS class attribute is exactly ui container.

To be precise, the rendered output must include this opening tag:

<div class="ui container">

The class value must be made up of the two words ui and container separated by a single space, and it must not have any leading, trailing, or duplicated internal whitespace.

The child content supplied as positional arguments must be included as the content of the <div> element.

Edge Cases

  • The class string must not include extra or empty space segments (for example, "ui container", written with a double space, is incorrect; it must be "ui container").

Task Specification: Implement the divider Element

Goal

The task is to implement a divider function that produces an HTML <div> element styled as a UI divider.

Public Interface

Make the function accessible via the following import path:

from shiny_semantic.elements import divider
Signature
def divider(*args, **kwargs):
    ...

Positional child content (e.g., strings) is accepted by the function, which returns an HTML element object.

Required Behavior

  • A call to divider("Hello") must produce a <div> element whose rendered HTML opening tag is exactly:

    <div class="ui divider">

  • The value that the class attribute holds must be exactly ui divider — the words ui and divider separated by a single space, with no leading, trailing, or doubled whitespace.

  • The positional content provided (e.g., "Hello") is passed into the element as its child content.

Additional Notes

  • The returned object must render to HTML in such a way that the opening tag string above appears within the rendered output.
  • When called as shown, the element should have no additional attributes or classes beyond ui divider.
