01 Serialization for int128 and int256 Values 318 words · source specification

Task Specification: Serialization for int128 and int256 Values

Overview

Implement serialization (dump) and deserialization (load) functions for fixed-width 128-bit and 256-bit unsigned integer values. These functions handle conversion between Python integers and their little-endian byte representations.

Public API Surface

Create two modules:

Module: mtpylon.serialization.int128

Must expose two callables:

  • dump(number: int) -> bytes
  • load(input_bytes: bytes) -> <LoadedValue>
Module: mtpylon.serialization.int256

Must expose two callables:

  • dump(number: int) -> bytes
  • load(input_bytes: bytes) -> <LoadedValue>

Behavior Requirements

dump
  • int128.dump: Takes an integer and returns exactly 16 bytes representing the value in little-endian byte order.
  • int256.dump: Takes an integer and returns exactly 32 bytes representing the value in little-endian byte order.

Example (int128): the integer 0x3E0549828CCA27E966B301A48FECE2FC dumps to the 16-byte sequence:

\xfc\xe2\xec\x8f\xa4\x01\xb3\x66\xe9\x27\xca\x8c\x82\x49\x05\x3e

Example (int256): the integer 0x3E0549828CCA27E966B301A48FECE2FC3E0549828CCA27E966B301A48FECE2FC dumps to the 32-byte sequence that is the above 16-byte block repeated twice:

\xfc\xe2\xec\x8f\xa4\x01\xb3\x66\xe9\x27\xca\x8c\x82\x49\x05\x3e\xfc\xe2\xec\x8f\xa4\x01\xb3\x66\xe9\x27\xca\x8c\x82\x49\x05\x3e
load

Takes a bytes input and reads a fixed-width value from the beginning of the input, interpreting the bytes as a little-endian unsigned integer. Returns an object with the following attributes:

  • value: the decoded integer.
  • offset: the number of bytes consumed — 16 for int128, 32 for int256.

The load function reads only the required number of leading bytes; the offset attribute always equals the fixed width of the type (16 or 32).

Example (int128): loading the 16-byte sequence above produces an object whose value equals 0x3E0549828CCA27E966B301A48FECE2FC and whose offset equals 16.

Example (int256): loading the 32-byte sequence above produces an object whose value equals 0x3E0549828CCA27E966B301A48FECE2FC3E0549828CCA27E966B301A48FECE2FC and whose offset equals 32.

dump and load are inverse operations for their respective width.

Error Conditions
  • int128.load: If the input contains fewer than 16 bytes, raise ValueError.
  • int256.load: If the input contains fewer than 32 bytes, raise ValueError.

Notes

The object returned by load must support attribute access via .value and .offset.

02 Implement a module that serializes (dump) and deserializes (load) byte strings according to the MTProto encoding scheme for the bytes/string type. 555 words · source specification

Task: Implement Byte-String Serialization for MTProto

Overview

Implement a module that serializes (dump) and deserializes (load) byte strings according to the MTProto encoding scheme for the bytes/string type.

Module & Public API

Create the module mtpylon/serialization/bytes.py exposing two functions:

def dump(value: bytes) -> bytes: ...
def load(input_bytes: bytes) -> LoadedValue: ...

The load function must return an object with two attributes:

  • value — the decoded bytes
  • offset — an int giving the total number of bytes consumed from the input

(Any object type that supports .value and .offset attribute access is acceptable; e.g. a named tuple or small dataclass.)

Encoding Scheme

The encoding depends on the length L of the byte string.

Short form (L <= 253)
  • The first byte is L (the length, as a single byte).
  • Followed by the L payload bytes.
  • Followed by zero or more padding bytes (\x00) so that the total length (length prefix byte + payload + padding) is a multiple of 4.

Examples:

  • A 4-byte payload produces: 1 length byte + 4 payload bytes = 5 bytes, padded to 8 bytes total (3 padding bytes).
  • A 13-byte payload produces: 1 length byte + 13 payload bytes = 14 bytes, padded to 16 bytes total (2 padding bytes).
Long form (L >= 254)
  • The first byte is \xfe (254).
  • Followed by L encoded as a 3-byte little-endian integer.
  • Followed by the L payload bytes.
  • Followed by zero or more padding bytes (\x00) so that the total length (1 marker byte + 3 length bytes + payload + padding) is a multiple of 4. Note that the 4-byte header itself is always aligned to 4, so padding is determined by aligning the payload length to a multiple of 4.

Examples:

  • A 256-byte payload produces: \xfe\x00\x01\x00 (marker + length 256 little-endian) followed by the 256 payload bytes; total 260 bytes, already a multiple of 4 (no padding).
  • A 257-byte payload produces: \xfe\x01\x01\x00 followed by the 257 payload bytes, followed by 3 padding bytes; total 264 bytes.

dump Behavior

Given a bytes value, return the encoded bytes according to the scheme above (short form when length <= 253, long form otherwise).

load Behavior

Given an input bytes buffer that begins with an encoded byte string:

  • Read the first byte. If it is less than 254, treat the input as short form: that byte is the payload length L; the payload follows immediately.
  • If the first byte is 254 (\xfe), treat the input as long form: the next 3 bytes are L in little-endian; the payload follows.
  • Return an object whose value is the decoded payload (bytes of length L) and whose offset is the total number of bytes consumed, including the length prefix, payload, and any padding needed to align the consumed total to a multiple of 4.

Consumed-offset examples:

  • 4-byte payload (short form): offset 8.
  • 13-byte payload (short form): offset 16.
  • 256-byte payload (long form): offset 260.
  • 257-byte payload (long form): offset 264.

The input buffer may contain additional data beyond the encoded byte string; only the leading encoded value is consumed and the reported offset reflects that.

Error Conditions

If the input buffer is empty, load must raise ValueError.

03 String Serialization 564 words · source specification

Task Specification: String Serialization

Overview

Implement serialization (dump) and deserialization (load) for str values in a new module mtpylon/serialization/string.py. The encoding follows a length-prefixed, 4-byte-aligned byte format.

Existing Dependency

The module mtpylon/serialization/bytes.py must expose a constant:

  • LONG_STRING_CHAR: a single byte b'\xfe' used as a marker for long strings.

(If this constant does not already exist in that module, it must be created there so it can be imported.)

Public API

In mtpylon/serialization/string.py, provide:

dump(value: str) -> bytes

Serializes a string into the length-prefixed, padded byte format described below.

load(data: bytes) -> LoadedValue

Deserializes bytes (in the same format) into a result object that exposes two attributes:

  • .value — the decoded str.
  • .offset — an int giving the total number of bytes consumed by this string (including its length prefix and any padding).

You may name the returned object's type as you wish, but it must be accessible via attribute access (loaded.value, loaded.offset).

Encoding Format

Strings are encoded from their UTF-8 byte representation. Let n be the number of UTF-8 encoded bytes of the string.

Short strings (n <= 253)
  • Prefix: a single byte whose value is n.
  • Body: the UTF-8 encoded bytes.
  • Padding: zero bytes (b'\x00') appended so that the total length (prefix + body + padding) is a multiple of 4.

Padding calculation: the total length before padding is 1 + n. Append the minimum number of \x00 bytes to reach the next multiple of 4. When 1 + n is already a multiple of 4, no padding is added.

Examples of the padding behavior:

  • A 15-byte string produces prefix \x0f + 15 bytes = 16 bytes total (already a multiple of 4, no padding).
  • A 12-byte string produces prefix \x0c + 12 bytes + 3 padding bytes = 16 bytes total.
Long strings (n >= 254)
  • Prefix: the LONG_STRING_CHAR byte (b'\xfe') followed by n encoded as a 3-byte little-endian integer (4 bytes of prefix total).
  • Body: the UTF-8 encoded bytes.
  • Padding: zero bytes appended so that the total length (4-byte prefix + body + padding) is a multiple of 4.

Padding calculation: the body length n is padded to the next multiple of 4 with \x00 bytes. When n is already a multiple of 4, no padding is added.

Example:

  • A 505-byte string: prefix \xfe + 3-byte little-endian size + 505 body bytes + 3 padding bytes = 512 bytes total.

Load Behavior

load reads the format described above from the beginning of the input bytes:

  • If the first byte is not \xfe (short string): its value gives n. The next n bytes are the UTF-8 body. .offset is the total consumed length including prefix and padding (i.e., 1 + n rounded up to the next multiple of 4).
  • If the first byte is \xfe (long string): the following 3 bytes are the little-endian length n. The next n bytes are the UTF-8 body. .offset is the total consumed length including the 4-byte prefix and padding (i.e., 4 + n rounded up to the next multiple of 4).

.value is always the decoded string with padding stripped.

Round-Trip Requirement

dump and load must be mutually consistent: loading the output of dump recovers the original string value, and .offset equals the total byte length of the dumped output.

05 Implement serialization (dump) and deserialization (load) of a "vector" type — a homogeneous list of elements — following the MTProto-style binary encoding. 445 words · source specification

Task: Implement Vector Serialization

Implement serialization (dump) and deserialization (load) of a "vector" type — a homogeneous list of elements — following the MTProto-style binary encoding.

Module and Public API

Create the module mtpylon.serialization.vector exposing two functions:

def dump(dump_object, value) -> bytes
def load(load_object, input_bytes)

You may rely on the following existing element serializers (already available and importable):

  • mtpylon.serialization.int.load, mtpylon.serialization.int.dump
  • mtpylon.serialization.string.load, mtpylon.serialization.string.dump

Their behavior (for reference on element encoding):

  • int.dump(value) returns 4 little-endian bytes for an integer.
  • int.load(bytes) reads a 4-byte little-endian integer.
  • string.dump(value) returns the MTProto string encoding (length prefix + bytes + padding to a 4-byte boundary).
  • string.load(bytes) reads such a string.
  • Each load function returns an object with attributes .value (the decoded value) and .offset (number of bytes consumed).

Binary Format

A serialized vector consists of, in order:

  1. A fixed 4-byte vector identifier: b'\x15\xc4\xb5\x1c'.
  2. A 4-byte little-endian unsigned integer giving the number of elements.
  3. The concatenation of each element serialized with the provided element dumper.

dump(dump_object, value)

  • dump_object is a callable that serializes a single element to bytes (e.g. int.dump or string.dump).
  • value is a list of elements.
  • Returns bytes: the vector id, followed by the element count as a 4-byte little-endian integer, followed by each element in value serialized in order via dump_object.

Example: dumping [2, 3, 4] with the int dumper yields:

b'\x15\xc4\xb5\x1c' + b'\x03\x00\x00\x00' + b'\x02\x00\x00\x00' + b'\x03\x00\x00\x00' + b'\x04\x00\x00\x00'

load(load_object, input_bytes)

  • load_object is a callable that decodes a single element from bytes, returning an object with .value and .offset (bytes consumed).
  • input_bytes is the byte buffer to decode from.
  • Returns an object with:
    • .value: the list of decoded elements.
    • .offset: the total number of bytes consumed for the whole vector (the 4-byte id + the 4-byte count + the sum of the bytes consumed by all elements).

Decoding steps:

  1. Read the first 4 bytes and verify they equal the vector id b'\x15\xc4\xb5\x1c'.
  2. Read the next 4 bytes as the little-endian element count.
  3. Decode that many elements sequentially, advancing through the buffer by each element's consumed length.

Example: loading the int-dumped [2, 3, 4] buffer yields .value == [2, 3, 4] and .offset == 20. Loading a string vector ['hello', 'world', 'telegram'] (each string encoded with length prefix and 4-byte padding) yields .value == ['hello', 'world', 'telegram'] and .offset == 36.

Error Conditions

Raise ValueError when:

  • The first 4 bytes of input_bytes do not match the vector id.
  • The buffer is too short to contain the 4-byte length field (e.g. only the vector id is present).

07 Subscript Lookup on Schema 581 words · source specification

Task Specification: Subscript Lookup on Schema

Objective

Implement subscript (__getitem__) access on the Schema class so that combinator data and function data can be retrieved by key.

Public API Surface

The following must be importable:

  • from mtpylon import Schema
  • from mtpylon.schema import CombinatorData, FunctionData
Data Classes

CombinatorData and FunctionData are the data objects returned from Schema lookups. They expose the following read-only attributes:

CombinatorData

  • id — an integer identifier for the combinator.
  • params — a sequence of the combinator's parameters (supports len()).
  • predicate — a string, the combinator's predicate name.
  • type — a string, the name of the type the combinator belongs to.

FunctionData

  • id — an integer identifier for the function.
  • params — a sequence of the function's parameters (supports len()).
  • method — a string, the function's method name.
  • type — a string, the name of the return type of the function.

Required Behavior: Schema.__getitem__(key)

A Schema instance is built from a collection of types (each having one or more combinators) and functions. Subscript access schema[key] must resolve the key and return the associated combinator or function data.

The key may be one of the following:

  1. A combinator class — a class that represents a single specific combinator of a type. Return the corresponding CombinatorData.

  2. A type "construct" — the abstract type/base object that aggregates multiple combinators (e.g. a boolean type that groups its true/false combinators). Passing such a construct is not a valid lookup: raise ValueError.

  3. A function — a callable/object registered in the schema as a function. Return the corresponding FunctionData.

  4. An integer — a numeric identifier. Match it against the id of any registered combinator or function:

    • If it matches a combinator's id, return that CombinatorData.
    • If it matches a function's id, return that FunctionData.
Error Conditions
  • If the key is a type construct (an aggregate type rather than a specific combinator), raise ValueError.
  • If the key is a combinator class, function, or integer that is not present in the schema, raise KeyError.
Return Value Details
  • When a combinator is found (by class or by integer id), the returned CombinatorData reflects that combinator: its id, params, predicate, and type.
  • When a function is found (by function object or by integer id), the returned FunctionData reflects that function: its id, params, method, and type.
  • Combinators with no parameters yield params of length 0.

Examples of Expected Resolution

Given a schema containing:

  • A Bool type whose combinators include boolTrue (id 2574415285, no params, type Bool).
  • A Task type with a task combinator (id 6457282, 3 params, type Task).
  • A login function (id 475889219, 2 params, return type User).

Then:

  • schema[BoolTrue] → CombinatorData(id=2574415285, params len 0, predicate='boolTrue', type='Bool')
  • schema[Task] → CombinatorData(id=6457282, params len 3, predicate='task', type='Task')
  • schema[2574415285] → the boolTrue CombinatorData
  • schema[6457282] → the task CombinatorData
  • schema[login] → FunctionData(id=475889219, params len 2, method='login', type='User')
  • schema[475889219] → the login FunctionData
  • schema[Bool] (the aggregate boolean type) → raises ValueError
  • schema[<unknown combinator class>] → raises KeyError
  • schema[<unregistered function>] → raises KeyError
  • schema[12312] (unknown id) → raises KeyError

Note: in the example above Task serves both as a type construct name and as the single combinator; a type with exactly one combinator resolves to that combinator's CombinatorData rather than raising ValueError. Only aggregate types with multiple combinators (such as Bool) raise ValueError.

09 Schema-Based Serialization (dump) 725 words · source specification

Task Specification: Schema-Based Serialization (dump)

Overview

Implement a function dump that serializes values into the MTProto-style binary (TL) wire format, using a Schema object to resolve type/combinator/function metadata. The serialization must handle basic types, schema-registered objects (combinators), and schema-registered functions (with their arguments).

Public API

mtpylon.serialization.dump
def dump(schema, value, **kwargs) -> bytes
  • schema: a Schema instance describing the known objects and functions.
  • value: either an instance of a schema-registered object/type, or a schema-registered function (a callable).
  • **kwargs: keyword arguments supplying the parameters of a function when value is a function.
  • Returns the serialized bytes.

This function must be importable as from mtpylon.serialization import dump.

mtpylon.exceptions.DumpError

An exception class importable as from mtpylon.exceptions import DumpError, raised for any serialization failure described below.

Serialization Format

All integers below are little-endian unless otherwise implied by the examples.

Combinator / function number prefix

Every serialized object or function begins with a 4-byte combinator (or function) identifier that comes from the schema metadata for that object/function. This 4-byte prefix is emitted first, followed by the serialized values of the object's/function's parameters in their declared order.

Basic type: int

Serialized as a 4-byte little-endian value. Example: 12 → b'\x0c\x00\x00\x00'.

Basic type: str

Serialized as a length-prefixed, byte-aligned string:

  • For strings whose byte length is small (fits in a single length byte), emit one length byte equal to the number of content bytes, then the UTF-8 content bytes, then zero-padding bytes so that the total length (length byte + content + padding) is a multiple of 4.

Examples:

  • 'root' (4 bytes) → b'\x04root\x00\x00\x00' (1 length byte + 4 content + 3 padding = 8 bytes).
  • 'dump by schema' (14 bytes) → b'\x0edump by schema\x00' (1 length byte + 14 content + 1 padding = 16 bytes).
Boolean objects

The schema contains two boolean singleton object types, BoolTrue and BoolFalse. Each serializes to just its 4-byte identifier:

  • BoolTrue() → b'\xb5\x75\x72\x99'
  • BoolFalse() → b'\x37\x97\x79\xbc'
Schema objects (combinators)

When value is an instance of a schema-registered object, emit the object's 4-byte combinator number, then serialize each declared parameter value (in order) according to its declared type. Parameter types may themselves be basic types or other schema types (including nested objects such as Bool).

Schema functions

When value is a schema-registered function, emit the function's 4-byte identifier. If the function declares parameters, the parameter values are supplied via **kwargs; serialize each declared parameter (in order) according to its declared type. A function with no parameters serializes to just its 4-byte identifier.

Error Conditions

dump must raise DumpError in each of the following cases:

  • value is an object instance whose type is not registered in the schema.
  • value is a callable/function that is not registered in the schema.
  • value is a schema function but a supplied parameter value does not match the declared type of that parameter (e.g. a value of the wrong Python type where a specific type is expected).
  • value is a schema object but one of its parameter values does not match the declared type of that parameter.

Test Fixtures Required

A test-support module tests/simpleschema.py (importable as ..simpleschema from the serialization test package) must exist and expose a Schema instance named schema together with the following schema-registered members, consistent with the serialization behavior and identifiers above:

  • BoolTrue — object type; instance serializes to b'\xb5\x75\x72\x99'.
  • BoolFalse — object type; instance serializes to b'\x37\x97\x79\xbc'.
  • Task — object type constructible as Task(id=<int>, content=<str>, completed=<Bool>), with combinator number b'\xc2\x87\x62\x00' and parameters serialized in the order id (int), content (str), completed (Bool).
  • get_task_list — a schema function taking no parameters, with identifier b'\x53\x29\x22\xca'.
  • login — a schema function taking username: str and password: str, with identifier b'\x43\x7e\x5d\x1c', parameters serialized in order username, password.

The Bool type used by Task.completed and returned via BoolTrue/BoolFalse must accept either boolean object instance as a valid value.

Worked examples

The schema describes combinators (data constructors) and functions, each identified by a 4-byte little-endian combinator/function id at the start of its encoding. load reads the leading id, resolves it against the schema, and decodes the remaining bytes according to the resolved definition.

  • A combinator with int, str, and Bool fields decodes each in order and consumes the sum of their encoded sizes plus the leading 4-byte combinator id.

  • When the flags value indicates an optional field is present, decode that field and consume its bytes.
