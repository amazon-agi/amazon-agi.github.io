Task: Implement Serialization for the Message Service Schema

Overview

You must implement the data structure Message together with a pair of serialization functions (load and dump) that convert a Message to and from its binary wire representation.

Public API Surface

1. mtpylon.service_schema.constructors.Message

It must be possible to import a Message type from mtpylon.service_schema.constructors. It is constructed by supplying the following keyword arguments:

  • msg_id: a long value (see the long type below)
  • seqno: an int
  • bytes: an int
  • body: a bytes object

When two Message instances are constructed with equal field values, they must compare equal (==).

2. mtpylon.utils.long

It must be possible to import a long type/callable from mtpylon.utils. It serves to construct 64-bit integer values, e.g. long(32). The values that long produces are used as the msg_id field of a Message.

3. mtpylon.service_schema.serialization.message

Two functions must be exposed by this module:

  • dump(message: Message) -> bytes
  • load(data: bytes) -> <result>

Binary Format

A serialized Message is the concatenation, in order, of the following:

  1. A constructor identifier of fixed 4-byte size: b'\x11\xe5\xb8['
  2. msg_id — encoded as an integer in 8-byte little-endian form.
  3. seqno — encoded as an integer in 4-byte little-endian form.
  4. bytes — encoded as an integer in 4-byte little-endian form.
  5. body — the bytes value in raw form, appended verbatim (its length is equal to the value of the bytes field).
Example

Take a Message where msg_id=long(32), seqno=0, bytes=14, body=b'dumped message'; its serialized form is then:

b'\x11\xe5\xb8['                     # constructor id
b'\x20\x00\x00\x00\x00\x00\x00\x00'  # msg_id = 32, 8-byte LE
b'\x00\x00\x00\x00'                  # seqno = 0, 4-byte LE
b'\x0e\x00\x00\x00'                  # bytes = 14, 4-byte LE
b'dumped message'                    # body

Required Behavior

dump(message)

Given a Message, return the bytes produced by following the binary format above.

load(data)

  • .value: the reconstructed Message, which is equal to the original.

  3. MessageContainer

    • Constructed using the keyword argument messages, a list of Message instances.
Type: mtpylon.long

A long type used for 64-bit integer values, already available for import from mtpylon.

Module: mtpylon.service_schema

It must be possible to import two functions from this module:

  • dump(value) -> bytes Serializes one of the supported constructor instances (MsgsAck, Message, MessageContainer) to its binary representation.

  • load(data: bytes) Deserializes a binary representation, turning it back into the corresponding constructor instance. Returns an object with two attributes:

    • .value: the constructor instance that was reconstructed (equal by value to the original).
    • .offset: an int, the count of bytes consumed while reading (equal to the total length of the input for the cases below).

Binary Format

All multi-byte integers use little-endian byte order. The formats below are exact and must round-trip: load(dump(x)).value == x and dump(load(b)).value reproduces b, where load(...).offset is equal to the length of the consumed bytes.

Constructor and type numbers (4-byte little-endian tags)
  • MsgsAck tag: the bytes 59 b4 d6 62
  • Message tag: the bytes 11 e5 b8 5b
  • MessageContainer tag: the bytes 48 49 c3 94
  • Vector tag (used for lists): the bytes 15 c4 b5 1c
Layout of MsgsAck
  1. The MsgsAck tag (4 bytes).
  2. The Vector tag (4 bytes).
  3. Vector length: the count of msg_ids as a 4-byte little-endian integer.
  4. Each msg_id, in order, as an 8-byte little-endian value.
Layout of Message
  1. The Message tag (4 bytes).
  2. The msg_id as an 8-byte little-endian value.
  3. The seqno as a 4-byte little-endian integer.
  4. The bytes as a 4-byte little-endian integer.
  5. body: exactly bytes raw bytes (the body content is emitted and read verbatim, and its length equals the bytes field).
Layout of MessageContainer
  1. The MessageContainer tag (4 bytes).
  2. The Vector tag (4 bytes).
  3. Vector length: the count of messages as a 4-byte little-endian integer.
  4. Each message serialized with the Message layout above, in order.

Required Behavior

  • For each constructor type, dump produces exactly the byte sequences described above.
  • load reads a byte sequence that follows one of these formats, dispatches on the leading 4-byte tag, and returns the reconstructed instance together with the total number of bytes consumed.
  • Field values must be preserved exactly by round-tripping, including 64-bit msg_id values and raw body bytes.

Goal

Implement a function that generates a random odd number with a given bit length.

Public API

Create a module at the path mtpylon/crypto/random_prime.py exposing a function:

    ...

Ensure that the package layout supports importing this function as:

from mtpylon.crypto.random_prime import random_odd

Behavior Requirements

random_odd(bits) accepts a positive integer bits denoting a bit length, and it returns an integer satisfying both of the following conditions:

  1. The result is odd. In other words, result % 2 == 1.

  2. The result has exactly bits + 1 significant bits, and its highest bit is set. Concretely, result >> bits == 1. That is, the returned value falls within the half-open range [2**bits, 2**(bits+1)) — the bit located at position bits (zero-indexed) is always set.

As an example, a call to random_odd(64) returns an odd integer value for which value >> 64 == 1.

Additional Notes

  • The value should be randomly generated while staying within the constraints above; separate calls may return different values, yet every returned value must satisfy the two conditions on every invocation.
