Overview

Public API Surface

A Message type must be importable from mtpylon.service_schema.constructors. It is constructed with the following keyword arguments:

  • msg_id: a long value (see the long type below)
  • seqno: an int
  • bytes: an int
  • body: a bytes object

Two Message instances constructed with equal field values must compare equal (==).

2. mtpylon.utils.long

A long type/callable must be importable from mtpylon.utils. It is used to construct 64-bit integer values, e.g. long(32). Values produced by long are used as the msg_id field of a Message.

3. mtpylon.service_schema.serialization.message

This module must expose two functions:

  • dump(message: Message) -> bytes
  • load(data: bytes) -> <result>

Binary Format

A Message is serialized as the concatenation, in order, of:

  1. A fixed 4-byte constructor identifier: b'\x11\xe5\xb8['
  2. msg_id — encoded as an 8-byte little-endian integer.
  3. seqno — encoded as a 4-byte little-endian integer.
  4. bytes — encoded as a 4-byte little-endian integer.
  5. body — the raw bytes value, appended verbatim (length equal to the bytes field value).
Example

For a Message with msg_id=long(32), seqno=0, bytes=14, body=b'dumped message', the serialized form is:

b'\x11\xe5\xb8['                     # constructor id
b'\x20\x00\x00\x00\x00\x00\x00\x00'  # msg_id = 32, 8-byte LE
b'\x00\x00\x00\x00'                  # seqno = 0, 4-byte LE
b'\x0e\x00\x00\x00'                  # bytes = 14, 4-byte LE
b'dumped message'                    # body

Behavior Requirements

dump(message)

Given a Message, return the bytes produced according to the binary format above.

load(data)

Given a bytes buffer that begins with a serialized Message (and may contain arbitrary trailing bytes afterward), parse exactly one Message from the beginning of the buffer and return a result object with two attributes:

  • .value: the reconstructed Message (equal to the original).
  • .offset: an int equal to the number of bytes consumed from the start of the buffer to parse the message (i.e. the length of that message's serialized form). Any bytes beyond this offset are ignored.

The parsing must read the constructor id (4 bytes), the msg_id (8 bytes LE), seqno (4 bytes LE), bytes (4 bytes LE), then read exactly bytes bytes as the body. The .offset therefore equals 20 + bytes.

dump and load must be exact inverses for the format described.

  • Message tag: bytes 11 e5 b8 5b
  • MessageContainer tag: bytes 48 49 c3 94
  • Vector tag (used for lists): bytes 15 c4 b5 1c
MsgsAck layout
  1. MsgsAck tag (4 bytes).
  2. Vector tag (4 bytes).
  3. Vector length: number of msg_ids as a 4-byte little-endian integer.
  4. Each msg_id as an 8-byte little-endian value, in order.
Message layout
  1. Message tag (4 bytes).
  2. msg_id as an 8-byte little-endian value.
  3. seqno as a 4-byte little-endian integer.
  4. bytes as a 4-byte little-endian integer.
  5. body: exactly bytes raw bytes (the body content is emitted/read verbatim, and its length equals the bytes field).
MessageContainer layout
  1. MessageContainer tag (4 bytes).
  2. Vector tag (4 bytes).
  3. Vector length: number of messages as a 4-byte little-endian integer.
  4. Each message serialized using the Message layout above, in order.

  • load reads a byte sequence in one of these formats, dispatching on the leading 4-byte tag, and returns the reconstructed instance together with the total number of bytes consumed.
  • Round-tripping must preserve field values exactly, including 64-bit msg_id values and raw body bytes.

Create a module at the path mtpylon/crypto/random_prime.py that exposes a function:

Required Behavior

The random_odd(bits) function accepts a positive integer bits representing a bit length and returns an integer satisfying both of the following conditions:

  1. The result is odd. That is, result % 2 == 1.

  2. The result has exactly bits + 1 significant bits, with the highest bit set. Specifically, result >> bits == 1. This means the returned value lies in the half-open range [2**bits, 2**(bits+1)) — the bit at position bits (zero-indexed) is always set.

For example, calling random_odd(64) returns an odd integer value such that value >> 64 == 1.

Notes

  • The value should be randomly generated within the constraints above; different calls may return different values, but every returned value must satisfy the two conditions on every invocation.

For example, random_odd(64) returns an odd, 65-bit integer satisfying result >> 64 == 1. The generated value is not required to be prime.
