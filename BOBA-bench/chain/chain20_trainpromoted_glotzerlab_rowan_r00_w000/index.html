Task Specification: Quaternion Operations Module

Overview

Implement a Python module named quaternion (importable as import quaternion) that provides quaternion multiplication and vector rotation operations. Operations must work on single quaternions/vectors as well as arbitrarily-shaped batches, using NumPy.

Quaternion & Vector Conventions

  • A quaternion is represented as a NumPy array whose last axis has length 4, in the order [w, x, y, z] (scalar part first, then vector part).
  • A 3-vector is represented as a NumPy array whose last axis has length 3, in the order [x, y, z].
  • Batches are supported: inputs may be 1-D (a single quaternion/vector), 2-D (a stack of them along axis 0), or higher-dimensional. In all cases the quaternion/vector components lie along the last axis.

Public API

The module must expose the following two functions.

multiply(q1, q2)

Compute the Hamilton product of two quaternions (or batches thereof).

  • Inputs: q1, q2 — NumPy arrays with the same shape, whose last axis has length 4.
  • Output: A NumPy array with the same shape as the inputs, containing the element-wise (per-batch) quaternion product q1 * q2.
  • Batch behavior: For inputs of shape (..., 4), the product is computed independently for each quaternion along the leading axes, and the result has the identical shape (..., 4). This applies to 1-D, 2-D, and higher-dimensional (e.g. 3-D) inputs.

Required behaviors that must hold:

  • multiply of two zero quaternions [0,0,0,0] yields [0,0,0,0].
  • multiply of two identity quaternions [1,0,0,0] yields [1,0,0,0].
  • These hold both for single quaternions and for batched arrays (each batch element behaving as above).
rotate(q, v)

Rotate 3-vector(s) by quaternion(s).

  • Inputs:
    • q — NumPy array of quaternions, last axis length 4, shape (..., 4).
    • v — NumPy array of 3-vectors, last axis length 3, shape (..., 3), with leading dimensions matching those of q.
  • Output: A NumPy array of rotated 3-vectors with the same shape as v, i.e. (..., 3). Rotation is computed independently per batch element.
  • Batch behavior: Must support single vectors (1-D), 2-D stacks, and higher-dimensional (3-D) arrays, with the vector components along the last axis.

Required behaviors that must hold:

  • Rotating any vector by the zero quaternion [0,0,0,0] yields the zero vector [0,0,0].
  • Rotating any vector by the identity quaternion [1,0,0,0] yields the vector unchanged.
  • These hold both for single vectors and for batched arrays (each batch element behaving as above).

Numerical Requirements

  • For the trivial cases above (zero and identity quaternions), results must be exactly equal to the expected arrays.
  • For general (arbitrary) quaternion inputs, results must be correct to within standard floating-point tolerance (as with numpy.allclose).

Packaging Notes

  • The module must be importable simply as quaternion and expose multiply and rotate as top-level attributes (quaternion.multiply, quaternion.rotate).

Converts a unit quaternion into a 3×3 rotation matrix.

  • Input: a length-4 NumPy array [w, x, y, z].
  • Returns a (3, 3) NumPy array.
  • Required behavior:
    • A zero quaternion [0, 0, 0, 0] must raise ZeroDivisionError.
    • [1, 0, 0, 0] returns exactly np.eye(3).

      [[0, 1, 0],
 [0, 0, -1],

    • from_matrix and to_matrix are mutual inverses for these cases.

Additional Existing Functions

These support quaternion arrays of shape (..., 4) and, for rotate, vector arrays of shape (..., 3), operating over the last axis with standard broadcasting. multiply performs the Hamilton quaternion product; rotate applies a quaternion rotation to a 3-vector. Task Specification: Quaternion Library (hamilton)

Overview

Implement a NumPy-based Python package named hamilton for quaternion algebra and 3D rotations. It must be importable with import hamilton, and every required callable must be available directly on the package.

Public API

The package must expose these top-level callables:

  • conjugate
  • multiply
  • rotate
  • about_axis
  • from_euler
  • to_euler
  • from_matrix
  • to_matrix
  • norm
  • normalize

Data conventions and common behavior

  • A quaternion is a NumPy array whose final axis has length 4 and is ordered as [w, x, y, z], where w is the scalar part and [x, y, z] is the vector part.
  • A 3D vector is a NumPy array whose final axis has length 3.
  • Functions that support batches operate independently over arbitrary leading dimensions. Thus, quaternion shapes such as (4,), (N, 4), (A, B, 4), and higher-dimensional (..., 4) shapes are supported where stated.
  • Array-valued results must be NumPy arrays with the documented final component axis and leading shape.
  • Angles are expressed in radians.
No in-place mutation

No public operation may modify any caller-supplied input array. Array results must be newly produced rather than aliases that are modified in place. This applies to every operation, including conjugate and from_euler.

Quaternion operations

conjugate(q)

Accept a quaternion or batch of quaternions of shape (..., 4) and return a fresh array of the same shape. For each quaternion,

conjugate([w, x, y, z]) = [w, -x, -y, -z]

The original q must remain unchanged.

norm(q)

Compute the Euclidean norm along the final axis, exactly as:

np.linalg.norm(q, axis=-1)

For an input of shape (..., 4), the result has shape (...); a single quaternion of shape (4,) therefore produces a scalar norm. The same last-axis behavior also permits vector inputs such as shape (..., 3).

normalize(q)

Normalize each item independently along its final axis. Its required result is exactly equivalent to:

q / norm(q)[..., np.newaxis]

The result has the same shape as q. This operation supports arbitrary leading dimensions and applies to both quaternions and 3D vectors. It must not mutate q.

multiply(q1, q2)

Compute the elementwise Hamilton product of two equally shaped quaternion arrays. Both operands have shape (..., 4), their shapes must match, and the returned fresh array has the same shape. Differently shaped operands are not implicitly cross-multiplied; they must be rejected with ValueError.

For q1 = [w1, x1, y1, z1] and q2 = [w2, x2, y2, z2], each result is:

w = w1*w2 - x1*x2 - y1*y2 - z1*z2
x = w1*x2 + x1*w2 + y1*z2 - z1*y2
y = w1*y2 - x1*z2 + y1*w2 + z1*x2
z = w1*z2 + x1*y2 - y1*x2 + z1*w2

Neither operand may be modified. In particular, multiplying two zero quaternions produces [0, 0, 0, 0], and multiplying the identity quaternion by itself produces the identity quaternion.

rotate(q, v)

Rotate vectors using the quaternion sandwich product. q has shape (..., 4) and v has the corresponding shape (..., 3), with matching leading dimensions. The operation is performed independently at every leading index and returns a fresh NumPy array of shape (..., 3).

Embed each vector as the pure quaternion [0, vx, vy, vz] and compute:

q * [0, vx, vy, vz] * conjugate(q)

Return the final three components. The function does not implicitly normalize q; the sandwich-product definition governs non-unit inputs as well. Consequently, the identity quaternion leaves a vector unchanged, while the zero quaternion maps it to the zero vector. Neither input may be modified.

Rotation construction and conversion

about_axis(axis, theta)

Construct quaternions for rotations through theta radians about axis.

  • axis has shape (..., 3).
  • theta may be a scalar, have shape axis.shape[:-1], or have any lower-rank shape that NumPy-broadcasts to axis.shape[:-1].
  • The returned array has shape (..., 4), with exactly the same leading dimensions as axis; equivalently, result.shape[:-1] == axis.shape[:-1].

For normalized axis u = axis / norm(axis), the result is:

[cos(theta/2), sin(theta/2)*u_x, sin(theta/2)*u_y, sin(theta/2)*u_z]

Broadcasting must cover, at minimum:

  • one axis of shape (3,) and a scalar angle;
  • axes of shape (N, 3) with either a scalar or (N,) angles;
  • axes of shape (A, B, N, 3) with (A, B, N) angles; and
  • axes of shape (A, B, N, 3) with lower-rank (N,) angles broadcast across A and B.

Canonical examples include a rotation of pi about [1, 0, 0], which yields [0, 1, 0, 0] up to floating-point roundoff, and angles [pi, pi/2, pi/3] about the x, y, and z axes respectively, which yield:

[[0,         1, 0,         0],
 [sqrt(2)/2, 0, sqrt(2)/2, 0],
 [sqrt(3)/2, 0, 0,         1/2]]
from_euler(angles)

Accept exactly one array argument whose final axis contains [alpha, beta, gamma] in the library's 3-2-1 Euler convention. An input of shape (..., 3) returns a quaternion array of shape (..., 4). It is not a three-separate-arguments API.

Let a = alpha/2, b = beta/2, and g = gamma/2, and abbreviate their sines and cosines as sa, ca, sb, cb, sg, and cg. The returned components are:

w = ca*cb*cg + sa*sb*sg
x = sa*cb*cg - ca*sb*sg
y = ca*sb*cg + sa*cb*sg
z = ca*cb*sg - sa*sb*cg

Required canonical values are:

from_euler([0, 0, 0])           = [1, 0, 0, 0]
from_euler([pi/2, pi/2, 0])      = [0.5, 0.5, 0.5, -0.5]

The input angle array must remain unchanged.

to_euler(q)

Convert quaternions of shape (..., 4) to Euler angles in the same convention. Return a NumPy array, not a tuple, of shape (..., 3) ordered as [alpha, beta, gamma].

For q = [w, x, y, z], compute the principal values:

alpha = atan2(2*(w*x + y*z), w*w - x*x - y*y + z*z)
beta  = asin(2*(w*y - x*z))
gamma = atan2(2*(w*z + x*y), w*w + x*x - y*y - z*z)

If one of these expressions produces NaN, return pi/2 for that component. Required canonical values are:

to_euler([1, 0, 0, 0])             = [0, 0, 0]
to_euler([0.5, 0.5, 0.5, 0.5])     = [pi/2, 0, pi/2]
to_matrix(q)

Convert a unit quaternion or batch of unit quaternions of shape (..., 4) to rotation matrices of shape (..., 3, 3). For q = [w, x, y, z], use the convention:

[[1 - 2*(y*y + z*z), 2*(x*y - z*w),     2*(x*z + y*w)],
 [2*(x*y + z*w),     1 - 2*(x*x + z*z), 2*(y*z - x*w)],
 [2*(x*z - y*w),     2*(y*z + x*w),     1 - 2*(x*x + y*y)]]

A zero quaternion cannot define a rotation matrix: to_matrix([0, 0, 0, 0]) must raise ZeroDivisionError. For a batch, the presence of a zero quaternion must likewise raise ZeroDivisionError.

The convention is fixed by these values:

to_matrix([1, 0, 0, 0]) =
[[1, 0, 0],
 [0, 1, 0],
 [0, 0, 1]]

to_matrix([0.5, 0.5, 0.5, 0.5]) =
[[0, 0, 1],
 [1, 0, 0],
 [0, 1, 0]]

to_matrix([0.5, 0.5, 0.5, -0.5]) =
[[ 0, 1,  0],
 [ 0, 0, -1],
 [-1, 0,  0]]
from_matrix(mat)

Convert a rotation matrix or batch of rotation matrices of shape (..., 3, 3) to unit quaternions of shape (..., 4) using the same rotation convention as to_matrix. The result must represent the supplied rotation, and the canonical sign choices for these matrices are:

from_matrix([[1, 0, 0],
             [0, 1, 0],
             [0, 0, 1]])
= [1, 0, 0, 0]

from_matrix([[0, 0, 1],
             [1, 0, 0],
             [0, 1, 0]])
= [0.5, 0.5, 0.5, 0.5]

from_matrix([[ 0, 1,  0],
             [ 0, 0, -1],
             [-1, 0,  0]])
= [0.5, 0.5, 0.5, -0.5]

The non-identity values are understood within normal floating-point tolerance. Inputs must not be modified.

Reference quaternions

The canonical zero and identity values are:

zero     = [0, 0, 0, 0]
identity = [1, 0, 0, 0]

These establish the scalar-first convention throughout the API.
