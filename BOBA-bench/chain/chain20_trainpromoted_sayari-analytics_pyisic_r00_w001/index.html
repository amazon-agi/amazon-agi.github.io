Task Specification: Adding the KSIC10 Standard Together with a KSIC10→ISIC4 Concordance

Summary

Within the pyisic package, support for the KSIC10 (Korean Standard Industrial Classification, revision 10) classification standard is to be added, along with a concordance from KSIC10 to ISIC4. In their behavior, the new standard and the new concordance must stay consistent with the standards and concordances the package already has, and both must take part in the already existing unified ISIC4 concordance graph.

Public API

Direct imports from the top-level pyisic package must make the following objects available:

  • pyisic.KSIC10 — an object that represents the KSIC10 classification standard; its public type and interface must be the same as those of the other standard objects the package exposes, e.g. pyisic.NACE2, pyisic.NAICS2017, and pyisic.TSIC2552.
  • pyisic.KSIC10_to_ISIC4 — a directed concordance object that maps KSIC10 codes to ISIC4 codes; its public type and interface must be the same as those of existing concordances, e.g. pyisic.NACE2_to_ISIC4 and pyisic.TSIC2552_to_ISIC3.

The composed graph pyisic.ToISIC4 at the top level, which already exists, must stay public and must be extended so that the new concordance is included.

Importing the Standards enumeration from pyisic.types must keep working, and it must continue to make Standards.ISIC4 available. The KSIC10 standard must expose its source-standard identity the way the other standard objects expose theirs, so that it can be used as a source in concordance graph operations.

Behavior Requirements

The KSIC10 standard object

The mapping, iteration, and collection behavior exposed by KSIC10 must be the same as that of the package's other standard objects. Specifically:

  • Enumeration of its classification codes must be possible by iterating over KSIC10.
  • Its length must correspond to the number of KSIC10 codes it includes.
  • It must be possible to use its codes as inputs to KSIC10_to_ISIC4.concordant.
  • The code set obtained by enumeration must satisfy the concordance coverage requirement below.
The KSIC10_to_ISIC4 concordance object

Directed relationships from KSIC10 classifications to ISIC4 classifications must be represented by KSIC10_to_ISIC4, which must also expose the usual concordance graph interface, its public nodes and directed edges included. The following must be provided:

  • concordant(code: str) -> set — given a KSIC10 code, return the set of ISIC4 classifications that are concordant with it.

Every element of a result must be a tuple of the form (Standards.ISIC4, "<target_code>"), with the target code being a string. A single source code may map to one or more target codes.

The following cases must be included in the lookup behavior:

  • When a source code is unknown or unmapped, an empty set is returned instead of an error being raised. For instance:
    • KSIC10_to_ISIC4.concordant("DOESNT EXIST") == set()
    • KSIC10_to_ISIC4.concordant("A") == set()
  • The code "14112" has the following known mapping:
    • KSIC10_to_ISIC4.concordant("14112") == {(Standards.ISIC4, "1410")}

Every target entry this concordance produces must use Standards.ISIC4; targets belonging to any other standard must not be produced by it.

Mapping Coverage and Completeness

One or more mappings in KSIC10_to_ISIC4 must exist for at least 40% of the codes that KSIC10 enumerates. Coverage is defined as:

number of KSIC10 codes c for which KSIC10_to_ISIC4.concordant(c) is non-empty / len(KSIC10)

The ratio must be greater than or equal to 0.4. The mapping data must therefore contain enough valid KSIC10-to-ISIC4 relationships for this threshold to be met, and the specific "14112" mapping above must be preserved as well.

Integrating the Concordance into pyisic.ToISIC4

The complete KSIC10_to_ISIC4 concordance must be incorporated into the public combined graph pyisic.ToISIC4; merely exposing that concordance as a standalone object is not enough. Specifically:

  • Every node that KSIC10_to_ISIC4.nodes exposes must also be among the nodes of pyisic.ToISIC4.
  • Every directed edge that KSIC10_to_ISIC4.edges exposes must also appear in pyisic.ToISIC4.edges, carrying the same source and destination.
  • Consequently, KSIC10 source codes must be resolvable to ISIC4 via the unified graph, with the KSIC10 source-standard identity used for this, in the same way as codes from the package's other supported source standards. In particular, unified resolution must include (Standards.ISIC4, "1410") when applied to the KSIC10 code "14112".
  • Containment of nodes and edges is additive: all standards, concordance relationships, and resolution paths that ToISIC4 previously supported must remain available.

Compatibility Constraints and Non-Goals

  • The observable behavior and the public interfaces of existing standards and direct concordances must not be altered.
  • Nodes, directed edges, and lookup results that already exist in pyisic.ToISIC4 must not be removed or changed; integrating KSIC10 must serve to extend that graph.
  • Standards.ISIC4 must be preserved, as must the existing ISIC4 identity used in concordance result tuples.
  • Rather than introducing a separate lookup API, the KSIC10 additions must follow the conventions the package already applies to its standards and concordances.
  • The KSIC10 code and mapping data must be sourced so that all of the following hold: the 40% minimum coverage, the ISIC4-only target requirement, and the explicit example mappings.

An ATECO code string is what ATECO_to_NACE2.concordant(code) accepts, and what it returns is a set of (Standards, str) tuples.
