Overview

Add support for the KSIC10 (Korean Standard Industrial Classification, revision 10) classification standard to the pyisic package, together with a concordance from KSIC10 to ISIC4. The new standard and concordance must behave consistently with the package's existing standards and concordances and must participate in the existing unified ISIC4 concordance graph.

Public API Surface

The following objects must be importable directly from the top-level pyisic package:

  • pyisic.KSIC10 — an object representing the KSIC10 classification standard, with the same public type and interface as the other standard objects exposed by the package, such as pyisic.NACE2, pyisic.NAICS2017, and pyisic.TSIC2552.
  • pyisic.KSIC10_to_ISIC4 — a directed concordance object mapping KSIC10 codes to ISIC4 codes, with the same public type and interface as existing concordances such as pyisic.NACE2_to_ISIC4 and pyisic.TSIC2552_to_ISIC3.

The existing top-level pyisic.ToISIC4 composed graph must remain public and must be extended to include the new concordance.

The Standards enumeration in pyisic.types must remain importable and must continue to provide Standards.ISIC4. The KSIC10 standard must expose its source-standard identity in the same manner as the other standard objects, so it can be used as a source in concordance graph operations.

Required Behavior

KSIC10 standard object

KSIC10 must expose the same mapping, iteration, and collection behavior used by the package's other standard objects. In particular:

  • Its classification codes must be enumerable by iterating over KSIC10.
  • Its length must represent the number of included KSIC10 codes.
  • Its codes must be usable as inputs to KSIC10_to_ISIC4.concordant.
  • The enumerated code set must satisfy the concordance coverage requirement below.
KSIC10_to_ISIC4 concordance object

KSIC10_to_ISIC4 must represent directed relationships from KSIC10 classifications to ISIC4 classifications and expose the normal concordance graph interface, including its public nodes and directed edges. It must provide:

  • concordant(code: str) -> set — return the set of concordant ISIC4 classifications for the supplied KSIC10 code.

Each result element must be a tuple of the form (Standards.ISIC4, "<target_code>"), where the target code is a string. One source code may map to one or more target codes.

Lookup behavior must include the following cases:

  • An unknown or unmapped source code returns an empty set rather than raising an error. For example:
    • KSIC10_to_ISIC4.concordant("DOESNT EXIST") == set()
    • KSIC10_to_ISIC4.concordant("A") == set()
  • The known mapping for code "14112" is:
    • KSIC10_to_ISIC4.concordant("14112") == {(Standards.ISIC4, "1410")}

All target entries produced by this concordance must use Standards.ISIC4; the concordance must not produce targets belonging to any other standard.

Coverage and mapping completeness

At least 40% of the codes enumerated by KSIC10 must have one or more mappings in KSIC10_to_ISIC4. Define coverage as:

number of KSIC10 codes c for which KSIC10_to_ISIC4.concordant(c) is non-empty / len(KSIC10)

This ratio must be greater than or equal to 0.4. The mapping data must therefore include enough valid KSIC10-to-ISIC4 relationships to meet this threshold, in addition to preserving the specific "14112" mapping above.

The public combined graph pyisic.ToISIC4 must incorporate the complete KSIC10_to_ISIC4 concordance, not merely expose that concordance as a standalone object. Specifically:

  • Every node exposed by KSIC10_to_ISIC4.nodes must also be a node in pyisic.ToISIC4.

  • As a consequence, KSIC10 source codes must be resolvable to ISIC4 through the unified graph using the KSIC10 source-standard identity, just like codes from the package's other supported source standards. In particular, unified resolution of KSIC10 code "14112" must include (Standards.ISIC4, "1410").

Node and edge containment is additive: all previously supported standards, concordance relationships, and resolution paths in ToISIC4 must remain available.

Compatibility and Non-Goals

  • Do not alter the observable behavior or public interfaces of existing standards and direct concordances.
  • Do not remove or change existing nodes, directed edges, or lookup results in pyisic.ToISIC4; integrating KSIC10 must extend that graph.
  • Preserve Standards.ISIC4 and the existing ISIC4 identity used in concordance result tuples.
  • The KSIC10 additions must follow the package's existing standard and concordance conventions rather than introducing a separate lookup API.
