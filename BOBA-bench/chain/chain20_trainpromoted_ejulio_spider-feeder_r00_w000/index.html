Input consists of one URL per line, with newline characters separating entries. Line separators are not included in the resulting strings, and empty lines do not become URL entries.

Loader Extension Lifecycle

Both loader classes are Scrapy extensions and must provide from_crawler(cls, crawler).

from_crawler must:

  1. Read configuration from crawler.settings.
  2. Construct an extension instance.
  3. Connect that instance to Scrapy's spider_opened signal.
  4. Return the extension instance.

The loaders are intended to be enabled through Scrapy's EXTENSIONS setting, for example:

EXTENSIONS = {
    "spider_feeder.loaders.StartUrlsLoader": 500,
}

or:

EXTENSIONS = {
    "spider_feeder.loaders.StartRequestsLoader": 500,
}

Normal Scrapy extension initialization followed by delivery of the spider_opened signal must be sufficient to trigger loading; callers must not have to invoke the extension manually.

SPIDERFEEDER_INPUT_URI is required. Each loader's from_crawler(crawler) must raise scrapy.exceptions.NotConfigured if that setting is absent or empty, rather than returning or connecting an active extension. This requirement applies in particular to StartUrlsLoader.from_crawler(crawler).

Input URI Formatting and Store Resolution

Before resolving or opening a store, the configured SPIDERFEEDER_INPUT_URI must support Python mapping-style % interpolation against the opened spider's attributes. For example, with spider attributes dir = "/tmp" and input_file = "spider_input":

SPIDERFEEDER_INPUT_URI = "%(dir)s/%(input_file)s.txt"

must resolve to /tmp/spider_input.txt. The fully formatted URI is used both for scheme selection and as the URI passed to the store.

Both loaders use this built-in scheme-to-store mapping:

URI scheme Store class
no scheme spider_feeder.store.file_store.FileStore
file spider_feeder.store.file_store.FileStore
s3 spider_feeder.store.file_store.FileStore
collections spider_feeder.store.scrapinghub_collection.ScrapinghubCollectionStore

SPIDERFEEDER_STORES may contain a mapping from scheme names to dotted store-class paths. Its entries are merged with the built-ins: a new scheme adds support, and an entry for a built-in scheme overrides that built-in.

After selecting and importing the class, instantiate it with exactly these two positional arguments:

store_class(formatted_uri, crawler.settings)

A store must be iterable and produce ordered (url, meta) pairs, where url is the input URL and meta is a dictionary associated with it.

StartUrlsLoader

When the spider opens, StartUrlsLoader must:

  1. Resolve and instantiate the store.
  2. Iterate all store entries in order.
  3. Assign spider.start_urls an iterable collection containing only each pair's url, in the same order. Metadata is ignored by this loader.
  4. Set the crawler stat spider_feeder/<spider_name>/url_count to the number of entries loaded, where <spider_name> is the opened crawler spider's name.

The resulting spider.start_urls must be consumable as an iterable of URL strings.

StartRequestsLoader

When the spider opens, StartRequestsLoader must:

  1. Resolve and instantiate the same kind of store as StartUrlsLoader.
  2. Load all (url, meta) pairs in store order.
  3. Make spider.start_requests callable and make iteration of spider.start_requests() produce one Scrapy Request for each loaded pair.
  4. Set spider_feeder/<spider_name>/url_count to the number of loaded pairs.

For every pair, the corresponding request must have:

  • request.url equal to the stored URL; and
  • request.meta equal to the stored metadata dictionary, without losing its fields.

Request order must match store order. Entries are not deduplicated: repeated pairs, including repeated URLs with the same metadata, must each produce a separate request.

Common Input-Item Conversion

The built-in FileStore and ScrapinghubCollectionStore use SPIDERFEEDER_INPUT_FIELD to convert logical input items into (url, meta) pairs.

  • If no non-empty SPIDERFEEDER_INPUT_FIELD is configured (including when it is absent, None, or the empty string), each logical item produces (item, {}).

  • If it is a non-empty field name, each logical item must be a dictionary and produces (item[field_name], item). The original dictionary is the metadata value.

  • If a non-empty field is configured but an item is not a dictionary, iteration must raise TypeError, and the exception's first argument must be exactly:

    Data is expected to be a dict when SPIDERFEEDER_INPUT_FIELD is set.

This conversion preserves input order and does not deduplicate items.

FileStore

Constructor and Iteration

FileStore(uri, settings) represents a local or remote input file. Iterating it must:

  1. Select a file handler from the URI scheme.
  2. Open the complete URI with the configured encoding.
  3. Select a parser from the URI's file extension, excluding the leading dot.
  4. Call the parser with the opened text object and the same settings object passed to FileStore.
  5. Apply the common input-item conversion to each parsed item.
Built-in File Handlers

The built-in handler mapping is:

URI scheme Handler callable
no scheme spider_feeder.store.file_handler.local.open
file spider_feeder.store.file_handler.local.open
s3 spider_feeder.store.file_handler.s3.open

The encoding defaults to utf-8. If SPIDERFEEDER_INPUT_FILE_ENCODING is set, its value replaces that default. The selected handler receives the full, unmodified URI and the encoding as a keyword argument:

handler(uri, encoding=selected_encoding)

SPIDERFEEDER_FILE_HANDLERS may map scheme names to dotted callable paths. These entries add new schemes or override built-in handlers while retaining the same call contract.

Built-in File Parsers

The built-in extension mapping is:

Extension Parser callable
txt spider_feeder.store.parser.parse_txt
csv spider_feeder.store.parser.parse_csv
json spider_feeder.store.parser.parse_json

SPIDERFEEDER_FILE_PARSERS may map extensions, without a leading dot, to dotted parser-callable paths. These entries add new formats or override built-ins. The selected parser is called with two positional arguments:

parser(opened_content, settings)

For example, a text file with no input field produces (line, {}) per line. A CSV or JSON file containing dictionaries can use SPIDERFEEDER_INPUT_FIELD to select the URL while retaining the full dictionary as metadata.

Parser Functions

All three built-in parser functions accept (content, settings). content is an opened text/file-like object; settings is accepted as part of the public parser interface.

parse_txt(content, settings)

Read the content and return its lines in order as strings, without line-ending characters.

parse_csv(content, settings)

Parse the first row as column headers and return subsequent rows in order as dictionaries keyed by those headers. CSV field values remain strings.

parse_json(content, settings)

Decode and return the JSON value. JSON value types must be preserved; for example, JSON numbers remain numeric rather than being converted to strings.

Local File Handler

The module spider_feeder.store.file_handler.local must expose the standard Python builtins module as builtins and provide:

open(file_uri, encoding)

If file_uri starts with file://, remove that prefix before opening it. A schemeless path is used unchanged. Delegate to:

builtins.open(resulting_path, encoding=encoding)

The supplied encoding value must be passed through unchanged, and the underlying file object's result must be returned.

S3 File Handler

The module spider_feeder.store.file_handler.s3 must provide:

open(blob_uri, encoding)

Supported URIs include:

s3://bucket/key
s3://access_key:secret_key@bucket/key
Credentials and Client Creation

If both access credentials are present in the URI, they take precedence. Otherwise, obtain them from the Scrapy project settings named:

  • SPIDERFEEDER_AWS_ACCESS_KEY_ID
  • SPIDERFEEDER_AWS_SECRET_ACCESS_KEY

Create the client through the botocore session using the resolved values:

get_session().create_client(
    "s3",
    aws_access_key_id=access_key,
    aws_secret_access_key=secret_key,
)
Object Retrieval and Return Value

Use the URI hostname as the bucket and the URI path with its leading slash removed as the object key. Retrieve it with the requested encoding:

client.get_object(
    Bucket=bucket,
    Key=key,
    ResponseContentEncoding=encoding,
)

Read the response's Body, decode its bytes using the same encoding, and return an io.StringIO containing the decoded text. This must work for the default UTF-8 encoding and alternate encodings supplied through SPIDERFEEDER_INPUT_FILE_ENCODING or direct calls.

Scrapinghub Collection Store

ScrapinghubCollectionStore(uri, settings) supports collections://<collection_name> URIs.

On construction it must:

  1. Create a ScrapinghubClient using its normal environment-based configuration.
  2. Read SHUB_JOBKEY from the environment and derive the project identifier from that job key.
  3. Obtain the project with client.get_project(project_id).
  4. Remove the collections:// prefix from the URI to obtain the collection name.
  5. Obtain the collection through project.collections.get_store(collection_name).

Iteration must consume the records returned by the collection store's iter() method in their provided order. Collection records are envelopes; each envelope's value member is the logical input item. Apply the common SPIDERFEEDER_INPUT_FIELD conversion to that value:

  • without a non-empty input field, yield (envelope["value"], {});
  • with a non-empty input field and a dictionary value, yield (value[field_name], value); and
  • with a non-empty input field and a non-dictionary value, raise the exact TypeError described above.

Configuration Summary

  • SPIDERFEEDER_INPUT_URI: required input URI; supports spider-attribute % interpolation.
  • SPIDERFEEDER_STORES: scheme-to-dotted-store-class additions or overrides.
  • SPIDERFEEDER_INPUT_FIELD: optional dictionary field containing the URL; false/empty values mean the whole logical item is the URL.
  • SPIDERFEEDER_INPUT_FILE_ENCODING: file decoding name; defaults to utf-8.
  • SPIDERFEEDER_FILE_HANDLERS: file-scheme-to-dotted-handler additions or overrides.
  • SPIDERFEEDER_FILE_PARSERS: file-extension-to-dotted-parser additions or overrides.
  • SPIDERFEEDER_AWS_ACCESS_KEY_ID and SPIDERFEEDER_AWS_SECRET_ACCESS_KEY: fallback S3 credentials when credentials are not embedded in the URI.
