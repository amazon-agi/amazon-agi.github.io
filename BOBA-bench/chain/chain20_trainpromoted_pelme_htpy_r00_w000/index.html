01 Class Attribute Support in htpy 392 words · source specification

Task Specification: Class Attribute Support in htpy

Overview

Implement support for a class_ keyword attribute on HTML element builders in the htpy module. The attribute must accept multiple value types (string, list, dict) and render an appropriate, HTML-escaped class attribute on the generated element.

Public API

The module htpy must expose element builder objects, including at minimum div, ul, and li. Each element builder must be callable and support:

  • A single positional argument for text content, e.g. div("hello").
  • A class_ keyword argument (note the trailing underscore) to specify the element's CSS class attribute.

Calling an element builder returns an object whose str() representation is the rendered HTML string.

Required Behavior

Basic rendering

str(div("hello")) must produce:

<div>hello</div>

An element with no content and no attributes renders as an empty element with open and close tags, e.g. <div></div>.

class_ attribute rendering

When class_ is provided, the rendered element must include a class attribute (rendered as the HTML attribute name class, without the trailing underscore). The resolved class value is HTML-escaped in the output. The < and > characters must be escaped as &lt; and &gt; respectively (e.g. a class value containing >foo renders as &gt;foo).

The class_ argument accepts the following value types, each resolving to a final space-separated class string:

String

The string is used directly as the class value (then HTML-escaped on output).

  • div(class_=">foo bar") → <div class="&gt;foo bar"></div>

List

A list of items. Each item that is a non-empty string is included. Items that are falsy — specifically False, None, and the empty string "" — are omitted. The included string items are joined with a single space, in order.

  • div(class_=[">foo", False, None, "", "bar"]) → <div class="&gt;foo bar"></div>

Dict

A dict mapping class-name strings to values. A class name (the key) is included when its associated value is truthy, and omitted when the value is falsy (False, None, and "" are all treated as falsy/omit). Included keys are joined with a single space, preserving insertion order.

  • div(class_={">foo": True, "x": False, "y": None, "z": "", "bar": True}) → <div class="&gt;foo bar"></div>

Notes

  • The final class string is HTML-escaped in the rendered output regardless of the input type.
  • Class names are joined by exactly one space with no leading or trailing whitespace introduced by omitted entries.
02 htpy HTML Generation Library 1242 words · rewritten by GPT-5.6-sol

Task Specification: htpy HTML Generation Library

Implement a typed Python library named htpy that provides a declarative API for building HTML. Every public name described below must be importable directly from the top-level htpy module, for example from htpy import div, mark_safe, Element, SafeString. The distributed package must include a py.typed marker so that its type information is exported.

Public API Surface

Element factories

HTML tag names are exposed as importable, callable module attributes. This includes standard tags such as div, ul, li, button, img, input, html, head, and body, as well as arbitrary custom names. Accessing an otherwise valid Python identifier as an attribute of htpy, including through an import such as from htpy import my_custom_element, must provide the corresponding element factory.

For module-level factory names, every underscore is converted to a hyphen in the emitted tag name. For example, my_custom_element() renders as <my-custom-element></my-custom-element>.

Element

Element is the public type returned by every element-factory call, including calls that apply attributes or children. An Element must support:

  • str(element), which returns its complete serialized HTML.
  • Iteration with iter(element) or list(element), which yields the serialized HTML as ordered string pieces. For a normal non-void element, the opening tag, including its attributes, is one piece; ordinary child content is yielded in order; nested elements yield their own pieces recursively; and the closing tag is one piece. Joining all yielded pieces must equal str(element). Void elements and the special html serialization follow their rules below while retaining the same join-to-full-output guarantee.
SafeString

SafeString is the public type returned by mark_safe. It represents HTML content that has already been made safe and must not be escaped again when used as element content.

mark_safe(value: str) -> SafeString

mark_safe wraps the supplied string as a SafeString. When that value is rendered as a child, its contents are inserted verbatim.

Element Construction

An element factory can be used in the following forms:

  1. With attributes, supplied as keyword arguments and/or as a single positional dictionary:
    • div(id="hello")
    • button(hx_post="/foo")
    • div({"@click": "..."})
  2. With children, supplied positionally:
    • div("hello")
    • ul(li(), li())
    • ul([li("a"), li("b")])
    • ul(li(x) for x in ["a", "b"])
  3. By applying children to an existing element, so an element created with attributes is itself callable:
    • div(id="a")("hi")

Every one of these forms returns an Element. Both dictionary and keyword attribute forms must be supported; no separate attribute-chaining or attribute-merging API beyond these construction forms is required.

Children

Accepted child forms are:

  • One or more positional strings or Element objects, such as ul(li(), li()).
  • A single list of children, such as ul([li("a"), li("b")]).
  • A single generator or iterator of children, such as ul(li(x) for x in ["a", "b"]).
  • A SafeString, which is handled as described under escaping.

Ordinary string children are escaped for HTML text content. SafeString children are emitted verbatim, and nested Element children emit their own HTML. Lists and iterators represent sequences of children rather than literal child values. Child order must be preserved.

An element must be reusable: rendering the same element repeatedly must produce the same output. In particular, construction from a one-shot generator or iterator must not cause later renders to lose its children.

Calling a factory without arguments creates an empty element. Non-void elements still have an explicit closing tag, for example:

  • str(div()) → <div></div>

A single positional dict is interpreted as attributes. A single positional value of another supported kind—a string, SafeString, Element, list, generator, or iterator—is interpreted as child content.

Attributes

Attributes can be supplied through keyword arguments or through a single positional dictionary.

Keyword attribute names

Keyword names are translated before serialization:

  • One trailing underscore is stripped, so class_ becomes class.
  • Other remaining underscores are converted to hyphens, so hx_post becomes hx-post.
  • The keyword name _ is a special case and remains _, supporting syntax such as div(_="foo"), which renders as <div _="foo"></div>.

For example, button(hx_post="/foo")("click me!") renders as <button hx-post="/foo">click me!</button>.

Dictionary attribute names

Keys supplied in an attribute dictionary are treated literally: trailing underscores are not stripped and embedded underscores are not converted to hyphens. For example:

  • str(div({"class_": "foo", "hello_hi": "abc"})) → <div class_="foo" hello_hi="abc"></div>
  • A key such as @click remains @click.

Dictionary attribute names are HTML-escaped when emitted. For example:

  • str(div({"<disturbing attr>": "value"})) → <div &lt;disturbing attr&gt;="value"></div>
Attribute values
  • A string value is HTML-escaped for an attribute context and emitted as name="value".
  • Boolean True emits a minimized attribute consisting only of its name.
  • Boolean False omits the attribute completely.

Boolean handling is the same for keyword and dictionary attributes. It affects only the opening tag; it never suppresses the closing tag of a non-void element. For example:

  • str(button(disabled=True)) → <button disabled></button>
  • str(button(disabled=False)) → <button></button>
  • str(div({"bool-true": True})) → <div bool-true></div>
  • str(div({"bool-false": False})) → <div></div>

When children are present, the non-void closing tag likewise follows those children, regardless of whether a boolean attribute was minimized or omitted.

Special handling for the class value

The value of the class attribute supports class-name composition:

  • String: escape it and use it as-is.
  • List: include only truthy string items. Falsy items such as False, None, and "" are dropped. Escape each included item and join the items with one space.
  • Dictionary: treat keys as class names and values as conditions. Include a key only when its condition is truthy, preserve insertion order, escape each included class name, and join included names with one space.

Examples:

  • str(div(class_=">foo bar")) → <div class="&gt;foo bar"></div>
  • str(div(class_=[">foo", False, None, "", "bar"])) → <div class="&gt;foo bar"></div>
  • str(div(class_={">foo": True, "x": False, "y": None, "z": "", "bar": True})) → <div class="&gt;foo bar"></div>

Escaping

Escaping is context-sensitive. Dictionary attribute names and string attribute values use attribute-context escaping. Ordinary string children use text-context escaping. At minimum, the following rules apply:

  • < becomes &lt; and > becomes &gt; in ordinary string children, dictionary attribute names, and string attribute values.
  • A double quote (") becomes &quot; in attribute names and values.
  • A double quote in an ordinary string child remains a literal "; it is not escaped merely because it occurs in text content.

Consequently:

  • str(div('<hello">')) → <div>&lt;hello"&gt;</div>
  • str(div(id='"hello"')) → <div id="&quot;hello&quot;"></div>
  • str(div("<foo></foo>")) → <div>&lt;foo&gt;&lt;/foo&gt;</div>

A SafeString used as content bypasses child escaping:

  • str(div(mark_safe("<foo></foo>"))) → <div><foo></foo></div>

Closing Tags and Void Elements

Every non-void element always emits its closing tag. This includes empty elements and elements whose opening tags contain minimized boolean attributes or omit false boolean attributes. For example, an empty custom element renders as <my-custom-element></my-custom-element>, not as a self-closing tag.

HTML void elements render only their opening tag, without a closing tag. The supported void-element set includes at least img and input:

  • str(input(name="foo")) → <input name="foo">
  • str(img()) → <img>

Void elements cannot have children. Passing children to one must raise ValueError with a message of the form "{tag} elements cannot have children"; for example, img("hey") raises ValueError with a message matching img elements cannot have children.

Special html Element

The html element prepends the lowercase HTML doctype declaration to its serialized output:

  • str(html(foo="bar")("hello")) → <!doctype html><html foo="bar">hello</html>

Typing Requirements

  • Element-factory calls must be statically typed as returning Element.
  • mark_safe(...) must be statically typed as returning SafeString.
  • Element and SafeString must be importable and usable directly in type annotations.
  • The package must ship its py.typed marker.
03 Implement a Python module named htpy that provides a declarative way to build HTML strings. 569 words · source specification

Task: Implement htpy — an HTML generation library

Implement a Python module named htpy that provides a declarative way to build HTML strings. The public API must support importing HTML element objects (e.g. div, ul, li, button, html, img), plus SafeString and mark_safe.

Public API

The module htpy must expose:

  • HTML element objects accessible by name: div, ul, li, button, html, img, and any other standard HTML tag name accessed as an attribute/importable name from the module.
  • A SafeString type.
  • A mark_safe(value: str) -> SafeString function.

Element behavior

Each element name (e.g. div) is an object representing an HTML tag. Elements support two independent operations:

1. Setting attributes — via calling ()

Calling an element with arguments returns a new element carrying those attributes. Two calling forms must be supported:

  • Keyword arguments: div(id="hello") produces attributes from kwargs. Underscores in keyword names are replaced with hyphens (e.g. hx_post="/foo" → hx-post="/foo").
  • A single dict argument: div({"@click": 'hi = "hello"'}) produces attributes directly from the dict keys/values, allowing attribute names that are not valid Python identifiers.

Calling with no arguments is allowed and yields an element with no attributes.

Attribute value rules:

  • String values render as name="value".
  • A boolean value of True renders the attribute name alone with no value (e.g. disabled=True → disabled).
  • A boolean value of False omits the attribute entirely.

Attribute values are HTML-escaped, and attribute names are escaped as needed. For example, a value containing " is escaped to &quot;.

2. Setting children — via subscript []

Indexing an element with [] sets its children and returns a new element. The children expression may be:

  • A single string: div["hello"].
  • Multiple comma-separated children: ul[li(), li()].
  • Nested elements: div(id="a")[div(id="b")["inner"]].
  • A list of children: ul[[li["a"], li["b"]]].
  • A tuple of children: ul[(li["a"], li["b"])].
  • A generator of children: ul[(li[x] for x in ["a", "b"])].

Lists, tuples, and generators are flattened so their items become the element's children.

Attributes and children compose: div(id="hello")["hi"] sets attribute id and child hi.

Void elements

img is a void element. Attempting to give it children via [] must raise ValueError with a message matching img elements cannot have children.

The html element

Rendering the html element prepends a doctype. For example, html(foo="bar")["hello"] renders as <!doctype html><html foo="bar">hello</html>.

Rendering

str()

Calling str() on an element renders the complete HTML string:

  • An empty element renders as <tag></tag> (e.g. str(button(disabled=True)) → <button disabled></button>).
  • Elements with attributes and/or children render accordingly.
Iteration

Iterating an element yields the HTML in string chunks: the opening tag (with attributes) as one chunk, each child rendered, and the closing tag as a final chunk.

Examples:

  • list(div(id="a")["hello"]) → ['<div id="a">', "hello", "</div>"]
  • list(ul[li(id="a")["hi a"], li(id="b")["hi b"]]) → ['<ul>', '<li id="a">', "hi a", "</li>", '<li id="b">', "hi b", "</li>", "</ul>"]
__html__()

Each element provides an __html__() method returning the same full HTML string as str(). For example, div(id="a").__html__() → <div id="a"></div>.

Escaping

Text children are HTML-escaped when rendered:

  • < → &lt;, > → &gt;
  • A " in text content is left as-is (div['<hello">'] → <div>&lt;hello"&gt;</div>).

Safe strings

  • mark_safe(s) returns a SafeString (a str subtype) whose contents are treated as already-safe HTML and are not escaped when used as a child.
  • str(div[mark_safe("<foo></foo>")]) → <div><foo></foo></div>.
  • By contrast, ordinary strings are escaped: str(div["<foo></foo>"]) → <div>&lt;foo&gt;&lt;/foo&gt;</div>.
04 HTML Element Builder Library (htpy) 1460 words · rewritten by GPT-5.6-sol

Task Specification: HTML Element Builder Library (htpy)

Overview

Implement a Python module named htpy that provides an expressive API for constructing HTML markup. Module-level element objects accept attributes by being called and accept children through subscription. The resulting objects render to escaped HTML strings and can also be consumed as ordered streams of HTML fragments.

Public API Surface

The htpy module must expose these importable public names:

  • Element: the class/type representing an HTML element.
  • SafeString: a str subclass representing trusted, already-safe markup.
  • mark_safe: a callable accepting a str and returning a SafeString.
  • Element objects for standard and custom tags, including at least div, ul, li, img, input, html, button, and my_custom_element.

The package must expose typing information with these results:

  • A bare element such as div, a called element such as div(), and an element with children such as div()["a"] all statically type as Element.
  • mark_safe(...) statically returns SafeString.
  • Element.__html__() statically returns str.
  • Dynamically named module elements statically type as Element.
Dynamic elements and identity

Accessing any otherwise-undefined attribute on htpy must produce an Element. Convert the Python attribute name to the HTML tag name by replacing every underscore with a hyphen. For example, htpy.my_custom_element renders the tag my-custom-element.

Bare module-level elements are cached by name. Repeated access to the same predefined or dynamically produced element must return the identical object; in particular, htpy.div is htpy.div is true. Calling or subscripting that reusable bare element produces an element expression without changing the behavior of the shared bare element.

Element Construction

An element supports three forms that can be combined:

  1. Bare use: div
  2. Calling for attributes: div(id="a") or div({"id": "a"})
  3. Subscripting for children: div["hello"]

Calling with no arguments is valid and returns an Element with unchanged rendered content. Attribute and child operations can be chained, as in div(id="a")["hello"].

str(element) returns the complete rendered markup. A bare ordinary element has no attributes or children, so str(div) is <div></div>.

Attributes

Attributes are attached by calling an element. Existing attributes on an element expression are retained when another construction step adds children.

Accepted forms

Attributes may be supplied in either of these forms:

  • Keyword arguments: div(id="hello")
  • One positional dictionary: div({"id": "hello"})

The dictionary and keyword forms must not be mixed in one call; doing so raises TypeError. Attributes render in the opening tag. A non-boolean attribute has the form name="value", including the leading space and double quotes.

Keyword attribute-name conversion

For keyword arguments only:

  • Remove one trailing underscore, allowing Python keywords or conventional aliases such as class_ to represent class.
  • Replace remaining underscores with hyphens, so hx_post becomes hx-post.
  • Preserve the single name _ exactly, so div(_="foo") renders <div _="foo"></div>.

Consequently:

div(class_=">foo bar")
# <div class="&gt;foo bar"></div>

button(hx_post="/foo")["click me!"]
# <button hx-post="/foo">click me!</button>

Dictionary keys are used exactly as supplied before escaping; they do not undergo trailing-underscore removal or underscore-to-hyphen conversion:

div({"class_": "foo", "hello_hi": "abc"})
# <div class_="foo" hello_hi="abc"></div>
Boolean attributes

Boolean values have HTML boolean-attribute semantics in both input forms:

  • True includes only the attribute name, with no ="..." suffix.
  • False omits the attribute entirely.

For example:

button(disabled=True)       # <button disabled></button>
button(disabled=False)      # <button></button>
div({"bool-true": True})   # <div bool-true></div>
div({"bool-false": False}) # <div></div>
class values

The normalized class attribute supports class-name composition:

  • A string is used as the class value.
  • A list or tuple is filtered to its truthy items, and those items are converted to text and joined with single spaces.
  • A dictionary contributes each key whose corresponding value is truthy, preserving dictionary iteration order; included keys are joined with single spaces.

Class names are escaped for attribute context. Thus:

div(class_=[">foo", False, None, "", "bar"])
# <div class="&gt;foo bar"></div>

div(class_={">foo": True, "x": False, "y": None, "z": "", "bar": True})
# <div class="&gt;foo bar"></div>
Attribute escaping

Ordinary attribute names and values are converted to text and escaped for a double-quoted attribute context. This includes escaping &, <, >, and " (with " becoming &quot;). Attribute names are escaped as well as values.

Examples:

div(id='"hello"')
# <div id="&quot;hello&quot;"></div>

div({"@click": 'hi = "hello"'})
# <div @click="hi = &quot;hello&quot;"></div>

div({"<disturbing attr>": "value"})
# <div &lt;disturbing attr&gt;="value"></div>

div({'<"': '"hello"'})
# <div &lt;&quot;="&quot;hello&quot;"></div>

SafeString attribute names and values bypass this escaping, as described under Safe strings.

Children

Children are attached with element[...]. Supported child forms include:

  • One child: div["hello"]
  • Multiple comma-separated children: ul[li, li]
  • A list: ul[[li["a"], li["b"]]]
  • A tuple: ul[(li["a"], li["b"])]
  • A generator: ul[(li[x] for x in ["a", "b"])]
  • Nested Element objects

Lists, tuples, and generators supplied in the child position are expanded in order into sibling children. Nested elements render recursively in document order.

Ordinary child values are converted to text and escaped in child-text context. A bare element used as a child renders that element:

ul[li, li]
# <ul><li></li><li></li></ul>

div(id="a")[div(id="b")["inner"]]
# <div id="a"><div id="b">inner</div></div>
Ignored children

None and the boolean value False are ignored entirely wherever they occur as children and produce no text or iteration fragment:

div[None]   # <div></div>
div[False]  # <div></div>

This rule must distinguish False from numeric zero. 0 is not ignored and renders as text:

div[0]      # <div>0</div>

Rendering Rules

Ordinary elements

A non-void element renders an opening tag, its children, and a closing tag. It always includes the closing tag even when empty:

div["hello"]             # <div>hello</div>
div(id="hello")["hi"]    # <div id="hello">hi</div>
Void elements

The HTML void elements are area, base, br, col, embed, hr, img, input, link, meta, param, source, track, and wbr. They render only an opening tag, with no slash and no closing tag:

input(name="foo")  # <input name="foo">
img()               # <img>
div[img]            # <div><img></div>

Void elements cannot have children. An attempt to attach children raises ValueError; the message identifies the tag using the form <name> elements cannot have children. For example, img["hey"] raises ValueError with img elements cannot have children in its message.

The html element and doctype

The module-level html element prefixes its rendered element with the exact HTML doctype <!doctype html> and no intervening whitespace:

html(foo="bar")["hello"]
# <!doctype html><html foo="bar">hello</html>

The doctype remains present when attributes or children are added to html.

Context-Sensitive Escaping

Escaping differs between child text and attributes.

Ordinary child text

For untrusted child text, escape markup-significant characters such as &, <, and >. Double quotes are not escaped in child-text context. In particular:

div['>"']
# <div>&gt;"</div>

div["<foo></foo>"]
# <div>&lt;foo&gt;&lt;/foo&gt;</div>

This child-specific rule takes precedence over attribute quoting rules: " becomes &quot; in an attribute name or value, but remains a literal " in ordinary child text.

Safe strings

mark_safe(value) returns a SafeString, a trusted str subclass. A SafeString is emitted verbatim rather than escaped when used as child content, an attribute value, or a dictionary attribute key.

str(div[mark_safe("<hello></hello>")])
# <div><hello></hello></div>

str(div(id=mark_safe("<hi>")))
# <div id="<hi>"></div>

str(div({mark_safe('<"'): mark_safe('"hello"')}))
# <div <"=""hello""></div>

Trust is explicit: the plain string "<foo></foo>" is escaped as child text, while mark_safe("<foo></foo>") is not. SafeString.__html__() returns its trusted string content.

Fragment Iteration

An Element is iterable and yields str fragments in rendering order. Joining all yielded fragments must equal str(element).

For an ordinary element, iteration yields:

  1. The opening tag, including attributes, as one fragment.
  2. Child fragments in document order. A nested element contributes its own fragments depth-first.
  3. The closing tag as one fragment.

For example:

list(div(id="a")["hello"])
# ['<div id="a">', 'hello', '</div>']

list(ul[li(id="a")["hi a"], li(id="b")["hi b"]])
# [
#   '<ul>',
#   '<li id="a">', 'hi a', '</li>',
#   '<li id="b">', 'hi b', '</li>',
#   '</ul>',
# ]

Ignored None and False children yield no fragment. A void element yields only its opening-tag fragment. The html element yields <!doctype html> as its first fragment, followed by the ordinary html element fragments.

__html__ Interface

Every element provides __html__(). It returns a str exactly equal to str(element), allowing the element to participate in HTML-safe rendering interfaces:

div(id="a").__html__()
# <div id="a"></div>

Representation

repr(element) has the exact form:

<htpy element '<rendered HTML>'>

where <rendered HTML> is the same markup produced by str(element). For example:

repr(div)
# <htpy element '<div></div>'>

05 You are extending an HTML element generation library that produces HTML element objects which render to string form. 331 words · source specification

Overview

You are extending an HTML element generation library that produces HTML element objects which render to string form. This task adds support for specifying an element's id and class attributes using a compact CSS-selector-like string passed as a positional argument.

API Surface

The library exposes HTML element factory callables (e.g., div, button) that:

  • Accept content and/or attribute specifications.
  • Return an object whose str() representation is the rendered HTML.

These callables are importable and callable directly (as demonstrated by existing usage such as div(...) and button(...)).

Required Behavior

CSS-selector-like string for id and class

When an element factory (e.g., div) is called with a single positional string argument that begins with # and/or . tokens, that string must be interpreted as a shorthand for the element's id and class attributes rather than as text content.

The shorthand string syntax:

  • A #-prefixed token specifies the element's id.
  • Each .-prefixed token specifies a CSS class name.
  • Multiple class tokens are combined into a single class attribute, with the individual class names separated by a single space, in the order they appear in the string.

Example:

div("#myid.cls1.cls2")

must render as:

<div id="myid" class="cls1 cls2"></div>

Here the #myid token becomes id="myid", and the two .cls1 and .cls2 tokens are combined into class="cls1 cls2". The element has no text content in this case.

Existing behavior to preserve

result = div(class_=("foo", {"bar": False}))

converting result to a string must produce exactly:

<div class="foo"></div>

The class name "foo" is included, while "bar" is omitted because its mapping value is False. Omitting the false conditional class must not leave trailing or additional whitespace in the rendered class attribute.
