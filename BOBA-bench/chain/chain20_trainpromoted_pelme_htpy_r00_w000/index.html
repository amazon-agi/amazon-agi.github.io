01 Support for Class Attributes in htpy 440 words · source specification, reworded by GLM-5.3-Flash

Task Specification: Support for Class Attributes in htpy

Overview

This task is to implement support for a class_ keyword attribute on the HTML element builders in the htpy module. The attribute must accept multiple value types (string, list, dict) and must render an appropriate, HTML-escaped class attribute on the element that is generated.

Public API

Element builder objects must be exposed by the htpy module, including at minimum div, ul, and li. Each element builder must be callable, and it must support:

  • A single positional argument that carries the text content, e.g. div("hello").
  • A class_ keyword argument (note the trailing underscore) for specifying the element's CSS class attribute.

Calling an element builder returns an object, and the str() representation of that object is the rendered HTML string.

Behavior Requirements

Basic rendering of elements

The expression str(div("hello")) must produce:

<div>hello</div>

An element that receives no content and no attributes renders as an empty element with open and close tags, e.g. <div></div>.

Rendering of the class_ attribute

When class_ is provided, the rendered element must include a class attribute (spelled as the HTML attribute name class, without the trailing underscore). Once the class value has been resolved, it is HTML-escaped in the output. The characters < and > must be escaped as &lt; and &gt; respectively (e.g. a class value containing >foo is rendered as &gt;foo).

The class_ argument accepts the following value types, each of which resolves to a final space-separated class string:

String

The string is taken directly as the class value (then HTML-escaped on output).

  • div(class_=">foo bar") → <div class="&gt;foo bar"></div>

List

The value is a list of items. Each item that is a non-empty string is included. Items that are falsy — specifically False, None, and the empty string "" — are omitted. The string items that are included are joined with a single space, in order.

  • div(class_=[">foo", False, None, "", "bar"]) → <div class="&gt;foo bar"></div>

Dict

The value is a dict that maps class-name strings to values. A class name (the key) is included when its associated value is truthy, and it is omitted when the value is falsy (False, None, and "" are all treated as falsy/omit). The keys that are included are joined with a single space, preserving insertion order.

  • div(class_={">foo": True, "x": False, "y": None, "z": "", "bar": True}) → <div class="&gt;foo bar"></div>

Notes

  • No matter what the input type is, the final class string is HTML-escaped in the rendered output.
  • Class names are joined by exactly one space, and omitted entries introduce no leading or trailing whitespace.
02 Implement a typed Python library named htpy that offers a declarative API for building HTML. 1310 words · rewritten by GPT-5.6-sol, reworded by GLM-5.3-Flash

Task Specification for the htpy HTML Generation Library

Implement a typed Python library named htpy that offers a declarative API for building HTML. Every public name described below must be directly importable from the top-level htpy module, for example via from htpy import div, mark_safe, Element, SafeString. The distributed package must include a py.typed marker so that its type information is exported.

Public API Surface

Element factories

HTML tag names are exposed as module attributes that are importable and callable. This covers standard tags such as div, ul, li, button, img, input, html, head, and body, as well as arbitrary custom names. Reading an otherwise valid Python identifier as an attribute of htpy—including through an import such as from htpy import my_custom_element—must provide the corresponding element factory.

For module-level factory names, every underscore is converted to a hyphen in the emitted tag name. To give an example, my_custom_element() renders as <my-custom-element></my-custom-element>.

Element

Element is the public type that every element-factory call returns, including calls that apply attributes or children. An Element must support:

  • str(element), which returns the element's complete serialized HTML.
  • Iteration via iter(element) or list(element), which yields the serialized HTML as ordered string pieces. For a normal non-void element, the opening tag—with its attributes included—is one piece; ordinary child content is yielded in order; nested elements yield their own pieces recursively; and the closing tag is one piece. Joining all the pieces that were yielded must equal str(element). Void elements and the special html serialization follow their rules below while keeping the same guarantee that the joined pieces reproduce the full output.
SafeString

SafeString is the public type that mark_safe returns. It stands for HTML content that has already been made safe, and it must not be escaped again when used as element content.

mark_safe(value: str) -> SafeString

mark_safe wraps the string it receives as a SafeString. When the value is rendered as a child, its contents are inserted verbatim.

Element Construction

An element factory can be used in the following forms:

  1. With attributes, given as keyword arguments and/or as a single positional dictionary:
    • div(id="hello")
    • button(hx_post="/foo")
    • div({"@click": "..."})
  2. With children, passed positionally:
    • div("hello")
    • ul(li(), li())
    • ul([li("a"), li("b")])
    • ul(li(x) for x in ["a", "b"])
  3. By applying children to an existing element, so that an element created with attributes is itself callable:
    • div(id="a")("hi")

Each of these forms returns an Element. Both the dictionary and the keyword attribute forms must be supported; no separate attribute-chaining or attribute-merging API beyond these construction forms is required.

Children

The accepted child forms are:

  • One or more positional strings or Element objects, for instance ul(li(), li()).
  • A single list of children, for instance ul([li("a"), li("b")]).
  • A single generator or iterator of children, for instance ul(li(x) for x in ["a", "b"]).
  • A SafeString, which is handled in the way described under escaping.

Ordinary string children get HTML text-content escaping. SafeString children are emitted verbatim, while nested Element children emit their own HTML. Lists and iterators stand for sequences of children, not for literal child values. The order of children must be preserved.

An element must be reusable: rendering one and the same element repeatedly must give the same output. In particular, building an element from a one-shot generator or iterator must not cause later renders to lose its children.

Calling a factory with no arguments produces an empty element. Non-void elements still get an explicit closing tag, for example:

  • str(div()) → <div></div>

A single positional dict is read as attributes. A single positional value of another supported kind (a string, SafeString, Element, list, generator, or iterator) is read as child content.

Attributes

Attributes can be provided by keyword arguments or by a single positional dictionary.

Keyword attribute names

Keyword names are transformed before serialization:

  • A single trailing underscore is stripped, so class_ becomes class.
  • The remaining underscores are converted to hyphens, so hx_post becomes hx-post.
  • The keyword name _ is a special case and stays _; this supports syntax such as div(_="foo"), which renders as <div _="foo"></div>.

As an example, button(hx_post="/foo")("click me!") renders as <button hx-post="/foo">click me!</button>.

Dictionary attribute names

Keys provided in an attribute dictionary are used literally: trailing underscores are not stripped and embedded underscores are not turned into hyphens. For example:

  • str(div({"class_": "foo", "hello_hi": "abc"})) → <div class_="foo" hello_hi="abc"></div>
  • A key like @click stays @click.

When they are emitted, dictionary attribute names are HTML-escaped. For example:

  • str(div({"<disturbing attr>": "value"})) → <div &lt;disturbing attr&gt;="value"></div>
Attribute values
  • A string value is HTML-escaped for the attribute context and emitted as name="value".
  • Boolean True emits a minimized attribute containing only the name.
  • Boolean False leaves the attribute out entirely.

Booleans are handled the same way for keyword and dictionary attributes. Only the opening tag is affected; the closing tag of a non-void element is never suppressed. For example:

  • str(button(disabled=True)) → <button disabled></button>
  • str(button(disabled=False)) → <button></button>
  • str(div({"bool-true": True})) → <div bool-true></div>
  • str(div({"bool-false": False})) → <div></div>

When children are present, the non-void closing tag likewise comes after those children, no matter whether a boolean attribute was minimized or omitted.

Special handling for the class value

The value of the class attribute supports composing class names:

  • String: escape it and use it unchanged.
  • List: only truthy string items are included. Falsy items such as False, None, and "" are dropped. Escape each included item and join the items with one space.
  • Dictionary: keys serve as class names and values as conditions. A key is included only when its condition is truthy, insertion order is preserved, each included class name is escaped, and the included names are joined with one space.

Examples:

  • str(div(class_=">foo bar")) → <div class="&gt;foo bar"></div>
  • str(div(class_=[">foo", False, None, "", "bar"])) → <div class="&gt;foo bar"></div>
  • str(div(class_={">foo": True, "x": False, "y": None, "z": "", "bar": True})) → <div class="&gt;foo bar"></div>

Escaping

Escaping depends on the context. Dictionary attribute names and string attribute values get attribute-context escaping. Ordinary string children get text-context escaping. At minimum, these rules apply:

  • < turns into &lt; and > turns into &gt; in ordinary string children, dictionary attribute names, and string attribute values.
  • A double quote (") turns into &quot; in attribute names and values.
  • In an ordinary string child, a double quote stays a literal "; it is not escaped simply because it appears in text content.

As a result:

  • str(div('<hello">')) → <div>&lt;hello"&gt;</div>
  • str(div(id='"hello"')) → <div id="&quot;hello&quot;"></div>
  • str(div("<foo></foo>")) → <div>&lt;foo&gt;&lt;/foo&gt;</div>

A SafeString that is used as content bypasses child escaping:

  • str(div(mark_safe("<foo></foo>"))) → <div><foo></foo></div>

Closing Tags and Void Elements

The closing tag of every non-void element is always emitted. That covers empty elements and elements whose opening tags contain minimized boolean attributes or omit false boolean attributes. As an example, an empty custom element renders as <my-custom-element></my-custom-element>, not as a self-closing tag.

HTML void elements render only their opening tag and no closing tag. The set of supported void elements includes at least img and input:

  • str(input(name="foo")) → <input name="foo">
  • str(img()) → <img>

Void elements cannot have children. Supplying children to one must raise ValueError with a message of the form "{tag} elements cannot have children"; for instance, img("hey") raises ValueError with a message matching img elements cannot have children.

Special html Element

The html element places the lowercase HTML doctype declaration at the beginning of its serialized output:

  • str(html(foo="bar")("hello")) → <!doctype html><html foo="bar">hello</html>

Typing Requirements

  • Calls to element factories must be statically typed as returning Element.
  • mark_safe(...) must have a static return type of SafeString.
  • It must be possible to import Element and SafeString and use them directly in type annotations.
  • The package must ship its py.typed marker.
03 Create a Python module called htpy that offers a declarative way to build HTML strings. 628 words · source specification, reworded by GLM-5.3-Flash

Task: Build htpy — a library for generating HTML

Create a Python module called htpy that offers a declarative way to build HTML strings. The public API must support importing HTML element objects (e.g. div, ul, li, button, html, img) as well as SafeString and mark_safe.

Public API

The htpy module must expose:

  • HTML element objects reachable by name: div, ul, li, button, html, img, and any other standard HTML tag name that is accessed as an attribute/importable name from the module.
  • A type named SafeString.
  • A function mark_safe(value: str) -> SafeString.

Element behavior

Each element name (e.g. div) is an object that stands for an HTML tag. Elements support two operations that are independent:

1. Setting attributes — by calling ()

An element called with arguments returns a new element that carries those attributes. The following two calling forms must be supported:

  • Keyword arguments: div(id="hello") turns the kwargs into attributes. Underscores inside keyword names are replaced with hyphens (e.g. hx_post="/foo" → hx-post="/foo").
  • A single dict argument: div({"@click": 'hi = "hello"'}) takes the attributes directly from the dict keys/values, which allows attribute names that are not valid Python identifiers.

A call with no arguments is allowed and produces an element with no attributes.

Rules for attribute values:

  • A string value renders as name="value".
  • A boolean value of True renders the attribute name alone, with no value (e.g. disabled=True → disabled).
  • A boolean value of False leaves the attribute out entirely.

HTML-escaping is applied to attribute values, and attribute names are escaped as needed. As an example, a value containing " is escaped to &quot;.

2. Setting children — with subscript []

Subscripting an element with [] sets its children and returns a new element. The expression used for the children may be:

  • One string by itself: div["hello"].
  • Multiple children separated by commas: ul[li(), li()].
  • Elements nested within one another: div(id="a")[div(id="b")["inner"]].
  • Children supplied as a list: ul[[li["a"], li["b"]]].
  • Children supplied as a tuple: ul[(li["a"], li["b"])].
  • Children supplied by a generator: ul[(li[x] for x in ["a", "b"])].

Lists, tuples, and generators get flattened, so that their items become the element's children.

Attributes and children can be combined: div(id="hello")["hi"] sets the attribute id and the child hi.

Void elements

img is a void element. Attempting to give it children via [] must raise ValueError with a message that matches img elements cannot have children.

The html element

When the html element is rendered, a doctype is prepended. For example, html(foo="bar")["hello"] renders as <!doctype html><html foo="bar">hello</html>.

Rendering

str()

Invoking str() on an element renders the complete HTML string:

  • When an element is empty, it renders as <tag></tag> (e.g. str(button(disabled=True)) → <button disabled></button>).
  • Elements that have attributes and/or children render accordingly.
Iteration

When you iterate an element, the HTML is yielded in string chunks: the opening tag (with attributes) as one chunk, each child rendered, and the closing tag as a final chunk.

Examples:

  • list(div(id="a")["hello"]) → ['<div id="a">', "hello", "</div>"]
  • list(ul[li(id="a")["hi a"], li(id="b")["hi b"]]) → ['<ul>', '<li id="a">', "hi a", "</li>", '<li id="b">', "hi b", "</li>", "</ul>"]
__html__()

Each element has an __html__() method that returns the same full HTML string as str(). For example, div(id="a").__html__() → <div id="a"></div>.

Escaping

When text children are rendered, they are HTML-escaped:

  • < → &lt;, > → &gt;
  • A " that occurs in text content is left as-is (div['<hello">'] → <div>&lt;hello"&gt;</div>).

Safe strings

  • mark_safe(s) returns a SafeString (a str subtype) whose contents are treated as HTML that is already safe and are not escaped when used as a child.
  • str(div[mark_safe("<foo></foo>")]) → <div><foo></foo></div>.
  • Ordinary strings, in contrast, are escaped: str(div["<foo></foo>"]) → <div>&lt;foo&gt;&lt;/foo&gt;</div>.
04 HTML Element Builder Library (htpy) 1580 words · rewritten by GPT-5.6-sol, reworded by GLM-5.3-Flash

Task Specification: HTML Element Builder Library (htpy)

Overview

Create a Python module named htpy that offers an expressive API for building HTML markup. Element objects at module level accept attributes by being called and accept children via subscription. The objects that result render to escaped HTML strings and can also be consumed as ordered streams of HTML fragments.

Public API Surface

The htpy module must expose the following public names, all importable:

  • Element: the class/type that represents an HTML element.
  • SafeString: a str subclass standing for trusted markup that is already safe.
  • mark_safe: a callable that accepts a str and returns a SafeString.
  • Element objects for standard and custom tags, with at least div, ul, li, img, input, html, button, and my_custom_element among them.

The package must expose typing information that produces these results:

  • A bare element such as div, a called element such as div(), and an element with children such as div()["a"] all have static type Element.
  • mark_safe(...) statically returns SafeString.
  • Element.__html__() statically returns str.
  • Module elements given dynamic names statically type as Element.
Dynamically named elements and identity

Any attribute access on htpy for a name that is otherwise undefined must produce an Element. The Python attribute name is converted to the HTML tag name by replacing every underscore with a hyphen. For instance, htpy.my_custom_element renders the tag my-custom-element.

Bare elements at module level are cached by name. Repeatedly accessing the same predefined or dynamically produced element must return the identical object; in particular, htpy.div is htpy.div is true. Calling or subscripting that reusable bare element produces an element expression without altering the behavior of the shared bare element.

Constructing Elements

An element supports three forms, which can be combined:

  1. Bare element: div
  2. Calling to supply attributes: div(id="a") or div({"id": "a"})
  3. Subscripting to supply children: div["hello"]

A call with no arguments is valid and returns an Element whose rendered content is unchanged. Attribute and child operations can be chained, for instance div(id="a")["hello"].

The call str(element) returns the complete rendered markup. An ordinary bare element has no attributes and no children, so str(div) is <div></div>.

Attributes

Calling an element attaches attributes to it. When a further construction step adds children, existing attributes on the element expression are retained.

Accepted attribute forms

Either of the following forms may be used to supply attributes:

  • Keyword arguments: div(id="hello")
  • A single positional dictionary: div({"id": "hello"})

The dictionary and keyword forms must not be mixed in a single call; doing so raises TypeError. Attributes are rendered in the opening tag. A non-boolean attribute is rendered as name="value", with the leading space and double quotes included.

Conversion of keyword attribute names

These rules apply to keyword arguments only:

  • Strip one trailing underscore; this is what allows Python keywords or conventional aliases such as class_ to represent class.
  • Convert any remaining underscores to hyphens, so hx_post becomes hx-post.
  • The single name _ is preserved exactly, so div(_="foo") renders <div _="foo"></div>.

As a result:

div(class_=">foo bar")
# <div class="&gt;foo bar"></div>

button(hx_post="/foo")["click me!"]
# <button hx-post="/foo">click me!</button>

Before escaping, dictionary keys are used exactly as supplied; they are not subject to trailing-underscore removal or to underscore-to-hyphen conversion:

div({"class_": "foo", "hello_hi": "abc"})
# <div class_="foo" hello_hi="abc"></div>
Boolean attributes

In both input forms, boolean values follow HTML boolean-attribute semantics:

  • True includes only the attribute name, with no ="..." suffix.
  • False leaves the attribute out entirely.

For example:

button(disabled=True)       # <button disabled></button>
button(disabled=False)      # <button></button>
div({"bool-true": True})   # <div bool-true></div>
div({"bool-false": False}) # <div></div>
Values of the class attribute

The class attribute, in its normalized form, supports composing class names:

  • A string is taken as the class value.
  • A list or tuple is filtered down to its truthy items, which are then converted to text and joined with single spaces.
  • A dictionary contributes each key whose corresponding value is truthy, with dictionary iteration order preserved; the keys that are included are joined with single spaces.

Class names are escaped for the attribute context. Consequently:

div(class_=[">foo", False, None, "", "bar"])
# <div class="&gt;foo bar"></div>

div(class_={">foo": True, "x": False, "y": None, "z": "", "bar": True})
# <div class="&gt;foo bar"></div>
Escaping of attributes

Ordinary attribute names and values are converted to text and escaped for a double-quoted attribute context. The escaping covers &, <, >, and " (with " becoming &quot;). Attribute names are escaped, as are attribute values.

Examples:

div(id='"hello"')
# <div id="&quot;hello&quot;"></div>

div({"@click": 'hi = "hello"'})
# <div @click="hi = &quot;hello&quot;"></div>

div({"<disturbing attr>": "value"})
# <div &lt;disturbing attr&gt;="value"></div>

div({'<"': '"hello"'})
# <div &lt;&quot;="&quot;hello&quot;"></div>

When an attribute name or value is a SafeString, it bypasses this escaping, as described under Safe strings.

Children

Children are attached via element[...]. The child forms that are supported include:

  • A single child: div["hello"]
  • Several comma-separated children: ul[li, li]
  • A list: ul[[li["a"], li["b"]]]
  • A tuple: ul[(li["a"], li["b"])]
  • A generator: ul[(li[x] for x in ["a", "b"])]
  • Nested Element objects

When supplied in the child position, lists, tuples, and generators are expanded in order into sibling children. Nested elements are rendered recursively in document order.

In child-text context, ordinary child values are converted to text and escaped. When a bare element is used as a child, that element is what gets rendered:

ul[li, li]
# <ul><li></li><li></li></ul>

div(id="a")[div(id="b")["inner"]]
# <div id="a"><div id="b">inner</div></div>
Children that are ignored

Wherever they occur as children, None and the boolean value False are ignored entirely and produce no text or iteration fragment:

div[None]   # <div></div>
div[False]  # <div></div>

This rule must distinguish False from numeric zero: 0 is not ignored and renders as text:

div[0]      # <div>0</div>

Rules for Rendering

Ordinary elements

A non-void element renders an opening tag, then its children, then a closing tag. The closing tag is always included, even when the element is empty:

div["hello"]             # <div>hello</div>
div(id="hello")["hi"]    # <div id="hello">hi</div>
Void elements

The void elements of HTML are area, base, br, col, embed, hr, img, input, link, meta, param, source, track, and wbr. They render an opening tag only, with no slash and no closing tag:

input(name="foo")  # <input name="foo">
img()               # <img>
div[img]            # <div><img></div>

Void elements cannot have children. Attempting to attach children raises ValueError; the message identifies the tag, in the form <name> elements cannot have children. As an example, img["hey"] raises ValueError whose message contains img elements cannot have children.

The html element and the doctype

The module-level html element places the exact HTML doctype <!doctype html> before its rendered element, with no intervening whitespace:

html(foo="bar")["hello"]
# <!doctype html><html foo="bar">hello</html>

If attributes or children are added to html, the doctype remains present.

Context-Dependent Escaping

Child text and attributes are not escaped in the same way.

Ordinary child text

With untrusted child text, markup-significant characters such as &, <, and > are escaped. In the child-text context, double quotes are not escaped. Specifically:

div['>"']
# <div>&gt;"</div>

div["<foo></foo>"]
# <div>&lt;foo&gt;&lt;/foo&gt;</div>

This child-specific rule takes precedence over the attribute quoting rules: in an attribute name or value, " becomes &quot;, but in ordinary child text it remains a literal ".

Safe strings

mark_safe(value) returns a SafeString, which is a trusted str subclass. Where a SafeString is used as child content, an attribute value, or a dictionary attribute key, it is emitted verbatim rather than escaped.

str(div[mark_safe("<hello></hello>")])
# <div><hello></hello></div>

str(div(id=mark_safe("<hi>")))
# <div id="<hi>"></div>

str(div({mark_safe('<"'): mark_safe('"hello"')}))
# <div <"=""hello""></div>

Trust is explicit: the plain string "<foo></foo>" is escaped as child text, whereas mark_safe("<foo></foo>") is not. SafeString.__html__() returns the trusted string content it holds.

Fragment Iteration

An Element is iterable; iterating it yields str fragments in rendering order. Joining all of the yielded fragments must equal str(element).

For an ordinary element, the iteration yields:

  1. The opening tag, attributes included, as one fragment.
  2. The child fragments, in document order. A nested element contributes its own fragments depth-first.
  3. The closing tag as one fragment.

For example:

list(div(id="a")["hello"])
# ['<div id="a">', 'hello', '</div>']

list(ul[li(id="a")["hi a"], li(id="b")["hi b"]])
# [
#   '<ul>',
#   '<li id="a">', 'hi a', '</li>',
#   '<li id="b">', 'hi b', '</li>',
#   '</ul>',
# ]

Children that are ignored (None and False) yield no fragment. A void element yields only the fragment for its opening tag. The html element yields <!doctype html> as its first fragment, followed by the fragments of the ordinary html element.

The __html__ Interface

Every element provides __html__(). The method returns a str exactly equal to str(element), so the element can take part in HTML-safe rendering interfaces:

div(id="a").__html__()
# <div id="a"></div>

Representation

repr(element) takes the exact form:

<htpy element '<rendered HTML>'>

where <rendered HTML> is the same markup that str(element) produces. For example:

repr(div)
# <htpy element '<div></div>'>

# '<div &lt;&#34;="&#34;hello&#34;"></div>'

Arbitrary mapping attributes are subject to the same quote representation:

str(div({"@click": 'hi = "hello"'}))
# '<div @click="hi = &#34;hello&#34;"></div>'

Specifically, these outputs must use &#34; rather than &quot;.

Child values that are safe

A markupsafe.Markup value that serves as a child must be treated as already safe, and its markup must not be escaped.

A value returned by markupsafe.escape must likewise remain safe and must not be escaped a second time:

from markupsafe import escape

str(ul[escape("<hi>")])
# '<ul>&lt;hi&gt;</ul>'

Safe strings from Django must also remain unescaped:

from django.utils.safestring import SafeString

str(ul[SafeString("<li>hello</li>")])
# '<ul><li>hello</li></ul>'

Element rendering through Jinja2 and Django templates, in its existing form, must continue to preserve generated HTML. When ul[li["I am safe!"]] is rendered as template content, the output must be:

<ul><li>I am safe!</li></ul>

Child attachment via subscription syntax must be supported by div:

The value that is returned must be renderable with str().

When child is a django.forms.utils.ErrorList, the ErrorList’s complete HTML output must be rendered inside the <div>, rather than it being treated as a generic iterable of individual errors.

As an example:

from django.forms.utils import ErrorList

error_list = ErrorList(["my error"])

19 Modify the behavior of the public htpy API as described below. 246 words · source specification, reworded by GLM-5.3-Flash

Change that is required

Modify the behavior of the public htpy API as described below.

Handling of the htpy.div class attribute

It must remain possible to call htpy.div with a class_ keyword argument.

The class_ value must accept a tuple that combines:

  • strings holding class names, and
  • dictionaries that map class names to inclusion flags.

Here is an example:

from htpy import div

result = div(
    class_=(
        "class-1",
        "class-2",
        {"class-3": False, "class-4": True},
    )
)

When the result is converted to a string, the output must be:

<div class="class-1 class-2 class-4"></div>

The order of the string entries is preserved. Dictionary keys whose value is true are included; keys whose value is false are omitted.

List objects with HTML capability as children

htpy.div must support supplying child content via the subscription syntax:

div[child]

When child is both list-like and supplies the __html__ safe-HTML protocol, the HTML representation of that object must take priority over handling the object as a collection of separate children.

This must work in the situation where the object is constructed directly inside the subscription expression. In particular, when Django's public API is used:

from django.forms.utils import ErrorList
from htpy import div

result = div[ErrorList(["my error"])]

Converting the result to a string must produce exactly:

<div><ul class="errorlist"><li>my error</li></ul></div>

The HTML of the ErrorList must be embedded as HTML instead of being escaped or rendered as its individual list entries.

Modify the public div element factory that the htpy module exports:

from htpy import div

It must accept a class_ keyword argument that contains a tuple combining class-name strings with conditional class mappings.

result = div(class_=("foo", {"bar": False}))
