In the tests, F and T are instances of these two tensor types. Ordinary NumPy arrays are also valid inputs to the functions below. The functions must accept any mixture of these tensor types and plain NumPy arrays as their array arguments.

Public API

The package (conventionally imported as import ... as tr) must expose the following callables at the top level:

  • tr.function(fun, ntrax=..., parallel=...)
  • tr.gradient(fun, ntrax=..., parallel=..., full_output=...)
  • tr.hessian(fun, ntrax=..., parallel=..., full_output=...)

Each of these is a higher-order function: calling it with a scalar-valued function fun and the keyword options returns a callable. That returned callable is then invoked with a single array argument (a deformation-gradient-like array F) and produces the result.

Accepted keyword arguments:

  • ntrax (int): number of trailing "trax" axes on the input array. Defaults to a sensible value; called both with and without it.
  • parallel (bool): enables/disables a parallel evaluation path. Must be accepted for both True and False; both paths must produce identically-shaped results.
  • full_output (bool): new argument for gradient and hessian only. Controls how many outputs are returned (see below). Its default value must be False.

Behavior of full_output

tr.gradient(...)

The returned callable, when applied to F, computes the gradient of fun with respect to F (call it dWdF) and the function value itself (call it W).

  • When full_output=True: returns a tuple (dWdF, W) in that order.
  • When full_output=False (the default): returns only dWdF (a single array, not a tuple).
tr.hessian(...)

The returned callable, when applied to F, computes the Hessian of fun (call it d2WdF2), the gradient (dWdF), and the function value (W).

  • When full_output=True: returns a tuple (d2WdF2, dWdF, W) in that order.
  • When full_output=False (the default): returns only d2WdF2 (a single array, not a tuple).
tr.function(...)

Unchanged: the returned callable applied to F returns the scalar function value evaluated over the input (call it W). It has no full_output argument.

Output shapes

For an input F with shape (3, 3, *trax) where *trax is a set of ntrax trailing axes:

  • W has shape (*trax).
  • dWdF has shape (3, 3, *trax).
  • d2WdF2 has shape (3, 3, 3, 3, *trax).

Concretely, for F of shape (3, 3, 1, 1) with ntrax=2:

  • W.shape == (1, 1)
  • dWdF.shape == (3, 3, 1, 1)
  • d2WdF2.shape == (3, 3, 3, 3, 1, 1)

The numerical results must be independent of the parallel flag: computing with parallel=False and parallel=True must yield the same values.

The gradient and function value returned as part of hessian's full output must match the corresponding values computed by gradient and function for the same fun and F, including for inputs F that produce repeated eigenvalues (e.g. the identity matrix, or diagonal matrices with some equal and some differing diagonal entries), across the supported functions.

The implementations must remain correct for at least the following categories of scalar functions of F: standard strain-energy-type functions expressed via invariants (neo-Hookean form), functions expressed via principal stretches / eigenvalues (Ogden form), and functions involving trigonometric operations on F.

Constraint

Do not change any behavior other than introducing the full_output argument (defaulting to False) and the corresponding return-value selection described above.

1. Reshaping Tensor objects

Expose reshape through both the Tensor class and the public tensortrax.math module (commonly imported as tm).

Tensor core and trailing axes

A Tensor separates its dimensions into:

  • a core shape, exposed as Tensor.shape; and
  • Tensor.ntrax trailing axes, whose shape is exposed as Tensor.trax.

Tensor.size is the product of the core dimensions only. A reshape target applies only to this core shape. Trailing axes are batch-like dimensions and must not be included when checking whether a target shape has the correct number of elements.

Consequently, every valid target shape must have a product equal to the original Tensor.size, not necessarily to the total number of entries in the tensor's backing array.

Tensor.reshape method

Add a method with the reshape-style interface:

Tensor.reshape(*shape)

The target core shape must be accepted either as one shape argument or as multiple positional integer dimensions, following ordinary reshape calling conventions. In particular, for a tensor with core size 9, all of the following forms must be supported as applicable:

t.reshape(9)       # target core shape (9,)
t.reshape(3, 3)    # target core shape (3, 3)
t.reshape((3, 3))  # a shape supplied as one argument

The method returns a Tensor representing the reshaped result. It is not an in-place API. No particular copy-versus-view behavior is required.

Module-level reshape function

tm.reshape(t, (3, 3))
Required reshape semantics

Both APIs must obey the same rules:

  1. Reshape only the leading core dimensions.
  2. Preserve ntrax unchanged.
  3. Preserve the number, order, and extents of all trailing axes unchanged.
  4. Reshape all data carried by the tensor consistently: the value data (x) and the first- and second-order variation data (δx, Δx, and Δδx) must remain associated with the same elements. For example, a tensor whose backing value has shape (3, 3, 100) and whose ntrax is 1 has core shape (3, 3), trailing shape (100,), and core size 9. Its required result shapes are:

(9,) (9, 100) 1
(3, 3) (3, 3, 100) 1

take(fun, item=0)
  • fun: a callable that, when invoked with some argument(s), returns an indexable sequence (e.g. a tuple) of results.
  • item: an integer index (default 0) selecting which element of fun's return value to keep.
Behavior

take(fun, item=0) returns a new callable. When that returned callable is invoked with the same arguments that fun accepts, it must:

  1. Call fun with those arguments.
  2. Take the return value (an indexable sequence) and return the element at position item.

In other words, take(fun, item=i)(*args) is equivalent to fun(*args)[i].

The returned callable must be usable directly and must also be compatible with the existing differentiation/evaluation wrappers in the tensortrax package (tr.function, tr.gradient, tr.hessian, tr.jacobian), i.e. it must preserve whatever call/return protocol those wrappers rely on, forwarding all arguments through to fun and returning only the selected item.

Context / Existing API Used

The following already exist in the package and are used to validate take; they are not part of this task but define the calling protocol the wrapped callable must respect:

  • tr.function(fun)(x) — evaluates fun.
  • tr.gradient(fun)(x) — evaluates the gradient of a scalar-valued fun.
  • tr.hessian(fun)(x) — evaluates the hessian of a scalar-valued fun.
  • tr.jacobian(fun)(x) — evaluates the jacobian of a tensor-valued fun.
  • tensortrax.math (tm) helpers such as tm.trace, tm.linalg.det, and tensor operations like .T() and @.

Illustrative Usage

Given a function that returns a tuple of two results:

def f(F):
    scalar_result = ...   # scalar
    tensor_result = F     # tensor, same shape as input
    return scalar_result, tensor_result

Then:

  • tr.take(f, item=0) yields a callable returning only scalar_result, suitable for tr.gradient (producing a result with the same shape as the input) and tr.hessian (producing a result whose shape is the input shape repeated/squared).
  • tr.take(f, item=1) yields a callable returning only tensor_result, suitable for tr.function (reproducing the tensor unchanged) and tr.jacobian (producing the derivative of that tensor with respect to the input).

For an input of shape (3, 3):

  • gradient of the item=0 result has shape (3, 3).
  • hessian of the item=0 result has shape (3, 3, 3, 3).
  • function evaluation of the item=1 result reproduces the input.
  • jacobian of the item=1 result (when that item equals the input) equals the identity of shape (3, 3, 3, 3), i.e. np.einsum("ik,jl", np.eye(3), np.eye(3)).

Notes

  • The default value of item is 0.
  • No behavior beyond selecting the indexed element from the wrapped callable's return value is required.

Required Public API

The package's top level must expose the following two callables:

1. hessian_vectors_product(fun, wrt, ntrax, parallel)

This is a rename of a previously existing function. It has the same behavior as the prior Hessian–vector product function that contracted the Hessian against two direction vectors.

  • Factory signature: hessian_vectors_product(fun, wrt="F", ntrax=2, parallel=<bool>)
    • fun: a scalar-valued function of the named argument(s).
    • wrt: the name (string) of the argument to differentiate with respect to.
    • ntrax: number of trailing "trailing-axes" dimensions treated as batch/broadcast axes.
    • parallel: boolean flag selecting a parallel execution path (must accept both True and False).
  • Returned callable: accepts keyword arguments consisting of the primary input (e.g., F=...) plus two direction arrays δx=... and Δx=....
  • Result: returns the Hessian contracted with both direction vectors — a fully scalar-contracted quantity. Given inputs whose trailing (batch) shape is (1, 1), the result has shape (1, 1). The result must contain no NaN values.
2. hessian_vector_product(fun, wrt, ntrax, parallel)

This is a new function computing the Hessian contracted with a single direction vector.

  • Factory signature: hessian_vector_product(fun, wrt="F", ntrax=2, parallel=<bool>)
    • Parameters have the same meaning as above.
  • Returned callable: accepts keyword arguments consisting of the primary input (e.g., F=...) plus one direction array δx=.... (It does NOT take Δx.)
  • Result: returns the Hessian contracted with the single direction vector along one of its two "input" index groups, leaving the other index group free. Concretely, if the differentiated argument has a leading (non-batch) shape of (3, 3) and a trailing (batch) shape of (1, 1), the result has shape (3, 3, 1, 1) — i.e., the two free component axes followed by the batch axes. The result must contain no NaN values.

Consistency Requirements

  • Both functions must support parallel=True and parallel=False and produce valid (non-NaN) results in both modes.
  • Both functions must correctly handle inputs with trailing batch axes as controlled by ntrax.
  • A related gradient–vector-product function (gradient_vector_product) already exists with the same factory-call / returned-callable structure (returned callable takes the primary input plus a single δx); its scalar-contracted result for (1, 1) batch inputs has shape (1, 1). The two Hessian functions above must be usable alongside it with the same calling conventions.

Summary of the Change

  1. Rename the existing two-vector Hessian–vector product function to hessian_vectors_product (keeping its behavior identical).
  2. Add a new hessian_vector_product function that contracts the Hessian with a single direction vector, returning a result that retains the free component axes of the differentiated argument followed by the batch axes.

  • a .x attribute holding the underlying numpy.ndarray
  • a .shape attribute equal to the shape of its underlying array

In this task, a tensor T wraps an underlying array F (i.e. T.x equals F, and T.shape == F.shape). A tensor's .shape must be derived from its underlying array .x.

Overview

Provide the required NumPy-like array construction and combination behavior through the existing tensortrax package. The public entry point is tensortrax.math, conventionally imported as:

import tensortrax.math as tm

Here, tm is only a local import alias for tensortrax.math; it is not the name of a separate top-level package. The existing package layout must remain usable, and no standalone package named tm or /src/tm layout is required.

Public API Location

The following functions must be exposed as public attributes of tensortrax.math (and therefore available through the alias above):

  • array
  • vstack
  • hstack
  • stack
  • repeat
  • tile

The existing base namespace must also remain exposed as tensortrax.math.base, including base.eye.

Tensor and Plain-Array Interoperability

The wrapper object for tensor-aware operations is the existing tensortrax.Tensor. Its numeric value is available through its .x attribute. In the requirements below, the “numeric contents” of a Tensor means its .x value; the numeric contents of a plain input are the input itself as interpreted by NumPy.

All listed helpers must accept the forms appropriate to their operation:

  • plain numeric scalars, sequences, or NumPy-compatible arrays;
  • tensortrax.Tensor values; and
  • for sequence-based helpers, mixtures of Tensor values and plain array-like values.

Tensor inputs and equivalent plain inputs must be treated interchangeably with respect to numeric values. If F is a plain array and T is a Tensor with T.x equal to F, applying a helper to T (or a sequence containing T) must produce represented numeric data equal, element by element, to applying that helper to F (or the corresponding plain sequence). Tensor-aware results must expose that data through .x.

Plain-input calls must produce the corresponding NumPy-compatible numeric result rather than None. Existing Tensor-aware behavior, including the use of the existing Tensor type and its trailing-axis and variation semantics, must remain compatible.

Array Construction and Combination Functions

tensortrax.math.array(object, dtype=None)

Construct an array in the manner of numpy.array.

  • A sequence such as [a, b] combines the numeric contents of a and b into one array with the same shape, ordering, values, and requested dtype as numpy.array applied to the equivalent plain values.
  • A Tensor input, or a sequence requiring a Tensor-aware result, must produce a result exposing its represented array through .x.
  • A sequence containing only plain values must still return a valid NumPy-compatible array result.
tensortrax.math.vstack(seq)

Vertically stack the numeric contents of seq, with the same numeric values and shape as numpy.vstack on equivalent plain inputs. A Tensor-aware result exposes the stacked data through .x.

tensortrax.math.hstack(seq)

Horizontally stack the numeric contents of seq, with the same numeric values and shape as numpy.hstack on equivalent plain inputs. A Tensor-aware result exposes the stacked data through .x.

tensortrax.math.stack(seq, axis=0)

Join the numeric contents of seq along a new axis, with the same numeric values and shape as numpy.stack on equivalent plain inputs. The existing axis argument must be honored. A Tensor-aware result exposes the stacked data through .x.

tensortrax.math.repeat(a, repeats, axis=None)

Repeat elements from the numeric contents of a, following numpy.repeat for the supplied repeat count and axis. A Tensor-aware result exposes the repeated data through .x. In particular, the two-argument form repeat(a, n) must behave like numpy.repeat(a, n).

tensortrax.math.tile(a, reps)

Tile the numeric contents of a, following numpy.tile for the supplied repetition specification. A Tensor-aware result exposes the tiled data through .x. In particular, the form tile(a, n) must behave like numpy.tile(a, n).

For every helper above, equivalent Tensor, plain, and mixed inputs must yield numerically equivalent represented data. This includes equality of shape and element values, not merely successful construction.

Direct NumPy Compatibility of Results

Every result returned by array, vstack, hstack, stack, repeat, or tile must be directly usable as NumPy array-like data without requiring callers to access .x first.

Specifically:

  • numpy.asarray(result) and numpy.array(result) must expose the represented numeric array, not a scalar object array containing the wrapper.
  • The converted shape and element values must match the result’s .x attribute whenever the result is a Tensor wrapper.
  • A result must be accepted directly by numeric routines such as numpy.allclose.
  • This compatibility must hold whether inputs are plain values, Tensor values, or—where applicable—a mixture of both.

Consequently, for equivalent underlying data, directly comparing the Tensor-input result or its .x value with the plain-input result must succeed numerically for each helper.

tensortrax.math.base.eye(M)

base.eye must create an identity-like numeric array based on M.

  • The result must have the same shape as the represented input data.
  • Both plain array-like values and Tensor values must be accepted.
  • If a Tensor and a plain input represent the same numeric shape and values, their base.eye results must have equal shapes and be element-wise equal.
  • The returned data must be directly usable by NumPy comparison routines.

Compatibility Scope

These requirements extend the existing tensortrax.math interface rather than replacing it. Existing Tensor arithmetic, automatic-differentiation behavior, trailing-axis handling, and the other public tensortrax.math namespaces and functions must continue to operate as before.
