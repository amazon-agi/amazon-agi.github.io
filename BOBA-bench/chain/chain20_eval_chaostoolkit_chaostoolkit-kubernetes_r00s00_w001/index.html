01 Pod Termination Behavior 438 words · source specification

Task Specification: Pod Termination Behavior

Objective

Modify the pod termination logic so that when the Kubernetes client's delete_namespaced_pod method is invoked, the deletion options object is passed as a keyword argument named body, rather than as a positional argument.

Public API Surface

The following function must exist and be importable:

from chaosk8s.pod.actions import terminate_pods
Function: terminate_pods

Accepts the following keyword parameters (all optional, with the behaviors described below):

  • name_pattern (str): a regular expression used to filter pods by their metadata name.
  • all (bool): when True, all matching/selected pods are terminated.
  • rand (bool): when True, selection among candidate pods is randomized.
  • mode (str): selection mode; supports the value 'percentage'.
  • qty (int): quantity value whose meaning depends on mode (a count of pods, or a percentage when mode='percentage').
  • grace_period / grace period handling (see below).

Required Behavior

The function selects one or more pods from the "default" namespace (based on the parameters above) and terminates each selected pod by calling the Kubernetes core V1 API method delete_namespaced_pod.

Each call to delete_namespaced_pod MUST be made with:

  1. The pod's name (pod.metadata.name) as the first positional argument.
  2. The namespace string "default" as the second positional argument.
  3. A deletion options object passed as the keyword argument body.

The key required change: the deletion options object must be supplied under the keyword body=.... It must NOT be passed positionally.

Deletion options object
  • When no grace period is specified, the value passed to body is a delete-options object (any V1DeleteOptions instance is acceptable).
  • When a grace period is specified (e.g., 5 seconds), the value passed to body must be a V1DeleteOptions instance constructed with grace_period_seconds set to that value, i.e. equivalent to client.V1DeleteOptions(grace_period_seconds=5).
Selection / call-count behavior
  • With name_pattern alone and a single matching pod: exactly one termination call is made for that pod.
  • With name_pattern and all=True: every matching pod is terminated (one call per pod).
  • With all=True (no pattern): every pod in the namespace is terminated (one call per pod).
  • With no parameters: exactly one pod is terminated.
  • With qty=N where N exceeds the number of selected pods: all selected pods are terminated.
  • With mode='percentage', qty=P: a percentage P of the selected pods is terminated (rounded such that, for example, 40% of 5 pods results in 2 termination calls).
  • The rand=True flag randomizes which candidate pods are chosen but does not change the number terminated or the call convention.

In all cases the argument convention for delete_namespaced_pod described above (positional name, positional "default", keyword body) must hold.

06 You are working in the chaosk8s Python package, which provides chaos-engineering actions and probes for Kubernetes. 922 words · source specification

Overview

You are working in the chaosk8s Python package, which provides chaos-engineering actions and probes for Kubernetes. You must modify pod selection/termination behavior and add a new action to execute commands inside pod containers.

All public symbols live in the module chaosk8s.pod.actions.

The Kubernetes client is accessed via chaosk8s.client (i.e. client.CoreV1Api() returns a CoreV1Api instance, and client.V1DeleteOptions(...) constructs delete options). Pod listing uses CoreV1Api.list_namespaced_pod(...), which returns an object whose .items is a list of pod objects. Each pod object exposes:

  • pod.metadata.name — the pod name (string)
  • pod.metadata.creation_timestamp — an ISO-8601 timestamp string (e.g. "2019-11-25T13:50:31Z")
  • pod.spec.containers — a list of container objects, each with a .name attribute

Part 1: Pod selection for terminate_pods

Modify the existing function:

def terminate_pods(label_selector=None, name_pattern=None, all=False,
                   rand=False, mode="fixed", qty=1, grace_period=-1,
                   ns="default", order="alphabetic", secrets=None):

The function lists pods in namespace ns (default "default") via list_namespaced_pod, selects a subset of them according to the parameters, and deletes each selected pod via delete_namespaced_pod(name, ns, body=...).

Pod filtering by name pattern
  • When name_pattern is provided, restrict the candidate pods to those whose metadata.name matches the given regular expression (using a search/match against the pattern). Only matching pods are eligible for selection.
    • Example: pattern "my-app-[0-9]$" matches "my-app-1" and "my-app-2" but not "my-app-test-3" or "some-db".
  • When name_pattern is not provided, all listed pods are candidates.
Selection semantics (applied to the candidate pods)
  • all=True: select every candidate pod.
  • mode="fixed" (default): select up to qty candidate pods. qty defaults to 1.
    • If qty is greater than the number of candidates, select all candidates.
  • mode="percentage": select ceil(qty% of the candidate count) pods. For example, qty=40 with 4 candidates selects 2 pods.
  • rand=True: choose the pods randomly from the candidate set (using random.sample(sequence, count)), rather than taking them in their existing order. When rand=False, selection takes candidates from the front of the (ordered) sequence.
Deletion

For each selected pod call:

delete_namespaced_pod(pod.metadata.name, ns, body=<delete options>)
  • When grace_period >= 0, the body must be client.V1DeleteOptions(grace_period_seconds=grace_period).
  • Otherwise the body is a delete-options object (its exact contents are unconstrained).
Error conditions (raise chaoslib.exceptions.ActivityFailed)

No pods are deleted when an error is raised.

  • If qty is negative, raise with message containing: Cannot select pods. Quantity '<qty>' is negative.
  • If mode is not one of the recognized modes, raise with message containing: Cannot select pods. Mode '<mode>' is invalid.

(Note: these error messages use the phrase "Cannot select pods." — not "Cannot terminate pods.")

Part 2: New action exec_in_pods

Add a new function:

def exec_in_pods(cmdstr, label_selector=None, name_pattern=None, all=False,
                 rand=False, mode="fixed", qty=1, ns="default",
                 order="alphabetic", container_name=None, secrets=None):

It selects a subset of pods (same selection semantics as Part 1: name_pattern regex filter, label_selector, all, mode/qty, rand, order) and executes the given command string inside a named container of each selected pod using kubernetes.stream.stream(...).

Command execution
  • cmdstr is the command string to run (e.g. "dummy -a -b -c").
  • For each selected pod, the command is executed against the container whose .name equals container_name, by invoking kubernetes.stream.stream(...) once per selected pod. The number of stream.stream invocations therefore equals the number of pods that were selected and contain a container matching container_name.
  • The returned execution object exposes a read_channel(...) method; the response payload is a JSON string such as '{"status":"Success"}'.
Behavior details
  • container_name matching: A pod is only acted upon if it contains a container whose .name equals container_name. Pods whose containers do not include a matching container_name result in no stream.stream call for that pod.
    • Example: if container_name="bad_container_name" and no pod contains such a container, stream.stream is never called.
  • Name-pattern / label-selector filtering: If name_pattern matches no listed pods (e.g. pattern "no-app-[0-9]$" against pods my-app-1, my-app-2), no pods are selected and stream.stream is never called. When label_selector is provided, it is passed through to list_namespaced_pod for server-side filtering; the number of pods returned reflects that filtering.
  • Selection count: With qty=N and rand=True, up to N pods are selected (capped at the candidate count). With all=True, all matching candidates are selected. Each selected pod that has the matching container triggers exactly one stream.stream call.
Ordering
  • order defaults to "alphabetic". A value of "oldest" is also valid; when order="oldest", candidate pods are ordered by metadata.creation_timestamp (oldest first) before selection.
  • Valid order values are "alphabetic" and "oldest". Any other value must raise ActivityFailed with a message containing: Cannot select pods. Order '<order>' is invalid. In this case no stream.stream call is made.
Error conditions (raise chaoslib.exceptions.ActivityFailed)
  • If cmdstr is None, raise with a message containing: No command specified to be executed No stream.stream call is made in this case.
  • Invalid order as described above.

Import requirements

The following must be importable:

from chaosk8s.pod.actions import terminate_pods, exec_in_pods

The implementation must use kubernetes.stream.stream for in-container command execution (so that patching kubernetes.stream.stream intercepts the calls).

Notes on unchanged behavior

The pod probes pods_in_phase, pods_not_in_phase, and pods_in_conditions in chaosk8s.pod.probes retain their existing behavior:

  • pods_in_phase(label_selector, phase) returns True when all matching pods are in phase; otherwise raises ActivityFailed with a message like pod '<selector>' is in phase '<actual>' but should be '<phase>'.
  • pods_not_in_phase(label_selector, phase) returns True when no matching pod is in phase.
  • pods_in_conditions(label_selector, conditions) returns True when every matching pod has all the specified conditions (each condition is a dict with type and status keys, order-independent); otherwise raises ActivityFailed.

These need not be modified beyond keeping them working.

Overview

Update the resource-selection behavior of three Kubernetes delete/remove actions. A resource selected by its Kubernetes name must be queried with a field selector on metadata.name; it must not be selected by assuming that its name is also present as a label. Explicit label-selector selection must remain available.

The affected public functions are:

  • chaosk8s.deployment.actions.delete_deployment
  • chaosk8s.replicaset.actions.delete_replica_set
  • chaosk8s.statefulset.actions.remove_statefulset

No create, scale, probe, pod, service, or other unrelated activity behavior is to change.

Public Interfaces and Client Compatibility

The functions must retain these argument orders and defaults, including support for Kubernetes authentication secrets:

delete_deployment(
    name, ns="default", label_selector=None, secrets=None
)

delete_replica_set(
    name, ns="default", label_selector=None, secrets=None
)

remove_statefulset(
    name=None, ns="default", label_selector=None, secrets=None
)

Each action must obtain the underlying Kubernetes API client through its module's create_k8s_api_client helper, passing through secrets. The resource API accessors must remain compatible with the existing library behavior:

  • Deployment deletion must use the stable client.AppsV1Api(...) accessor. It must not use an Extensions or other beta API accessor.
  • ReplicaSet deletion must continue to use client.ExtensionsV1beta1Api(...).
  • StatefulSet removal must continue to use client.AppsV1Api(...).

All three functions use "default" when ns is omitted.

Selector Semantics

For name-based selection, construct the field selector by concatenating the exact prefix metadata.name= and the supplied name:

metadata.name=<name>

There must be no extra whitespace, quoting, label expression, or other formatting. In name mode, the list operation receives the namespace as its sole positional argument and the selector as the field_selector keyword argument. It must not receive a synthesized name-based label_selector.

An explicitly supplied, non-empty label selector selects through the Kubernetes API's label_selector argument instead. Deployment and ReplicaSet selectors retain compatibility with the existing {name} placeholder convention: if the explicit selector contains {name}, that placeholder is expanded using the required name argument before the selector is sent. A selector without that placeholder is unchanged.

Deployment Deletion

delete_deployment(name, ns="default", label_selector=None, secrets=None)

When label_selector is omitted, list deployments by name using exactly:

v1.list_namespaced_deployment(
    ns, field_selector="metadata.name={name}"
)

Here {name} denotes the value supplied by the caller, not literal braces. For example:

delete_deployment("fake_name", "fake_ns")

must list with:

v1.list_namespaced_deployment(
    "fake_ns", field_selector="metadata.name=fake_name"
)

When a label selector is explicitly supplied, retain label-based querying:

v1.list_namespaced_deployment(ns, label_selector=<effective selector>)

Do not add the name field selector to this label-selection call.

For every deployment in the returned collection, delete the resource using the name from that returned object's metadata.name and the requested namespace:

v1.delete_namespaced_deployment(
    deployment.metadata.name, ns, body=<delete options>
)

If the list is empty, perform no delete call. If it contains multiple deployments, delete each one exactly once.

v1.delete_namespaced_stateful_set(
