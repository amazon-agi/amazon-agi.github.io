01 Behavior of Pod Termination 521 words · source specification, reworded by GLM-5.3-Flash

Task Specification: Behavior of Pod Termination

Goal

Adjust the pod-termination logic so that, whenever the Kubernetes client's delete_namespaced_pod method gets invoked, the deletion options object is handed over as a keyword argument named body and not as a positional argument.

Public API

The function that follows must be present and importable:

from chaosk8s.pod.actions import terminate_pods
The function terminate_pods

It accepts these keyword parameters (all of them optional; their behaviors are laid out further down):

  • name_pattern (str): a regular expression for filtering pods on the basis of their metadata name.
  • all (bool): when it is set to True, all matching/selected pods get terminated.
  • rand (bool): when it is set to True, candidate pods are picked at random.
  • mode (str): the mode used for selection; 'percentage' is a value it supports.
  • qty (int): a quantity whose interpretation is governed by mode (a count of pods, or else a percentage when mode='percentage').
  • grace_period / handling of the grace period (see further below).

Behavior That Is Required

One or more pods are selected by the function out of the "default" namespace — depending on the parameters above — and each selected pod is terminated through a call to the Kubernetes core V1 API method delete_namespaced_pod.

Each delete_namespaced_pod call MUST be formed as follows:

  1. The name of the pod (pod.metadata.name), which goes in the first positional argument.
  2. The namespace string "default", which goes in the second positional argument.
  3. A deletion options object, which goes in the keyword argument body.

The change that is required above all: the deletion options object must be supplied under the keyword body=..., and it must NOT be passed positionally.

The deletion options object
  • When no grace period has been specified, what is passed to body is a delete-options object (an acceptable value is any V1DeleteOptions instance).
  • When a grace period has been specified (for example, 5 seconds), the value passed to body must be a V1DeleteOptions instance whose construction sets grace_period_seconds to that value — that is, the equivalent of client.V1DeleteOptions(grace_period_seconds=5).
Selection and call-count behavior
  • If name_pattern is the only parameter and a single pod matches, that pod is the target of exactly one termination call.
  • If name_pattern is combined with all=True, every matching pod is terminated (one termination call for each pod).
  • If all=True is set without any pattern, every pod in the namespace is terminated (one termination call for each pod).
  • If no parameters are given, exactly one pod is terminated.
  • If qty=N is given and N is greater than the number of selected pods, all selected pods are terminated.
  • If mode='percentage' and qty=P are set, a percentage P of the selected pods is terminated (with rounding applied, so that 40% of 5 pods, for example, produces 2 termination calls).
  • The rand=True flag makes the choice of candidate pods random, yet the number terminated and the call convention are not affected.

Across all cases, the argument convention for delete_namespaced_pod set out above (name positional, "default" positional, body as a keyword) must hold.

Task Description

Introduce a probe that waits for a Kubernetes deployment to become fully available

Overview

A public probe is to be added to chaosk8s.probes; it waits until an observed Kubernetes deployment has all of its desired replicas ready. As soon as that state is observed, the probe succeeds, and it fails if that state is not observed before the configured watch timeout.

This probe is the counterpart of the existing deployment_is_not_fully_available probe. Rather than waiting for a deployment to cease being fully available, it must wait for a deployment to become fully available.

Public API

The following function must be exposed from chaosk8s.probes:

def deployment_is_fully_available(
    name,
    ns="default",
    label_selector="name in ({name})",
    timeout=30
):
    ...

It must be directly importable in the following way:

from chaosk8s.probes import deployment_is_fully_available

The only required parameter is name. Its parameters are:

  • name: the name of the deployment or microservice.
  • ns: the Kubernetes namespace to watch; the default is "default".
  • label_selector: the label selector of the deployment; the default is "name in ({name})". The selector is resolved for the supplied name, so with name="mysvc" the default selects name in (mysvc).
  • timeout: the watch timeout in seconds; the default is 30.
Kubernetes client and watch behavior

The probe must rely on the existing Kubernetes configuration and client-loading behavior that the other probes use, including the chaosk8s.has_local_config_file configuration path. Access to Kubernetes must go through the module-level client name in chaosk8s.probes.

Rather than performing a one-time lookup, the probe must watch the selected namespaced deployment resources:

  • Acquire a watcher through the module-level chaosk8s.probes.watch name by calling watch.Watch().
  • Consume the events that this watcher's stream(...) method produces for deployments in ns, using the resolved label_selector and the configured timeout.
  • Each event that the watcher yields is a mapping, and its "object" entry is the observed deployment. Accordingly, the deployment must be read from event["object"].
  • Keep consuming events until the success condition is met or the watch times out.
Evaluating availability and success

For every observed deployment, directly compare the following fields:

  • The desired replicas: deployment.spec.replicas
  • The ready replicas: deployment.status.ready_replicas

Full availability of a deployment means deployment.status.ready_replicas == deployment.spec.replicas. The probe must stop watching and return True when any observed deployment meets that equality condition. Events whose values are unequal do not satisfy the probe and must not cause a successful return.

For the readiness decision, status.ready_replicas must be used, not another replica-status field.

Timeout and failure

When the deployment does not become fully available before the watch timeout and the watch stream surfaces this as urllib3.exceptions.ReadTimeoutError, the probe must translate that timeout into chaoslib.exceptions.ActivityFailed. In this case, it must not return False or expose the raw timeout exception.

The ActivityFailed message must contain:

microservice '<name>' failed to recover within

where <name> stands in for the supplied deployment name. For example, a timeout that happens while waiting for "mysvc" must produce a message containing:

microservice 'mysvc' failed to recover within
Compatibility

The behavior and public contracts of any existing function must not be altered. The existing urllib3 timeout type and the Chaos Toolkit library's chaoslib.exceptions.ActivityFailed exception type must continue to be used.

06 Your work takes place in the chaosk8s Python package, which supplies chaos-engineering actions and probes for Kubernetes. 993 words · source specification, reworded by GLM-5.3-Flash

Specification for the Task

Overview

Your work takes place in the chaosk8s Python package, which supplies chaos-engineering actions and probes for Kubernetes. You must alter the pod selection/termination behavior and add a new action that executes commands inside pod containers.

Every public symbol lives in the module chaosk8s.pod.actions.

The Kubernetes client is reached through chaosk8s.client (that is, client.CoreV1Api() returns a CoreV1Api instance, and client.V1DeleteOptions(...) builds delete options). Listing pods is done via CoreV1Api.list_namespaced_pod(...), which returns an object whose .items is a list of pod objects. Each pod object exposes:

  • pod.metadata.name — name of the pod (string)
  • pod.metadata.creation_timestamp — an ISO-8601 timestamp string (e.g. "2019-11-25T13:50:31Z")
  • pod.spec.containers — a list of container objects, each of which has a .name attribute

Part 1: Selecting pods for terminate_pods

Change the existing function:

def terminate_pods(label_selector=None, name_pattern=None, all=False,
                   rand=False, mode="fixed", qty=1, grace_period=-1,
                   ns="default", order="alphabetic", secrets=None):

The function lists the pods in namespace ns (default "default") through list_namespaced_pod, picks a subset of them based on the parameters, and deletes each of the selected pods through delete_namespaced_pod(name, ns, body=...).

Filtering pods by name pattern
  • If name_pattern is given, the candidate pods are restricted to those whose metadata.name matches the supplied regular expression (via a search/match against the pattern). Only pods that match are eligible for selection.
    • Example: the pattern "my-app-[0-9]$" matches "my-app-1" and "my-app-2" but not "my-app-test-3" or "some-db".
  • If name_pattern is not given, all of the listed pods are candidates.
Semantics of selection (applied to the candidate pods)
  • all=True: every candidate pod is selected.
  • mode="fixed" (the default): up to qty candidate pods are selected. qty defaults to 1.
    • If qty is greater than the number of candidates, all candidates are selected.
  • mode="percentage": the number of pods selected is ceil(qty% of the candidate count). For example, qty=40 with 4 candidates selects 2 pods.
  • rand=True: the pods are chosen at random from the candidate set (using random.sample(sequence, count)), instead of being taken in their existing order. With rand=False, the selection takes candidates from the front of the (ordered) sequence.
Deleting the selected pods

For each selected pod, call:

delete_namespaced_pod(pod.metadata.name, ns, body=<delete options>)
  • If grace_period >= 0, the body must be client.V1DeleteOptions(grace_period_seconds=grace_period).
  • Otherwise the body is a delete-options object (the exact contents are unconstrained).
Error conditions (raising chaoslib.exceptions.ActivityFailed)

When an error is raised, no pods are deleted.

  • If qty is negative, raise with a message containing: Cannot select pods. Quantity '<qty>' is negative.
  • If mode is not among the recognized modes, raise with a message containing: Cannot select pods. Mode '<mode>' is invalid.

(Note: the phrase used in these error messages is "Cannot select pods." — not "Cannot terminate pods.")

Part 2: The new action exec_in_pods

Add the following new function:

def exec_in_pods(cmdstr, label_selector=None, name_pattern=None, all=False,
                 rand=False, mode="fixed", qty=1, ns="default",
                 order="alphabetic", container_name=None, secrets=None):

It picks a subset of pods (the selection semantics are the same as in Part 1: name_pattern regex filter, label_selector, all, mode/qty, rand, order) and executes the given command string inside a named container of each selected pod using kubernetes.stream.stream(...).

Executing the command
  • cmdstr is the command string that gets run (e.g. "dummy -a -b -c").
  • For each selected pod, the command is executed against the container whose .name equals container_name, with kubernetes.stream.stream(...) invoked once per selected pod. So the number of stream.stream invocations equals the number of pods that were selected and contain a container matching container_name.
  • The execution object that is returned exposes a read_channel(...) method; the response payload is a JSON string such as '{"status":"Success"}'.
Details of the behavior
  • container_name matching: A pod is acted upon only if it contains a container whose .name equals container_name. For a pod whose containers do not include a matching container_name, no stream.stream call is made.
    • Example: when container_name="bad_container_name" and no pod contains such a container, stream.stream is never called.
  • Name-pattern / label-selector filtering: If name_pattern matches no listed pods (e.g. the pattern "no-app-[0-9]$" against pods my-app-1, my-app-2), then no pods are selected and stream.stream is never called. If label_selector is given, it is passed through to list_namespaced_pod for server-side filtering; the number of pods returned reflects that filtering.
  • Selection count: With qty=N and rand=True, up to N pods are selected (capped at the candidate count). With all=True, all matching candidates are selected. Each selected pod that has the matching container results in exactly one stream.stream call.
Ordering of pods
  • order defaults to "alphabetic". "oldest" is also a valid value; with order="oldest", the candidate pods are ordered by metadata.creation_timestamp (oldest first) before selection.
  • The valid values for order are "alphabetic" and "oldest". Any other value must raise ActivityFailed with a message containing: Cannot select pods. Order '<order>' is invalid. In that case, no stream.stream call is made.
Error conditions (raising chaoslib.exceptions.ActivityFailed)
  • If cmdstr is None, raise with a message containing: No command specified to be executed In this case, no stream.stream call is made.
  • An invalid order, as described above.

Requirements for imports

It must be possible to import the following:

from chaosk8s.pod.actions import terminate_pods, exec_in_pods

The implementation must use kubernetes.stream.stream for executing commands inside containers (so that patching kubernetes.stream.stream intercepts the calls).

Notes on behavior that stays unchanged

The pod probes pods_in_phase, pods_not_in_phase, and pods_in_conditions found in chaosk8s.pod.probes keep their existing behavior:

  • pods_in_phase(label_selector, phase) returns True when all pods that match are in phase; otherwise it raises ActivityFailed with a message like pod '<selector>' is in phase '<actual>' but should be '<phase>'.
  • pods_not_in_phase(label_selector, phase) returns True when no pod that matches is in phase.
  • pods_in_conditions(label_selector, conditions) returns True when every pod that matches has all of the specified conditions (each condition is a dict with type and status keys, order-independent); otherwise it raises ActivityFailed.

Beyond keeping them working, these do not need to be modified.

The public functions affected are:

  • chaosk8s.deployment.actions.delete_deployment
  • chaosk8s.replicaset.actions.delete_replica_set
  • chaosk8s.statefulset.actions.remove_statefulset

No behavior of create, scale, probe, pod, service, or other unrelated activities is to change.

Public Interfaces and Client Compatibility

The functions must keep the argument orders and defaults shown here, including support for Kubernetes authentication secrets:

    name, ns="default", label_selector=None, secrets=None
)

delete_replica_set(
    name, ns="default", label_selector=None, secrets=None
)

remove_statefulset(
    name=None, ns="default", label_selector=None, secrets=None
)

Each action must obtain the underlying Kubernetes API client via its module's create_k8s_api_client helper, with secrets passed through. The resource API accessors must remain compatible with the library's existing behavior:

  • Deployment deletion must use the stable client.AppsV1Api(...) accessor. An Extensions or other beta API accessor must not be used.
  • ReplicaSet deletion must keep using client.ExtensionsV1beta1Api(...).
  • StatefulSet removal must keep using client.AppsV1Api(...).

When ns is omitted, all three functions use "default".

Selector Semantics

For selection by name, the field selector is built by concatenating the exact prefix metadata.name= with the name that is supplied:

metadata.name=<name>

No extra whitespace, quoting, label expression, or other formatting is permitted. In name mode, the namespace goes to the list operation as its sole positional argument and the selector as the field_selector keyword argument. A synthesized name-based label_selector must not be passed to it.

When a label selector is explicitly supplied and non-empty, selection happens through the Kubernetes API's label_selector argument instead. )

v1.list_namespaced_deployment(ns, label_selector=<effective selector>)

v1.delete_namespaced_deployment(
