Task: Implement GeoJSON Feature Helper Functions

Overview

Create a module at turf/helpers/_features.py that provides factory functions for constructing GeoJSON Feature and FeatureCollection objects. These functions build objects with attribute-based and dictionary-based access to their data, and perform input validation.

Public API

The module turf.helpers._features must expose the following functions:

point(coordinates, properties=None, ...)
line_string(coordinates, properties=None, ...)
polygon(coordinates, properties=None, ...)
multi_point(coordinates, properties=None, ...)
multi_line_string(coordinates, properties=None, ...)
multi_polygon(coordinates, properties=None, ...)
points(list_of_coordinates, properties=None, options=None, ...)
line_strings(list_of_coordinates, properties=None, options=None, ...)
polygons(list_of_coordinates, properties=None, options=None, ...)

Object Structure

Feature objects

A Feature is returned by point, line_string, polygon, multi_point, multi_line_string, and multi_polygon. It must support attribute access:

  • .type — the string "Feature".
  • .properties — a dictionary. If no properties argument is supplied, this must be an empty dict {}. Otherwise it holds the supplied dictionary (accessible both as a whole and by key, e.g. feature.properties["name"]).
  • .geometry — a geometry object supporting attribute access:
    • .type — the geometry type string (see below).
    • .coordinates — the coordinate data, stored as given (nesting preserved). Must compare equal (==) to the input coordinate list.
FeatureCollection objects

A FeatureCollection is returned by points, line_strings, and polygons. It must support attribute access:

  • .features — a list of Feature objects, one per input coordinate entry. len(...) returns the count.
  • .id — the value provided via the options argument's "id" key (see below).
  • Each Feature in .features carries the shared properties dict passed to the collection function, accessible by key (e.g. .features[0].properties["foo"]).

Geometry Types

Function geometry .type
point "Point"
line_string "LineString"
polygon "Polygon"
multi_point "MultiPoint"
multi_line_string "MultiLineString"
multi_polygon "MultiPolygon"

Function Details

point(coordinates, properties=None)
  • coordinates is a position: a list of exactly two numbers [lng, lat].
  • The resulting geometry's .coordinates preserves this list, so coordinates[0] and coordinates[1] are the two numbers.
line_string(coordinates, properties=None)
  • coordinates is a list of two or more positions (each a [lng, lat] pair).
polygon(coordinates, properties=None)
  • coordinates is a list of LinearRings. Each LinearRing is a list of positions.
  • Each ring must contain four or more positions, and its first and last position must be equal (closed ring).
multi_point(coordinates, properties=None)
  • coordinates is a list of positions.
multi_line_string(coordinates, properties=None)
  • coordinates is a list of LineStrings, each a list of two or more positions.
multi_polygon(coordinates, properties=None)
  • coordinates is a list of Polygons, each a list of LinearRings (each ring following the polygon ring rules above: four or more positions, closed).
points(list_of_coordinates, properties=None, options=None)
line_strings(list_of_coordinates, properties=None, options=None)
polygons(list_of_coordinates, properties=None, options=None)
  • list_of_coordinates is a list where each entry is a valid coordinate structure for the corresponding singular type.
  • Build one Feature per entry (using the singular helper's rules), collect them into a FeatureCollection.
  • The properties dict is shared across all generated features.
  • The options argument is a dict; its "id" key becomes the collection's .id.

Validation and Error Conditions

Calling with invalid input must raise an exception. The exception messages must contain the specified substrings.

  • Missing required coordinates argument (calling point(), line_string(), polygon() with no arguments): raise an exception.

  • point:

    • Coordinates not being a valid 2-element position (e.g. [1]): message contains "[lng, lat]".
    • Coordinate values not numeric (e.g. [1, "xyz"]): message contains "invalid".

  • line_string:

    • Fewer than two positions (e.g. [[5, 10]]): message contains "two or more".
    • Non-numeric coordinate values (e.g. [["xyz", 10], [1, 4]]): message contains "invalid".

  • polygon:

    • Coordinates not a list of LinearRings (e.g. the string "xyz"): message contains "list of LinearRing".
    • A ring that is not a list of positions (e.g. ["xyz"]): message contains "list of Positions".
    • A ring with fewer than four positions (e.g. [[[5, 10], [20, 40], [40, 0]]]): message contains "4 or more Positions".
    • A ring whose first and last positions are not equal (e.g. [[[5, 10], [20, 40], [40, 0], [2, 3]]]): message contains "not equivalent".

  • multi_line_string:

    • Any contained LineString with fewer than two positions (e.g. [[[0, 0]], [[5, 0], [15, 8]]]): message contains "two or more".

  • multi_polygon:

    • Any contained ring whose first and last positions are not equal: message contains "not equivalent".
    • Any contained ring with fewer than four positions: message contains "4 or more Positions".

Notes on Numeric Validation

Coordinate values must be numbers. A non-numeric value (such as a string) in a position triggers the "invalid" error described for point and line_string. Numeric integers such as those shown in the examples are valid.

Objective

Create a module turf.length that exposes a public function length which computes the total linear (geodesic) distance along the line segments of a GeoJSON geometry, feature, or collection.

Public API

from turf.length import length
Signature
def length(geojson, options=None):
    ...
  • geojson: the input to measure (see accepted input types below).
  • options: an optional dict. The only key exercised is "units", whose value is a string naming the output distance unit (e.g. "feet"). When omitted, options may be None.
Return value

A number: the total distance obtained by summing the great-circle distances between each pair of consecutive coordinates along every line contained in the input, expressed in the requested units.

Accepted inputs and how they are measured

The function must walk the coordinate structure of the input and sum the distances between consecutive coordinate pairs. Distances between two [longitude, latitude] positions must be computed as geodesic (great-circle) distances on the Earth, then converted to the requested unit.

The following input forms must be supported:

  1. A raw list of coordinate line strings — a list whose elements are each a list of [lon, lat] positions (i.e., the structure of a MultiLineString's coordinates). Each inner list is treated as an independent line; distances are summed within and across all inner lists.

  2. A Feature whose geometry is one of:

    • LineString — sum distances along its single coordinate sequence.
    • MultiLineString — sum distances along each of its coordinate sequences.
    • Polygon — sum distances along each ring (treating each ring as a line following its coordinate order, including the closing segment back to the first point as given by the ring's coordinates).
    • MultiPolygon — sum distances along every ring of every polygon.

  3. A FeatureCollection — sum the measured length of every feature it contains.

Feature/geometry objects may be provided either as plain GeoJSON-style dicts or as objects produced by the helper constructors in turf.helpers (for example multi_line_string(...)). Both must be handled equivalently.

Within each individual line/ring, distance is accumulated by taking consecutive coordinate pairs in order. No line contributes distance from its last point to the first point unless that point is explicitly present in its coordinate list (as it is for polygon rings).

Error conditions

The function must reject inputs that do not contain measurable line geometry. In particular:

  • A bare coordinate position such as [0, 0] (a single point as a raw list).
  • A Point feature (e.g. the result of turf.helpers.point([0, 0])).

In these cases the function must raise an exception whose message contains the substring Input must be.

Numerical expectations

Results are validated after rounding to the nearest integer. Using units="feet", the following representative results must hold (rounded):

  • A MultiLineString feature with two lines (first line points [-77.031669, 38.878605] … [-77.019824, 38.892368], second line [-77.041669, 38.885821] … [-77.035661, 38.878605]) → 15433.
  • The same coordinate structure passed as a raw list of point lists → 15433.
  • A Polygon whose single ring is [-77.031669, 38.878605] … [-77.04, 38.88] → [-77.031669, 38.878605] → 18364.
  • A MultiPolygon with two polygons (ring counts of 8 and 5 coordinates respectively) → 27335.
  • A FeatureCollection containing the MultiLineString above plus the Polygon above → 33796 (i.e., the sum of the members).
  • A long real-world LineString route → 1068692.
  • A second long real-world LineString route → 2432897.

These values fix the choice of Earth radius / distance model and unit conversion factor; your implementation must reproduce them (to the rounded integer) for the given coordinates.

Notes

  • Coordinates are in [longitude, latitude] order (degrees).
  • The distance-summing logic should rely on a geodesic point-to-point distance computation consistent across all input types so that the same coordinates always yield the same total regardless of how they are wrapped (raw list, Feature, or FeatureCollection).

Task Specification: Implement square Module

Objective

Create a new module that computes the smallest enclosing bounding box that is a perfect square, given an input bounding box.

Public API

Create a module at turf/square/ that exposes a callable named square, importable as:

from turf.square import square

Function Signature

def square(bbox):
    ...

Behavior

The square function takes a single argument bbox, which is a list of four numeric values representing a bounding box in the form:

[west, south, east, north]

where:

  • west (bbox[0]) and east (bbox[2]) define the horizontal extent,
  • south (bbox[1]) and north (bbox[3]) define the vertical extent.

The function must return a new bounding box (a list of four numeric values, same format) that is the smallest square that fully contains the input bounding box. The returned box is centered on the input box along the dimension that needs to be expanded.

Computation rules

Let:

  • horizontal_distance = east - west
  • vertical_distance = north - south

Then:

  • If horizontal_distance >= vertical_distance (the box is wider than or equal to its height):

    • The horizontal extent is kept unchanged.
    • The vertical extent is expanded symmetrically about its center so its height equals horizontal_distance.
    • Specifically, with mid = (south + north) / 2 and half = horizontal_distance / 2, the result is:
      [west, mid - half, east, mid + half]

  • Otherwise (the box is taller than it is wide):

    • The vertical extent is kept unchanged.
    • The horizontal extent is expanded symmetrically about its center so its width equals vertical_distance.
    • Specifically, with mid = (west + east) / 2 and half = vertical_distance / 2, the result is:
      [mid - half, south, mid + half, north]

  • If the input box is already square (horizontal_distance == vertical_distance), the returned box is equal to the input box.

[0, 0, 5, 10] [-2.5, 0, 7.5, 10]
[0, 0, 10, 5] [0, -2.5, 10, 7.5]
[0, 0, 10, 10] [0, 0, 10, 10]

The returned value must be a list whose elements compare equal to the values shown above.
