Overview

Create a Python package named ubermagutil that exposes package metadata and a descriptor-based type system. The public imports must work as follows:

import ubermagutil as uu
import ubermagutil.typesystem as ts

The type system validates managed instance attributes on both initial construction and later assignment, while preserving the assigned value unless a descriptor explicitly documents normalization.

Package metadata

The top-level ubermagutil package must expose:

  • __version__: a string containing at least one . character.
  • __dependencies__: a non-empty list.

Public ubermagutil.typesystem API

The ubermagutil.typesystem module must publicly export these exact names:

  • typesystem
  • Descriptor
  • Typed
  • Scalar
  • Vector
  • Name
  • InSet
  • Subset

Capitalization is significant. In particular, the subset descriptor's public class name is Subset, not SubSet.

The typesystem decorator

typesystem is a class decorator used with keyword field declarations:

@ts.typesystem(
    count=ts.Scalar(expected_type=int, positive=True),
    point=ts.Vector(size=3, component_type=float),
    label=ts.Name,
    choices=ts.Subset(sample_set="xyz"),
)
class SomeClass:
    ...

Each keyword name is the managed attribute name. A declaration may be either:

  1. an already-created Descriptor instance, or
  2. a bare Descriptor subclass, such as ts.Scalar, ts.Vector, ts.Name, or a user-defined subclass.

A bare descriptor class must be instantiated and bound to the corresponding field using its default configuration. For either declaration form, the resulting descriptor's public name attribute must equal the decorator keyword.

The descriptor is installed on the decorated class. Access through the class returns the descriptor object itself, so declarations can be inspected publicly:

SomeClass.count.name == "count"
SomeClass.count.const is False
SomeClass.point.size == 3
SomeClass.point.component_type is float

Descriptor-specific configuration, including expected_type, size, component_type, positive, unsigned, allowed_values, and sample_set, must remain inspectable where applicable.

Managed fields are independent and optional constructor keyword fields. Constructing a decorated class with all, some, or none of them must be possible. Supplied values are assigned through their descriptors and receive the same validation as later direct assignment. Omitting a field must not require it and must not implicitly assign None; the field can be assigned later.

Common descriptor behavior

Descriptor is the public base class for all descriptors. The base descriptor stores assignments without imposing a type or value constraint and is suitable for subclassing. Every public descriptor supports const=False by default. Values are kept independently for each instance.

A successful assignment stores the value in that instance. A failed assignment raises the descriptor-specific exception and does not replace a previously stored value. Except for Subset, descriptors store the assigned object without conversion or container normalization.

Constant fields

With const=True, a managed field is settable once per instance. An omitted constant field remains unset and may be assigned once later. After a value has been stored:

  • any later assignment that passes the descriptor's validation raises AttributeError, including assignment of the same value;
  • the proposed value is validated before the set-once check, so an invalid reassignment raises its normal TypeError or ValueError instead of AttributeError; and
  • a failed first assignment does not consume the one permitted assignment.

For example, assigning a scalar to an already initialized constant Vector raises TypeError because it is not a vector. Assigning another valid vector raises AttributeError.

Deletion

Deleting any managed descriptor attribute is unsupported and raises AttributeError, whether or not that field currently has an instance value. Deletion must never allow a constant field to be reset.

Typed

Construction:

ts.Typed(expected_type=<type-or-tuple-of-types>, const=False)

Typed accepts a value exactly when isinstance(value, expected_type) is true. Consequently, expected_type may be one type or a tuple of types and may use abstract numeric classes such as numbers.Real or NumPy classes such as numpy.ndarray. A mismatch raises TypeError. The accepted value is stored unchanged.

Scalar

Supported construction options are:

ts.Scalar(
    expected_type=numbers.Real,
    positive=False,
    unsigned=False,
    const=False,
)

The positive and unsigned keywords are the public sign-constraint interface; min_bound and max_bound are not required options.

Validation proceeds as follows:

  1. The value must be an instance of numbers.Real; otherwise, raise TypeError.
  2. It must satisfy the configured expected_type using ordinary isinstance semantics; otherwise, raise TypeError.
  3. If unsigned=True, the value must be greater than or equal to zero; a negative value raises ValueError.
  4. If positive=True, the value must be strictly greater than zero; zero or a negative value raises ValueError.

positive=False does not require a negative value; it simply disables the positivity restriction. Likewise, unsigned=False imposes no unsigned restriction. If both flags are true, the stricter positive condition also applies. Type validation occurs before sign validation. For example, assigning the integer -1 to Scalar(expected_type=float, unsigned=True) raises TypeError, not ValueError. NumPy scalar values follow ordinary isinstance behavior and are not coerced. Accepted values are stored unchanged.

Vector

Supported construction options are:

ts.Vector(
    size=None,
    component_type=numbers.Real,
    positive=False,
    unsigned=False,
    const=False,
)

The component-type keyword is named component_type, not expected_type. The positive and unsigned keywords are the public sign constraints; min_bound and max_bound are not required options.

A vector value must be a list, tuple, or one-dimensional numpy.ndarray. Other inputs, such as a scalar or dictionary, raise TypeError. Lists, tuples, and NumPy arrays are all preserved as assigned rather than converted or copied.

Vector validation has these rules:

  1. Every component must first be an instance of numbers.Real. A non-numeric component, such as a string, raises ValueError.
  2. If size is not None, len(value) must equal size; a mismatch raises ValueError. This applies equally to NumPy arrays, including an empty array.
  3. Every real component must satisfy component_type using ordinary isinstance semantics. A real numeric component of the wrong configured type raises TypeError; for example, an integer component in Vector(component_type=float) is invalid.
  4. If unsigned=True, every component must be greater than or equal to zero; a violation raises ValueError.
  5. If positive=True, every component must be strictly greater than zero; a zero or negative component raises ValueError.

positive=False and unsigned=False impose no corresponding sign restriction. If both flags are true, all components must be strictly positive. The distinction between a non-real component and a real component of the wrong configured type is required: the former raises ValueError, while the latter raises TypeError.

Examples of valid values include (1, 2.5), [0, 5] for an unsigned vector, and numpy.array([5, 1e5]) for a positive vector. A vector's configured size is exact, not a maximum.

Name

Construction:

ts.Name(const=False)

Name accepts identifier-like strings under these rules:

  • A non-string raises TypeError.
  • The string must be non-empty and begin with a letter or underscore; otherwise, raise ValueError.
  • The string must not contain spaces; a space raises ValueError.

The descriptor does not require str.isidentifier(): digits, underscores, and hyphens are permitted after a valid first character. Thus "var_name", "a1a", and "var-name" are valid, while "1a", "-a", and "val name" are invalid. The accepted string is stored unchanged. Name may be supplied to typesystem either as the bare class or as an instance such as Name(const=True).

InSet

Construction uses the exact allowed_values keyword:

ts.InSet(allowed_values=<collection>, const=False)

The allowed collection is not configured through a set keyword. An assigned value is accepted exactly when it is a member of allowed_values, using ordinary membership semantics. The allowed collection may be heterogeneous; no common Python type is inferred from its members. A non-member raises ValueError, regardless of whether its Python type differs from those of the allowed members. A valid member is stored unchanged.

For example, with InSet(allowed_values=[1, 2, "5"]), both 1 and "5" are valid, while -1 raises ValueError.

Subset

Construction uses the exact class name and keyword:

ts.Subset(sample_set=<collection>, const=False)

The allowed collection is not configured through a set keyword. An assigned value is treated as an iterable of candidate members. It is valid exactly when every distinct candidate belongs to sample_set. Lists, tuples, sets, strings, other usable iterables, duplicate elements, and the empty iterable follow these subset semantics.

On a valid assignment, Subset stores set(value), not the original iterable. This collapses duplicates and discards order. For example, with Subset(sample_set="xyz"):

  • assigning "x" stores {'x'};
  • assigning "yxzz" is valid and stores {'y', 'x', 'z'}; and
  • assigning an empty iterable stores set().

An iterable containing any disallowed member raises ValueError. A non-iterable, such as a bare integer, raises TypeError. Strings are iterable candidates rather than singleton values, so their individual characters are checked against sample_set.

Required exception and compatibility summary

Unless a descriptor states a more specific rule above, a Python type mismatch raises TypeError, while a value of an accepted structural type that violates a configured constraint raises ValueError. The Vector non-real-component rule is intentionally ValueError. Validation always occurs before constant-write protection, and deletion of managed fields always raises AttributeError.

Common descriptor behavior

Constant attributes

Descriptors support const=False by default. With const=True, the first successful assignment initializes the attribute and a later otherwise-valid assignment raises AttributeError.

For the existing ordinary descriptors, descriptor-specific validation occurs before constant-write protection. Consequently, after a constant Vector has been initialized:

  • assigning a scalar rather than a supported vector container raises TypeError;
  • assigning another valid vector reaches constant enforcement and raises AttributeError.

The new Parameter descriptor has the stronger, separately specified rule that every assignment after its first successful assignment raises AttributeError, regardless of whether the replacement value would otherwise be valid.

The otherwise fallback

All descriptors must accept an optional otherwise keyword; this behavior is required in particular for Scalar, Vector, and Parameter. Its value is a Python type, for example tuple or float. Type matching uses isinstance.

For otherwise=T:

  1. Apply the descriptor's primary validation.
  2. If primary validation succeeds, accept the value using the descriptor's normal storage behavior.
  3. If primary validation fails but isinstance(value, T) is true, accept and store the fallback value unchanged.
  4. If the value satisfies neither branch, reject it with TypeError.

The fallback is an alternative accepted type; it does not coerce or copy the value. The more specific dictionary validation and error rules of Parameter remain as described below.

Required examples include:

  • ts.Scalar(otherwise=tuple) accepts 1 through normal scalar validation and accepts (1, 2, 1e5, 5) through the fallback; it rejects a string with TypeError.
  • ts.Vector(size=3, otherwise=float) accepts (1, 2, 3) through normal vector validation and accepts 1.2 through the fallback. It rejects a string and rejects integer 5 with TypeError; an int is not a float for this isinstance check.

Existing descriptors

Descriptor

Descriptor is the public base class for the descriptor family and remains usable for custom descriptors. It provides managed-value storage, const enforcement, and deletion protection. Custom validators can perform their own type/value checks before delegating the successful assignment to the base behavior.

Scalar

ts.Subset(sample_set=..., const=False, otherwise=None)

Accepted values and validation order

An assignment is accepted through one of these forms:

  1. A single wrapped-descriptor value. Validate the assigned value directly with descriptor. If it is valid, store it unchanged.
  2. A named-value dictionary. If the assigned value is a dictionary rather than a valid single value, all of the following are required:
    • The dictionary is non-empty. An empty dictionary raises ValueError.

Logging configuration

Signature
setup_logging(level=logging.WARNING, package_levels=None)

Calling setup_logging must set the levels of these named loggers:

  • discretisedfield
  • mag2exp
  • micromagneticdata
  • micromagneticmodel
  • micromagnetictests
  • oommfc
  • ubermagtable
  • ubermagutil

Requirements:

  • The default fallback level is logging.WARNING.
  • level must accept integer logging levels, logging constants such as logging.DEBUG, and standard level-name strings such as "DEBUG". The logger's resulting level must be the corresponding integer value.
  • If package_levels is supplied, it is a mapping from exact package logger names to levels. An entry for one of the names above overrides level for that logger only; listed loggers without a matching entry continue to use the fallback level. Override values use the same accepted logging-level forms.
  • Entries whose keys do not exactly match one of the listed logger names must not alter the level selected for those listed loggers.
  • The root logger's own level must remain unchanged. Configuring the package loggers must not replace it with the fallback or a package-specific level.

Hysteresis value generation

Signature
hysteresis_values(vmin, vmax, step)

For a range that contains an integral number n = (vmax - vmin) / step of steps, this function must return a Python list with the sequence

[vmax, vmax-step, ..., vmin, vmin+step, ..., vmax]

Thus:

  • the sweep first descends from vmax through vmin;
  • it then ascends from vmin back to vmax;
  • vmin appears only once, while vmax is both the first and final value; and
  • the result contains 2*n + 1 entries.

For example:

import ubermagutil as uu

assert uu.hysteresis_values(-1, 1, 1) == [1.0, 0.0, -1.0, 0.0, 1.0]

The integrality check must tolerate ordinary floating-point rounding, including ranges and steps at large and very small magnitudes. A materially non-integral step count must raise ValueError; for example, the range from -1 to 1 cannot be traversed exactly with a step of 0.3.

Documentation inheritance

inherit_docs is a class decorator. For a decorated subclass:

  • an overridden method with no docstring must receive the corresponding inherited method's docstring;
  • an overridden property whose getter has no docstring must receive the corresponding inherited property's docstring;
  • an explicitly supplied overriding docstring must not be replaced;
  • a constructor inherited without being overridden must retain the base constructor's docstring; and
  • copying documentation to the subclass must not modify the base class, its methods, or its properties.

The decorator must return the decorated class so that normal class construction and inheritance continue to work.

SI multiplier utilities

The functions in this section must be public from ubermagutil.units:

import ubermagutil.units as units
si_multiplier(value)

For a nonzero numeric value, si_multiplier must use the magnitude of the value and select a positive supported SI power-of-1000 multiplier m such that

1 <= abs(value) / m < 1000

Supported multipliers range from yocto through yotta:

1e-24, 1e-21, 1e-18, 1e-15, 1e-12, 1e-9, 1e-6, 1e-3,
1, 1e3, 1e6, 1e9, 1e12, 1e15, 1e18, 1e21, 1e24

Additional requirements:

  • The sign of value does not affect the selected multiplier.
  • Zero returns 1.
  • If no supported multiplier satisfies the magnitude rule, return None.

The following boundary and scale results are required:

assert units.si_multiplier(1e-9) == 1e-9
assert units.si_multiplier(50e-9) == 1e-9
assert units.si_multiplier(100e-9) == 1e-9
assert units.si_multiplier(-100e-9) == 1e-9
assert units.si_multiplier(1001e-9) == 1e-6
assert units.si_multiplier(0.5e-9) == 1e-12
assert units.si_multiplier(0.5) == 1e-3
assert units.si_multiplier(0.05) == 1e-3
assert units.si_multiplier(5) == 1
assert units.si_multiplier(50) == 1
assert units.si_multiplier(500) == 1
assert units.si_multiplier(1e3) == 1e3
assert units.si_multiplier(0) == 1
assert units.si_multiplier(5e30) is None
si_max_multiplier(values)

si_max_multiplier must compute si_multiplier for the supplied values and return the numerically largest resulting multiplier. It must accept ordinary finite sequences such as lists and tuples. Required examples are:

assert units.si_max_multiplier((5e-10, 6e-9, 4e-9)) == 1e-9
assert units.si_max_multiplier((1, 1e-3, 1e-6)) == 1
assert units.si_max_multiplier((1, 1e3, 1e6)) == 1e6

Managed attribute type system

The ubermagutil.typesystem namespace must publicly expose:

  • the typesystem class decorator; and
  • the Typed, Scalar, Vector, Name, Dictionary, Subset, and Parameter managed descriptors.

Typical use is:

import ubermagutil.typesystem as ts

@ts.typesystem(count=ts.Scalar(expected_type=int, unsigned=True))
class Example:
    def __init__(self, count):
        self.count = count

The keyword names passed to typesystem identify the managed class attributes, and their descriptor values define assignment validation.

Common descriptor behavior

All managed descriptors must obey these rules:

  • Validation occurs before an assigned value replaces the currently stored value.
  • A successful assignment makes the accepted value available through normal attribute access.
  • If an assignment is rejected, the last successfully assigned value remains unchanged.
  • const=True permits the first assignment but raises AttributeError on reassignment.
  • Deleting a managed attribute raises AttributeError.
  • Where an otherwise type is supported, a value matching that type is accepted as an alternative before the descriptor's normal validation and is stored unchanged.
Typed

Conceptual constructor options are:

Typed(expected_type=..., allow_none=False, const=False)
  • Values matching expected_type according to normal isinstance semantics are accepted.
  • None is additionally accepted when allow_none=True.
  • Other values raise TypeError.
Scalar

Scalar manages real numeric values and supports expected_type, positive, unsigned, otherwise, and const options.

  • Without a narrower expected_type, values must satisfy numbers.Real.
  • If expected_type is supplied, the value must also match that type; a mismatch raises TypeError.
  • positive=True requires a value strictly greater than zero.
  • unsigned=True requires a value greater than or equal to zero.
  • positive=False and unsigned=False impose no corresponding sign restriction.
  • A sign violation raises ValueError.
  • A value matching otherwise, when configured, is accepted and stored unchanged even though it does not satisfy the numeric rules.
Vector

Vector supports size, component_type, positive, unsigned, otherwise, and const options.

  • A vector value may be a tuple, list, or NumPy ndarray. Other container/value types raise TypeError, unless accepted by otherwise.
  • Every component must be a numbers.Real; if component_type is supplied, every component must also match it. Invalid component types raise TypeError.
  • If size is supplied, the vector must have exactly that many components. A size mismatch raises ValueError.
  • positive=True requires every component to be strictly greater than zero.
  • unsigned=True requires every component to be greater than or equal to zero.
  • A component sign violation raises ValueError.
  • An accepted vector is stored in its original representation; lists, tuples, and arrays are not required to be converted to a common container.
  • A value matching otherwise, when configured, is accepted and stored unchanged.
Name

Conceptual constructor options are:

Name(allowed_char=..., const=False)
  • The assigned value must be a string. Non-strings raise TypeError.
  • Without allowed_char, the string must be a valid Python identifier and must not be a Python keyword. Names may contain the characters Python permits in identifiers, such as letters, digits after the first character, and underscores.
  • If a separator is configured with allowed_char, that separator may occur between name components. Every component obtained by splitting at the separator must independently be a valid non-keyword Python identifier. For example, allowed_char=":" accepts both "r1" and "r1:r2".
  • Malformed strings, including names beginning with a digit, names containing spaces or unconfigured punctuation, keywords, and empty/invalid separated components, raise ValueError.
Dictionary

Conceptual constructor options are:

Dictionary(
    key_descriptor=...,
    value_descriptor=...,
    allow_empty=False,
    otherwise=None,
    const=False,
)
  • Normal values must be dictionaries. A non-dictionary raises TypeError unless it matches the configured otherwise type.
  • Every key must pass key_descriptor, and every corresponding value must pass value_descriptor. Validation errors from those descriptors retain their appropriate exception category.
  • An empty dictionary raises ValueError by default. It is accepted when allow_empty=True.
  • An accepted dictionary, or an accepted otherwise value, is stored unchanged.
Subset

Conceptual constructor options are:

Subset(sample_set=..., unpack=..., otherwise=None, const=False)
  • With unpack=False, the assigned value itself must be a member of sample_set; it is stored unchanged.
  • With unpack=True, the assigned value is unpacked into a set. Every resulting element must belong to sample_set, and the resulting set is the stored value. Duplicate input elements are therefore collapsed.
  • A value or unpacked element outside sample_set raises ValueError.
  • A value matching otherwise, when configured, bypasses subset validation and is stored unchanged.
Parameter

Conceptual constructor options are:

Parameter(descriptor=..., otherwise=None, const=False)

A parameter supports either one uniform value or a region-to-value dictionary:

  • A non-dictionary value must pass the configured descriptor.
  • A dictionary must be non-empty. Every key must be a string name whose colon-separated components are valid Python identifiers, and every value must pass the configured descriptor. Keys such as "a:b" are valid.
  • An empty dictionary or a dictionary containing a malformed string key raises ValueError.
  • A key of an invalid type, or a value with a type rejected by the configured descriptor, raises TypeError. Other value constraints retain the configured descriptor's exception category.
  • If no descriptor was configured, an assignment requiring descriptor validation raises AttributeError.
  • A value matching otherwise, when configured, is accepted unchanged instead of being interpreted as either the direct parameter value or the region mapping.
  • Valid direct values and valid dictionaries are stored unchanged.
