01 Build a Python package called ubermagutil that exposes package metadata together with a descriptor-based type system. 1591 words · rewritten by GPT-5.6-sol, reworded by GLM-5.3-Flash

Specification of the Task

Overview

Build a Python package called ubermagutil that exposes package metadata together with a descriptor-based type system. The following public imports must work:

import ubermagutil as uu
import ubermagutil.typesystem as ts

Validation of managed instance attributes is carried out by the type system both at initial construction and at later assignment, and the assigned value is preserved unless a descriptor explicitly documents normalization.

Metadata of the package

At the top level, the ubermagutil package must expose:

  • __version__: a string that contains at least one . character.
  • __dependencies__: a list that is non-empty.

Public API of ubermagutil.typesystem

These exact names must be publicly exported by the ubermagutil.typesystem module:

  • typesystem
  • Descriptor
  • Typed
  • Scalar
  • Vector
  • Name
  • InSet
  • Subset

Capitalization matters. In particular, the public class name of the subset descriptor is Subset, not SubSet.

The decorator typesystem

typesystem is a class decorator used together with keyword field declarations:

@ts.typesystem(
    count=ts.Scalar(expected_type=int, positive=True),
    point=ts.Vector(size=3, component_type=float),
    label=ts.Name,
    choices=ts.Subset(sample_set="xyz"),
)
class SomeClass:
    ...

The managed attribute name is given by each keyword name. A declaration may be either:

  1. a Descriptor instance that has already been created, or
  2. a bare Descriptor subclass, for example ts.Scalar, ts.Vector, ts.Name, or a subclass defined by the user.

A descriptor class given in bare form must be instantiated and bound to the corresponding field using its default configuration. Under either declaration form, the public name attribute of the resulting descriptor must equal the decorator keyword.

The descriptor is installed onto the decorated class. Accessing the attribute through the class returns the descriptor object itself; declarations can therefore be inspected publicly:

SomeClass.count.name == "count"
SomeClass.count.const is False
SomeClass.point.size == 3
SomeClass.point.component_type is float

Descriptor-specific configuration, including expected_type, size, component_type, positive, unsigned, allowed_values, and sample_set, must remain inspectable wherever applicable.

Managed fields are constructor keyword fields that are independent and optional. It must be possible to construct a decorated class with all, some, or none of them. Values that are supplied are assigned through their descriptors and receive the same validation as a later direct assignment. Omitting a field must not make it required and must not implicitly assign None; the field can be assigned later.

Behavior common to descriptors

All descriptors have Descriptor as their public base class. The base descriptor stores assignments and imposes no type or value constraint; it is suitable for subclassing. By default, every public descriptor supports const=False. Each instance keeps its values independently.

When an assignment succeeds, the value is stored in that instance. When an assignment fails, the descriptor-specific exception is raised and a previously stored value is not replaced. Apart from Subset, descriptors store the assigned object without conversion or container normalization.

Constant fields

When const=True, a managed field is settable a single time per instance. A constant field that was omitted remains unset and may be assigned once at a later point. After a value has been stored:

  • any later assignment passing the descriptor's validation raises AttributeError, including assignment of the same value;
  • the proposed value is validated before the set-once check, so an invalid reassignment raises its normal TypeError or ValueError rather than AttributeError; and
  • a first assignment that fails does not consume the single permitted assignment.

As an example, assigning a scalar to a constant Vector that has already been initialized raises TypeError because it is not a vector. Assigning a different valid vector raises AttributeError.

Deletion

Deleting any managed descriptor attribute is not supported and raises AttributeError, whether or not that field currently has an instance value. Deletion must never allow a constant field to be reset.

Typed

Construction:

ts.Typed(expected_type=<type-or-tuple-of-types>, const=False)

A value is accepted by Typed exactly when isinstance(value, expected_type) is true. As a consequence, expected_type may be a single type or a tuple of types, and it may use abstract numeric classes such as numbers.Real or NumPy classes such as numpy.ndarray. A mismatch raises TypeError. An accepted value is stored unchanged.

Scalar

The supported construction options are:

ts.Scalar(
    expected_type=numbers.Real,
    positive=False,
    unsigned=False,
    const=False,
)

The positive and unsigned keywords make up the public sign-constraint interface; min_bound and max_bound are not required options.

Validation proceeds in the following way:

  1. The value must be an instance of numbers.Real; if it is not, raise TypeError.
  2. It must satisfy the configured expected_type under ordinary isinstance semantics; if it does not, raise TypeError.
  3. With unsigned=True, the value must be greater than or equal to zero; a negative value raises ValueError.
  4. With positive=True, the value must be strictly greater than zero; zero or a negative value raises ValueError.

A negative value is not required by positive=False; it simply disables the positivity restriction. In the same way, unsigned=False imposes no unsigned restriction. When both flags are true, the stricter positive condition also applies. Type validation happens before sign validation. As an example, assigning the integer -1 to Scalar(expected_type=float, unsigned=True) raises TypeError, not ValueError. Ordinary isinstance behavior applies to NumPy scalar values, and they are not coerced. Values that are accepted are stored unchanged.

Vector

The supported construction options are:

ts.Vector(
    size=None,
    component_type=numbers.Real,
    positive=False,
    unsigned=False,
    const=False,
)

The keyword for the component type is component_type, not expected_type. The public sign constraints are the positive and unsigned keywords; min_bound and max_bound are not required options.

A vector value must be a list, a tuple, or a one-dimensional numpy.ndarray. Inputs of other kinds, such as a scalar or a dictionary, raise TypeError. Lists, tuples, and NumPy arrays are all preserved as assigned rather than being converted or copied.

Vector validation follows these rules:

  1. First, every component must be an instance of numbers.Real. A component that is not numeric, such as a string, raises ValueError.
  2. When size is not None, len(value) must equal size; a mismatch raises ValueError. This applies equally to NumPy arrays, an empty array included.
  3. Every real component must satisfy component_type under ordinary isinstance semantics. A real numeric component of the wrong configured type raises TypeError; an integer component in Vector(component_type=float), for example, is invalid.
  4. With unsigned=True, every component must be greater than or equal to zero; a violation raises ValueError.
  5. With positive=True, every component must be strictly greater than zero; a component that is zero or negative raises ValueError.

No corresponding sign restriction is imposed by positive=False and unsigned=False. When both flags are true, all components must be strictly positive. The distinction between a non-real component and a real component of the wrong configured type is a required one: the former raises ValueError, while the latter raises TypeError.

Valid value examples include (1, 2.5), [0, 5] for an unsigned vector, and numpy.array([5, 1e5]) for a positive vector. The configured size of a vector is exact, not a maximum.

Name

Construction:

ts.Name(const=False)

Under these rules, Name accepts strings that are identifier-like:

  • A value that is not a string raises TypeError.
  • The string must be non-empty and start with a letter or underscore; otherwise, raise ValueError.
  • Spaces must not appear in the string; a space raises ValueError.

str.isidentifier() is not required by the descriptor: after a valid first character, digits, underscores, and hyphens are permitted. Hence "var_name", "a1a", and "var-name" are valid, while "1a", "-a", and "val name" are invalid. A string that is accepted is stored unchanged. Name may be supplied to typesystem either as the bare class or as an instance like Name(const=True).

InSet

At construction, the exact allowed_values keyword is used:

ts.InSet(allowed_values=<collection>, const=False)

The allowed collection is not configured by way of a set keyword. A value that is assigned is accepted exactly when it is a member of allowed_values, with ordinary membership semantics. The collection of allowed values may be heterogeneous; no common Python type is inferred from its members. A value that is not a member raises ValueError, regardless of whether its Python type differs from the Python types of the allowed members. A member that is valid is stored unchanged.

As an example, with InSet(allowed_values=[1, 2, "5"]), both 1 and "5" are valid, while -1 raises ValueError.

Subset

At construction, the exact class name and keyword are used:

ts.Subset(sample_set=<collection>, const=False)

A set keyword is not used to configure the allowed collection. A value that is assigned is treated as an iterable of candidate members. The value is valid exactly when every distinct candidate belongs to sample_set. Lists, tuples, sets, strings, other usable iterables, duplicate elements, and the empty iterable are subject to these subset semantics.

When an assignment is valid, Subset stores set(value), not the original iterable. Duplicates are collapsed and order is discarded as a result. As an example, with Subset(sample_set="xyz"):

  • an assignment of "x" stores {'x'};
  • an assignment of "yxzz" is valid and stores {'y', 'x', 'z'}; and
  • an assignment of an empty iterable stores set().

An iterable that contains any disallowed member raises ValueError. A value that is not iterable, such as a bare integer, raises TypeError. Strings serve as iterable candidates rather than singleton values, so their individual characters are checked against sample_set.

Summary of required exceptions and compatibility

Unless a more specific rule is stated by a descriptor above, a Python type mismatch raises TypeError, while a value of an accepted structural type that violates a configured constraint raises ValueError. The non-real-component rule of Vector is intentionally ValueError. Validation always takes place before constant-write protection, and deletion of managed fields always raises AttributeError.

Task Specification: Adding Parameter and otherwise Support to the Type System

Goal

Extend the descriptor-based validation API found in ubermagutil.typesystem, which is importable as:

import ubermagutil.typesystem as ts

The module is required to keep exposing Descriptor, Typed, Scalar, Vector, Name, InSet, Subset, and typesystem, and must in addition expose the new Parameter descriptor. While the common otherwise fallback is being added, existing behavior and compatibility must be preserved.

A typical declaration looks like this:

@ts.typesystem(
    count=ts.Scalar(expected_type=int),
    direction=ts.Vector(size=3),
)
class DecoratedClass:
    def __init__(self, **kwargs):
        for key, value in kwargs.items():
            setattr(self, key, value)

The same validation rules must apply to assignments performed during construction and to assignments made later. When a descriptor does not explicitly transform a value, an accepted value is stored unchanged. A rejected assignment must not alter a previously stored valid value.

The decorator typesystem

ts.typesystem(**declarations) associates every keyword name with a class attribute placed under management.

  • A declaration may be written either as a descriptor instance, such as ts.Scalar(unsigned=True), or as a bare descriptor class, such as ts.Scalar, ts.Vector, or ts.Name.
  • A bare descriptor class can be used with its default options.
  • Supplying every managed attribute to the constructor of the decorated class is not required by the decorator, and omitted attributes are not implicitly initialized. An omitted attribute can be assigned later, and that assignment must then undergo normal validation.
  • A managed attribute always raises AttributeError on deletion, whether or not it has been assigned before.

As an example:

@ts.typesystem(value=ts.Scalar, name=ts.Name)
class Example:
    pass

obj = Example()
obj.value = 5       # valid even though value was initially omitted
del obj.name        # raises AttributeError even though name was never assigned

Behavior common to descriptors

Constant attributes

By default, descriptors support const=False. With const=True, the attribute is initialized by the first successful assignment, and a later assignment that is otherwise valid raises AttributeError.

For the ordinary descriptors that already exist, descriptor-specific validation happens before constant-write protection. Therefore, once a constant Vector has been initialized:

  • assigning a scalar instead of a supported vector container raises TypeError;
  • assigning a different valid vector gets as far as constant enforcement and raises AttributeError.

The new Parameter descriptor follows the stronger rule that is specified separately: every assignment made after its first successful assignment raises AttributeError, no matter whether the replacement value would otherwise be valid.

The otherwise fallback

Every descriptor must accept an optional otherwise keyword; this behavior is required in particular for Scalar, Vector, and Parameter. The keyword's value is a Python type, for example tuple or float. Matching of types uses isinstance.

For otherwise=T:

  1. The descriptor's primary validation is applied.
  2. If primary validation succeeds, the value is accepted with the descriptor's normal storage behavior.
  3. If primary validation fails while isinstance(value, T) is true, the fallback value is accepted and stored unchanged.
  4. If the value satisfies neither branch, it is rejected with TypeError.

The fallback acts as an alternative accepted type; it does not coerce or copy the value. The dictionary validation and error rules that are more specific to Parameter remain as described below.

Required examples include:

  • ts.Scalar(otherwise=tuple) accepts 1 via normal scalar validation and (1, 2, 1e5, 5) via the fallback; a string is rejected with TypeError.
  • ts.Vector(size=3, otherwise=float) accepts (1, 2, 3) via normal vector validation and 1.2 via the fallback. A string is rejected, and integer 5 is rejected with TypeError; for this isinstance check, an int is not a float.

Existing descriptors

Descriptor

Descriptor serves as the public base class of the descriptor family and stays usable for custom descriptors. It supplies managed-value storage, const enforcement, and protection against deletion. Custom validators can carry out their own type/value checks before the successful assignment is delegated to the base behavior.

Typed
ts.Typed(expected_type=..., const=False, otherwise=None)

Typed accepts a value if isinstance(value, expected_type) is true and stores that value unchanged. A mismatch raises TypeError. The check is subclass-aware, not an exact type(value) is expected_type comparison; for example, expected_type=numbers.Real accepts concrete integer and floating-point real values.

Scalar
ts.Scalar(
    expected_type=None,
    positive=None,
    unsigned=None,
    const=False,
    otherwise=None,
)

The primary validation rules for scalars are:

  1. The value must be an instance of numbers.Real; if it is not, raise TypeError.
  2. When expected_type is supplied, the value must satisfy isinstance(value, expected_type); if it does not, raise TypeError. Exact-type identity is not what is checked. In particular, expected_type=numbers.Real accepts an int as well as a float.
  3. When unsigned=True, the value must be greater than or equal to zero; a negative value raises ValueError. Setting unsigned=False disables this constraint.
  4. When positive=True, the value must be strictly greater than zero; zero or a negative value raises ValueError. Setting positive=False disables this constraint.

Type validation, including expected_type, happens before sign validation. Consequently, Scalar(expected_type=float, unsigned=True) rejects integer -1 with TypeError before its sign is considered. A valid scalar is stored unchanged.

Vector
ts.Vector(
    size=None,
    component_type=None,
    positive=None,
    unsigned=None,
    const=False,
    otherwise=None,
)

A primary vector value must be a list, tuple, or NumPy ndarray; rather than being converted, the accepted container itself is preserved. Validation then proceeds as follows:

  1. A value of an unsupported container kind raises TypeError.
  2. Each component must be an instance of numbers.Real. A supported container that contains a non-real component raises ValueError.
  3. When size is supplied, the container must have exactly that many components; a size mismatch raises ValueError.
  4. When component_type is supplied, every already-real component must satisfy isinstance(component, component_type). A real component that fails to match raises TypeError. For example, an integer component in a vector configured with component_type=float raises TypeError.
  5. When unsigned=True, every component must be greater than or equal to zero; a violation raises ValueError. Setting unsigned=False disables this constraint.
  6. When positive=True, every component must be strictly greater than zero; a violation raises ValueError. Setting positive=False disables this constraint.

Hence Vector(size=3) accepts (1, 2, 3) and rejects (1, 2) with ValueError; NumPy arrays are valid vector containers too. The distinction between a non-real component (ValueError) and a real component that fails component_type (TypeError) must be preserved.

Name
ts.Name(const=False, otherwise=None)

Name accepts strings that start with an alphabetic character or underscore and contain no embedded space. After a valid initial character, digits and a hyphen are permitted, so values such as a1, mesh, a1a, var_name, and var-name are valid.

  • A value that is not a string raises TypeError.
  • A string that starts with a digit or hyphen raises ValueError.
  • A string with an embedded space, such as val name, raises ValueError.

Name can be used either as a bare declaration (ts.Name) or as an instance, including ts.Name(const=True).

InSet
ts.InSet(allowed_values=..., const=False, otherwise=None)

InSet accepts a value and stores it unchanged when the value is a member of allowed_values. A non-member raises ValueError. Normal constant-attribute behavior is supported. For example, with allowed_values=[1, 2, '5'], both 1 and '5' are valid while -1 is not.

Subset
ts.Subset(sample_set=..., const=False, otherwise=None)

The value assigned must be iterable, and all of its elements must belong to sample_set.

  • An empty iterable is valid.
  • Elements that repeat are valid.
  • When the assignment succeeds, the distinct assigned elements are stored as a set. Assigning 'x' therefore stores {'x'}, and assigning 'yxzz' stores {'y', 'x', 'z'}.
  • An iterable that contains an element outside sample_set raises ValueError.
  • A value that is not iterable raises TypeError.
  • Constant behavior is likewise supported.

With Subset(sample_set='xyz'), values such as [], 'x', 'yx', and 'yxzz' are valid, while 'a' and [1] raise ValueError.

The new Parameter descriptor

Public construction
ts.Parameter(descriptor=<descriptor instance>, const=False, otherwise=None)
  • descriptor receives an instance of another descriptor, such as ts.Scalar(...) or ts.Vector(...), and that instance defines the validation applied to each individual parameter value.
  • One-time assignment is controlled by const, as described below.
  • The alternative accepted type described above is supplied via otherwise.

Parameter must be publicly importable as ubermagutil.typesystem.Parameter.

Accepted values and the order of validation

An assignment is accepted via one of the following forms:

  1. A single value for the wrapped descriptor. The assigned value is validated directly with descriptor; if it is valid, it is stored unchanged.
  2. A dictionary of named values. When the assigned value is a dictionary rather than a valid single value, all of the following are required:
    • The dictionary must be non-empty; an empty dictionary raises ValueError.
    • Every key must be a string with no whitespace; a non-string key or a key containing whitespace raises ValueError.
    • Every dictionary value must independently satisfy the wrapped descriptor. A wrapped type mismatch raises TypeError; a wrapped violation of range, sign, or size raises ValueError.
    • A dictionary that is valid is stored unchanged.
  3. The fallback value. If neither the single-value form nor the dictionary form accepts the value and otherwise=T was supplied, isinstance(value, T) accepts the value and stores it unchanged.

For a dictionary assignment, empty-dictionary validation takes place before entry validation. Invalid keys and invalid values keep the error categories listed above, and malformed dictionaries are not stored partially. For a non-dictionary that is not accepted by otherwise, the wrapped descriptor's normal distinction between TypeError and ValueError must be preserved. After every failed assignment, the previous value remains unchanged.

Parameter values that are constant

With const=True, the first successful assignment is accepted. Every later assignment raises AttributeError, including a later assignment made with an invalid value. This unconditional reassignment rule applies specifically to Parameter.

ts.Scalar

It must be possible to use Scalar as a bare declaration (ts.Scalar), as ts.Scalar(), or with the keyword options expected_type, positive, unsigned, const, and otherwise.

The normal scalar route of Scalar accepts values that satisfy isinstance(value, numbers.Real) and stores them unchanged. That route is refined by the options as follows:

  • expected_type=T additionally requires that isinstance(value, T) hold. A failure raises TypeError.
  • With positive=True, value > 0 is required; values that are zero or negative raise ValueError. positive=False imposes no positivity constraint.
  • With unsigned=True, value >= 0 is required; negative values raise ValueError. unsigned=False imposes no unsigned constraint.
  • otherwise=T adds an alternative route: any value that satisfies isinstance(value, T) is accepted unchanged and does not have to satisfy the normal scalar constraints. As an example, ts.Scalar(otherwise=tuple) accepts both ordinary real scalars and tuples.

ts.Vector

It must be possible to use Vector as a bare declaration (ts.Vector), as ts.Vector(), or with the keyword options size, component_type, positive, unsigned, const, and otherwise.

The normal vector route accepts values of type list, tuple, or numpy.ndarray whose components are real numbers. Accepted values keep their original container type and contents; they are not converted to another vector representation. The externally observable behavior of validation is the following:

  • If the value is not a list, tuple, or NumPy array, TypeError is raised.
  • If any component is not a numbers.Real, TypeError is raised. In particular, assigning ["a", 1, 3] raises TypeError, not ValueError.
  • size=n requires exactly n components. When the length is wrong, ValueError is raised.
  • component_type=T requires every component to satisfy isinstance(component, T). A component that is real but of the wrong configured type raises TypeError.
  • With positive=True, every component is required to be greater than zero; a violation raises ValueError. positive=False disables this constraint.
  • With unsigned=True, every component is required to be greater than or equal to zero; a violation raises ValueError. unsigned=False disables this constraint.
  • otherwise=T adds an alternative accepted type that bypasses the normal vector validation.
