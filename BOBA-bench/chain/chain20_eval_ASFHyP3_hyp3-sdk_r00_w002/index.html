Required API

  • The hyp3_sdk package must publicly export a class named HyP3.
  • HyP3 must be constructible with no arguments:
    api = HyP3()
  • Instances must expose a url attribute containing the API base URL.
  • Instances must provide:
    api.find_jobs()

Required find_jobs behavior

Calling HyP3.find_jobs() must retrieve every page of jobs:

  1. Send the initial request to the /jobs endpoint without a next query parameter.
  2. Read job records from the response’s "jobs" list.
  3. If the response contains a "next" URL, request that URL. Its query parameters, including next, must be included in the subsequent request.
  4. Continue until a response does not contain "next".
  5. Return one batch containing jobs from all retrieved pages.

For example, if the first response contains two jobs and a "next" URL ending in /jobs?next=foobar, and the following response contains one job with no "next" value, the returned batch must have length 3. The first request must not contain a next parameter, while the second must contain it.

11 Job Class Refactor 1013 words · rewritten by GPT-5.6-sol

Task Specification: Job Class Refactor

Overview

Refactor the existing Job class so that it has a consistent, fixed attribute model, can be constructed from a job dictionary, and can serialize either a complete job dictionary or a resubmission payload. Job must remain importable as Job from hyp3_sdk.jobs and through the existing package-level export.

This work must preserve the surrounding Job API. In particular, timestamp conversion must remain compatible with expiration checks and product downloads.

Required Public API

Job.from_dict(data: dict) -> Job

Provide a class-level constructor that returns a new Job for each call. For every key in a valid input dictionary:

  • the returned object must expose an attribute of the same name through normal Python attribute access, including getattr(job, key) and job.__getattribute__(key);
  • the attribute must represent the supplied value; and
  • except for the timestamp conversion documented below, the value must be preserved unchanged.

Valid job dictionaries in this contract contain truthy values for the keys they supply. Those values, including nested dictionaries and lists, must retain their content.

The class has a fixed set of known job attributes rather than creating only the attributes present in one response. Consequently:

  • vars(job).keys() must be a superset of data.keys();
  • every known instance attribute that was not supplied in data must still be present in vars(job), with the value None exactly rather than another falsy sentinel such as 0, False, or an empty string; and
  • a job's available attributes must not depend on whether the job is running, failed, or succeeded. No valid input field may be discarded merely because it is associated with a particular job state.

Distinct calls must produce independent instances. Populating or later changing one job must not alter another job's attributes or serialization.

ISO-8601 expiration timestamps

A nonempty ISO-8601 expiration_time supplied in data is a timestamp, not an opaque string. from_dict must interpret it as a datetime-compatible value with the timezone semantics required for comparison with the current time. This in-memory conversion is the exception to retaining the literal supplied value as the instance attribute.

The converted value must preserve the existing expiration behavior:

  • job.expired() can compare it with the current time and reports future and past expiration times correctly;
  • a successful, unexpired job created from a service dictionary can proceed through job.download_files();
  • an expired job continues to be rejected by that operation; and
  • neither operation may fail merely because expiration_time originally arrived as an ISO-8601 string.

If expiration_time is absent or has no value, the corresponding known attribute remains None, and the existing behavior for a job without an expiration timestamp remains unchanged.

Job.to_dict(for_resubmit: bool = False) -> dict

Serialize the job to an ordinary dictionary without mutating the instance.

Default mode: for_resubmit=False

For a job created with Job.from_dict(data), the default result must equal data exactly:

  • every supplied key is included;
  • all non-timestamp values are returned unchanged;
  • known attributes that remained None because they were absent from data are omitted; and
  • no bookkeeping fields or additional defaulted fields are added.

More generally, default serialization includes every populated known job attribute and omits known attributes whose value is None.

Datetime-valued timestamp attributes must be converted to their ISO-8601 dictionary representation. In particular, a parsed expiration_time must serialize back to the corresponding ISO-8601 value, so canonical service dictionaries round-trip through from_dict and to_dict without changing their public representation. Existing datetime serialization conventions, including second precision where applicable, must remain compatible.

Resubmission mode: for_resubmit=True

Resubmission uses whitelist semantics. The result must contain only populated attributes whose names are members of Job._attributes_for_resubmit; the set does not name attributes to remove.

For any valid input dictionary data, the keys in the resubmission result must be exactly:

set(data) & Job._attributes_for_resubmit

Accordingly:

  • a supplied key that belongs to _attributes_for_resubmit is retained with its original public dictionary value;
  • every supplied key that does not belong to the set is absent, even when its instance value is truthy;
  • an allowed known attribute that was not supplied and therefore remains None is not added; and
  • no other keys may appear.

Calling this mode must not clear or modify excluded attributes. Immediately afterward, every key originally supplied to from_dict must still be readable on the instance and retain its value, subject only to the documented in-memory timestamp representation.

Job._attributes_for_resubmit

Expose _attributes_for_resubmit as a class-level set of plain attribute-name strings. It must support normal set behavior, including membership checks and set difference with a set of dictionary key strings.

The set must be a proper subset of the attributes a job may carry, allowing populated job-definition fields to be retained while job state and result metadata are excluded. Normal valid job dictionaries must contain eligible job-definition fields so that resubmission retains those fields. Membership and the class's fixed attribute schema must be internally consistent with the exact-intersection rule above.

The individual field names and exact membership are defined by the Job schema. Callers must not need separate class-level registries partitioned by job outcome; _attributes_for_resubmit is the only class-level field registry required by this refactor.

Attribute and Serialization Invariants

The following requirements apply together:

  1. Every valid input key is available through standard attribute access.
  2. Every class-defined instance attribute omitted from the input is exactly None in vars(job).
  3. Default serialization omits those None defaults and recreates the complete input dictionary.
  4. Resubmission serialization emits exactly the populated input keys allowed by _attributes_for_resubmit.
  5. Neither serialization mode mutates the instance.
  6. Timestamp parsing is internal to the object model; dictionary output remains ISO-8601 and expiration-dependent operations receive a comparable timestamp.
  7. No non-None per-instance bookkeeping may leak into vars(job) as an additional attribute that was absent from the construction dictionary.

Scope

This is a behavioral refactor of Job, not a redesign of batches, submission clients, status helpers, expiration checks, or downloading. Existing consumers of Job.from_dict, Job.to_dict, expired(), and download_files() must continue to work with the representations described above. No particular internal organization is required as long as all public behavior and invariants are satisfied.
