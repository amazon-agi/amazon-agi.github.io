Task Specification: SUSE Migration Services — System Mounting Feature

Overview

Implement a Python package called suse_migration_services whose functionality covers parsing fstab files and discovering and mounting an existing (to-be-upgraded) system onto a fixed mount root. 1. suse_migration_services.version

2. suse_migration_services.fstab.Fstab

A class for reading and interpreting an fstab file.

Constructor
Fstab(fstab_path)
  • fstab_path: path of an fstab file, which is read and parsed when the instance is constructed.
Format of the fstab file

Within each non-empty line, columns are separated by whitespace; the columns of interest are:

  1. device specification (column 1)
  2. mountpoint (column 2)
  3. filesystem type (column 3)
  4. mount options (column 4)

The device specification may take one of the forms below, and it must be translated into a device path in the following way:

  • UUID=<value> → /dev/disk/by-uuid/<value>
  • LABEL=<value> → /dev/disk/by-label/<value>
  • an already-absolute device node path (for example /dev/mynode) → used verbatim
Method
get_devices()

Returns a list holding one entry per fstab line, in the same order as the lines appear in the file. Every entry must be a collections.namedtuple with the type name fstab_entry_type and exactly these fields, in this order:

namedtuple('fstab_entry_type', ['mountpoint', 'device', 'options'])
  • mountpoint: the mountpoint column (column 2), taken verbatim (for example /, swap, /boot/efi, /home, /foo).
  • device: the device path after translation (see the rules above).
  • options: the mount options column (column 4), verbatim.

The swap entry is part of the returned list in the same way as any other entry (it is not filtered out here).

6. suse_migration_services.units.mount_system

The module must import and use:

  • Command (via suse_migration_services.command.Command), calling Command.run(...).
  • Path (a helper that provides a Path.create(path) static/class method), referenced within this module such that suse_migration_services.units.mount_system.Path resolves to it. Path.create(path) is expected to create a directory path.
  • Fstab (referenced as suse_migration_services.units.mount_system.Fstab).
  • Defaults.
  • os.path.exists.

The module must expose two public functions:

main()

Coordinates discovering and mounting the system to be upgraded. Behavior:

  1. Ensure that the system root directory exists. Call Path.create('/system-root').

  2. Check if something is already mounted at the system root. Run:

    Command.run(['mountpoint', '-q', '/system-root'], raise_on_error=False)

    If the returned object has returncode == 0 (that is, the system root is already a mountpoint), stop: no further actions are performed. In this early-return case, the only side effects are the Path.create('/system-root') call and the mountpoint check.

  3. Enumerate block partitions. Run:

    Command.run(['lsblk', '-p', '-n', '-r', '-o', 'NAME,TYPE'])

    The command's output is text; every line describes a block device as NAME TYPE. Consider only the entries whose type is part, extracting the device NAME (first field).

  4. Find the system to upgrade. For each partition device that was found (in the order reported by lsblk):

    • Try to mount it at the system root:
      Command.run(['mount', <device>, '/system-root'], raise_on_error=False)
    • Check whether an fstab file is present on the mounted partition by testing os.path.exists for the fstab file located at /system-root/etc/fstab.
    • Afterwards, unmount the probe mount:
      Command.run(['umount', '/system-root'], raise_on_error=False)
    • The first partition that contains an fstab file is selected as the system to upgrade. Once such a partition is identified, the device probing stops.

  5. If no partition contains an fstab file, raise DistMigrationSystemNotFoundException.

  6. Mount the discovered system. Build an Fstab from the fstab file found on the selected partition and call mount_system(Defaults.get_system_root_path(), <fstab>) (see below).

For a successful run in which a partition /dev/sda1 is found and its fstab is the reference fstab, the resulting sequence of Command.run calls is:

['mountpoint', '-q', '/system-root']            (raise_on_error=False)
['lsblk', '-p', '-n', '-r', '-o', 'NAME,TYPE']
['mount', '/dev/sda1', '/system-root']          (raise_on_error=False)
['umount', '/system-root']                       (raise_on_error=False)
# followed by the mount_system calls (see below)
mount_system(root_path, fstab)

Mounts every filesystem described by the given Fstab under the given root_path. Behavior:

  1. Iterate over the fstab entries (as returned by fstab.get_devices()) in order and mount each real filesystem. Swap entries are skipped (an entry whose mountpoint is swap is not mounted).

  2. For each mounted entry, the target directory is computed by appending the entry's mountpoint to root_path, applying the following rule:

    • The root mountpoint / yields target <root_path>/ (a trailing slash, for example /system-root/).
    • A mountpoint like /boot/efi yields <root_path>/boot/efi.
    • A mountpoint like /home yields <root_path>/home.
    • A mountpoint like /foo yields <root_path>/foo.

  3. Mount each entry with:

    Command.run(['mount', '-o', <options>, <device>, <target>])

    using the entry's options and its translated device.

    For the reference fstab (root_path /system-root), the mount calls, in order, are:

    ['mount', '-o', 'acl,user_xattr', '/dev/disk/by-uuid/bd604632-663b-4d4c-b5b0-8d8686267ea2', '/system-root/']
['mount', '-o', 'defaults', '/dev/disk/by-uuid/FCF7-B051', '/system-root/boot/efi']
['mount', '-o', 'defaults', '/dev/disk/by-label/foo', '/system-root/home']
['mount', '-o', 'defaults', '/dev/mynode', '/system-root/foo']

    (The swap entry is not mounted.)

  4. Error handling / rollback: If any mount raises an exception, all previously successful mounts within this call must be unmounted in reverse order, after which a DistMigrationSystemMountException must be raised.

    For example, if mounting /system-root/home fails after /system-root/ and /system-root/boot/efi have succeeded, the complete call sequence is:

    ['mount', '-o', 'acl,user_xattr', '/dev/disk/by-uuid/bd604632-663b-4d4c-b5b0-8d8686267ea2', '/system-root/']
['mount', '-o', 'defaults', '/dev/disk/by-uuid/FCF7-B051', '/system-root/boot/efi']
['mount', '-o', 'defaults', '/dev/disk/by-label/foo', '/system-root/home']   # raises
['umount', '/system-root/boot/efi']
['umount', '/system-root/']

    that is, the mounts that succeeded (/system-root/ and /system-root/boot/efi) are unmounted in reverse order, and DistMigrationSystemMountException is raised.

Notes on the reference fstab that determines the behavior

The reference fstab consists of these lines (device spec / mountpoint / type / options):

UUID=bd604632-663b-4d4c-b5b0-8d8686267ea2  /          ext4  acl,user_xattr  0  1
UUID=daa5a8c3-5c72-4343-a1d4-bb74ec4e586e  swap       swap  defaults        0  0
UUID=FCF7-B051                             /boot/efi  vfat  defaults        0  0
LABEL=foo                                  /home      ext4  defaults        0  0
/dev/mynode                                /foo       ext4  defaults        0  0

This fstab drives the expected device translations, ordering, and swap-skipping behavior described above.

Task Description

Summary

Rework the mount-path handling of the migration services so that all mount metadata goes through a shared Fstab abstraction, while mounted locations are recorded in a single central metadata file, /etc/system-root.fstab. A cleanup unit then reads that file back and unmounts everything.

The components described below must be implemented/modified so that they can be imported and behave exactly as specified.

1. The Fstab class — suse_migration_services/fstab.py

A class Fstab must be provided with the following public surface.

Instance construction
  • Fstab() — takes no arguments at construction time. An instance that has just been constructed contains an empty list of entries.
Data type of an entry
  • The class must expose an attribute fstab_entry_type; this attribute is a named-tuple type with exactly the fields fstype, mountpoint, device, options, in this order.
read(self, filename)
  • Parses the fstab-format file at filename and fills the instance's entries from it.
  • Every relevant line consists of whitespace-separated columns: device mountpoint fstype options <dump> <pass>.
  • Each line is parsed into an fstab_entry_type instance where:
    • device = column 1
    • mountpoint = column 2
    • fstype = column 3
    • options = column 4
  • Any entry whose fstype is swap must be skipped (not stored).
  • Stored entries keep their file order (with skipped swap entries excluded).
add_entry(self, device, mountpoint, fstype='none')
  • Builds a new entry from the supplied device, mountpoint, and fstype, and appends it.
  • When fstype is not supplied, it defaults to 'none'.
  • The options field of an added entry is always the literal string 'defaults'.
get_devices(self)
  • Returns the stored fstab_entry_type instances as a list, in the order they are stored.
export(self, filename)
  • Opens filename for writing with mode 'w', inside a context manager (with open(...)).
  • For every stored entry, one line of the form "{device} {mountpoint} {fstype} {options} 0 0" is written.
  • Each entry goes out through a single write call with exactly the string shown above (that call adds no additional trailing newline). The entries are written in stored order.

2. Unit for mounting the system — suse_migration_services/units/mount_system.py

The module must import Fstab from suse_migration_services.fstab (referenceable as suse_migration_services.units.mount_system.Fstab).

The function mount_system(root_path, fstab)

Given a target root path together with an Fstab instance:

  • Walk over fstab.get_devices() and, for each entry, mount the entry's device at the location created by joining root_path with the entry's mountpoint.
  • The mount happens by running a command of the form: ['mount', <device>, <root_path + mountpoint>]
  • If a mount fails, raise DistMigrationSystemMountException (from suse_migration_services.exceptions).

For an input fstab with these entries (device → mountpoint):

  • /dev/disk/by-uuid/bd604632-663b-4d4c-b5b0-8d8686267ea2 → /
  • /dev/disk/by-uuid/FCF7-B051 → /boot/efi
  • /dev/disk/by-label/foo → /home
  • /dev/mynode → /foo

and root_path = /system-root, the mount commands that result are, in order:

  • ['mount', '/dev/disk/by-uuid/bd604632-663b-4d4c-b5b0-8d8686267ea2', '/system-root/']
  • ['mount', '/dev/disk/by-uuid/FCF7-B051', '/system-root/boot/efi']
  • ['mount', '/dev/disk/by-label/foo', '/system-root/home']
  • ['mount', '/dev/mynode', '/system-root/foo']

(Further discovery/preparation commands may come before these, matching the existing unit's device-detection behavior; the mount ordering above is what matters.)

Recording the mounted locations

Within the module's overall flow (the main-level operation that constructs an Fstab, reads the system fstab, and mounts it), after each device has been mounted successfully the module must record every mounted location into a new Fstab metadata object and export it. Concretely, for every mounted entry it must call add_entry with three positional arguments in this order: the entry's device, the joined mount path (root_path + mountpoint), and the entry's fstype. In the example above, these calls are:

  • add_entry('/dev/disk/by-uuid/bd604632-663b-4d4c-b5b0-8d8686267ea2', '/system-root/', 'ext4')
  • add_entry('/dev/disk/by-uuid/FCF7-B051', '/system-root/boot/efi', 'vfat')
  • add_entry('/dev/disk/by-label/foo', '/system-root/home', 'ext4')
  • add_entry('/dev/mynode', '/system-root/foo', 'ext4')

As the final step, the metadata must be exported by calling export('/etc/system-root.fstab') exactly once.
