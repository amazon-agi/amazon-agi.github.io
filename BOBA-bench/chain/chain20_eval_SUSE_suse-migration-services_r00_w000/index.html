2. suse_migration_services.fstab.Fstab

A class to read and interpret an fstab file.

Constructor
Fstab(fstab_path)
  • fstab_path: path to an fstab file that is read and parsed at construction time.
fstab file format

Each non-empty line has whitespace-separated columns, where the columns of interest are:

  1. device specification (column 1)
  2. mountpoint (column 2)
  3. filesystem type (column 3)
  4. mount options (column 4)

The device specification may be given in one of these forms, and must be translated into a device path as follows:

  • UUID=<value> → /dev/disk/by-uuid/<value>
  • LABEL=<value> → /dev/disk/by-label/<value>
  • an already-absolute device node path (e.g. /dev/mynode) → used verbatim
Method
get_devices()

Returns a list of entries, one per fstab line, in the same order as they appear in the file. Each entry must be a collections.namedtuple with type name fstab_entry_type and exactly these fields, in this order:

namedtuple('fstab_entry_type', ['mountpoint', 'device', 'options'])
  • mountpoint: the mountpoint column (column 2), taken verbatim (e.g. /, swap, /boot/efi, /home, /foo).
  • device: the translated device path (see rules above).
  • options: the mount options column (column 4), verbatim.

The swap entry is included in the returned list like any other entry (it is not filtered out here).

6. suse_migration_services.units.mount_system

This module must import and use:

  • Command (via suse_migration_services.command.Command), calling Command.run(...).
  • Path (a helper providing a Path.create(path) static/class method), referenced within this module such that suse_migration_services.units.mount_system.Path resolves to it. Path.create(path) is expected to create a directory path.
  • Fstab (referenced as suse_migration_services.units.mount_system.Fstab).
  • Defaults.
  • os.path.exists.

It must expose two public functions:

main()

Orchestrates discovery and mounting of the system to be upgraded. Behavior:

  1. Ensure the system root directory exists. Call Path.create('/system-root').

  2. Check whether something is already mounted at the system root. Run:

    Command.run(['mountpoint', '-q', '/system-root'], raise_on_error=False)

    If the returned object has returncode == 0 (i.e. the system root is already a mountpoint), stop: perform no further actions. In this early-return case, the only side effect is the Path.create('/system-root') call and the mountpoint check.

  3. Enumerate block partitions. Run:

    Command.run(['lsblk', '-p', '-n', '-r', '-o', 'NAME,TYPE'])

    The command output is text; each line describes a block device as NAME TYPE. Consider only entries whose type is part, extracting the device NAME (first field).

  4. Find the system to upgrade. For each partition device found (in the order reported by lsblk):

    • Attempt to mount it at the system root:
      Command.run(['mount', <device>, '/system-root'], raise_on_error=False)
    • Check for the presence of an fstab file on the mounted partition by testing os.path.exists for the fstab file located at /system-root/etc/fstab.
    • Then unmount the probe mount:
      Command.run(['umount', '/system-root'], raise_on_error=False)
    • The first partition that contains an fstab file is selected as the system to upgrade. The device probing stops once such a partition is identified.

  5. If no partition contains an fstab file, raise DistMigrationSystemNotFoundException.

  6. Mount the discovered system. Construct an Fstab from the fstab file found on the selected partition and call mount_system(Defaults.get_system_root_path(), <fstab>) (see below).

The resulting sequence of Command.run calls for a successful run where a partition /dev/sda1 is found and its fstab is the reference fstab is:

['mountpoint', '-q', '/system-root']            (raise_on_error=False)
['lsblk', '-p', '-n', '-r', '-o', 'NAME,TYPE']
['mount', '/dev/sda1', '/system-root']          (raise_on_error=False)
['umount', '/system-root']                       (raise_on_error=False)
# followed by the mount_system calls (see below)
mount_system(root_path, fstab)

Mounts each filesystem described by the given Fstab under the given root_path. Behavior:

  1. Iterate the fstab entries (as returned by fstab.get_devices()) in order, and mount each real filesystem. Swap entries are skipped (entries whose mountpoint is swap are not mounted).

  2. For each mounted entry, compute the target directory by appending the entry's mountpoint to root_path with the following rule:

    • The root mountpoint / yields target <root_path>/ (a trailing slash, e.g. /system-root/).
    • A mountpoint like /boot/efi yields <root_path>/boot/efi.
    • A mountpoint like /home yields <root_path>/home.
    • A mountpoint like /foo yields <root_path>/foo.

  3. Mount each entry with:

    Command.run(['mount', '-o', <options>, <device>, <target>])

    using the entry's options and translated device.

    For the reference fstab (root_path /system-root), the mount calls in order are:

    ['mount', '-o', 'acl,user_xattr', '/dev/disk/by-uuid/bd604632-663b-4d4c-b5b0-8d8686267ea2', '/system-root/']
['mount', '-o', 'defaults', '/dev/disk/by-uuid/FCF7-B051', '/system-root/boot/efi']
['mount', '-o', 'defaults', '/dev/disk/by-label/foo', '/system-root/home']
['mount', '-o', 'defaults', '/dev/mynode', '/system-root/foo']

    (The swap entry is not mounted.)

  4. Error handling / rollback: If any mount raises an exception, all previously successful mounts within this call must be unmounted in reverse order, then a DistMigrationSystemMountException must be raised.

    For example, if mounting /system-root/home fails after /system-root/ and /system-root/boot/efi succeeded, the full call sequence is:

    ['mount', '-o', 'acl,user_xattr', '/dev/disk/by-uuid/bd604632-663b-4d4c-b5b0-8d8686267ea2', '/system-root/']
['mount', '-o', 'defaults', '/dev/disk/by-uuid/FCF7-B051', '/system-root/boot/efi']
['mount', '-o', 'defaults', '/dev/disk/by-label/foo', '/system-root/home']   # raises
['umount', '/system-root/boot/efi']
['umount', '/system-root/']

    i.e. the mounts that succeeded (/system-root/ and /system-root/boot/efi) are unmounted in reverse order, and DistMigrationSystemMountException is raised.

Notes on the reference fstab used for behavior

The reference fstab has these lines (device spec / mountpoint / type / options):

UUID=bd604632-663b-4d4c-b5b0-8d8686267ea2  /          ext4  acl,user_xattr  0  1
UUID=daa5a8c3-5c72-4343-a1d4-bb74ec4e586e  swap       swap  defaults        0  0
UUID=FCF7-B051                             /boot/efi  vfat  defaults        0  0
LABEL=foo                                  /home      ext4  defaults        0  0
/dev/mynode                                /foo       ext4  defaults        0  0

This drives the expected device translations, ordering, and swap-skipping behavior described above.
