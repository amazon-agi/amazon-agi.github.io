Class: Polynomial

Constructor

The constructor supports both of these forms:

  • Polynomial(coeffs), where coeffs is one iterable of coefficients.
  • Polynomial(c1, c2, ..., cn), where the coefficients are supplied as separate positional arguments.

In either form, coefficients are given in descending order of degree: the first coefficient corresponds to the highest-degree term and the last coefficient corresponds to the constant term (degree 0). When a single iterable is supplied, it is expanded as the coefficient sequence; for example, a string is treated as an iterable of character coefficients.

Supplying coefficients separately must construct the same polynomial as supplying the corresponding iterable. This equivalence applies to integer, float, complex, and arbitrary-object coefficients, including character strings. For example:

  • Polynomial([1, 2, 3]) is equal to Polynomial(1, 2, 3).
  • Polynomial("abc") is equal to Polynomial("a", "b", "c").

Coefficients may be integers, floats, complex numbers, or, for formatting purposes, arbitrary objects such as single-character strings.

Equality

Polynomial objects must support value-based equality. Two instances that represent the same coefficient value at every degree compare equal; equality must not depend on object identity. In particular, the single-iterable and separate-positional constructor forms described above must compare equal when given the same coefficient sequence. Ordinary coefficient equality determines whether corresponding coefficient values match.

Class: ZeroPolynomial

ZeroPolynomial() constructs a polynomial with no terms: the zero polynomial. It takes no arguments.

Required Behavior: str(...) (Human-Readable Form)

str(polynomial) must produce a human-readable representation according to the following rules.

Term Construction

Associate each coefficient with its degree based on its position, with the coefficients ordered from highest degree to degree 0. Construct each displayed term as follows.

Variable and Power
  • Degree 0 (the constant term): display no variable or power; display only the coefficient.
  • Degree 1: append x, never x^1.
  • Degree 2 or greater: append x^ followed by the degree, such as x^2 or x^5.
Coefficient Display
  • A coefficient equal to 1 is omitted from a nonconstant term. Thus a degree-2 term with coefficient 1 is x^2, and a degree-1 term with coefficient 1 is x.
  • A coefficient equal to 1 remains visible for the constant term, which renders as 1.
  • Other coefficients use their normal textual form and are placed directly before the variable part.
  • Complex coefficients are enclosed in parentheses, for example (-69-420j)x^2.
Term Omission

Terms with a numeric coefficient equal to 0 are omitted entirely.

Joining Terms and Signs

Display terms from highest degree to lowest degree.

  • Separate displayed terms with + when the following coefficient is non-negative.
  • For a negative real numeric coefficient, use - instead. Display the following coefficient by its absolute value so that its minus sign is not duplicated. In particular, a nonconstant coefficient of -1 is displayed as a minus sign followed by only the variable and power.
  • If the first displayed term has a negative coefficient, put a short minus directly before the term, such as -x^2 or -2x^5, and display the coefficient magnitude after that sign.
  • A non-negative leading term has no leading sign.

For non-numeric coefficients such as single-character strings, numeric zero omission, unit-coefficient suppression, and numeric sign handling do not apply. Such coefficients are ordinary prefixes, and their terms are joined with +. Coefficient magnitudes used for numeric sign handling use standard absolute-value behavior.

Examples:

  • Polynomial([0, 0, -2, 0, 4.6666666666, -(69+420j), -1, 1337]) renders as -2x^5 + 4.6666666666x^3 + (-69-420j)x^2 - x + 1337.

  • Polynomial([2, 0]) renders as 2x.
  • Polynomial([2]) renders as 2.
  • Polynomial([1, 2]) renders as x + 2.
  • Polynomial([1, 0, 1]) renders as x^2 + 1.
  • Polynomial([-1, 0, 2]) renders as -x^2 + 2.
  • Polynomial("abcdef") renders as ax^5 + bx^4 + cx^3 + dx^2 + ex + f.
Zero Polynomial
  • str(ZeroPolynomial()) returns "0".
  • More generally, any polynomial with no displayable non-zero terms renders as "0".

Required Behavior: repr(...) (Reconstructable Form)

repr(polynomial) must produce a string representing an equivalent polynomial as a call to the Polynomial constructor. Its coefficients are separate positional arguments in descending degree order, and leading zero-coefficient terms are stripped.

  • The output has the form Polynomial(<c1>, <c2>, ..., <cn>).
  • Each <ci> uses that coefficient's standard representation. Complex values therefore appear in forms such as (-69-420j).
  • Leading coefficients equal to 0 are removed, so the first argument corresponds to the highest-degree non-zero term.
  • Interior and trailing zero coefficients are preserved because they represent missing terms at degrees below the polynomial's highest degree.

For example:

  • repr(Polynomial([0, 0, -2, 0, 4.6666666666, -(69+420j), -1, 1337])) returns "Polynomial(-2, 0, 4.6666666666, (-69-420j), -1, 1337)".

Numeric special cases—zero omission, unit-coefficient suppression, and negativity handling—apply only to numeric coefficients. Formatting must remain compatible with arbitrary non-numeric coefficient objects as described above.

  • __irshift__(self, n) for p >>= n.

The shift amount n is an integer and may be positive, negative, or zero. For every term coefficient * x**degree:

  • p << n maps its degree to degree + n.
  • p >> n maps its degree to degree - n.
  • A negative amount reverses direction: p << -n has the value of p >> n, and p >> -n has the value of p << n.
  • Shifting by zero produces a new value equal to the original. Augmented assignment by zero likewise preserves the value.

Polynomial(1, 3, 5) >> 3   == Polynomial()
Polynomial(1, 3, 5) >> -1  == Polynomial(1, 3, 5, 0)

Monomial(1, 5) << 10    == Monomial(1, 15)
Monomial(1, 15) << -10  == Monomial(1, 5)
Monomial(1, 5) >> -10   == Monomial(1, 15)
Monomial(1, 15) >> 10   == Monomial(1, 5)
Constant(5) << 10       == Monomial(5, 10)

Monomial(1, 10) << -15  == ZeroPolynomial()

assert c1 == Monomial(5, 5)

Monomial(1, 10) >> 15   == ZeroPolynomial()
Monomial(1, 10) << -15  == ZeroPolynomial()

A shift exactly down to degree zero remains a Monomial at degree zero.

Constant and zero behavior

A constant behaves as a monomial at degree zero. An upward shift therefore produces a Monomial:

Constant(5) << 10  == Monomial(5, 10)

The equivalent negative right shift has the same effect. A downward shift past degree zero produces ZeroPolynomial(). A zero shift remains equal to the original constant. Shifting a ZeroPolynomial by any amount leaves a ZeroPolynomial value.

Result categories and augmented assignment

The constructor categories shown above are required, not merely mathematical equivalence:

  • A shifted general Polynomial remains a general Polynomial, including when all terms are removed.
  • A surviving shifted Monomial is a Monomial.
  • A monomial shifted below degree zero is a ZeroPolynomial.
  • A constant shifted upward is a Monomial.

The result must have the same normalized coefficients, degree, terms, monomials, str, and repr as the indicated target object.

<<= and >>= must produce the same resulting values as << and >>. Constant and ZeroPolynomial are immutable-valued for augmented shifts: augmented assignment must return a new object rather than modifying an aliased original. For example:

c = Constant(5)
c1 = c
c1 <<= 5
assert c1 is not c

z = ZeroPolynomial()
z1 = z
z1 <<= 5
assert z1 is not z

The same non-mutating rebinding rule applies to both augmented shift directions.

Calculus operations

The derivative property applies the ordinary power rule to every term. For example:

Polynomial(1, 2, 3).derivative == Polynomial(2, 2)

The derivative of a constant or any zero representation is ZeroPolynomial().

nth_derivative(n) returns the value obtained by differentiating n times:

  • n=0 returns an equal, unchanged copy.
  • Positive orders apply the repeated power rule.
  • Once n exceeds the polynomial's degree, the result is ZeroPolynomial().
  • n must be a non-negative integer; invalid orders raise ValueError.

Equality, numeric conversion, and membership

Equality

Equality and inequality compare normalized polynomial values, and != must be the logical opposite of ==. Leading-zero construction differences do not affect equality. All zero forms compare equal:

Polynomial() == ZeroPolynomial() == Constant(0) == 0
Polynomial() == 0.0
Polynomial() == 0j

A nonzero polynomial does not compare equal to numeric zero.

A Constant exposes its stored value through const, compares equal to the corresponding numeric value, and supports matching conversions through int(), float(), and complex(). Thus Constant(69).const == int(Constant(69)) == 69, with analogous float and complex behavior.

ZeroPolynomial.const always returns numeric 0. It is read-only; assigning to it must raise AttributeError.

Membership

item in polynomial performs exact term containment. The accepted item forms are:

  • one (coefficient, degree) tuple;
  • a list of such tuples;
  • a set of such tuples; or
  • another polynomial.

A collection or polynomial is contained exactly when every one of its complete coefficient-degree pairs occurs in the receiving polynomial. Subsets of terms are allowed, but a matching coefficient at the wrong degree, a matching degree with the wrong coefficient, or an otherwise partial pair is not a match. For example, Polynomial(1, 2, 3) is contained in Polynomial(6, 5, 4, 1, 2, 3), while adding a trailing zero to shift all three degrees changes the terms and prevents containment in either direction. Unsupported membership item types raise ValueError.

Arithmetic compatibility

Addition, subtraction, and multiplication

Addition and subtraction align coefficients by degree. Multiplication performs ordinary coefficient convolution. Each operation supports another polynomial or an int, float, or complex value, with numeric values treated as constants. Reflected operations and the augmented forms +=, -=, and *= must agree with their corresponding binary operations.

Representative results include:

Polynomial(1, 1, 1) + Polynomial(2, 2) == Polynomial(1, 3, 3)
Polynomial(3, 3, 3) - 2 == Polynomial(3, 3, 1)
2 - Polynomial(3, 3, 3) == Polynomial(-3, -3, -1)
Polynomial(1, 2, 3) * Polynomial(1, 2, 3) == Polynomial(1, 4, 10, 12, 9)

Adding numeric zero or ZeroPolynomial() preserves the polynomial value. Subtracting a general polynomial from itself produces a normalized general Polynomial() value.

Binary multiplication by any zero polynomial or numeric zero returns ZeroPolynomial(). In contrast, augmented multiplication of a general Polynomial by zero keeps the receiver in the general-polynomial category while normalizing it to Polynomial(). Multiplying two Constant instances returns a Constant; multiplying compatible monomials retains monomial behavior.

Polynomial quotient and remainder

Polynomial long division is exposed through:

  • divmod(dividend, divisor), returning (quotient, remainder);
  • // and //=, selecting the quotient; and
  • % and %=, selecting the remainder.

The quotient and remainder satisfy ordinary polynomial division, with the remainder having lower degree than the divisor when nonzero. Examples:

divmod(Polynomial(1, 4, 4), Polynomial(1, 2))
# (Polynomial(1, 2), Polynomial())

divmod(Polynomial(1, 2, 3), Polynomial(1, 2))
# (Polynomial(1, 0), Polynomial(3))

Division by a Constant or numeric constant scales every coefficient and leaves a zero remainder:

divmod(Polynomial(1, 2, 3), Constant(5))
# (Polynomial(1/5, 2/5, 3/5), Polynomial())

Division by a monomial whose degree is greater than the dividend's degree returns Polynomial() as quotient and leaves the dividend value as remainder. Division by a zero polynomial raises ZeroDivisionError.

Powers

Polynomial values support ** and **= for non-negative integer powers. Non-integer and negative powers raise ValueError. Augmented exponentiation must be value-consistent with ordinary exponentiation.

  • Power zero yields multiplicative one: Constant(1) for a general polynomial, constant, or zero polynomial, while a plain Monomial yields Monomial(1, 0).
  • Power one returns an equal fresh result and preserves the concrete category of the operand.
  • Higher powers equal repeated polynomial multiplication.
  • Constants remain Constant values.
  • Monomial(c, d) ** n has coefficient c ** n and degree d * n.
  • ZeroPolynomial() ** n remains ZeroPolynomial() for positive n.
  • Higher powers of a general polynomial are general polynomial products.

For example, Constant(5) ** 2 == Constant(25) and Monomial(5, 10) ** 2 == Monomial(25, 20). A non-augmented power result must not alias the original operand.

Representations

repr

Representations use reconstructable constructor syntax and the repr of each coefficient. General polynomial coefficients appear in normalized descending-degree order, including internal and low-degree zero positions:

repr(Polynomial(1, 2, 3)) == "Polynomial(1, 2, 3)"
repr(Polynomial("abcdef")) == "Polynomial('a', 'b', 'c', 'd', 'e', 'f')"
repr(Polynomial()) == "Polynomial()"
repr(ZeroPolynomial()) == "ZeroPolynomial()"

Specialized values retain their concrete constructor names:

repr(Monomial(1, 2)) == "Monomial(1, 2)"
repr(Constant(5)) == "Constant(5)"
repr(LinearBinomial(5, 2)) == "LinearBinomial(5, 2)"
repr(QuadraticTrinomial(1, -4, 4)) == "QuadraticTrinomial(1, -4, 4)"

Character coefficients remain quoted in repr, and complex coefficients use their normal Python repr, including parentheses where Python supplies them.

str

str renders conventional descending polynomial notation:

  • Omit terms with zero coefficients.
  • Use x for degree one and x^n for other positive degrees.
  • Do not append a variable to the degree-zero term.
  • Suppress coefficient 1 on nonconstant terms, including rendering leading -1 as a short -.
  • Retain coefficient 1 for a constant term.
  • Render a negative numeric term with - rather than + -, with spaces between terms.
  • Prefix arbitrary character coefficients directly to their variable terms.
  • Preserve the normal text and parentheses of complex coefficients.
  • Render every zero polynomial value as 0.

Required examples:

str(Polynomial(3, -2, 0, 0)) == "3x^3 - 2x^2"
str(Polynomial(-1, 0, 2)) == "-x^2 + 2"
str(Polynomial(1, 0, 1)) == "x^2 + 1"
str(Monomial(5, 10)) == "5x^10"
str(Polynomial("abcdef")) == "ax^5 + bx^4 + cx^3 + dx^2 + ex + f"
str(ZeroPolynomial()) == "0"

Task Specification: Polynomial Subclasses

Overview

Extend the public polynomial module with specialized classes for common polynomial shapes while preserving the existing behavior of Polynomial, Monomial, Constant, and ZeroPolynomial.

The following names must all be importable directly from polynomial:

  • Polynomial
  • Monomial
  • Constant
  • ZeroPolynomial
  • Binomial
  • LinearBinomial
  • Trinomial
  • QuadraticTrinomial

Every specialized class is a polynomial value. It must compare equal to a normalized Polynomial with the same coefficients and participate in the existing polynomial operations described below.

Polynomial construction and normalization

Coefficient construction

Coefficients are given in descending degree order. Polynomial supports both of these equivalent forms:

Polynomial(a, b, c, ...)
Polynomial([a, b, c, ...])

The single argument may be any iterable of coefficients, including a string, a generator, or another polynomial. For example:

Polynomial([1, 2, 3]) == Polynomial(1, 2, 3)
Polynomial("abc") == Polynomial("a", "b", "c")
Polynomial(Polynomial(1, 2, 3)) == Polynomial(1, 2, 3)

Polynomial() is the zero polynomial. Leading zero coefficients are removed from the normalized value, while zero coefficients between terms or at lower degrees retain their positional meaning. Thus:

Polynomial(0, 0, 1, 2, 3, 0) == Polynomial(1, 2, 3, 0)
Construction from terms

Polynomial(terms, from_monomials=True) constructs a polynomial from an iterable of terms. Each term may be either a Monomial or a 2-tuple (coefficient, degree). Terms at the same degree contribute to the same coefficient. A tuple places the coefficient first and the exponent second.

Existing specialized defaults
  • Monomial(coefficient, degree) represents coefficient * x^degree.
  • Monomial() is equivalent to Monomial(1, 1), representing x.
  • Constant(value) represents a degree-zero value.
  • Constant() is equivalent to Constant(1).
  • ZeroPolynomial() represents zero and is equal in value to Polynomial() and Constant(0).

Normalized views and coefficient mutation

Polynomial values expose the following normalized public views:

  • degree: the greatest exponent with a nonzero coefficient. Every representation of zero has degree -math.inf.
  • terms: a list of nonzero (coefficient, degree) pairs, ordered from greatest degree to least degree.
  • monomials: a list of corresponding Monomial objects in the same descending-degree order.

For example, Polynomial(1, 0, 3) has degree 2, terms [(1, 2), (3, 0)], and monomials equal to [Monomial(1, 2), Monomial(3, 0)].

Degree-based item access uses the exponent as the index. Assigning a coefficient by degree must update all normalized views. In particular, setting the leading coefficient to zero lowers the degree and removes that leading term:

p = Polynomial(1, 2, 3)
p[p.degree] = 0
p == Polynomial(2, 3)

Arithmetic that cancels a leading term or the entire polynomial must normalize the same way.

Equality, constants, and zero

Polynomial equality is value-based after normalization, regardless of whether the value is represented by Polynomial or a specialized subclass. Inequality must always be the logical opposite of equality.

All zero forms compare equal:

Polynomial() == ZeroPolynomial() == Constant(0) == 0

They also compare equal to numeric zero written as an int, float, or complex. A nonzero polynomial does not compare equal to numeric zero.

Constant(value) exposes value through its const property, compares equal to the corresponding numeric value, and supports int(), float(), and complex() conversions using that value. ZeroPolynomial.const always returns numeric 0; it is read-only, and assigning to it raises AttributeError.

Differentiation

derivative is a property containing the first derivative under the usual power rule. For example:

Polynomial(1, 2, 3).derivative == Polynomial(2, 2)

nth_derivative(n) applies differentiation n times:

  • n == 0 returns an equal but independent copy.
  • Positive orders apply the repeated power rule.
  • Once all terms have vanished, the result is ZeroPolynomial().
  • The derivative of a constant or any zero polynomial is ZeroPolynomial().

The derivative order must be a non-negative integer; invalid orders raise ValueError.

Arithmetic compatibility

For addition, subtraction, and multiplication, operands may be polynomials (including any specialized subclass) or numeric int, float, and complex scalars. A scalar is treated as a constant. Ordinary, reflected, and augmented forms must agree in value: +, -, *, +=, -=, and *= are supported as applicable.

  • Addition and subtraction align coefficients by degree.
  • Multiplication performs polynomial convolution.
  • Leading zeroes created by cancellation are removed.
  • Adding any zero representation preserves the polynomial value.
  • Binary multiplication by zero returns ZeroPolynomial().
  • Augmented multiplication of a general Polynomial by zero leaves a normalized zero Polynomial rather than changing it to the dedicated ZeroPolynomial class.
  • Multiplying two Constant objects returns a Constant.

Examples:

Polynomial(1, 1, 1) + Polynomial(2, 2) == Polynomial(1, 3, 3)
Polynomial(3, 3, 3) - 2 == Polynomial(3, 3, 1)
2 - Polynomial(3, 3, 3) == Polynomial(-3, -3, -1)
Polynomial(1, 2, 3) * Polynomial(1, 2, 3) == Polynomial(1, 4, 10, 12, 9)
Constant(5) * Constant(5) == Constant(25)

Subtracting two equal general polynomials produces a normalized general zero value equal to Polynomial() and ZeroPolynomial().

Polynomial division

Polynomial long division is available through:

  • divmod(dividend, divisor), returning (quotient, remainder);
  • dividend // divisor and dividend //= divisor, selecting the quotient;
  • dividend % divisor and dividend %= divisor, selecting the remainder.

These are polynomial quotient/remainder operations; // does not mean that quotient coefficients are numerically rounded down. Numeric scalar divisors are treated as constants. Division by a zero polynomial raises ZeroDivisionError.

Required examples and edge cases include:

divmod(Polynomial(1, 4, 4), Polynomial(1, 2))
# (Polynomial(1, 2), Polynomial())

divmod(Polynomial(1, 2, 3), Polynomial(1, 2))
# (Polynomial(1, 0), Polynomial(3))

divmod(Polynomial(1, 2, 3), Constant(5))
# (Polynomial(1/5, 2/5, 3/5), Polynomial())

Dividing by a constant scales every coefficient and has zero remainder. If the divisor is a monomial of greater degree than the dividend, the quotient is zero and the remainder equals the original dividend.

Exponentiation

** and **= support non-negative integer powers and must agree in polynomial value. Non-integer or negative powers raise ValueError.

  • Power zero yields multiplicative one: Constant(1) for a general polynomial, a Constant, or ZeroPolynomial; a Monomial yields Monomial(1, 0).
  • Power one returns an equal, fresh value and preserves the concrete category. In particular, p ** 1 must not alias p.
  • Higher powers equal repeated polynomial multiplication.
  • A Constant raised to a power remains a Constant.
  • Monomial(c, d) ** n has coefficient c ** n and degree d * n for positive n.
  • ZeroPolynomial() remains ZeroPolynomial() for every positive power.
  • Powers of a general multi-term polynomial produce the corresponding general polynomial product.

For example, Polynomial(1, 2) ** 2 == Polynomial(1, 4, 4).

Degree shifts

The shift operators move every term by a signed integer number of degrees:

  • p << n raises every exponent by n.
  • p >> n lowers every exponent by n and discards terms moved below degree zero.
  • A negative shift reverses direction: p << -n is equivalent in value to p >> n, and vice versa.
  • A zero shift preserves the value.
  • <<=, >>=, <<, and >> have corresponding values.

Examples:

Polynomial(1, 3, 5) << 3 == Polynomial(1, 3, 5, 0, 0, 0)
Polynomial(1, 3, 5) >> 1 == Polynomial(1, 3)
Constant(5) << 10 == Monomial(5, 10)

Shifting a general polynomial entirely below degree zero yields Polynomial(). Doing the same to a monomial yields ZeroPolynomial(). Augmented shifts of Constant and ZeroPolynomial return a distinct result object rather than mutating another reference to the original fixed-category object.

Term membership

The in operator checks exact coefficient-and-degree terms. Its left operand may be:

  • one (coefficient, degree) tuple;
  • a list or set of such tuples; or
  • another polynomial.

Membership is true exactly when every supplied tuple appears in the target polynomial's nonzero terms, matching both coefficient and degree. For another polynomial, its nonzero terms are the supplied terms. Supplying only a subset is allowed, but every term in that supplied subset must match. A partial match of the supplied collection is false, and equal coefficient patterns at shifted degrees do not match. Unsupported membership operand forms raise ValueError.

For example, all of [(1, 2), (2, 1)], (3, 0), and Polynomial(1, 2, 3) are members of Polynomial(1, 2, 3), while Polynomial(1, 2, 3) is not a member of Polynomial(1, 2, 3, 0) because its terms occur at different degrees.

Representations

repr

Representations use constructor-like forms and the repr of each coefficient:

  • A normalized general polynomial uses Polynomial(c_n, ..., c_0), retaining internal zero coefficients needed to represent degree positions and omitting normalized-away leading zeroes.
  • A general zero polynomial uses Polynomial().
  • The dedicated zero type uses ZeroPolynomial().
  • Specialized forms use Monomial(coefficient, degree), Constant(value), LinearBinomial(a, b), and QuadraticTrinomial(a, b, c) as appropriate.
  • Character coefficients are quoted, and complex coefficients use their normal reconstructable representation.

Examples:

repr(Polynomial(0, 0, -2, 0, 4.5)) == "Polynomial(-2, 0, 4.5)"
repr(Polynomial("abc")) == "Polynomial('a', 'b', 'c')"
repr(ZeroPolynomial()) == "ZeroPolynomial()"
repr(Monomial(1, 2)) == "Monomial(1, 2)"
repr(Constant(5)) == "Constant(5)"
repr(LinearBinomial(5, 2)) == "LinearBinomial(5, 2)"
repr(QuadraticTrinomial(1, -4, 4)) == "QuadraticTrinomial(1, -4, 4)"
str

Human-readable strings use conventional descending polynomial notation:

  • Zero-coefficient terms are omitted; a zero polynomial is "0".
  • Terms are separated by " + ", except that a negative real coefficient uses " - " without duplicating its minus sign.
  • A leading negative coefficient begins with - and no extra space.
  • Coefficients 1 and -1 are suppressed on nonconstant terms but retained for constants.
  • Degree one uses x; degrees greater than one use x^n; constants have no variable suffix.
  • Character coefficients are placed directly before their term.
  • Complex coefficients use their normal parenthesized text.

Examples:

str(Polynomial(-1, 0, 2)) == "-x^2 + 2"
str(Polynomial(3, -2, 0, 0)) == "3x^3 - 2x^2"
str(Polynomial("abcdef")) == "ax^5 + bx^4 + cx^3 + dx^2 + ex + f"
str(Polynomial(-2, 0, 4.6666666666, -(69 + 420j), -1, 1337)) \
    == "-2x^5 + 4.6666666666x^3 + (-69-420j)x^2 - x + 1337"

New specialized classes

Binomial

Binomial(monomial1, monomial2) constructs a polynomial from two supplied terms. Each argument may be a Monomial or a (coefficient, degree) tuple. Its value must equal Polynomial([monomial1, monomial2], from_monomials=True), and equivalent tuple and Monomial inputs must compare equal.

Binomial() defaults to x^2 + x:

Binomial() == Polynomial(1, 1, 0)
LinearBinomial

LinearBinomial(a, b) represents a*x + b and equals Polynomial(a, b). The leading coefficient a must be nonzero. LinearBinomial() defaults to x + 1:

LinearBinomial() == Polynomial(1, 1)
Trinomial

Trinomial(monomial1, monomial2, monomial3) constructs a polynomial from three supplied terms. Each argument may be a Monomial or a (coefficient, degree) tuple. Its value must equal the corresponding Polynomial(..., from_monomials=True) value.

Trinomial() defaults to x^3 + x^2 + x:

Trinomial() == Polynomial(1, 1, 1, 0)
QuadraticTrinomial

QuadraticTrinomial(a, b, c) represents a*x^2 + b*x + c and equals Polynomial(a, b, c). The leading coefficient a must be nonzero. QuadraticTrinomial() defaults to x^2 + x + 1:

QuadraticTrinomial() == Polynomial(1, 1, 1)

QuadraticTrinomial properties

For q = QuadraticTrinomial(a, b, c), the following properties are read-only.

discriminant

q.discriminant is:

b ** 2 - 4 * a * c

It remains an integer when the inputs and result are integral.

real_roots

q.real_roots returns:

  • for a positive discriminant, a 2-tuple of the two distinct real roots, largest first;
  • for a zero discriminant, a 2-tuple containing the repeated root twice;
  • for a negative discriminant, ().

Whole-number roots must be returned as exact integers rather than floating-point equivalents.

QuadraticTrinomial(1, -5, 6).real_roots == (3, 2)
QuadraticTrinomial(1, 4, 4).real_roots == (-2, -2)
QuadraticTrinomial(1, 2, 5).real_roots == ()
complex_roots

q.complex_roots always returns both roots:

  • for a non-negative discriminant, it is the same tuple as real_roots, including ordering and exact integer normalization;
  • for a negative discriminant, it contains the complex-conjugate pair with the positive-imaginary root first.
QuadraticTrinomial(1, -5, 6).complex_roots == (3, 2)
QuadraticTrinomial(1, 4, 4).complex_roots == (-2, -2)
QuadraticTrinomial(1, 2, 5).complex_roots == (-1 + 2j, -1 - 2j)
real_factors

For a non-negative discriminant, q.real_factors returns:

(a, LinearBinomial(1, -r1), LinearBinomial(1, -r2))

Here a is the leading coefficient value and (r1, r2) is real_roots in its specified order. Each linear factor represents x - root. For a negative discriminant, the result is the one-element tuple (q,), containing the trinomial itself.

QuadraticTrinomial(1, -5, 6).real_factors \
    == (1, LinearBinomial(1, -3), LinearBinomial(1, -2))
QuadraticTrinomial(1, 4, 4).real_factors \
    == (1, LinearBinomial(1, 2), LinearBinomial(1, 2))
complex_factors

q.complex_factors always returns:

(a, LinearBinomial(1, -r1), LinearBinomial(1, -r2))

where (r1, r2) is complex_roots in its specified order.

QuadraticTrinomial(1, 2, 5).complex_factors \
    == (1, LinearBinomial(1, 1 - 2j), LinearBinomial(1, 1 + 2j))

All root and factor results must preserve the exact integer form of whole-number roots so the resulting LinearBinomial coefficients are exact integer values as well.
