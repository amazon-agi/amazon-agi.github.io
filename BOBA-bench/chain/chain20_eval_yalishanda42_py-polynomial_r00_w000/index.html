The Polynomial Class

Constructor

The constructor supports both of the following forms:

  • Polynomial(coeffs), where coeffs is a single iterable of coefficients.
  • Polynomial(c1, c2, ..., cn), where the coefficients are passed as separate positional arguments.

In either form, coefficients appear in descending order of degree: the first coefficient corresponds to the highest-degree term, and the last coefficient corresponds to the constant term (degree 0). When one iterable is supplied, it is expanded as the coefficient sequence; for instance, a string is treated as an iterable of character coefficients.

Passing coefficients separately must construct the same polynomial as passing the corresponding iterable. This equivalence holds for integer, float, complex, and arbitrary-object coefficients, including character strings. For example:

  • Polynomial([1, 2, 3]) and Polynomial(1, 2, 3) are equal.
  • Polynomial("abc") and Polynomial("a", "b", "c") are equal.

Coefficients may be integers, floats, complex numbers, or, for formatting purposes, arbitrary objects such as single-character strings.

Equality

Instances of Polynomial must support value-based equality. Two instances that hold the same coefficient value at every degree compare equal; equality must not rely on object identity. In particular, when given the same coefficient sequence, the single-iterable and separate-positional constructor forms described above must compare equal. Whether corresponding coefficient values match is determined by ordinary coefficient equality.

The ZeroPolynomial Class

ZeroPolynomial() builds a polynomial with no terms: the zero polynomial. It takes no arguments.

Required Behavior: str(...) (Human-Readable Form)

Term Construction

Match each coefficient with its degree according to its position, with the coefficients ordered from the highest degree to degree 0. Each displayed term is constructed as follows.

Variable and Power
  • Degree 0 (the constant term): no variable or power is displayed; only the coefficient is shown.
  • Degree 1: append x and never x^1.
  • Degree 2 or greater: append x^ followed by the degree, as in x^2 or x^5.
Coefficient Display
  • A coefficient equal to 1 is omitted from a nonconstant term. So a degree-2 term with coefficient 1 renders as x^2, and a degree-1 term with coefficient 1 renders as x.
  • For the constant term, a coefficient equal to 1 remains visible; the term renders as 1.
  • Other coefficients appear in their normal textual form and are placed directly before the variable part.
  • Complex coefficients are wrapped in parentheses, for example (-69-420j)x^2.
Term Omission

Terms whose numeric coefficient equals 0 are omitted entirely.

Joining Terms and Signs

Terms are displayed from the highest degree to the lowest degree.

  • When the following coefficient is non-negative, separate displayed terms with +.
  • For a negative real numeric coefficient, use - instead. Render the following coefficient by its absolute value so that its minus sign is not duplicated. In particular, a nonconstant coefficient of -1 appears as a minus sign followed by only the variable and power.
  • If the first displayed term has a negative coefficient, place a short minus directly before the term, as in -x^2 or -2x^5, and show the coefficient magnitude after that sign.
  • A leading term that is non-negative has no leading sign.

With non-numeric coefficients such as single-character strings, numeric zero omission, unit-coefficient suppression, and numeric sign handling do not apply. Such coefficients act as ordinary prefixes, and their terms are joined with +. Coefficient magnitudes used for numeric sign handling follow standard absolute-value behavior.

Examples:

  • Polynomial([0, 0, -2, 0, 4.6666666666, -(69+420j), -1, 1337]) is rendered as -2x^5 + 4.6666666666x^3 + (-69-420j)x^2 - x + 1337.
  • Polynomial([3, -2, 0, 0]) is rendered as 3x^3 - 2x^2.
  • Polynomial([2, 0]) is rendered as 2x.
  • Polynomial([2]) is rendered as 2.
  • Polynomial([1, 2]) is rendered as x + 2.
  • Polynomial([1, 0, 1]) is rendered as x^2 + 1.
  • Polynomial([-1, 0, 2]) is rendered as -x^2 + 2.
  • Polynomial("abcdef") is rendered as ax^5 + bx^4 + cx^3 + dx^2 + ex + f.
Zero Polynomial
  • The call str(ZeroPolynomial()) returns "0".
  • More generally, any polynomial that has no displayable non-zero terms is rendered as "0".

Required Behavior: repr(...) (Reconstructable Form)

repr(polynomial) must generate a string that represents an equivalent polynomial as a call to the Polynomial constructor. The coefficients are given as separate positional arguments in descending degree order, and leading zero-coefficient terms are stripped.

  • The output takes the form Polynomial(<c1>, <c2>, ..., <cn>).
  • Each <ci> uses the standard representation of that coefficient. Complex values therefore appear in forms such as (-69-420j).
  • Leading coefficients equal to 0 are dropped, so the first argument corresponds to the highest-degree non-zero term.
  • Interior and trailing zero coefficients are kept, since they stand for missing terms at degrees below the polynomial's highest degree.

For example:

  • repr(Polynomial([0, 0, -2, 0, 4.6666666666, -(69+420j), -1, 1337])) returns "Polynomial(-2, 0, 4.6666666666, (-69-420j), -1, 1337)".

Notes

The numeric special cases — zero omission, unit-coefficient suppression, and negativity handling — apply only to numeric coefficients. Formatting must stay compatible with arbitrary non-numeric coefficient objects as described above.

derivative is a property that returns the first derivative under the ordinary power rule, and it does not mutate the source. As an example, Polynomial(1, 2, 3).derivative == Polynomial(2, 2). The derivative of a constant, or of any zero polynomial, is zero.

nth_derivative(n) returns a new polynomial, produced without mutation, that is equal to applying derivative exactly n times:

  • Support is provided for every non-negative integer n.
  • nth_derivative(0) has the unchanged value of the source, delivered as a separate result.
  • After the degree has been exhausted, the result is a zero polynomial, and derivative orders larger than that remain zero.
  • An order that is negative or not an integer is invalid and raises ValueError.

Membership based on exact terms

The following method is to be implemented on Polynomial:

def __contains__(self, item) -> bool:
    ...

Conceptually, a polynomial's terms form a set of exact (coefficient, degree) pairs. True is the value of item in polynomial if and only if every term implied by item occurs among polynomial.terms. Matching requires both tuple components to match: an equal coefficient at a different degree does not match, and a different coefficient at the same degree does not match either. Order, adjacency, and position within the coefficient vector are irrelevant.

The forms of item that are supported are:

  1. A single term tuple: (coefficient, degree) checks one exact term.
  2. A list of term tuples: every term in the list must occur. It may be a proper, non-contiguous subset and may appear in any order.
  3. A set of term tuples: the subset rule is the same here.
  4. A Polynomial: every nonzero term of that polynomial must occur. So candidate in container compares candidate.terms with container.terms; it is not ordinary polynomial equality and does not require equal degrees or equal numbers of terms.

Because the rule is universal ("every implied term"), an empty supported term collection or a zero polynomial is contained vacuously. When a term is repeated inside a list, this does not introduce multiplicity requirements. not in is required to be the logical negation of in.

When p = Polynomial(1, 2, 3), all of the following are true:

(1, 2) in p
(2, 1) in p
(3, 0) in p
[(1, 2), (2, 1), (3, 0)] in p
[(1, 2), (2, 1)] in p
[(2, 1), (3, 0)] in p
[(1, 2), (3, 0)] in p
{(1, 2), (2, 1), (3, 0)} in p
Polynomial([(1, 2), (2, 1), (3, 0)], from_monomials=True) in p

The examples that follow define important failure and subset cases:

  • The expression Polynomial(1, 2, 3) in Polynomial(6, 5, 4, 1, 2, 3) is True, since the larger value contains (1, 2), (2, 1), and (3, 0). In reverse, the result is False.
  • Because their degree-zero terms differ, neither Polynomial(1, 2, 3) nor Polynomial(1, 2, 4) is contained in the other.
  • The terms of Polynomial(1, 2, 3) are {(1, 2), (2, 1), (3, 0)}, whereas those of Polynomial(1, 2, 3, 0) are {(1, 3), (2, 2), (3, 1)}. Neither is contained in the other, since coefficient values that match at shifted degrees are not matches. The trailing zero coefficient does not itself constitute a term.

Equality, inequality, and constants

Equality between polynomials compares the normalized polynomial values: after leading-zero normalization, the coefficients and their degrees must agree. Inequality is the logical opposite of equality for equal normalized values and for the zero/nonzero cases below.

Every zero form compares equal to numeric zero when that zero is represented as an int, float, or complex value:

Polynomial() == Constant(0) == ZeroPolynomial() == 0
Polynomial() == 0.0
Polynomial() == 0j

A polynomial that is nonzero does not equal numeric zero. A Constant(value) compares equal to its scalar value, exposes that value by way of its mutable const property, and supports int(...), float(...), and complex(...) conversion using that value.

Arithmetic compatibility

Ordinary polynomial coefficient arithmetic must be performed by addition, subtraction, and multiplication. Support covers polynomial operands and numeric constants (int, float, and complex) in direct, reflected, and in-place forms:

  • +, reflected +, and +=
  • -, reflected -, and -=
  • *, reflected *, and *=

Operations that are not in-place return the resulting value and do not mutate their operands. The left-hand object is updated by in-place operations. Canonical normalization applies to results: leading cancellations lower the degree, and complete cancellation produces a zero-valued polynomial.

Representative results include the following:

Polynomial(1, 1, 1) + Polynomial(2, 2) == Polynomial(1, 3, 3)
Polynomial(3, 3, 3) - 2 == Polynomial(3, 3, 1)
2 - Polynomial(3, 3, 3) == Polynomial(-3, -3, -1)
Polynomial(1, 2, 3) * Polynomial(1, 2, 3) == Polynomial(1, 4, 10, 12, 9)
Polynomial(1, 1, 1) * 10 == Polynomial(10, 10, 10)

The usual polynomial identity is satisfied by the quotient and remainder, and a remainder that is nonzero has lower degree than the divisor.

  • A non-exact case is divmod(Polynomial(1, 2, 3), Polynomial(1, 2)), which returns quotient Polynomial(1, 0) and remainder Polynomial(3).
  • Dividing Polynomial(1, 2, 3) by Constant(5) returns Polynomial(1/5, 2/5, 3/5) and a zero remainder.
  • If the divisor has greater degree, the quotient is zero and the remainder equals the dividend; for instance, dividing Polynomial(1, 2, 3) by Monomial(1, 10) has that result.

  • Operands are left unchanged by the binary forms; //= and %= update the left-hand value to the quotient and the remainder, respectively.
  • Dividing by a zero polynomial raises ZeroDivisionError.

Membership by terms

With a target polynomial p, candidate in p performs an exact term-containment check rather than a numeric evaluation.

The accepted forms for a candidate are:

  • a single (coefficient, degree) tuple;
  • a list or set of such tuples; or
  • another polynomial.

The containment check is true exactly when every nonzero candidate term occurs in p with both the same coefficient and the same degree.

  • Subsets are allowed, including subsets of terms that are non-contiguous.
  • Containment is directional: all of a smaller polynomial's terms may occur in a larger polynomial while the reverse does not hold.
  • It does not count when coefficients match at different degrees. For instance, Polynomial(1, 2, 3) and Polynomial(1, 2, 3, 0) do not contain each other, since their nonzero terms have shifted degrees.

Degree-shifting operators

Support must be provided across the polynomial class hierarchy for:

  • __lshift__(self, n) for obj << n
  • __rshift__(self, n) for obj >> n
  • __ilshift__(self, n) for obj <<= n
  • __irshift__(self, n) for obj >>= n

The shift amount n is an integer; it may be positive, negative, or zero.

Left shift

Applying obj << n produces a new value in which every term's degree is increased by n. Equivalently, each nonzero term (coefficient, degree) becomes (coefficient, degree + n) when the resulting degree is non-negative. Any term whose resulting degree would be negative is dropped.

  • With positive n, n zero coefficients are appended at the low-degree/constant end:
    • Polynomial(1, 3, 5) << 3 == Polynomial(1, 3, 5, 0, 0, 0)
    • Polynomial(1, 3, 5) << 1 == Polynomial(1, 3, 5, 0)
  • With negative n, degrees decrease and terms that cross below degree zero are removed:
    • Polynomial(1, 3, 5) << -1 == Polynomial(1, 3)
  • A shift by zero produces an equal value and does not change the source.
Right shift

Under obj >> n, every term's degree is decreased by n, making it the exact mirror of left shift:

obj >> n is value-equivalent to obj << (-n).

  • With positive n, degrees decrease and terms crossing below zero are removed:
    • Polynomial(1, 3, 5) >> 1 == Polynomial(1, 3)
    • Polynomial(1, 3, 5) >> 3 == Polynomial()
  • With negative n, degrees increase:
    • Polynomial(1, 3, 5) >> -1 == Polynomial(1, 3, 5, 0)
  • A shift by zero produces an equal value and does not change the source.
Shifting beyond degree zero

When every term is dropped, the result is zero; terms of negative degree must never remain.

  • Both Polynomial(*range(1, 11)) >> 15 and Polynomial(*range(1, 11)) << -15 produce the general zero result Polynomial().
  • Both Monomial(1, 10) >> 15 and Monomial(1, 10) << -15 produce ZeroPolynomial().
Specialized shift results
  • After a shift, a nonzero Monomial remains a Monomial with the same coefficient and a shifted degree:
    • Monomial(1, 5) << 10 produces Monomial(1, 15).
    • Monomial(1, 15) << -10 produces Monomial(1, 5).
    • Monomial(1, 5) >> -10 produces Monomial(1, 15).
    • Monomial(1, 15) >> 10 produces Monomial(1, 5).
  • When a nonzero Constant(value) is shifted to any non-negative resulting degree, the result is Monomial(value, resulting_degree). In particular, Constant(5) << 10 produces Monomial(5, 10); the corresponding right-shift behavior follows the mirror rule above. A shift of zero degrees therefore produces the mathematically equal Monomial(value, 0).
  • When a monomial or constant is shifted below degree zero, the result is ZeroPolynomial().
  • ZeroPolynomial() shifted by any integer produces a ZeroPolynomial() value.
  • A general Polynomial that is shifted produces a general Polynomial, including when all terms are removed.

These result forms must have the corresponding normalized repr, str, terms, monomials, and degree; it is not enough to merely compare equal mathematically.

Augmented assignment and object identity
  • <<= and >>= produce the same value as their binary counterparts, with the left-hand name bound to the resulting object.
  • Shift operations produce values: the pre-shift value must not be altered through an alias.
  • In particular, shift assignments on Constant and ZeroPolynomial must not mutate the original degree-zero instance. Given c1 = c followed by c1 <<= 5 (or c1 >>= n), c remains unchanged and c1 is not c. An aliased ZeroPolynomial is subject to the same identity rule.
  • Even though the resulting value may compare equal to the original — as happens with a zero shift or a shifted zero polynomial — this identity requirement applies.

The direct, reflected, and in-place forms must agree in polynomial value. The in-place forms mutate their left operand. Results must come out normalized: cancellation or subtraction may lower the degree or produce zero, and adding zero must preserve the original value.

Multiplication by Zero

Multiplication by zero that is not in place must return a ZeroPolynomial-typed result. This holds regardless of operand order and covers numeric zero, a general zero polynomial, ZeroPolynomial, and zero-valued Monomial/Constant operands.

In particular, multiplying two specialized zero polynomials must succeed without raising an exception:

z = ZeroPolynomial()
product = z * z

product must be a new ZeroPolynomial having all of the following observable properties:

repr(product) == "ZeroPolynomial()"
str(product) == "0"
product.terms == []
product.monomials == []
product.degree == -math.inf
product == z ** 2

In contrast, in-place multiplication must not downcast a general Polynomial instance. When a general polynomial is multiplied in place by zero, it remains a general Polynomial object whose normalized value is zero (and whose general representation is Polynomial()).

Polynomial Division

divmod(dividend, divisor) must perform polynomial long division and return (quotient, remainder), such that the dividend is equal in value to divisor * quotient + remainder and any nonzero remainder has lower degree than the divisor.

The required cases include:

divmod(Polynomial(1, 4, 4), Polynomial(1, 4, 4))
# (Polynomial(1.0), Polynomial())

divmod(Polynomial(1, 4, 4), Polynomial(1, 2))
# (Polynomial(1.0, 2.0), Polynomial())

divmod(Polynomial(1, 2, 3), Polynomial(1, 2))
# (Polynomial(1.0, 0), Polynomial(3))

divmod(Polynomial(1, 2, 3), Constant(5))
# (Polynomial(0.2, 0.4, 0.6), Polynomial())

divmod(Polynomial(1, 2, 3), Monomial(1, 10))
# (Polynomial(), Polynomial(1, 2, 3))

Dividing by a zero polynomial must raise ZeroDivisionError.

The operators relate to one another as follows:

  • a // b returns the quotient that divmod(a, b) returns;
  • a % b returns the remainder;
  • a //= b mutates a into the quotient; and
  • a %= b mutates a into the remainder.

Membership

candidate in polynomial performs a check for term containment. A candidate may be:

  • a single (coefficient, degree) tuple;
  • a list or set of tuples of that form; or
  • another polynomial, in which case the nonzero terms it contains are used.

Containment holds exactly when every candidate term occurs in the target with both coefficient and degree matching. The candidate terms may form a proper subset and need not be contiguous. For example, each of the following is contained in Polynomial(1, 2, 3):

(1, 2)
[(1, 2), (2, 1)]
[(1, 2), (3, 0)]
{(1, 2), (2, 1), (3, 0)}
Polynomial([(1, 2), (3, 0)], from_monomials=True)

Containment is directional. The terms of a smaller polynomial can be contained in a larger polynomial while the reverse does not hold. Degree takes part in each match, so coefficient sequences shifted to different degrees do not contain one another. If even one candidate term fails to match, containment is false.

Exponentiation

The ** operator must support non-negative integer exponents for Polynomial, Constant, Monomial, and ZeroPolynomial values.

  • For every supported value, an exponent of zero returns Constant(1), including ZeroPolynomial() ** 0.
  • An exponent of one returns a new object, distinct from the source, with the same effective polynomial type and all the same observable polynomial properties.
  • Positive powers neither mutate nor alias the source.
  • Higher powers hold the same mathematical value as repeated multiplication.

Power results with specialized types must be preserved:

Constant(5) ** 2 == Constant(25)
Monomial(5, 10) ** 2 == Monomial(25, 20)
ZeroPolynomial() ** 2 == ZeroPolynomial()

The constant result must remain a Constant, the monomial result a Monomial, and the zero result a ZeroPolynomial. Squaring a general polynomial must agree with its self-product in normalized value, representation, terms, monomials, and degree. Building from coefficients

For Polynomial, coefficients arrive starting from the highest degree and ending at the constant term. To illustrate, Polynomial(1, 2, 3) stands for x^2 + 2x + 3. Coefficients must be accepted by the constructor either positionally or as a single iterable, and the two input styles give the same result:

Integer, floating-point, complex, and character coefficients are all covered by this. A string is handled as an iterable whose elements are characters, which makes the two calls below equivalent:

Polynomial("abcdef")

Normal form

Zero coefficients on the leading side — that is, the highest-degree side — must be discarded. Normalization controls degree, equality, terms, arithmetic results, and display. As an example:

Polynomial(0, 0, 0, 1, 2, 3, 0) == Polynomial(1, 2, 3, 0)

Their repr and str output must agree as well. A zero constant sitting at the low-degree end is kept when it is what fixes the degrees of the nonzero terms preceding it.

The defaults of the specialized classes are:

Interface of Polynomial Values

Degree, terms, monomials

The following members are exposed by every polynomial:

  • degree: the greatest degree at which a nonzero coefficient is present. The degree of every zero-polynomial value is -math.inf.
  • terms: a list of the nonzero (coefficient, degree) pairs, ordered from the greatest degree to the least.
  • monomials: those same nonzero terms in the shape of Monomial objects, again ordered by descending degree.

As an example:

p = Polynomial(1, 2, 0, 3)
p.degree     # 3
p.terms      # [(1, 3), (2, 2), (3, 0)]

For a zero polynomial, no nonzero terms and no monomials exist.

Coefficient access by degree

Reading and writing coefficients by degree is something the mutable polynomial types support: p[k] gives the coefficient of x^k. After an assignment of this kind, the value must be re-normalized. One case in particular: assigning zero to the leading coefficient of a general polynomial lowers its degree, as appropriate:

p = Polynomial(1, 2, 3)
p[p.degree] = 0
p == Polynomial(2, 3)

ZeroPolynomial lies outside this mutability: as specified above, its item assignment always raises AttributeError.

Taking derivatives

derivative is a property; what it returns is the ordinary power-rule derivative, delivered as a new polynomial value. As an example:

Polynomial(1, 2, 3).derivative == Polynomial(2, 2)

For a constant, taking the derivative gives a zero polynomial; for a zero polynomial, it gives zero.

For every non-negative integer n, calling nth_derivative(n) returns a new polynomial — the outcome of applying derivative exactly n times. With n equal to zero, the returned object is a new polynomial even though its value matches the source's; once the degree has been used up, taking derivatives beyond that point keeps producing zero. The source may not be mutated, either by derivative or by nth_derivative.

What polynomial equality compares is the normalized values, coefficient by degree. Within the comparison situations covered here, != is the logical opposite of ==. Normalized polynomials that are equal compare equal regardless of which supported constructor was used to create them. A polynomial that is nonzero is not equal to numeric zero.

All public zero forms, when compared against integer, floating-point, and complex zero, come out equal:

ZeroPolynomial() == Polynomial() == Constant(0) == 0
ZeroPolynomial() == 0.0
ZeroPolynomial() == 0j

Arithmetic Operations

Adding, subtracting, multiplying

Ordinary coefficient arithmetic is something polynomials support, both with other polynomials and with integer, floating-point, and complex constants. The direct form, the reflected form, and the in-place form must agree in value:

  • p + q, q + p, and p += q
  • p + c, c + p, and p += c
  • p - q and p -= q
  • p - c, c - p, and p -= c
  • p * q, q * p, and p *= q
  • p * c, c * p, and p *= c

Alignment of coefficients happens degree by degree, products are formed through ordinary polynomial convolution, and every result is normalized. As an example:

Polynomial(1, 1, 1) + Polynomial(2, 2) == Polynomial(1, 3, 3)
Polynomial(3, 3, 3) - 2 == Polynomial(3, 3, 1)
2 - Polynomial(3, 3, 3) == Polynomial(-3, -3, -1)
Polynomial(1, 2, 3) * Polynomial(1, 2, 3) == Polynomial(1, 4, 10, 12, 9)

Adding zero of any kind — numeric or polynomial — leaves the value unchanged. Subtraction may normalize its result to zero, or it may remove leading terms that have canceled.

Multiplication by zero, when it is not in-place, returns a ZeroPolynomial value:

Polynomial(1, 1, 1) * ZeroPolynomial()
# ZeroPolynomial()

In-place multiplication is another matter: it must not downcast a general Polynomial. Once p *= 0 or p *= ZeroPolynomial() has been applied, the object is still a general Polynomial: its value is zero, and its general representation is Polynomial().

Division with remainder

Polynomial long division is performed by divmod(dividend, divisor), which returns the pair (quotient, remainder). The situations it must handle are these: exact division; a remainder that is nonzero; division by a constant polynomial; and a case where the divisor's degree is greater than the dividend's. Coefficients undergo ordinary division, so integral inputs can come out with floating-point coefficients in the quotient. Either the remainder is zero, or its degree is lower than the divisor's.

Value equalities that are required include the following:

divmod(Polynomial(1, 4, 4), Polynomial(1, 4, 4))
# (Polynomial(1), Polynomial())

divmod(Polynomial(1, 4, 4), Polynomial(1, 2))
# (Polynomial(1, 2), Polynomial())

divmod(Polynomial(1, 2, 3), Polynomial(1, 2))
# (Polynomial(1, 0), Polynomial(3))

divmod(Polynomial(1, 2, 3), Constant(5))
# (Polynomial(1/5, 2/5, 3/5), Polynomial())

divmod(Polynomial(1, 2, 3), Monomial(1, 10))
# (Polynomial(), Polynomial(1, 2, 3))

The quotient is what // returns, and the remainder is what % returns. Their in-place forms are //= and %=, and these swap a mutable left operand's value for the corresponding normalized quotient or remainder.

  • monomials is the matching list of Monomial objects in descending degree order.

  • apply derivative exactly n times;
  • for n == 0, return an independent result carrying the source's unchanged value and concrete class;

  • leave p unmodified.

Membership tests

Each of the following candidate forms is supported by candidate in p:

  • one (coefficient, degree) tuple;
  • a list of such tuples;
  • a set of such tuples; or
  • another polynomial.

Membership is true exactly when every nonzero candidate term appears in p with both its coefficient and its absolute degree matching. The candidate may be a proper subset whose terms need not be contiguous. For instance, (1, 2), [(1, 2), (3, 0)], and Polynomial(1, 2, 3) are all contained in Polynomial(1, 2, 3). Polynomial equality is judged on normalized values rather than concrete classes. Specifically:

  • Normalized polynomials that are equal satisfy == and not !=.
  • A polynomial that is nonzero satisfies p != 0 and not p == 0.
  • ZeroPolynomial(), Polynomial(), and Constant(0) compare equal to each other and to numeric zero written as an int, float, or complex; for these values != 0 is false.
  • A Constant(value) that is nonzero compares equal to its numeric scalar value.

Adding, subtracting, and multiplying

Addition and subtraction carry out ordinary coefficient-wise polynomial arithmetic. Polynomial operands and numeric int, float, and complex constants are supported in direct, reflected, and in-place forms (+, -, +=, and -=). Reflected subtraction uses the normal operand order. These operations must normalize cancelled leading terms and zero results. Examples:

  • Polynomial(1, 1, 1) + 2 is Polynomial(1, 1, 3).
  • 2 - Polynomial(3, 3, 3) is Polynomial(-3, -3, -1).
  • The subtraction of two equal general Polynomial values produces the general zero representation Polynomial().

Multiplication computes ordinary polynomial convolution and supports polynomial and numeric operands in direct, reflected, and in-place forms (* and *=). As an example, Polynomial(1, 2, 3) * Polynomial(1, 2, 3) is Polynomial(1, 4, 10, 12, 9), whereas multiplication by the scalar 10 scales every coefficient.

The concrete-result rules that follow are required:

  • The product of two nonzero operands whose concrete type is Monomial is a Monomial with coefficient a*b and degree d+e.

  • Any non-in-place multiplication that involves a ZeroPolynomial returns a ZeroPolynomial; in particular, ZeroPolynomial() * ZeroPolynomial() is a ZeroPolynomial.
  • For a general Polynomial, multiplication by zero returns a ZeroPolynomial when it is not in-place.
  • In-place multiplication does not downcast an existing general Polynomial: after p *= 0, p has zero value and the concrete general representation Polynomial() instead of becoming a ZeroPolynomial.

Dividing polynomials

divmod(dividend, divisor) carries out polynomial long division and returns (quotient, remainder). It must support exact division, a nonzero remainder, constant divisors, monomial divisors, and a divisor with degree greater than the dividend's. The remainder is zero, or its degree lies below the divisor's. Representative results are as follows:

  • divmod(Polynomial(1, 4, 4), Polynomial(1, 2)) gives quotient Polynomial(1, 2) with Polynomial() as the remainder.
  • divmod(Polynomial(1, 2, 3), Polynomial(1, 2)) gives quotient Polynomial(1, 0) and remainder Polynomial(3).
  • Dividing Polynomial(1, 2, 3) by Constant(5) gives quotient Polynomial(1/5, 2/5, 3/5) and a zero remainder.
  • When the divisor has larger degree, the quotient is zero and the remainder equals the original dividend.
  • A polynomial divided by itself gives quotient one and remainder zero.

The quotient component is produced by // and //=. The remainder component is produced by % and %=. Dividing by the zero polynomial raises ZeroDivisionError.

For any supported polynomial p and exponent n:

  1. Zeroth power: p ** 0 is exactly the same as Constant(1), including for ZeroPolynomial(); hence zero raised to the zeroth power follows this library identity rule.
  2. First power: p ** 1 has the same normalized value and concrete class as p, yet it is a distinct object.
  3. Higher powers: for n >= 2, p ** n is exactly what multiplying p by itself n times gives, with the specialized result type described below.
  4. Direct exponentiation must not mutate p. Every direct result of p ** n must be a distinct object from p, including the zeroth and first powers.

Concrete power results include the following:

  • When n >= 1, Constant(a) ** n is a Constant with value a ** n; for example, Constant(5) ** 2 is exactly the same as Constant(25). The universal zeroth-power rule above takes precedence.
  • For n >= 1, an operand that is nonzero and has concrete type Monomial produces a Monomial with coefficient a ** n and degree d*n; for example, Monomial(5, 10) ** 2 is exactly the same as Monomial(25, 20) and as the corresponding monomial multiplication.
  • For n >= 1, raising ZeroPolynomial() to a positive power gives a ZeroPolynomial.
  • When the operand is a general nonzero Polynomial, the result agrees in value and concrete type with repeated general polynomial multiplication. As an example, Polynomial(1, 2) ** 2 is exactly the same as Polynomial(1, 4, 4).

These same rules hold for arbitrary supported positive powers, not only squares.

**= must also be supported through __ipow__ by all four core classes. If the left operand's pre-operation value is p, then after p **= n the bound result must have the same value and concrete type that direct p ** n would produce. This includes preserving a Monomial result for positive monomial powers and producing Constant(1) for exponent zero.

Exponents that are negative or non-integer are outside the supported exponentiation contract.

Operators that shift degree

Implement the following operators on the polynomial types:

  • __lshift__(self, n) implements p << n and returns a new object;
  • __rshift__(self, n) implements p >> n and returns a new object;
  • __ilshift__(self, n) implements p <<= n;
  • __irshift__(self, n) implements p >>= n.

The shift amount n is an integer; it may be positive, negative, or zero. For every term coefficient * x**degree:

  • under p << n, its degree maps to degree + n;
  • under p >> n, its degree maps to degree - n;
  • a negative amount reverses the direction: p << -n has the value of p >> n, and p >> -n has the value of p << n;
  • shifting by zero produces a new value equal to the original; augmented assignment by zero likewise preserves the value.

The only effect of these operations is to shift degrees. They must not apply a bit shift to any coefficient.

Dropping terms that would fall below degree zero

When a shifted term would have a negative degree, that term is dropped completely; it is not retained as a negative-degree or fractional term. When every term is dropped, the result is zero. The rule applies both to a positive right shift and to a negative left shift.

Behavior of a general Polynomial

For a general Polynomial, raising degrees appends zero coefficient slots at lower degrees, while lowering degrees removes slots that pass below degree zero:

Polynomial(1, 3, 5) << 3   == Polynomial(1, 3, 5, 0, 0, 0)
Polynomial(1, 3, 5) << 1   == Polynomial(1, 3, 5, 0)
Polynomial(1, 3, 5) << -1  == Polynomial(1, 3)

Polynomial(1, 3, 5) >> 1   == Polynomial(1, 3)
Polynomial(1, 3, 5) >> 3   == Polynomial()
Polynomial(1, 3, 5) >> -1  == Polynomial(1, 3, 5, 0)

A shift that goes past the entire polynomial returns the general zero Polynomial():

Polynomial(*range(1, 11)) >> 15   == Polynomial()
Polynomial(*range(1, 11)) << -15  == Polynomial()

The augmented-assignment counterparts must produce the same resulting values. For augmented assignment on an ordinary Polynomial, there is no object-identity requirement.

Behavior of Monomial, Constant, and the zero value

A nonzero Monomial that stays at a non-negative degree returns a Monomial with the same coefficient and adjusted degree, including when the adjusted degree is zero:

Monomial(1, 5) << 10    == Monomial(1, 15)
Monomial(1, 15) << -10  == Monomial(1, 5)
Monomial(1, 5) >> -10   == Monomial(1, 15)
Monomial(1, 15) >> 10   == Monomial(1, 5)
Constant(5) << 10       == Monomial(5, 10)

When a monomial or constant is shifted below degree zero, the result is ZeroPolynomial():

Monomial(1, 10) >> 15   == ZeroPolynomial()
Monomial(1, 10) << -15  == ZeroPolynomial()

Shifting a ZeroPolynomial in either direction still leaves a ZeroPolynomial value.

Augmented assignment and immutability of specialized instances

A shift carried out with <<= or >>= must never mutate an existing Constant or ZeroPolynomial instance. Augmented assignment must rebind the target to a new, distinct result object, leaving every alias to the original unchanged. The requirement covers both directions and every shift amount. For example:

c = Constant(5)
c1 = c
c1 <<= 5

assert c == Constant(5)
assert c1 == Monomial(5, 5)
assert c1 is not c

z = ZeroPolynomial()
z1 = z
z1 <<= 5

assert z == ZeroPolynomial()
assert z1 == ZeroPolynomial()
assert z1 is not z

>>= falls under the same distinctness rule. Non-augmented << and >> always return new objects as specified above.

For human-readable output, the conventional descending polynomial notation is used:

  • Terms whose coefficient is zero are left out; a zero polynomial is rendered as "0".
  • The separator between terms is " + ", except that a negative real coefficient uses " - " with its minus sign not duplicated.
  • A string with a leading negative coefficient begins with - and no extra space.
  • On nonconstant terms the coefficients 1 and -1 are suppressed, but for constants they are retained.
  • Degree one is written as x; degrees greater than one are written as x^n; constants carry no variable suffix.
  • A character coefficient sits directly before its term.
  • Complex coefficients appear in their normal parenthesized text.

Some examples:

str(Polynomial(-1, 0, 2)) == "-x^2 + 2"
str(Polynomial(3, -2, 0, 0)) == "3x^3 - 2x^2"
str(Polynomial("abcdef")) == "ax^5 + bx^4 + cx^3 + dx^2 + ex + f"
str(Polynomial(-2, 0, 4.6666666666, -(69 + 420j), -1, 1337)) \
    == "-2x^5 + 4.6666666666x^3 + (-69-420j)x^2 - x + 1337"

Newly added specialized classes

Binomial

The constructor Binomial(monomial1, monomial2) builds a polynomial from the two given terms. Each argument may be a Monomial or a (coefficient, degree) tuple. Its value must equal Polynomial([monomial1, monomial2], from_monomials=True), and tuple inputs and Monomial inputs that are equivalent must compare equal.

The default value of Binomial() is x^2 + x:

Binomial() == Polynomial(1, 1, 0)
LinearBinomial

The class LinearBinomial(a, b) stands for a*x + b and is equal to Polynomial(a, b). Its leading coefficient a must be nonzero. The default for LinearBinomial() is x + 1:

LinearBinomial() == Polynomial(1, 1)
Trinomial

The constructor Trinomial(monomial1, monomial2, monomial3) builds a polynomial from the three given terms. Each argument may be a Monomial or a (coefficient, degree) tuple. Its value must equal the value of the corresponding Polynomial(..., from_monomials=True) call.

The default value of Trinomial() is x^3 + x^2 + x:

Trinomial() == Polynomial(1, 1, 1, 0)
QuadraticTrinomial

The class QuadraticTrinomial(a, b, c) stands for a*x^2 + b*x + c and is equal to Polynomial(a, b, c). Its leading coefficient a must be nonzero. The default for QuadraticTrinomial() is x^2 + x + 1:

QuadraticTrinomial() == Polynomial(1, 1, 1)

Properties of QuadraticTrinomial

With q = QuadraticTrinomial(a, b, c), all of the properties below are read-only.

discriminant

The value of q.discriminant is:

b ** 2 - 4 * a * c

It remains an integer whenever the inputs and the result are integral.

real_roots

q.real_roots returns the following:

  • with a positive discriminant, a 2-tuple of the two distinct real roots, largest first;
  • with a zero discriminant, a 2-tuple holding the repeated root twice;
  • with a negative discriminant, ().

Roots that are whole numbers must be returned as exact integers, not as their floating-point equivalents.

QuadraticTrinomial(1, -5, 6).real_roots == (3, 2)
QuadraticTrinomial(1, 4, 4).real_roots == (-2, -2)
QuadraticTrinomial(1, 2, 5).real_roots == ()
complex_roots

In every case, q.complex_roots returns both roots:

  • with a non-negative discriminant, it is the same tuple as real_roots, with its ordering and exact integer normalization included;
  • with a negative discriminant, it contains the complex-conjugate pair, with the positive-imaginary root first.
QuadraticTrinomial(1, -5, 6).complex_roots == (3, 2)
QuadraticTrinomial(1, 4, 4).complex_roots == (-2, -2)
QuadraticTrinomial(1, 2, 5).complex_roots == (-1 + 2j, -1 - 2j)
real_factors

When the discriminant is non-negative, q.real_factors returns:

(a, LinearBinomial(1, -r1), LinearBinomial(1, -r2))

In this tuple, a is the leading coefficient value, and (r1, r2) is real_roots in its specified order. Each of the linear factors represents x - root. With a negative discriminant, the result is the one-element tuple (q,), which contains the trinomial itself.

QuadraticTrinomial(1, -5, 6).real_factors \
    == (1, LinearBinomial(1, -3), LinearBinomial(1, -2))
QuadraticTrinomial(1, 4, 4).real_factors \
    == (1, LinearBinomial(1, 2), LinearBinomial(1, 2))
complex_factors

In every case, q.complex_factors returns:

(a, LinearBinomial(1, -r1), LinearBinomial(1, -r2))

with (r1, r2) being complex_roots in its specified order.

QuadraticTrinomial(1, 2, 5).complex_factors \
    == (1, LinearBinomial(1, 1 - 2j), LinearBinomial(1, 1 + 2j))

All root and factor results must preserve the exact integer form of whole-number roots, so that the resulting LinearBinomial coefficients are exact integer values as well.
