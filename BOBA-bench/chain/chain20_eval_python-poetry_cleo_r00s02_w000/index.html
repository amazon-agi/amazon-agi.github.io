Task Specification: Output Formatter Classes

Implement a text-formatting subsystem in the cleo.formatter module that renders styled markup tags into ANSI terminal escape codes. Three classes must be importable from cleo.formatter:

  • OutputFormatterStyle
  • OutputFormatterStyleStack
  • OutputFormatter

All ANSI escape sequences below use \033 (ESC, 0x1b) as the escape character.

1. OutputFormatterStyle

Represents a foreground color, background color, and a set of display options that can be applied to a string.

Constructor
OutputFormatterStyle(foreground=None, background=None, options=None)
  • foreground: color name or None.
  • background: color name or None.
  • options: iterable of option names or None.
Color and Option Tables

Supported foreground colors and their codes:

color code
black 30
red 31
green 32
yellow 33
blue 34
white 37

Supported background colors and their codes:

color code
black 40
red 41
blue 44
yellow 43
white 47
cyan 46

Supported options and their codes:

option code
bold 1
underscore 4
blink 5
reverse 7
conceal 8
Methods
  • set_foreground(color): Set the foreground color. Raise an exception if color is not a recognized foreground color name.
  • set_background(color): Set the background color. Raise an exception if color is not a recognized background color name.
  • set_options(options): Replace the current option set with the given iterable of option names.
  • set_option(option): Add a single option to the current set. If already present, the set is unchanged. Raise an exception whose message is exactly Invalid option specified: "<option>" when the option name is not recognized.
  • unset_option(option): Remove a single option from the current set. If not present, the set is unchanged. Raise an exception whose message is exactly Invalid option specified: "<option>" when the option name is not recognized.
  • apply(text): Return text wrapped with the appropriate ANSI codes.
apply output format

Produce a string of the form:

\033[<codes>m<text>\033[0m

where <codes> is a semicolon-joined list of the applicable numeric codes in this fixed order:

  1. foreground code (if a foreground color is set)
  2. background code (if a background color is set)
  3. option codes, in the order the options were first added

Examples:

  • foreground green, background black, options ['bold', 'underscore'], applied to foo → \033[32;40;1;4mfoo\033[0m
  • foreground red, no background, options ['blink'], applied to foo → \033[31;5mfoo\033[0m
  • no foreground, background white, applied to foo → \033[47mfoo\033[0m

Option ordering behavior for set_options/set_option/unset_option (starting from an empty style, applying to foo):

  • set_options(['reverse', 'conceal']) → \033[7;8mfoo\033[0m
  • then set_option('bold') → \033[7;8;1mfoo\033[0m
  • then unset_option('reverse') → \033[8;1mfoo\033[0m
  • then set_option('bold') again (already present, no change) → \033[8;1mfoo\033[0m
  • then set_options(['bold']) (full replacement) → \033[1mfoo\033[0m
Equality

Two OutputFormatterStyle instances must compare equal when they represent the same foreground, background, and option set, and unequal otherwise (this comparison is used to distinguish separately-constructed styles).

2. OutputFormatterStyleStack

A LIFO stack of OutputFormatterStyle objects.

Constructor
OutputFormatterStyleStack()

Starts empty.

Methods

  • get_current(): Return the style at the top of the stack (the most recently pushed one still present).
  • pop(style=None):

    • When called with a style argument, remove and return the top-most style on the stack that is equal to the given style, also discarding every style above it. (For example, with s1, s2, s3 pushed in that order, pop(s2) returns s2 and leaves s1 on the stack so a subsequent pop() returns s1.)
    • When called with a style argument that does not match any style currently on the stack, raise an exception.

3. OutputFormatter

Parses markup in strings and converts it to ANSI-formatted output.

Constructor
OutputFormatter(decorated=False)
  • decorated: when True, tags are converted to ANSI codes; when False, tags are stripped and only the plain text content remains.

The formatter must be pre-populated with these built-in named styles:

name foreground background
error white red
info green (none)
comment yellow (none)
question black cyan
Methods
  • set_decorated(decorated): Enable or disable decoration.
  • has_style(name): Return True if a style with the given name is defined.
  • set_style(name, style): Register an OutputFormatterStyle under name, overriding any existing one.
  • get_style(name): Return the OutputFormatterStyle registered under name.
  • format(message): Parse the markup in message and return the resulting string.
  • escape(text) (available as both an instance method and a static/class method): Return text with each < character escaped as \< so it will not be interpreted as a tag opening.
Markup syntax and format behavior

Tags take the form <name>...</name>, <name>...</> (a closing tag with no name closes the most recently opened tag), or inline-defined styles.

Named-style tags. A tag whose name matches a defined style applies that style. Example (decorated): <info>some info</info> → \033[32msome info\033[0m.

Built-in results (decorated):

  • <error>some error</error> → \033[37;41msome error\033[0m
  • <info>some info</info> → \033[32msome info\033[0m
  • <comment>some comment</comment> → \033[33msome comment\033[0m
  • <question>some question</question> → \033[30;46msome question\033[0m

Inline style definition. A tag whose body is a semicolon-separated list of fg=<color> and bg=<color> assignments defines an ad-hoc style. Its matching closing tag may be either </> or a closing tag repeating the same body.

  • <fg=blue;bg=red>some text</> → \033[34;41msome text\033[0m
  • <fg=blue;bg=red>some text</fg=blue;bg=red> → \033[34;41msome text\033[0m

Nesting. Nested tags each emit their own open/close sequences. When an inner styled region ends, the surrounding style is re-emitted for the remaining text.

  • <error>some <info>some info</info> error</error> → \033[37;41msome \033[0m\033[32msome info\033[0m\033[37;41m error\033[0m
  • Deeply nested: <error>error<info>info<comment>comment</comment></info>error</error> → \033[37;41merror\033[0m\033[32minfo\033[0m\033[33mcomment\033[0m\033[32m\033[0m\033[37;41merror\033[0m

Adjacent tags.

  • <error>some error</error><info>some info</info> → \033[37;41msome error\033[0m\033[32msome info\033[0m

Custom style tags. After set_style('test', OutputFormatterStyle('blue','white')) and set_style('b', OutputFormatterStyle('blue','white')):

  • <test>some <b>custom</b> msg</test> → \033[34;47msome \033[0m\033[34;47mcustom\033[0m\033[34;47m msg\033[0m

Redefining a built-in style. After set_style('info', OutputFormatterStyle('blue','white')):

  • <info>some custom msg</info> → \033[34;47msome custom msg\033[0m

Non-style tags. A tag whose name is not a defined style and is not a valid inline style definition is passed through literally as text (still subject to the surrounding style). Example:

  • <info>some <tag> styled <p>single-char tag</p></info> → \033[32msome \033[0m\033[32m<tag> styled \033[0m\033[32m<p>single-char tag\033[0m\033[32m</p>\033[0m

Empty tag. <> is not a tag; it is passed through as literal text.

  • foo<>bar → foo<>bar

Escaping.

  • A backslash before < escapes it: foo\<bar → foo<bar.
  • \<info>some info\</info> → <info>some info</info> (literal, no styling).
  • OutputFormatter.escape('<info>some info</info>') → \<info>some info\</info>.
  • formatter.escape(...) used inside a formatted string prevents its < from starting tags: (<info>%s</info>) with the argument escaped from z>=2.0,<a2.3 → (\033[32mz>=2.0,<a2.3\033[0m).

Tag matching is non-greedy. In (<info>>=2.0,<2.3</info>), the content between the <info> and </info> tags is taken correctly, yielding (\033[32m>=2.0,<2.3\033[0m).

Line breaks. Content that spans multiple lines is preserved exactly; the opening ANSI code is emitted before the content and the reset \033[0m after it. For example <info>\nsome text</info> → \033[32m\nsome text\033[0m, <info>some text\n</info> → \033[32msome text\n\033[0m, and multi-line content between the tags is passed through with newlines intact.

Non-decorated mode

When decorated is False, format strips all recognized style tags and returns only their text content:

  • <error>some error</error> → some error
  • <info>some info</info> → some info
  • <comment>some comment</comment> → some comment
  • <question>some question</question> → some question

Switching the same formatter to decorated (set_decorated(True)) makes it emit the full ANSI sequences shown above.

Test-support requirement

A fixture file tests/fixtures/definition_astext.txt must exist with exactly the following contents (this is styled markup used by other parts of the test suite; it is a static asset, not something generated by the code above):

Return a string that wraps the section name in an <info>[...]</info> tag, followed by a space and the message. Given a section name and a message, the result is:

<info>[<section>]</info> <message>

For example, format_section('cli', 'Some text to display') returns '<info>[cli]</info> Some text to display'.

format_block(messages, style, large=False)

Return a string that renders one or more messages as a formatted block wrapped in a tag named by style (e.g. error → <error>...</error>).

  • messages may be either a single string or a list of strings. A single string is treated as a one-line block.
  • Each line of message text is padded on the left with one space and padded on the right so that all lines share the same width. The width is determined by the longest message: each line's content is a single leading space, the message text, and trailing spaces so that every message occupies (length of longest message) + 2 characters total (one leading space plus the message plus enough trailing spaces to reach that width).
  • Each padded line is wrapped individually in <style> ... </style> (i.e. an opening <style> tag, the padded content, a closing </style> tag). Multiple lines are joined by newline characters (\n).

In the large form each line's content width is (length of longest message) + 4 (the content is two leading spaces, the message text, then trailing spaces to reach that width; blank lines are all spaces of that same width). These blank/padded lines are each wrapped in <style>...</style> and joined by \n.

Behavior examples:

  • format_block('Some text to display', 'error') → '<error> Some text to display </error>'

  • format_block(['Some text to display', 'foo bar'], 'error') →

<error> foo bar              </error>

  • format_block('Some text to display', 'error', True) →

    <error>                        </error>
<error>  Some text to display  </error>
<error>                        </error>
