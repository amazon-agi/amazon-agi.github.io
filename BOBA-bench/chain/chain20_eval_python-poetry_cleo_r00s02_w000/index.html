Task Specification: Classes for Output Formatting

Inside the cleo.formatter module, build a subsystem for formatting text that reads styled markup tags and turns them into ANSI terminal escape codes. From cleo.formatter, the following three classes must be importable:

  • OutputFormatterStyle
  • OutputFormatterStyleStack
  • OutputFormatter

In all ANSI escape sequences below, \033 (ESC, 0x1b) serves as the escape character.

1. OutputFormatterStyle

Each instance bundles a foreground color with a background color and a set of display options; the combination can be applied to a string.

Constructor
OutputFormatterStyle(foreground=None, background=None, options=None)
  • foreground: either a color name or None.
  • background: either a color name or None.
  • options: either an iterable of option names or None.
Tables of Colors and Options

The foreground colors that are supported, with their codes:

color code
black 30
red 31
green 32
yellow 33
blue 34
white 37

The supported background colors and the code each one maps to:

color code
black 40
red 41
blue 44
yellow 43
white 47
cyan 46

The supported options, again with their codes:

option code
bold 1
underscore 4
blink 5
reverse 7
conceal 8
Methods
  • set_foreground(color): Assigns the foreground color. An exception is raised if color is not a recognized foreground color name.
  • set_background(color): Assigns the background color. An exception is raised if color is not a recognized background color name.
  • set_options(options): The current option set is replaced by the iterable of option names supplied here.
  • set_option(option): Adds a single option into the current set. An option that is already present does not change the set. If the option name is unrecognized, an exception is raised whose message is exactly Invalid option specified: "<option>".
  • unset_option(option): Takes a single option out of the current set. An option that is not present does not change the set. If the option name is unrecognized, an exception is raised whose message is exactly Invalid option specified: "<option>".
  • apply(text): Returns text with the appropriate ANSI codes wrapped around it.
Format produced by apply

The string that comes out looks like this:

\033[<codes>m<text>\033[0m

In this template, <codes> denotes the applicable numeric codes joined by semicolons, listed in the following fixed order:

  1. the foreground code (present when a foreground color is set)
  2. the background code (present when a background color is set)
  3. the option codes, ordered by the point at which each option was first added

Examples:

  • given foreground green, background black, options ['bold', 'underscore'], applied to foo → \033[32;40;1;4mfoo\033[0m
  • given foreground red, no background, options ['blink'], applied to foo → \033[31;5mfoo\033[0m
  • given no foreground, background white, applied to foo → \033[47mfoo\033[0m

How the option order evolves through set_options/set_option/unset_option (the style begins empty; each output is for foo):

  • set_options(['reverse', 'conceal']) → \033[7;8mfoo\033[0m
  • next, set_option('bold') → \033[7;8;1mfoo\033[0m
  • next, unset_option('reverse') → \033[8;1mfoo\033[0m
  • next, set_option('bold') a second time (already there, so nothing changes) → \033[8;1mfoo\033[0m
  • next, set_options(['bold']) (replaces the whole set) → \033[1mfoo\033[0m
Equality semantics

Two OutputFormatterStyle objects that stand for the same foreground, the same background, and the same set of options must compare equal; any other pairing must compare unequal. (Separately-constructed styles are told apart by this comparison.)

2. OutputFormatterStyleStack

This class provides a LIFO stack whose entries are OutputFormatterStyle objects.

Constructor
OutputFormatterStyleStack()

A newly created instance has nothing on the stack.

Methods
  • push(style): Puts an OutputFormatterStyle on top of the stack.
  • get_current(): Returns whichever style currently sits on top of the stack (the most recently pushed of those still present).
  • pop(style=None):
    • Called without an argument, it takes the top style off the stack and returns it.
    • If the stack is empty, a (default) OutputFormatterStyle instance is returned.
    • Called with a style argument, it removes and returns the top-most style that equals the given style, and every style above it is taken off the stack as well. (Push s1, s2, s3 in that order: pop(s2) then returns s2, s1 remains on the stack, and the following pop() returns s1.)
    • If the style argument matches no style currently on the stack, an exception is raised.

3. OutputFormatter

This class parses whatever markup appears in strings and produces ANSI-formatted output from it.

Constructor
OutputFormatter(decorated=False)
  • decorated: a value of True means tags are translated into ANSI codes; a value of False means the tags are stripped away, leaving only the plain text content.

The formatter must come with these built-in named styles already in place:

name foreground background
error white red
info green (none)
comment yellow (none)
question black cyan
Methods
  • set_decorated(decorated): Switches decoration on or off.
  • has_style(name): Returns True in case a style of the given name is defined.
  • set_style(name, style): Registers an OutputFormatterStyle under name; any style registered there before is overridden.
  • get_style(name): Returns whichever OutputFormatterStyle is registered under name.
  • format(message): Parses the markup found in message and returns the string that results.
  • escape(text) (usable both as an instance method and as a static/class method): Returns text with each < character rewritten as \<, so that it will not be taken for the opening of a tag.
Markup syntax and the behavior of format

Tags can appear as <name>...</name>, as <name>...</> (a closing tag without a name closes the tag opened most recently), or as inline-defined styles.

Named-style tags. When a tag's name matches one of the defined styles, the tag applies that style. Example (decorated): <info>some info</info> → \033[32msome info\033[0m.

Results for the built-in styles (decorated):

  • <error>some error</error> → \033[37;41msome error\033[0m
  • <info>some info</info> → \033[32msome info\033[0m
  • <comment>some comment</comment> → \033[33msome comment\033[0m
  • <question>some question</question> → \033[30;46msome question\033[0m

Inline style definition. A body made up of a semicolon-separated list of fg=<color> and bg=<color> assignments turns the tag into an ad-hoc style definition. To close it, either </> or else a closing tag that repeats the same body may be used.

  • <fg=blue;bg=red>some text</> → \033[34;41msome text\033[0m
  • <fg=blue;bg=red>some text</fg=blue;bg=red> → \033[34;41msome text\033[0m

Nesting. Every nested tag emits open/close sequences of its own. After an inner styled region finishes, the style surrounding it is emitted again for whatever text remains.

  • <error>some <info>some info</info> error</error> → \033[37;41msome \033[0m\033[32msome info\033[0m\033[37;41m error\033[0m
  • Deeply nested: <error>error<info>info<comment>comment</comment></info>error</error> → \033[37;41merror\033[0m\033[32minfo\033[0m\033[33mcomment\033[0m\033[32m\033[0m\033[37;41merror\033[0m

Tags placed back to back.

  • <error>some error</error><info>some info</info> → \033[37;41msome error\033[0m\033[32msome info\033[0m

Custom style tags. Suppose both set_style('test', OutputFormatterStyle('blue','white')) and set_style('b', OutputFormatterStyle('blue','white')) have been called:

  • <test>some <b>custom</b> msg</test> → \033[34;47msome \033[0m\033[34;47mcustom\033[0m\033[34;47m msg\033[0m

Redefining a built-in style. Once set_style('info', OutputFormatterStyle('blue','white')) has been run:

  • <info>some custom msg</info> → \033[34;47msome custom msg\033[0m

Non-style tags. Whenever a tag's name is neither a defined style nor a valid inline style definition, the tag is emitted as literal text (the style around it still applies). Example:

  • <info>some <tag> styled <p>single-char tag</p></info> → \033[32msome \033[0m\033[32m<tag> styled \033[0m\033[32m<p>single-char tag\033[0m\033[32m</p>\033[0m

Empty tag. <> does not form a tag; it goes through as literal text.

  • foo<>bar → foo<>bar

Escaping.

  • A backslash in front of < escapes that character: foo\<bar → foo<bar.
  • \<info>some info\</info> → <info>some info</info> (the text stays literal, with no styling applied).
  • OutputFormatter.escape('<info>some info</info>') → \<info>some info\</info>.
  • Inside a formatted string, formatter.escape(...) keeps its < from starting tags: (<info>%s</info>) with the argument escaped from z>=2.0,<a2.3 → (\033[32mz>=2.0,<a2.3\033[0m).

Non-greedy tag matching. Take (<info>>=2.0,<2.3</info>): the content between <info> and </info> gets read correctly, so the outcome is (\033[32m>=2.0,<2.3\033[0m).

Line breaks. Content that covers several lines is kept exactly as is; the opening ANSI code goes before the content, and the reset \033[0m goes after it. For instance, <info>\nsome text</info> → \033[32m\nsome text\033[0m and <info>some text\n</info> → \033[32msome text\n\033[0m; content spanning lines between the tags passes through with its newlines kept intact.

Behavior when not decorated

With decorated holding False, format takes out all recognized style tags and returns only the text that was inside them:

  • <error>some error</error> → some error
  • <info>some info</info> → some info
  • <comment>some comment</comment> → some comment
  • <question>some question</question> → some question

Calling set_decorated(True) on the same formatter makes it emit the complete ANSI sequences displayed above.

1. cleo.helper.FormatterHelper

Create a class FormatterHelper that is importable via from cleo.helper import FormatterHelper. Its constructor takes no arguments, and it provides the following methods.

format_section(section, message)

Return a string that encloses the section name in an <info>[...]</info> tag, with a space and the message following it. For a given section name and message, the result is:

<info>[<section>]</info> <message>

For instance, format_section('cli', 'Some text to display') returns '<info>[cli]</info> Some text to display'.

format_block(messages, style, large=False)

Return a string that presents one or more messages as a formatted block enclosed in a tag whose name comes from style (e.g. error → <error>...</error>).

  • messages may be either a single string or a list of strings. A single string is handled as a one-line block.
  • Each line of message text gets one space of padding on the left, plus padding on the right, so that all lines end up the same width. The width comes from the longest message: each line's content consists of a single leading space, the message text, and trailing spaces, so that every message occupies (length of longest message) + 2 characters in total (one leading space, the message, and enough trailing spaces to reach that width).
  • Each padded line is wrapped on its own in <style> ... </style> (i.e. an opening <style> tag, the padded content, a closing </style> tag). Where there are multiple lines, they are joined by newline characters (\n).
  • If large is True, one extra fully-blank padded line is added before the first message line and after the last message line. In the large form, each line's content width is (length of longest message) + 4 (the content is two leading spaces, the message text, then trailing spaces so the content reaches that width; blank lines are all spaces of that same width). Each of these blank/padded lines is wrapped in <style>...</style>, and the lines are joined by \n.

Examples of the behavior:

  • format_block('Some text to display', 'error') → '<error> Some text to display </error>'

  • format_block(['Some text to display', 'foo bar'], 'error') →

    <error> Some text to display </error>
<error> foo bar              </error>

    (Both lines are padded to the width of the longest message plus the surrounding spaces; the shorter line gets extra trailing spaces so that both closing tags align.)

  • format_block('Some text to display', 'error', True) →

    <error>                        </error>
<error>  Some text to display  </error>
<error>                        </error>

    (A blank line above and below, two leading spaces before the message, and trailing spaces such that every line has equal width.)

Add the following class method:
