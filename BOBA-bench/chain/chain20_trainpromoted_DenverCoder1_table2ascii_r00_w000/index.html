Task Specification: ASCII Table Conversion Function

Objective

Implement a function that converts tabular data (a header row, body rows, and a footer row) into a formatted ASCII table string using box-drawing characters.

Public API

Create a module table2ascii that exposes a callable named table2ascii.

The function must accept the following keyword arguments:

  • header_row: a list of strings representing the column headings.
  • body: a list of rows, where each row is a list of strings representing cell values.
  • footer_row: a list of strings representing the footer/summary values.

Signature:

def table2ascii(header_row, body, footer_row) -> str:
    ...

All three arguments are passed by keyword. Each header, body row, and footer entry has the same number of columns.

Behavior

The function returns a single string representing the rendered ASCII table.

Structure
  • The table is drawn using Unicode box-drawing characters.
  • The first column is visually separated from the remaining columns by a double-line vertical divider.
  • The header row is separated from the body by a horizontal divider, and the body is separated from the footer row by a horizontal divider.
  • The table is enclosed in a border: a top border, a bottom border, and left/right vertical borders on every content line.
Cell alignment and spacing
  • Cell values are centered within their column width. Each column's width is determined by the widest value appearing in that column across all rows (header, body, footer).
  • Column content is padded so that each column has consistent width across every row.
Exact output format

Given:

  • header_row = ["#", "G", "H", "R", "S"]
  • body = [["1", "30", "40", "35", "30"], ["2", "30", "40", "35", "30"]]
  • footer_row = ["SUM", "130", "140", "135", "130"]

The function must return exactly the following string (note the trailing newline at the end):

╔═════╦═══════════════════════╗
║  #  ║  G     H     R     S  ║
╟─────╫───────────────────────╢
║  1  ║  30    40    35    30 ║
║  2  ║  30    40    35    30 ║
╟─────╫───────────────────────╢
║ SUM ║ 130   140   135   130 ║
╚═════╩═══════════════════════╝

The returned string ends with a trailing newline character (\n) after the bottom border line. Each line within the table is separated by a single newline character.

Character reference
  • Top border: ╔, ═, ╦ (over the first-column separator), ╗.
  • Content lines: ║ for the outer left/right borders and for the divider after the first column.
  • Horizontal dividers: ╟, ─, ╫ (at the first-column separator), ╢.
  • Bottom border: ╚, ═, ╩ (at the first-column separator), ╝.

The remaining columns (all columns after the first) share a single grouped region separated from the first column by the double-line divider; within that grouped region, individual column values are spaced/centered but not separated by additional vertical dividers.

Overview

Implement the public table2ascii renderer. It converts optional header, body, and footer rows into one Unicode box-drawing table string. The first column is a key column separated from the remaining value columns by a double vertical rule; value columns have whitespace between them rather than vertical rules.

Public API

The callable must be exported directly by the table2ascii package/module:

from table2ascii import table2ascii


def table2ascii(header_row=None, body=None, footer_row=None) -> str:
    ...

All three arguments may be supplied positionally or by keyword and default to None.

  • header_row: an optional list of strings, one per column.
  • body: an optional list of rows, where every row is a list of strings.
  • footer_row: an optional list of strings, one per column.

A missing or empty section is omitted. Every non-empty header, body row, and footer belongs to the same table and must have the same number of columns. The function returns the complete table as a string.

Table and Column Structure

For a table with n columns:

  • Column 0 is the key column.
  • Columns 1 through n - 1 are value columns.
  • The key and value regions are separated by ║ in content lines and by the corresponding junction character in border/separator lines.
  • Adjacent value columns have whitespace between them; they do not have vertical box-drawing separators.

Automatic Column Widths and Footer Compatibility

For each column i, let m_i be the greatest len(cell) in that column across every supplied content row:

  • the header, if present;
  • every body row, if present; and
  • the footer, if present.

Thus footer content participates in width calculation exactly like header and body content. The content is not truncated.

For tables without a footer, the content width is w_i = m_i. When a non-empty footer is supplied, preserve the established footer-bearing layout by using a minimum content width of three characters: w_i = max(3, m_i). The complete visible field for column i is f_i = w_i + 2, accounting for one outer space on each side of the centered content area. Consequently, footer-bearing cells that contain at most three characters use the established fixed five-character fields; longer content expands its column rather than being truncated.

Cell Alignment and Spacing

Every cell, including header, body, and footer cells in both key and value columns, is centered in its column's w_i-character content area. If centering requires an odd number of spare spaces, the extra space goes on the left.

For cell text s in column i, where d = w_i - len(s), its complete field is:

<one space><ceil(d / 2) spaces><s><floor(d / 2) spaces><one space>

Equivalently, define field_i(s) as that complete field. A content line is:

║field_0(s0)║field_1(s1) field_2(s2) ... field_(n-1)(sN)║

The single literal space between complete value fields combines with the trailing space of one field and the leading space of the next, so adjacent value content areas are separated by exactly three spaces before any centering space inside those areas is considered. The value region also has one outer space immediately after the key divider and one immediately before the right border. For a one-column table, the line is simply ║field_0(s0)║ and has no key/value divider.

Value cells are therefore centered, not left-aligned. In particular, a one-character value in a two-character content area receives the spare space before the value.

Borders and Separators

Use the following Unicode box-drawing characters:

  • Top border: ╔, ═, ╦, ╗
  • Header and footer separators: ╟, ─, ╫, ╢
  • Bottom border: ╚, ═, ╩, ╝
  • Content borders and key divider: ║

For two or more columns, let the visible value-region width be:

R = f_1 + f_2 + ... + f_(n-1) + (n - 2)

The final term counts the one literal separator between each pair of value fields. Border lines are then:

╔ + (═ repeated f_0 times) + ╦ + (═ repeated R times) + ╗
╟ + (─ repeated f_0 times) + ╫ + (─ repeated R times) + ╢
╚ + (═ repeated f_0 times) + ╩ + (═ repeated R times) + ╝

These expressions describe concatenation, not literal + characters. The horizontal fill count in each region must exactly equal that region's visible width in a content line. For a one-column table, omit the middle junction and value region, using only the left corner/connector, f_0 fill characters, and the right corner/connector.

Section Ordering

Compose the output in this order:

  1. Top border.
  2. If a header is present: the header content line, followed immediately by a header separator.
  3. Every body content line in input order.
  4. If a footer is present: a footer separator, followed immediately by the footer content line.
  5. Bottom border.

A header separator is emitted whenever a header is present, even when no body follows it. A footer separator is emitted whenever a footer is present, even when there is no header or body. Consequently, when a header and footer are supplied without a body, the header separator and footer separator are consecutive lines.

Every rendered line, including the bottom border, ends with \n.

If all three sections are missing or empty, preserve the empty-frame result:

╚═════╝

Presence and Column-Count Validation

None and an empty section list ([]) mean that the corresponding section is absent. In particular, an empty body contributes no rows, while an empty header or footer emits neither a content row nor a separator for that section.

Every present row must have the same number of cells. The column count is obtained from any present header, footer, or body row after this consistency requirement is satisfied. Raise ValueError whenever present rows disagree, including any of these cases:

An absent or empty section imposes no column-count constraint of its own.

Column Widths and Cell Alignment

For each column independently, inspect that column in every present header, body, and footer row. If the greatest content display width in column i is M_i, that column's rendered field width is:

w_i = M_i + 2

The additional two positions guarantee at least one space on each side of every value.

Every cell in every section is centered in its computed field width; this applies equally to the first column and to header, body, and footer cells. For content of width n in a field of width w, let P = w - n. Render:

floor(P / 2) spaces + content + ceil(P / 2) spaces

Thus, if the total padding is odd, the smaller share is before the value and the one extra space is after it. This is centered alignment with right-biased tie-breaking, not left alignment. For example:

  • "G" in a width-5 field becomes " G ";
  • "30" in a width-5 field becomes " 30 ";
  • "G" in a width-4 field becomes " G ".

The renderer uses Unicode box-drawing characters.

Column grouping

The first column is visually separated from all remaining columns by a double vertical divider (║). Columns after the first occupy one visual region and are separated from one another by a single space rather than by vertical rules.

For fields f0, f1, ..., a content row with multiple columns has this shape:

║f0║f1 f2 ...║

The inter-column spaces in the remaining-column region are in addition to the padding already contained in each field. If there is only one column, there is no remaining-column region or internal divider, and its row has the shape ║f0║.

Separators between body rows

Each preset independently controls whether a separator is drawn between adjacent body rows:

  • In row-separating styles, one body separator appears between each pair of consecutive body rows.
  • In compact/non-row-separating styles, consecutive body rows appear on consecutive lines.
  • Header and footer section separators remain tied to the presence of those sections and are not removed merely because a style is compact.
  • A style's body-row separator and its header/footer separators are distinct roles and may use different characters. For example, Styles.thin_thick uses thin body-row separators but thick header/footer separators, while Styles.thin_double uses thin body-row separators but double header/footer separators.
Heading-column dividers

For non-box styles:

  • first_col_heading=True draws the style's heading divider after column 1 and uses the corresponding tee/cross/junction characters at that boundary in horizontal lines.
  • last_col_heading=True does the same immediately before the last column.
  • Both options may be enabled together.
  • With both options False, no heading-column divider appears; the columns occupy one continuous, otherwise unbordered interior region.

Box styles always draw regular dividers between every column, regardless of heading flags. For non-box styles, ordinary internal boundaries use the style's regular inner character (often a space), and horizontal border and separator lines run straight through those boundaries using the line's own fill character, so each horizontal line forms one continuous run between the outer edges and any enabled heading-column junctions.

Overview

Modify the rendering behavior of the "simple" table style so that the vertical separator between the first (index/label) column and the remaining columns uses a double-line character instead of a single-line character.

Required Behavior Change

In the "simple" theme/style, when a table is rendered as text, the vertical divider that separates the first column from the rest of the columns must be drawn using the double vertical bar character ║ (U+2551, "BOX DRAWINGS DOUBLE VERTICAL").
