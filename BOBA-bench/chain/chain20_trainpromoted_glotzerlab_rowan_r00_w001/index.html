quaternion.multiply(a, b)

Quaternions are represented as NumPy arrays whose last axis has length 4 (the four quaternion components). A single quaternion is a shape-(4,) array; collections of quaternions are arrays whose trailing dimension is 4 and whose leading dimensions index individual quaternions.

Required Behavior: quaternion.multiply(a, b)

The function multiplies two quaternion arrays element-wise (using the quaternion product for each aligned pair) and must support NumPy broadcasting over the leading dimensions (all dimensions except the final length-4 component axis).

Specifically:

  1. Broadcasting over leading dimensions. Given two inputs whose shapes both end in a trailing axis of length 4, the leading dimensions must be broadcast together following standard NumPy broadcasting rules. The result's leading dimensions are the broadcast of the two operands' leading dimensions, and the result's trailing dimension is 4.

    • Example: an operand of shape (45, 3, 13, 4) multiplied by an operand of shape (4,) yields a result of shape (45, 3, 13, 4).
    • Example: an operand of shape (1, 1, 3, 8, 1, 4) multiplied by an operand of shape (3, 5, 1, 1, 9, 4) yields a result of shape (3, 5, 3, 8, 9, 4).

  2. Non-conforming shapes. When the leading dimensions of the two operands cannot be broadcast together under standard NumPy rules, a ValueError must be raised.

    • Example: an operand of shape (45, 3, 13, 4) multiplied by an operand of shape (2, 4) must raise ValueError.

  3. Correctness of products. For any aligned pair of quaternions selected from the broadcast result, the value at that position must equal the quaternion product of the two corresponding single quaternions (i.e., the result computed by calling multiply on those two individual shape-(4,) quaternions). Broadcasting must not alter the computed product values relative to computing each pair individually.

The existing behavior for multiplying single quaternions (shape (4,) inputs) and equally-shaped batched inputs must continue to work.

The following functions must no longer raise errors on the inputs described below. These validation checks must be removed so that these calls no longer raise:

  • quaternion.from_matrix(...) must not raise ValueError for a non-rotation (non-orthonormal) input matrix.
  • quaternion.to_matrix(...) must not raise ValueError for a non-unit-norm quaternion input.

Note: quaternion.to_euler(...) and quaternion.to_matrix(...) must still raise ZeroDivisionError where a zero quaternion causes division by zero — that behavior is unchanged. Only the ValueError norm/validation checks are removed.
