C 0
C# 1
Db 1
C### 3
Eb 3
Fbb 3
Dbb 0

PitchClass represents a chromatic pitch without an octave.

C is the default root. from_value accepts values in 0..11 and selects the canonical (“nice”) spelling corresponding to the absolute chromatic pitch. For the default root, the complete canonical order is:

Value Name
0 C
1 C#
2 D
3 Eb
4 E
5 F
6 F#
7 G
8 Ab
9 A
10 Bb
11 B

In particular, sharps are preferred for values 1 and 6, while flats are preferred for values 3, 8, and 10.

p.equivalent_sharp == PitchClass("C##")

For example:

p0 = PitchClass("C")
p = p0.with_root("Bb")

assert p.value == 2
assert p0.name == "C"

C4 + 12 C
C4 - 1 B
C4 - (-1) C#
C4 - 12 C

SimpleInterval(12).name == "P8"
SimpleInterval(24).name == "P8"  # emits UserWarning
Equality

Equality is based on the reduced semantic value, not object identity. Intervals whose inputs reduce to the same simple interval compare equal. A SimpleInterval returned by pitch-class arithmetic must compare equal to a directly constructed SimpleInterval representing the same reduced semitone distance.

SignedInterval

SignedInterval(v) represents an exact signed semitone displacement. Unlike a SimpleInterval, it retains direction and may span any number of octaves.

  • Its value remains the supplied signed semitone count.
  • Its .name property returns the existing signed interval notation. The magnitude is decomposed into octave components (P8) plus a simple remainder; a negative interval wraps the complete positive-magnitude name in -[...].
  • Representative names are:
SignedInterval(0).name == "P1"
SignedInterval(2).name == "M2"
SignedInterval(3).name == "m3"
SignedInterval(15).name == "P8+m3"
SignedInterval(27).name == "2(P8)+m3"
SignedInterval(-27).name == "-[2(P8)+m3]"

Equality between SignedInterval instances is based on the exact signed semitone value. A value returned by pitch arithmetic must compare equal to a directly constructed SignedInterval with the same signed count.

Pitch

Pitch(n) represents an absolute pitch identified by integer chromatic value n.

Subtracting pitches

Subtracting one Pitch from another must return a SignedInterval, not another pitch. Its value is the left pitch value minus the right pitch value, preserving direction:

Pitch(50) - Pitch(40) == SignedInterval(10)
Pitch(40) - Pitch(50) == SignedInterval(-10)
Adding a signed interval

Adding a SignedInterval on the right of a Pitch must return a new Pitch shifted by that exact signed semitone count:

Pitch(40) + SignedInterval(-10) == Pitch(30)

This applies to positive, zero, and negative signed intervals. Existing arithmetic with integer semitone offsets must continue to work.

Equality

Pitch equality is semantic: instances with the same absolute pitch value compare equal, including results produced by interval addition.

PitchClass

PitchClass(n) represents a pitch class identified by integer chromatic value n. A simple interval is directionless, so pitch-class subtraction uses SimpleInterval normalization rather than retaining the sign of a descending difference.

Subtracting pitch classes

Subtracting one PitchClass from another must return a SimpleInterval. Begin with the raw value difference left.value - right.value, then apply the SimpleInterval reduction and warning rules above:

PitchClass(7) - PitchClass(0) == SimpleInterval(7)

For a descending difference, the raw negative value is outside the simple interval range. It is reduced to its directionless magnitude and emits a UserWarning:

PitchClass(0) - PitchClass(7) == SimpleInterval(7)  # emits UserWarning

The warning must be emitted through warnings as part of producing the normalized result.

Adding a simple interval

Adding a SimpleInterval on the right of a PitchClass must return a new PitchClass whose value is shifted by the interval's semitone count:

PitchClass(0) + SimpleInterval(5) == PitchClass(5)

The originating pitch class's root context must be preserved. Existing addition and subtraction with integer semitone offsets must continue to retain their current behavior.

Equality

PitchClass equality must remain based on semantic pitch-class value rather than identity. Results produced by interval addition must compare equal to directly constructed pitch classes representing the same value.

General Compatibility Requirements

  • Every arithmetic result above must be an instance of the stated public type, with == comparing musical values rather than object identities.
  • Support for interval operands must coexist with the established integer arithmetic on Pitch and PitchClass.
  • Existing interval naming, pitch naming, conversion, note, key, and parsing behavior must not regress as a result of these changes.
