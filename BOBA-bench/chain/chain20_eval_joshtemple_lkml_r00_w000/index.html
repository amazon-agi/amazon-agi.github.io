Task: Implement a Lexer for LookML Tokenization

Overview

Implement a lexer (tokenizer) for parsing LookML source text. You must create two modules: lkml.tokens (containing token classes) and lkml.lexer (containing the Lexer class).

Module: lkml.tokens

Define token classes representing scanned pieces of source text. At minimum, provide the following classes:

  • LiteralToken — represents an unquoted literal value.
  • QuotedLiteralToken — represents a quoted literal value.

Each token must store the scanned string in a value attribute, accessible as token.value. A token should be constructed with its string value (e.g. LiteralToken("some_value")), such that token.value returns that exact string.

Module: lkml.lexer

Define a class Lexer with the following behavior.

Construction

Lexer(text) — constructed with a string of source text.

Attributes
  • index — an integer position marker into the source text. It must be a mutable public attribute (callers may set lexer.index directly before invoking scan methods). Its initial value on construction is unspecified by this task.
Method: scan_quoted_literal()

Scans a quoted literal value starting from the current index position. When called, index will already be positioned at the first character inside the opening quote (i.e. just past the opening ").

  • Consumes characters up to (but not including) the closing double-quote character ".
  • Returns a QuotedLiteralToken whose value is the string of characters between the current position and the closing quote.
  • The quoted content may contain characters that would otherwise be significant or illegal outside quotes, including :, {, }, spaces, and newline (\n) characters. All such characters are included verbatim in the returned value.

Example: given text "This is quoted text." with index set to 1, the returned token's value is This is quoted text.. Given text "This: is {quoted} \n text." with index set to 1, the returned token's value is This: is {quoted} \n text..

Method: scan_literal()

Scans an unquoted literal value starting from the current index position (by default at the beginning of the text).

  • Consumes consecutive non-whitespace characters.
  • Returns a LiteralToken whose value is the run of characters up to the first whitespace character (or end of text).
  • Stops at any whitespace, including spaces and newlines. Characters following the whitespace are not included.

Example: given text unquoted_literal, the returned token's value is unquoted_literal. Given text unquoted_literal \n and text following whitespace, the returned token's value is unquoted_literal.

Notes

  • Both scan methods return token objects (instances of the classes described above), not raw strings.
  • The value attribute contains only the scanned content, without surrounding quotes or trailing delimiters.

Task Specification: List Parsing Validation

Overview

You must ensure that the Parser class correctly rejects malformed lists during parsing. Specifically, the list-parsing logic must return None when a list is not well-formed with respect to comma placement.

Public API

The following must be importable and callable:

  • Module: lkml.parser
  • Class: lkml.parser.Parser
  • Constructor: Parser(stream) — accepts a single argument, a sequence (tuple) of token objects.
  • Method: Parser.parse_list() — takes no arguments (other than self) and returns either a parsed representation of the list, or None if the list is malformed.

The token types referenced below come from the tokens module and are used to build the input stream:

  • tokens.LiteralToken(value) — a literal string value (e.g., a field name or the list's key).
  • tokens.ValueToken() — separates a key from its value.
  • tokens.ListStartToken() — marks the beginning of a list.
  • tokens.ListEndToken() — marks the end of a list.
  • tokens.CommaToken() — separates elements within a list.
  • tokens.StreamEndToken() — marks the end of the token stream.

Input Structure

parse_list() operates over a token stream representing a key followed by a bracketed list of literal values. A well-formed list stream has this general shape:

LiteralToken(key), ValueToken(), ListStartToken(),
    <literal>, CommaToken(), <literal>, CommaToken(), ..., <literal>,
ListEndToken(), StreamEndToken()

That is: the list's elements are literals separated by commas, with a comma appearing between consecutive elements only.

Required Behavior

parse_list() must return None (indicating a parse failure) in the following malformed cases:

  1. Trailing comma: The list contains a comma immediately before the list-end marker, with no element following it. For example, a stream where the list body is a single literal followed by a comma and then the list-end token must yield None.

  2. Missing comma between elements: Two consecutive literal elements appear in the list body with no comma separating them. For example, a stream where one literal is followed by a comma and another literal, and that literal is immediately followed by a third literal (with no intervening comma) before the list-end token must yield None.

In both cases, the input stream is otherwise structurally complete (properly opened and closed with the appropriate start/end tokens and terminated by a stream-end token); the only defect is the incorrect comma placement.

Constraints

  • The behavior described applies only to comma-placement validation in parse_list(). Do not alter or add any other parsing behavior.

scan_sql_block returns a SqlBlockToken with value:

concat(${orders.order_id}, '|', ${orders__items.primary_key})

  3. ValueToken() — for the :
  4. SqlBlockToken(<sql body>) — the SQL body, captured per the SQL block rules above (trailing whitespace before ;; removed)
  5. SqlBlockEndToken() — for the ;;
  6. StreamEndToken()

Example: given input

sql_distinct_key: concat(${orders.order_id}, '|', ${orders__items.primary_key}) ;;

(
    StreamStartToken(),
    LiteralToken("sql_distinct_key"),

    SqlBlockEndToken(),

Background

Expression-block recognition must depend on the complete field key. Recognizing a block merely because the next literal begins with sql, html, or another reserved string incorrectly classifies ordinary keys and names, can consume the remainder of the input while searching for ;;, and prevents otherwise valid documents from loading.

Public API

The following public imports, names, and call forms must remain available:

  • Module lkml exposes class Lexer.

    • Lexer(text: str) accepts raw LookML source text.
    • Lexer.scan() scans the complete input and returns the ordered tokens as a tuple.

    • StreamEndToken(line: int)

    • LiteralToken(value: str, line: int), representing a bare key or value

Given a dictionary, serialize_dict produces a LookML block. The rules exercised are:

The name key becomes the block label

The value associated with the key "name" is used as the identifier that precedes the opening brace of the block. It is not rendered as an ordinary key-value pair inside the block.

For a dict whose "name" value is X, the block is structured as:

X: {
<body>
}
  • The block opens with the name value, followed by : { and a newline.
  • The closing brace } appears on its own line with no trailing newline after it.
Remaining keys become key-value pairs in the block body

Every other key (all keys except "name") is rendered, in the order they appear in the dict, as a line inside the block body. Each such line:

  • Is indented by exactly two spaces.
  • Has the form key: value followed by a single newline (\n).
Quoting of values

Whether a value is wrapped in double quotes depends on the key:

  • Unquoted keys: The keys from_field and to_field render their values with no quotes.

    • Example: {"name": "bind_filters", "from_field": "field_name", "to_field": "field_name"} produces:
      bind_filters: {
  from_field: field_name
  to_field: field_name
}

  • Quoted keys: The keys label and description render their values wrapped in double quotes (").

    • Example: {"name": "dimension", "label": "Dimension Name", "description": "A dimension description."} produces:
      dimension: {
  label: "Dimension Name"
  description: "A dimension description."
}

N: {

}

where:

  • Each body line is prefixed with two spaces and suffixed with a newline.

  • There is no trailing newline or whitespace after the final }.
