Task Specification: cli_helpers — a Package of CLI Helpers for Tabular Output

The job here is to build a Python package called cli_helpers that bundles utility helpers together with adapters for formatting tabular output. Each of the modules and public APIs laid out in the sections below must exist and must behave exactly as stated.

1. The module cli_helpers._compat

Define the name text_type, pointing at the string type Python uses to hold unicode text (i.e., str on Python 3, unicode on Python 2).

2. The module cli_helpers.utils

The functions described in this section need to be implemented.

bytes_to_string(value)
  • Should value be a byte string (bytes):
    • When decoding as UTF-8 text succeeds, return the resulting string.
    • When the bytes cannot be decoded as text (binary data), return a hexadecimal string representation that begins with 0x; for instance b'\xff' → '0xff'.
    • A byte string that decodes fine, such as b'foobar', gives 'foobar'.
  • When value is not a byte string, it is returned untouched (e.g., 'abc' → 'abc', 1 → 1).
to_string(value)
  • A byte string is decoded/converted into a text string (b'foo' → 'foo').
  • In every other case, what comes back is the value's string form (1 → '1', 2.33 → '2.33').
intlen(value)
  • For a string that represents a number, the result is the count of characters found before the decimal point.
  • '11.1' → 2, '1.1' → 1, '11' → 2.

3. The module cli_helpers.tabular_output.preprocessors

A preprocessor is called with (data, headers, **kwargs); here data is a list of rows, each row itself a list of cell values, and headers is a list. What every preprocessor hands back is a 2-tuple (data, headers) keeping the same structure. Rows and headers not changed in some other way keep their original values and their types.

convert_to_string(data, headers)

Every cell in data and every element in headers is to be put into its string form.

  • data=[[1, 'John'], [2, 'Jill']], headers=[0, 'name'] → ([['1', 'John'], ['2', 'Jill']], ['0', 'name']).
override_missing_value(data, headers, missing_value='', **kwargs)

A cell that holds None as its value must be replaced with missing_value. Headers stay as they were.

  • For missing_value='<EMPTY>', [[1, None], [2, 'Jill']] turns into [[1, '<EMPTY>'], [2, 'Jill']]; the headers are not modified.
bytes_to_string(data, headers)

The conversion performed by the utility utils.bytes_to_string (see there) is run over every cell in data. Headers stay untouched.

  • [[1, 'John'], [2, b'Jill']] → [[1, 'John'], [2, 'Jill']].
align_decimals(data, headers)

Within each column, the decimal numbers are right-aligned so that their integer parts line up, with spaces padded on the left as needed. Only columns/values that are decimal numbers are affected.

  • data=[[Decimal('200'), Decimal('1')], [Decimal('1.00002'), Decimal('1.0')]], headers=['num1','num2'] → ([['200', '1'], [' 1.00002', '1.0']], ['num1', 'num2']).
  • Note: how much padding a column receives comes from the widest integer part found in that column; the fractional parts show up exactly as they are. Values come out as strings.
  • When data=[] is empty, ([], headers) is returned with no changes.
quote_whitespaces(data, headers, quotestyle="'")

Any cell string that begins or ends with whitespace is to be wrapped in quote characters (single quote by default).

  • [[" before", "after "], [" both ", "none"]] → [["' before'", "'after '"], ["' both '", "'none'"]], headers stay the same.
  • For empty data=[], the result is ([], headers) with nothing altered.

adapter(data, headers, table_format='csv', **kwargs)

Produce the rows as text separated by a delimiter.

  • First comes a header line, then a line for every data row.
  • Every line terminates with \r\n (the final one included).
  • The default (table_format='csv' or left unspecified) is comma-delimited.
  • For table_format='tsv', the output is tab-delimited.

  • Example (tsv): identical data → letters\tnumber\r\nabc\t1\r\nd\t456\r\n.

What the function gives back is one string.

7. The module cli_helpers.tabular_output.vertical_table_adapter

vertical_table(data, headers, sep_title='{n}. row', sep_character='*', sep_length=27)

Present the rows in a vertical layout, with one field on each line.

  • Every row gets a separator line first, after which each field gets its own line of the shape name | value; name here is the header, and the header names are padded on the left to a single shared width (the width of the longest header) so that the | separators all line up.
  • A separator line consists of sep_length repetitions of sep_character, then [ <title> ], then another sep_length repetitions of sep_character. For row i (1-based), the <title> is obtained from sep_title by swapping the token {n} for the row number. Should sep_title contain no placeholder, the row number and the title are merged, and the title then reads <row_number>. <sep_title>.
  • A trailing newline finishes the output.

Examples showing the behavior:

Default call — data=[('hello', '123'), ('world', '456')], headers=('name', 'age'):

***************************[ 1. row ]***************************
name | hello
age  | 123
***************************[ 2. row ]***************************
name | world
age  | 456

(trailing newline included)

Customized — sep_title='person', sep_character='-', sep_length=5, data=[('john', '47'), ('jill', '50')], headers=('name', 'age'):

-----[ 1. person ]-----
name | john
age  | 47
-----[ 2. person ]-----
name | jill
age  | 50

(trailing newline included)

Notice that the separator titles come out as 1. row / 2. row in the default case and as 1. person / 2. person in the customized one: the prefix <n>. carrying the number is put in front of the title that was supplied.

The returned value is one string.

Task Description

Goal

Write (or modify) the quote_whitespaces function located in the module cli_helpers.tabular_output.preprocessors. The function identifies columns whose data includes whitespace and wraps every value belonging to each such column in a configurable quote string.

Public API

def quote_whitespaces(data, headers, quotestyle="'"):
    ...
  • It must be possible to import quote_whitespaces from cli_helpers.tabular_output.preprocessors.

Parameters

  • data: An iterable of rows; every row is an iterable of string field values.
  • headers: An iterable that holds the column headers.
  • quotestyle: The string placed before and after a value when it is quoted. It defaults to "'" (a single quote).

Return Value

Return a 2-tuple (data, headers) where:

  • data is a list of rows, each row being a list of field values, with column-based quoting applied.
  • headers is returned unchanged. Headers are not quoted, and they do not affect whether a data column gets quoted.

Behavior

Whitespace detection

Examine the field values in data for whitespace. A field is considered to contain whitespace if a single one of its characters is a whitespace character, no matter where in the value that character sits. Detection therefore covers leading, trailing, and interior whitespace.

Whitespace detection has to cover the full set of standard whitespace characters, including at minimum:

  • space (" ")
  • tab ("\t")
  • newline ("\n")
  • carriage return ("\r")
  • vertical tab ("\x0b")
  • form feed ("\x0c")
Column-based quoting

Whether quoting applies is determined per column, with the field's position within its row serving as the column index:

  • If a minimum of one value in a column contains whitespace, quotestyle must be prepended and appended to every value in that column. This also covers values in that column which themselves contain no whitespace.
  • If none of the values in a column contains whitespace, every value in that column stays as it is.

Put differently, whitespace decides which complete columns are quoted; the decision to quote is not made field by field.

Examples

Given:

data = [["\tbefore", "after \r"], ["\n both  ", "none"]]
headers = ['h1', 'h2']

the result is:

([
    ["'\tbefore'", "'after \r'"],
    ["'\n both  '", "'none'"],
], ['h1', 'h2'])

Both columns are chosen for quoting since each of them has at least one value that contains whitespace. As a result, "none" gets quoted too, despite having no whitespace itself.

For a case where only a single column is chosen:

data = [["alpha beta", "one"], ["gamma", "two"]]
headers = ['h1', 'h2']

the result is:

([["'alpha beta'", "one"], ["'gamma'", "two"]], ['h1', 'h2'])

The first column is quoted in its entirety because one of its values contains a space. The second column is left unquoted because it has no values containing whitespace.

Given empty data:

data = []
headers = ['h1', 'h2']

the result is:

([], ['h1', 'h2'])

Specification of the Task

Goal

Extend TabularOutputFormatter.format_output() with an optional preprocessing pipeline supplied by the caller, while all existing formatter selection, built-in preprocessing, keyword handling, and rendering behavior are preserved.

Public API

The class TabularOutputFormatter is still available from cli_helpers.tabular_output.output_formatter. In addition to all existing behavior, its format_output() method must support the following signature:

def format_output(self, data, headers, format_name=None, preprocessors=(), **kwargs):
    ...
The preprocessors argument

  • preprocessors is an iterable of callables, and its default is an empty tuple.

  • Each callable has this contract:

    preprocessor(data, headers, **kwargs) -> (data, headers)

  • A preprocessor may return replacement data and headers, or it may mutate the objects it receives and return them. In either case, the (data, headers) pair it returns serves as the input to the next preprocessing stage.

  • Providing caller preprocessors augments the selected format's existing built-in preprocessors; it does not replace or disable them.

Preprocessing Pipeline

For the output format that has been selected, processing must take place in exactly this order:

  1. Run the caller-supplied preprocessors, one time each, in the order they appear in the iterable.
  2. Run the built-in preprocessors of the selected format, one time each, in their existing registered order.
  3. The final transformed data and headers are then passed to the selected formatter for rendering.

Every stage's output must be fed forward to the stage that follows it. All additional formatting keyword arguments that are supplied to format_output() (such as missing_value) must be forwarded to every caller-supplied and built-in preprocessor. The existing forwarding of applicable keyword arguments to the selected formatter remains unchanged.

As a result, caller-supplied preprocessors operate on the values as originally passed to format_output(), before built-in operations such as missing-value substitution happen. A value that a built-in preprocessor introduces later must not retroactively be processed by a caller-supplied preprocessor that runs earlier.

If preprocessors is omitted or empty, the behavior must stay the same as before: only the built-in preprocessing pipeline of the selected format runs before rendering.

Rendering Compatibility

Existing rendering behavior stays unchanged. In particular:

  • With format_name='ascii', the result is an ASCII table that uses +, -, and | as border characters, with a header row and a separator between the headers and the data.
  • Each column is wide enough for its widest header or data cell, and there is one space of padding on each side of every cell value.
  • The missing_value keyword argument controls which value gets substituted for data cells whose value is None.
  • Existing format selection, built-in preprocessors, supported formats, and formatter-specific keyword behavior must continue to function.

Example

Suppose the following:

  • data = [['foo', None], ['hello!', 'hello']]
  • headers = 'ab'
  • format_name='ascii'
  • missing_value='hello'
  • a caller-supplied preprocessor that turns cells exactly equal to 'hello' into 'hello, world'

the caller preprocessor sees the original rows first. It changes only the original 'hello' literal and leaves None untouched. The built-in preprocessing of the ASCII format then replaces that None with the missing value 'hello'. The rendered output is:

+--------+--------------+
| a      | b            |
+--------+--------------+
| foo    | hello        |
| hello! | hello, world |
+--------+--------------+

So, the first-row value that was newly substituted remains hello, while the original second-row value becomes hello, world.
