  • The function must be importable as quote_whitespaces from cli_helpers.tabular_output.preprocessors.

Parameters

  • data: An iterable of rows, where each row is an iterable of string field values.
  • headers: An iterable containing the column headers.
  • quotestyle: The string to prepend and append when quoting a value. It defaults to "'" (a single quote).

Return Value

Return a 2-tuple (data, headers) where:

  • data is a list of rows, with each row represented as a list of field values after column-based quoting has been applied.
  • headers is returned unchanged. Headers are not quoted and do not determine whether a data column is quoted.

Behavior

Whitespace detection

Inspect field values in data for whitespace. A field contains whitespace if any one of its characters is a whitespace character, regardless of where that character occurs in the value. Detection therefore applies to leading, trailing, and interior whitespace.

Whitespace detection must recognize the full set of standard whitespace characters, including at minimum:

  • space (" ")
  • tab ("\t")
  • newline ("\n")
  • carriage return ("\r")
  • vertical tab ("\x0b")
  • form feed ("\x0c")
Column-based quoting

Quoting is selected independently for each column, using the field's position in its row as the column index:

  • If at least one value in a column contains whitespace, prepend and append quotestyle to every value in that column. This includes values in the selected column that do not themselves contain whitespace.
  • If no value in a column contains whitespace, leave every value in that column unchanged.

In other words, whitespace determines which entire columns are quoted; quoting is not decided separately for each individual field.

Examples

Given:

headers = ['h1', 'h2']

the result is:

([
    ["'\tbefore'", "'after \r'"],
    ["'\n both  '", "'none'"],
], ['h1', 'h2'])

Both columns are selected for quoting because each contains at least one whitespace-containing value. Consequently, "none" is also quoted even though it has no whitespace of its own.

For a case where only one column is selected:

data = [["alpha beta", "one"], ["gamma", "two"]]
headers = ['h1', 'h2']

the result is:

([["'alpha beta'", "one"], ["'gamma'", "two"]], ['h1', 'h2'])

The first column is quoted in full because one of its values contains a space. The second column remains unquoted because none of its values contains whitespace.

Public API

TabularOutputFormatter remains available from cli_helpers.tabular_output.output_formatter. Its format_output() method must support the following signature in addition to all existing behavior:

def format_output(self, data, headers, format_name=None, preprocessors=(), **kwargs):
    ...
preprocessors argument

  • preprocessors is an iterable of callables and defaults to an empty tuple.

  • Each callable has the contract:

    preprocessor(data, headers, **kwargs) -> (data, headers)

  • A preprocessor may return replacement data and headers or mutate and return the objects it receives. In either case, its returned (data, headers) pair is the input to the next preprocessing stage.

  • Supplying caller preprocessors augments the selected format's existing built-in preprocessors; it does not replace or disable them.

Preprocessing Pipeline

For the selected output format, processing must occur in this exact order:

  1. Run the caller-supplied preprocessors, once each and in their iterable order.
  2. Run the selected format's built-in preprocessors, once each and in their existing registered order.
  3. Pass the final transformed data and headers to the selected formatter for rendering.

The output of every stage must be fed forward to the next stage. All additional formatting keyword arguments supplied to format_output(), such as missing_value, must be forwarded to every caller-supplied and built-in preprocessor. Existing forwarding of applicable keyword arguments to the selected formatter remains unchanged.

Caller-supplied preprocessors therefore operate on the values as originally passed to format_output(), before built-in operations such as missing-value substitution. A value introduced later by a built-in preprocessor must not retroactively be processed by an earlier caller-supplied preprocessor.

When preprocessors is omitted or empty, behavior must remain the same as before: only the selected format's built-in preprocessing pipeline runs before rendering.

Existing rendering behavior is unchanged. In particular:

  • With format_name='ascii', the result is an ASCII table using +, -, and | border characters, with a header row and a separator between the headers and data.
  • Each column is wide enough for its widest header or data cell and has one space of padding on each side of every cell value.
  • The missing_value keyword argument controls the value substituted for data cells whose value is None.
  • Existing format selection, built-in preprocessors, supported formats, and formatter-specific keyword behavior must continue to work.
