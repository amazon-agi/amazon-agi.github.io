Add explicit text-encoding support to the local and S3 file handlers and propagate the configured encoding from the Scrapy start-URLs loader to whichever handler is selected. Preserve scheme dispatch, spider-attribute path formatting, custom handlers, S3 authentication, and text-stream behavior.

Public interfaces

The following interfaces are public:

  • spider_feeder.file_handler.local.open(file_path, encoding)
  • spider_feeder.file_handler.s3.open(uri, encoding)
  • spider_feeder.loaders.StartUrlsLoader, including StartUrlsLoader.from_crawler(crawler)

Every shipped or custom file-handler callable must accept the file path or URI as its first positional argument and an encoding keyword argument. The loader must always pass the encoding by name, as encoding=<resolved value>.

1. Local file handler

The spider_feeder.file_handler.local module must expose open(file_path, encoding).

  • file_path may be either a normal filesystem path or a URI beginning with file://.
  • If, and only if, the value begins with file://, remove that leading prefix before opening the file. For example, file:///tmp/input_urls.txt resolves to /tmp/input_urls.txt. A path with no scheme remains unchanged.
  • Open the resolved path as a text file through the module's builtins reference. The delegated call must be exactly builtins.open(resolved_path, encoding=encoding): the path is the sole positional argument, encoding is forwarded as a keyword argument, and no additional arguments are supplied.
  • Return the file object produced by builtins.open.

For example, local.open('file:///tmp/input_urls.txt', encoding='latin-1') must delegate as builtins.open('/tmp/input_urls.txt', encoding='latin-1').

2. S3 file handler

The spider_feeder.file_handler.s3 module must expose open(uri, encoding), accepting an s3:// URI and returning decoded text in an io.StringIO.

URI parsing
  • The URI host is the bucket name.
  • The URI path, without its leading /, is the object key. Thus, s3://bucket/blob.txt selects bucket bucket and key blob.txt. Nested key paths must remain intact after the one leading slash is removed.
  • A URI may contain credentials as user information in the form s3://key_id:secret@bucket/blob.txt. These values are authentication data and must not become part of the bucket or key.
Credential selection and client creation

Create the client through the botocore session's create_client method with service name 's3'. Credential precedence is as follows:

  1. When the URI contains key_id:secret, use those values and pass them as aws_access_key_id and aws_secret_access_key. URI credentials take precedence over project-setting credentials.
  2. When the URI has no embedded credentials, obtain the project settings through the module-level get_project_settings() callable and look up SPIDERFEEDER_AWS_ACCESS_KEY_ID and SPIDERFEEDER_AWS_SECRET_ACCESS_KEY. When configured, these fallback values must be passed to create_client as aws_access_key_id and aws_secret_access_key. A credential-free URI must not bypass this project-settings fallback.
  3. If neither URI nor project settings supply credentials, client creation may use botocore's normal credential discovery; no credential values should be invented.

The settings accessor must remain exposed at spider_feeder.file_handler.s3.get_project_settings, and fallback credential lookup must go through that callable. With selected credentials key_id and secret, the required client call is equivalent to session.create_client('s3', aws_access_key_id='key_id', aws_secret_access_key='secret').

Object retrieval and decoding
  • Call get_object with exactly the parsed bucket and key plus the requested response content encoding: Bucket=<bucket>, Key=<key>, and ResponseContentEncoding=<encoding>.
  • Read the bytes from the response's Body.
  • Decode those bytes using the same encoding argument.
  • Wrap the decoded string in io.StringIO and return it. Calling read() on the returned object must reproduce the decoded object content exactly.

For example, bytes encoded as iso-8859-1 for content containing http://vérystrangeurl.com must round-trip when encoding='iso-8859-1', and that same value must be sent as ResponseContentEncoding.

3. Start-URLs loader

StartUrlsLoader must be importable with from spider_feeder.loaders import StartUrlsLoader and usable as a Scrapy extension.

Settings

The loader recognizes these settings:

  • SPIDERFEEDER_INPUT_FILE — required path or URI of the text input file. If this setting is absent or has no configured value, StartUrlsLoader.from_crawler(crawler) must raise scrapy.exceptions.NotConfigured.
  • SPIDERFEEDER_INPUT_FILE_ENCODING — optional text encoding. Its default is 'utf-8'; a configured value such as 'latin-1' replaces that default.
  • SPIDERFEEDER_FILE_HANDLERS — optional mapping from URI scheme names to dotted callable paths. Its entries extend or override the built-in handler mapping.

The built-in scheme mapping is:

  • Empty scheme (''): spider_feeder.file_handler.local.open
  • file: spider_feeder.file_handler.local.open
  • s3: spider_feeder.file_handler.s3.open

A custom mapping such as {'s3': 'myproject.my_reader.open'} must replace the built-in S3 callable for that loader. Custom entries may also add handlers for other schemes. Values are resolved as dotted callable paths, and the custom callable follows the same (file_path, encoding=...) contract as the built-in handlers.

Lifecycle and loading behavior
  • from_crawler must register the loader for Scrapy's signals.spider_opened signal and return the configured loader instance. The input must be opened and loaded when that signal is received for the spider.
  • Before dispatch, format SPIDERFEEDER_INPUT_FILE with Python %()s mapping substitution using the spider's attributes. For example, '%(dir)s/%(input_file)s.txt' with spider.dir == '/tmp' and spider.input_file == 'spider_input' becomes /tmp/spider_input.txt.
  • Perform scheme selection using the formatted value. A formatted s3:// URI uses the S3 handler, a formatted file:// URI uses the local handler, and a formatted path with no URI scheme also uses the local handler.
  • Pass the formatted value itself, unchanged, as the handler's first positional argument. Scheme stripping belongs to the selected handler; for example, the loader passes file:///tmp/input_file.txt to the local handler rather than pre-stripping it.
  • Invoke the selected handler with the resolved encoding as a keyword argument. For example, the default call for a scheme-less local.txt is local.open('local.txt', encoding='utf-8'), while setting SPIDERFEEDER_INPUT_FILE_ENCODING to 'latin-1' changes it to local.open('local.txt', encoding='latin-1'). The same propagation rule applies to S3 and custom handlers.
  • Use the returned text file-like object as the URL source, read its content, split the text with str.splitlines(), and assign the resulting list to spider.start_urls. Thus, content https://url1.com\nhttps://url2.com produces ['https://url1.com', 'https://url2.com'].

Encoding compatibility

The complete path from loader configuration through handler invocation and file decoding must support at least:

  • 'utf-8', including its role as the loader default;
  • 'latin-1'; and
  • 'iso-8859-1', including non-ASCII S3 content.

Handlers return text streams, not undecoded byte streams. The loader therefore reads strings and must not apply an additional decode step.

  • Function: spider_feeder.store.file_handler.s3.open(uri, encoding=...)
    • Must accept an S3 URI as the first positional argument.
    • Must accept encoding as a keyword argument.
  • The module must expose get_project_settings, providing access to Scrapy project settings.
Credential fallback behavior

When open() is called without spider-feeder-specific AWS credentials being configured:

  1. Read the Scrapy project settings via get_project_settings().
  2. Use:
    • AWS_ACCESS_KEY_ID as the S3 client's aws_access_key_id
    • AWS_SECRET_ACCESS_KEY as the S3 client's aws_secret_access_key
  3. Create the S3 client with the equivalent of:
    • service name: "s3"
    • aws_access_key_id=<AWS_ACCESS_KEY_ID value>
    • aws_secret_access_key=<AWS_SECRET_ACCESS_KEY value>

For example, project settings containing:

{
    "AWS_ACCESS_KEY_ID": "some_key_id",
    "AWS_SECRET_ACCESS_KEY": "some_secret",
}

must result in an S3 client configured with those exact credential values.

S3 object request

For:

s3.open("s3://bucket/blob.txt", encoding="utf-8")

the handler must request the object using:

  • Bucket: "bucket"
  • Key: "blob.txt"
  • Response content encoding: "utf-8"

Existing spider-feeder-specific credential behavior must remain in place; Scrapy project credentials are the fallback when those credentials are not set.

Overview

Modify the file-opener functions in the spider_feeder package so they accept a Scrapy Settings object as a required keyword argument, and update the FileStore so it forwards its settings to whichever file opener it invokes. Credentials for S3 access must be read from the passed settings rather than from a globally-loaded project settings.

Required API and Behavior

1. Local file opener

Module: spider_feeder.store.file_handler.local

Provide a function:

def open(uri, *, encoding, settings)

Behavior:

  • Accepts a file path or a file://-scheme URI, an encoding keyword argument, and a settings keyword argument (a Scrapy Settings instance).
  • If the URI uses the file:// scheme, strip the scheme so that only the local filesystem path remains (e.g. file:///tmp/input_urls.txt → /tmp/input_urls.txt). A plain path without a scheme is used as-is.
  • Opens the resolved local path using the built-in open, passing only the path and the encoding keyword argument (the settings argument is accepted but not forwarded to the built-in open).
  • The built-in open must be referenced in a way that is patchable as spider_feeder.store.file_handler.local.builtins.open (i.e. import the builtins module and call builtins.open).
2. S3 file opener

Module: spider_feeder.store.file_handler.s3

Provide a function:

def open(uri, *, encoding, settings)

Behavior:

  • Accepts an s3://-scheme URI, an encoding keyword argument, and a settings keyword argument (a Scrapy Settings instance).
  • Parses the URI to extract the bucket name, the object key, and optional inline credentials of the form s3://key_id:secret@bucket/key.
  • Creates an S3 client via a botocore session's create_client('s3', ...).
  • Credential resolution:
    • If the URI contains inline credentials (key_id:secret@), use them: call create_client('s3', aws_access_key_id=<key_id>, aws_secret_access_key=<secret>).
    • Otherwise, read credentials from the passed settings using the keys SPIDERFEEDER_AWS_ACCESS_KEY_ID and SPIDERFEEDER_AWS_SECRET_ACCESS_KEY, and call create_client('s3', aws_access_key_id=<value>, aws_secret_access_key=<value>).
    • Credentials must be obtained only from the URI or from the passed settings; do not load or consult any global/project settings.
  • Retrieves the object via get_object with parameters Bucket=<bucket>, Key=<key>, and ResponseContentEncoding=<encoding>.
  • Reads the object body, decodes it using the given encoding, and returns the content wrapped in an in-memory text stream (io.StringIO), so the caller can .read() the full text.
3. FileStore

Module: spider_feeder.store.file_store — class FileStore.

Constructor signature (unchanged):

FileStore(uri, settings)

Behavior change:

  • When FileStore selects and invokes a file opener (based on the URI scheme / configured handlers), it must call that opener with the URI, the resolved encoding keyword argument, and additionally a settings keyword argument whose value is the exact Settings instance passed into the FileStore constructor.
  • The encoding is determined as before: default utf-8, overridable via the SPIDERFEEDER_INPUT_FILE_ENCODING setting.
  • Handler selection is unchanged: built-in schemes map to the local and S3 openers, and custom handlers can be registered via the SPIDERFEEDER_FILE_HANDLERS setting (a mapping of scheme → dotted path to an opener callable). Any custom opener will also be invoked with the settings keyword argument.
  • All existing parsing/iteration behavior (txt, csv, json formats; SPIDERFEEDER_INPUT_FIELD; SPIDERFEEDER_INPUT_FORMAT taking precedence over file extension) remains unchanged; only the addition of the settings keyword argument to the opener call is required here.

Summary of the call contract

Every file opener callable used by FileStore must accept this signature:

opener(uri, *, encoding, settings)

and FileStore must always supply all three when calling it.
