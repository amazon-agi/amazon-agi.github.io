Task: Implement a Tracker class for tracking TAP test results

Overview

Create a new module tap/tracker.py providing a Tracker class. This class is responsible for tracking test case outcomes grouped by test case class name, and it stores each outcome as a structured line record.

The Tracker class

Located at: tap.tracker.Tracker

It must be possible to construct the class with no arguments:

tracker = Tracker()
Attribute: _test_cases

After construction, the instance must expose an attribute _test_cases whose value is an empty dictionary ({}).

This dictionary maps a test case class name (a string) to a list of line records belonging to that class.

Method: _track(self, class_name)

This method ensures that the given class_name is registered in _test_cases. After _track is called with a class name that has not been seen before, _test_cases[class_name] must be an empty list ([]).

Line records

Each outcome that is recorded is stored as an object (a line record) with the following attributes:

  • status — a string that is either 'ok' or 'not ok'.
  • description — a string that describes the test.
  • directive — a string; it is empty ('') when there is no directive, or a formatted directive string when applicable.

These line records are appended to the list in _test_cases that corresponds to the relevant class name.

Method: add_ok(self, class_name, description)

The method records a successful outcome for the given class name. The line record that is appended must have:

  • status with a value equal to 'ok'
  • description with a value equal to the provided description
  • directive with a value equal to ''

The record is appended to _test_cases[class_name]; if the class entry does not already exist, it is created.

Method: add_not_ok(self, class_name, description)

The method records a failed outcome for the given class name. The line record that is appended must have:

  • status with a value equal to 'not ok'
  • description with a value equal to the provided description
  • directive with a value equal to ''

The record is appended to _test_cases[class_name]; if the class entry does not already exist, it is created.

Method: add_skip(self, class_name, description, reason)

The method records a skipped outcome for the given class name. The line record that is appended must have:

  • status with a value equal to 'ok'
  • description with a value equal to the provided description
  • directive with a value equal to '# SKIP ' followed by the provided reason (that is, for the reason 'a reason', the directive is '# SKIP a reason')

The record is appended to _test_cases[class_name]; if the class entry does not already exist, it is created.

Notes
  • In all of the add_* methods, if the class name has not yet been registered, calling the method must still succeed and cause the line record to be present in a list at _test_cases[class_name].
  • The line record must be an object whose status, description, and directive attributes are accessible via attribute access (dot notation).

Summary

Write a nose test plugin class called TAP inside the module tap/plugin.py (importable as from tap.plugin import TAP). The plugin's job is to record test results while distinguishing normal errors from skipped tests.

Public API

The TAP Class

The class lives at tap.plugin.TAP.

The following usage must be supported by the class:

  • Instantiation: TAP() has no required arguments.
  • Attribute enabled: an attribute that can be set (callers set plugin.enabled = True).
  • Method configure(self, options, conf): takes two positional arguments (both of which may be None). Invoking it prepares the plugin for use; this includes initializing a result tracker.
  • Attribute tracker: the plugin must expose a tracker attribute after configure has been called.
  • Method addError(self, test, err): records a result for the test passed to it.

How addError Behaves

The arguments passed to addError are:

  • test: a test object whose associated test case class name can be obtained from the object; for the tests exercised here, the relevant name is 'FakeTestCase'.
  • err: a 3-tuple (exc_type, exc_value, traceback) that describes an exception.

Behavior:

  1. Skip detection: If err[0] (the exception type) is unittest.SkipTest, the result must be recorded as a skipped test.   • Constructor Parser(): accepts no arguments.

The Parsing Behavior of parse_line

The parser handles lines that start with ok (a passing test result). For every line of this kind, the returned Result must have category == 'test' and a truthy ok.

The general form that is recognized is:

ok [<number>] [<description>] [# <directive>]
The test number
  • When a numeric value immediately follows ok (separated by whitespace), that value is the test number and must be stored in number as an int.
    • Example: 'ok 42 is the magic number.' → number == 42.
  • When no numeric value follows ok, number must be None.
    • Example: 'ok - This is a passing test line.' → number is None.
The description
  • The description is the text that comes after ok and the optional number.
  • When a number is present, the description is the text that remains after the number.
    • Example: 'ok 42 A passing test.' → description == 'A passing test.'.
  • A # character starts the directive/comment section. Any text located at or after the # is NOT part of the description. The description is the text that appears before the #, with the surrounding whitespace stripped.
    • Example: 'ok A description # Not part of description.' → description == 'A description'.
The directives

Directives show up after a #.

  • todo must be truthy when the directive section contains a TODO directive (the token TODO indicates it, case as shown).
    • Example: 'ok A description # TODO Not done' → todo is truthy.
  • skip must be truthy when the directive section contains a SKIP directive (the token SKIP indicates it, case as shown).
    • Example: 'ok A description # SKIP for now' → skip is truthy.

Package layout

  • tap/line.py, which defines Line and Result.
  • tap/parser.py, which defines Parser.
  • The tap package (and the location of its tests subpackage) must be importable so that from tap.line import Line, Result and from tap.parser import Parser succeed.
