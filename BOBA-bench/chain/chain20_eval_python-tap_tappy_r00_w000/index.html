01 Create a new module tap/tracker.py that provides a Tracker class. 442 words · source specification

Task: Implement a Tracker class for TAP test result tracking

Overview

Create a new module tap/tracker.py that provides a Tracker class. This class is responsible for tracking test case outcomes, grouped by test case class name, storing each outcome as a structured line record.

The Tracker class

Location: tap.tracker.Tracker

The class must be constructible with no arguments:

tracker = Tracker()
Attribute: _test_cases

After construction, the instance must expose an attribute _test_cases that is an empty dictionary ({}).

This dictionary maps a test case class name (a string) to a list of line records for that class.

Method: _track(self, class_name)

Ensures that the given class_name is registered in _test_cases. After calling _track with a class name that has not been seen before, _test_cases[class_name] must be an empty list ([]).

Line records

Each recorded outcome is stored as an object (a line record) with the following attributes:

  • status — a string, either 'ok' or 'not ok'.
  • description — a string describing the test.
  • directive — a string; empty ('') when there is no directive, or a formatted directive string when applicable.

These line records are appended to the list corresponding to the relevant class name in _test_cases.

Method: add_ok(self, class_name, description)

Records a successful outcome for the given class name. The appended line record must have:

  • status equal to 'ok'
  • description equal to the provided description
  • directive equal to ''

The record is appended to _test_cases[class_name], creating the class entry if it does not already exist.

Method: add_not_ok(self, class_name, description)

Records a failed outcome for the given class name. The appended line record must have:

  • status equal to 'not ok'
  • description equal to the provided description
  • directive equal to ''

The record is appended to _test_cases[class_name], creating the class entry if it does not already exist.

Method: add_skip(self, class_name, description, reason)

Records a skipped outcome for the given class name. The appended line record must have:

  • status equal to 'ok'
  • description equal to the provided description
  • directive equal to '# SKIP ' followed by the provided reason (i.e., for reason 'a reason' the directive is '# SKIP a reason')

The record is appended to _test_cases[class_name], creating the class entry if it does not already exist.

Notes
  • In all add_* methods, if the class name has not been registered yet, calling the method must still succeed and result in the line record being present in a list at _test_cases[class_name].
  • The line record must be an object whose attributes status, description, and directive are accessible via attribute access (dot notation).

Parsing Behavior of parse_line

The parser processes lines that begin with ok (a passing test result). For every such line, the returned Result must have category == 'test' and ok truthy.

The general form recognized is:

ok [<number>] [<description>] [# <directive>]
Test number
  • If a numeric value immediately follows ok (separated by whitespace), it is the test number and must be stored as an int in number.
    • Example: 'ok 42 is the magic number.' → number == 42.
  • If no numeric value follows ok, number must be None.
    • Example: 'ok - This is a passing test line.' → number is None.
Description
  • The description is the text following ok and the optional number.
  • If a number is present, the description is the remaining text after the number.
    • Example: 'ok 42 A passing test.' → description == 'A passing test.'.
  • A # character begins a directive/comment section. Any text at or after the # is NOT part of the description. The description is the text before the #, with surrounding whitespace stripped.
    • Example: 'ok A description # Not part of description.' → description == 'A description'.
Directives

Directives appear after a #.

  • todo must be truthy when the directive section contains a TODO directive (indicated by the token TODO, case as shown).
    • Example: 'ok A description # TODO Not done' → todo is truthy.
  • skip must be truthy when the directive section contains a SKIP directive (indicated by the token SKIP, case as shown).
    • Example: 'ok A description # SKIP for now' → skip is truthy.

Package Structure

  • tap/line.py defining Line and Result.
  • tap/parser.py defining Parser.
  • The tap package (and its tests subpackage location) must be importable such that from tap.line import Line, Result and from tap.parser import Parser succeed.
