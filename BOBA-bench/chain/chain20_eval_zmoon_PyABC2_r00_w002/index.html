Overview

PyABC2 models pitches and notes parsed from ABC notation. This task corrects accidental-spelling retention for the public Note.from_abc(...) API. A Note returned by this parser must retain the notated pitch letter and the multiplicity of any explicitly written sharp or flat, rather than retaining only the chromatic value and later choosing a simpler enharmonic name.

This is a spelling correction, not a change to the note's sounding pitch, octave, or duration.

Required Public Behavior

Note.from_abc must retain the parsed spelling

When Note.from_abc(abc, ...) parses a valid ABC note with explicit accidental marks, the returned Note must preserve that spelling in its pitch identity and string representation. ABC accidentals are represented in the library's ASCII pitch-name form as follows:

  • ^ becomes #.
  • ^^ becomes ##.
  • _ becomes b.
  • __ becomes bb.
  • With no accidental, no accidental character is added.

The input letter is rendered uppercase in the library's pitch-name format, but its diatonic identity must remain the same. Each explicitly written sharp or flat contributes one corresponding character. The result must not be respelled as another letter merely because that letter is enharmonically equivalent.

The retained spelling is part of the returned Note, not merely an unrelated formatting substitution. Existing pitch-name and pitch-class views of that parsed note must therefore remain consistent with the retained spelling. In particular, viewing the parsed note as a pitch class must not turn an explicitly notated F## into G. The primary entry point for this requirement is Note.from_abc; support for spelling on an independently constructed Pitch or PitchClass is not sufficient if ABC parsing discards it.

String format

str(note) for a parsed note continues to use this format:

<letter><accidental(s)><octave>_<duration>

where:

  • <letter> is the uppercase notated pitch letter.
  • <accidental(s)> contains the retained ASCII accidental characters, including repeated characters for double accidentals.
  • <octave> is the computed integer octave.
  • <duration> is the computed fractional duration in numerator/denominator form.
Normative double-sharp example

For the ABC note ^^f',,3:

  • ^^ explicitly spells a double sharp.
  • The notated base letter is F.
  • Existing octave rules produce octave 4.
  • Existing duration rules produce duration 3/8.

Therefore:

str(Note.from_abc("^^f',,3")) == "F##4_3/8"

Although F##4 has the same chromatic pitch as G4, the result must remain F##4_3/8; it must not become G4_3/8.

Compatibility Requirements

All other parsing and conversion behavior must remain unchanged. In particular, these existing results must continue to hold:

str(Note.from_abc("_B,2,")) == "Bb3_1/4"
str(Note.from_abc("^f")) == "F#5_1/8"
str(Note.from_abc("C/")) == "C4_1/16"

The correction must not alter:

  • chromatic pitch-value calculations;
  • octave calculation from letter case, commas, and apostrophes;
  • duration calculation or fraction formatting;
  • existing handling of single accidentals or notes without accidentals;
  • existing key-aware parsing behavior; or
  • canonical naming behavior for values that do not carry an explicitly retained spelling.

Scope

The required change is limited to preserving accidental spelling on notes produced from ABC notation, with double sharps as the motivating case and the same character-for-character multiplicity rule applying to explicit sharps and flats generally. No new public API or signature change is required, and chromatic values must not be globally forced to use the spelling from the example.

Core Concept: Name Preservation

Each of the three classes may carry an explicitly spelled name. When an object is constructed from a name (or from another object that has a name), that spelling must be carried through subsequent conversions rather than being normalized to a default enharmonic spelling.

The key distinction:

  • A PitchClass constructed directly from an integer value uses a default spelling (sharps).
  • A PitchClass, Pitch, or Note constructed from an explicit name (or converted from an object that carries an explicit name) uses that explicit spelling.

Classes and API

PitchClass

Represents a pitch class (an integer 0–11, where 0 = C), optionally with a spelled name.

  • PitchClass(value: int) — construct from an integer pitch-class value. Its name uses the default sharp spelling. For example, PitchClass(1).name == "C#".
  • PitchClass.from_name(name: str) -> PitchClass — construct from a spelled name. The resulting object's name equals the given spelling.
