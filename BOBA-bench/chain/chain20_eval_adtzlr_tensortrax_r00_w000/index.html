Objective

Support evaluation of a scalar-valued matrix function and its first and second derivatives when the input has no trailing axes, while preserving the established behavior of calls that omit ntrax.

Public API

The top-level tensortrax module must expose the following callable factories with an optional ntrax argument:

  • tensortrax.function(fun, ntrax=0)
  • tensortrax.gradient(fun, ntrax=0)
  • tensortrax.hessian(fun, ntrax=0)

The forms above show the required explicit ntrax=0 calls. Omitting the optional argument has the distinct compatibility behavior described below. Each factory must return a callable that accepts a NumPy matrix or matrix-field argument.

The returned callables have these result protocols:

  • function(fun, ...)(F) returns the function value.
  • gradient(fun, ...)(F) returns exactly (gradient, value).
  • hessian(fun, ...)(F) returns exactly (hessian, gradient, value).

The tensortrax.math module must expose:

  • tensortrax.math._eye(array)
  • tensortrax.math.trace(value)
  • tensortrax.math.det(value)

These operations must remain usable both to construct matrix inputs and inside functions evaluated through the three factories.

Trailing-axis semantics

ntrax denotes how many final input axes are trailing axes rather than differentiated matrix axes.

  • An explicit ntrax=0 means that the input has no trailing axes.
  • When ntrax is omitted, the established effective default remains two trailing axes. Omission must not be treated as explicit ntrax=0.

Explicit no-trailing-axis behavior

All three factories must support a scalar-valued function of one 3 x 3 NumPy array when called with ntrax=0.

For example:

import numpy as np
import tensortrax


def fun(F):
    C = F.T() @ F
    I1 = tensortrax.math.trace(C)
    J = tensortrax.math.det(F)
    return I1 * J - 3


dudX = np.arange(9).reshape(3, 3) / 10
F = tensortrax.math._eye(dudX) + dudX

Construction of F must succeed. The differentiable argument passed to fun must support the method-form transpose F.T(), matrix multiplication, trace, det, multiplication, and scalar subtraction used by this expression.

All of the following must execute without raising an exception:

value = tensortrax.function(fun, ntrax=0)(F)
gradient, value = tensortrax.gradient(fun, ntrax=0)(F)
hessian, gradient, value = tensortrax.hessian(fun, ntrax=0)(F)

Apart from successful evaluation and the required two-item and three-item return protocols, no particular numerical values or output shapes are required for this explicit ntrax=0 scenario.

Compatibility when ntrax is omitted

For a matrix field of shape (3, 3, 8, 50), the first two axes are matrix axes and the final axes of shape (8, 50) are trailing axes. tensortrax.math._eye must remain usable with such a field so that adding it to the field constructs same-shaped matrix data.

Given a supported scalar-valued matrix function and such an input F, calls that omit ntrax must behave as follows:

value_from_function = tensortrax.function(fun)(F)
gradient_from_gradient, value_from_gradient = tensortrax.gradient(fun)(F)
hessian, gradient_from_hessian, value_from_hessian = tensortrax.hessian(fun)(F)

The result shapes must be:

  • Each function-value result: (8, 50).
  • Each gradient result: (3, 3, 8, 50).
  • The Hessian result: (3, 3, 3, 3, 8, 50).

Results repeated across the three evaluation paths must be numerically consistent:

  • value_from_function, value_from_gradient, and value_from_hessian must agree to normal NumPy floating-point tolerance.
  • gradient_from_gradient and gradient_from_hessian must agree to normal NumPy floating-point tolerance.

This compatibility behavior must continue to support established scalar matrix expressions composed from existing tensor operations, including F.T() @ F, trace, det, powers, sqrt, symmetric eigenvalue evaluation, and reductions such as sum.

Task Specification: Tensor-based Automatic Differentiation Library

Overview

Implement a Python package named tensortrax that provides forward-mode automatic differentiation over tensor-valued functions. The package must expose a top-level module (imported as tensortrax) and a submodule for mathematical operations (imported as tensortrax.math).

Package Structure and Public API

tensortrax (top-level module)

Must expose the following three functions:

  • tensortrax.function(fun, ntrax=0)
  • tensortrax.gradient(fun, ntrax=0)
  • tensortrax.hessian(fun, ntrax=0)

Each of these is a higher-order function: it takes a scalar-valued function fun and an integer keyword argument ntrax, and returns a new callable. That returned callable accepts a single NumPy array argument (a tensor field) and returns evaluated results as described below.

  • fun is a user-supplied function that accepts a tensor (represented via this library's differentiable tensor type) and returns a scalar quantity (also of the library's tensor type).
  • ntrax (number of "trailing axes") specifies how many trailing dimensions of the input array are treated as batch/field axes that are not differentiated over. The leading dimensions form the actual tensor operand.
tensortrax.math (submodule)

Must expose the following operations, each operating on the library's differentiable tensor type (and, where sensible, plain arrays):

  • tensortrax.math.sum(x) — sum over the tensor's tensor-axes, returning a scalar-like tensor.
  • tensortrax.math.trace(x) — trace of a second-order tensor.
  • tensortrax.math.det(x) — determinant of a second-order tensor.
  • tensortrax.math.eigvalsh(x) — eigenvalues of a symmetric second-order tensor.
  • tensortrax.math.transpose(x) OR a .T() method on the tensor type — transpose of a second-order tensor. (The tensor type must support a callable .T() transpose method; a matrix-multiply operator @ must also be supported between tensors.)
  • tensortrax.math._eye(x) — given an array x whose leading two axes are square (shape (n, n, ...)), returns an identity tensor broadcast to match the trailing shape of x.

The differentiable tensor type must support the arithmetic needed by the functions below: element-wise power (**), multiplication and division by scalars, subtraction, addition, matrix multiplication (@), and the transpose method .T().

Input / Output Conventions

The input to the returned callables is a NumPy array representing a field of second-order tensors. With ntrax=2, an input of shape (3, 3, a, b) represents a 3×3 tensor at each of the a×b field points. The leading axes (3, 3) are the tensor axes; the trailing axes (a, b) are field axes.

For an input F of shape (3, 3, a, b) with ntrax=2:

  • tensortrax.function(fun, ntrax=2)(F) returns the scalar function value evaluated at each field point: an array of shape (a, b).

  • tensortrax.gradient(fun, ntrax=2)(F) returns a tuple (dWdF, W) where:

    • dWdF is the first derivative of the scalar output with respect to the input tensor, shape (3, 3, a, b).
    • W is the scalar function value, shape (a, b).

  • tensortrax.hessian(fun, ntrax=2)(F) returns a tuple (d2WdF2, dWdF, W) where:

    • d2WdF2 is the second derivative with respect to the input tensor, shape (3, 3, 3, 3, a, b).
    • dWdF is the first derivative, shape (3, 3, a, b).
    • W is the scalar function value, shape (a, b).
Consistency Requirements

For the same fun and input:

  • The scalar value returned by function, the w/W returned by gradient, and the W returned by hessian must all be numerically equal.
  • The first derivative dwdf returned by gradient and the dWdF returned by hessian must be numerically equal.

Functions That Must Be Supported

The following two user functions must work correctly through function, gradient, and hessian. They rely on the math operations above.

Neo-Hookean type function (uses transpose/.T(), @, trace, det):

def neo_hooke(F, mu=1):
    C = F.T() @ F
    I1 = tm.trace(C)
    J = tm.det(F)
    return mu / 2 * (J ** (-2 / 3) * I1 - 3)

Ogden type function (uses transpose/.T(), @, eigvalsh, sum, power):

def ogden(F, mu=1, alpha=2):
    C = F.T() @ F
    λ = tm.eigvalsh(C) ** (1 / 2)
    return tm.sum(1 / alpha * (λ ** alpha - 1))

Both must produce correct scalar values and correct first and second derivatives with the shapes specified above.

Edge Case: Repeated Eigenvalues

The eigenvalue-based path (eigvalsh and its use in functions like ogden) must remain numerically stable when the input tensor has repeated (degenerate) eigenvalues. Specifically, when the input tensor is the identity (e.g. F equal to a 3×3 identity broadcast over field axes), computing the hessian of the Ogden-type function must produce finite results: none of W, dWdF, or d2WdF2 may contain NaN values.

Notes

  • Derivatives are with respect to the full second-order input tensor, so first derivatives carry the two tensor axes of the input, and second derivatives carry four tensor axes.
  • All results must be plain NumPy arrays with exactly the shapes described.
  • Field (trailing) axes of size 1 must be preserved (e.g. input (3, 3, 1, 1) yields scalar value (1, 1), gradient (3, 3, 1, 1), hessian (3, 3, 3, 3, 1, 1)).

    • Tensor objects returned/consumed by these operations must support:

      • @ — matrix/tensor multiplication.

      • .sum(...) (or an equivalent reduction) usable to sum over eigenvalues.

The core requirement concerns tm.eigvalsh (eigenvalues of a symmetric tensor) and everything built on it. The gradient and Hessian obtained by differentiating a function that uses eigvalsh must be correct and finite (no NaNs) even when the input tensor has repeated (degenerate) eigenvalues.

Concretely, consider two mathematically equivalent formulations of the same scalar quantity applied to a deformation-gradient-like tensor F:

  1. An invariant-based formulation:

    • Compute C = F.T() @ F.
    • Compute I1 = tm.trace(C) and J = tm.det(F).
    • Return (J ** (-2/3) * I1 - 3) / 2.

  2. An eigenvalue-based formulation:

    • Compute C = F.T() @ F.
    • Compute the eigenvalues wC = tm.eigvalsh(C).
    • Compute principal stretches λ = sqrt(wC) and J = product of λ.
    • Form a value equivalent to (sum over i of (J**(-2/3) * λ_i**2) - 3) / 2 (an Ogden-type strain energy with alpha=2, mu=1, that reduces to the same neo-Hookean expression above).

For any input F — including the identity tensor (where all three eigenvalues of C are equal, i.e. fully repeated) and near-identity tensors where only some eigenvalues coincide — differentiating both formulations with tensortrax.hessian must yield:

  • The same scalar value W.
  • The same gradient dWdF.
  • The same Hessian d2WdF2.

The results must agree numerically (within standard floating-point tolerance) and must contain no NaN values. Prior to the fix, the eigenvalue-based path produced NaNs / incorrect derivatives in the repeated-eigenvalue case; the corrected eigvalsh (and its derivative computation) must handle the degenerate/repeated-eigenvalue case so the two formulations match.

Input Details

  • F is a NumPy array shaped as a batch of 3×3 tensors with trailing/batch axes. For example, a 3×3 identity tensor with two trailing singleton axes has shape (3, 3, 1, 1), differentiated with ntrax=2.
  • Inputs to test against include the exact identity (all eigenvalues equal) and a perturbed identity where one diagonal entry differs (e.g. F[2,2] = 2, giving a partial degeneracy among the remaining eigenvalues).

Success Criterion

For both the identity and the perturbed-identity inputs, the value, gradient, and Hessian computed from the eigenvalue-based formulation must equal those from the invariant-based formulation, with no NaNs anywhere in any of the three outputs.
