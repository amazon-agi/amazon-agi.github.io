Task Description

Goal

Make it possible to evaluate a scalar-valued matrix function together with its first and second derivatives for an input that has no trailing axes, while the established behavior of calls that omit ntrax is preserved.

Public Interface

The top-level tensortrax module must expose the following callable factories, each of which takes an optional ntrax argument:

  • tensortrax.function(fun, ntrax=0)
  • tensortrax.gradient(fun, ntrax=0)
  • tensortrax.hessian(fun, ntrax=0)

The forms above are the required explicit calls with ntrax=0. Omitting the optional argument leads to the distinct compatibility behavior described below. Each factory must return a callable that accepts a NumPy matrix or a matrix-field argument.

The callables returned by these factories have the following result protocols:

  • function(fun, ...)(F) returns the value of the function.
  • gradient(fun, ...)(F) returns exactly (gradient, value).
  • hessian(fun, ...)(F) returns exactly (hessian, gradient, value).

The tensortrax.math module must expose the following:

  • tensortrax.math._eye(array)
  • tensortrax.math.trace(value)
  • tensortrax.math.det(value)

These operations must remain usable both for building matrix inputs and inside functions that are evaluated through the three factories.

Semantics of trailing axes

ntrax states how many of the final input axes count as trailing axes rather than differentiated matrix axes.

  • An explicit ntrax=0 indicates that the input has no trailing axes.
  • If ntrax is omitted, the established effective default continues to be two trailing axes. Omitting it must not be handled as an explicit ntrax=0.

Behavior when no trailing axes are specified explicitly

All three factories must support a scalar-valued function of a single 3 x 3 NumPy array when they are called with ntrax=0.

For example:

import numpy as np
import tensortrax


def fun(F):
    C = F.T() @ F
    I1 = tensortrax.math.trace(C)
    J = tensortrax.math.det(F)
    return I1 * J - 3


dudX = np.arange(9).reshape(3, 3) / 10
F = tensortrax.math._eye(dudX) + dudX

Building F must succeed. The differentiable argument that is passed to fun must support the method-form transpose F.T(), matrix multiplication, trace, det, multiplication, and the scalar subtraction that this expression uses.

The following must all execute without raising an exception:

value = tensortrax.function(fun, ntrax=0)(F)
gradient, value = tensortrax.gradient(fun, ntrax=0)(F)
hessian, gradient, value = tensortrax.hessian(fun, ntrax=0)(F)

For this explicit ntrax=0 scenario, apart from successful evaluation and the required two-item and three-item return protocols, no particular numerical values or output shapes are required.

Compatibility behavior when ntrax is omitted

In a matrix field whose shape is (3, 3, 8, 50), the first two axes act as matrix axes, and the final axes, of shape (8, 50), are the trailing axes. tensortrax.math._eye must remain usable with such a field, so that adding it to the field builds matrix data of the same shape.

Given a supported scalar-valued matrix function together with an input F of this kind, calls that omit ntrax must behave as follows:

value_from_function = tensortrax.function(fun)(F)
gradient_from_gradient, value_from_gradient = tensortrax.gradient(fun)(F)
hessian, gradient_from_hessian, value_from_hessian = tensortrax.hessian(fun)(F)

The shapes of the results must be:

  • Each function-value result: (8, 50).
  • Each gradient result: (3, 3, 8, 50).
  • The result of the Hessian: (3, 3, 3, 3, 8, 50).

Results that are repeated across the three evaluation paths must be numerically consistent:

  • value_from_function, value_from_gradient, and value_from_hessian must agree within normal NumPy floating-point tolerance.
  • gradient_from_gradient and gradient_from_hessian must agree within normal NumPy floating-point tolerance.

This compatibility behavior must continue to support established scalar matrix expressions assembled from existing tensor operations, including F.T() @ F, trace, det, powers, sqrt, symmetric eigenvalue evaluation, and reductions such as sum.

Task Specification: Automatic Differentiation Library for Tensors

Overview

A Python package called tensortrax is to be implemented; it provides forward-mode automatic differentiation for tensor-valued functions. Two things must be exposed by the package: a top-level module, imported as tensortrax, and a submodule for mathematical operations, imported as tensortrax.math.

Package Layout and Public Interface

tensortrax (top-level module)

Three functions must be exposed here:

  • tensortrax.function(fun, ntrax=0)
  • tensortrax.gradient(fun, ntrax=0)
  • tensortrax.hessian(fun, ntrax=0)

Every one of the three is a higher-order function: handed a scalar-valued function fun plus an integer keyword argument ntrax, it returns a new callable. The callable that comes back accepts one argument — a single NumPy array, namely a tensor field — and returns the evaluated results set out below.

  • fun is supplied by the user; it accepts a tensor — represented by this library's differentiable tensor type — and returns a scalar quantity, which likewise has the library's tensor type.
  • ntrax (number of "trailing axes") states how many of the input array's trailing dimensions act as batch/field axes that are not differentiated over; the actual tensor operand is formed by the leading dimensions.
tensortrax.math (submodule)

Exposure is required for the operations listed below; every one of them works on the library's differentiable tensor type (and, where sensible, on plain arrays):

  • tensortrax.math.sum(x) — sums across the tensor's tensor-axes; the result is a scalar-like tensor.
  • tensortrax.math.trace(x) — calculates the trace of a second-order tensor.
  • tensortrax.math.det(x) — delivers the determinant of a second-order tensor.
  • tensortrax.math.eigvalsh(x) — produces the eigenvalues of a second-order tensor that is symmetric.
  • either tensortrax.math.transpose(x) or a .T() method on the tensor type — gives the transpose of a second-order tensor. (A .T() transpose method that is callable must be supported by the tensor type; the matrix-multiply operator @ must be supported between tensors as well.)
  • tensortrax.math._eye(x) — accepts an array x whose two leading axes are square (shape (n, n, ...)) and returns an identity tensor that has been broadcast so as to match the trailing shape of x.

Whatever arithmetic the functions below rely on must be supported by the differentiable tensor type: element-wise power (**), multiplication and division by scalars, subtraction, addition, matrix multiplication (@), and the transpose method .T().

Input and Output Conventions

Each callable handed back takes as its input a NumPy array that describes a field of second-order tensors. For ntrax=2, an input of shape (3, 3, a, b) stands for a 3×3 tensor located at each of the a×b field points. The leading axes (3, 3) play the role of tensor axes; the trailing axes (a, b) play the role of field axes.

Now take an input F with shape (3, 3, a, b) and ntrax=2:

  • tensortrax.function(fun, ntrax=2)(F) returns an array of shape (a, b): the value of the scalar function evaluated at each field point.

  • tensortrax.gradient(fun, ntrax=2)(F) returns the tuple (dWdF, W); within this tuple:

    • dWdF is the first derivative of the scalar output, taken with respect to the input tensor; its shape is (3, 3, a, b).
    • W is the scalar function value; its shape is (a, b).

  • tensortrax.hessian(fun, ntrax=2)(F) returns the tuple (d2WdF2, dWdF, W); within this tuple:

    • d2WdF2 is the second derivative, taken with respect to the input tensor; its shape is (3, 3, 3, 3, a, b).
    • dWdF is the first derivative; its shape is (3, 3, a, b).
    • W is the scalar function value; its shape is (a, b).
Consistency Between Results

With one and the same fun and input:

  • the scalar value that function returns, the w/W that gradient returns, and the W that hessian returns must all be numerically equal;
  • the dWdF that hessian returns and the first derivative dwdf that gradient returns must be numerically equal.

User Functions That Must Be Supported

Through function, gradient, and hessian, both user functions listed below must work correctly; each of them depends on the math operations above.

Neo-Hookean type function (relies on transpose/.T(), @, trace, det):

def neo_hooke(F, mu=1):
    C = F.T() @ F
    I1 = tm.trace(C)
    J = tm.det(F)
    return mu / 2 * (J ** (-2 / 3) * I1 - 3)

Ogden type function (relies on transpose/.T(), @, eigvalsh, sum, power):

def ogden(F, mu=1, alpha=2):
    C = F.T() @ F
    λ = tm.eigvalsh(C) ** (1 / 2)
    return tm.sum(1 / alpha * (λ ** alpha - 1))

In both cases, correct scalar values and correct first and second derivatives must be produced, with shapes matching those specified above.

Edge Case: Repeated Eigenvalues

Numerical stability must be preserved by the eigenvalue-based path (eigvalsh, along with its use inside functions such as ogden) whenever the input tensor has repeated (degenerate) eigenvalues. Concretely: let the input tensor be the identity (e.g. F being a 3×3 identity broadcast across the field axes). Computing the hessian of the Ogden-type function must then produce finite results — NaN values may appear in none of W, dWdF, or d2WdF2.

Additional Notes

  • Differentiation happens with respect to the full second-order input tensor; consequently, the two tensor axes of the input are carried by first derivatives, and four tensor axes are carried by second derivatives.
  • All of the results must be plain NumPy arrays, with shapes exactly as described.
  • Axes of size 1 that sit in trailing (field) position must be preserved (e.g. an input (3, 3, 1, 1) yields a scalar value (1, 1), a gradient (3, 3, 1, 1), and a hessian (3, 3, 3, 3, 1, 1)).

      • F.T() — the transpose.
      • @ — matrix/tensor multiplication.
      • Arithmetic involving scalars and other tensors: **, *, +, -, /.
      • .sum(...) (or an equivalent reduction) that can be used to sum over the eigenvalues.

The core requirement is about tm.eigvalsh (eigenvalues of a symmetric tensor) and everything built on top of it. Differentiating a function that uses eigvalsh must give a gradient and Hessian that are correct and finite (no NaNs) even when the input tensor has repeated (degenerate) eigenvalues.

Concretely, take two mathematically equivalent formulations of the same scalar quantity, applied to a deformation-gradient-like tensor F:

  1. An invariant-based formulation:

    • Build C = F.T() @ F.
    • Evaluate I1 = tm.trace(C) and J = tm.det(F).
    • Return (J ** (-2/3) * I1 - 3) / 2.

  2. An eigenvalue-based formulation:

    • Build C = F.T() @ F.
    • Evaluate the eigenvalues wC = tm.eigvalsh(C).
    • Form the principal stretches λ = sqrt(wC) and J = product of λ.
    • Assemble a value equivalent to (sum over i of (J**(-2/3) * λ_i**2) - 3) / 2 (an Ogden-type strain energy with alpha=2, mu=1, reducing to the same neo-Hookean expression above).

For any input F, including the identity tensor (where all three eigenvalues of C are equal, i.e. fully repeated) and near-identity tensors in which only some eigenvalues coincide, differentiating both formulations with tensortrax.hessian must yield:

  • The same scalar value W.
  • The same gradient dWdF.
  • The same Hessian d2WdF2.

Numerically, the results must agree (within standard floating-point tolerance) and must contain no NaN values. Before the fix, the eigenvalue-based path produced NaNs / incorrect derivatives in the repeated-eigenvalue case; the corrected eigvalsh (and its derivative computation) must handle the degenerate/repeated-eigenvalue case so that the two formulations match.

Details of the Inputs

  • F is a NumPy array whose shape is a batch of 3×3 tensors with trailing/batch axes. For example, a 3×3 identity tensor with two trailing singleton axes has shape (3, 3, 1, 1) and is differentiated with ntrax=2.
  • The inputs to test against include the exact identity (all eigenvalues equal) and a perturbed identity in which one diagonal entry differs (e.g. F[2,2] = 2, which leaves a partial degeneracy among the remaining eigenvalues).

Criterion for Success

For both the identity and the perturbed-identity inputs, the value, gradient, and Hessian computed from the eigenvalue-based formulation must equal those computed from the invariant-based formulation, and there must be no NaNs anywhere in any of the three outputs.
