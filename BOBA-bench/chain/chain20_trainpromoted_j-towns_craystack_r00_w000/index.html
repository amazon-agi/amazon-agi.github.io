craystack.craystack Module

Codecs are represented as a pair (append, pop):

  • append(message, data) — Takes a message and some data, encodes the data onto the message, and returns the updated message.
  • pop(message) — Takes a message and returns a tuple (message, data), where message is the message with the top item removed and data is the decoded data.
Codec Round-Trip Behavior

For any codec (append, pop) and any valid data:

  1. Starting from a fresh message produced by vrans.x_init(head_shape),
  2. Appending data produces a new message,

There is no separate step that derives an output shape from the head shape; pop operates on a message and needs no shape argument.

  • The append and pop functions must satisfy the round-trip inverse property described above for the codecs provided.

Task: Implement a substack codec combinator

Context

The codebase implements entropy codecs operating on "messages". A message is a pair (head, tail):

  • head is a structured collection (in general a nested/array structure) representing the mutable working portion of the ANS state.
  • tail is the compressed stream portion.

A codec is a pair of functions (append, pop):

  • append(message, data) -> message encodes data into the message.
  • pop(message) -> (message, data) decodes data from the message.

These functions must be inverses of one another: popping immediately after appending the same data returns the original message and the original data.

You must add a new combinator, substack, to the craystack package. It must be accessible as craystack.substack (i.e. importable via the package's top-level namespace, the same place craystack.repeat and craystack.Uniform live).

substack(codec, view_fun)

Signature: substack(codec, view_fun) returns a codec, i.e. a pair (append, pop).

Parameters:

  • codec: an inner codec (inner_append, inner_pop) that operates on messages.
  • view_fun: a function that, given a message head, returns a view into that head — a sub-portion of the head structure on which the inner codec should operate.

Semantics:

substack produces a codec that runs the inner codec against a restricted "view" of the message head rather than the whole head. The view_fun selects which part of the head the inner codec sees and modifies; the remaining parts of the head must be left unchanged.

Concretely, given a message (head, tail):

  • append: Build a sub-message consisting of (view_fun(head), tail), run the inner append on that sub-message with the provided data, then reintegrate the (possibly modified) view back into the original head structure at the same location view_fun selected. The tail returned by the inner codec becomes the new tail. The parts of head not selected by view_fun must remain exactly as they were.

  • pop: Build a sub-message (view_fun(head), tail), run the inner pop on it to obtain a modified view, the new tail, and the decoded data. Reintegrate the modified view into head at the selected location, leaving all other parts of head unchanged, and return (new_message, data).

The reintegration must work such that when view_fun selects one element/slot of the head, only that slot is affected and the rest of the head keeps its original values.

Correctness requirement

For any head structure and any view_fun that selects a component of that head, the resulting substack codec must satisfy the round-trip property: appending data and then popping returns a message equal to the original message and returns data equal to the original data. Additionally, the untouched portion of the head (the parts not selected by view_fun) must be identical before and after an append.

Compatibility note

Messages are compared for equality by comparing the full nested structure of both head and tail element-wise. Ensure the head structures you produce compare equal (same shapes/values) to the originals after a round trip, including nested tuple/list structure.

Example usage pattern
import craystack as cs

# head is a length-2 structure (e.g. two array slots); tail is the stream
view_fun = lambda h: h[0]              # operate only on the first slot
append, pop = cs.substack(cs.repeat(cs.Uniform(prec), n_data), view_fun)

message2 = append(message, data)       # message2's tail-slot(s) not in view unchanged
message3, data2 = pop(message2)        # message3 == message and data2 == data

In the example, the head is a list/tuple of two array parts. view_fun selects index 0; after append, index 1 of the head is unchanged, and the append/pop pair round-trips the data exactly.

This codec performs lossless entropy coding of integer symbols drawn from a discretized mixture-of-logistics distribution.

Background: Codec Contract

A codec in this codebase is an object exposing an encode/decode pair that is invertible: given a data value, encoding it into a message and then decoding must recover the original data exactly, and the message state must round-trip consistently (encoding then decoding returns the message to its prior state). Existing codecs (e.g. Categorical) follow this same contract and are constructed with distribution parameters plus a precision argument. Your LogisticMixture must be interchangeable with these existing codecs in the same testing harness (i.e., it must satisfy the standard round-trip verification used for all codecs in this package).

Public API

Create a callable/constructor:

craystack.LogisticMixture(theta, precision)
  • theta: a NumPy array of distribution parameters (described below).
  • precision: an integer giving the total bit-precision of the quantized probability model (e.g. 12).

The returned object must be a valid codec conforming to the package's existing codec interface (the same interface implemented by Categorical), supporting the standard encode and decode operations over the vectorized message representation used throughout the package.

Parameterization of theta

The codec models a mixture of nr_mix logistic components per coded element.

  • Let the per-element mixture parameters have shape (..., nr_mix) for each of three parameter groups: means, log-scales, and logit mixture probabilities.
  • theta is the concatenation of these three groups along the last axis, i.e. theta has last-axis length 3 * nr_mix, laid out in the order: means, then log-scales, then mixture logit-probabilities.
  • The leading dimensions of theta (all axes except the last) form the batch/coding shape. Concretely, for a batch of size B with nr_mix mixture components, theta has shape (B, 3 * nr_mix), and the codec codes B independent symbols (the coding shape is (B,)).

Symbol Domain

Each coded symbol is an integer in the range [0, 256) (i.e. one of the 256 discrete values 0, 1, ..., 255), representing a discretized/quantized value under the logistic mixture. The discretized mixture-of-logistics distribution must assign the appropriate probability mass to each of the 256 bins, quantized to the given precision, such that encode/decode round-trips exactly for any valid symbol in this range.

Model Definition

For each coded element, given its nr_mix means m_k, log-scales ls_k, and mixture logit-probabilities l_k:

  • Mixture weights are obtained by a softmax over the logit-probabilities l_k across the nr_mix components.
  • Each component k is a logistic distribution with location m_k and scale exp(ls_k).
  • The probability mass assigned to an integer bin value v (for v in 0..255) is the mixture-weighted sum of the probability mass each logistic component places on that bin, where a bin's mass is computed from the difference of the logistic CDF evaluated at the bin's upper and lower edges (standard discretized-logistic binning over the 256-value domain). Edge bins (the lowest and highest values) capture the remaining tail mass so the total probability over the 256 bins sums to 1.

These per-bin probabilities are quantized to precision bits to form the coding distribution used for entropy coding.

Requirements

  • The codec must correctly encode any integer symbol in [0, 256) and decode it back to the identical integer, for batched inputs of shape (B,).
  • The message state must be fully restored after an encode followed by the corresponding decode (round-trip consistency of the coder state).

Error Handling

When the quantized per-bin probability mass must be rebalanced (adjusted so that all bins have nonzero mass and the quantized masses sum exactly to 2**precision) and this rebalancing cannot be performed validly, the codec must raise an exception rather than silently proceeding with an invalid distribution.
