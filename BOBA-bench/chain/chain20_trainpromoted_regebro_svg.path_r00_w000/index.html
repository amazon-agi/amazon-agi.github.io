Task Specification: SVG Path Parser Number Format Support

Overview

You are working on a Python package for parsing SVG path definition strings into geometric path objects. The public API is exposed via the module svg.path. You must ensure the path parser correctly handles negative numbers and numbers written in scientific/exponential notation.

Public API

The following must be importable from the svg.path package:

  • parse_path(pathdef) — a function that accepts an SVG path definition string and returns a Path object.
  • Path — a class representing a sequence of path segments. Path instances are constructed by passing one or more segment objects as positional arguments, e.g. Path(segment1, segment2, ...).
  • Line — a path segment class representing a straight line. It is constructed as Line(start, end), where start and end are complex numbers representing 2D points (real part = x coordinate, imaginary part = y coordinate).

Two Path objects must compare equal (==) when they contain equivalent segments; two Line segments must compare equal when their start and end points are equal.

Required Behavior

Coordinate and number parsing

The parser must correctly tokenize and interpret numeric values in path coordinate data, including the following cases:

  1. Negative numbers. A minus sign introduces a negative number and also acts as an implicit separator between coordinate values. For example, the coordinate sequence 10-5,20-10,30-20 must parse into the same numbers as 10 -5 20 -10 30 -20.

  2. Scientific / exponential notation. Numbers may be written using an exponent:

    • The exponent marker may be either lowercase e or uppercase E.
    • The exponent may carry an explicit sign: +, -, or no sign at all.
    • Both the mantissa and the exponent may be negative.
    • Values with magnitude at least 3.4e38 (i.e. 3.4 × 10^38) must be supported, as well as very small values such as 3.4e-38.

    Examples of valid numeric tokens: -3.4e38, 3.4E+38, -3.4E-38, 3.4e-38.

  3. Separators. Commas, whitespace, and a leading minus sign of a following number all serve to separate adjacent numeric values.

Command parsing

The parser must handle at least the following path commands as they appear in the test-exercised inputs:

  • M / m — moveto (establishes the current point / start of the path).
  • L — lineto (produces a Line segment from the current point to the given point).
  • c — relative cubic curve (must be parseable when its coordinate arguments use the number formats above).
Concrete equivalence requirements

  • Parsing 'M-3.4e38 3.4E+38L-3.4E-38,3.4e-38' must yield a path equal to:

    Path(Line(-3.4e+38 + 3.4e+38j, -3.4e-38 + 3.4e-38j))

    That is: the moveto establishes the point (-3.4e38, 3.4e38), and the L command draws a single line from that point to (-3.4e-38, 3.4e-38).

  • Parsing 'M100,200c10-5,20-10,30-20' must produce a path equal to parsing 'M 100 200 c 10 -5 20 -10 30 -20'.

Constraints

  • A minus sign must be treated as the start of a new number only when it is not part of an exponent. In 3.4e-38 the - belongs to the exponent and must not split the token into two numbers; in 20-10 the - separates two distinct numbers.
  • Coordinate values are combined into complex numbers, with the x value as the real part and the y value as the imaginary part.

Task Specification: SVG Path Library

Modules and Public API

Module: svg.path.path

This module must expose the following classes: Line, CubicBezier, QuadraticBezier, Arc, and Path.

Throughout, all 2D points are represented as Python complex numbers, where the real part is the x-coordinate and the imaginary part is the y-coordinate.

Each path segment class (Line, CubicBezier, QuadraticBezier, Arc) must provide:

  • point(pos) — returns the point (a complex) on the segment at parameter pos, where pos ranges from 0.0 (start) to 1.0 (end).
  • length() — returns the arc length of the segment as a float.

All segment classes and Path must support equality comparison (==) such that two instances are equal when they are of the same type and have equal defining parameters.

Line

Constructor: Line(start, end) where start and end are complex points.

  • point(pos) linearly interpolates: start + (end - start) * pos.
  • length() returns the straight-line (Euclidean) distance between start and end.

Examples:

  • Line(0j, 400+0j).point(0.3) → 120+0j; .length() → 400.
  • Line(400+0j, 400+300j).length() → 300.
  • Line(400+300j, 0j).point(0.3) → 280+210j; .length() → 500.
CubicBezier

Constructor: CubicBezier(start, control1, control2, end) — four complex points.

  • point(pos) evaluates the standard cubic Bézier at pos.
  • length() estimates the arc length of the curve.

Representative behavior (points):

  • CubicBezier(100+200j, 100+100j, 250+100j, 250+200j): point(0)=100+200j, point(0.3)=132.4+137j, point(0.5)=175+125j, point(0.9)=245.8+173j, point(1)=250+200j.

  • A degenerate straight vertical curve CubicBezier(0j, 0j, 0+100j, 0+100j) → length() ≈ 100.
  • A degenerate straight diagonal CubicBezier(0j, 0j, 100+100j, 100+100j) → length() ≈ sqrt(2*100*100).
  • A quarter-circle approximation with radius 100 (kappa = 4*(sqrt(2)-1)/3), CubicBezier(0j, 0+kappa*100j, (100-kappa*100)+100j, 100+100j) → length() ≈ 157.1016698.

Constructor: Path(*segments) — accepts any number of segment objects (Line, CubicBezier, QuadraticBezier, Arc) as positional arguments, in order.

The Path represents a piecewise curve composed of its segments joined end to end. Parameterization over [0,1] spans the whole path, distributing the parameter across segments proportionally by segment length (so equal lengths of curve correspond to equal spans of pos).

Methods and attributes:

Module: svg.path.parser

Expose a function:

parse_path(pathdef) -> Path

It parses an SVG path-data string and returns an equivalent Path of segment objects. The following must be supported:

Commands (uppercase = absolute, lowercase = relative to current point):

  • M/m — moveto. Sets the current point (and the start of the current subpath). Extra coordinate pairs after a moveto are treated as implicit L/l (line) commands.
  • L/l — lineto → produces Line segments.
  • H/h — horizontal lineto → produces Line segments.
  • V/v — vertical lineto → produces Line segments.
  • C/c — cubic Bézier → produces CubicBezier segments.
  • S/s — smooth cubic Bézier. The first control point is the reflection of the previous segment's second control point about the current point (or the current point itself if the previous command was not a cubic). Produces CubicBezier segments.
  • Q/q — quadratic Bézier → produces QuadraticBezier segments (start, control, end).
  • T/t — smooth quadratic Bézier. The control point is the reflection of the previous quadratic's control point about the current point (or the current point itself if the previous command was not a quadratic). Produces QuadraticBezier segments.
  • A/a — elliptical arc → produces Arc segments. The parameter order is radius_x,radius_y rotation large-arc-flag,sweep-flag end_x,end_y.
  • Z/z — closepath. Adds a Line from the current point back to the start of the current subpath (when they differ) and marks the resulting Path (subpath) as closed.

Multiple subpaths: A new M/m starts a new subpath. When a subpath is closed with Z/z, the closing line returns to that subpath's own start point (the most recent moveto), not to the very first point of the path.

Number and separator format:

  • Coordinates may be separated by whitespace and/or commas, interchangeably.
  • Commands need not be separated from their arguments by whitespace (e.g. M100 100L200 200).
  • A minus sign implicitly separates numbers, so no whitespace is required before it (e.g. c10-5,20-10,30-20 is valid).
  • Scientific notation must be supported: e/E exponent, optional +/- after the exponent marker, magnitudes at least up to ±3.4e38 (e.g. M-3.4e38 3.4E+38L-3.4E-38,3.4e-38).

Task Specification: SVG Path Parsing and Serialization

Overview

Implement functionality in the module svg.path to parse SVG path data strings into an object model and serialize that model back into SVG path data strings. The round-trip (parse then serialize) must reproduce a canonical, normalized form of the path string.

Public API

The module svg.path must expose a function:

def parse_path(path_data: str) -> Path
  • Input: a string containing SVG path data.
  • Output: a Path object representing the parsed path.

The returned Path object must provide a method:

def to_svg(self) -> str
  • Output: a string containing the SVG path data in a canonical normalized form (described below).

Supported Path Commands

The parser must understand the following SVG path commands (uppercase, absolute coordinates as they appear in the inputs below):

  • M x,y — Moveto: begins a new subpath at the given point.
  • L x,y — Lineto: draws a straight line to the given point.
  • C x1,y1 x2,y2 x,y — Cubic Bézier curve, with two control points and an end point.
  • S x2,y2 x,y — Smooth cubic Bézier curve. The first control point is the reflection of the second control point of the previous command (relative to the current point). If the previous command was not a cubic Bézier (C or S), the first control point coincides with the current point. x2,y2 is the second control point and x,y is the end point.
  • Q x1,y1 x,y — Quadratic Bézier curve, with one control point and an end point.
  • T x,y — Smooth quadratic Bézier curve. The control point is the reflection of the control point of the previous command (relative to the current point). If the previous command was not a quadratic Bézier (Q or T), the control point coincides with the current point. x,y is the end point.
  • Z — Closepath: closes the current subpath by drawing a straight line back to the start of that subpath.
