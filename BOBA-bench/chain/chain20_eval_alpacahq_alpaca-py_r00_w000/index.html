Task Specification: Client for Historical Market Data

Summary

Build a client that fetches historical stock bar (OHLCV) data from the Alpaca market data API, plus the accompanying bar data models and timeframe utilities. The client must handle both single-symbol and multi-symbol requests, respect an optional overall bar limit while paginating, and return either structured objects or raw Python data according to its configuration.

Publicly importable package structure

The modules and names below must be importable:

  • alpaca/__init__.py must expose __version__, and its value must be exactly the string "0.1.0". So from alpaca import __version__ must succeed and produce "0.1.0".
  • alpaca/data/clients.py must expose HistoricalDataClient.
  • alpaca/common/time.py must expose TimeFrame as well as TimeFrameUnit.
  • alpaca/data/models.py must expose BarSet together with the underlying Bar model.

Timeframes

TimeFrameUnit

TimeFrameUnit is an enumeration of timeframe units and must include at least these members:

  • TimeFrameUnit.Minute
  • TimeFrameUnit.Hour
  • TimeFrameUnit.Day
TimeFrame

A TimeFrame combines an integer amount with a TimeFrameUnit. It must support positional construction in the form:

TimeFrame(amount, unit)

For instance:

TimeFrame(1, TimeFrameUnit.Minute)

It must additionally provide the following convenient class-level values:

  • TimeFrame.Minute, which is equivalent to TimeFrame(1, TimeFrameUnit.Minute)
  • TimeFrame.Hour, which is equivalent to TimeFrame(1, TimeFrameUnit.Hour)
  • TimeFrame.Day, which is equivalent to TimeFrame(1, TimeFrameUnit.Day)

A timeframe must serialize to the compact string that the API expects by concatenating its amount and its unit's representation. In particular, TimeFrame.Day must be sent as 1Day; the corresponding forms for minutes and hours are 1Min and 1Hour.

HistoricalDataClient

Constructor
HistoricalDataClient(api_key, secret_key, raw_data=False)
  • api_key and secret_key are the API credentials. They must be accepted either positionally or by keyword, and they must be used to authenticate outgoing API requests.
  • raw_data defaults to False. If it is false, the data-returning operations return structured objects. If it is true, they return plain Python dictionaries and lists that contain raw bar fields rather than Bar objects.
get_bars
get_bars(symbol_or_symbols, timeframe, start, end=None, limit=None)

The parameters:

  • symbol_or_symbols: either a single ticker symbol as a str, such as "AAPL", or a list of ticker symbols, such as ["AAPL", "TSLA"].
  • timeframe: an instance of TimeFrame, serialized in the API form described above.
  • start: the start date string being requested, for instance "2022-02-01".
  • end: an optional string for the end date.
  • limit: an optional integer bound on the total number of bars to be returned.

The host used for the API is always:

https://data.alpaca.markets
Requests for a single symbol

If symbol_or_symbols is a string, issue a GET request to:

https://data.alpaca.markets/v2/stocks/{symbol}/bars

The query string contains timeframe and start, plus end and limit whenever those optional arguments are given.

As an example:

get_bars("AAPL", TimeFrame.Day, "2022-02-01", limit=2)

must issue a request equivalent to:

/v2/stocks/AAPL/bars?timeframe=1Day&start=2022-02-01&limit=2
Requests for multiple symbols

If symbol_or_symbols is a list, issue a GET request to the aggregate endpoint:

https://data.alpaca.markets/v2/stocks/bars

The query string contains timeframe, start, and symbols, plus end and limit when they are provided. The symbols value consists of the supplied symbols joined by commas in the order they were supplied.

As an example:

get_bars(
    ["AAPL", "TSLA"],
    TimeFrame.Day,
    "2022-03-09",
    end="2022-03-09",
)

must issue a request equivalent to:

/v2/stocks/bars?timeframe=1Day&start=2022-03-09&end=2022-03-09&symbols=AAPL,TSLA

Standard URL encoding may show the comma in the actual URL as %2C; once decoded, the symbols query value must be AAPL,TSLA.

Shapes of the API response

For a single symbol, the response has an envelope such as:

{
  "bars": [{"t": "...", "o": 1, "h": 2, "l": 1, "c": 2, "v": 10, "n": 3, "vw": 1.5}],
  "symbol": "AAPL",
  "next_page_token": "..."
}

For multiple symbols, the response has an envelope such as:

{
  "bars": {
    "AAPL": [{"t": "...", "o": 1, "h": 2, "l": 1, "c": 2, "v": 10, "n": 3, "vw": 1.5}],
    "TSLA": [{"t": "...", "o": 3, "h": 4, "l": 3, "c": 4, "v": 20, "n": 5, "vw": 3.5}]
  },
  "next_page_token": null
}

Every raw bar uses the API's abbreviated keys:

  • t: timestamp in ISO 8601 form
  • o: open
  • h: high
  • l: low
  • c: close
  • v: volume
  • n: trade count
  • vw: volume-weighted average price
  • x: exchange, when supplied
Pagination and limit handling

When an API response carries a non-null next_page_token and the requested limit has not yet been reached, retrieve subsequent pages with that token and merge their bars into the result. Bars coming from later pages must be appended, in page order, to the existing sequence of the appropriate symbol. Keep going until the API returns no next-page token or the overall limit has been satisfied.

A non-null token on its own must not trigger another request when the current result already contains the requested number of bars. For instance, a first page containing two bars satisfies limit=2, even if that page advertises another token. The final public result is a single combined collection keyed by symbol and does not expose pagination-envelope metadata.

Returned values
Structured mode (raw_data=False)

For both single-symbol and multi-symbol calls, get_bars returns a BarSet. Data from a single-symbol call uses the same symbol-keyed representation as multi-symbol data, with exactly one symbol entry.

Raw mode (raw_data=True)

For both request forms, get_bars returns a plain dict keyed by symbol. Every value is an ordered list of raw bar dictionaries. These dictionaries keep the original abbreviated keys and raw values, including any optional fields such as x. The outer API envelope is normalized away; for a single-symbol request, the dictionary has a single entry keyed by that symbol.

For instance, raw results support access such as:

raw_bars["AAPL"][0]["o"]
raw_bars["AAPL"][0]["h"]

Models for bar data

Bar

A structured Bar maps the abbreviated API fields onto descriptive attributes:

  • t to timestamp
  • o to open
  • h to high
  • l to low
  • c to close
  • v to volume
  • n to trade_count
  • vw to vwap
  • optional x to exchange

The timestamp must be parsed into a datetime-like value that is suitable for datetime indexing. A bar additionally carries the corresponding symbol and timeframe. Numeric values remain numeric and retain their values; for instance, a raw opening value of 174 is available as bar.open == 174.

BarSet

BarSet represents bars belonging to one or more symbols and is always organized by symbol. It must support indexing by symbol:

bars_for_aapl = barset["AAPL"]
first_bar = barset["AAPL"][0]

barset[symbol] returns the ordered sequence of Bar objects for that symbol. The order of bars within a symbol must not be disturbed by pagination. The same indexing contract applies when only one symbol was requested.

DataFrame output

BarSet exposes a df property that returns a pandas DataFrame holding its bar data.

  • For a single-symbol BarSet, the DataFrame has a one-level index (df.index.nlevels == 1) that is indexed by bar timestamp. For instance, a bar timestamp of 2022-02-01T05:00:00Z yields an index value whose .day is 1. The lone symbol must not add a redundant symbol index level.
  • For a multi-symbol BarSet, the DataFrame has a two-level MultiIndex (df.index.nlevels == 2). The symbol makes up the first level, and the bar timestamp the second. So a row for 2022-03-09T05:00:00Z has a second index component whose .day is 9.

The DataFrame must reflect the same bars, in the same ordering, that are available through symbol indexing.

Dependencies and runtime environment

The implementation may use requests for HTTP communication and pandas for DataFrame support. Python 3.8 or newer is assumed.

Task Specification: Adding Trade Data Retrieval to the Historical Data Client

Overview

Extend the historical data client with support for retrieving trade data (both stock and crypto). This is an extension of the existing client, which already supports retrieving bar and quote data.

Public API Additions

New model class: TradeSet

A new class TradeSet is to be added, importable from alpaca.data.models:

from alpaca.data.models import TradeSet

Its design must match that of the existing BarSet and QuoteSet classes.

New methods on the client

The HistoricalDataClient class (in alpaca.data.clients) receives two new methods:

def get_trades(self, symbol_or_symbols, start=None, end=None, limit=None) -> TradeSet | dict
def get_crypto_trades(self, symbol_or_symbols, start=None, end=None, limit=None) -> TradeSet | dict
  • symbol_or_symbols accepts either one symbol string or a list of symbol strings.
  • start, end, and limit are optional query parameters. If they are provided, they get included as query-string parameters; if they are omitted, they must not be sent.
  • These methods must accept the parameters shown above as keyword arguments.

Behavior of the new methods

get_trades (stock trades)

Single-symbol request (symbol_or_symbols is a string):

  • Sends a GET request to: https://data.alpaca.markets/v2/stocks/{symbol}/trades with the query parameters start and limit (only the ones provided).

Multi-symbol request (symbol_or_symbols is a list):

  • Sends a GET request to: https://data.alpaca.markets/v2/stocks/trades with the query parameter symbols (a comma-separated list of the symbols) together with start/end/limit as provided.
get_crypto_trades (crypto trades)

Single-symbol request (symbol_or_symbols is a string):

  • Sends a GET request to: https://data.alpaca.markets/v1beta1/crypto/{symbol}/trades with the query parameters start and limit (only the ones provided).

Multi-symbol request (symbol_or_symbols is a list):

  • Sends a GET request to: https://data.alpaca.markets/v1beta1/crypto/trades with the query parameter symbols (a comma-separated list of the symbols) together with start/end/limit as provided.
Shape of the responses

For single-symbol responses, the JSON body takes this shape:

{
    "trades": [ { ...trade... }, ... ],
    "symbol": "AAPL",
    "next_page_token": "..."
}

For multi-symbol responses, the JSON body takes this shape:

{
    "trades": {
        "AAPL": [ { ...trade... } ],
        "TSLA": [ { ...trade... } ]
    },
    "next_page_token": null
}

Each trade object has fields such as:

  • t — the timestamp (an ISO 8601 string, e.g. "2022-03-09T05:00:02.183Z")
  • x — the exchange (a string, e.g. "D" or "CBSE")
  • p — the price (number)
  • s — the size (number)
  • i — the trade id (integer)
  • c — a list of condition codes (may be present)
  • z — the tape (may be present)
  • tks — the taker side (may be present, crypto)

What the methods return

The client is constructed as HistoricalDataClient(key_id, secret_key) or as HistoricalDataClient(key_id, secret_key, raw_data=True).

With raw_data=False (the default)

Both methods return a TradeSet object, which must support:

  • Keyed access by symbol: tradeset[symbol] returns a list of trade objects. This holds for both single-symbol requests (where the requested symbol serves as the key) and multi-symbol requests (where each symbol serves as a key).
  • Trade object attributes available on each element:
    • .price → the value of p
    • .size → the value of s
    • .exchange → the value of x, returned as the raw string (e.g. "CBSE", "D"). Unlike the bar/quote exchange attributes, this is not converted to an Exchange enum; it remains a plain string.
  • A .df property that returns a pandas DataFrame:
    • With a single-symbol request, df.index has 1 level, and the entries in the index are timestamps parsed from t (so df.index[0].day reflects the day of the trade timestamp).
    • With a multi-symbol request, df.index has 2 levels (symbol and timestamp); the second level (df.index[0][1]) holds the parsed timestamp.
With raw_data=True

Both methods return a plain dict keyed by symbol, in which each value is a list of raw trade dictionaries that preserve the original JSON field names. In other words:

  • result[symbol][i]["p"] → price
  • result[symbol][i]["s"] → size
  • result[symbol][i]["x"] → exchange string

This covers both single-symbol and multi-symbol requests (the single-symbol request being keyed by the requested symbol).

Constraints

  • The behavior of the existing get_bars, get_crypto_bars, get_quotes, and get_crypto_bars must remain unchanged.
  • The version string of the package, alpaca.__version__, must equal "0.1.0".
