Task Specification: Historical Market Data Client

Overview

Implement a client for retrieving historical stock bar (OHLCV) data from the Alpaca market data API, together with the supporting bar data models and timeframe utilities. The client must support single-symbol and multi-symbol requests, honor an optional overall bar limit while paginating, and return either structured objects or raw Python data according to its configuration.

Public package structure

The following modules and names must be importable:

  • alpaca/__init__.py must expose __version__. Its exact value must be the string "0.1.0". Thus, from alpaca import __version__ must succeed and produce "0.1.0".
  • alpaca/data/clients.py must expose HistoricalDataClient.
  • alpaca/common/time.py must expose TimeFrame and TimeFrameUnit.
  • alpaca/data/models.py must expose BarSet and the underlying Bar model.

Timeframes

TimeFrameUnit

TimeFrameUnit is an enumeration of timeframe units and must include at least:

  • TimeFrameUnit.Minute
  • TimeFrameUnit.Hour
  • TimeFrameUnit.Day
TimeFrame

A TimeFrame represents an integer amount and a TimeFrameUnit. It must support positional construction in the form:

TimeFrame(amount, unit)

For example:

TimeFrame(1, TimeFrameUnit.Minute)

It must also provide these convenient class-level values:

  • TimeFrame.Minute, equivalent to TimeFrame(1, TimeFrameUnit.Minute)
  • TimeFrame.Hour, equivalent to TimeFrame(1, TimeFrameUnit.Hour)
  • TimeFrame.Day, equivalent to TimeFrame(1, TimeFrameUnit.Day)

A timeframe must serialize to the compact string expected by the API by concatenating its amount and unit representation. In particular, TimeFrame.Day must be sent as 1Day; the corresponding minute and hour forms are 1Min and 1Hour.

HistoricalDataClient

Construction
HistoricalDataClient(api_key, secret_key, raw_data=False)
  • api_key and secret_key are the API credentials. They must be accepted either positionally or by keyword and used to authenticate outgoing API requests.
  • raw_data defaults to False. If false, data-returning operations return structured objects. If true, they return plain Python dictionaries and lists containing raw bar fields rather than Bar objects.
get_bars
get_bars(symbol_or_symbols, timeframe, start, end=None, limit=None)

Parameters:

  • symbol_or_symbols: either one ticker symbol as a str, such as "AAPL", or a list of ticker symbols, such as ["AAPL", "TSLA"].
  • timeframe: a TimeFrame instance, serialized using the API form described above.
  • start: the requested start date string, for example "2022-02-01".
  • end: an optional end date string.
  • limit: an optional integer bound on the total number of bars to return.

The API host is always:

https://data.alpaca.markets
Single-symbol requests

When symbol_or_symbols is a string, issue a GET request to:

https://data.alpaca.markets/v2/stocks/{symbol}/bars

The query contains timeframe and start, plus end and limit when those optional arguments are provided.

For example:

get_bars("AAPL", TimeFrame.Day, "2022-02-01", limit=2)

must request the equivalent of:

/v2/stocks/AAPL/bars?timeframe=1Day&start=2022-02-01&limit=2
Multi-symbol requests

When symbol_or_symbols is a list, issue a GET request to the aggregate endpoint:

https://data.alpaca.markets/v2/stocks/bars

The query contains timeframe, start, and symbols, plus end and limit when provided. The symbols value is the supplied symbols joined by commas in their supplied order.

For example:

get_bars(
    ["AAPL", "TSLA"],
    TimeFrame.Day,
    "2022-03-09",
    end="2022-03-09",
)

must request the equivalent of:

/v2/stocks/bars?timeframe=1Day&start=2022-03-09&end=2022-03-09&symbols=AAPL,TSLA

Standard URL encoding may represent the comma in the actual URL as %2C; the decoded symbols query value must be AAPL,TSLA.

API response forms

A single-symbol response has an envelope such as:

{
  "bars": [{"t": "...", "o": 1, "h": 2, "l": 1, "c": 2, "v": 10, "n": 3, "vw": 1.5}],
  "symbol": "AAPL",
  "next_page_token": "..."
}

A multi-symbol response has an envelope such as:

{
  "bars": {
    "AAPL": [{"t": "...", "o": 1, "h": 2, "l": 1, "c": 2, "v": 10, "n": 3, "vw": 1.5}],
    "TSLA": [{"t": "...", "o": 3, "h": 4, "l": 3, "c": 4, "v": 20, "n": 5, "vw": 3.5}]
  },
  "next_page_token": null
}

Each raw bar uses the API's abbreviated keys:

  • t: timestamp in ISO 8601 form
  • o: open
  • h: high
  • l: low
  • c: close
  • v: volume
  • n: trade count
  • vw: volume-weighted average price
  • x: exchange, when supplied
Pagination and limits

If an API response has a non-null next_page_token and the requested limit has not yet been reached, retrieve subsequent pages using that token and merge their bars into the result. Bars from later pages must be appended in page order to the appropriate symbol's existing sequence. Continue until the API returns no next-page token or the overall limit has been satisfied.

A non-null token alone must not trigger another request when the current result already contains the requested number of bars. For example, a first page containing two bars satisfies limit=2, even if that page advertises another token. The final public result is one combined symbol-keyed collection and does not expose pagination-envelope metadata.

Return values
Structured mode (raw_data=False)

get_bars returns a BarSet for both single-symbol and multi-symbol calls. Single-symbol data uses the same symbol-keyed representation as multi-symbol data, with exactly one symbol entry.

Raw mode (raw_data=True)

get_bars returns a plain dict keyed by symbol for both request forms. Each value is an ordered list of raw bar dictionaries. The bar dictionaries retain the original abbreviated keys and raw values, including any optional fields such as x. The outer API envelope is normalized away; for a single-symbol request, the dictionary has one entry keyed by that symbol.

For example, raw results support access such as:

raw_bars["AAPL"][0]["o"]
raw_bars["AAPL"][0]["h"]

Bar data models

Bar

A structured Bar maps abbreviated API fields to descriptive attributes:

  • t to timestamp
  • o to open
  • h to high
  • l to low
  • c to close
  • v to volume
  • n to trade_count
  • vw to vwap
  • optional x to exchange

The timestamp must be parsed into a datetime-like value suitable for datetime indexing. A bar also carries the corresponding symbol and timeframe. Numeric values remain numeric and retain their values; for example, a raw opening value of 174 is available as bar.open == 174.

BarSet

BarSet represents bars for one or more symbols and is always organized by symbol. It must support symbol indexing:

bars_for_aapl = barset["AAPL"]
first_bar = barset["AAPL"][0]

barset[symbol] returns that symbol's ordered sequence of Bar objects. Pagination must not disturb the order of bars within a symbol. The same indexing contract applies when only one symbol was requested.

DataFrame representation

BarSet exposes a df property that returns a pandas DataFrame containing its bar data.

  • For a single-symbol BarSet, the DataFrame has a one-level index (df.index.nlevels == 1) indexed by bar timestamp. A bar timestamp of 2022-02-01T05:00:00Z, for example, yields an index value whose .day is 1. The sole symbol must not add a redundant symbol index level.
  • For a multi-symbol BarSet, the DataFrame has a two-level MultiIndex (df.index.nlevels == 2). The first level is the symbol and the second is the bar timestamp. Thus a row for 2022-03-09T05:00:00Z has a second index component whose .day is 9.

The DataFrame must reflect the same bars and ordering available through symbol indexing.

Dependencies and runtime

The implementation may use requests for HTTP communication and pandas for DataFrame support. Python 3.8 or newer is assumed.

{
    "trades": [ { ...trade... }, ... ],
    "symbol": "AAPL",
    "next_page_token": "..."
}

For multi-symbol responses, the JSON body has this shape:

{
    "trades": {
        "AAPL": [ { ...trade... } ],
        "TSLA": [ { ...trade... } ]
    },
    "next_page_token": null
}

Each trade object contains fields such as:

  • t — timestamp (ISO 8601 string, e.g. "2022-03-09T05:00:02.183Z")
  • x — exchange (string, e.g. "D" or "CBSE")
  • p — price (number)
  • s — size (number)
  • i — trade id (integer)
  • c — list of condition codes (may be present)
  • z — tape (may be present)
  • tks — taker side (may be present, crypto)

The client is constructed as HistoricalDataClient(key_id, secret_key) or HistoricalDataClient(key_id, secret_key, raw_data=True).

When raw_data=False (default)

    • .price → the value of p
    • .size → the value of s

    • For a single-symbol request, df.index has 1 level, and the index entries are timestamps parsed from t (so df.index[0].day reflects the day of the trade timestamp).
    • For a multi-symbol request, df.index has 2 levels (symbol and timestamp); the second level (df.index[0][1]) is the parsed timestamp.
When raw_data=True

  • result[symbol][i]["p"] → price
  • result[symbol][i]["s"] → size
  • result[symbol][i]["x"] → exchange string

This applies to both single-symbol and multi-symbol requests (with the single-symbol request keyed by the requested symbol).

Constraints

  • The existing get_bars, get_crypto_bars, get_quotes, and get_crypto_bars behavior must remain unchanged.
