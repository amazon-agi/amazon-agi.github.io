Task Specification: Configuration Loading and Job Types

Overview

You will implement configuration parsing for a data-syncing tool that transfers data between Dune Analytics and a PostgreSQL database. The system loads job definitions from YAML config files, validates them, and exposes runnable jobs.

Public API Surface

Module: src.config

The following must be importable from src.config:

  • Env — an environment-configuration class with a class method Env.load() that reads configuration from environment variables (using load_dotenv internally, which may be patched by callers). It requires the environment variables DUNE_API_KEY and DB_URL.

  • RuntimeConfig — a configuration object exposing:

    • A class method RuntimeConfig.load_from_yaml(path) that accepts a filesystem path (a str or pathlib.Path, including absolute paths) to a YAML config file, parses it, validates it, and returns a RuntimeConfig instance.
    • An attribute jobs — a list (indexable, supporting len()) of job objects. Each job object exposes a run() method (see below).

  • parse_query_parameters — a function that converts a list of parameter definitions into Dune query parameter objects (see "Query Parameters" below).

Config File Format

Config files are YAML documents with a top-level jobs key mapping to a list of job entries. Each job entry has:

  • name: a human-readable string.
  • source: a mapping describing where data comes from.
  • destination: a mapping describing where data goes.

Both source and destination contain a ref field naming the connector type. Supported ref values are:

  • dune — the Dune Analytics connector.
  • postgres — the PostgreSQL connector.

Any other ref value is unsupported (see "Validation and Errors").

Dune source/destination fields
  • query_id: an integer query identifier (unquoted integer in YAML, e.g. 4238114, 123, 1).
  • query_engine: an optional string engine selector (e.g. medium).
  • poll_frequency: an optional integer.
  • parameters: an optional list of query parameters (see below).
  • table_name: a string table name (used when Dune is the destination).
Postgres source/destination fields
  • table_name: a string table name. Mandatory for a postgres destination.
  • if_exists: a string strategy (e.g. replace, append).
  • query_string: a SQL query string (used when postgres is the source).

Note: YAML values may be unquoted. Integers such as query_id arrive as native integers, and strings such as medium, replace, SELECT * FROM foo;, and table names arrive as native strings. Parsing must not depend on values being quoted.

Query Parameters

Each entry in a parameters list is a mapping with:

  • name: parameter name string.
  • value: parameter value.
  • type: one of ENUM, DATE, NUMBER (and other Dune parameter types), determining how the value is interpreted.

parse_query_parameters takes such a list and returns the corresponding list of Dune QueryParameter objects.

Behavior Requirements

Successful loading

Given a well-formed config with supported connector types and all mandatory fields present, RuntimeConfig.load_from_yaml returns a RuntimeConfig whose jobs list contains one runnable job per entry in the file's jobs list, in order.

Running a job

Each job object's run() method executes the source-to-destination transfer. For a Dune-source → Postgres-destination job:

  • It fetches the query result from the Dune client and writes it to the destination.
  • If the Dune client returns a result, the run completes successfully.
  • If the Dune client returns None (no result), run() raises ValueError.

Validation and Errors

Validation occurs during load_from_yaml (before any job is run):

  • If a source specifies an unsupported connector ref (any value other than dune or postgres), raise ValueError whose message contains the text Unsupported source_db type.

  • If a destination specifies an unsupported connector ref, raise ValueError whose message contains the text Unsupported destination_db type.

  • If a postgres destination is missing its mandatory table_name field, raise KeyError referencing the missing key table_name (the exception string must contain 'table_name').

Naming Note

There is exactly one job class in the system; it must be named Job (not BaseJob). Job objects produced in jobs are instances of this single job type and expose the run() method described above.

Documentation

Update the project README to reflect that configuration (including query IDs and optional parameters) is now provided via YAML config files rather than environment variables, and indicate which config parameters are optional (query_engine, poll_frequency, parameters).

Test Fixtures Location

Config fixtures live under tests/fixtures/config/. Ensure the test support package (tests/__init__.py) exposes a config_root path pointing to tests/fixtures/config, defined relative to the existing fixtures_root.

Fixture files that must exist under tests/fixtures/config/:

  • basic.yaml — two well-formed jobs (a dune→postgres job with parameters, and a postgres→dune job).
  • dune_to_postgres.yaml — one well-formed dune→postgres job with a table_name destination.
  • postgres_to_dune.yaml — one well-formed postgres→dune job.
  • buggy.yaml — a dune→postgres job whose postgres destination omits the mandatory table_name.
  • unsupported_source.yaml — a job whose source ref is sqlite.
  • unsupported_dest.yaml — a job whose destination ref is sqlite.

All fixture YAML values should be written unquoted.

The Postgres source configuration accepts a query_string value. This value must be interpreted so that when it refers to a .sql file, the file's contents are loaded and used as the query. When the referenced .sql file does not exist, configuration loading must fail with a clear error.

    • Returns a RuntimeConfig instance whose jobs attribute is a list of parsed jobs (len(conf.jobs) reflects the number of jobs defined in the YAML).

  • if_exists: string (e.g. append)
  • query_string: string

When loading a configuration whose Postgres source query_string ends in .sql, the value is treated as a path to a SQL file, resolved relative to the current working directory. Loading must:
