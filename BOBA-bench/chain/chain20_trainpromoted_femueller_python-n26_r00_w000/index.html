Objective

A configuration container that holds three fields: username, password, and card_id.

Requirements:

  • Two Config instances constructed with the same username, password, and card_id values must compare as equal (==).
get_config() function

Signature: get_config() (no arguments).

Returns a Config instance populated with credentials, using the following resolution logic:

  1. Environment variables (highest priority): Read credentials from these environment variables:

    • N26_USER → username
    • N26_PASSWORD → password
    • N26_CARD_ID → card_id

    If these environment variables are present and non-empty, use their values to build and return the Config.

  2. YAML file fallback: If the environment variables are absent or empty, load credentials from a YAML configuration file located at a path obtained by calling os.path.expanduser(...).     password: $upersecret
    card_id: "123456789"

Behavior Details

  • When all three environment variables (N26_USER, N26_PASSWORD, N26_CARD_ID) are set to non-empty values, get_config() returns a Config with those values, and the YAML file is not consulted.
  • When those environment variables are empty strings, get_config() falls back to reading the YAML file (via the os.path.expanduser-resolved path) and returns a Config built from the file's n26 section.
  • card_id values are treated as strings (e.g. "123456789").

  • The command must run end-to-end (retrieving and rendering transaction data) and produce output when both --from and --to are supplied as human-readable datetime strings in any of the supported formats.
  • No behavior beyond parsing these two datetime options and producing non-empty output is required to be verified by this task.

Logging

The package's logging must be organized under a logger named n26 (i.e., logging.getLogger("n26")), so that log output from the package is emitted through that logger hierarchy.
