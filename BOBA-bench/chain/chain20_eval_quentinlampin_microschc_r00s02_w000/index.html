02 Implement a parser for the SCTP (Stream Control Transmission Protocol) header that decomposes a raw byte buffer into a structured list of field descriptors. 776 words · source specification

Task: Implement an SCTP Header Parser

Overview

Implement a parser for the SCTP (Stream Control Transmission Protocol) header that decomposes a raw byte buffer into a structured list of field descriptors. The parser must handle the SCTP common header, a chunk common header, and a DATA chunk (including its payload and trailing padding).

Module and Public API

Create the module microschc/protocol/sctp.py exposing the following public names:

SCTPFields

A container of string constants used as field identifiers. It must define (at minimum) the following attributes, each carrying a descriptive string identifier value:

  • SOURCE_PORT
  • DESTINATION_PORT
  • VERIFICATION_TAG
  • CHECKSUM
  • CHUNK_TYPE
  • CHUNK_FLAGS
  • CHUNK_LENGTH
  • CHUNK_DATA_TSN
  • CHUNK_DATA_STREAM_IDENTIFIER
  • CHUNK_DATA_STREAM_SEQUENCE_NUMBER
  • CHUNK_DATA_PAYLOAD_PROTOCOL_IDENTIFIER
  • CHUNK_DATA_PAYLOAD
  • CHUNK_PADDING

The concrete string values are not constrained beyond being distinct identifiers per field; they are used only as the id of the produced field descriptors.

SCTPParser

A class that can be instantiated with no arguments: SCTPParser().

It must provide a method:

def parse(self, buffer: Buffer) -> HeaderDescriptor

where Buffer is microschc.binary.buffer.Buffer and HeaderDescriptor is microschc.parser.parser.HeaderDescriptor.

Supporting Types (already available in the codebase)

  • microschc.binary.buffer.Buffer — constructed as Buffer(content=<bytes>, length=<bit_length>). Two Buffer instances are equal when their content and bit-length are equal.
  • microschc.parser.parser.HeaderDescriptor — has a fields attribute that is a list of FieldDescriptor.
  • microschc.rfc8724.FieldDescriptor — each has at least id, position, and value attributes. value is a Buffer.

Required Parsing Behavior

Given a Buffer whose content is an SCTP packet, parse returns a HeaderDescriptor whose fields is an ordered list of FieldDescriptor objects. Each FieldDescriptor must have position equal to 0, id set to the corresponding SCTPFields constant, and value set to a Buffer containing exactly the bits of that field.

The packet layout to parse consists of, in order:

SCTP common header (12 bytes):

  1. Source Port Number — 16 bits — id SCTPFields.SOURCE_PORT
  2. Destination Port Number — 16 bits — id SCTPFields.DESTINATION_PORT
  3. Verification Tag — 32 bits — id SCTPFields.VERIFICATION_TAG
  4. Checksum — 32 bits — id SCTPFields.CHECKSUM

Chunk common header: 5. Chunk Type — 8 bits — id SCTPFields.CHUNK_TYPE 6. Chunk Flags — 8 bits — id SCTPFields.CHUNK_FLAGS 7. Chunk Length — 16 bits — id SCTPFields.CHUNK_LENGTH

The 16-bit Chunk Length value gives the number of bytes in the chunk, counting from the start of the chunk common header (i.e. from the Chunk Type field) up to and including the chunk's data/value, but excluding any trailing padding needed to align the chunk to a 4-byte boundary.

DATA chunk body (this chunk has Chunk Type 0, a DATA chunk): 8. TSN — 32 bits — id SCTPFields.CHUNK_DATA_TSN 9. Stream Identifier — 16 bits — id SCTPFields.CHUNK_DATA_STREAM_IDENTIFIER 10. Stream Sequence Number — 16 bits — id SCTPFields.CHUNK_DATA_STREAM_SEQUENCE_NUMBER 11. Payload Protocol Identifier — 32 bits — id SCTPFields.CHUNK_DATA_PAYLOAD_PROTOCOL_IDENTIFIER 12. Payload — id SCTPFields.CHUNK_DATA_PAYLOAD. Its length in bits is determined by the Chunk Length: the payload occupies the remaining bytes of the chunk after the chunk common header (4 bytes) and the DATA chunk fixed fields (TSN 4 bytes, Stream Identifier 2 bytes, Stream Sequence Number 2 bytes, Payload Protocol Identifier 4 bytes = 12 bytes). Thus payload byte length = Chunk Length - 4 - 12.

Chunk padding: 13. Padding — id SCTPFields.CHUNK_PADDING. After the chunk, there may be padding bytes so that the total chunk length (chunk common header + chunk body + padding) is a multiple of 4 bytes. The padding field's value must contain exactly those padding bytes. If the chunk is already 4-byte aligned, no padding field is produced.

Example (concrete)

For an input packet where:

  • Source Port = 0x250f
  • Destination Port = 0x960c
  • Verification Tag = 0xc9596db9
  • Checksum = 0x00000000
  • Chunk Type = 0x00, Chunk Flags = 0x03, Chunk Length = 0x0049 (73 bytes)
  • TSN = 0xbc5bc068
  • Stream Identifier = 0x0000
  • Stream Sequence Number = 0x0000
  • Payload Protocol Identifier = 0x0000003c
  • Payload = 57 bytes (73 − 4 − 12 = 57 bytes → 456 bits)
  • Padding = 3 bytes (73 rounded up to 76 → 3 padding bytes → 24 bits)

The returned HeaderDescriptor.fields is a list of 13 FieldDescriptor objects in exactly the order listed above, each with position == 0 and the described id and value.

Notes

  • The order of fields in the returned list is significant and must match the order given above.
  • All field values are Buffer objects whose bit length matches the field's bit width as described.
  • Only DATA chunks (Chunk Type 0) with a single chunk followed by optional padding need to be handled for the described behavior.

The following must be importable and usable exactly as described.

Parser

  • SCTPFields.SOURCE_PORT
  • SCTPFields.DESTINATION_PORT
  • SCTPFields.VERIFICATION_TAG

  • SCTPFields.PARAMETER_LENGTH

Required Behavior

SCTPParser.parse receives a Buffer wrapping the full SCTP header bytes and returns a HeaderDescriptor whose fields list contains, in order, one FieldDescriptor per parsed field. For every FieldDescriptor:

  • position is 0.
  • value is a Buffer whose content is the raw bytes of that field and whose length is the field length in bits.
Common SCTP header (always parsed first, in order)
Order id Bit length
Source Port Number SOURCE_PORT 16
Destination Port Number DESTINATION_PORT 16
Verification Tag VERIFICATION_TAG 32
Checksum CHECKSUM 32
Chunk common header (parsed next, in order)
Order id Bit length
Chunk Type CHUNK_TYPE 8
Chunk Flags CHUNK_FLAGS 8
Chunk Length CHUNK_LENGTH 16
INIT chunk body (when Chunk Type = 1)

When the chunk type byte equals 0x01, after the chunk common header the following fixed fields are parsed, in order:

Order id Bit length
Initiate Tag CHUNK_INIT_INITIATE_TAG 32
Advertised Receiver Window Credit CHUNK_INIT_ADVERTISED_RECEIVER_WINDOW_CREDIT 32
Number of Outbound Streams CHUNK_INIT_NUMBER_OF_OUTBOUND_STREAMS 16
Number of Inbound Streams CHUNK_INIT_NUMBER_OF_INBOUND_STREAMS 16
Initial TSN CHUNK_INIT_INITIAL_TSN 32
INIT chunk parameters (following the fixed INIT fields)

After the fixed INIT fields, the remainder of the chunk consists of zero or more parameters. Each parameter is encoded as a Type-Length-Value structure and is parsed into FieldDescriptors in order:

  • Parameter Type — PARAMETER_TYPE, 16 bits.
  • Parameter Length — PARAMETER_LENGTH, 16 bits. This value is the total length in bytes of the parameter, counting the 2-byte type field, the 2-byte length field, and the value bytes (but not any trailing padding).
  • Parameter Value — PARAMETER_VALUE, present only when the parameter length indicates value bytes exist (i.e., length > 4). Its bit length equals (parameter_length - 4) * 8.
  • Parameter Padding — PARAMETER_PADDING, present only when the parameter's value length is not a multiple of 4 bytes. Padding brings the parameter's total occupied length up to the next multiple of 4 bytes; its bit length equals the number of padding bytes × 8.

Parameters are parsed sequentially until the input is consumed. A parameter with length exactly 4 (type + length only, no value) yields only the PARAMETER_TYPE and PARAMETER_LENGTH descriptors, with neither value nor padding descriptors.

Worked example of parameter handling

For an INIT chunk whose trailing bytes are:

\xc0\x00 \x00\x04            (parameter 1: type=0xc000, length=4, no value, no padding)
\x00\x0c \x00\x06 \x00\x05 \x00\x00   (parameter 2: type=0x000c, length=6, value=2 bytes, padding=2 bytes)

the produced parameter field descriptors are, in order:

  • PARAMETER_TYPE = \xc0\x00 (16 bits)
  • PARAMETER_LENGTH = \x00\x04 (16 bits)
  • PARAMETER_TYPE = \x00\x0c (16 bits)
  • PARAMETER_LENGTH = \x00\x06 (16 bits)
  • PARAMETER_VALUE = \x00\x05 (16 bits)
  • PARAMETER_PADDING = \x00\x00 (16 bits)

Concrete end-to-end expectation

Given the 44-byte input:

43 23 25 44 00 00 ff ff 00 11 00 11 5c fe 37 9f
c0 00 00 04 00 0c 00 06 00 05 00 00

  2. DESTINATION_PORT = \x00\x07 (16)
  3. VERIFICATION_TAG = \x00\x00\x00\x00 (32)
  4. CHECKSUM = \x37\x61\xa7\x46 (32)
  5. CHUNK_TYPE = \x01 (8)
  6. CHUNK_FLAGS = \x00 (8)
  7. CHUNK_LENGTH = \x00\x20 (16)
  8. CHUNK_INIT_INITIATE_TAG = \x43\x23\x25\x44 (32)
  9. CHUNK_INIT_ADVERTISED_RECEIVER_WINDOW_CREDIT = \x00\x00\xff\xff (32)
  10. CHUNK_INIT_NUMBER_OF_OUTBOUND_STREAMS = \x00\x11 (16)

Task Specification: SCTP INIT_ACK Chunk Parsing

Objective

Extend the existing SCTP header parser so that it can parse SCTP packets whose payload begins with an INIT_ACK chunk (chunk type 0x02), decomposing the packet into a flat list of field descriptors.

Public API

The parser must be importable and usable via the following surface (already established by existing DATA and INIT chunk support; INIT_ACK must integrate consistently):

  • SCTPParser — a class with a no-argument constructor.
    • Method: parse(self, buffer: Buffer) -> HeaderDescriptor
  • SCTPFields — an enumeration/namespace of field identifier constants (see required members below).
  • HeaderDescriptor — an object with a .fields attribute (a list of FieldDescriptor).
  • FieldDescriptor — an object with attributes .id, .position (int), and .value (a Buffer).
  • Buffer — a byte-content container constructed as Buffer(content: bytes, length: int), where length is expressed in bits. Two Buffer instances are equal when their content and bit-length match.

These types live in the same modules already used by the existing SCTP parser tests; do not change their locations.

Required SCTPFields members

The following identifier constants must exist and be used by the parser:

  • SCTPFields.SOURCE_PORT
  • SCTPFields.DESTINATION_PORT
  • SCTPFields.VERIFICATION_TAG
  • SCTPFields.CHECKSUM
  • SCTPFields.CHUNK_TYPE
  • SCTPFields.CHUNK_FLAGS
  • SCTPFields.CHUNK_LENGTH
  • SCTPFields.CHUNK_INIT_ACK_INITIATE_TAG
  • SCTPFields.CHUNK_INIT_ACK_ADVERTISED_RECEIVER_WINDOW_CREDIT
  • SCTPFields.CHUNK_INIT_ACK_NUMBER_OF_OUTBOUND_STREAMS
  • SCTPFields.CHUNK_INIT_ACK_NUMBER_OF_INBOUND_STREAMS
  • SCTPFields.CHUNK_INIT_ACK_INITIAL_TSN
  • SCTPFields.PARAMETER_TYPE
  • SCTPFields.PARAMETER_LENGTH
  • SCTPFields.PARAMETER_VALUE

(The existing DATA/INIT field members must remain functional; only add what is missing.)

Input

parse receives a single Buffer whose content is the raw SCTP packet bytes and whose length equals len(content) * 8.

Parsing behavior for an INIT_ACK chunk

The packet layout to parse (when the chunk type byte is 0x02) is:

Common SCTP header (12 bytes)

Produce these field descriptors in order:

  1. SOURCE_PORT — 16 bits, bytes 0–1.
  2. DESTINATION_PORT — 16 bits, bytes 2–3.
  3. VERIFICATION_TAG — 32 bits, bytes 4–7.
  4. CHECKSUM — 32 bits, bytes 8–11.
INIT_ACK chunk common header
  1. CHUNK_TYPE — 8 bits (value 0x02 for INIT_ACK).
  2. CHUNK_FLAGS — 8 bits.
  3. CHUNK_LENGTH — 16 bits. This is the total length in bytes of the chunk (chunk type + flags + length + fixed fields + all parameters, before final chunk padding).
INIT_ACK fixed fields
  1. CHUNK_INIT_ACK_INITIATE_TAG — 32 bits.
  2. CHUNK_INIT_ACK_ADVERTISED_RECEIVER_WINDOW_CREDIT — 32 bits.
  3. CHUNK_INIT_ACK_NUMBER_OF_OUTBOUND_STREAMS — 16 bits.
  4. CHUNK_INIT_ACK_NUMBER_OF_INBOUND_STREAMS — 16 bits.
  5. CHUNK_INIT_ACK_INITIAL_TSN — 32 bits.
Variable-length parameters (Type-Length-Value)

After the fixed fields, the remainder of the chunk consists of zero or more parameters. Each parameter begins with:

  • PARAMETER_TYPE — 16 bits.
  • PARAMETER_LENGTH — 16 bits. This value is the number of bytes covering the type, length, and value fields together (i.e. 4 + value_byte_length).

Then, only when the parameter carries a value (i.e. PARAMETER_LENGTH > 4):

  • PARAMETER_VALUE — (PARAMETER_LENGTH - 4) * 8 bits, containing exactly the parameter's value bytes (no padding included).

When PARAMETER_LENGTH == 4 there is no value, so no PARAMETER_VALUE descriptor is emitted for that parameter — only its PARAMETER_TYPE and PARAMETER_LENGTH.

Parameters must be consumed sequentially until the chunk's declared length (CHUNK_LENGTH) is exhausted. Parameter parsing must be driven by the chunk length, and internal padding must be accounted for so consecutive parameters are located at correct offsets. No parameter-padding field descriptor is emitted in this scenario.

Output ordering and count

HeaderDescriptor.fields must be a list of FieldDescriptor objects in the exact order the fields appear in the packet. Every field descriptor's position is 0. Each descriptor's value is a Buffer whose content is the raw bytes of that field and whose bit-length equals the field's bit width as specified above.

Concrete example

For an INIT_ACK packet consisting of the common header, the INIT_ACK fixed fields, one parameter of type 0x0007 with a 800-bit (100-byte) value, and one parameter of type 0xc000 with declared length 0x0004 (no value), the resulting fields list contains exactly 17 descriptors, in order:

  1. SOURCE_PORT = b'\x00\x07' (16)
  2. DESTINATION_PORT = b'\x00\x07' (16)
  3. VERIFICATION_TAG = b'\x43\x23\x25\x44' (32)
  4. CHECKSUM = b'\xc9\x01\x85\x24' (32)
  5. CHUNK_TYPE = b'\x02' (8)
  6. CHUNK_FLAGS = b'\x00' (8)
  7. CHUNK_LENGTH = b'\x00\x80' (16)
  8. CHUNK_INIT_ACK_INITIATE_TAG = b'\x00\x00\x0e\xb0' (32)
  9. CHUNK_INIT_ACK_ADVERTISED_RECEIVER_WINDOW_CREDIT = b'\x00\x00\x10\x00' (32)
  10. CHUNK_INIT_ACK_NUMBER_OF_OUTBOUND_STREAMS = b'\x00\x11' (16)
  11. CHUNK_INIT_ACK_NUMBER_OF_INBOUND_STREAMS = b'\x00\x11' (16)
  12. CHUNK_INIT_ACK_INITIAL_TSN = b'\x00\x00\x36\x14' (32)
  13. PARAMETER_TYPE = b'\x00\x07' (16)
  14. PARAMETER_LENGTH = b'\x00\x68' (16)
  15. PARAMETER_VALUE = the 100 value bytes (800 bits)
  16. PARAMETER_TYPE = b'\xc0\x00' (16)
  17. PARAMETER_LENGTH = b'\x00\x04' (16)

Note in this example that the first parameter's declared length (0x68 = 104) covers 4 header bytes plus 100 value bytes; the second parameter's declared length is 4, so it emits no value descriptor.

Constraints

  • Existing SCTP parsing behavior for DATA and INIT chunks must remain intact and unchanged.
  • The return value is always a HeaderDescriptor instance.

Checksum Computation Function

Signature

The callable retrieved via SCTPComputeFunctions[SCTPFields.CHECKSUM][0] must accept two positional arguments:

compute_fn(decompressed_fields: List[Tuple[str, Buffer]], field_position: int) -> Buffer
  • decompressed_fields: an ordered list of (field_id, value) pairs, where each field_id is an SCTP field identifier string and each value is a microschc.binary.buffer.Buffer. This list represents the fully parsed field sequence of an SCTP packet, in header/packet order, as produced by parsing a complete SCTP packet.
  • field_position: an integer index. This identifies which occurrence/position within the field sequence corresponds to the checksum field being computed (the checksum field's position in the packet layout).
Behavior

The function must compute the SCTP CRC-32c checksum over the entire SCTP packet reconstructed from the provided decompressed_fields, with the checksum field itself treated as zero (i.e., the four checksum bytes are set to 0x00000000 before computing the CRC).

The reconstruction concatenates all field values in the order given by decompressed_fields to form the full SCTP packet byte sequence. The checksum is then calculated per the SCTP standard (CRC-32c / Castagnoli), and the resulting 32-bit checksum is placed into the packet in the byte order required by SCTP.

Return Value

The function must return a microschc.binary.buffer.Buffer of length 32 bits containing the computed 4-byte checksum.

Worked Example

Given an SCTP packet whose full byte content is:

00 07 00 07 00 00 00 00 00 00 00 00 01 00 00 20
43 23 25 44 00 00 ff ff 00 11 00 11 5c fe 37 9f
c0 00 00 04 00 0c 00 06 00 05 00 00

(where bytes at offset 8..11 are the checksum field, here already zeroed), parsing this packet with SCTPParser().parse(...) and passing the resulting field list together with field_position = 3 to the compute function must yield:

Buffer(content=b'\x37\x61\xa7\x46', length=32)

Constraints

  • The existing behavior of SCTPParser and SCTPFields must remain unchanged; parsing a complete SCTP packet continues to produce a HeaderDescriptor whose fields are FieldDescriptor objects exposing .id and .value attributes.
  • No other new public behavior is required.
