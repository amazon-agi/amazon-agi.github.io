  • Invalid assignments raise the descriptor-specific exception documented below.
  • Deleting a descriptor-managed instance attribute is forbidden and raises AttributeError.

The module's general-purpose descriptor foundations remain public:

Descriptor Contracts

General typed attributes
  • Typed validates values with its configured expected_type.
  • TypedAttribute(expected_type=...) accepts values satisfying isinstance(value, expected_type) and raises TypeError for all other values. The expected_type option is mandatory.
  • Real accepts real numbers and rejects non-real values, including complex numbers, with TypeError.
  • Int accepts integer values. A non-integer value, such as a float, raises TypeError; negative integers remain valid.
  • String accepts strings and raises TypeError for non-string values.
Sign-constrained scalars
  • UnsignedReal accepts real values greater than or equal to zero. Assigning a negative real value raises TypeError.
  • UnsignedInt accepts integer values greater than or equal to zero. Assigning a negative integer raises TypeError.
  • PositiveReal accepts only real values strictly greater than zero. Assigning zero or a negative real value raises TypeError.

The sign violations above are part of this API's type/constraint validation contract. They must not be reported as ValueError merely because the assigned object is otherwise numeric.

Vectors and fixed sizes
  • Vector accepts non-scalar vector containers represented by a list, tuple, or NumPy array. It does not constrain the number or type of components. A scalar or a string is not an accepted vector and raises TypeError.
  • SizedVector(size=n) accepts the same vector container types as Vector but requires exactly n components. Both shorter and longer vectors raise TypeError.
  • RealVector(size=n) requires an accepted vector container of exactly n components, with every component being a real number. A wrong-length vector raises TypeError. A vector of the correct length containing a non-real component, such as a complex number, also raises TypeError. Negative real components are valid for this descriptor.
  • PositiveRealVector(size=n) requires an accepted vector container of exactly n real components, all strictly greater than zero. A wrong length, a non-real component, or any zero or negative component raises TypeError.
  • A fixed-length integer-valued vector constraint requires exactly the declared number of components and requires every component to be an integer. A wrong-length value or a component of another type, such as a float, raises TypeError.

A vector length mismatch is a validation/type mismatch for this API even when the supplied object is otherwise an accepted vector container. It must therefore raise TypeError, not ValueError.

Object names

ObjectName accepts identifier-like strings used as object names. A valid name starts with a letter or underscore and contains no spaces; digits may appear after the initial character. Examples of valid values include "exchange_energy_name" and "_new_name2".

Assigning a non-string or an invalid name raises TypeError. Invalid examples include a value containing a space, such as "new name2", and a value starting with a digit, such as "2newname2".

Required Configuration Errors

Configuration omissions must fail immediately with TypeError:

  • Constructing or installing TypedAttribute without expected_type raises TypeError.
  • Constructing or installing SizedVector without size raises TypeError. The same required size contract applies to its fixed-size subclasses such as RealVector and PositiveRealVector.

Consequently, using a bare configuration-dependent class such as @ts.typesystem(a=ts.SizedVector) or @ts.typesystem(a=ts.TypedAttribute) is invalid and raises TypeError while the decorated class is being created.

Assignment, Retrieval, and Deletion

Successful assignments must preserve the supplied value and make it available through ordinary instance attribute access. This applies to values assigned in an __init__ method as well as later reassignments.

Controlled attributes cannot be deleted. Attempting del instance.attribute for a descriptor-managed attribute raises AttributeError.

Exception Summary

The following all require TypeError:

  • assigning an object of the wrong scalar type;
  • assigning a scalar or string where a vector is required;
  • assigning a vector with the wrong fixed length;
  • assigning a fixed-length vector with a component of the wrong type;
  • assigning a negative value to an unsigned scalar descriptor;
  • assigning zero or a negative value to a strictly positive scalar descriptor;
  • assigning a positive-real vector containing a zero or negative component;
  • assigning an invalid object name; and
  • omitting a mandatory descriptor configuration option.

In particular, neither fixed-length mismatches nor sign/range violations covered by these descriptors may be changed to ValueError. Assignment of conforming values succeeds silently.

A non-string raises TypeError. A string beginning with a digit or hyphen, or a string containing a space, raises ValueError. Accepted names are stored unchanged.

ts.InSet

ts.InSet(allowed_values=..., const=...) accepts a value when it is a member of allowed_values and stores it unchanged. A value that is not a member raises ValueError. If the descriptor is constant, reassignment after successful initialization raises AttributeError.

ts.Subset

ts.Subset(sample_set=..., const=...) requires the assigned value to be iterable and every distinct element in it to belong to sample_set.

  • Empty iterables are valid.
  • Repeated elements are valid.
  • On success, the attribute stores a set containing the assigned value's distinct elements.
  • A non-iterable raises TypeError.
  • An iterable containing an element outside sample_set raises ValueError.
  • If the descriptor is constant, reassignment after successful initialization raises AttributeError.

For example, with sample_set="xyz", each of [], "x", "yx", and "yxzz" is valid, while "a" and [1] raise ValueError.

ts.Parameter

Parameter supports the keyword options descriptor, const, and otherwise. The descriptor option is optional at construction time, so all of the following must be valid declarations:

ts.Parameter()
ts.Parameter(descriptor=ts.Scalar())
ts.Parameter(descriptor=ts.Vector(size=3))
ts.Parameter(descriptor=ts.Scalar(), otherwise=tuple)

A configured Parameter(descriptor=d) accepts either:

  1. a single value accepted by d; or
  2. a non-empty dictionary whose keys satisfy Name and whose values are each accepted by d.

The accepted scalar, vector, fallback value, or dictionary is stored in its original form. Dictionary keys must therefore be strings beginning with a letter or underscore and containing no spaces. Malformed string keys raise ValueError, and non-string keys raise TypeError. An empty dictionary raises ValueError. Errors from wrapped value validation retain their descriptor-specific class: type failures raise TypeError, while value or constraint failures raise ValueError. If any key or value is invalid, a previously stored parameter value remains unchanged.

otherwise=T adds an alternative accepted type using isinstance. A matching fallback value is accepted unchanged without wrapped-descriptor validation. For example, ts.Parameter(descriptor=ts.Scalar(), otherwise=tuple) accepts tuples, scalar values, and non-empty name-to-scalar dictionaries, but does not thereby accept lists or dictionaries with non-scalar values.

A descriptor-less ts.Parameter() must be accepted by ts.typesystem; the absence of descriptor is not a construction-time error. If an attribute backed by that unconfigured parameter is assigned (0, 0, 1), it must raise AttributeError, including when the assignment occurs while handling a constructor keyword argument.

Once a Parameter(const=True) has been successfully initialized, any later assignment must raise AttributeError.

ts.Dictionary

Add and export the public Dictionary descriptor. It must support at least these constructor forms:

ts.Dictionary(
    key_descriptor=ts.Name(),
    value_descriptor=ts.Scalar(),
)

ts.Dictionary(
    value_descriptor=ts.Scalar(),
)

It must be usable as a descriptor supplied to ts.typesystem. An assignment must be a non-empty dictionary; non-dictionary values raise TypeError, and an empty dictionary raises ValueError. When both descriptors are configured, every key is validated by key_descriptor and every value by value_descriptor, and a valid dictionary is stored as the attribute value.

For the concrete configuration using Name keys and Scalar values:

  • assigning {"a": 1, "b": -3} succeeds;
  • reassigning {"a": 15, "b": -51} succeeds, and reading the attribute returns a dictionary equal to that value;
  • assigning 5 raises TypeError; and
  • assigning {} raises ValueError.

Constructing ts.Dictionary(value_descriptor=ts.Scalar()) without a key descriptor must itself succeed. Assigning {"a": 15, "b": -51} through such an incompletely configured descriptor must raise AttributeError.
