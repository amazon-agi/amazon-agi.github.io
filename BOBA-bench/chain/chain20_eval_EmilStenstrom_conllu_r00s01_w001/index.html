01 Your work takes place in a CoNLL-U parsing library. 726 words · source specification, reworded by GLM-5.3-Flash

Overview

Your work takes place in a CoNLL-U parsing library. The task consists of two related changes: (1) repairing the parsing of dependency relations so that valid dependency labels containing uppercase letters and digits are parsed correctly, and (2) supplying a doctest-parsing helper class that is used to run the examples embedded in the project's README.

Part 1: Fixing dependency-relation ("deps") parsing

Public API

A function exists:

parse_paired_list_value(value)

which resides in the module conllu.parser (importable as from conllu.parser import parse_paired_list_value).

Required behavior

The function is given a string representing the enhanced-dependencies column value from a CoNLL-U record. A value is well-formed when it is a |-separated list of entries, where each entry has the form HEAD:DEPREL. Within this form:

  • HEAD is an ID value, and it may be:
    • a plain integer (e.g. 5), returned as an int;
    • an "empty node" ID of the form <int>.<int> (e.g. 8.1), returned as the tuple (major, ".", minor), where major and minor are ints.
  • DEPREL is the dependency relation label, which may itself contain colons separating subtypes (e.g. conj:and, nsubj:pass).

If the whole value matches the well-formed pattern, the function must return a list of (deprel, head) tuples — exactly one per |-separated entry, in order — where deprel is the label string (everything after the entry's first colon) and head is the parsed ID value as described above.

Examples of the results that are required:

  • "5:conj:and|8.1:nsubj:pass|9:nsubj:xsubj" → [("conj:and", 5), ("nsubj:pass", (8, ".", 1)), ("nsubj:xsubj", 9)]
  • "1:compound|6:ARG|9:ARG1|10:ARG2" → [('compound', 1), ('ARG', 6), ('ARG1', 9), ('ARG2', 10)]
The specific bug to be fixed

When a label contains uppercase letters and/or trailing digits, it must be accepted, as long as the label is otherwise valid. In particular:

  • A label may start with letters and end with digits (e.g. ARG1, ARG2).
  • A label made up purely of uppercase letters (e.g. ARG) is valid.
  • Values with a single entry, such as "4:ARG1", and values with multiple entries, such as "1:compound|6:ARG1|9:ARG1", must be recognized as well-formed and parsed into the list-of-tuples form.

However, a label must not be treated as valid when its (final, post-colon) segment starts with a digit. For instance, in the entry 10:2ARG, the label 2ARG starts with a digit and is therefore not a valid dependency relation. As a result, a value such as "1:compound|6:ARG|9:ARG1|10:2ARG" must not parse into [('compound', 1), ('ARG', 6), ('ARG1', 9), ('2ARG', 10)]. (It is enough for the result to differ from that list; when the overall value does not match the well-formed pattern, the fallback behavior below applies.)

Fallback for values that do not match

When the entire value does not match the well-formed pattern, the function must fall back to parsing it as a nullable single value (the existing behavior for null/underscore-style values). A helper already implements this; the only change required is to broaden the pattern so that valid relation labels containing uppercase letters and/or trailing digits are recognized as well-formed, while still rejecting labels whose final segment starts with a digit.

03 Support Multiple Metadata Pairs on a Single Comment Line 545 words · source specification, reworded by GLM-5.3-Flash

Task Specification: Support Multiple Metadata Pairs on a Single Comment Line

Overview

Update the metadata parsing behavior so that one comment line can yield multiple metadata key/value pairs. Two public functions in the parser module are affected: parse_comment_line and parse_token_and_metadata.

Public API

As before, both functions are importable from the same module (the one that currently exposes parse_token_and_metadata and parse_comment_line).

parse_comment_line(line)
  • Input: one string that represents a single comment line.
  • Output: a list of (key, value) tuples (a single tuple was returned previously; it must now always return a list).

The following behavior is required:

  1. A valid comment line starts with # (the # may optionally be preceded by whitespace such as spaces or tabs; whitespace between # and the content is also tolerated).

  2. Key/value form — a line shaped like # key = value:

    • It returns [(key, value)].
    • Surrounding whitespace is stripped from both the key and the value.
    • Only the first = separates the key from the value; any = characters after that one are part of the value. For example, # text = five plus three = eight yields [("text", "five plus three = eight")].
    • The content may immediately follow the leading # with no space, e.g. #sent_id = 1 yields [("sent_id", "1")].

  3. Optional-value (flag) form — a comment line whose content is one recognized keyword with no value:

    • The recognized keywords are newdoc and newpar.
    • Each of # newdoc, # newpar, #newdoc, #newpar (with or without the space after #) yields [(keyword, None)], e.g. [("newdoc", None)].

  4. Invalid / unrecognized lines — an empty list [] is returned. This applies to:

    • A comment line whose content is neither a key/value pair nor a recognized keyword, e.g. # invalid or # sent_id: 1 (no = present and not a recognized keyword).

  5. Not a comment line — a string that does not begin with # (after leading whitespace), e.g. sent_id = 1. The behavior that existed for this case before the change is unchanged; do not modify it.

parse_token_and_metadata(data, ..., metadata_parsers=...)

The function keeps its existing signature and returns its existing pair of results (a tokens structure and a metadata OrderedDict). What changes is how results from custom metadata_parsers are incorporated.

  • metadata_parsers maps a metadata key name to a callable parser(key, value).
  • A custom parser callable may now return either:
    • one (key, value) pair, or
    • a list of (key, value) pairs.
  • If a parser returns a list containing multiple pairs, all of those pairs must be inserted into the resulting metadata OrderedDict, with their order preserved.

Example of the multi-pair case: for a comment line

#	id='1'-document_id='36:1047'-span='1'

together with a custom parser registered under the key "id" that returns

[("id", "1"), ("document_id", "36:1047"), ("span", "1")]

the metadata OrderedDict that is produced must contain, in order:

OrderedDict([("id", "1"), ("document_id", "36:1047"), ("span", "1")])

Constraints

  • For standard key/value comment lines, the existing single-pair parsing behavior and the existing metadata handling (e.g. producing an OrderedDict of metadata) must continue to work.
  • parse_comment_line must now return a list uniformly, in every case (including an empty list for invalid lines and single-element lists for valid single pairs).

Task Specification: Custom Metadata Fallback Parser

Summary

The parse_token_and_metadata function is to be extended so that it supports a fallback metadata parser which deals with metadata lines that do not match any explicitly-registered metadata key.

API

The function can be imported as:

parse_token_and_metadata(data, metadata_parsers=None)

Its return value is a 2-tuple (tokens, metadata), in which metadata is an collections.OrderedDict that maps metadata field names to their parsed values.

Format of the Input

Input data is a string that contains lines. Metadata is carried on comment lines that begin with #. A metadata line generally has the form:

# key = value

but it may also appear with no key/value separator, in which case the whole remaining content of the line (the part after the #, with surrounding whitespace stripped) is treated as a single unstructured token — e.g. a line such as #20191005 yields the raw string 20191005.

Required Behavior: Fallback Metadata Parsing

The metadata_parsers argument is a mapping of metadata key names to parser callables. This task introduces a special key — the string "__fallback__" — whose associated callable serves as a catch-all parser.

When a metadata line corresponds to none of the specifically-registered parser keys, the fallback parser (if it is present under "__fallback__") is invoked to interpret it.

The callable acting as the fallback parser has the signature:

fallback(key, value) -> (result_key, result_value)
  • The parsed components of the metadata line are given to it as its arguments.
  • Its return value is a 2-tuple: the field name to store in the resulting metadata dictionary, and the value to store under that name.
Concrete Case

When a fallback parser is supplied and the input line consists solely of #20191005 (with no = separator):

  • The fallback parser is called with the content of the line ("20191005") as its first argument.
  • If a fallback parser is defined as lambda key, value: ("sentence-id", key), the resulting metadata must be:
OrderedDict([("sentence-id", "20191005")])

In other words, the field name "sentence-id" maps to the string "20191005".

Restrictions

  • The metadata_parsers argument is optional and may be passed as a keyword.
  • Behavior that already exists for standard metadata parsing must remain unchanged.

Task: Add Auto-Detection of CoNLL-U Plus Columns

Summary

Support must be added for the CoNLL-U Plus format, in which the columns (field names) of the data are declared inside the input by way of a special # global.columns = ... comment line, instead of being assumed to be the default CoNLL-U column set. Whenever such a declaration is present, parsing must use the declared columns when interpreting each token's fields.

Public API to Implement

conllu.parser.parse_conllu_plus_fields

Add this new function to the conllu.parser module:

def parse_conllu_plus_fields(in_file):
    ...

Input: in_file is a file-like object (an object with the interface produced by conllu.compat.string_to_file). It may wrap an empty string or None.

Behavior: Look through the input for a comment line that declares the global columns. A declaration line has this form:

# global.columns = ID FORM UPOS HEAD DEPREL MISC PARSEME:MWE
  • If a global.columns declaration is found that has one or more whitespace-separated column names, return a Python list of those column names, each one lowercased, in the order in which they appear. For example, the line above yields:
    ["id", "form", "upos", "head", "deprel", "misc", "parseme:mwe"]
  • If the input is empty (an empty string or None wrapped by the file-like object), return None.
  • If a global.columns declaration is present but contains no column names (i.e. # global.columns = with nothing after the =), return None.

The function must not consume/exhaust the caller's ability to still parse the same data — what it returns is only the field list, or None.

Integration with Parsing

The existing top-level conllu.parse function must detect and honor a global.columns declaration in the input data automatically.

Whenever the input contains a valid # global.columns = ... declaration, the field names used for each token are the columns declared there (lowercased, as above). Each token becomes an OrderedDict whose keys are exactly those declared field names, in the declared order, each key mapped to the corresponding value parsed from that token's tab-separated columns.

Rules for parsing values (as applied under the declared columns)

On a token line under the declared columns, values are parsed in a way consistent with the existing CoNLL-U field handling:

  • When an id field holds a plain integer, it becomes that integer (e.g. 5 → 5).
  • When a head field holds an integer, it becomes that integer (e.g. 0 → 0).
  • A field with a raw value of _ becomes None (e.g. a misc value of _).
  • Other textual fields (e.g. form, upos, deprel, parseme:mwe) keep their string value.

Example. For input containing the following:

# global.columns = ID FORM UPOS HEAD DEPREL MISC PARSEME:MWE
# source_sent_id = conllu http://hdl.handle.net/11234/1-2837 UD_German-GSD/de_gsd-ud-train.conllu train-s16
# sent_id = train-s16
# text = Der CDU-Politiker strebt
1	Der	DET	2	det	_	*
2	CDU	PROPN	4	compound	SpaceAfter=No	*
3	-	PUNCT	2	punct	SpaceAfter=No	*
4	Politiker	NOUN	5	nsubj	_	*
5	strebt	VERB	0	root	_	2:VPC.full

parsing yields sentences in which the fifth token (the strebt line) is:

OrderedDict([
    ('id', 5),
    ('form', 'strebt'),
    ('upos', 'VERB'),
    ('head', 0),
    ('deprel', 'root'),
    ('misc', None),
    ('parseme:mwe', '2:VPC.full'),
])

When there is no valid global.columns declaration, the existing default parsing behavior is left unchanged.

Notes

  • It must be possible to import parse_conllu_plus_fields from conllu.parser.
  • The existing exports of conllu.parser (including DEFAULT_FIELDS, ParseException, head_to_token, parse_comment_line, parse_dict_value, parse_id_value, parse_int_value, parse_line, parse_nullable_value, parse_paired_list_value, parse_sentences, parse_token_and_metadata, serialize, serialize_field) must remain available, with behavior unchanged.
