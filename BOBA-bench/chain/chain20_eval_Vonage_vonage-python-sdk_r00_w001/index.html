You will be modifying the nexmo Python module (the package importable as nexmo, containing the nexmo.Client class). Implement the following features.

1. Module Version Attribute

The nexmo module must expose a __version__ attribute (a string) representing the current version of the library.

2. Client Constructor — Application Name/Version Options

The nexmo.Client constructor must accept two new optional keyword arguments in addition to its existing parameters:

  • app_name (string)
  • app_version (string)

Existing constructor keyword arguments that must continue to work include at least:

  • key
  • secret
  • signature_secret

When both app_name and app_version are provided, the client must build a User-Agent identifier string composed of the following components joined by a single / (forward slash) character, in this exact order:

  1. The literal string nexmo-python
  2. The module's __version__
  3. The running Python version (as returned by platform.python_version())
  4. app_name
  5. app_version

Example: for __version__ of 1.3.0, Python 3.8.1, app_name='ExampleApp', and app_version='X.Y.Z', the identifier is:

nexmo-python/1.3.0/3.8.1/ExampleApp/X.Y.Z

This User-Agent identifier must be sent as the User-Agent HTTP header on outgoing API requests (for example, the request performed by get_balance(), which is an HTTP GET to https://rest.nexmo.com/account/get-balance). When app_name/app_version are not provided, the base identifier (without the app name/version components) is used.

3. Client.signature(params) Method

Add an instance method signature(self, params) to nexmo.Client.

  • Input: params is a dict of string keys to string values (which does not include a sig entry).
  • Output: returns a string — the computed signature for the given parameters, using the client's signature_secret.

The signature computation must produce this exact result: given

params = {'a': '1', 'b': '2', 'timestamp': '1461605396'}

and a client constructed with signature_secret='secret', signature(params) must return:

6af838ef94998832dbfc29020b564830

The algorithm: sort the params by key, concatenate each key/value as &key=value (in sorted key order), append the signature_secret, and compute the MD5 hex digest of the resulting string. The result is a 32-character lowercase hexadecimal string.

4. Client.check_signature(params) Method

Add an instance method check_signature(self, params) to nexmo.Client.

  • Input: params is a dict of string keys to string values that includes a sig entry holding a provided signature.
  • Behavior: compute the signature over params excluding the sig entry (using the same algorithm as signature), and compare it against the value of the sig entry.
  • Output: returns True if the computed signature matches the provided sig value; otherwise returns False.

For example, given a client with signature_secret='secret' and

params = {'a': '1', 'b': '2', 'timestamp': '1461605396', 'sig': '6af838ef94998832dbfc29020b564830'}

check_signature(params) must return True.

Required public API

The public nexmo module must allow Client to be constructed with a callback-signing secret in addition to its existing credentials:

client = nexmo.Client(
    key=<api_key>,
    secret=<api_secret>,
    signature_secret='secret'
)

The signature_secret is the secret used for callback signature generation and validation. Existing Client construction and behavior must remain compatible.

Expose these public instance methods:

Client.signature(params)
Client.check_signature(params)

Signature generation

Client.signature(params)

params is a dictionary of callback parameters. The method must return the callback signature as a lowercase hexadecimal string, using the client's signature_secret.

Construct the signature deterministically as follows:

  1. Sort the parameter keys in ascending key order.
  2. Starting with an empty string, append each sorted key/value pair in the exact form &key=value. This means the first pair also has a leading &.
  3. Append the client's signature_secret directly to the end of that string, without adding another delimiter.
  4. Compute the MD5 digest of the resulting string.
  5. Return the digest as its lowercase hexadecimal representation.

Therefore, dictionary insertion order must not affect the result.

For example, given:

params = {
    'a': '1',
    'b': '2',
    'timestamp': '1461605396'
}

and signature_secret='secret', the exact string to hash is:

&a=1&b=2&timestamp=1461605396secret

and the result must be:

'6af838ef94998832dbfc29020b564830'

Signature validation

Client.check_signature(params)

params is a dictionary containing callback parameters and a sig entry. The sig value is the signature supplied with the callback; it is not one of the callback parameters included in the signature input.

The method must compute the expected signature from all entries other than sig, using the same sorted-parameter MD5 algorithm and the client's signature_secret, and compare it with the supplied sig. It must return a Python boolean: True when the supplied signature is valid and False when it is not.

For example, given:

params = {
    'a': '1',
    'b': '2',
    'timestamp': '1461605396',
    'sig': '6af838ef94998832dbfc29020b564830'
}

and signature_secret='secret', the method must return:

True

Existing Signature Helpers

These helpers perform no HTTP request and must retain their existing behavior:

  • signature(params) returns the lowercase MD5 signature produced by the existing Nexmo signing algorithm and the configured signature secret. Parameters are processed in sorted-key order. Response and Error Handling

The same response behavior applies to existing and new operations:

  • A successful response with a JSON body is decoded and returned as a dict.
  • HTTP 204 returns None.
  • HTTP 401 raises nexmo.AuthenticationError.
  • Other HTTP 4xx responses raise nexmo.ClientError. The existing message format is {status_code} response from {host}, for example 400 response from rest.nexmo.com.
  • HTTP 5xx responses raise nexmo.ServerError with the same message format, for example 500 response from rest.nexmo.com.

JWT Authentication

Voice API operations under /v1/calls use a JWT Bearer token instead of API-key/secret authentication. Every such request must include:

Authorization: Bearer {token}

The token must:

  • Be signed with RS256 using the client's RSA private_key.
  • Contain an application_id claim equal to the client's configured application ID unless that claim has been overridden through auth.
  • Be verifiable using the public key corresponding to the configured private key.

JWT-authenticated operations must not require key or secret. JSON-bearing Voice requests must have Content-Type: application/json.

For each explicit mode, generate an HMAC whose key is the UTF-8-encoded signature_secret, whose message is the canonical UTF-8 payload, and whose digest algorithm is the configured method. Return its lowercase hexadecimal digest. Case-insensitive aliases are not required.

Given:

key = "nexmo-api-key"
secret = "nexmo-api-secret"
signature_secret = "secret"
params = {"a": "1", "b": "2", "timestamp": "1461605396"}

the required results are:

"md5" "c15c21ced558c93a226c305f58f902f2"
"sha1" "3e19a4e6880fdc2c1426bfd0587c98b9532f0210"
"sha256" "a321e824b9b816be7c3f28859a31749a098713d39f613c80d455bbaffae1cd24"
"sha512" "812a18f76680fa0fe1b8bd9ee1625466ceb1bd96242e4d050d2cfd9a7b40166c63ed26ec9702168781b6edcf1633db8ff95af9341701004eec3fcf9550572ee8"
Omitted-method compatibility

Omitting signature_method must preserve the legacy signing algorithm; omission must not be treated as explicit signature_method="md5". Legacy signing computes an MD5 digest over the canonical payload followed directly by the UTF-8-encoded signature_secret, rather than using HMAC.

Thus, with signature_secret="secret" and the fixed parameters above:

client = nexmo.Client(
    key="nexmo-api-key",
    secret="nexmo-api-secret",
    signature_secret="secret",
)

assert client.signature(params) == "6af838ef94998832dbfc29020b564830"

The distinction is intentional: explicit "md5" returns c15c21ced558c93a226c305f58f902f2, while an omitted method returns the legacy value 6af838ef94998832dbfc29020b564830.

Client.check_signature must likewise continue to validate legacy webhook signatures when signature_method was omitted. For example, the omitted-method client above must return True for:

client.check_signature({
    "a": "1",
    "b": "2",
    "timestamp": "1461605396",
    "sig": "6af838ef94998832dbfc29020b564830",
})
Compatibility constraints

The new option is additive. Existing client construction—including clients that use application credentials without an API key or API secret—and all unrelated request, authentication, response, and error behavior must remain unchanged.
