5. Request-size validation

era5cli._request_size defines TooLargeRequestError. During construction, Fetch validates the size of every request it plans to submit. If any otherwise resolvable request exceeds the applicable limit, construction raises TooLargeRequestError before retrieval.

Per-request calculation

Validation applies to one actual submitted request, not the aggregate workload. For one request and one variable:

field_count = years_in_request
              * months_in_request
              * day_count
              * hour_count
              * pressure_level_count
  • With merge=False, years_in_request is 1; with merge=True, it is the number of selected years.
  • Without month splitting, months_in_request is the number of selected months; with splitmonths=True, it is 1 for each generated request.
  • day_count is the number of selected days for hourly data and 1 for monthly data.
  • hour_count is the number of selected hourly or synoptic hours.
  • pressure_level_count is the number of levels when the variable resolves to a pressure-level dataset, and 1 for surface, single-level, and ERA5-Land requests.

Variables are sent separately and do not multiply one request's size. Ensemble selection and the total output count likewise do not replace this dimensional calculation. merge and splitmonths never combine in a size computation because their combination is rejected outright (section 6).

The maximum is 1,000 fields for each ERA5-Land request and 100,000 fields for each non-land ERA5 request, including single- and pressure-level datasets. A request exactly at its maximum is allowed; only a strictly larger request raises.

Required consequences include:

  • A full-year unsplit hourly ERA5-Land skin_temperature request has 12 * 31 * 24 = 8,928 fields and is too large.
  • A full-year monthly ERA5-Land snow_cover request at one hour has 12 * 1 * 1 = 12 fields and is valid.
  • Splitting the hourly land case by month makes each request 1 * 31 * 24 = 744 fields and valid.
  • A one-month hourly pressure-level request at all 37 levels has 1 * 31 * 24 * 37 = 27,528 fields and is valid.
  • Its full-year counterpart has 12 * 31 * 24 * 37 = 330,336 fields and is too large.
  • A merged two-year full-year hourly non-land single-level request has 2 * 12 * 31 * 24 = 17,856 fields and is valid.

Size checking must not mask an independently invalid dataset selection. Dataset resolution must be possible before a size can be computed, so size validation applies only to selections whose dataset resolves. Combinations that request resolution itself rejects, such as ERA5-Land with the preliminary back extension, raise their existing ValueError during request resolution or building rather than TooLargeRequestError, and selections whose errors are deferred under section 6 (for example unknown variable names) keep those deferred errors instead of failing the size check.

  • merge=True (necessarily splitmonths=False): exactly one request per selected variable, covering all selected years.
  • splitmonths=True (necessarily merge=False): exactly one request for every combination of selected variable, year, and month; each such request contains only that single month, and its output filename carries the YYYY-MM year-month specification of section 8.

For example, two variables and three years yield 6 requests unsplit and unmerged, 2 requests merged, and 2 * 3 * 12 = 72 requests with all twelve months selected and splitmonths=True.

With dryrun=True, nothing is submitted or downloaded. Instead, every planned request is printed to standard output — the resolved dataset name, the request dictionary, and the output filename together on one line per request — without altering the count or content relative to what a real run would submit. Each printed request dictionary carries its product_type entry exactly once whenever the dataset takes one.

Without dryrun, each request prints the existing queueing message, is submitted to the CDS API using the stored URL and key, downloads into its output filename, and appends the history entry of section 11 to netCDF output. Downloads may run in parallel: threads sets the number of worker threads, and threads=None uses the default pool. Fetch.fetch() returns None after successful dry-run and retrieval paths.

8. Extensions and filenames

Fetch._extension() is callable before filename definition. It sets self.ext to "nc" for netCDF and "grb" for GRIB, case-insensitively. Any other format raises ValueError.

_define_outputfilename(variable, years, month=None) follows:

<prefix>_<variable>_<yearspec>_<period>[<area>][_ensemble][_statistics][_synoptic].<ext>
  • The prefix is outputprefix, or <outputprefix>-land for ERA5-Land.
  • A single year is YYYY; a merged range is first through last as YYYY-YYYY.
  • If a zero-padded month, such as "01", is supplied, a one-year specification becomes YYYY-MM.
  • Existing ensemble, statistics, and synoptic suffixes appear when active.
  • An area [N, W, S, E] appends _<W>-<E>_<S>-<N>, with coordinates rounded to whole degrees and hemisphere letters. Zero uses E for longitude and N for latitude.

After _extension() for a netCDF ERA5-Land month-split request:

_define_outputfilename("total_precipitation", [2008], month="01")
-> era5-land_total_precipitation_2008-01_hourly.nc

Area examples are:

[90.0, -180.0, -90.0, 180.0]
-> era5-land_total_precipitation_2008-01_hourly_180W-180E_90S-90N.nc

[90.0, -180.0, -80.999, 170.001]
-> era5-land_total_precipitation_2008-01_hourly_180W-170E_81S-90N.nc

[0, 120, -90, 180]
-> era5-land_total_precipitation_2008-01_hourly_120E-180E_90S-0N.nc

Existing suffix forms remain valid, including:

era5_total_precipitation_2008_hourly_ensemble.nc
era5_total_precipitation_2008-2009_hourly_ensemble.grb
era5_total_precipitation_2008-2009_hourly_ensemble_statistics.grb
era5_total_precipitation_2008-2009_hourly_ensemble_synoptic.grb

9. Dataset resolution and request dictionaries

Fetch._build_request(variable, years, ...) validates inputs, resolves the CDS dataset, and returns (dataset_name, request_dict). The dictionary includes the resolved variable, year or years, zero-padded months, HH:00 times, output format, product type when required, zero-padded days for hourly data, pressure levels for pressure-level datasets, and a validated area when supplied.

An unsplit request contains the full selected month list: by default ['01', ..., '12'], or only ['01'] after --months 01. A month-split request contains its one month. Monthly requests omit day. Hourly geopotential without surface selection, restricted to January 2008, resolves to reanalysis-era5-pressure-levels and includes January, all selected pressure levels, days, and hours.

Dataset and variable rules

Preserve these rules:

  • Hourly surface variables use reanalysis-era5-single-levels; pressure variables use reanalysis-era5-pressure-levels.
  • Monthly requests append -monthly-means.
  • Preliminary-back-extension requests append -preliminary-back-extension.
  • ERA5-Land uses reanalysis-era5-land hourly and reanalysis-era5-land-monthly-means monthly.
  • Variables must exist in the selected dataset. Land-only variables such as snow_cover fail without land=True, and non-land variables fail when unavailable in ERA5-Land.
  • Variables unavailable monthly remain valid hourly but raise ValueError monthly. Unknown names raise ValueError when validated or built.
  • ERA5-Land and preliminary back extension are incompatible and fail during request resolution/building, not prematurely through size validation.
  • ERA5-Land and ensemble output remain incompatible and must not silently form a valid request.

orography remains a deprecated alias: it uses the single-level dataset and sends geopotential. geopotential is otherwise ambiguous. Without surface selection it uses pressure levels; with ["surface"] it uses single levels. Retain explanatory warnings for ambiguous geopotential and deprecated orography.

Product types

Preserve existing generation:

  • Ordinary hourly requests use reanalysis; hourly ensembles use ensemble_members.
  • Hourly ensemble statistics select ensemble_members, ensemble_mean, and ensemble_spread.
  • Monthly requests use monthly_averaged_reanalysis, or monthly_averaged_ensemble_members for ensembles. Synoptic variants append _by_hour_of_day.
  • Preliminary monthly forms remain reanalysis-monthly-means-of-daily-means, members-monthly-means-of-daily-means, reanalysis-synoptic-monthly-means, and members-synoptic-monthly-means, according to options.
  • Hourly ERA5-Land omits product_type. Monthly ERA5-Land uses monthly_averaged_reanalysis, with the synoptic suffix when selected.

Area validation

Areas require -90 <= lat_min, lat_max <= 90, lat_max > lat_min, -180 <= lon_min, lon_max <= 180, and unequal longitudes. Reversed longitude ordering is permitted, so [90, 120, -90, -120] is valid. Equal latitudes or longitudes, out-of-range coordinates, and wrong-length lists raise ValueError. Request coordinates are rounded to two decimals; [89.9999, -179.90, -90.0000, 179.012] becomes [90.0, -179.90, -90.0, 179.01].

Implement a strtobool function in the era5cli.utils module that converts a string representation of a truth value into a Python boolean.

Behavior

The function accepts a single string argument and returns a Python bool.

Values that must return True

The following string inputs must return True:

  • "True"
  • "true"
  • "Yes"
  • "y"
  • "1"

The following string inputs must return False:

  • "False"
  • "false"
  • "No"
  • "n"
  • "0"
Invalid inputs

For any input string that does not represent a recognized truth value (for example "tr", "01", "maybe", "Fals"), the function must raise a ValueError. The exception message must contain the text:

Could not convert string to boolean

Notes

  • The recognition of true/false values is case-insensitive (e.g., both "True" and "true" map to True; "Yes" maps to True).
  • Inputs that only partially match a recognized value (such as "tr" for "true", or "Fals" for "false") are not valid and must raise the ValueError described above.
