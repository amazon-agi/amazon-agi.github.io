Task Specification: Refactoring the Scope Resource and Reverting Two Settings Resources

Change the three affected settings resource classes of the hpOneView Python library. Scopes must use the newer stateful resource family, whereas ApplianceDeviceSNMPv1TrapDestinations and FirmwareDrivers must use the older ResourceClient delegation family. Update the corresponding OneViewClient properties so that they use the required object-lifetime behavior.

Two resource base-class families already exist in hpOneView.resources.resource:

  • Newer family: Resource, ResourceHelper, ResourcePatchMixin, as well as the other resource mixins. A resource in this family subclasses Resource and any mixins it requires, retains its resource instance data, and delegates through the helper or the resource operations it inherits.
  • Older family: ResourceClient. A resource in this family is a wrapper object that owns a ResourceClient—by convention stored as self._client—built from the connection that is supplied and the resource's base URI.

All resource classes and OneViewClient accessors that are unaffected must remain compatible with their existing behavior. Unless stated otherwise, each wrapper method below must return the value produced by the operation it delegates to.

1. hpOneView/resources/settings/scopes.py — Scopes

Scopes belongs to the newer family and has the base URI:

URI = '/rest/scopes'

The class must subclass Resource and include ResourcePatchMixin. Its constructor must follow the newer resource convention, taking the connection and optional initial resource data:

__init__(self, connection, data=None)

Initialization must set up the normal Resource state and helper for the scopes URI.

get_all(self, start=0, count=-1, sort='', query='', view='')

Scopes are retrieved through ResourceHelper.get_all, passing along the two positional pagination arguments and the named options exactly like this:

self._helper.get_all(start, count, sort=sort, query=query, view=view)

With the defaults, the request covers all scopes from the beginning, without an explicit sort, query, or view.

update(self, resource, timeout=-1)

Construct a custom If-Match header. When the eTag field is present, the value is resource['eTag']; otherwise the value is '*'. The call is delegated to the newer Resource.update operation in this form:

update(
    resource,
    timeout=timeout,
    custom_headers={'If-Match': etag_or_star}
)

A default_values argument must not be passed.

delete(self, resource, timeout=-1)

Construct a custom If-Match header. If resource is a dictionary that contains eTag, that value is used; for a dictionary without eTag, a bare ID, a URI, or any other supported non-dictionary resource representation, '*' is used.

The call is delegated to the newer Resource.delete operation in this form:

delete(
    resource,
    timeout=timeout,
    custom_headers={'If-Match': etag_or_star}
)
update_resource_assignments(self, id_or_uri, resource, timeout=-1)

The method modifies scope membership by adding or removing the assignments that resource represents.

  1. Resolve id_or_uri as a scope URI. A bare ID is treated as relative to /rest/scopes; a full scope URI remains a full URI.
  2. Append /resource-assignments to the scope URI obtained in this way.
  3. Produce a shallow copy of the resource payload that was supplied.
  4. Invoke ResourcePatchMixin.patch_request with the derived URI, the copied payload, and the timeout forwarded from the caller:
self.patch_request(
    resolved_scope_uri + '/resource-assignments',
    resource.copy(),
    timeout=timeout
)

A custom_headers argument must not be supplied in the invocation.

As an example, an id_or_uri of /rest/scopes/11c466d1-0ade-4aae-8317-2fb20b6ef3f2 results in /rest/scopes/11c466d1-0ade-4aae-8317-2fb20b6ef3f2/resource-assignments.

Old-family surface to remove

The old ResourceClient forms of these scope methods must not be retained or reintroduced:

  • patch(id_or_uri, operation, path, value, timeout=-1);
  • get_by_name(name), which returns a plain dictionary;
  • get(id_or_uri), which returns a plain dictionary via ResourceClient.get;
  • create(resource, timeout=-1), which uses the former scope DEFAULT_VALUES mapping.

In particular, a DEFAULT_VALUES-based old-family create operation must not be provided by Scopes. Any same-named behavior that the newer base family naturally supplies follows that family's API rather than the removed ResourceClient signatures.

create(self, resource, id=None, timeout=-1)

A new SNMPv1 trap destination is created at a particular numeric id slot. The behavior breaks down as follows:

  1. Work out the numeric id being targeted:

    • When an id argument has been given, that value is used directly.
    • When id has not been given, the next available id is found by counting the existing trap destinations (which are obtained through the resource-helper get_all behavior) and applying len(existing) + 1. To illustrate: with no existing destinations, the id is 1; with two existing destinations, it is 3.

  2. Two URIs are computed from the base URI and this id:

    • create URI: "{base_uri}/{id}" (e.g. /rest/appliance/trap-destinations/1)
    • validation URI: "{base_uri}/validation" (e.g. /rest/appliance/trap-destinations/validation)

  3. A validation step is performed first; the actual creation comes after:

    • The validation routine (see create_validation below) gets called with the destination and communityString values taken from resource, together with the computed create URI. In concrete terms, a ResourceHelper.create call is issued whose payload consists of exactly {'destination': <resource destination>, 'communityString': <resource communityString>, 'uri': <create URI>}, with timeout=timeout and uri=<validation URI> passed along.
    • Next, the actual creation is issued through the inherited Resource.create: the original resource payload is passed unchanged (a copy of the input resource), together with timeout=timeout and uri=<create URI>.

Note: in the actual create call, the input resource goes through unchanged (fields such as port included), whereas the validation payload contains only destination, communityString, and uri.

create_validation(self, destination, community_string, dest_uri, timeout=-1)
  • The validation payload {'destination': destination, 'communityString': community_string, 'uri': dest_uri} is assembled by this method.
  • The validation request is issued by way of the resource-helper create behavior (ResourceHelper.create); the payload is passed with timeout=timeout and uri="{base_uri}/validation".
update(self, resource, timeout=-1)
  • The inherited update behavior is what this method delegates to. The resulting resource-helper update call must be made with these arguments, passed positionally in this order: the resource payload, the resource's own uri, a force flag of False, the timeout value, and None.
  • For timeout, the default is -1; a timeout value that has been provided must be forwarded.
delete(self)
  • The current resource is deleted by delegating to the inherited Resource.delete behavior, which is called with no arguments.

For the OneViewClient accessor appliance_device_snmp_v1_trap_destinations, the following must hold:

  • It must return an instance of ApplianceDeviceSNMPv1TrapDestinations.
  • It must return a new instance on each access (put another way: the object from one access and the object from the next must not be the same — the property must not cache/lazy-load a single shared instance).

  • ResourceClient must not be used or imported for this class; the class must be built on Resource/ResourceHelper.
  • Every method delegation must forward its arguments exactly as described above, because callers/tests verify the precise arguments that reach the base-class methods.
