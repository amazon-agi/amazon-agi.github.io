Task Specification: Refactor Scope Resource and Revert Two Settings Resources

Modify the three affected settings resource classes in the hpOneView Python library. Scopes must use the newer stateful resource family, while ApplianceDeviceSNMPv1TrapDestinations and FirmwareDrivers must use the older ResourceClient delegation family. Update the corresponding OneViewClient properties to use the required object-lifetime behavior.

Two resource base-class families are already provided by hpOneView.resources.resource:

  • Newer family: Resource, ResourceHelper, ResourcePatchMixin, and the other resource mixins. A resource in this family subclasses Resource and any required mixins, retains resource instance data, and delegates through the helper or inherited resource operations.
  • Older family: ResourceClient. A resource in this family is a wrapper object that owns a ResourceClient—conventionally as self._client—constructed from the supplied connection and the resource's base URI.

Keep all unaffected resource classes and OneViewClient accessors compatible with their existing behavior. Unless stated otherwise, each wrapper method below must return the value produced by the operation to which it delegates.

1. hpOneView/resources/settings/scopes.py — Scopes

Scopes uses the newer family and the base URI:

URI = '/rest/scopes'

It must subclass Resource and include ResourcePatchMixin. Its constructor must follow the newer resource convention, accepting the connection and optional initial resource data:

__init__(self, connection, data=None)

Initialization must establish the normal Resource state and helper for the scopes URI.

get_all(self, start=0, count=-1, sort='', query='', view='')

Retrieve scopes through ResourceHelper.get_all, forwarding the two positional pagination arguments and the named options exactly as follows:

self._helper.get_all(start, count, sort=sort, query=query, view=view)

The defaults request all scopes from the beginning, without an explicit sort, query, or view.

update(self, resource, timeout=-1)

Build an If-Match custom header. Its value is resource['eTag'] when the eTag field is present; otherwise it is '*'. Delegate to the newer Resource.update operation as:

update(
    resource,
    timeout=timeout,
    custom_headers={'If-Match': etag_or_star}
)

Do not pass a default_values argument.

delete(self, resource, timeout=-1)

Build an If-Match custom header. If resource is a dictionary containing eTag, use that value; for a dictionary without eTag, a bare ID, a URI, or any other supported non-dictionary resource representation, use '*'.

Delegate to the newer Resource.delete operation as:

delete(
    resource,
    timeout=timeout,
    custom_headers={'If-Match': etag_or_star}
)
update_resource_assignments(self, id_or_uri, resource, timeout=-1)

Modify scope membership by adding or removing the assignments represented by resource.

  1. Resolve id_or_uri as a scope URI. A bare ID is relative to /rest/scopes; a full scope URI remains a full URI.
  2. Append /resource-assignments to the resolved scope URI.
  3. Make a shallow copy of the supplied resource payload.
  4. Invoke ResourcePatchMixin.patch_request with the derived URI, the copied payload, and the forwarded timeout:
self.patch_request(
    resolved_scope_uri + '/resource-assignments',
    resource.copy(),
    timeout=timeout
)

The invocation must not supply a custom_headers argument.

For example, an id_or_uri of /rest/scopes/11c466d1-0ade-4aae-8317-2fb20b6ef3f2 produces /rest/scopes/11c466d1-0ade-4aae-8317-2fb20b6ef3f2/resource-assignments.

Removed old-family surface

Do not retain or reintroduce the old ResourceClient forms of these scope methods:

  • patch(id_or_uri, operation, path, value, timeout=-1);
  • get_by_name(name) returning a plain dictionary;
  • get(id_or_uri) returning a plain dictionary through ResourceClient.get;
  • create(resource, timeout=-1) using the former scope DEFAULT_VALUES mapping.

In particular, Scopes must not provide a DEFAULT_VALUES-based old-family create operation. Any same-named behavior naturally supplied by the newer base family follows that family's API rather than the removed ResourceClient signatures.
