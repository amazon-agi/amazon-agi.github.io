3. Singular-value thresholding compatibility (modopt.signal.svd)

The existing svd module must remain available through:

from modopt.signal import *

The following public signature must remain callable exactly as shown:

svd.svd_thresh(data, threshold=None, n_pc=None, thresh_type='hard')
Input and output
  • data must be a two-dimensional NumPy ndarray. Passing anything else, including a scalar, a Python sequence, or an array whose dimensionality is not two, must raise TypeError.
  • Rectangular matrices are supported; the matrix need not be square.
  • The function returns a floating-point NumPy matrix with the same shape as data.
  • The output is the reconstruction obtained after applying the selected operation to the singular values of data.
Explicit threshold mode

For singular values s_i and an explicitly supplied threshold:

  • thresh_type='hard' replaces singular values strictly below the threshold with zero and leaves singular values at or above the threshold unchanged.
  • thresh_type='soft' replaces each singular value with max(s_i - threshold, 0).
  • Any other thresholding mode is invalid and must raise ValueError.
  • When threshold is supplied, it governs singular-value thresholding; n_pc is used to choose a cutoff only when threshold is omitted.
Principal-component mode

When threshold is omitted, n_pc may be either a positive integer or the exact string 'all':

  • For a positive integer n_pc, the default hard-threshold behavior retains the n_pc largest singular-value components and discards the remaining components. If the requested count is at least the number of available singular values, all components are retained.
  • The exact string n_pc='all' means retain every singular-value component. Thus svd_thresh(data, n_pc='all') returns the full floating-point SVD reconstruction, numerically equal to the original input up to floating-point roundoff.
Automatic mode

Calling svd_thresh(data) with both threshold and n_pc omitted is valid and must not raise merely because both options are None.

In this mode:

  • The number of components is selected automatically from a spatial autocorrelation analysis of the left singular vectors, using the automatic-mode autocorrelation factor 0.1.
  • This analysis treats each left singular vector as a square image, so the first dimension of data must be a perfect square for automatic selection. If it is not, automatic component selection cannot be performed and raises ValueError.
  • The automatically selected singular-value cutoff is then used for the reconstruction with the requested threshold type, which defaults to hard thresholding.
  • If automatic selection reaches or exceeds the available number of singular values, all singular values are used.

For the representative rectangular matrix:

data = np.arange(18).reshape(9, 2).astype(float)

svd_thresh(data) must return the full-rank reconstruction, equal to data to standard floating-point precision. Tiny roundoff is expected; for example, the reconstructed value corresponding to the original 0.0 may be approximately -1.05e-16.

n_pc validation
  • None, a positive integer, and the exact string 'all' are the only valid n_pc forms.
  • A string other than 'all', such as 'bla', must raise ValueError.
  • A non-positive integer must raise ValueError.
  • A non-None value that is neither an integer nor a string must raise ValueError.

Compatibility and required imports

  • All behavior must execute correctly under Python 3.
  • These modules and functions must remain importable and callable:
    • modopt.base.types.check_float
    • modopt.base.types.check_int
    • modopt.signal.wavelet.filter_convolve
    • modopt.signal.wavelet.filter_convolve_stack
    • modopt.signal.svd.svd_thresh
  • Existing unrelated public package behavior must remain intact.

Task Specification: Cost Aggregation and Convergence Object

Module and export surface

Provide the modopt.opt.cost module and expose it through modopt.opt so that:

from modopt.opt import *
obj = cost.costObj(...)

works. Direct access as modopt.opt.cost.costObj must also remain available.

costObj class

Implement the following public constructor, preserving the parameter order and defaults:

costObj(operators, initial_cost=1e6, tolerance=1e-4,
        cost_interval=1, test_range=4, verbose=True,
        plot_output=None)
Constructor parameters
  • operators: A list of objects whose contributions form the aggregate cost. Every object must expose a callable attribute named cost.
  • initial_cost: The value assigned to the public cost attribute before the first scheduled cost calculation. The default is 1e6. This initial value is not itself a convergence sample.
  • tolerance: The inclusive relative-change threshold used to decide convergence. The default is 1e-4.
  • cost_interval: A positive integer specifying how many get_cost invocations occur between cost calculations. The default is 1.
  • test_range: The number of calculated cost values collected for each convergence window. The default is 4.
  • verbose: Whether to emit progress information when a cost is calculated and when a convergence window is evaluated. The default is True.
  • plot_output: Optional output-name prefix used by plot_cost. The default is None.
Operator validation

Validation occurs during construction:

  • If operators is not a list, raise TypeError.
  • If any list element lacks a callable cost attribute, raise ValueError. A present but non-callable cost attribute is invalid as well.

Public state

Each instance must expose a public attribute named cost. Immediately after construction it equals initial_cost. After a scheduled calculation, it contains the most recently calculated aggregate cost. Calls on which no calculation is scheduled must leave it unchanged.

All scheduling and convergence state persists across successive calls to the same instance.

get_cost

get_cost(self, *args, **kwargs)

get_cost conditionally calculates the aggregate cost and returns the result of a stateful convergence check. Its boolean result does not merely indicate that a cost was calculated.

Scheduling

Invocation numbering starts at 1 and advances on every call, including calls that do not calculate a cost. A cost is calculated exactly when the invocation number is divisible by cost_interval:

  • With cost_interval=1, every call calculates a cost.
  • With cost_interval=2, calls 2, 4, 6, and so on calculate a cost; calls 1, 3, 5, and so on do not.

On an unscheduled call, operators are not evaluated, cost and the convergence window are not updated, and the method returns False.

Aggregate cost calculation

On a scheduled call, invoke every operator's cost callable once with the positional and keyword arguments explicitly supplied to get_cost, sum all returned contributions, and assign the total to self.cost. The calculated total must also be retained as part of the cost history used for convergence and plotting.

The constructor's verbose setting must not cause an unexpected keyword argument to be passed to an operator. In particular, operators such as lambda x: x ** 2, which accept only the arguments explicitly passed to get_cost, must work with the default constructor settings.

Convergence windows

Every newly calculated aggregate cost is appended to the current convergence window. No convergence decision is made until that window contains test_range calculated values. Until then, get_cost returns False, even though self.cost was calculated and updated.

Once the window contains test_range values, split it at test_range // 2 into an earlier portion and a later portion. Let:

  • m_earlier be the mean of the earlier values;
  • m_later be the mean of the later values; and
  • relative_change = norm(m_later - m_earlier) / norm(m_later).

The convergence result is True exactly when relative_change <= tolerance; otherwise it is False. After evaluating either outcome, clear that convergence window so the next calculated value begins a new, independent window. The complete calculated-cost history used by plot_cost is not cleared.

Thus a full, non-converged window still returns False and resets before collecting the next window. Calls skipped because of cost_interval never count toward test_range.

Required examples

For two operators whose cost callables are x -> x**2 and x -> x**3, every scheduled call with x=2 calculates:

2**2 + 2**3 = 12

and stores 12 in self.cost.

With the defaults and constant input, all calls are scheduled, but four calculated values are needed for convergence. From a new instance, the return sequence is therefore:

False, False, False, True

The fourth call compares the four identical totals, obtains zero relative change, returns True, and resets the convergence window. The fifth call begins a new window and returns False. Equivalently, if an instance has already received two such calls, its next call returns False and the following call returns True.

With cost_interval=2, the first call does not calculate a cost, the second call calculates and stores 12, and six calls are sufficient for self.cost to hold 12. Four calculated samples are not available until call 8, so for a constant cost the first True convergence result occurs on call 8, not merely on call 2.

Verbose and plotting behavior

When verbose=True, scheduled calculations may report the current invocation and aggregate cost, and completed convergence-window evaluations report their relative change. Setting verbose=False suppresses this progress output without changing scheduling, cost values, or convergence results.

Provide:

plot_cost(self)

This method plots the sequence of calculated aggregate costs; unscheduled invocations do not add entries. With plot_output=None, the output file is named cost_function.png. Otherwise the output is named <plot_output>_cost_function.png. If plotting support is unavailable, calling plot_cost must be a harmless no-op.

Ngole mode

Ngole mode is coefficient-domain SVD thresholding. The supplied operator does not preprocess or otherwise transform the input cube before its SVD. Its result is defined as follows:

  1. Form X = data.reshape(n, r*c).T, so X has shape (r*c, n) and each input layer is one column.
  2. Compute the reduced SVD X = U @ diag(s) @ Vh, with k = min(r*c, n) singular components.
  3. Form the coefficient matrix A = diag(s) @ Vh, of shape (k, n).
  4. Reshape the columns of U into a stack of component images with shape (k, r, c). Apply operator to this stack. For each component i, let q_i be the Euclidean/Frobenius norm of the corresponding operated image. For square layers, reshaping an individual component is equivalently a sqrt(r*c) by sqrt(r*c) reshape.
  5. Give coefficient row i the threshold t_i = (threshold * extra_factor) * q_i, broadcast across all columns of that row. Apply the selected hard or soft threshold rule element-wise to A, producing A_thresholded.
  6. Reconstruct X_thresholded = U @ A_thresholded, transpose it, and reshape it back to (n, r, c).

In particular, the operator is applied to left-singular-vector component images solely to determine the per-component threshold scales. Applying it directly to data and then performing ordinary singular-value thresholding is not equivalent and does not satisfy Ngole mode.
