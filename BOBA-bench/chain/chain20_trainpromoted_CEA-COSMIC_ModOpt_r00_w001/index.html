3. Compatibility for singular-value thresholding (modopt.signal.svd)

The existing svd module must remain accessible through:

from modopt.signal import *

The public signature shown below must remain callable exactly as given:

svd.svd_thresh(data, threshold=None, n_pc=None, thresh_type='hard')
Input and output
  • data must be a two-dimensional NumPy ndarray. Anything else that is passed in, including a scalar, a Python sequence, or an array whose dimensionality is not two, must raise TypeError.
  • Support exists for rectangular matrices; the matrix need not be square.
  • The function returns a floating-point NumPy matrix whose shape is the same as that of data.
  • The output is the reconstruction obtained once the selected operation has been applied to the singular values of data.
Explicit threshold mode

Given singular values s_i and a threshold that is explicitly supplied:

  • thresh_type='hard' substitutes zero for singular values strictly below the threshold and leaves singular values at or above the threshold unchanged.
  • thresh_type='soft' substitutes max(s_i - threshold, 0) for each singular value.
  • Any thresholding mode other than these is invalid and must raise ValueError.
  • As long as threshold is supplied, it governs singular-value thresholding; n_pc is used to choose a cutoff only in the case where threshold is omitted.
Principal-component mode

If threshold is omitted, n_pc may be either a positive integer or the exact string 'all':

  • With a positive integer n_pc, the default hard-threshold behavior keeps the n_pc largest singular-value components and drops the components that remain. When the requested count is at least the number of available singular values, all components are kept.
  • The exact string n_pc='all' has the meaning that every singular-value component is retained. Consequently, svd_thresh(data, n_pc='all') returns the full floating-point SVD reconstruction, numerically equal to the original input up to floating-point roundoff.
Automatic mode

A call to svd_thresh(data) in which both threshold and n_pc are omitted is valid and must not raise merely due to both options being None.

Within this mode:

  • Selection of the component count happens automatically, based on a spatial autocorrelation analysis of the left singular vectors and using the automatic-mode autocorrelation factor 0.1.
  • In this analysis, each left singular vector is treated as a square image; hence the first dimension of data must be a perfect square for automatic selection. If that is not the case, automatic component selection cannot be performed and raises ValueError.
  • The singular-value cutoff selected automatically is then used for the reconstruction together with the requested threshold type, whose default is hard thresholding.
  • Should automatic selection reach or exceed the available number of singular values, all singular values are used.

For this representative rectangular matrix:

data = np.arange(18).reshape(9, 2).astype(float)

svd_thresh(data) must return the full-rank reconstruction, which is equal to data to standard floating-point precision. A tiny amount of roundoff is expected; for instance, the reconstructed value that corresponds to the original 0.0 may be approximately -1.05e-16.

Validation of n_pc
  • The only valid forms for n_pc are None, a positive integer, and the exact string 'all'.
  • A string that is not 'all', such as 'bla', must raise ValueError.
  • An integer that is non-positive must raise ValueError.
  • Any value that is not None and is neither an integer nor a string must raise ValueError.

Compatibility and the required imports

  • All behavior must work correctly when run under Python 3.
  • The modules and functions listed below must remain importable and callable:
    • modopt.base.types.check_float
    • modopt.base.types.check_int
    • modopt.signal.wavelet.filter_convolve
    • modopt.signal.wavelet.filter_convolve_stack
    • modopt.signal.svd.svd_thresh
  • Existing public package behavior that is unrelated must remain intact.

Location

LinearParent(op_callable, adj_op_callable)

It exposes:

  • op(x) — the result of applying op_callable to x.
  • adj_op(x) — the result of applying adj_op_callable to x.

As an example, LinearParent(lambda x: x ** 2, lambda x: x ** 3) results in an object whose op squares its input and whose adj_op cubes its input.

The Class to Implement: LinearCombo

LinearCombo brings together a list of linear operators (each an object exposing op and adj_op methods, e.g. LinearParent instances) and applies them collectively, with optional per-operator weighting on the adjoint operation.

Constructor
LinearCombo(operators, weights=None)

Parameters:

  • operators: a list (or a sequence of a similar kind) of linear operator objects, each exposing op and adj_op methods.
  • weights (optional): a list of numeric weights, one weight per operator.

Validation / error conditions (checked in the constructor):

  • If operators is not a list-like sequence (e.g. a single operator object is passed instead of a list of operators), raise TypeError.
  • If weights is supplied and its length does not match the number of operators, raise ValueError.
  • If weights is supplied but any of its elements is not numeric (e.g. strings), raise TypeError.
Method: op(x)

Each operator's op method is applied to the same input x, and the collection of results is returned.

  • The return value must be a NumPy array holding the individual operator results, with dtype=object.
  • Example: for two operators that each square their input, op(2) returns np.array([4, 4], dtype=object).
Method: adj_op(x)

The method takes an input sequence x with one entry per operator. Each operator's adj_op method is applied to the corresponding entry of x, after which the results are combined into a single value by summation.

Without weights:

  • The combined adjoint result is the plain sum, over operators, of operator_i.adj_op(x[i]).

  • Example: for two operators that each cube their input, adj_op([2, 2]) returns 2**3 + 2**3 = 16.0...

    Correction — the required behavior is: the unweighted sum equals 8.0 in the two-cubing-operators case. Specifically, when no weights are given, the combined adjoint returns the average (mean) of the per-operator adjoint results:

    • adj_op([2, 2]) with two cubing operators → (2**3 + 2**3) / 2 = 8.0.

With weights:

  • Each per-operator adjoint result is multiplied by the weight that corresponds to it, and the weighted results are summed (no averaging).
  • Example: for two cubing operators with weights [1.0, 1.0], adj_op([2, 2]) → 1.0*(2**3) + 1.0*(2**3) = 16.0.

In these cases, the returned value is a scalar (float).

Task Specification: Base Class for Gradients

Goal

Implement a base class serving gradient operators within the module modopt.opt.gradient.

Public Interface

A class called GradParent must be created in modopt/opt/gradient.py.

Constructor
GradParent(data, op, trans_op)

Parameters:

  • data: the observed data. It must be a NumPy array. When data is not a NumPy array (e.g. an int), the constructor is required to raise a TypeError.
  • op: a callable that represents the operator M. When applied to an input array, an array is returned.
  • trans_op: a callable that represents the transpose operator M^T. When applied to an input array, an array is returned.
Methods

Every method listed here takes a single NumPy array as its argument x and returns a NumPy array:

  • MX(x): applies the operator and returns op(x).
  • MtX(x): applies the transpose operator and returns trans_op(x).
  • MtMX(x): applies the operator and then the transpose operator in sequence, returning trans_op(op(x)).
Gradient Computation Method

  • get_grad(x): takes the input array x, computes the gradient from it, and stores the outcome in an instance attribute called grad. The gradient is defined as applying the transpose operator to the difference between the result of applying the operator to x and the observed data that was stored, i.e.:

    grad = MtX(MX(x) - data)

    with data being the data given to the constructor. Once this method has been called, the grad attribute holds the resulting NumPy array.

Behaviour Details

  • Every array operation is carried out element-wise using NumPy.
  • The callables op and trans_op are arbitrary; the class does nothing more than apply them in the way described.
  • The grad attribute is only guaranteed to exist after a call to get_grad.
Example Walkthrough

Take:

  • data = a 3×3 float array holding the values 0 through 8 (i.e. arange(9).reshape(3,3))
  • op = lambda x: x ** 2
  • trans_op = lambda x: x ** 3

Now, using x = data as the input:

  • MX(x) yields the element-wise square of x.
  • MtX(x) yields the element-wise cube of x.
  • MtMX(x) yields the element-wise square of x and then cubed (i.e. x raised to the 6th power element-wise).
  • get_grad(x) sets grad = trans_op(op(x) - data) = (x**2 - data) ** 3, computed element-wise.

Task Specification: Object for Cost Aggregation and Convergence

Module and its export surface

Make the modopt.opt.cost module available and expose it through modopt.opt such that:

from modopt.opt import *
obj = cost.costObj(...)

works. Direct access via modopt.opt.cost.costObj must also remain available.

The costObj class

Implement the public constructor shown below, keeping the parameter order and the defaults intact:

costObj(operators, initial_cost=1e6, tolerance=1e-4,
        cost_interval=1, test_range=4, verbose=True,
        plot_output=None)
Parameters of the constructor
  • operators: A list of objects whose contributions make up the aggregate cost. Every object must expose an attribute named cost that is callable.
  • initial_cost: The value assigned to the public cost attribute before the first scheduled cost calculation; the default is 1e6. This initial value is not itself a convergence sample.
  • tolerance: The inclusive relative-change threshold used to decide convergence; the default is 1e-4.
  • cost_interval: A positive integer that specifies how many get_cost invocations take place between cost calculations; the default is 1.
  • test_range: The number of calculated cost values gathered for each convergence window; the default is 4.
  • verbose: Whether progress information is emitted when a cost is calculated and when a convergence window is evaluated; the default is True.
  • plot_output: An optional output-name prefix that plot_cost uses; the default is None.
Validation of the operators

Validation is performed during construction:

  • Raise TypeError if operators is not a list.
  • Raise ValueError if any element of the list lacks a callable cost attribute. A cost attribute that is present but not callable is invalid as well.

State that is public

Each instance must expose a public attribute named cost. It equals initial_cost immediately after construction. After a scheduled calculation, it holds the most recently calculated aggregate cost. Calls during which no calculation is scheduled must leave it unchanged.

All scheduling and convergence state is carried across successive calls to the same instance.

get_cost

get_cost(self, *args, **kwargs)

get_cost calculates the aggregate cost conditionally and returns the result of a stateful convergence check. Its boolean result does not simply signal that a cost was calculated.

Scheduling

Invocation numbering begins at 1 and moves forward on every call, including calls that do not calculate a cost. A cost is calculated exactly when the invocation number is divisible by cost_interval:

  • With cost_interval=1, a cost is calculated on every call.
  • With cost_interval=2, a cost is calculated on calls 2, 4, 6, and so on; no cost is calculated on calls 1, 3, 5, and so on.

On a call without a scheduled calculation, operators are not evaluated, cost and the convergence window are not updated, and the method returns False.

Calculation of the aggregate cost

On a scheduled call, invoke the cost callable of every operator once, passing it the positional and keyword arguments explicitly supplied to get_cost, sum all returned contributions, and assign the total to self.cost. The calculated total must also be kept as part of the cost history used for convergence and plotting.

The verbose setting of the constructor must not lead to an unexpected keyword argument being passed to an operator. In particular, operators such as lambda x: x ** 2, which accept only the arguments explicitly passed to get_cost, must work with the constructor's default settings.

Convergence windows

Every newly calculated aggregate cost is appended to the convergence window currently in use. Until that window holds test_range calculated values, no convergence decision is made. Until that point, get_cost returns False, even though self.cost was calculated and updated.

As soon as the window holds test_range values, split it at test_range // 2 into an earlier portion and a later portion. Let:

  • m_earlier denote the mean of the earlier values;
  • m_later denote the mean of the later values; and
  • relative_change = norm(m_later - m_earlier) / norm(m_later).

The convergence result is True exactly when relative_change <= tolerance, and False otherwise. After either outcome has been evaluated, that convergence window is cleared, so that the next calculated value starts a new, independent window. The complete history of calculated costs used by plot_cost is not cleared.

Thus a full but non-converged window still returns False and is reset before the next window is collected. Calls skipped due to cost_interval never count toward test_range.

Required example cases

For two operators with cost callables x -> x**2 and x -> x**3, every scheduled call made with x=2 calculates:

2**2 + 2**3 = 12

and it stores 12 in self.cost.

With the default settings and a constant input, all calls are scheduled, but convergence needs four calculated values. Starting from a new instance, the sequence of return values is therefore:

False, False, False, True

The fourth call compares the four identical totals, obtains a relative change of zero, returns True, and resets the convergence window. The fifth call starts a new window and returns False. Equivalently, if an instance has already received two calls of this kind, its next call returns False, and the following call returns True.

With cost_interval=2, the first call does not calculate a cost, the second call performs a calculation and stores 12, and six calls are enough for self.cost to hold 12. Four calculated samples are unavailable until call 8, so for a constant cost the first True convergence result occurs on call 8, not merely on call 2.

Behavior for verbosity and plotting

When verbose=True, a scheduled calculation may report the current invocation and the aggregate cost, and evaluations of completed convergence windows report their relative change. Setting verbose=False suppresses this progress output, leaving scheduling, cost values, and convergence results unchanged.

Supply:

plot_cost(self)

The method plots the sequence of calculated aggregate costs; invocations without a scheduled calculation do not add entries. When plot_output=None, the output file is named cost_function.png; otherwise the output is named <plot_output>_cost_function.png. Where plotting support is unavailable, calling plot_cost must be a harmless no-op.

Operation in Ngole mode

  1. Set X = data.reshape(n, r*c).T; this gives X the shape (r*c, n), with each input layer occupying one column.
  2. Compute the reduced SVD X = U @ diag(s) @ Vh, in which the number of singular components is k = min(r*c, n).
  3. Build the coefficient matrix A = diag(s) @ Vh, whose shape is (k, n).
  4. Turn the columns of U into a stack of component images of shape (k, r, c), and apply operator to that stack. For each component i, q_i is defined as the Euclidean/Frobenius norm of the corresponding operated image. When the layers are square, reshaping an individual component amounts to a sqrt(r*c) by sqrt(r*c) reshape.
  5. Coefficient row i receives the threshold t_i = (threshold * extra_factor) * q_i, broadcast across all columns of that row. The selected hard or soft threshold rule is applied element-wise to A, which produces A_thresholded.
  6. Form X_thresholded = U @ A_thresholded, then transpose it and reshape it back to (n, r, c).

Note in particular that the operator is applied to the left-singular-vector component images for the sole purpose of determining the per-component threshold scales.     x_n - tau_n * g_n - tau_n * linear.adj_op(y_n)
)

Extrapolation of that result then takes place through the linear operator:

y_temp = y_n + sigma_n * linear.op(2 * x_prox - x_n)

The prox_dual handed to the algorithm is the proximity of the dual/composite term itself; it is not a proximity of its convex conjugate that was computed ahead of time. Moreau decomposition must therefore be applied in the dual update:

y_prox = y_temp - sigma_n * prox_dual.op(y_temp / sigma_n,

x_(n+1) = rho_n * x_prox + (1 - rho_n) * x_n
y_(n+1) = rho_n * y_prox + (1 - rho_n) * y_n

  2. Convergence is evaluated through cost.get_cost(x_(n+1), y_(n+1)).
