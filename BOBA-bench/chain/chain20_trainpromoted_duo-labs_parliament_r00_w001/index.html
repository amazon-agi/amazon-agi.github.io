Overview

The parliament Python package analyzes AWS IAM policies. This task defines the public behavior for expanding IAM action names and for distinguishing malformed action strings, unknown service prefixes, and unknown actions.

Existing successful action expansion and policy-analysis behavior must remain compatible.

Public API

Exception classes

The package root must export two exception classes:

from parliament import UnknownPrefixException, UnknownActionException

Both names must refer to subclasses of Exception.

  • UnknownPrefixException represents an unrecognized IAM service prefix: the part before the colon in an action string.
  • UnknownActionException represents an action name or wildcard pattern that matches no known action under a recognized service prefix.

The classes must be distinct. Neither may be an alias or subclass of the other, so catching one does not catch errors belonging to the other category. They may share a common superclass.

expand_action

The action-expansion function must remain importable as:

from parliament.statement import expand_action

It must support the existing one-argument call:

def expand_action(action_string):
    ...

action_string is normally a string in the form "<prefix>:<action>". The action component may be a literal IAM action or a wildcard pattern such as *.

Successful expansion behavior

expand_action compares the input against the package's known AWS IAM service prefixes and actions and returns a list of matching action records. Each returned record has this shape:

{"service": "<canonical-prefix>", "action": "<CanonicalActionName>"}

The following behavior must be preserved:

  • Matching of both the service prefix and action pattern is case-insensitive.
  • Returned service prefixes use their canonical lowercase form, and returned actions use their canonical IAM casing.
  • Literal action names and wildcard action patterns are both supported. A wildcard may occur within the action component, and every known matching action must be returned.
  • If the same IAM prefix is represented by more than one service definition, matches from all definitions using that prefix must be included.
  • Known actions designated as permission-only actions are valid and must also be expandable.

Required examples include:

expand_action("s3:listallmybuckets")
# [{"service": "s3", "action": "ListAllMyBuckets"}]

expand_action("s3:listallmybucke*")
# [{"service": "s3", "action": "ListAllMyBuckets"}]

expand_action("iAm:li*sTuS*rs")
# [{"service": "iam", "action": "ListUsers"}]

expand_action("logs:GetLogDelivery")
# [{"service": "logs", "action": "GetLogDelivery"}]

For a prefix represented by multiple service definitions, expand_action("ses:Describe*") must include all of these records:

[
    {"service": "ses", "action": "DescribeActiveReceiptRuleSet"},
    {"service": "ses", "action": "DescribeConfigurationSet"},
    {"service": "ses", "action": "DescribeReceiptRule"},
    {"service": "ses", "action": "DescribeReceiptRuleSet"},
]

Error behavior

Error classification occurs after validating the action-string format.

Malformed action string

If the input cannot be split into exactly a prefix component and an action component using a single colon—for example, "malformed" contains no colon—expand_action must raise an exception catchable as ValueError.

This malformed-format requirement is separate from unknown-prefix and unknown-action classification. Raising one of the domain-specific exceptions satisfies the malformed-input requirement only if that exception is itself a subclass of ValueError.

Unknown service prefix

For a correctly structured action string whose prefix does not correspond to any known IAM service, expand_action must raise UnknownPrefixException.

Example:

expand_action("333:listallmybuckets")  # raises UnknownPrefixException
Known prefix with no matching action

For a correctly structured action string whose prefix is known but whose literal action or wildcard pattern matches no known action for that prefix, expand_action must raise UnknownActionException.

Examples:

expand_action("s3:zzz")   # raises UnknownActionException
expand_action("s3:zzz*")  # raises UnknownActionException

A valid recognized expansion must continue to succeed and must not raise either exception.

Compatibility constraints

  • The two domain-specific errors must remain independently catchable.
  • Introducing the new exception types must not change valid expansion results, including case-insensitive matching, wildcard expansion, multi-definition prefixes, or permission-only actions.
  • Existing policy analysis that relies on action expansion must continue to work for valid policies and continue to report invalid actions rather than failing unexpectedly.

Findings must carry these identifier strings, produced under the following conditions:

  • MALFORMED_JSON — the policy string is not valid JSON.
  • MALFORMED — the policy is structurally invalid, including: a statement containing both Action and NotAction; a statement with no action at all; a policy with no Statement.

  • Boolean/effect comparisons must be handled consistently regardless of casing so that a Deny is properly recognized.

Principals
  • Well-formed S3 bucket policies with valid Principal values produce no findings.
