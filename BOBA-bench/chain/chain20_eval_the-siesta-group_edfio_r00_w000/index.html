Overview

You are working on edfio, a Python library for reading and writing EDF (European Data Format) files. EDF stores certain numeric header fields (such as physical minimum and physical maximum) as ASCII text limited to 8 characters. This task concerns how floating-point values are converted to fit within that 8-character limit, and how physical ranges of signals are constrained.

Required Public API

1. round_float_to_8_characters (in edfio._utils)

Add a new function to the module edfio._utils:

def round_float_to_8_characters(value: float, round_func) -> float:
    ...

Behavior:

The function takes a float value and a rounding function round_func (which will be one of the built-in round, math.floor, or math.ceil). It returns a float that is value adjusted so that its shortest decimal ASCII representation fits within 8 characters, where the adjustment (rounding) at the last retained decimal place is performed using round_func.

Conceptually: the value must be rounded to the maximum number of decimal places that still allows the number to be written using at most 8 characters (including the sign for negative numbers and the decimal point when present). The direction of rounding at that final decimal place is determined by round_func:

  • round — round to nearest (with Python's standard round-half-to-even behavior at exact halves).
  • math.floor — round toward negative infinity.
  • math.ceil — round toward positive infinity.

2. encode_float (existing, in edfio._utils)

The existing function encode_float(value: float, length: int) -> bytes (which produces an ASCII byte representation of value padded/fit to length characters) must no longer emit any UserWarning when a value requires rounding to fit within the field length. Values that require rounding must simply be encoded (rounded) silently. The rounding still produces the correct fitted representation; only the warning behavior is removed.

For a length of 8, encoding must produce the correct rounded-to-nearest 8-character representation, e.g.:

  • 0.12345678 → b"0.123457"
  • 1.23456789 → b"1.234568"
  • 12345.6789 → b"12345.68"

Behavioral Requirements for EdfSignal / Edf

The public classes EdfSignal, Edf, and the reader function read_edf live in the top-level package (importable such that EdfSignal(...), Edf(signals=[...]), read_edf(path) all work). FloatRange is a range type used for physical_range.

Physical range rounding must not clip data or overflow the digital range

When an EdfSignal is constructed, its physical minimum and physical maximum are stored in header fields limited to 8 characters, so they may need rounding. The physical minimum must always be rounded down (toward negative infinity) and the physical maximum must always be rounded up (toward positive infinity) so that the effective physical range always fully contains the original data — rounding must never shrink the range below the actual data extent.

Consequences that must hold:

  1. No warning on construction requiring rounding. Constructing an EdfSignal whose physical range endpoints require rounding to fit 8 characters must not emit any warning. For example:

    signal = EdfSignal(np.arange(10), 1, physical_range=(0, 10.123456789))
edf = Edf(signals=[signal])
edf.write(tmp_file)
loaded_signal = read_edf(tmp_file).signals[0]

    must complete without warnings and round-trip correctly.

  2. No clipping and no digital overflow from range rounding. Given tightly-spaced data where the automatically-derived physical range endpoints need rounding, the outward rounding of physical min/max must keep every data point strictly within the digital representable range [-32768, 32767], and must not distort the recovered physical data.

    Concretely, for:

    data = np.array([0, 0.0000014999])
sig = EdfSignal(data, 1)

    the following must hold:

    • sig.data recovers the original data to within an absolute tolerance of 1e-11 (i.e. np.testing.assert_allclose(sig.data, data, atol=1e-11)).
    • The internal digital sample array is exactly sig._digital.tolist() == [-32768, 16380].

    EdfSignal must expose:

    • a data property returning the physical (float) sample array,
    • a _digital attribute/property holding the integer digital sample array (a numpy array supporting .tolist()).

Notes

  • Do not introduce any UserWarning related to field-length/rounding anywhere in the encoding or signal-construction path.
  • The rounding direction rule (min → floor, max → ceil) applies specifically to the physical minimum/maximum header fields so the stored range always encloses the data.
