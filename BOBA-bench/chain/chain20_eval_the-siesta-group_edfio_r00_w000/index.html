01 The codebase for this task is edfio, a Python library that reads and writes EDF (European Data Format) files. 1129 words · source specification, reworded by GLM-5.3-Flash

Task Description

Context

The codebase for this task is edfio, a Python library that reads and writes EDF (European Data Format) files. The ASCII text in which EDF stores certain numeric header fields (for instance the physical minimum and the physical maximum) is limited to 8 characters. Two topics are addressed by this task: the conversion of floating-point values so as to fit into that limit of 8 characters, and the constraints on the physical ranges of signals.

Public API Requirements

1. round_float_to_8_characters (in edfio._utils)

To the module edfio._utils, add this new function:

def round_float_to_8_characters(value: float, round_func) -> float:
    ...

Behavior:

The inputs are a float value plus a rounding function round_func (for the latter, one of the built-in round, math.floor, or math.ceil will be passed in). Its return value is a float: value after an adjustment that makes the shortest decimal ASCII spelling of it fit into 8 characters; round_func determines the rounding of the last decimal place that is kept.

In conceptual terms: rounding value must keep as many decimal places as possible — specifically the largest count that still permits writing the number in at most 8 characters (the sign counts for negative numbers, and the decimal point counts when one is present). Which way the rounding goes at that final decimal place is decided by round_func:

  • round — nearest-value rounding (at exact halves, Python's standard round-half-to-even behavior applies).
  • math.floor — rounding toward negative infinity.
  • math.ceil — rounding toward positive infinity.

Worked examples (all of them must hold exactly):

With positive values, no sign is needed, so the whole 8-character budget goes to the number. How many decimals are allowed is decided by the number of digits taken up by the integer part:

1.1111114 1.111111 1.111111 1.111112
1.111111444 1.111111 1.111111 1.111112
1.111111499 1.111111 1.111111 1.111112
1.1111115 1.111112 1.111111 1.111112

1111111.5 1111112 1111111 1111112
11111111.4 11111111 11111111 11111112

11111111.499 11111111 11111111 11111112
11111111.5 11111112 11111111 11111112

The values that come back must equal the tabulated results exactly (as float).

2. encode_float (already present, in edfio._utils)

The function encode_float(value: float, length: int) -> bytes already exists; it writes value out as ASCII bytes, padded/fit to length characters. Whenever rounding of a value is required for it to fit within the field length, the function must no longer emit any UserWarning. For values that require rounding, the encoding must simply happen silently (rounded). What the rounding produces is still the correct fitted representation; removing the warning behavior is the only change.

With length equal to 8, what the encoding must produce is the correct rounded-to-nearest 8-character representation, e.g.:

  • 0.12345678 → b"0.123457"
  • 1.23456789 → b"1.234568"
  • 12345.6789 → b"12345.68"
  • 1234567.8 → b"1234568 "
  • 12345678.9 → b"12345679"
  • -0.987654321 → b"-0.98765"
  • -0.444444 → b"-0.44444"

Whenever decoding fails on out-of-range float text (e.g. exponent-based text outside the representable float range), a ValueError must continue to be raised with a message containing "outside float range" — this behavior stays the same.

Requirements for the Behavior of EdfSignal / Edf

In the top-level package one finds the public classes EdfSignal and Edf plus the reader function read_edf (imports of the forms EdfSignal(...), Edf(signals=[...]), read_edf(path) all work). The range type that physical_range uses is FloatRange.

Rounding of the physical range must not clip data or overflow the digital range

Constructing an EdfSignal stores its physical minimum and its physical maximum into header fields with an 8-character limit, so rounding may be needed. Rounding down (toward negative infinity) must always be applied to the physical minimum, and rounding up (toward positive infinity) must always be applied to the physical maximum; the original data is therefore always fully contained in the effective physical range — rounding must never make the range smaller than the actual data extent.

As consequences, the following must hold:

  1. No warning when construction needs rounding. If the physical range endpoints of an EdfSignal require rounding so that they fit 8 characters, constructing it must not emit any warning. For example:

    signal = EdfSignal(np.arange(10), 1, physical_range=(0, 10.123456789))
edf = Edf(signals=[signal])
edf.write(tmp_file)
loaded_signal = read_edf(tmp_file).signals[0]

    — this sequence must complete without warnings and with a correct round-trip.

  2. Range rounding leads to no clipping and no digital overflow. With tightly-spaced data whose automatically-derived physical range endpoints need rounding, rounding physical min/max outward must leave every data point strictly inside the representable digital range [-32768, 32767], and the recovered physical data must not be distorted by it.

    A concrete instance:

    data = np.array([0, 0.0000014999])
sig = EdfSignal(data, 1)

    the following must hold:

    • the original data is recovered by sig.data up to an absolute tolerance of 1e-11 (i.e. np.testing.assert_allclose(sig.data, data, atol=1e-11)).
    • the digital sample array held internally comes out as exactly sig._digital.tolist() == [-32768, 16380].

    The following must be exposed by EdfSignal:

    • a data property whose return value is the physical (float) sample array,
    • a _digital attribute/property that holds the integer digital sample array (a numpy array with support for .tolist()).

Remarks

  • Anywhere in the encoding or signal-construction path, do not introduce any UserWarning that relates to field-length/rounding.
  • It is specifically the physical minimum/maximum header fields that the rounding direction rule (min → floor, max → ceil) applies to; the stored range then always encloses the data.

    ...

The two arguments are Python floating-point values. What the function returns must be a Python int.

Behavior that is required

For inputs that are valid, return the integer quotient that is conceptually represented by:

signal_duration / data_record_duration

The computation must take the error introduced by ordinary floating-point representation and division into account. Whenever the durations represent an exact integer number of records, the helper must still produce the correct integer even if floating-point arithmetic alone leaves the quotient microscopically above or below that integer. signal_duration data_record_duration result
11 1 11
1.1 0.1 11
1.01 0.01 101
1.001 0.001 1001
1.0001 0.0001 10001
1.00001 0.00001 100001

Task: EDF Files Containing Only Annotations

Background

Within this codebase, a European Data Format file is represented by the Edf class, which comes with supporting types — EdfSignal, EdfAnnotation, and Recording are among them — along with a read_edf function. Whenever annotations are supplied, an empty sequence of signals must be accepted by the Edf constructor. Take the call:

Edf([], annotations=annotations)

Here annotations stands for a sequence of EdfAnnotation objects, and the call must produce a valid EDF object — one that can be written to disk through its .write(path) method and read back via read_edf(path).

Task Description

Summary

This task takes place inside a library for EDF (European Data Format) files, which provides an Edf class used for reading and writing EDF files. The subject of the task is the reading of the recording start time (starttime) out of EDF+ files that have no annotations signal.

Context

The time at which a recording starts is stored by EDF files. A "reserved" field sits in the file header, and its content can flag the file as an EDF+ variant (e.g., EDF+C). EDF+ files conventionally place the start time's sub-second precision inside an annotations signal. Even so, a file may be marked as EDF+ (via the reserved field) while it holds no annotations signal.

Behavior That Is Required

If the reserved field of an EDF file points to an EDF+ variant (such as EDF+C) and the file contains no annotations signal, then reading it must complete successfully, and the recording start time that is exposed must be the one taken directly from the standard header field.

In concrete terms: once a start time has been written into a file of this kind, reading the file back must recover it unchanged. When a file gets created with a given datetime.time start time and has its reserved field set to an EDF+ marker, reading that file must yield the identical start time.

Public API

Everything in the list below must be importable and usable:

  • Module: an Edf class and a read_edf function are what the library exposes (importable just as they are at present in the package).

  • Edf(signals, *, starttime=...)

    • Constructor accepting a sequence of EdfSignal objects plus a keyword argument starttime, which has type datetime.time.

  • Edf.reserved

    • A descriptor/field accessor that the Edf class provides; it exposes an encode(value: str) -> bytes method, and that method encodes a string (e.g., "EDF+C") into the byte form the reserved header field uses.

  • Edf._reserved

    • On each Edf instance there is a writable attribute, and it holds the encoded reserved-field bytes.

  • Edf.write(path)

    • Writes the Edf instance out to the file path supplied.

  • Edf.starttime

    • A property that returns the recording start time in the form of a datetime.time.

  • read_edf(path) -> Edf

    • Reads an EDF file located at the given path and returns an Edf instance.

  • EdfSignal(data, sampling_frequency)

    • Constructor accepting the sample data (a NumPy array) together with a sampling frequency.

Conditions That Must Hold

  • When a file is marked as EDF+ but contains no annotations signal, reading it must not fail; the read must return the start time stored in the header.
  • Whatever value was written, the value returned for starttime must exactly equal it (down to the second).

Usage Example

import datetime
import numpy as np

edf = Edf([EdfSignal(np.arange(2), 1)], starttime=datetime.time(22, 33, 44))
edf._reserved = Edf.reserved.encode("EDF+C")
edf.write(some_path)

result = read_edf(some_path)
assert result.starttime == datetime.time(22, 33, 44)

Representation behavior

EdfSignal.__repr__(self) -> str

Return a concise representation that contains the sampling frequency and, when it is non-empty, the label.

Required outputs:

  • EdfSignal(np.arange(5), 1) → "<EdfSignal (1Hz)>"
  • EdfSignal(np.arange(5), 1, label="ECG") → "<EdfSignal (1Hz, 'ECG')>"

If the label is empty, it must be left out entirely, its comma and quotes included. The signal data, together with all other metadata, must not appear in these representations.

Edf.__repr__(self) -> str

Return a concise representation that contains only the number of signals and annotations:

<Edf (<signal count> signal/signals, <annotation count> annotation/annotations)>

The singular noun is to be used only when the corresponding count is exactly one.

Required outputs include:

  • With one signal and one annotation: "<Edf (1 signal, 1 annotation)>"
  • With two signals and no annotations: "<Edf (2 signals, 0 annotations)>"
  • With no signals and two annotations: "<Edf (0 signals, 2 annotations)>"

These representations should not show any signal contents, annotation contents, or other EDF metadata.

Task: Revise EDF object representations

It must remain possible to construct the public classes edfio.EdfSignal, edfio.Edf, and edfio.EdfAnnotation through the existing top-level edfio API.

Adjust the __repr__ behavior described below:

edfio.EdfSignal.__repr__(self) -> str

For a signal created as:

EdfSignal(np.arange(5), 1)

repr(signal) must return:

<EdfSignal 1Hz>

If a label is supplied:

EdfSignal(np.arange(5), 1, label="ECG")

repr(signal) must return:

<EdfSignal ECG 1Hz>

This representation must:

  • Be delimited by angle brackets.
  • Not enclose the details in parentheses.
  • Position the label before the sampling frequency when present.
  • Leave the label unquoted.

edfio.Edf.__repr__(self) -> str

The representation must contain the signal count followed by the annotation count, with nothing but spaces between them. Parentheses and commas must not be used.

Mandatory examples:

  • One signal together with one annotation:

    <Edf 1 signal 1 annotation>

  • Two signals and no annotations:

    <Edf 2 signals 0 annotations>

  • No signals together with two annotations:

    <Edf 0 signals 2 annotations>

Singular nouns apply at a count of 1, and plural nouns apply for the exercised counts 0 and 2.
