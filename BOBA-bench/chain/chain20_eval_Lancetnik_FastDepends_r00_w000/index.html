Task Specification: fast_depends Dependency Injection Library

You are implementing a Python dependency-injection library named fast_depends. The library provides a decorator that validates/casts function arguments and return values using Pydantic (v2), and a Depends mechanism for declaring dependencies between callables.

Public API Surface

The following imports and names must be available exactly as specified.

fast_depends
  • inject — a decorator (usable as @inject) that wraps a sync or async function.
  • Depends — a callable used as a parameter default or inside Annotated metadata to declare a dependency.
  • dependency_provider — an object exposing an override(original_callable, replacement_callable) method used to substitute dependency callables.
fast_depends.core
  • build_call_model(func) — returns a "call model" object describing the function's parameters and dependencies. The returned object must expose (at minimum) the properties real_params and flat_params described below.
fast_depends.library
  • CustomField — a base class for user-defined parameter markers (see "Custom Fields").
fast_depends.types
  • AnyDict — a type alias suitable for annotating **kwargs dictionaries.
Depends signature

Depends(dependency, *, cast: bool = True)

  • dependency: the callable to resolve.
  • cast: when False, the resolved value of that dependency is not type-cast (details below). Default True.

inject behavior

@inject wraps a function f. The wrapper preserves sync/async nature: wrapping an async function yields an awaitable wrapper; wrapping a sync function yields a sync wrapper.

When the wrapped function is called:

  1. Argument casting/validation. Each declared parameter is validated and coerced according to its type annotation using Pydantic v2 semantics. Examples:

    • A parameter annotated float receiving the string "1" yields a float.
    • A parameter annotated int yields an int after coercion.
    • A parameter annotated with a Pydantic BaseModel subtype receiving a dict produces a validated model instance (with the model's own fields coerced, e.g. a field annotated int receiving "31" becomes int).

  2. Unannotated parameters are not cast. A parameter with no type annotation (e.g. default = Field(..., alias="b") with no annotation) receives its incoming value unchanged (e.g. a str stays a str).

  3. Pydantic Field support. A parameter default of Field(...) is honored, including alias (the caller passes the aliased name) and constraints such as max_length. Constraint/type mismatches raise pydantic.ValidationError.

  4. Extra keyword arguments are ignored. Calling the wrapped function with additional keyword arguments that do not correspond to declared parameters is allowed and does not cause an error.

  5. Return-value casting. If the function has a return annotation, the returned value is coerced to that type. For example, a function annotated -> float returning an int-valued expression yields a float (so an integer result 6 becomes 6.0).

  6. Invalid incoming types (values that cannot be validated against the annotation) raise pydantic.ValidationError.

Depends behavior

A parameter whose default is Depends(dep), or whose annotation is Annotated[T, Depends(dep)], is resolved by calling dep. The dependency's own parameters are themselves resolved/injected recursively (dependencies may have their own annotated parameters, Fields, and nested Depends).

  • Result casting. By default the dependency's return value is cast according to the dependency's return annotation (e.g. a dep annotated -> float returning a yields a float). When the depending parameter itself is annotated (e.g. c: int = Depends(dep) or Annotated[int, Depends(dep)]), the resolved value is coerced to that annotation.
  • cast=False. When Depends(dep, cast=False) is used, the dependency's resolved value is not coerced.
  • Annotated form. Annotated[int, Depends(dep)] is equivalent to using Depends(dep) as the default with the parameter typed int. Such a parameter may be supplied without a caller-provided value.
  • Caching. Within a single top-level call, each distinct dependency callable is resolved at most once; multiple parameters depending on the same callable receive the identical resolved object (identity-equal). This applies to nested dependencies shared across the graph.
  • Class dependencies. Depends(SomeClass) instantiates the class (injecting its __init__ parameters) and returns the instance. Depends(instance) where the instance is callable resolves by calling the instance. Depends(instance.method) resolves by calling the bound (possibly async) method.
Sync/async mixing rules
  • A sync wrapped function may not depend (directly or transitively) on an async dependency. Attempting to build such an injected function raises AssertionError at decoration time (i.e. when @inject is applied).
  • An async wrapped function may depend on both sync and async dependencies.
yield (generator) dependencies

A dependency may be a (sync) generator that yields a value and performs cleanup after the yield:

  • The yielded value is provided to the caller.
  • Cleanup code after the yield runs after the wrapped function body completes (it must not have run while the body executes).
  • If the dependency raises before yielding, the exception propagates and the wrapped body does not run.
  • If the wrapped body raises, the exception propagates; cleanup is still expected to run in that case, but the exception is re-raised to the caller.

Dependency overrides

dependency_provider.override(base_dep, override_dep) causes any Depends(base_dep) to resolve using override_dep instead. The sync/async compatibility rules apply to the overriding callable at call time:

  • Overriding a sync dependency with an async callable, then calling a sync wrapped function, raises AssertionError.
  • Async wrapped functions may use overrides of either sync or async callables.

Custom Fields (fast_depends.library.CustomField)

CustomField is a base class letting users define custom parameter markers, used as a parameter default (key: int = Header()) or inside Annotated (Annotated[int, Header()]).

Constructor

CustomField(*, cast: bool = True, required: bool = True)

  • required (default True): if True and the field produces no value, validation fails (pydantic.ValidationError). If False, a missing value resolves to None (and is not required).
  • cast (default True): if False, the resolved value is not coerced to the parameter's annotation.
use method

def use(self, **kwargs) -> dict — receives the current keyword-argument mapping and returns a (possibly modified) mapping. Subclass implementations call super().use(**kwargs) first, then may inject/replace values keyed by the parameter's name.

self.param_name

Each CustomField instance, once bound to a parameter, exposes self.param_name — the name of the parameter it decorates. Subclasses use it to know which key to populate.

Behavior required
  • A CustomField subclass may inspect incoming call kwargs (e.g. a headers dict) and set kwargs[self.param_name] to the extracted value. After use runs, that value is validated/cast against the parameter's annotation like any normal parameter.
    • Example: a Header field reads kwargs["headers"][param_name] and assigns it to kwargs[param_name]; with annotation int, incoming "1" becomes 1; with float, "1" becomes 1.0.
  • Multiple custom-field parameters in one function each populate their own param_name.
  • required=True (default) with no produced value raises pydantic.ValidationError.
  • required=False with no produced value resolves the parameter to None.
  • cast=False disables coercion for that parameter (e.g. an annotation of float or logging.Logger leaves the incoming raw value untouched).
  • Custom fields work when used via Annotated[T, Field()] as well as via defaults.
  • Custom fields also work on dependency functions: a Depends(dep) whose dep uses a custom field is resolved correctly (the custom field consumes the same incoming kwargs, e.g. headers).
Async custom fields
  • use may be defined as an async method. An async custom field may only be used on async wrapped functions. Using an async custom field on a sync wrapped function raises AssertionError at decoration time.
  • A sync custom field works on both sync and async functions.

Call model properties (build_call_model)

build_call_model(func) returns an object exposing:

  • real_params — a set[str] of the names of func's own directly-declared parameters that are plain parameters (i.e. not themselves Depends(...) markers). Names bound to Depends are excluded.
  • flat_params — a set[str] of the union of real_params with the plain (non-Depends) parameter names required by the entire transitive dependency graph. Duplicate names across dependencies collapse into one entry.

Example: for

def func1(a): ...
def func2(c, b=Depends(func1)): ...
def func3(b): ...
def main(a, b, m=Depends(func2), k=Depends(func3), c=Depends(func1)): ...

build_call_model(main).real_params == {"a", "b"} and .flat_params == {"a", "b", "c"}. (main's plain params are a, b; the dependency graph contributes plain params a from func1, c from func2, b from func3; the union of all plain names is {a, b, c}.)

Notes / non-requirements

  • Pydantic v2 must be the validation backend.
  • There is no requirement to raise on non-existent/forward-reference string annotations; do not add such behavior.

Overview

You are extending a dependency-injection / type-casting library that provides an inject decorator. The following import surfaces must exist and behave as described:

  • from fast_depends import Depends
  • from fast_depends.library import CustomField
  • from fast_depends.core import build_call_model

(The Depends, CustomField, and build_call_model names must simply be importable from those paths; only their existence is required here.)

Behavior to Implement

The inject decorator must correctly handle function signatures that include *args and/or **kwargs, as well as keyword-only parameters, in addition to the ordinary positional/keyword parameters that are already supported.

For all parameters, arguments passed at call time must be cast to the type declared in the annotation before being delivered to the underlying function. The return value must be exactly what the underlying function returns (a tuple in the cases below, since the functions return their parameters).

1. Full variadic support (*args and **kwargs)

For a function declared like:

def f(a: int, *args: Tuple[float, ...], b: int, **kwargs: Dict[str, int]):
    return a, args, b, kwargs
  • The regular parameter a is cast to its annotated type: passing 1.0 yields 1 (int).
  • Extra positional arguments beyond the declared regular parameters are collected into args. Each such value is cast to the element type declared for the variadic positional parameter (here float). Passing positional values 2.0, 3 produces args == (2.0, 3.0) (all floats). The collected result is a tuple, preserving order.
  • The keyword-only parameter b is cast to its annotated type: passing b=3.0 yields b == 3 (int).
  • Extra keyword arguments not matching any declared parameter are collected into kwargs. Each such value is cast to the value type declared for the variadic keyword parameter (here int). Passing key=1.0 produces kwargs == {"key": 1} (int value). The collected result is a dict, preserving keys.

Concretely, calling the wrapped function with positional args 1.0, 2.0, 3 and keyword args b=3.0, key=1.0 must return (1, (2.0, 3.0), 3, {"key": 1}).

2. Variadic positional only (*args, no **kwargs)

For a function declared like:

def f(a: int, *args: Tuple[float, ...], b: int):
    return a, args, b

Calling with positional args 1.0, 2.0, 3 and keyword arg b=3.0 must return (1, (2.0, 3.0), 3) — a cast to int, the surplus positional values cast to float and gathered into a tuple, and b cast to int.

3. Keyword-only parameter with no variadic collection

For a function declared like:

def f(a: int, *, b: int):
    return a, b

Here there is no *args collection. The first positional argument fills a; any further positional arguments are simply discarded (not collected, since no variadic positional parameter exists). The keyword-only parameter b is filled from the keyword argument.

Calling with positional args 1.0, 4 and keyword arg b=3.0 must return (1, 3) — a cast to int from 1.0, the extra positional 4 ignored, and b cast to int from 3.0.

Type-Casting Notes

  • Casting follows pydantic semantics for the annotated types.
  • For variadic positional parameters, the annotation's element type governs casting of each collected value.
  • For variadic keyword parameters, the annotation's value type governs casting of each collected value.
  • All previously supported casting behavior for ordinary and annotated parameters must continue to work unchanged.

Compatibility

Both synchronous and asynchronous forms of inject must exhibit identical casting and collection behavior for all cases above.
