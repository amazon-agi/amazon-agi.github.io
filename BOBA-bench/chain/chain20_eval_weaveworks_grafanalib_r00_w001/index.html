Task Specification: Adding Stat Value Mapping Classes to grafanalib.core

Overview

Four new classes are to be added to the grafanalib.core module in order to support value mappings (with color options) for Stat panels. All classes must expose a to_json_data() method that returns the structures described below.

Classes to Be Implemented

1. StatMapping

Signature of the constructor:

StatMapping(text, mapValue='', startValue='', endValue='', id=None)
  • It is constructed in the tests as StatMapping('dummy_text', startValue='foo', endValue='bar').
  • to_json_data() must return a dictionary that contains at least the following keys with the following values:
    • 'text' → the value of the text argument
    • 'from' → the value of the startValue argument
    • 'to' → the value of the endValue argument
2. StatValueMappingItem

Signature of the constructor:

StatValueMappingItem(text, mapValue, color='', index=None)
  • It is constructed positionally as StatValueMappingItem('foo', '0', 'dark-red'), that is, text='foo', mapValue='0', color='dark-red'.
  • mapValue serves as a string key.
  • This class acts as a component that StatValueMappings uses (see below). When it is embedded, its to_json_data() must produce a mapping from its mapValue string to an object containing:
    • 'text' → the value of the text argument
    • 'color' → the value of the color argument
3. StatValueMappings

Signature of the constructor (variadic):

StatValueMappings(*mappings)

  • The constructor accepts an arbitrary number of positional arguments; each of them must be a StatValueMappingItem instance.

  • The constructor must raise TypeError when any positional argument is not a StatValueMappingItem.

  • to_json_data() must return a dictionary containing:

    • 'type' → the string 'value'
    • 'options' → a dictionary keyed by the mapValue string of each item, where each value is a dictionary containing:
      • 'text' → the text of that item
      • 'color' → the color of that item

    Example: when the items are ('foo', '0', 'dark-red') and ('bar', '1', 'purple'), to_json_data()['options'] must be:

    {
    '0': {'text': 'foo', 'color': 'dark-red'},
    '1': {'text': 'bar', 'color': 'purple'},
}
4. StatRangeMappings

Signature of the constructor:

StatRangeMappings(text, startValue=0, endValue=0, color='', id=None)
  • It is constructed as StatRangeMappings('dummy_text', startValue=10, endValue=20, color='dark-red').
  • to_json_data() must return a dictionary containing:
    • 'type' → the string 'range'
    • 'options' → a dictionary that contains:
      • 'from' → the value of the startValue argument
      • 'to' → the value of the endValue argument
      • 'result' → a dictionary that contains:
        • 'text' → the value of the text argument
        • 'color' → the value of the color argument

Constraints

  • All of the classes live in the grafanalib.core module and must be importable as attributes of that module.
  • The only behavior that is required is the behavior described above.
02 Extend the public grafanalib.core API with support for Grafana's Discrete panel. 699 words · rewritten by GPT-5.6-sol, reworded by GLM-5.3-Flash

Task Description

Overview

Extend the public grafanalib.core API with support for Grafana's Discrete panel. The addition comprises the Discrete panel type identifier, a text-to-color mapping helper, and a Panel-compatible Discrete panel. Existing panel behavior and existing color constants must stay compatible.

Location in the Public API

The names listed below must be defined in grafanalib.core and must be directly accessible when that module is imported (for instance, as G.DISCRETE_TYPE, G.DiscreteColorMappingItem, and G.Discrete):

  • DISCRETE_TYPE
  • DiscreteColorMappingItem
  • Discrete

DISCRETE_TYPE

Define a string constant named DISCRETE_TYPE. This constant is the Grafana panel-type identifier for the Discrete panel. In its serialized type field, Discrete.to_json_data() must use this constant unchanged as the value.

The Existing GREY1 Constant

GREY1 continues to be the existing public color object in grafanalib.core; for this feature, it must not be redefined as a string or otherwise changed. It serves as the default color object for a discrete color mapping.

This default is a deliberate exception to the validation applied to colors supplied by the caller: in the current API, GREY1 is an RGBA object rather than a string.

DiscreteColorMappingItem

Constructor
DiscreteColorMappingItem(text, color=GREY1)
  • text is required, and it must be a string. Passing any non-string value must raise TypeError.
  • color may be passed either positionally or by keyword.
  • If the caller supplies color explicitly, its value must be a string. A non-string value that is explicitly supplied must raise TypeError.
  • When color is omitted, construction must succeed, and the value must default to the existing GREY1 object even though that object is not a string. The string-only validation therefore applies only to explicitly supplied color values.

No specific exception message is required.

to_json_data()

to_json_data() returns a mapping that contains at least the following:

  • text: the text string as originally supplied.
  • color: the color string that was explicitly supplied, or the GREY1 object itself when color was omitted.

At this stage, the default used when color is omitted must not be eagerly converted to an RGBA string or another representation. For example:

item = DiscreteColorMappingItem('foo')
data = item.to_json_data()

assert data['text'] == 'foo'
assert data['color'] is GREY1

custom = DiscreteColorMappingItem('foo', color='bar').to_json_data()
assert custom['color'] == 'bar'

The Discrete Panel

Discrete must match the existing Panel class in public construction and shared serialization conventions. It must accept the inherited panel arguments and defaults, including datasource, targets, title, repeat settings, transformations, and extraJson, in the same positional and keyword order the other panel classes use.

The constructor also accepts:

  • colorMapsItems: a list of DiscreteColorMappingItem objects. It can be passed by keyword and defaults to an empty list when omitted.

The historical first positional panel argument must continue to be accepted. It is separate from an explicitly configured serialized title: when Discrete('foo', colorMapsItems=...) is called, 'foo' must not appear in the serialized title field. If no explicit title is configured, the inherited title default stays the empty string. An explicit title= value keeps following normal Panel behavior.

to_json_data()

to_json_data() returns the normal shared panel mapping and includes at least the following:

  • colorMaps: the colorMapsItems list given to the constructor.
  • type: DISCRETE_TYPE.
  • title: the inherited panel title; this is '' when no explicit title was configured.

At this method boundary, colorMaps must keep the provided list and its DiscreteColorMappingItem elements unmodified. Those elements must not be eagerly replaced with their serialized dictionaries. The returned field must therefore compare equal to the original list, and an implementation that retains the original list object should expose that same object. Nested conversion may happen later via the package's normal JSON encoding process.

Example:

color_maps = [
    DiscreteColorMappingItem('bar', color='baz'),
    DiscreteColorMappingItem('foz', color='faz'),
]

panel = Discrete('foo', colorMapsItems=color_maps)
data = panel.to_json_data()

assert data['colorMaps'] == color_maps
assert data['type'] == DISCRETE_TYPE
assert data['title'] == ''

Compatibility and Scope

  • These additions belong in grafanalib.core; a separate module is not required.
  • For the new panel, all existing Panel construction, shared fields, serialization, and raw extraJson extension behavior must be preserved.
  • The type or serialization behavior of the existing GREY1 constant must not be changed.
  • Inside Discrete.to_json_data(), the mapping objects must not be eagerly serialized.
