02 ABC Note Duration Parsing 425 words · source specification

Task Specification: ABC Note Duration Parsing

Overview

Implement/extend note parsing functionality that converts ABC notation note strings into note objects with a well-defined string representation. This task focuses specifically on correctly interpreting duration modifiers in ABC note strings.

Public API

There must be a module named note (importable as note) exposing a class Note with a class method or static constructor:

Note.from_abc(abc: str) -> Note
  • from_abc accepts a single ABC-notation string describing one note.
  • The returned Note object must produce a canonical string representation via str(note_obj) (i.e. implement __str__).

String Representation Format

The canonical string representation has the form:

<PitchName><Octave>_<DurationNumerator>/<DurationDenominator>

Example: C4_1/16 means pitch C, octave 4, duration 1/16.

ABC Input Parsing Rules

An ABC note string consists of a pitch letter followed by optional duration modifiers. The base (default) duration of a bare note is 1/8.

The duration modifiers that must be supported:

  1. No modifier — e.g. C → duration 1/8.

  2. Slash(es) / — each trailing slash without a following number halves the duration:

    • A single / halves the base duration: C/ → 1/16.
    • Two slashes // halve twice: C// → 1/32.

  3. Slash followed by an integer /n — divides the base duration by n:

    • C/3 → base 1/8 divided by 3 → 1/24.

  4. Integer followed by a slash m/ — multiplies the base duration by m, then halves it (i.e. base × m, then applied to a single trailing slash halving):

    • C3/ → base 1/8, multiplied by 3 gives 3/8, then the trailing slash halves it → 3/16. This corresponds to a dotted eighth note.

Duration Value Representation

  • Durations are represented as an exact rational value with a numerator and denominator, rendered as numerator/denominator.
  • The examples above imply durations are kept in fractional form: 1/16, 1/32, 1/24, 3/16, etc. The denominator is not reduced away for these cases; the representation shown must match exactly (e.g. 3/16, not a decimal or a differently-reduced form).

Pitch and Octave

  • For the inputs covered here, the pitch letter maps directly to its name and the octave defaults to 4. For example, a bare C yields pitch name C and octave 4.

Concrete Behavior Examples

ABC input str(Note.from_abc(input))
C C4_1/8
C/ C4_1/16
C// C4_1/32
C/3 C4_1/24
C3/ C4_3/16

(The C → C4_1/8 row reflects the default duration; all others must match exactly as shown.)

03 ABC Tune Repeat Expansion 713 words · source specification

Task Specification: ABC Tune Repeat Expansion

Overview

You must extend an ABC-notation music parser so that repeat barlines (:| and |:) and first/second endings (|1, |2, along with :|1, :|2) are correctly expanded into the linear sequence of notes that would actually be played.

Public API

The following must be importable and usable:

  • Tune — a class constructed from a single string argument containing ABC notation: Tune(abc_string).
  • Tune instances must provide a method iter_notes() that returns an iterable of note objects, in the order they are played (with repeats already expanded).
  • Each note object yielded by iter_notes() must provide:
    • an attribute class_name — a string naming the note (e.g. the pitch letter such as "G", "A").
    • a method to_abc() — returns the ABC-text representation of that note (e.g. "G", "a"), preserving case (uppercase vs lowercase pitches are distinct).

These already exist and continue to work:

  • INFO_FIELDS — a mapping; INFO_FIELDS["T"].name == "tune title".

Input Format

The abc_string contains standard ABC header fields, one per line, such as:

T:?
L:1
M:4/4
R:reel
K:G

followed by one or more lines of music (the body). Leading/trailing whitespace on lines is not significant. Notes are single letters (A–G, a–g), separated by whitespace and barline tokens.

Barline and Repeat Semantics

The music body uses these structural tokens, separated by whitespace:

  • | — an ordinary barline (measure separator, no effect on playback order).
  • || — a section/double barline (no effect on playback order).
  • :| — end of a repeated section: playback returns to the most recent |: if one exists, otherwise to the start of the music, and plays that section a second time.
  • |: — start of a repeated section.
  • |1 — start of a first ending (played on the first pass through the repeat).
  • |2 — start of a second ending (played on the second/final pass through the repeat).
  • :|1 — end-of-repeat marker that also begins a first ending, i.e. it functions as both a repeat-end for the preceding pass and the opening of the first ending. (In practice, the first ending's content precedes this marker; see behavior below.)
  • :|2 — begins a second ending on the repeat pass.
Behavior Required

Repeats without endings. A repeated section delimited by |: … :| is played twice. If a :| appears without a preceding |:, the repeated section starts at the beginning of the music. Multiple independent repeated sections in sequence are each expanded in order.

Example — the body:

G | A :|
|: B | C :|

plays the notes in the order: G A G A B C B C.

Repeats with first/second endings. Within a repeated section, notes before an ending marker are common to both passes. On the first pass, the first ending (introduced by |1 or :|1) is played and then playback repeats back to the section start. On the second pass, the second ending (introduced by |2 or :|2) is played instead, and the repeat is not taken again.

For a section written as:

… common notes … |1 <first ending> :|2 <second ending> ||
  • Pass 1: common notes, then first ending, then repeat.
  • Pass 2: common notes, then second ending, then continue.

Example — the body:

G |1 A | A :|2 a | a ||
|: B |1 C :|2 c ||

plays the notes in the order: G A A G a a B C B c.

Working through the two lines:

  • First section (start-of-music is the implicit repeat start): common note G; first ending A A; repeat back; common note G again; second ending a a. → G A A G a a.
  • Second section (repeat start at |:): common note B; first ending C; repeat back; common note B; second ending c. → B C B c.

Concatenated: G A A G a a B C B c.

Constraints

  • The expansion must operate on note objects such that both class_name and to_abc() reflect the original notes exactly (including letter case).
  • Only the note-ordering behavior described above is required. Do not add any other transformations, validation, or output beyond what is specified here.

  • Function: Note.from_abc(abc: str) -> Note (i.e., a class named Note with a classmethod/staticmethod from_abc that accepts a single ABC string argument and returns a Note instance)

The resulting note object must have a string representation (via str()) of the form:

<PITCH>_<DURATION>

where <PITCH> is the note's pitch (e.g. C4) and <DURATION> is the note's duration expressed as a fraction (e.g. 1/32, 3/16).

Duration modifier semantics

The duration modifier follows the pitch. Given a base unit duration (in the cases below, the base unit corresponds to a duration of 1/8), the modifier scales that base unit as follows:

  • No modifier — duration is the base unit unchanged.
  • A trailing integer n (e.g. C3) — multiplies the base unit by n.

  • n/m (integer, slash, integer) — multiplies the base unit by n and divides by m.
The bug to fix

The n/m form (an explicit numerator, a slash, and an explicit denominator) must be parsed correctly as "multiply by n, divide by m". C// C4_1/32
C/3 C4_1/24
C3/ C4_3/16
C3/2 C4_3/16

The final row (C3/2) is the case that must be corrected; the others must continue to behave as shown.

  • Existing correct cases must remain correct.
