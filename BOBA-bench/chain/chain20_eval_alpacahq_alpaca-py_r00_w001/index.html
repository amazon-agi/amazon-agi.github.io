Public API Surface

Method

Supporting Types

The following must be importable and usable by callers:

  • GetAccountActivitiesRequest — a request/filter model that can be instantiated with no arguments (all fields optional).
  • PaginationType — an enumeration providing at least the members PaginationType.FULL, PaginationType.NONE, and PaginationType.ITERATOR.
  • BaseActivity — the base model type that each returned activity record is parsed into.

Data Model

The API returns JSON arrays of activity objects. There are two shapes of activity, distinguished by their activity_type:

  1. Non-trade activities (e.g. activity_type = "CSD"), with fields such as:

    • id, account_id, activity_type, date, net_amount, description, status.

  2. Trade activities (e.g. activity_type = "FILL"), with fields such as:

Both shapes must be parseable, and each parsed record must be an instance of BaseActivity.

Pagination Behavior

The broker API endpoint for account activities is paginated. A single request returns up to a page-size worth of records. When a full page is returned, the caller must continue fetching subsequent pages (using the last returned item to advance to the next page); when a page returns fewer records than the page size, that page is the last one.

For the purposes of this task, the page size behavior is such that a page containing 4 records indicates there may be more pages, and the paging continues until a request returns fewer than a full page.

The method's return value and request-issuing behavior depend on handle_pagination:

PaginationType.FULL
  • Fetch all pages, following pagination until exhausted.
  • Return a single List containing every activity record from all pages, in order.
  • Given a data set spanning multiple pages that requires 3 HTTP requests to fully retrieve, exactly 3 requests must be made, and the combined result must contain all 8 records.
  • Each element of the returned list must be a BaseActivity instance.
PaginationType.NONE
  • Fetch only the first page.
  • Make exactly 1 HTTP request.
  • Return a single List containing only the records from that first page (4 records for the reference data set).
  • Each element of the returned list must be a BaseActivity instance.
PaginationType.ITERATOR
  • Return a generator/iterator that yields one page at a time.
  • Each item produced by the generator is a List of BaseActivity instances (one page's worth of records).
  • Pages are fetched lazily as the generator is advanced.
  • After all pages have been consumed, advancing the generator again yields nothing further (i.e. next(generator, None) returns None).
  • Over the reference data set requiring 3 requests, driving the generator to exhaustion results in exactly 3 HTTP requests being made in total.

Reference Data Set

For a data set that, when fully paginated, spans 3 HTTP requests:

  • The first page returns 4 records.
  • Subsequent pages continue until a page returns fewer than 4 records.
  • The total number of records across all pages is 8.
  • The records include both non-trade ("CSD") and trade ("FILL") activity shapes, and all must parse successfully into BaseActivity instances.

Compatibility Note

The W8BenDocument model is used as the value passed to the content_data parameter of UploadW8BenDocumentRequest. A valid, fully-populated W8BenDocument instance (as produced by create_dummy_w8ben_document) must be accepted as content_data there. No changes to UploadW8BenDocumentRequest's own validation behavior are required by this task.
