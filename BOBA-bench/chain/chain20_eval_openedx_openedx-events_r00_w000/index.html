Task Specification: Open edX Events Tooling

Overview

Implement the core tooling that allows defining and sending Open edX events built on top of Django signals. This involves creating a custom signal class, a metadata data structure, and dedicated exception types.

Modules and Public API to Create

1. openedx_events/exceptions.py

Define two exception classes:

  • InstantiationError(Exception)
  • SenderValidationError(Exception)

Both must be importable as from openedx_events.exceptions import InstantiationError, SenderValidationError.

The message formatting behavior is described below in the context of where each exception is raised. Each exception's string message follows a fixed pattern that begins with the exception class name.

2. openedx_events/data.py

This module must define a metadata data structure (implemented using the attr library, so that attr.asdict(...) works on an instance). It must reference:

  • A module-level import bound to the name openedx_events (the top-level package), from which a __version__ string attribute is read.
  • A module-level import bound to the name socket, whose gethostname() is used.

The metadata object generated for an event must contain (at minimum) the following fields with these semantics:

  • event_type: the event type string of the signal.
  • minorversion: integer 0.
  • source: a string of the form "openedx/{service}/web", where {service} is taken from the Django setting SERVICE_VARIANT (e.g., with SERVICE_VARIANT="lms", source is "openedx/lms/web").
  • sourcehost: the value returned by socket.gethostname().
  • sourcelib: a list of integers derived from splitting the package __version__ string on . and converting each part to an integer (e.g., "0.1.0" → [0, 1, 0]).
3. openedx_events/tooling.py

Define the class OpenEdxPublicSignal, which subclasses Django's django.dispatch.Signal. It must be importable as from openedx_events.tooling import OpenEdxPublicSignal.

The module must import Django's Signal (so that openedx_events.tooling.Signal refers to it) and must be able to produce metadata via a method generate_signal_metadata (see below).

Constructor
OpenEdxPublicSignal(event_type, data)
  • event_type: a non-empty string identifying the event.
  • data: a mapping describing the expected send arguments, where each key is an argument name and each value is the type/class the argument's value must be an instance of.

Validation on instantiation — raise InstantiationError if a required argument is missing or falsy:

  • If event_type is empty/falsy, raise InstantiationError with message: InstantiationError {event_type}: Missing required argument 'event_type' (where {event_type} is the empty value passed in).
  • If data is None/falsy, raise InstantiationError with message: InstantiationError {event_type}: Missing required argument 'data' (where {event_type} is the event type value passed in).

The event_type check takes precedence when both are missing.

String representation

str(signal) must include the event_type string.

generate_signal_metadata(self)

Returns a metadata object (the data structure from openedx_events/data.py) describing this event, populated as specified in the data.py section. This method reads SERVICE_VARIANT from Django settings, calls socket.gethostname(), and reads the package __version__.

send_event(self, send_robust=False, **kwargs)

Sends the event as a Django signal after validating the provided keyword arguments against the data mapping supplied at construction.

Sender argument validation — validate the keyword arguments (excluding the send_robust control flag) against the construction-time data mapping. Raise SenderValidationError in these cases:

  • A key present in the construction data mapping is absent from the provided arguments: SenderValidationError {event_type}: Missing required argument '{key}' (using the missing key name).
  • A provided argument's value is not an instance of the class specified for that key in data: SenderValidationError {event_type}: The argument '{key}' is not instance of the Class Attribute '{type}' where {type} is the name of the expected type/class.
  • The set of provided argument names does not match the set of expected argument names (a mismatch, e.g., extra arguments provided): SenderValidationError {event_type}: There's a mismatch between initialization data and send_event arguments

The missing-argument and type-mismatch checks are evaluated per expected key; the count/mismatch check applies when the provided arguments do not correspond to the expected set.

Successful send behavior:

  • Generate metadata by calling self.generate_signal_metadata().
  • If send_robust is falsy: invoke the underlying Django Signal.send with sender=None, the validated keyword arguments passed through unchanged, plus metadata=<generated metadata>.
  • If send_robust is truthy: invoke the underlying Django Signal.send_robust with sender=None, the validated keyword arguments passed through unchanged, plus metadata=<generated metadata>.

The send_robust flag must not be forwarded as one of the passed-through keyword arguments.

  • send(self, sender, **kwargs): issue a warning (via the warnings mechanism, so assertWarns detects a Warning) with the message: Please, use 'send_event' when triggering an Open edX event.

  • send_robust(self, sender, **kwargs): issue a warning with the message: Please, use 'send_event' with send_robust equals to True when triggering an Open edX event.

These overrides only need to emit the warning.

  • openedx_events.tooling must reference Django's Signal as openedx_events.tooling.Signal.

Overview

The class must expose the following methods used by callers:

Behavior:

Task Specification: Avro–Attrs Bridge for Event Bus

Overview

Implement a bridge that converts between attrs-decorated Python class instances and Avro-serialized binary data. This enables attrs objects to be serialized to a compact binary wire format (using Avro) and later deserialized back into attrs objects, including support for schema evolution between different versions of a class.

Modules and Public API to Create

Module: openedx_events.avro_attrs_bridge

Define a class AvroAttrsBridge with the following public interface:

class AvroAttrsBridge:
    def __init__(self, attrs_cls, extensions=None):
        ...

    def serialize(self, obj) -> bytes:
        ...

    def deserialize(self, data, writer_schema=None):
        ...

    @property
    def schema_dict(self):
        ...
  • attrs_cls: an attrs-decorated class. This is the class the bridge is bound to; it defines the "reader" schema and the type into which deserialized data is reconstructed.
  • extensions: an optional mapping. The keys are Python types (classes) and the values are extension instances that describe how to convert non-primitive/custom types to and from Avro-compatible representations. Defaults to no extensions.
Module: openedx_events.avro_attrs_bridge_extensions

Define a class CourseKeyAvroAttrsBridgeExtension that handles conversion between opaque_keys.edx.keys.CourseKey instances and Avro-compatible values.

  • It must expose a class-level attribute cls whose value is the CourseKey class (i.e. CourseKeyAvroAttrsBridgeExtension.cls is CourseKey). This attribute is used as the key when registering the extension in an AvroAttrsBridge's extensions mapping.
  • Instances of this class must be able to convert a CourseKey object to a serializable form and reconstruct an equal CourseKey object from that form, such that a round trip through serialize/deserialize yields an object equal to the original.

Required Behavior

Construction and type support

The bridge must recognize and directly support the following primitive/attribute types when they appear as attrs fields: str, int, bool, and datetime.datetime.

The bridge must also support nested attrs classes as field types (an attrs class whose fields are themselves attrs classes, to arbitrary nesting depth). Nested attrs objects must be serialized and deserialized recursively.

For any field whose declared type is a "custom" type that is neither a primitive supported type nor an attrs class (for example CourseKey), the bridge requires a corresponding entry in extensions keyed by that type. Notably, datetime is a supported type and does not require an extension.

Error condition: If the bridge is constructed for a class that contains a custom (non-primitive, non-attrs) field type for which no matching extension is provided in extensions, construction must raise TypeError. For example, constructing a bridge for a class containing a CourseKey field without supplying a CourseKey extension must raise TypeError.

schema_dict property

The bridge must expose a schema_dict property returning the Avro schema (as a Python dictionary) that the bridge derives from the bound attrs class. This schema dictionary can be passed as the writer_schema argument to another bridge's deserialize method (see schema evolution below).

serialize(obj)

Given an instance of the bound attrs class, produce a serialized byte representation of the object using the bridge's derived Avro schema. Custom-typed fields are converted using the registered extensions; nested attrs fields are handled recursively; datetime values are handled as a supported type.

deserialize(data, writer_schema=None)

Given serialized bytes previously produced by serialize, reconstruct and return an instance of the bridge's bound attrs class.

  • When writer_schema is None, the data is interpreted using the bridge's own schema (used for a plain round trip where the same class/schema serialized and deserialized).
  • When writer_schema is provided (a schema dictionary, typically obtained from another bridge's schema_dict), the data must be read using that writer schema while the resulting object is constructed according to the current bridge's bound class (the reader schema). This supports schema evolution (see below).

The reconstructed object must be an instance of the bound attrs class, with custom-typed fields converted back into their Python types via the registered extensions, nested attrs fields reconstructed recursively, and datetime fields restored.

Round-trip guarantee

For a bridge bound to a given attrs class (with any necessary extensions), serializing an instance and then deserializing the result with the same bridge must yield an object equal to the original instance. This must hold for:

  • Classes with only primitive fields.
  • Classes with nested attrs fields.
  • Classes containing custom types (e.g. CourseKey) and datetime fields, when the appropriate extension(s) are supplied.
Schema evolution

Serialized data produced by a bridge bound to one version of an attrs class (the "writer") must be deserializable by a bridge bound to a different version of that class (the "reader"), by passing the writer bridge's schema_dict as the writer_schema argument to the reader bridge's deserialize. The reader bridge produces an instance of its own (new) bound class. The following evolution scenarios must be supported:

  1. Field added with a default (primitive type): If the reader's class defines an additional field (with a default value) that was not present in the writer's schema, deserialization succeeds and the new field takes its default value. All fields present in both versions retain their original serialized values.

  2. Field removed: If the reader's class omits a field that was present in the writer's schema, deserialization succeeds and the removed field is simply absent from the reconstructed object. Remaining fields retain their original serialized values.

  3. Field added with a default (nested attrs type): If the reader's class defines an additional field (with a default value) whose type is a nested attrs class and which was not present in the writer's schema, deserialization succeeds and the new field takes its default attrs instance value.

  4. Field added with a default (datetime type): If the reader's class defines an additional field (with a default value) of type datetime that was not present in the writer's schema, deserialization succeeds and the new field takes its default value (e.g. None).

In all evolution cases, fields common to both writer and reader must round-trip to values equal to the originally serialized values.

Supporting Data Classes (already present, used as field types)

The following attrs classes exist in openedx_events.learning.data and are used as inputs; the bridge must handle them and their nesting:

  • UserPersonalData(username: str, email: str, name: str)
  • UserData(id: int, is_active: bool, pii: UserPersonalData)
  • CourseData(course_key: CourseKey, display_name: str, start: datetime, end: datetime)
  • CourseEnrollmentData(user: UserData, course: CourseData, mode: str, is_active: bool, creation_date: datetime, created_by: UserData)

CourseEnrollmentData contains a CourseKey (transitively, via CourseData) and datetime fields; a bridge bound to it therefore requires a CourseKey extension.

Dependencies

The implementation may rely on attrs, fastavro, and opaque-keys (for CourseKey). Ensure these are available as project dependencies.

Equality Semantics

The supported attrs classes compare by value. The bridge's correctness is measured by value equality (==) of reconstructed objects with originals, and equality of their attr.asdict(...) representations in evolution scenarios.
