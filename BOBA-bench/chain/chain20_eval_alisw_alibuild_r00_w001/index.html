Task Specification: Refactor of Reference Repository Management

Overview

The reference-repository (git mirror) management code in the alibuild_helpers.workarea module must be refactored, and its callers in alibuild_helpers.build and alibuild_helpers.init must be updated so they accommodate a new API and new fetch semantics.

Module: alibuild_helpers.workarea

Public functions that must be provided

The previous single entry point must be replaced with two public functions:

def updateReferenceRepo(referenceSources, p, spec, fetch=True)
def updateReferenceRepoSpec(referenceSources, p, spec, fetch=True)

Moreover, the module must reference (import or define) a name is_writeable whose purpose is to determine whether a directory is writeable. is_writeable is a callable that takes a single path argument and returns a boolean.

The module must use os, os.path (referenced as path), execute, getstatusoutput, and debug from inside its own namespace, so that each of them can be patched individually as alibuild_helpers.workarea.os, alibuild_helpers.workarea.path, alibuild_helpers.workarea.execute, alibuild_helpers.workarea.getstatusoutput, alibuild_helpers.workarea.debug, and alibuild_helpers.workarea.is_writeable.

Shared parameters and derived values
  • referenceSources: a base directory path, which may be relative. It must be resolved to an absolute path.
  • p: the package name (e.g. "AliRoot"). The repo directory name comes from its lowercased form.
  • spec: a dict-like object. It contains at least spec["source"] (a git URL).
  • The reference repository path is: abspath(referenceSources) + "/" + p.lower().
    • Example: referenceSources="sw/MIRROR", p="AliRoot" ⇒ reference path is <cwd>/sw/MIRROR/aliroot.
How updateReferenceRepo(referenceSources, p, spec, fetch=True) behaves

This function does the actual mirror creation / update work. It must:

  1. Derive the reference repository path as set out above.

  2. Emit the debug message "Updating references.".

  3. Ensure the base directory exists via a call to os.makedirs(<abspath of referenceSources>).

    • With referenceSources="sw/MIRROR", that call must be os.makedirs('<cwd>/sw/MIRROR').

  4. Test whether the reference repo directory itself exists, using path.exists('<abspath of referenceSources>/<p.lower()>').

    • For the example inputs, path.exists must be called with '<cwd>/sw/MIRROR/aliroot'.

  5. Choose between cloning and fetching:

    • If the reference repo directory does not already exist:

      • Such a directory is a candidate for a fresh git clone --bare.
      • The clone must only be performed if the base directory is writeable (is_writeable(...) returns True).
        • When it is writeable: carry out the clone. The clone command must be issued through execute, its command text must begin with git clone, and it must take the form: git clone --bare <spec["source"]> <abspath of referenceSources>/<p.lower()>
        • When it is not writeable: no clone is performed (no git clone command is issued through execute).
      • In this branch, no git fetch takes place.

    • If the reference repo directory already exists:

      • A git fetch update is run via execute. The command text must contain the substring && git fetch --tags (and is thereby recognized as a fetch, not a clone).
      • In this branch, no git clone takes place.

  6. execute is invoked with a single command argument. That command may be a string or a list of tokens; before matching, callers/tests join a list with spaces. A command counts as a clone because its (joined) text starts with git clone , and as a fetch because its (joined) text contains && git fetch --tags.

Recap of the four cases for updateReferenceRepo:

Repo dir exists Base dir writeable Result
Yes Yes one git fetch --tags update, no clone
No Yes one git clone --bare, no fetch
No No neither clone nor fetch
Yes No (fetch/update branch; no clone)

os.makedirs('<abspath of referenceSources>') is called in all cases.

How updateReferenceRepoSpec(referenceSources, p, spec, fetch=True) behaves

This function is a higher-level wrapper which also records the reference path into the spec. It must:

  1. Derive the reference repository path as set out above.
  2. Set spec["reference"] to that reference path (<abspath of referenceSources>/<p.lower()>), so that once the call is over, spec["reference"] equals the computed reference path. This must happen regardless of whether the base directory is writeable.
  3. Perform the underlying repository update work — the same work as updateReferenceRepo — which includes emitting the "Updating references." debug message and calling os.makedirs('<abspath of referenceSources>').
  4. Honor the writeability semantics: if the reference repo directory already exists while the base directory is not writeable, the repository does not get updated — meaning neither git fetch nor git clone is issued — yet spec["reference"] is still set and os.makedirs(...) is still called. If the reference repo directory already exists and the base directory is writeable, exactly one git fetch --tags update is issued.

Behavior parity across the shared cases:

  • Existing repo + writeable base ⇒ spec["reference"] gets set, one git fetch, no clone.
  • Existing repo + non-writeable base ⇒ spec["reference"] gets set, no fetch, no clone.

Module: alibuild_helpers.build

Orchestration of fetching in doBuild

The build driver doBuild(args, parser) must obtain reference repositories by way of alibuild_helpers.workarea rather than doing this inline. What the boolean args.fetchRepos drives is the following behavior:

  • When args.fetchRepos is False:

    • A package whose mirror does not yet exist gets a fresh git clone --bare mirror created.
    • For a package whose mirror already exists, no git fetch update is run.
    • Net effect for the standard scenario (two packages, one with an existing mirror and one without): exactly one git clone --bare and zero git fetch --tags.

  • When args.fetchRepos is True:

    • A package whose mirror does not yet exist gets a fresh git clone --bare mirror created.
    • For a package whose mirror already exists, a git fetch --tags update is run.
    • Net effect for the standard scenario: exactly one git clone --bare and one git fetch --tags.

The clone/fetch commands must be issued through execute located in the workarea module. Clone command text has the form git clone --bare <source> <mirror-path> (e.g. git clone --bare https://github.com/star-externals/zlib /sw/MIRROR/zlib and git clone --bare https://github.com/root-mirror/root /sw/MIRROR/root). The text of a fetch command contains && git fetch --tags.

doBuild must keep returning a (fmt, msg, code) tuple; for a fully successful run the message is "Everything done".

The writeability check (is_writeable) and the existence check (path.exists) from the workarea module govern the same rules as those above.

Module: alibuild_helpers.init

doInit

doInit(args) must now go through alibuild_helpers.workarea.updateReferenceRepoSpec (imported/used in such a way that it is patchable as alibuild_helpers.init.updateReferenceRepoSpec) to set up reference repositories, instead of the old function name.

The existence probe tied to the mirror directory (previously '/sw/MIRROR/aliroot') must no longer be performed directly by doInit itself — that responsibility now sits with the workarea reference-update code.

The clone/checkout behavior for the working copy stays as it is: AliRoot continues to be cloned via execute, using a command equivalent to:

git clone https://github.com/alisw/AliRoot -b v5-08-00 --reference /sw/MIRROR/aliroot ./AliRoot && cd ./AliRoot && git remote set-url --push origin https://github.com/alisw/AliRoot

Constraint on naming / directory-name characters

While building relocation/replacement patterns that match directory-name characters, the set of characters treated as valid directory-name characters must exclude the semicolon (;) and colon (:) characters (on top of spaces, which are already excluded).

External interface notes (must remain patchable)

  • alibuild_helpers.workarea: os, path, execute, getstatusoutput, debug, is_writeable.
  • alibuild_helpers.build: execute, urlopen, getstatusoutput, exists, sys, dieOnError, readDefaults, makedirs, debug, open, shutil, glob, readlink, banner, getStatusOutputBash.
  • alibuild_helpers.init: os, execute, parseRecipe, updateReferenceRepoSpec, readDefaults, plus path, info, banner.

execute must accept optional keyword arguments (it gets called as execute(cmd, **kwds)).

Extra Requirements

  • Deriving absolute paths must stay functional even if the module-level os and path names are replaced, or lack working abspath/path-joining methods. doInit carries out its git operations by invoking an execute-style command runner, passing one shell command string per invocation.

Whenever doInit carries out a repository clone, the git commands it generates must be modified as follows:

1. Named remote used in the clone

git clone --origin upstream --filter=blob:none https://github.com/alisw/AliRoot -b v5-08-00 --reference /sw/MIRROR/aliroot ./AliRoot && cd ./AliRoot && git remote set-url --push upstream https://github.com/alisw/AliRoot
