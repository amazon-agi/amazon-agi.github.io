Modify the git repository initialization logic so that cloned repositories use a named remote called upstream instead of the default remote name (origin).

Public API

The behavior is triggered through the existing entry point:

  • Module: alibuild_helpers.init
  • Function: doInit(args)

doInit accepts a configuration/arguments object with at least the following attributes used by this task:

  • dist — a dict describing the alidist repository, containing repo (e.g. alisw/alidist) and ver (e.g. master).
  • pkg — the package/development repository to clone (e.g. AliRoot).
  • configDir — target path for the alidist clone (e.g. /alidist).
  • develPrefix — used to determine the clone target directory (e.g. clone into ./AliRoot).
  • referenceSources — mirror directory path (e.g. /sw/MIRROR).
  • fetchRepos — boolean.
  • architecture — architecture string (e.g. slc7_x86-64).

doInit performs its git operations by invoking an execute-style command runner with a single shell command string per invocation.

Required Behavior

When doInit clones a repository, the generated git commands must be changed as follows:

1. Named remote on clone

Every git clone command must include the option --origin upstream placed immediately after git clone and before any other options.

For example, cloning the alidist repository must produce:

git clone --origin upstream --filter=blob:none https://github.com/alisw/alidist -b master /alidist
2. Push URL set on the upstream remote

When a development package repository is cloned (using a reference mirror), the follow-up command that sets the push URL must target the upstream remote instead of origin.

For example, cloning the development package repository must produce:

git clone --origin upstream --filter=blob:none https://github.com/alisw/AliRoot -b v5-08-00 --reference /sw/MIRROR/aliroot ./AliRoot && cd ./AliRoot && git remote set-url --push upstream https://github.com/alisw/AliRoot

Details / Constraints

  • The order and total set of git commands issued must otherwise remain unchanged. For the scenario above (cloning both the alidist config repo and a development package repo with a reference mirror), exactly two clone commands are issued: first the alidist repo clone, then the development package repo clone (with its chained git remote set-url --push command).
  • The --filter=blob:none option, the -b <version> branch selection, the --reference <mirror> option, and the target directory arguments must all be preserved exactly as before, with only the remote-name changes described above applied.
  • The push-URL update in the chained command references the same repository URL as the clone (e.g. https://github.com/alisw/AliRoot).
  • These commands are produced identically whether fetchRepos is False or True.

The only change from the previous behavior is the introduction of --origin upstream on clone commands and the use of upstream (rather than origin) as the remote name in the git remote set-url --push command.
