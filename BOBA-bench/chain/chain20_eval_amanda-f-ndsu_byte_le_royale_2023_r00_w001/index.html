Task Specification: Storage Station

Overview

Implement a new Storage station class that can hold a single item and supports taking, returning, and swapping items via a single action method.

Public API

Module: game.common.stations.storage

Create a class Storage (a station type) with the following:

  • Constructor: Storage() — takes no required arguments and constructs a valid, empty storage station.
  • Attribute: item — holds the item currently stored (readable and writable). It defaults to None (empty) on a freshly constructed instance.
  • Attribute: object_type — must equal ObjectType.storage.
  • Method: take_action(self, item) — performs a single interaction with the storage station using the passed-in item and returns an item (or None). See behavior below.
Enum: game.common.enums

Add a new enum member ObjectType.storage to the existing ObjectType enumeration.

Behavior of take_action(item)

take_action swaps the incoming item with whatever is currently held in the station's item attribute. Specifically:

  • After the call, the station's item attribute holds the object that was passed in as the item argument.
  • The method returns the object that was previously held in the station's item attribute (before the call).

This single behavior covers all three interaction cases:

  1. Take (deposit into empty storage): When the station's item is None and a non-None item is passed in, after the call the station holds that item and the method returns None.

  2. Return (withdraw from storage): When the station holds an item and None is passed in, after the call the station's item is None and the method returns the previously held item.

  3. Swap: When the station holds an item and a different non-None item is passed in, after the call the station holds the passed-in item and the method returns the previously held item.

Integration Requirements

  • A Storage instance must be assignable to a Tile's occupied_by attribute; a station instance (including Storage) assigned there must be retrievable and remain an instance of its class. Supporting Context (already present, for reference)

  • Pizza objects (game.common.items.pizza.Pizza) can be constructed with a state keyword argument (e.g. Pizza(state=PizzaState.sauced)), have a mutable state attribute, and support add_topping(topping) where topping values come from the ToppingType enum. Add a new enum member delivery to the ObjectType enumeration.

Behavior of Delivery.take_action(cook)

The method inspects the item held by the passed-in cook (cook.item).

Acceptance rules
  • If the held item is a Pizza whose state is PizzaState.baked, the delivery succeeds:
    • The pizza is scored (see Scoring below), and the resulting score is assigned to the cook's score attribute (cook.score).
    • The method returns None (the pizza is consumed/delivered).
  • If the held item is not a baked pizza (any other PizzaState such as rolled or sauced, or a non-pizza item), the delivery fails:
    • The exact same item object that was held is returned unchanged (returned by identity — the caller receives back the original object).
    • The cook's score is not affected in this case.
Scoring (only applied on successful delivery of a baked pizza)

The score is derived from the pizza's overall quality, the dough's base score, and each topping's base score adjusted by that topping's individual quality.

Given:

  • GameStats.topping_stats[ToppingType.dough]["score"] — the base score contributed by the dough (always counted once per pizza).
  • Each topping on the pizza contributes a per-topping score computed as:
    • floor(topping_base_score * topping_quality), where topping_base_score is GameStats.topping_stats[<that topping's type>]["score"] and topping_quality is the topping's individual quality value.
  • The pizza itself has an overall quality value.

The final score is computed as:

raw_sum = dough_score + sum( floor(topping_base_score * topping_quality) for each topping )
final_score = int( floor( raw_sum * pizza_quality ) )

Notes on the arithmetic that the scoring must satisfy:

  • When a topping's quality is 1.0, its contribution equals its base score exactly (floor(base * 1.0) == base).
  • When the pizza's overall quality is 1.0, the final score equals the raw sum of dough + all topping contributions.
  • The dough base score is always added once regardless of the number of toppings.
  • The result must be an integer (floored after multiplying the raw sum by the pizza quality).

Examples (using base scores from GameStats.topping_stats):

  • A baked pizza with quality 1.0 and a single cheese topping (quality 1.0): score = dough_score + cheese_score.
  • A baked pizza with quality 1.0 and four toppings all at quality 1.0 (cheese, sausage, mushrooms, olives): score = dough_score + cheese_score + sausage_score + mushrooms_score + olives_score.
  • A baked pizza with overall quality 0.5 and toppings cheese(1.0), sausage(0.5), mushrooms(1.0), olives(1.0): score = int(floor((dough_score + cheese_score + floor(sausage_score * 0.5) + mushrooms_score + olives_score) * 0.5)).

Supporting Requirements

The Cook class must:

  • Accept an item keyword argument at construction (Cook(item=<something>)) that stores the held item, accessible as cook.item.
  • Have a score attribute that can be read and written; the delivery station writes the computed score to it.
