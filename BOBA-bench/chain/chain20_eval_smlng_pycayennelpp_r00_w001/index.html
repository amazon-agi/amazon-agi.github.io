01 Update LppFrame in cayennelpp.lpp_frame so that frames can enforce a configurable maximum serialized byte size. 683 words · rewritten by GPT-5.6-sol

Overview

Update LppFrame in cayennelpp.lpp_frame so that frames can enforce a configurable maximum serialized byte size. Preserve the existing frame API and Cayenne LPP encoding behavior; the size limit is an additional guard on frame data additions.

maxsize Property

LppFrame.maxsize must be a readable and writable property, used through normal attribute syntax:

limit = frame.maxsize
frame.maxsize = 12

It is not a method and is not required to support callable syntax.

  • A default-constructed LppFrame() has maxsize == 0.
  • 0 is the unlimited sentinel. While maxsize is 0, no addition may be rejected because of frame size. Existing validation of channels, types, and values remains unchanged.
  • A positive integer establishes the maximum permitted serialized size in bytes.
  • Reading the property returns the current setting.
Assignment validation

A value assigned to maxsize must be a valid non-negative integer size. Invalid values, including negative values and non-integer size values, must raise an exception.

Assignment also depends on the frame's current serialized size:

  • Assigning 0 is valid and disables the limit.
  • Assigning a positive value greater than or equal to the current frame size is valid.
  • Assigning a nonzero value smaller than the current frame size must raise an exception. A new limit must never make an already populated frame oversized.
  • A failed assignment must not replace the prior maxsize setting.

For example, a digital-input item occupies three serialized bytes. After such an item has been added to an unlimited frame, frame.maxsize = 1 must fail, whereas a limit equal to the current three-byte size is permitted. A positive value such as 1 is otherwise a valid limit when the frame's current size does not exceed it.

Serialized-Size Semantics

The limit applies to the complete serialized frame size, equivalent to the sum of the serialized sizes of its LppData entries. Each entry's channel and type bytes are included along with its payload. The boundary is inclusive: a resulting size equal to maxsize is allowed; only a resulting size greater than maxsize is rejected.

For reference:

  • A digital input has a one-byte payload and occupies three frame bytes in total.
  • A generic value has a four-byte payload and occupies six frame bytes in total.

Enforcement on Data Addition

Every LppFrame data-adding method must apply the same prospective-size check before committing its new entry. This includes all existing convenience methods, such as the digital and analog input/output methods, sensor methods, add_pressure and its add_barometer alias, and add_generic.

For each addition:

  1. If maxsize == 0, allow the addition without a size-limit check.
  2. If maxsize > 0 and the current frame size plus the new entry's full serialized size is less than or equal to maxsize, add the entry normally.
  3. If that prospective size is greater than maxsize, raise an exception and do not add the entry. The frame's data, serialized size, and maxsize must remain unchanged by this rejected addition.

The requirement applies to the existing methods:

  • add_digital_input(channel, value)
  • add_digital_output(channel, value)
  • add_analog_input(channel, value)
  • add_analog_output(channel, value)
  • add_generic(channel, value)
  • add_luminosity(channel, value)
  • add_presence(channel, value)
  • add_temperature(channel, value)
  • add_humidity(channel, value)
  • add_unix_time(channel, value)
  • add_accelerometer(channel, x, y, z)
  • add_pressure(channel, value)
  • add_barometer(channel, value)
  • add_gyrometer(channel, x, y, z)
  • add_gps(channel, lat, lon, alt)
  • add_voltage(channel, value)
  • add_load(channel, value)

These methods must retain their existing signatures and data-type behavior. In particular, with the unlimited default, adding a digital input continues to succeed and does not change maxsize from 0.

Generic Data API

LppFrame must expose:

add_generic(self, channel, value)

It adds the existing generic four-byte unsigned-integer LPP data type for the supplied channel and value, subject to the same frame limit as every other addition. Because the complete generic entry occupies six bytes, this operation on an empty frame with maxsize == 3 must raise an exception and leave the frame empty.

Error Handling

Any exception type derived from Exception is acceptable for invalid maxsize assignments and additions that would exceed the limit. No specific exception message is required.
