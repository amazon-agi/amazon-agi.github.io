01 Modify LppFrame in cayennelpp.lpp_frame so that frames can enforce a maximum serialized byte size that is configurable. 740 words · rewritten by GPT-5.6-sol, reworded by GLM-5.3-Flash

Overview

Modify LppFrame in cayennelpp.lpp_frame so that frames can enforce a maximum serialized byte size that is configurable. The existing frame API and the Cayenne LPP encoding behavior must be preserved; the size limit acts as an additional guard on frame data additions.

The maxsize Property

LppFrame.maxsize must be a property that is readable and writable, used through normal attribute syntax:

limit = frame.maxsize
frame.maxsize = 12

It is not a method, and supporting callable syntax is not required.

  • An LppFrame() constructed with defaults has maxsize == 0.
  • 0 serves as the unlimited sentinel. As long as maxsize is 0, no addition may be rejected on account of frame size. The existing validation of channels, types, and values stays unchanged.
  • A positive integer establishes the maximum serialized size in bytes that is permitted.
  • The property returns the current setting when read.
Validation of Assignments

Any value assigned to maxsize must be a valid non-negative integer size. Values that are invalid, including negative values and non-integer size values, must raise an exception.

Assignment additionally depends on the current serialized size of the frame:

  • Assigning 0 is valid and disables the limit.
  • A positive value that is greater than or equal to the current frame size is valid to assign.
  • Assigning a nonzero value that is smaller than the current frame size must raise an exception. A new limit must never leave an already populated frame oversized.
  • When an assignment fails, it must not replace the prior maxsize setting.

For example, a digital-input item occupies three serialized bytes. After such an item has been added to an unlimited frame, frame.maxsize = 1 must fail, whereas a limit equal to the current three-byte size is permitted. Otherwise, a positive value such as 1 is a valid limit when the frame's current size does not exceed it.

Semantics of the Serialized Size

The limit applies to the complete serialized frame size, which is equivalent to the sum of the serialized sizes of its LppData entries. Along with its payload, each entry's channel and type bytes are included. The boundary is inclusive: a resulting size equal to maxsize is allowed; rejection applies only to a resulting size greater than maxsize.

As a reference:

  • A digital input carries a one-byte payload and occupies three frame bytes in total.
  • A generic value carries a four-byte payload and occupies six frame bytes in total.

Enforcement When Data Is Added

Every LppFrame data-adding method must carry out the same prospective-size check before it commits its new entry. This covers all existing convenience methods, such as the digital and analog input/output methods, sensor methods, add_pressure and its add_barometer alias, and add_generic.

For each addition, the following applies:

  1. If maxsize == 0, the addition is allowed without a size-limit check.
  2. If maxsize > 0 and the current frame size plus the new entry's full serialized size is less than or equal to maxsize, the entry is added normally.
  3. If that prospective size is greater than maxsize, an exception is raised and the entry is not added. The frame's data, its serialized size, and maxsize must remain unchanged by this rejected addition.

The requirement applies to these existing methods:

  • add_digital_input(channel, value)
  • add_digital_output(channel, value)
  • add_analog_input(channel, value)
  • add_analog_output(channel, value)
  • add_generic(channel, value)
  • add_luminosity(channel, value)
  • add_presence(channel, value)
  • add_temperature(channel, value)
  • add_humidity(channel, value)
  • add_unix_time(channel, value)
  • add_accelerometer(channel, x, y, z)
  • add_pressure(channel, value)
  • add_barometer(channel, value)
  • add_gyrometer(channel, x, y, z)
  • add_gps(channel, lat, lon, alt)
  • add_voltage(channel, value)
  • add_load(channel, value)

These methods must keep their existing signatures and data-type behavior. In particular, with the unlimited default in place, adding a digital input continues to succeed and does not change maxsize from 0.

The Generic Data API

LppFrame must expose:

add_generic(self, channel, value)

The method adds the existing generic four-byte unsigned-integer LPP data type for the supplied channel and value, and it is subject to the same frame limit as every other addition. Because the complete generic entry occupies six bytes, performing this operation on an empty frame with maxsize == 3 must raise an exception and leave the frame empty.

Handling of Errors

For invalid maxsize assignments and for additions that would exceed the limit, any exception type derived from Exception is acceptable. No specific exception message is required.
