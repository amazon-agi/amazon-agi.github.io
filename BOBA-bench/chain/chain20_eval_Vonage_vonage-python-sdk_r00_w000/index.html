Objective

Update the nexmo module so that it functions correctly under both Python 2 and Python 3.

Background

The nexmo module contains code that relies on Python 2-only standard library imports and dictionary/iteration idioms. These need to be made compatible with Python 3 while continuing to work under Python 2.

Required Changes

1. urljoin import compatibility

The nexmo module uses urljoin to construct request URLs. The import of urljoin must work under both Python 2 and Python 3:

  • In Python 3, urljoin lives in urllib.parse.
  • In Python 2, urljoin lives in urlparse.

The module must import urljoin from the correct location depending on the Python version so that request URLs are joined correctly in both environments.

2. Dictionary iteration / merge compatibility

Any code in the nexmo module that iterates over dictionary key/value pairs (for example, when merging parameter dictionaries or building request parameters) must not rely on Python 2-only methods such as dict.iteritems(). The iteration must work identically under both Python 2 and Python 3.

Constraints

  • Public API surface (class names, method names, signatures, module name) must remain unchanged — the module is imported simply as nexmo.
  • Behavior of the client (constructing requests, building request bodies from parameters, joining URLs) must be identical to the existing behavior, only made portable across Python 2 and Python 3.
  • Request bodies produced from parameter dictionaries must contain each key/value pair encoded as quote_plus(key)=quote_plus(value).

Success Criteria

The nexmo module can be imported and used without error under both Python 2 and Python 3, producing correctly joined URLs and correctly encoded request bodies from parameter dictionaries.

JWT Authentication

Voice API operations under /v1/calls use a JWT Bearer token instead of API-key/secret authentication. Every such request must include:

Authorization: Bearer {token}

The token must:

  • Be signed with RS256 using the client's RSA private_key.
  • Contain an application_id claim equal to the client's configured application ID unless that claim has been overridden through auth.
  • Be verifiable using the public key corresponding to the configured private key.

JWT-authenticated operations must not require key or secret. JSON-bearing Voice requests must have Content-Type: application/json.

Claim overrides: Client.auth(**kwargs)

Client.auth(**kwargs) records claim values that are merged into subsequently generated JWT payloads. User-supplied claim values override defaults. For example:

client.auth(application_id=other_application_id, nbf=nbf, exp=exp)
client.get_call(call_id)

The resulting JWT must contain the supplied application_id, nbf, and exp values verbatim. In particular, the supplied application ID replaces the one configured on the client for token claims. Additional standard claims may be generated, but they must not overwrite explicit values passed to auth.
