01 Update the nexmo module so that it works correctly under both Python 2 and Python 3. 294 words · source specification, reworded by GLM-5.3-Flash

Task Description

Goal

Update the nexmo module so that it works correctly under both Python 2 and Python 3.

Context

The nexmo module includes code that depends on Python 2-only standard library imports and dictionary/iteration idioms. These parts need to be made compatible with Python 3 while continuing to work under Python 2.

Required Modifications

1. Import compatibility for urljoin

The nexmo module uses urljoin when constructing request URLs. Importing urljoin must work under both Python 2 and Python 3:

  • In Python 3, urljoin resides in urllib.parse.
  • In Python 2, urljoin resides in urlparse.

Depending on the Python version, the module must import urljoin from the correct location so that request URLs are joined correctly in both environments.

2. Compatibility of dictionary iteration / merging

Any code in the nexmo module that iterates over dictionary key/value pairs (for example, when parameter dictionaries are being merged or request parameters are being built) must not rely on Python 2-only methods such as dict.iteritems(). Under both Python 2 and Python 3, the iteration must work identically.

Constraints

  • The public API surface (class names, method names, signatures, module name) must remain unchanged — the module is imported simply as nexmo.
  • The behavior of the client (constructing requests, building request bodies from parameters, joining URLs) must be identical to the existing behavior; the only change is that it is made portable across Python 2 and Python 3.
  • When request bodies are produced from parameter dictionaries, they must contain each key/value pair encoded as quote_plus(key)=quote_plus(value).

Criteria for Success

Under both Python 2 and Python 3, the nexmo module can be imported and used without error, producing correctly joined URLs and correctly encoded request bodies from parameter dictionaries.

15 The public nexmo module must allow Client to be constructed with a callback-signing secret passed in addition to its existing credentials 348 words · rewritten by GPT-5.6-sol, reworded by GLM-5.3-Flash

Task Description

Public API requirements

The public nexmo module must allow Client to be constructed with a callback-signing secret passed in addition to its existing credentials:

client = nexmo.Client(
    key=<api_key>,
    secret=<api_secret>,
    signature_secret='secret'
)

signature_secret is the secret employed for callback signature generation and validation. Existing ways of constructing Client, and its behavior, must remain compatible.

Expose the following public instance methods:

Client.signature(params)
Client.check_signature(params)

Generating signatures

Client.signature(params)

The params parameter is a dictionary of callback parameters. Using the client's signature_secret, the method must return the callback signature as a lowercase hexadecimal string.

Build the signature deterministically through these steps:

  1. Sort the parameter keys into ascending key order.
  2. Starting from an empty string, append each sorted key/value pair in the exact form &key=value; as a consequence, the first pair also has a leading &.
  3. Append the client's signature_secret directly onto the end of that string, without inserting any further delimiter.
  4. Compute the MD5 digest of the string that results.
  5. Return the digest in its lowercase hexadecimal representation.

Consequently, dictionary insertion order must not affect the result.

As an example, given:

params = {
    'a': '1',
