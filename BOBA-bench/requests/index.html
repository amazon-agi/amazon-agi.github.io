What does a request look like?

Because the agent is never shown the hidden tests, every request must be recoverable from its specification alone. A request is one cut of a repository's real history where the developers added or changed tests: the tests they added are the hidden contract, the specification is written from them, and the change the developers actually made is the gold reference. These examples are drawn from the released benchmark; the full text of every request is on its chain page.

Requests cut from history

Twenty consecutive cuts of one repository's history form a chain. The agent receives them one at a time; later requests build on, extend or revise what earlier ones introduced, so the same symbols, modules and behaviours recur along a chain.

Specifications written from the tests

A language model drafts each specification from the test diff, the commit messages and the linked issues, never from the developers' patch, and names the public behaviour, API and errors the tests exercise without quoting test identifiers or assertions. Three model families must find the text sufficient before it is released.
